# 장 27: 필요한 만큼만 지불하기

토미는 Nimbus가 시작한 이후 매달 AWS 청구서를 검토했다. 처음 한 해 동안 그는 약 60% 정도 이해할 수 있었지만, 지금은 거의 모든 부분을 이해하고 있었다 — 단, EC2 섹션만 제외하고.

EC2 섹션에는 다양한 인스턴스 유형의 "즉시 예약 인스턴스"가 혼합되어 있고, 모두 시간당 가격으로 책정되어 총 $2,340/월을 추가로 지불해야 했다.

"이 인스턴스는 필요해요," 토미가 말했다. "하지만 왜 모든 인스턴스에 대해 즉시 예약 비율을 지불하고 있는지 이해할 수 없어요."

"즉시 예약 비율?" 레오가 물었다.

"즉시 예약 가격입니다," 토미가 설명했다. "예를 들어, 필요할 때 당일 아침에 호텔 방을 예약하는 것처럼요. 최대 유연성. 최고의 가격."

"그럼 대체 방법은?"

토미는 EC2 가격 페이지를 불러냈다.

"이유약 모델이 네 가지가 있어요," 그가 말했다. "우리는 단 하나만 사용하고 있어요."

**호텔 비유**

EC2 가격은 놀랍게도 호텔 방 예약 전략에 잘 매칭됩니다:

**즉시 예약**: 예약 없이 현장에서 방을 찾아가는 것처럼요. 완전한 요금을 지불하지만 언제든지 체크아웃할 수 있어요. 불확실한 숙박을 위한 이상적인 선택입니다.

**예약 인스턴스/절약 계획**: 한 해 동안 특정 인스턴스 유형과 지역에 대해 사전 예약합니다. 약 30-72% 할인을 받는 대신, 사용을 약속해야 합니다.

**스팟 인스턴스**: 호텔이 원하는 만큼의 방을 경매로 구매합니다. 최대 90% 할인이 가능하지만, 필요할 때 갑작스럽게 철수될 수 있습니다.

**디디케이티드 호스트**: 특정 호텔 층을 독점적으로 임대합니다. 다른 손님과 공유되지 않아요. 훨씬 비싸요. 소프트웨어 라이선싱 규칙이나 준수 규정으로 인해 물리적 호스트를 공유할 수 없을 때 필요합니다.

각 모델은 특정 사용 사례에 적합합니다. Nimbus가 범한 실수: 모든 작업 부하에 대해 즉시 예약을 사용하며, 24시간 연중 무휴로 완전히 예측 가능한 작업 부하를 포함하여.

**즉시 예약 인스턴스: 최대 유연성, 최대 비용**

**사용 시나리오**:

- 불확정한 작업 부하 (예측할 수 없는 트래픽 피크)
- 개발 및 테스트 (주기적으로 시작하고 중지)
- 단기 작업 부하 (일주일 동안 실험 실행)
- 첫 배포 (사용 패턴을 이해하기 전)

**사용하지 않는 시나리오**:

- 1년 이상 지속될 예정인 안정적인 생산 작업 부하
- 예측 가능한 기본 로드가 있는 모든 것

토미는 Nimbus의 즉시 예약 인스턴스를 식별했다:

- 웹 API 서버: 4개 EC2 인스턴스, 18개월 동안 24시간 연중 무휴로 실행. *예측 가능한 기본 로드.*
- 데이터베이스 프록시 (RDS Proxy): 항상 실행 중. *예측 가능한 기본 로드.*
- VPN 서버: 항상 실행 중. *예측 가능한 기본 로드.*
- 트래픽 피크 시 추가 API 서버: 불확정. *즉시 예약 인스턴스가 적절합니다.*

**예약 인스턴스: 1년간의 약속**

**예약 인스턴스 (RIs)**는 청구 약속입니다 — 특정 인스턴스 유형과 지역에서 1년 또는 3년 동안 사용하기로 합의합니다. 대신 AWS는 시간당 요금을 낮게 부과합니다.

**할인 계층**:

- 1년, 무위약금: 약 30-40% 할인 (즉시 예약 인스턴스 대비)
- 1년, 부분 위약금: 약 35-45% 할인 (현재 일부 지불하고 시간당 요금이 적게)
- 1년, 전체 위약금: 약 40-50% 할인 (전체 연간 금액을 지금 지불)
- 3년, 전체 위약금: 최대 할인 (최대 72%)

**표준형 vs 변환 가능한 RIs**:

- **표준형**: 정확한 인스턴스 유형과 지역에 고정되어 있습니다. 더 이상 필요하지 않으면 예약 인스턴스 마켓플레이스에서 판매할 수 있습니다.
- **변환 가능형**: 약속 기간 동안 인스턴스 유형, OS, 그리고 소유권을 변경할 수 있습니다. 표준형보다 할인율이 낮습니다 (~50% 최대).

토미는 4개 API 서버 (r6g.large, $0.252/시간 즉시 예약 인스턴스)의 연간 비용을 계산했다:

- 즉시 예약 인스턴스 비용: $0.252 × 24 × 365 × 4 = $8,820
- 1년 전체 위약금 RI (1개 인스턴스): 약 $1,600 위약금
- 4개 인스턴스: 약 $6,400 위약금 = **첫 해에 $2,420 절약**

"첫 해에만 $2,420를 절약할 수 있어요," 토미가 말했다.

"그건 약속이에요," 마야가 말했다. "만약 인스턴스 유형을 변경해야 한다면 어떻게 되나요?"

"변환 가능한 RI를 구매하면 됩니다."

"AWS가 더 나은 인스턴스 유형을 출시한다면?"

"RI 만료 시점에 확인합니다. 새로운 유형이 더 좋다면 새 RI를 구매합니다."

**절약 계획: 유연한 약속**

**절약 계획**은 예약 인스턴스보다 더 유연한 새로운 옵션입니다. 특정 시간당 지출 금액 (달러)에 대해 약속하는 대신, 특정 인스턴스 유형을 약속하지 않습니다.

**컴퓨트 절약 계획**: 모든 EC2 인스턴스에 적용되며, 유형, 크기, 지역 또는 OS와 상관없이 가장 유연합니다. 최대 66% 할인 가능.

**EC2 인스턴스 절약 계획**: 특정 인스턴스 가족 (예: "us-east-1의 c6g 인스턴스")에 적용됩니다. 컴프리트보다 더 제한적이나, 최대 72% 할인 가능 (RI 최대).

**SageMaker 절약 계획**: SageMaker ML 훈련 및 추론에 특화되어 있습니다.

 Nimbus의 경우: API 서버에 대해 컴프리트 절약 계획을 사용합니다. 그들은 $1.50/시간의 EC2 지출 약속을 하였습니다. 인스턴스 유형이나 크기와 상관없이, 클라우드 클러스터를 확장하거나 인스턴스 유형을 변경하더라도 절약 계획이 여전히 적용됩니다.

소피아가 말했다. "이건 Reserved Instances보다 나은 선택이다. 아직 인스턴스 타입에 대해 실험 중이라서, Compute Savings Plan으로 할인을 받으면서도 r6g를 특정하게 묶지 않게 된다."

**Spot 인스턴스: 90% 할인**

**Spot 인스턴스**는 AWS의 남은 EC2 용량을 사용합니다. AWS가 비어 있는 서버가 있을 때, 그 서버들을 On-Demand 가격보다 60-90% 저렴한 가격으로 렌트할 수 있습니다. AWS가 다시 용량을 필요로 할 때 (On-Demand 또는 Reserved 고객에게), 2분 전에 경고를 주고 인스턴스를 종료합니다.

중단 위험은 결정적인 특징입니다. Spot 인스턴스는 다음에 적합합니다:

- **결함 견디는 작업**: 인스턴스가 중간에 종료되더라도 작업이 중복되지 않고 재시작됩니다.
- **상태 없는 처리**: 이미지 리사이즈, 비디오 인코딩, 배치 분석, ML 훈련
- **단기적인 배치 작업**: 2분 경고는 상태를 저장하고 체크포인트를 만드는데 충분합니다.
- **자동 확장 혼합 클라이드**: ASG의 대다수 인스턴스에 Spot을 사용하고, 예측 가능한 성장을 위한 On-Demand 기준으로 합니다.

 Nimbus에서는 매일 밤 실행되는 배치 분석 작업이 Spot 인스턴스로 이동하여 비용이 $12/일에서 $2/일로 줄었습니다. 만약 중간에 인스턴스가 종료되면, 작업은 새로운 인스턴스에서 다시 시작됩니다. S3에 있는 데이터는 안전합니다.

" NIGHTLY 작업을 Spot으로 사용함으로써 비용이 $12/일에서 $2/일로 줄었어요," 레오가 보고했습니다.

**디DICicated 호스트: 준수 옵션**

某些软件许可证（如Oracle、某些配置下的Windows Server）按物理插槽或核心计价。当你在共享主机上运行此软件时（EC2的默认设置），你可能会为未使用的容量付费。

**Dedicated 호스트**让你可以访问完全用于你自己使用的物理服务器。你可以带来现有的每插槽许可证。同一硬件上不会运行其他AWS客户实例。

Dedicated 호스트比标准EC2贵得多。它们是合规和许可工具，而不是成本优化工具。

Nimbus没有需要使用Dedicated 호스트的许可证要求。大多数云原生应用程序也不需要。

**构建混合舰队**

成熟的策略：一起使用多种定价模型。

对于Nimbus的API舰队：

- **基线负载（4个实例，始终运行）**：由Savings Plan承诺覆盖
- **可预测高峰（业务时间内额外2个实例）**：如果承诺涵盖它们，则由Savings Plan覆盖；否则由On-Demand覆盖
- **流量峰值溢出**：Spot 인스턴스（因为API服务器是状态无的——请求会重新分配到其他实例）

结果是一个在每一层都优化成本的舰队——基线部分使用固定价格，不可预测增长部分使用按需定价，突发容量部分使用Spot。

## 강점과 한계

- **On-Demand**：没有承诺。全额价格。用于不可预测或短期工作负载。
- **Reserved 인스턴스**：最高72%折扣。锁定到特定实例类型/区域/操作系统。可以在RI Marketplace出售未使用的容量。
- **Savings Plans**：最高66-72%折扣。比RIs更灵活（Compute Savings Plans适用于任何实例类型）。自动应用于匹配的使用量。
- **Spot 인스턴스**：最高90%折扣。2分钟中断风险。仅限于故障容忍、状态无、可中断的工作负载。
- **Dedicated 호스트**：完整的物理服务器。最昂贵。某些许可证或合规场景所需。

## 요약

- EC2定价有四种模式：**On-Demand**（全额价格，没有承诺），**Reserved 인스턴스/Savings Plans**（固定支出以获得显著折扣），**Spot**（剩余容量90%折扣，可中断），**Dedicated 호스트**（物理服务器独占）。
- **Savings Plans**通常比Reserved 인스턴스更灵活，因此优先选择。
- **Spot 인스턴스**仅适用于故障容忍、状态无的工作负载——只用于批处理作业、ML训练和可中断的处理。
- 最佳策略是**混合舰队**：基线部分使用Savings Plans，不可预测增长部分使用On-Demand，突发容量部分使用Spot。
- 当工作负载稳定运行3个月以上时，请审查定价模式——这时On-Demand可能会成为浪费。

## 考试提示

*SAA-C03领域：设计成本优化架构（领域4，任务4.2）*

- **Savings Plans vs Reserved Instances**: Savings Plans은 더 유연합니다 (Compute Savings Plans은 모든 EC2 인스턴스에 적용 가능). Reserved Instances는 특정 인스턴스 타입에 고정됩니다. 시험 문제 사례: "최대 유연성을 유지하면서 할인을 받고 싶다" → Savings Plans. "3년 동안 정확한 인스턴스 타입이 확실하다" → Standard RI를 통해 최대 할인을 받는다.
- **Spot 신호**: "비용 민감형," "장애에 견디는 능력 있는," "배치 처리용," "중단 가능성을 수용할 수 있다" "상태가 없는 작업" "ML 훈련" → Spot.
- **Spot 중단 처리**: Spot 인스턴스는 중단 전 2분 경고를 받습니다. 응용 프로그램은 이에 적절히 대응해야 합니다 (상태 저장, 연결 해제, 정상적으로 종료).
- **웹 서버용 On-Demand vs Spot**: 실시간 사용자 트래픽을 처리하는 웹 서버는 Spot을 사용해서는 안 됩니다 (중단으로 인해 요청 실패). 웹 계층은 On-Demand 또는 Savings Plans을 사용해야 합니다.
- **EC2 Savings Plans vs Compute Savings Plans**: EC2 Savings Plans은 특정 인스턴스 가족과 지역에 적용되며 더 큰 할인율을 제공합니다. Compute Savings Plans은 모든 EC2 인스턴스, Lambda, Fargate에도 적용되지만 최대 할인율이 낮고 유연성이 높습니다.
- **RI 마켓플레이스**: 남은 Standard Reserved Instances는 다른 AWS 고객에게 판매할 수 있습니다. Convertible RIs는 판매할 수 없습니다.

**연습 문제 1 — 회상**

Spot 인스턴스가 적합한 상황과 그렇지 않은 상황을 설명하세요. 어떤 특성이 작업을 Spot에 적합하게 만드나요?

*(힌트: 인스턴스가 2분 경고 후 중단될 때 어떻게 대응할지 생각해보세요. 어떤 작업은 깨끗하게 회복 가능한가요? 어떤 작업은 그렇지 않나요?)*

**연습 문제 2 — 시험 연습**

*사건*: 미디어 회사는 업로드된 비디오를 여러 형식으로 변환하는 비디오 트랜스코딩 파이프라인을 운영합니다. 변환 작업은 비디오가 업로드될 때마다 지속적으로 실행됩니다 (24/7 운영, 용량 변화). 각 작업은 5-30분 소요되며, 변환 작업이 중단되면 데이터 손실 없이 다시 시작할 수 있습니다. 회사는 비용을 최소화하려고 합니다.

다음 EC2 가격 모델 중 어떤 것이 이 요구사항을 가장 잘 충족시킬까요?

A) 자동 스케일 그룹에 있는 On-Demand 인스턴스  
B) 1년, 전액 사전 지불형 Reserved Instances  
C) Spot Fleet와 함께 중단 가능한 인스턴스를 자동으로 다양화  
D) 회사의 기존 미디어 소프트웨어 라이선스가 있는 Dedicated Hosts

**힌트 1**: "데이터 손실 없이 다시 시작할 수 있다" — 이는 특정 가격 모델을 가능하게 하는 핵심 문구입니다.

**힌트 2**: "비용 최소화"와 중단 가능한 작업은 최대 할인 옵션을 지향합니다.

**힌트 3**: Spot Fleet는 여러 인스턴스 타입과 AZ에서 인스턴스 요청을 하여 대량 중단의 확률을 줄입니다.

**답변**: C

**설명**: 변환 작업은 장애에 견디는 능력이 있습니다 — 중단되면 다시 시작할 수 있습니다. 이 점 때문에 Spot Instances가 이상적입니다. Spot Instances는 On-Demand 대비 60-90% 할인을 제공합니다. Spot Fleet는 인스턴스 타입과 AZ를 다양화하여 대량 중단의 확률을 줄입니다.

**A 왜 안 되나?** On-Demand는 가장 비싼 옵션입니다. 장애에 견디는 능력이 있는 지속적으로 실행되는 작업에는 낭비가 됩니다.

**B 왜 안 되나?** Reserved Instances는 50-72% 할인을 제공하지만, 장애에 견디는 작업은 Spot의 최대 90% 할인이 더 유리합니다. 또한 RIs는 예측 가능한 정상 상태 작업용입니다 — Spot은 중단 가능한 배치 처리용으로 특화되어 있습니다.

**D 왜 안 되나?** Dedicated Hosts는 라이선스 준수를 위한 것이며, 비용 최적화에는 사용되지 않습니다. 이는 가장 비싼 옵션입니다.

*SAA-C03 도메인: 비용 최적화 아키텍처 설계 — 작업 4.2*

**연습 문제 3 — 아키텍처 도전** *(선택사항)*

Nimbus의 인프라에는 다음 작업이 있습니다:

1. API 서버: 6대, 24/7 운영 중, 2년 동안 안정적, r6g.large 사용
2. 매일 밤 분석 배치 작업: 4대, 매일 오전 3시부터 오전 6시까지 실행, 항상 같은 인스턴스 타입
3. 테스트 환경: 2대, 엔지니어들이 평일 오전 9시부터 오후 6시까지 사용
4. 트래픽 피크 시점 대응: 0-8대, 정기적으로 실행되며 완전히 예측 불가능
