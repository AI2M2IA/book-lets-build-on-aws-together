# 부록 B: SAA-C03 도메인 맵

AWS Solutions Architect Associate 시험(SAA-C03)은 네 개의 도메인으로 구성된다. 이 부록은 책의 모든 챕터를 관련 도메인과 태스크에 매핑하므로, 챕터 순서가 아닌 시험 영역별로 학습할 수 있다.

---

## 도메인 개요

| 도메인 | 비중 | 설명 |
|---|---|---|
| 도메인 1: 보안 아키텍처 설계 | 30% | IAM, 네트워크 보안, 데이터 보호 |
| 도메인 2: 탄력적 아키텍처 설계 | 26% | 고가용성, 내고장성, 재해 복구 |
| 도메인 3: 고성능 아키텍처 설계 | 24% | 컴퓨팅, 스토리지, 데이터베이스, 네트워크 성능 |
| 도메인 4: 비용 최적화 아키텍처 설계 | 20% | 가격 모델, 비용 관리, 리소스 최적화 |

---

## 도메인 1: 보안 아키텍처 설계 (30%)

**태스크 1.1 — AWS 리소스에 대한 보안 접근 설계**

핵심 개념: IAM 사용자, 그룹, 역할, 정책. 최소 권한 원칙. 교차 계정 접근. 서비스 역할. AWS Organizations의 SCP(서비스 제어 정책).

| 챕터 | 주제 |
|---|---|
| 3장 | IAM 기초: 사용자, 그룹, 역할, 정책, 정책 평가 |
| 14장 | IAM 고급: 서비스를 위한 역할, 권한 경계, 교차 계정 역할 |
| 3장 | 정책 평가 로직: 명시적 거부 > 명시적 허용 > 암묵적 거부 |
| 14장 | AWS Organizations 및 SCP |

핵심 시험 패턴:

- "자격증명 없이 S3에 접근해야 하는 EC2" → S3 정책이 연결된 IAM 역할이 있는 EC2 인스턴스 프로필
- "다른 계정이 리소스를 공유해야 함" → 교차 계정 신뢰 정책이 있는 IAM 역할
- "OU의 모든 IAM 사용자가 서비스에 접근하는 것을 방지" → AWS Organizations의 SCP

---

**태스크 1.2 — 보안 워크로드 및 애플리케이션 설계**

핵심 개념: VPC 설계, 보안 그룹 vs. NACL, 네트워크 격리, DDoS 보호, WAF, GuardDuty.

| 챕터 | 주제 |
|---|---|
| 11장 | VPC 설계: 공개/프라이빗 서브넷, NAT 게이트웨이, 인터넷 게이트웨이, 라우팅 테이블 |
| 15장 | 보안 그룹(상태가 있는, 인스턴스 수준) vs. NACL(무상태, 서브넷 수준) |
| 17장 | Shield(DDoS 보호), WAF(애플리케이션 방화벽), GuardDuty(위협 감지) |
| 25장 | Direct Connect, VPN, Transit Gateway, PrivateLink |

핵심 시험 패턴:

- "서브넷에 도달하는 특정 IP 차단" → NACL 거부 규칙
- "포트 8080에서 인바운드 허용, 서버 응답 자동 허용" → 보안 그룹(상태가 있는)
- "엣지에서 SQL 인젝션으로부터 웹 애플리케이션 보호" → WAF와 SQL 인젝션 규칙
- "침해된 IAM 자격증명 감지" → GuardDuty

---

**태스크 1.3 — 적절한 데이터 보안 제어 결정**

핵심 개념: 저장 시 및 전송 중 암호화, KMS, Secrets Manager, Parameter Store, S3 서버 측 암호화.

| 챕터 | 주제 |
|---|---|
| 16장 | KMS: 고객 관리 키, 키 교체, 봉투 암호화 |
| 16장 | Secrets Manager: 자동 자격증명 교체, 런타임 시크릿 검색 |
| 5장 | S3 암호화 옵션: SSE-S3, SSE-KMS, SSE-C |
| 8장 | 저장 시 RDS 암호화(생성 시 활성화해야 함) |

핵심 시험 패턴:

- "데이터베이스 자격증명 자동 교체" → RDS 통합이 있는 Secrets Manager
- "계정 전체에 걸쳐 암호화 키를 사용하는 사람 제어" → KMS 키 정책
- "민감하지 않은 설정 값 저장" → SSM Parameter Store(Secrets Manager 아님)
- "회사 관리 키로 S3 객체 암호화" → CMK가 있는 SSE-KMS

## 도메인 2: 탄력적 아키텍처 설계 (26%)

**태스크 2.1 — 확장 가능하고 느슨하게 결합된 아키텍처 설계**

핵심 개념: Auto Scaling, 로드 밸런서, SQS/SNS 분리, Lambda 이벤트 트리거, ECS/EKS, Step Functions.

| 챕터 | 주제 |
|---|---|
| 7장 | Auto Scaling Groups, Application Load Balancer, 확장 정책 |
| 19장 | SQS(큐를 사용한 분리), SNS(팬 아웃 알림) |
| 20장 | Lambda: 서버리스 컴퓨팅, 이벤트 트리거, 동시성 |
| 21장 | ECS 및 EKS: 컨테이너화된 마이크로서비스 |
| 22장 | Step Functions: 워크플로우 오케스트레이션 |
| 26장 | Kinesis: 실시간 데이터 스트리밍 |

핵심 시험 패턴:

- "주문 처리를 인벤토리 업데이트와 분리" → 서비스 간 SQS 큐
- "새 주문이 들어올 때 여러 서비스에 알림" → SQS 구독이 있는 SNS 토픽(팬 아웃)
- "S3 업로드를 자동으로 처리" → S3 이벤트 알림 → Lambda
- "재시도 로직이 있는 다중 단계 워크플로우 실행" → Step Functions

---

**태스크 2.2 — 고가용성 및/또는 내고장성 아키텍처 설계**

핵심 개념: 멀티 AZ, 멀티 리전, Route 53 장애 조치, RDS 읽기 복제본, Aurora 글로벌 데이터베이스, 백업 및 복원.

| 챕터 | 주제 |
|---|---|
| 2장 | AWS 글로벌 인프라: 리전, AZ, 엣지 로케이션 |
| 7장 | 여러 AZ에 걸친 ALB, ASG가 비정상 인스턴스 교체 |
| 8장 | RDS 멀티 AZ: 동기적 복제, 자동 장애 조치 |
| 12장 | Route 53: 장애 조치 라우팅, 지연 시간 라우팅, 상태 확인 |
| 18장 | 멀티 AZ vs. 멀티 리전: RTO/RPO, DR 전략(파일럿 라이트, 웜 스탠바이, 액티브-액티브) |
| 24장 | Aurora 글로벌 데이터베이스: 교차 리전 읽기 복제본, <1초 복제 지연 |

핵심 시험 패턴:

- "기본 RDS 실패 시 자동 장애 조치" → RDS 멀티 AZ(읽기 복제본이 아님)
- "전 세계적으로 낮은 지연으로 읽기 제공" → Aurora 글로벌 데이터베이스
- "기본 서버를 사용할 수 없으면 트래픽을 보조 리전으로 라우팅" → 상태 확인이 있는 Route 53 장애 조치 라우팅
- "RTO 1분, RPO 0" → 멀티 AZ 배포(멀티 리전 아님)
- "RTO 15분, 교차 리전" → 파일럿 라이트 전략

## 도메인 3: 고성능 아키텍처 설계 (24%)

**태스크 3.1 — 고성능 및/또는 확장 가능한 스토리지 솔루션 결정**

핵심 개념: S3 vs. EBS vs. EFS, 스토리지 클래스 선택, S3 Transfer Acceleration, 멀티파트 업로드, 자산용 CloudFront.

| 챕터 | 주제 |
|---|---|
| 5장 | S3: 객체 스토리지, 스토리지 클래스, 버전 관리, 수명주기 |
| 6장 | EBS: 블록 스토리지 유형(gp3, io2, st1), EFS: 공유 파일 스토리지 |
| 23장 | S3 스토리지 클래스 전환, Glacier 검색 옵션 |
| 28장 | EBS 적절한 크기 조정, gp2→gp3 마이그레이션, 스냅샷 관리 |

핵심 시험 패턴:

- "여러 EC2 인스턴스에서 접근 가능한 공유 파일 시스템" → EFS(EBS 아님; EBS는 하나의 인스턴스에 연결됨)
- "데이터베이스 워크로드에 높은 IOPS" → io2 EBS
- "90일 후 접근하지 않는 파일 비용 줄이기" → S3 수명주기 정책 → Glacier
- "먼 위치에서 큰 파일 더 빠르게 업로드" → S3 Transfer Acceleration

---

**태스크 3.2 — 고성능 및/또는 확장 가능한 컴퓨팅 솔루션 결정**

핵심 개념: EC2 인스턴스 패밀리, Graviton 프로세서, Auto Scaling, Lambda, Fargate, Spot 인스턴스.

| 챕터 | 주제 |
|---|---|
| 4장 | EC2 인스턴스 유형: 컴퓨팅 최적화(c), 메모리 최적화(r), 범용(m, t) |
| 7장 | Auto Scaling: 웹 계층을 위한 수평 확장 |
| 20장 | Lambda: 동시성, 프로비저닝된 동시성(일관된 지연을 위해) |
| 21장 | ECS Fargate: 서버리스 컨테이너 |
| 27장 | 내고장성 배치 워크로드를 위한 Spot 인스턴스 |

핵심 시험 패턴:

- "ML 훈련 워크로드, 비용 최소화, 중단 가능" → Spot 인스턴스
- "일관된 서브 100ms Lambda 응답" → 프로비저닝된 동시성(콜드 스타트 없앰)
- "인프라 관리 없는 컨테이너화된 마이크로서비스" → ECS Fargate

---

**태스크 3.3 — 고성능 데이터베이스 솔루션 결정**

핵심 개념: RDS vs. DynamoDB vs. Aurora vs. Redshift vs. ElastiCache, 접근 패턴, 읽기 복제본, DAX.

| 챕터 | 주제 |
|---|---|
| 8장 | RDS: 관리형 관계형 데이터베이스, 언제 RDBMS를 사용하는가 |
| 9장 | DynamoDB: NoSQL, 파티션 키, GSI, DAX(인메모리 캐시) |
| 10장 | ElastiCache: Redis vs. Memcached, 캐시 전략 |
| 24장 | Aurora: 성능, Serverless v2, 읽기 복제본, 글로벌 데이터베이스 |
| 29장 | DynamoDB 온디맨드 vs. Auto Scaling이 있는 프로비저닝 용량 |

핵심 시험 패턴:

- "세션 저장소에 마이크로초 읽기" → ElastiCache Redis 또는 DAX(DynamoDB 백엔드의 경우)
- "유연한 스키마로 높은 처리량 키-값 접근" → DynamoDB
- "복잡한 조인 및 ACID 트랜잭션" → Aurora 또는 RDS
- "페타바이트의 구조화된 데이터 분석" → Redshift(자세히 다루지 않지만 신호: "데이터 웨어하우스" → Redshift)

---

**태스크 3.4 — 고성능 및/또는 확장 가능한 네트워크 아키텍처 결정**

핵심 개념: CloudFront, Global Accelerator, Direct Connect, VPN, 배치 그룹, 향상된 네트워킹.

| 챕터 | 주제 |
|---|---|
| 12장 | Route 53: 라우팅 정책: 지연 시간 기반, 지리적 위치, 가중치 |
| 13장 | CloudFront: CDN, 엣지 캐싱, Lambda@Edge |
| 25장 | Direct Connect: 전용 프라이빗 연결 |
| 25장 | AWS Global Accelerator: 가장 가까운 AWS 엣지로의 Anycast 라우팅 |
| 30장 | VPC 엔드포인트: AWS 서비스에 대한 프라이빗 연결 |

핵심 시험 패턴:

- "동적 API 응답에 접근하는 전 세계 사용자의 지연 줄이기" → Global Accelerator(캐시 가능한 콘텐츠에 최적인 CloudFront가 아님)
- "전 세계 정적 자산의 지연 줄이기" → CloudFront
- "AWS로의 일관된 프라이빗 연결" → Direct Connect
- "전 세계 고객이 S3 버킷에 빠르게 업로드" → S3 Transfer Acceleration

---

**태스크 3.5 — 고성능 데이터 수집 및 변환 솔루션 결정**

핵심 개념: Kinesis Data Streams, Kinesis Firehose, Glue, Athena, EMR.

| 챕터 | 주제 |
|---|---|
| 26장 | Kinesis Data Streams: 실시간 순서가 있는 이벤트 처리 |
| 26장 | Kinesis Data Firehose: S3, Redshift, OpenSearch에 관리형 배달 |
| 26장 | AWS Glue: 서버리스 ETL, Data Catalog, Crawlers |
| 26장 | Athena: S3에서 서버리스 SQL |

핵심 시험 패턴:

- "실시간으로 클릭스트림 데이터 처리" → Kinesis Data Streams + Lambda 또는 KDA
- "나중에 분석하기 위해 스트리밍 데이터를 S3에 배달" → Kinesis Firehose
- "여러 소스의 데이터를 변환하고 카탈로그화" → AWS Glue
- "SQL로 S3에 저장된 이력 데이터 쿼리" → Athena

## 도메인 4: 비용 최적화 아키텍처 설계 (20%)

**태스크 4.1 — 비용 최적화 스토리지 솔루션 설계**

| 챕터 | 주제 |
|---|---|
| 23장 | S3 수명주기 정책, 스토리지 클래스 전환 |
| 28장 | EBS 적절한 크기 조정, gp2→gp3 마이그레이션, S3 버전 관리 수명주기 규칙 |
| 28장 | EFS Intelligent-Tiering, 비용 할당 태그, AWS Budgets |

핵심 시험 패턴:

- "어떤 팀이 S3 비용을 가장 많이 발생시키는지 식별" → 비용 할당 태그 + Cost Explorer
- "접근하지 않는 객체의 비용 자동으로 줄이기" → S3 Intelligent-Tiering
- "월 비용이 $10,000을 초과할 때 알림" → AWS Budgets

---

**태스크 4.2 — 비용 최적화 컴퓨팅 솔루션 설계**

| 챕터 | 주제 |
|---|---|
| 27장 | EC2 가격: 온디맨드, Reserved Instances, Savings Plans, Spot, Dedicated Hosts |
| 20장 | Lambda: 호출당 지불(유휴 비용 없음) |

핵심 시험 패턴:

- "안정적인 프로덕션 워크로드 비용 줄이기" → Savings Plans(더 유연함) 또는 Reserved Instances
- "중단될 수 있는 배치 작업 비용 최소화" → Spot 인스턴스
- "유휴 비용 없는 이벤트 기반 처리" → Lambda

---

**태스크 4.3 — 비용 최적화 데이터베이스 솔루션 설계**

| 챕터 | 주제 |
|---|---|
| 29장 | DynamoDB 온디맨드 vs. Auto Scaling이 있는 프로비저닝 |
| 29장 | RDS 및 ElastiCache Reserved Instances/Nodes |
| 29장 | RDS 스냅샷 관리 |

핵심 시험 패턴:

- "예측 불가능한 DynamoDB 트래픽" → 온디맨드 용량 모드
- "알려진 피크가 있는 일관된 DynamoDB 트래픽" → Auto Scaling이 있는 프로비저닝
- "안정적인 워크로드의 RDS 비용 줄이기" → Reserved Instances(1년 또는 3년)

---

**태스크 4.4 — 비용 최적화 네트워크 아키텍처 설계**

| 챕터 | 주제 |
|---|---|
| 30장 | 데이터 전송 가격: 인바운드(무료), 교차 AZ($0.01/GB), 교차 리전, 인터넷($0.09/GB) |
| 30장 | NAT 게이트웨이($0.045/GB) vs. VPC 엔드포인트(게이트웨이: 무료; 인터페이스: 가격 있음) |
| 30장 | 데이터 전송 비용 최적화 도구로서의 CloudFront |

핵심 시험 패턴:

- "S3 접근을 위해 EC2가 프라이빗 서브넷에 있음 — NAT 게이트웨이 비용 없애기" → S3 게이트웨이 엔드포인트(무료)
- "SQS 접근을 위해 EC2가 프라이빗 서브넷에 있음 — NAT 게이트웨이 비용 줄이기" → SQS 인터페이스 엔드포인트
- "전 세계 콘텐츠 배달을 위한 데이터 전송 비용 줄이기" → CloudFront(캐싱이 오리진 요청을 줄인다)

## 시험 전 체크리스트

시험에 앉기 전:

**높은 비중 영역(가장 자주 나타남)**

- [ ] IAM 정책 평가 로직(명시적 거부 → 명시적 허용 → 암묵적 거부)
- [ ] VPC 구성 요소: 서브넷, 라우팅 테이블, IGW, NAT 게이트웨이, 보안 그룹, NACL
- [ ] S3 스토리지 클래스 및 각각을 언제 사용하는가
- [ ] RDS 멀티 AZ vs. 읽기 복제본(장애 조치 vs. 읽기 확장)
- [ ] SQS vs. SNS vs. EventBridge(풀 vs. 푸시 vs. 이벤트 라우팅)
- [ ] EC2 가격 모델: 내고장성에는 Spot, 약정 워크로드에는 Savings Plans
- [ ] Lambda 트리거 및 동시성
- [ ] DynamoDB vs. Aurora vs. Redshift(접근 패턴이 선택을 결정)
- [ ] CloudFront: 정적에는 CDN, 동적에는 Global Accelerator

**흔한 함정**

- [ ] EBS는 하나의 인스턴스에 연결됨; EFS는 공유됨
- [ ] RDS 읽기 복제본은 읽기 확장을 위한 것이지, 자동 장애 조치가 아님(그것은 멀티 AZ)
- [ ] NACL은 무상태(인바운드와 아웃바운드 규칙 모두 필요)
- [ ] 게이트웨이 엔드포인트는 무료이고 S3와 DynamoDB에만 해당
- [ ] Kinesis는 보관하고 재생함; SQS는 소비 시 삭제함
- [ ] "분리"가 항상 SQS를 의미하지 않음 — SNS 팬 아웃과 EventBridge도 분리 패턴임
- [ ] Shield Standard는 무료이고 자동; Advanced는 유료 구독

**시험 구조**

- 65개 질문, 130분(2시간 10분)
- 객관식(하나 맞음)과 다중 응답(N개 정답 선택)
- 합격 점수: 1000점 중 720점
- 점수가 없는 질문이 포함됨; 어떤 것인지 알 수 없음
- 시간 관리: 질문당 약 2분; 어려운 것에 플래그를 달고 다시 돌아오기
