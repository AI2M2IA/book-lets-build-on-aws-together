# 부록 D: 전체 모의시험 (65문제)

이것은 전체 길이의 SAA-C03 모의시험입니다. 65문제로 실제 시험의 도메인 비중을 반영합니다 — 보안 아키텍처 설계(1~20번, 약 30%), 탄력적 아키텍처 설계(21~37번, 약 26%), 고성능 아키텍처 설계(38~53번, 약 24%), 비용 최적화 아키텍처 설계(54~65번, 약 20%).

**응시 방법:**

- 타이머를 **130분**으로 설정하십시오 — 실제 시험의 소요 시간입니다. 페이스를 연습하십시오: 문제당 2분입니다.
- 일곱 문제는 **"(두 개 선택.)"**이라고 표시됩니다 — 다섯 개의 선택지와 정확히 두 개의 정답이 있으며, 실제 시험의 다중 응답 문항과 동일합니다. 점수를 얻으려면 둘 다 맞아야 합니다.
- 65문제를 모두 풀기 전에는 정답 키를 보지 마십시오. 실제 시험에서는 진행 도중 피드백이 없으며, 불확실성에 대한 내성을 기르는 것이 준비의 일부입니다.
- 실제 시험에는 식별할 수 없는 15개의 채점되지 않는 실험 문제가 포함됩니다. 여기 있는 65문제는 모두 "채점" 대상입니다. 합격 기준점: **47개 이상 정답(약 72%)**이면 720/1000 환산 합격 점수의 범위에 들어갑니다. 47개 미만이라면, 시험을 예약하기 전에 부록 B에 매핑된, 취약한 도메인의 챕터를 다시 살펴보십시오.
- 틀린 모든 문제 — 그리고 맞았지만 망설였던 모든 문제 — 에 대해 오답 분석을 읽으십시오. 시험은 그럴듯한 선택지들 사이의 *차이*를 테스트하며, 거기에 학습이 있습니다.

**58. 정답: B** — Glacier Flexible Retrieval은 낮은 아카이브 스토리지 비용과 1~5분 내에 데이터를 반환하는 Expedited 검색(약 $0.03/GB)을 제공하여 5분 요구 사항을 충족합니다. *다른 선택지가 아닌 이유:* A — Deep Archive의 가장 빠른 검색은 약 12시간입니다; C — Bulk 검색은 5~12시간이 걸립니다; D — Standard-IA는 즉시 검색되지만 7년간 거의 접근하지 않는 스토리지에 비용이 훨씬 많이 듭니다.

**59. 정답: B** — One Zone-IA는 Standard-IA보다 약 20% 저렴하며, 재생성 가능한 썸네일에는 단일 AZ 내구성 트레이드오프가 허용됩니다. *다른 선택지가 아닌 이유:* A — Standard-IA는 데이터가 필요로 하지 않는 중복성에 더 많은 비용이 듭니다; C — Intelligent-Tiering은 모니터링 수수료를 추가하며 이미 알려진 자주 접근하지 않는 접근에 대해 비용을 최소화하지 않습니다; D — Glacier Instant Retrieval은 이 패턴에 대해 90일 최소와 다른 검색 비용 프로파일을 가집니다.

**60. 정답: A, C** — Intelligent-Tiering은 작은 객체당 모니터링/자동화 수수료를 부과하며, 128KB 미만의 객체는 저장되지만 모니터링되거나 계층화되지 않습니다(Frequent Access 요금으로 청구). *다른 선택지가 아닌 이유:* B — Intelligent-Tiering은 자동 계층 간에 검색 수수료가 없습니다; D — 결코 교차 리전 복제를 하지 않습니다; E — 이 클래스의 모든 객체에 90일 최소가 없습니다.

**61. 정답: B** — 불완전한 멀티파트 업로드 부분은 스토리지로 청구되지만 객체로는 보이지 않습니다; AbortIncompleteMultipartUpload가 있는 수명 주기 규칙이 그것들을 자동으로 삭제합니다. *다른 선택지가 아닌 이유:* A — 버전 관리는 부분을 정리하는 것이 아니라 스토리지를 증가시킵니다; C — 스토리지 클래스 변경은 고아가 된 부분을 제거하지 않습니다; D — Transfer Acceleration은 전송을 가속하지 이미 버려진 업로드를 정리하지 않습니다.

**62. 정답: B** — gp3는 IOPS/처리량을 크기에서 분리하고 gp2보다 GB당 약 20% 저렴하므로, 필요한 IOPS를 유지하면서 용량을 적정 크기로 조정할 수 있습니다; 마이그레이션은 온라인 ModifyVolume 작업입니다. *다른 선택지가 아닌 이유:* A — io2는 더 저렴한 것이 아니라 더 비쌉니다; C — st1은 필요한 IOPS를 제공할 수 없습니다; D — 볼륨 삭제는 실시간 데이터를 파괴합니다.

**63. 정답: B** — S3용 게이트웨이 VPC 엔드포인트는 무료이며 동일 리전 S3 트래픽에 대한 NAT 게이트웨이 데이터 처리 요금을 제거합니다. *다른 선택지가 아닌 이유:* A — NAT 인스턴스도 여전히 EC2 및 운영 비용이 발생합니다; C — 인터페이스 엔드포인트는 시간당 및 GB당 청구되어 무료 게이트웨이 엔드포인트보다 비쌉니다; D — 퍼블릭 서브넷은 퍼블릭 IPv4 요금을 추가하고 보안을 약화시킵니다.

**64. 정답: B, E** — AWS는 사용 중인 모든 퍼블릭 IPv4 주소에 요금을 부과하므로 필요 없는 것을 제거하면 비용이 절감되고, AWS Budgets는 예측/실제 지출에 대한 사전 임계값 경고를 제공합니다. *다른 선택지가 아닌 이유:* A — Elastic IP도 연결된 동안 퍼블릭 IPv4 요금으로 청구됩니다; C — Compute Optimizer는 적정 크기 조정을 권장하지만 지출 임계값을 차단하거나 경고할 수 없습니다; D — Shield Advanced는 비용을 추가하는 DDoS 서비스입니다.

**65. 정답: A** — Aurora Serverless v2는 0 ACU로의 확장(자동 일시 중지, 2024년 말부터 사용 가능)을 지원하고 연결 시 자동으로 재개하여, 수동 단계 없이 유휴 상태일 때 컴퓨팅 비용을 제거합니다. 알아둘 만한 뉘앙스: 자동 일시 중지는 최신 엔진 버전을 요구합니다(Aurora PostgreSQL 13.15+/14.12+/15.7+/16.3+, Aurora MySQL 3.08+); 일시 중지 후 첫 연결은 재개에 약 15초가 걸립니다(24시간 이상 일시 중지된 후에는 더 길어짐); 컴퓨팅이 일시 중지된 동안에도 스토리지는 계속 청구됩니다; 그리고 연결을 열어두는 모든 것 — RDS Proxy, 킵얼라이브 상태 확인 — 은 일시 중지를 완전히 방지합니다. *다른 선택지가 아닌 이유:* B — 중지된 프로비저닝된 클러스터는 개발자가 연결할 때 자동으로 깨어나지 않습니다(그리고 7일 후 재시작됩니다); C — 헤드리스 global database 보조는 유휴 비용이 아니라 DR을 다룹니다; D — 축소된 리더도 여전히 라이터 인스턴스를 실행 상태로 두고 청구합니다.
