# 付録 C: 概念レジストリ

本書で紹介したすべての主要な概念を、その章、使用したアナロジー、登場する SAA-C03 ドメインとともにマッピングしています。

学習インデックスとして使用してください。試験前にある概念があいまいなら、ここで見つけて、文脈を確認するためにその章に戻りましょう。

---

## A

**ACM（AWS Certificate Manager）** — ALB、CloudFront、API Gateway 向けの無料パブリック TLS 証明書。DNS 検証による自動更新付き。CloudFront の証明書は us-east-1 に存在する必要があります。第16章。ドメイン 1。

**ACU（Aurora Capacity Unit）** — Aurora Serverless v2 の容量を測定する単位。自動的にスケールし、サポートされるエンジンバージョンでは、接続が開かれていないときに 0 ACU まで自動的に一時停止できます。第24章。ドメイン 3。

**アラーム（CloudWatch）** — メトリクスがしきい値を超えたときに発火し、通知や自動スケーリングアクションをトリガーするルール。第7章。ドメイン 2。

**ALB（Application Load Balancer）** — パスとホストのルールに基づいて HTTP/HTTPS トラフィックをルーティングする Layer 7 ロードバランサー。第7章。ドメイン 2。

**AMI（Amazon Machine Image）** — EC2 インスタンス向けの OS、ソフトウェア、構成を含むテンプレート。第4章。ドメイン 3。

**アーキテクトの心構え** —「どうやって動くのか？」だけでなく、「最初に何が壊れるのか、どうやってそれを知るのか、午前3時に誰が何をするのか？」を問うこと。第32章、第34章。ドメイン横断。

**アーキテクチャ決定記録（ADR）** — ある決定、その代替案、その根拠、そして再検討を引き起こすであろうことを記録した短いドキュメント。第32章。ドメイン横断。

**アーキテクチャレビュー** — 制約 → 不明点 → 選択肢 → 障害モード → モニタリング → ランブック をカバーする構造化されたプロセス。第32章。ドメイン横断。

**Athena** — S3 内のデータに対するサーバーレス SQL クエリサービス。スキャンした TB ごとに支払います。Parquet/ORC の列指向フォーマットで最も効果を発揮します。第26章。ドメイン 3。

**Auto Scaling Group（ASG）** — まとめて管理される EC2 インスタンスのグループ。異常なインスタンスを自動的に置き換え、負荷に基づいてスケールします。第7章。ドメイン 2, 3。

**Availability Zone（AZ）** — リージョン内の1つ以上の物理的に分離されたデータセンターで、低レイテンシのリンクで接続されています。第2章。ドメイン 2。

## B

**AWS Backup** — EBS、RDS、DynamoDB、EFS、Storage Gateway をまたぐ、一元化されたポリシーベースのバックアップ。クロスリージョンおよびクロスアカウントのコピーをサポートします。第18章、第23章。ドメイン 2。

**AWS Batch** — Docker コンテナ向けのマネージドバッチコンピューティング。ジョブ定義（何を実行するか）、ジョブキュー（ジョブが待機する場所）、コンピューティング環境（EC2 または Fargate、オンデマンドまたはスポット）で構成されます。Lambda の15分制限を超えるワークロード向け。第21章。ドメイン 3。

**バケット（S3）** — S3 オブジェクトのコンテナ。バケットはグローバルに一意な名前を持ち、特定のリージョンに存在します。第5章。ドメイン 3。

**バケットポリシー** — S3 バケットにアタッチされ、IAM プリンシパルと外部アカウントのアクセスを制御するリソースベースのポリシー。第5章。ドメイン 1。

## C

**キャッシュアサイドパターン** — アプリケーションがまずキャッシュをチェックし、ミスの場合はデータベースをクエリして結果をキャッシュに保存します。第10章。ドメイン 3。

**キャッシュヒット率** — オリジンではなくキャッシュから提供されるリクエストの割合。高いほど良いです。第13章。ドメイン 3。

**AWS Client VPN** — マネージドの OpenVPN エンドポイント。個々のデバイス（ノート PC、ワークステーション）をインターネット経由で VPC に接続します。認証は Active Directory、ID プロバイダーとの SAML 2.0 フェデレーション、または相互 TLS 経由。スプリットトンネルとフルトンネルのモードをサポートします。Site-to-Site VPN（ネットワーク間）との対比。第11章。ドメイン 1。

**CloudFront** — AWS の CDN。世界中の 750 以上のエッジロケーションでコンテンツをキャッシュします。レイテンシとオリジンのデータ転送コストを削減します。第13章。ドメイン 3, 4。

**CloudTrail** — すべての AWS API 呼び出しを記録します: 誰が、何を、いつ、どこから。S3 に保存されます。監査とインシデント調査に使用されます。ドメイン 1。

**CloudWatch** — AWS リソースとカスタムアプリケーション向けのメトリクス、ログ、アラーム、ダッシュボード。本書全体で参照。すべてのドメイン。

**Amazon Cognito** — アプリケーションのエンドユーザー向けの認証: User Pool はマネージドなユーザーディレクトリ（サインアップ、サインイン、MFA、ソーシャルログイン、JWT）、Identity Pool は一時的な AWS 認証情報を発行します。IAM はエンジニア向け、Cognito は顧客向け。第14章。ドメイン 1。

**コールドスタート（Lambda）** — Lambda が実行環境を初期化する際の、初回呼び出し時（または非アクティブ後）の遅延。排除するにはプロビジョニング済み同時実行を使用します。第20章。ドメイン 3。

**Compute Savings Plan** — 時間あたりの EC2 支出のドル額に対するコミットメントで、任意のインスタンスタイプまたはサイズに適用されます。第27章。ドメイン 4。

**Config（AWS）** — AWS リソースの構成変更を時間の経過とともに追跡し、ルールに照らしてコンプライアンスを評価します。第31章。ドメイン 1。

**AWS Control Tower** — マルチアカウントガバナンスを自動化します: ガードレール付きのランディングゾーン（管理、ログアーカイブ、監査の各アカウント）を数分で構築します — Organizations、CloudTrail、Config を手作業で配線することの既製版です。第14章。ドメイン 1。

**AZ をまたぐデータ転送** — リージョン内の Availability Zone 間のトラフィック。各方向 $0.01/GB で課金されます。第30章。ドメイン 4。

**クロスリージョンレプリケーション** — データ（S3 CRR、Aurora Global、DynamoDB Global Tables）を別のリージョンにコピーすること。データ転送料金が発生します。第18章、第23章、第30章。ドメイン 2。

## D

**AWS DataSync** — ファイル共有（NFS/SMB）を S3、EFS、または FSx に移行・同期する、エージェントベースのサービス。「AWS コンソール付きの強化版 rsync」。第25章。ドメイン 3。

**DAX（DynamoDB Accelerator）** — DynamoDB 専用のインメモリキャッシュ。マイクロ秒の読み取りレイテンシ。第9章。ドメイン 3。

**デッドレターキュー（DLQ）** — 処理に繰り返し失敗したメッセージが送られるキューで、キューの詰まりを防ぎます。第19章。ドメイン 2。

**AWS DMS（Database Migration Service）** — 最小限のダウンタイムでデータベースを AWS に移行します。フルロード（初回コピー）に加えて CDC（Change Data Capture）が、移行中にソースとターゲットを同期させ続けます。同種移行（同じエンジンタイプ）: DMS を直接使用します。異種移行（異なるエンジンタイプ、例: Oracle → Aurora PostgreSQL）: まず SCT（Schema Conversion Tool）、その後 DMS を使用します。第8章。ドメイン 3。

**Dedicated Host** — 専有のために予約された物理 EC2 サーバー。特定のソフトウェアライセンスに必要です。第27章。ドメイン 4。

**多層防御** — 複数のセキュリティ制御（IAM + セキュリティグループ + NACL + WAF + GuardDuty）を重ねることで、1つの層の侵害がシステムを露出させないようにすること。第33章。ドメイン 1。

**Direct Connect** — オンプレミスの場所から AWS への専用プライベートネットワーク接続。VPN より一貫性があります。第25章。ドメイン 3。

**DLQ** — デッドレターキューを参照。

**DynamoDB** — あらゆる規模で1桁ミリ秒のレイテンシを実現するフルマネージドの NoSQL データベース。キーバリューおよびドキュメントモデル。第9章。ドメイン 3。

**DynamoDB Auto Scaling** — CloudWatch メトリクスに基づいてプロビジョンド読み取り/書き込み容量を自動的に調整します。第29章。ドメイン 4。

**DynamoDB Streams** — DynamoDB テーブル内のすべての項目変更の時系列順の変更ログ。イベント駆動処理のために Lambda とともに使用されます。第9章。ドメイン 2。

---

## E

**EBS（Elastic Block Store）** — 単一の EC2 インスタンスにアタッチされるブロックストレージ。独立して永続します。タイプ: gp3、io2、st1。第6章。ドメイン 3。

**EC2（Elastic Compute Cloud）** — クラウド上の仮想マシン。第4章。ドメイン 3。

**ECS（Elastic Container Service）** — マネージドなコンテナオーケストレーション。Fargate 起動タイプはサーバー管理を排除します。第21章。ドメイン 2, 3。

**EFS（Elastic File System）** — 複数の EC2 インスタンスからアクセスできる共有 NFS ファイルシステム。自動的にスケールします。ストレージクラスには Standard、Infrequent Access、Archive があり、Intelligent-Tiering が階層間の自動移動を行います。第6章。ドメイン 3。

**EKS（Elastic Kubernetes Service）** — AWS 上のマネージド Kubernetes コントロールプレーン。第21章。ドメイン 3。

**Elastic Disaster Recovery（DRS）** — サーバー（オンプレミスまたは EC2）を低コストなステージング領域に継続的にブロックレベルで複製し、数分でリカバリインスタンスを起動します — マネージドな pilot light。第18章。ドメイン 2。

**ElastiCache** — マネージドなインメモリキャッシング。Redis（より豊富な機能）または Memcached（よりシンプル）。第10章。ドメイン 3。

**Elastic IP** — 割り当てて EC2 インスタンスに再関連付けできる静的なパブリック IP アドレス。第11章。ドメイン 3。

**エンベロープ暗号化** — データがデータキー（DEK）で暗号化され、DEK がマスターキー（KMS の CMK）で暗号化されるパターン。第16章。ドメイン 1。

**EventBridge** — AWS サービス、SaaS パートナー、カスタムソースからのイベントをターゲットにルーティングするイベントバス。スケジュールされたルールをサポートします。第22章。ドメイン 2。

**明示的な拒否** — どの許可によっても上書きできない IAM の拒否ステートメント。すべての許可に優先します。第3章。ドメイン 1。

## F

**フェイルオーバールーティング（Route 53）** — プライマリがヘルスチェックに失敗したときにセカンダリエンドポイントにトラフィックをルーティングします。第12章。ドメイン 2。

**Fargate** — ECS と EKS 向けのサーバーレスコンピューティングエンジン。管理する EC2 インスタンスはありません。第21章。ドメイン 3。

**ファンアウトパターン** — 1つの SNS トピックが同じメッセージを複数の SQS キューに同時に配信します。第19章。ドメイン 2。

**FIFO キュー（SQS）** — 厳密に1回の処理、厳格な順序付け。標準キューより低いスループット。第19章。ドメイン 2。

**障害モード** — システムが失敗しうる特定の方法。プロダクション前に障害モードを特定することがアーキテクチャレビューの中核です。第32章。ドメイン横断。

---

## G

**ゲートウェイエンドポイント** — S3 と DynamoDB 向けの無料の VPC エンドポイントタイプ。トラフィックを AWS のプライベートネットワーク経由でルーティングし、NAT Gateway の料金を排除します。第30章。ドメイン 4。

**Gateway Load Balancer（GWLB）** — サードパーティの仮想ネットワークアプライアンス（ファイアウォール、IDS/IPS）をトラフィックフローにインラインで挿入するための Layer 3 ロードバランサー。第7章。ドメイン 1。

**位置情報ルーティング（Route 53）** — DNS クエリ発生元の地理的な場所に基づいてルーティングします。第12章。ドメイン 3。

**Global Accelerator** — Anycast 経由で最も近い AWS エッジにトラフィックをルーティングし、動的アプリケーションのレイテンシを向上させます。第25章。ドメイン 3。

**Glue（AWS）** — サーバーレス ETL。Glue クローラーがスキーマを検出し、Glue ジョブがデータを変換し、Data Catalog がメタデータを保存します。第26章。ドメイン 3。

**GSI（Global Secondary Index）** — DynamoDB テーブル上の、異なるパーティションキーとオプションのソートキーを持つ代替インデックス。柔軟なクエリパターンを可能にします。第9章。ドメイン 3。

**GuardDuty** — CloudTrail、VPC フローログ、DNS ログに対して ML を使用し、異常なアクティビティを検出する脅威検出サービス。第17章。ドメイン 1。

---

## H

**ヘルスチェック（Route 53）** — エンドポイントの可用性を監視します。失敗したヘルスチェックがフェイルオーバールーティングをトリガーします。第12章。ドメイン 2。

**ホットパーティション（DynamoDB）** — 多くのリクエストが同じパーティションキーを共有するために、不均衡なトラフィックを受けるパーティション。第9章。ドメイン 3。

---

## I

**IAM（Identity and Access Management）** — AWS アカウントの認証と認可を制御します。ユーザー、グループ、ロール、ポリシー。第3章、第14章。ドメイン 1。

**IAM ロール** — 一時的な認証情報を持つ IAM アイデンティティで、サービス、ユーザー、または他のアカウントによって引き受けられます。第3章、第14章。ドメイン 1。

**冪等性** — 1回呼ばれても何度呼ばれても同じ結果を生み出す操作の性質。分散システム（返金、支払い、注文処理）にとって重要です。第32章。ドメイン横断。

**冪等性キー** — 操作の一意な識別子で、重複処理を防ぐために実行前にチェックされます。第32章。ドメイン横断。

**インターフェイスエンドポイント（PrivateLink）** — ほとんどの AWS サービス向けの VPC エンドポイント。1時間あたり + 1GB あたりの料金。インターネットや NAT なしでプライベート接続を提供します。第30章。ドメイン 4。

**Internet Gateway（IGW）** — パブリックサブネットのインスタンスがインターネットと通信できるようにします。サブネットのルートテーブルに IGW へのルートが必要です。第11章。ドメイン 3。

**「場合による」** — ほとんどのアーキテクチャの問いに対する誠実な答え。常に次のように完結させなければなりません:「アクセスパターン / 規模 / 障害の影響 / コスト制約 による」。第33章。ドメイン横断。

## K

**Kinesis Data Firehose** — Amazon Data Firehose の旧名: ストリーミングデータを S3、Redshift、OpenSearch にマネージド配信。コンシューマー管理なし。古い試験問題では旧名が使われている場合があります。第26章。ドメイン 3。

**Kinesis Data Streams** — リアルタイムの順序付きイベントストリーム。耐久性があり、保持ウィンドウ内で再生可能（デフォルト24時間、最大365日）。シャードで測定されます。第26章。ドメイン 3。

**KMS（Key Management Service）** — 保存時暗号化のための暗号化キーを作成、保存、制御します。第16章。ドメイン 1。

---

## L

**Lambda** — イベントによってトリガーされるサーバーレス関数。呼び出しごとおよび ms ごとに支払います。最大実行時間15分。第20章。ドメイン 2, 3, 4。

**Lambda@Edge** — CloudFront エッジロケーションで実行され、リクエストとレスポンスを変更する Lambda 関数。第13章。ドメイン 3。

**AWS Lake Formation** — S3 と Glue Data Catalog の上に位置する、一元化されたデータレイクのアクセス制御層。テーブル、列、行のレベルできめ細かい権限を提供します。セキュアなデータレイクのセットアップを簡素化します。第26章。ドメイン 3。

**レイテンシーベースルーティング（Route 53）** — 測定されたレイテンシが最も低い AWS リージョンに DNS クエリをルーティングします。第12章。ドメイン 3。

**起動テンプレート** — Auto Scaling Group 向けの EC2 インスタンス構成を指定する、バージョン管理されたテンプレート。第7章。ドメイン 3。

**最小権限** — IAM のベストプラクティス: 必要な権限だけを付与し、それ以上は付与しません。第3章。ドメイン 1。

**ライフサイクルポリシー（S3）** — 経過日数に基づいて、オブジェクトをより安価なストレージクラスに自動的に移行したり削除したりするルール。第23章。ドメイン 4。

**LSI（Local Secondary Index）** — 同じパーティションキーを使うが異なるソートキーを使う、DynamoDB テーブル上の代替インデックス。テーブル作成時に作成する必要があります。第9章。ドメイン 3。

---

## M

**Amazon Macie** — S3 内の機密データ（PII）の ML ベースの検出と、露出リスクのフラグ付け。GuardDuty は動作を監視し、Macie は保存されているものを監査します。第17章。ドメイン 1。

**Memcached** — シンプルでマルチスレッドのインメモリキャッシングエンジン。永続化なし、データ構造なし。マルチスレッドが機能と引き換えに特に必要でない限り、Redis を使用します。第10章。ドメイン 3。

**Amazon MemoryDB for Redis** — 耐久性のある、Redis 互換のインメモリプライマリデータベース。ElastiCache とは異なり、MemoryDB は Multi-AZ トランザクションログに書き込み、データの耐久性を保証します。Redis API 互換性が必要かつデータ損失が許容されない場合に使用します。第10章。ドメイン 3。

**MGN（AWS Application Migration Service）** — リホスト/リフトアンドシフト: サーバー全体を AWS にブロックレベルで複製し、テスト起動を行い、その後ネイティブな EC2 インスタンスにカットオーバーします。DataSync はファイルを移動、DMS はデータベースを移動、MGN はサーバーを移動。第25章。ドメイン 3。

**Amazon MQ** — 標準プロトコル（AMQP、MQTT、STOMP）を話すマネージドな ActiveMQ/RabbitMQ ブローカー。既存のブローカーワークロードをコード変更なしでリフトアンドシフトするため向け。グリーンフィールドのメッセージング → SQS/SNS。第19章。ドメイン 2。

**Multi-AZ（RDS）** — 自動フェイルオーバー付きの、別の AZ にある同期スタンバイレプリカ。RPO ～0、RTO ～60秒。高可用性向けで、読み取りスケーリング向けではありません。第8章、第18章。ドメイン 2。

**Multi-Region** — 地理的冗長性とグローバルなパフォーマンスのために、アプリケーションコンポーネントを複数の AWS リージョンにわたってデプロイすること。複雑さとコストが高くなります。第18章。ドメイン 2。

---

## N

**Network Load Balancer（NLB）** — Layer 4（TCP/UDP/TLS）ロードバランサー: 毎秒数百万リクエスト、AZ ごとの静的 IP、ソース IP を保持。HTTP の認識はなし — それは ALB の仕事です。第7章。ドメイン 3。

**NACL（Network Access Control List）** — サブネットレベルのステートレスなファイアウォール。インバウンドとアウトバウンドの両方のルールが必要。ルールは数値順に評価されます。第15章。ドメイン 1。

**NAT Gateway** — プライベートサブネットのインスタンスがインターネットへのアウトバウンド接続を行えるようにします。処理 $0.045/GB で課金されます。第11章、第30章。ドメイン 4。

---

## O

**オブジェクト（S3）** — S3 に保存されるファイル。キー（名前）、値（データ）、メタデータで構成されます。最大サイズ 5TB。第5章。ドメイン 3。

**オンデマンド容量（DynamoDB）** — リクエストごとの支払いモード。プロビジョンドよりリクエストあたりは高価ですが、容量計画は不要です。第29章。ドメイン 4。

**オンデマンドインスタンス（EC2）** — コミットメントなしで1時間あたりの支払い。最大の柔軟性、最大の価格。第27章。ドメイン 4。

**AWS Outposts** — 顧客自身のデータセンターやコロケーション施設に設置される、フルマネージドの AWS ハードウェアラック。パブリッククラウドと同じ AWS サービス、API、ツールをオンプレミスで実行します。AWS が設置とパッチ適用を管理し、顧客がラックスペースと電源を提供します。データレジデンシー、低レイテンシのオンプレミスワークロード、または切断シナリオ向け。第2章。ドメイン 4。

---

## P

**パーティションキー（DynamoDB）** — どのパーティションが項目を保存するかを決定するプライマリキーの構成要素。均等な分散のために高カーディナリティのキーを選びます。第9章。ドメイン 3。

**アクセス許可境界** — 他のポリシーがより多くを付与しても、IAM アイデンティティが持てる最大権限を設定する IAM ポリシー。第14章。ドメイン 1。

**配置グループ** — レイテンシを最小化（cluster）または可用性を最大化（spread）するために EC2 インスタンスの物理的な配置を制御します。第4章。ドメイン 3。

**PrivateLink** — AWS でホストされるサービスへのプライベートエンドポイントを作成するための AWS サービスで、インターフェイスエンドポイント経由でアクセスできます。第30章。ドメイン 1。

**プロビジョニング済み同時実行（Lambda）** — コールドスタートの遅延を排除する、事前初期化された実行環境。第20章。ドメイン 3。

**プロビジョンド容量（DynamoDB）** — 事前に割り当てられた読み取りおよび書き込みスループットで、毎秒の容量ユニットで測定されます。予測可能なトラフィックでは、オンデマンドより安価です。第9章、第29章。ドメイン 4。

---

## Q

**Amazon QuickSight** — マネージドなビジネスインテリジェンスおよびデータ可視化サービス。SPICE（Super-fast, Parallel, In-memory Calculation Engine）を使用してデータをキャッシュし、高速なダッシュボードレンダリングを実現します。Athena、S3、Redshift、RDS、その他の AWS データソースに接続します。管理する BI サーバーはありません。第26章。ドメイン 3。

---

## R

**RDS（Relational Database Service）** — マネージドリレーショナルデータベース。バックアップ、パッチ適用、フェイルオーバーを処理します。第8章。ドメイン 3。

**RDS Proxy** — Lambda/アプリケーションと RDS の間の接続プールを管理し、接続枯渇を防ぎます。第8章。ドメイン 3。

**リードレプリカ（RDS）** — 読み取りスケーリングのためのデータベースの非同期コピー。自動フェイルオーバーは提供しません。第8章、第24章。ドメイン 3。

**Redis** — キャッシング、セッション管理、リアルタイムリーダーボード、pub/sub に使用されるインメモリデータ構造ストア。第10章。ドメイン 3。

**Reserved Instance（EC2）** — 割引と引き換えに、特定のリージョンの特定のインスタンスタイプを1年または3年使用するコミットメント。第27章。ドメイン 4。

**Route 53** — AWS の DNS サービスおよびドメインレジストラー。複数のルーティングポリシーをサポートします。第12章。ドメイン 2, 3。

**RPO（Recovery Point Objective）** — 時間で測定される、許容される最大のデータ損失。「どれだけのデータを失う余裕があるか？」第18章。ドメイン 2。

**RTO（Recovery Time Objective）** — 障害後にサービスを復旧するための許容される最大時間。「どれだけの間ダウンしていられるか？」第18章。ドメイン 2。

**ランブック** — システムを運用するための、特にインシデント対応のためのステップバイステップの指示。「午前3時に誰が何をするのか？」第32章。ドメイン横断。

---

## S

**S3 Intelligent-Tiering** — アクセスパターンに基づいて S3 オブジェクトをアクセス階層間で自動的に移動します。取得料金なし。第23章。ドメイン 4。

**S3 Select** — SQL 式を使って S3 オブジェクトコンテンツのサブセットを取得し、データ転送を削減します。レガシー: 2024年半ば以降、新規顧客は利用できません — Athena が現在、S3 内のデータをフィルタリング・クエリする主要な手段です。かつて推奨された代替手段だった S3 Object Lambda 自体もレガシーです（2025年11月に新規顧客の受付を終了。既存のワークロードは引き続き動作します）。第30章。ドメイン 4。

**Savings Plan** — 割引と引き換えに時間あたりの支出のドル額にコミットする柔軟な料金モデル。Reserved Instances より柔軟です。第27章。ドメイン 4。

**SCP（Service Control Policy）** — OU 内のアカウントが利用できる最大権限を制限する AWS Organizations のポリシー。第14章。ドメイン 1。

**Secrets Manager** — シークレット（データベースパスワード、API キー）を保存し、自動的にローテーションします。第16章。ドメイン 1。

**セキュリティグループ** — インスタンスレベルのステートフルな仮想ファイアウォール。許可ルールのみ、戻りトラフィックは自動。第15章。ドメイン 1。

**シャード（Kinesis）** — Kinesis Data Streams におけるスループットの基本単位: 書き込み 1 MB/秒、読み取り 2 MB/秒。第26章。ドメイン 3。

**責任共有モデル** — AWS はクラウド*の*セキュリティ（インフラ）に責任を負い、ユーザーはクラウド*内の*セキュリティ（データ、構成、アクセス）に責任を負います。第1章。ドメイン 1。

**Shield** — DDoS 保護。Standard: 無料、自動。Advanced: 有料、DRT サポートと財務的保護付き。第17章。ドメイン 1。

**Snow ファミリー** — オフラインの大量データ転送向けの物理デバイス（Snowball Edge: 80 TB）— 高速道路を運転する代わりに貨物便をチャーターするようなもの。レガシー（2026年）: Snowmobile と Snowcone は提供終了、Snow デバイスは2025年11月に新規顧客の受付を終了（AWS は DataSync と Data Transfer Terminals を案内）。しかし SAA-C03 試験では「数週間の転送、限られた帯域幅」に対して依然として Snowball が期待されます。第25章。ドメイン 3。

**SNS（Simple Notification Service）** — Pub/sub メッセージング。すべてのサブスクライバーに同時にメッセージをプッシュします。ファンアウトパターン。第19章。ドメイン 2。

**ソートキー（DynamoDB）** — プライマリキーのオプションの第2構成要素。パーティション内での範囲クエリを可能にします。第9章。ドメイン 3。

**スポットインスタンス** — 60～90% の割引でスペア容量を使用する EC2 インスタンス。2分の通知で中断される可能性があります。フォールトトレラントなワークロード専用。第27章。ドメイン 4。

**SQS（Simple Queue Service）** — マネージドなメッセージキュー。プロデューサーとコンシューマーを疎結合にします。標準（最低1回）と FIFO（厳密に1回）のキュー。第19章。ドメイン 2。

**Step Functions** — サーバーレスのワークフローオーケストレーションサービス。AWS サービスを協調させるためのステートマシン。第22章。ドメイン 2。

**AWS Storage Gateway** — オンプレミスとクラウドストレージの間の橋渡し: NFS/SMB（File）、iSCSI（Volume）、または仮想テープ（Tape）のインターフェイスをローカルで提示しつつ、データを S3、Glacier、または EBS スナップショットとして永続化します。第6章。ドメイン 3。

## T

**ターゲット追跡スケーリング** — ターゲットメトリクス値（例: 60% の CPU 使用率）を維持するように容量を調整する Auto Scaling ポリシー。第7章。ドメイン 2。

**AWS Transfer Family** — S3 または EFS をバッキングとするマネージドな SFTP/FTPS/FTP エンドポイント。パートナーは既存の SFTP クライアントをそのまま使い、ファイルは直接あなたのバケットに格納されます。第25章。ドメイン 3。

**Transit Gateway** — 中央のゲートウェイを通じて複数の VPC とオンプレミスネットワークを接続する、ハブアンドスポーク型ネットワークトポロジ。第25章。ドメイン 3。

**TTL（Time to Live）** — その後 DynamoDB が項目を自動的に削除するタイムスタンプ。DNS（リゾルバがレコードをキャッシュする時間）やキャッシング（キャッシュされた値が有効な時間）でも使用されます。第9章、第12章。ドメイン 3。

---

## V

**VIF（Virtual Interface）** — AWS Direct Connect で使用される論理接続。Public VIF は AWS のパブリックエンドポイントにアクセスし、Private VIF は VPC リソースにアクセスします。第25章。ドメイン 3。

**可視性タイムアウト（SQS）** — 受信したメッセージが他のコンシューマーから隠される期間。他のコンシューマーが同じメッセージを見ることなく処理できるようにします。第19章。ドメイン 2。

**VPC（Virtual Private Cloud）** — AWS 内の隔離された仮想ネットワーク。サブネット、ルートテーブル、ゲートウェイを含みます。第11章。ドメイン 1。

**VPC エンドポイント** — VPC リソースを AWS のプライベートネットワーク経由で AWS サービスに接続します。ゲートウェイ（無料、S3/DynamoDB）とインターフェイス（有料、その他のほとんどのサービス）。第30章。ドメイン 1, 4。

**VPC フローログ** — VPC 内のネットワークインターフェイスとの間で行き来する IP トラフィックに関する情報をキャプチャします。GuardDuty やネットワークのトラブルシューティングに使用されます。第17章。ドメイン 1。

**VPC ピアリング** — プライベート IP アドレスを使ってトラフィックを2つの VPC 間でルーティングできるようにするネットワーク接続。第11章。ドメイン 3。

---

## W

**WAF（Web Application Firewall）** — ルール（IP ブロック、SQL インジェクション、レート制限）を使って HTTP/HTTPS トラフィックをフィルタリングします。CloudFront、ALB、または API Gateway にアタッチします。第17章。ドメイン 1。

**AWS Wavelength** — 5G 通信事業者のネットワーク内、無線エッジに展開される AWS インフラ。モバイルデバイスへの1桁ミリ秒のレイテンシを実現します。モバイル AR/VR、リアルタイムゲーミング、自動運転車のテレメトリ、5G エッジでのライブ動画向け。Wavelength Zone は通信ネットワーク内の AWS リージョンの拡張です。第2章。ドメイン 3。

**Well-Architected フレームワーク** — AWS の6つの柱からなる評価フレームワーク: 運用上の優秀性、セキュリティ、信頼性、パフォーマンス効率、コスト最適化、持続可能性。第31章。ドメイン横断。

**加重ルーティング（Route 53）** — DNS クエリを重みに応じてエンドポイント間に分散します。ブルーグリーンデプロイや A/B テストに使用されます。第12章。ドメイン 3。

**ライトスルーキャッシング** — データベースが更新されるたびにキャッシュを更新します。データは常に一貫していますが、二度と読まれない多くの項目をキャッシュが保持する可能性があります。第10章。ドメイン 3。
