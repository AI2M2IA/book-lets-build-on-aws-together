# 付録 A: AWS サービスクイックリファレンス

本書で扱うすべてのサービスを、登場順に並べています。学習用のリファレンスとして、また試験対策中のクイックルックアップとして使用してください。

---

## コンピューティング

**EC2 — Elastic Compute Cloud** *(第4章)*

クラウド上の仮想マシンです。インスタンスタイプ（CPU、メモリ、ストレージ）、オペレーティングシステム、リージョンを選択します。料金は、1時間あたり（オンデマンド）、コミットメントごと（Reserved Instances / Savings Plans）、またはスペア容量スロットごと（スポット）で支払います。コンピューティングの基礎となるプリミティブです。

主要な概念: AMI（Amazon Machine Image）、インスタンスタイプ（t3、m6g、r6g、c6g ファミリー）、キーペア、インスタンスプロファイル、配置グループ。

試験のヒント: 永続的、ステートフル、または長時間実行されるコンピューティングが必要なシナリオでは EC2 または ECS。短時間、イベント駆動、またはアイドルコストゼロのコンピューティングが必要なシナリオでは Lambda。

---

**Auto Scaling + Application Load Balancer** *(第7章)*

Auto Scaling Group（ASG）は、負荷に応じて EC2 インスタンスを追加・削除します。Application Load Balancer（ALB）は、インスタンス間でトラフィックを分散し、パスまたはホストに基づいてルーティングします。両者が組み合わさって水平スケーリング層を形成します。

主要な概念: 起動テンプレート、スケーリングポリシー（ターゲット追跡、ステップ、スケジュール）、ヘルスチェック、ALB ターゲットグループ、リスナールール、重み付きルーティング。

試験のヒント:「変動する負荷の処理」または「AZ をまたいだ高可用性」→ ASG + ALB。

---

**Lambda** *(第20章)*

サーバーレス関数です。コードを記述すれば、AWS がイベントに応答して実行します。管理するサーバーはありません。呼び出しごと、および実行ミリ秒ごとに料金を支払います。数千の同時実行まで自動的にスケールします。

主要な概念: イベントソース（API Gateway、S3、SQS、EventBridge、Kinesis）、実行ロール、同時実行制限、予約済みおよびプロビジョニング済み同時実行、コールドスタート、Layers、最大15分の実行時間。

試験のヒント:「サーバーレス」「イベント駆動」「短時間タスク」「アイドルコストなし」→ Lambda。

---

**ECS — Elastic Container Service** *(第21章)*

AWS 上で Docker コンテナを実行します。2つの起動タイプがあります。EC2（ホストはユーザーが管理）と Fargate（ホストは AWS が管理）です。ECS は、タスク定義、サービス、クラスタースケジューリング、ロードバランサーおよびサービスディスカバリとの統合を管理します。

主要な概念: タスク定義、ECS サービス、Fargate と EC2 起動タイプ、ECR（コンテナレジストリ）、タスク IAM ロール、サービスの自動スケーリング。

試験のヒント:「コンテナ化されたワークロード」「マイクロサービス」「Docker on AWS」→ ECS（通常、サーバーレスコンテナには Fargate）。

---

**EKS — Elastic Kubernetes Service** *(第21章)*

マネージド Kubernetes です。AWS がコントロールプレーンを実行し、ユーザーがワーカーノード（EC2 または Fargate）を実行します。チームがすでに Kubernetes を使用している場合、または Kubernetes 固有の機能を必要とするワークロードがある場合に EKS を使用します。

試験のヒント:「Kubernetes」「既存の K8s ワークロードを移行する必要がある」→ EKS。「K8s のオーバーヘッドなしでコンテナだけが必要」→ ECS。

---

**AWS Batch** *(第21章)*

Docker コンテナ向けのマネージドバッチコンピューティングです。ジョブ（Docker イメージ + コマンド）、ジョブキュー、コンピューティング環境（EC2 または Fargate）を定義します。AWS Batch がコンピューティングを自動的にプロビジョニングおよびスケールし、ジョブが完了すると終了します。コスト削減のためにスポットインスタンスをサポートしています。

主要な概念: ジョブ定義（何を実行するか）、ジョブキュー（ジョブが待機する場所）、コンピューティング環境（EC2 または Fargate、オンデマンドまたはスポット）、配列ジョブ（同じジョブの多数の並列コピーを実行）。

試験のヒント:「Lambda の15分タイムアウトを超えるバッチ処理」「コンテナ上の有限なコンピューティングジョブ」「AWS 上の HPC ワークロード」→ AWS Batch。

---

**AWS Outposts** *(第2章)*

ユーザー自身のデータセンターやコロケーション施設に設置される、フルマネージドの AWS ハードウェアラックです。パブリッククラウドと同じ AWS サービス、API、ツール（EC2、EBS、RDS、EKS、Outposts 上の S3）を、物理的にオンプレミスで実行します。

主要な概念: オンプレミスでの同一 AWS API、AWS が設置とパッチ適用を管理、顧客がラックスペースと電源を提供、Local Gateway（LGW）が Outposts をオンプレミスネットワークに接続。

試験のヒント:「自社のデータセンターで AWS を実行する」「データレジデンシーのためコンピューティングをオンプレミスに保つ必要がある」「インターネット依存のない AWS API」→ Outposts。

---

**AWS Wavelength** *(第2章)*

5G 通信事業者のネットワーク内に展開される AWS インフラです。Wavelength Zone は 5G ネットワークのエッジに配置され、モバイルデバイスへの1桁ミリ秒のレイテンシを実現します。

主要な概念: Wavelength Zone は通信ネットワーク内の AWS リージョンの拡張であり、デバイスと Wavelength Zone の間のトラフィックはキャリアネットワーク内に留まります。

試験のヒント:「5G モバイルユーザーへの1桁ミリ秒のレイテンシ」「モバイル AR/VR」「モバイルでのリアルタイムゲーミング」「自動運転車のテレメトリ」→ Wavelength。

---

**AWS Application Migration Service（MGN）** *(第25章)*

リホスト（リフトアンドシフト）移行サービスです。エージェントがソースサーバーのディスクをブロック単位で AWS の低コストなステージング領域に複製します。テストコピーをオンデマンドで起動でき、カットオーバー時に MGN は複製されたサーバーをネイティブな EC2 インスタンスに変換します。アプリケーションの変更は不要です。

主要な概念: ブロックレベルの継続的レプリケーション、ステージング領域、カットオーバー前のテスト起動、「7 つの R」移行戦略（MGN = リホスト）。

試験のヒント:「数百の VM をコード変更なしで迅速に移行する」「サーバーを EC2 にリフトアンドシフトする」→ MGN。DataSync は*ファイル*を移動し、DMS は*データベース*を移動し、MGN は*サーバー全体*を移動します。

---

## ストレージ

**S3 — Simple Storage Service** *(第5章)*

オブジェクトストレージです。無制限の容量、99.999999999%（イレブンナイン）の耐久性を備えています。ファイルをオブジェクトとしてバケットに保存します。バケットはリージョンに存在します。オブジェクトは 0 バイトから 5TB までの範囲です。

主要な概念: バケットポリシー、オブジェクト ACL、バージョニング、静的ウェブサイトホスティング、署名付き URL、マルチパートアップロード、Transfer Acceleration、ストレージクラス（Standard、Intelligent-Tiering、Standard-IA、One Zone-IA、Glacier Instant Retrieval、Glacier Flexible Retrieval、Glacier Deep Archive、加えて単一 AZ かつレイテンシ重視のディレクトリバケットワークロード向けの S3 Express One Zone）。

試験のヒント:「ファイルの保存と取得」「静的アセット」「バックアップ」「データレイク」→ S3。適切なストレージクラスは、アクセス頻度と取得速度によって決まります。

---

**EBS — Elastic Block Store** *(第6章)*

単一の EC2 インスタンスにアタッチされるブロックストレージです。ハードドライブのように動作します。インスタンスのライフサイクルとは独立して永続します（デタッチして再アタッチできます）。最も一般的なタイプ: gp3（汎用 SSD、デフォルト）、io2（データベース向けのプロビジョンド IOPS）、st1（シーケンシャル読み取り向けのスループット最適化 HDD）。

主要な概念: スナップショット（増分、S3 に保存）、暗号化（KMS）、マルチアタッチ（io1/io2 のみ）、IOPS およびスループットのプロビジョニング。

試験のヒント:「EC2 向けの永続ストレージ」「データベースストレージ」「低レイテンシのブロックアクセスが必要」→ EBS。

---

**EFS — Elastic File System** *(第6章)*

複数の EC2 インスタンスから同時にアクセスできる共有ファイルシステムです。NFS プロトコルを使用します。自動的にスケールします。GB あたりのコストは EBS より高くなります。ストレージクラスには Standard、Infrequent Access、Archive があります。Intelligent-Tiering がファイルを自動的に移動します。

試験のヒント:「共有ファイルシステム」「複数の EC2 インスタンスが同じファイルを必要とする」「NFS」→ EFS。

---

**FSx ファミリー** *(第6章)*

特定の名前付き技術向けのマネージドファイルサーバーです。FSx for Windows File Server: SMB プロトコル、NTFS、Active Directory 統合、Multi-AZ。FSx for Lustre: HPC/ML 向けの並列高性能ファイルシステムで、S3 オブジェクトをファイルとして提示します（遅延ロード）。FSx for NetApp ONTAP: マルチプロトコル（NFS + SMB + iSCSI）、スナップショット、SnapMirror レプリケーション。FSx for OpenZFS: 低レイテンシ NFS、インスタントスナップショット、書き込み可能なクローン。

試験のヒント:「SMB/Active Directory」→ FSx for Windows。「S3 データでの HPC/ML トレーニング」→ FSx for Lustre。「同じデータへの NFS と SMB / NetApp 移行」→ FSx for ONTAP。「ZFS 移行 / インスタントクローン」→ FSx for OpenZFS。

---

**S3 ストレージクラスとライフサイクルポリシー** *(第23章)*

S3 Intelligent-Tiering は、アクセス頻度に基づいてオブジェクトをアクセス階層間で自動的に移動します。ライフサイクルポリシーは、経過日数のルールに基づいてオブジェクトをクラス間で移行します（Standard → Standard-IA → Glacier）。Glacier ストレージクラスの取得遅延は、数分（Glacier Instant）から12時間（Glacier Deep Archive）まで幅があります。

試験のヒント:「アクセス頻度の低いデータのストレージコストを削減する」→ ライフサイクルポリシー、Intelligent-Tiering、または Glacier。

---

**AWS Storage Gateway** *(第6章)*

オンプレミス環境を AWS ストレージに接続するハイブリッドストレージサービスです。アプリケーションがすでに理解しているプロトコルでストレージを提示しつつ、データを S3、S3 Glacier、または EBS スナップショットとして永続化します。

主要な概念: File Gateway（NFS/SMB → S3）、Volume Gateway（iSCSI、キャッシュモードまたは保存モード）、Tape Gateway（仮想テープライブラリ → Glacier）。

試験のヒント:「オンプレミスアプリケーションがコード変更なしでクラウドストレージを必要とする」→ Storage Gateway。「テープバックアップを置き換える」→ Tape Gateway。

---

**AWS DataSync** *(第25章)*

エージェントベースのデータ移行・レプリケーションサービスです。軽量なエージェントが NFS または SMB 経由でオンプレミスのファイルサーバーに接続し、共有を S3、EFS、または FSx に同期します。スケジューリング、帯域幅スロットリング、整合性検証が組み込まれています。

主要な概念: DataSync エージェント（オンプレミスの VM または EC2）、NFS/SMB ソース、S3/EFS/FSx 宛先、スケジュールされた増分転送。

試験のヒント:「オンプレミスの NAS から AWS へ、ネットワーク経由で大量のファイルを移行または継続的に同期する」→ DataSync。

---

**AWS Transfer Family** *(第25章)*

S3 または EFS をストレージ宛先とする、フルマネージドの SFTP、FTPS、FTP サーバーです。クライアントは既存の SFTP ソフトウェアで接続し、アップロードされたファイルは直接バケットまたはファイルシステムに格納されます。

主要な概念: マネージドエンドポイント（オプションで静的 IP）、S3 または EFS のバッキングストレージ、外部パートナー向けの既存プロトコル互換性。

試験のヒント:「パートナーは SFTP でのアップロードを続ける必要があるが、ファイルは S3 に格納すべき」→ Transfer Family。

---

**AWS Snow ファミリー** *(第25章)*

オフラインで大量のデータを移行するための物理的なデータ転送デバイスです。Snowball Edge Storage Optimized: 80 TB の使用可能容量、堅牢な筐体、ユーザーの所在地に配送されます。ローカルでデータをロードし、返送して S3 へ取り込みます。

主要な概念: まず転送の計算を行いましょう。ネットワーク転送におおよそ1週間以上かかる場合は、物理デバイスが有利です。*レガシーに関する注記（2026年）*: AWS はこのファミリーの提供を縮小しており、Snowmobile（2024年）と Snowcone（2024年後半）は終了し、Snow デバイスは2025年11月に新規顧客の受付を終了しました（AWS は現在 DataSync と Data Transfer Terminals を案内しています）。SAA-C03 の問題バンクはこれより前のものなので、試験では依然として Snowball が解答として期待されます。

試験のヒント:「ペタバイト規模の移行」「限られた帯域幅、数週間の転送時間」→ Snow ファミリー。

---

**AWS Backup** *(第18章および第23章)*

EBS、RDS、DynamoDB、EFS、Storage Gateway をまたいだ、一元化されたポリシーベースのバックアップサービスです。バックアッププランがスケジュールと保持期間を定義し、ボールトがリカバリポイントを保存します。

主要な概念: バックアッププランとボールト、クロスリージョンおよびクロスアカウントのコピー、不変性のための Vault Lock。

試験のヒント:「複数の AWS サービスにわたってバックアップを一元化・自動化する」「ランサムウェア/アカウント侵害対策のためのクロスアカウントバックアップコピー」→ AWS Backup。

## データベース

**RDS — Relational Database Service** *(第8章)*

マネージドリレーショナルデータベースです。サポートされるエンジン: MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、Aurora（AWS 独自のエンジン）。AWS がバックアップ、パッチ適用、フェイルオーバー、レプリケーションを処理します。スキーマ設計、クエリ、インスタンスサイジングはユーザーが管理します。

主要な概念: Multi-AZ デプロイ（自動フェイルオーバー、同期レプリケーション）、リードレプリカ（非同期、読み取りスケーリング向け）、自動バックアップ（1～35日の保持）、手動スナップショット（削除されるまで保持）、RDS Proxy（接続プーリング）。

試験のヒント:「リレーショナルデータベース」「ACID トランザクション」「既存の SQL ワークロード」→ RDS または Aurora。

---

**Aurora** *(第24章)*

MySQL および PostgreSQL と互換性のある AWS のリレーショナルデータベースエンジンです。データを 3 つの AZ に 6 コピーで複製する分散ストレージエンジンを備えています。通常、MySQL より5倍高速です。Aurora Serverless v2 は容量を自動的にスケールし（ACU — Aurora Capacity Units で測定）、サポートされるエンジンバージョンでは、接続が開かれていないときに 0 ACU まで自動的に一時停止できます。

主要な概念: Aurora クラスター（ライター + 単一のリーダーエンドポイントの背後にある最大15個の Aurora レプリカ）、Aurora Global Database（レプリケーション遅延が1秒未満のクロスリージョンリードレプリカ）、Aurora Serverless v2、ACU、自動一時停止/再開の動作。

試験のヒント:「高性能なリレーショナルデータベース」「MySQL/PostgreSQL 互換」「グローバルな読み取り」「変動するワークロード」→ Aurora。

---

**DynamoDB** *(第9章)*

フルマネージドの NoSQL データベースです。キーバリューおよびドキュメントモデルです。1桁ミリ秒のパフォーマンスで任意のスループットにスケールします。2つの容量モード: オンデマンド（リクエストごとの支払い）とプロビジョンド（1時間あたりの容量ユニットごとの支払い、Auto Scaling 付き）。

主要な概念: パーティションキー（必須）、ソートキー（オプション）、Global Secondary Index（GSI）、Local Secondary Index（LSI）、DynamoDB Streams（変更データキャプチャ）、DynamoDB Accelerator（DAX）— インメモリキャッシュ、TTL（Time to Live）、トランザクション。

試験のヒント:「高スループットのキーベースアクセス」「柔軟なスキーマ」「サーバーレス NoSQL」→ DynamoDB。

---

**ElastiCache** *(第10章)*

マネージドのインメモリキャッシングです。2つのエンジン: Redis（永続化、pub/sub、Lua スクリプティング、データ構造）と Memcached（純粋なキャッシュ、よりシンプル、マルチスレッド）。データベース負荷を軽減し、頻繁に読み取られるデータをマイクロ秒単位で提供するために使用します。

主要な概念: キャッシュアサイドパターン、ライトスルーパターン、エビクションポリシー、TTL、クラスターモード（Redis）、自動フェイルオーバー付きの Multi-AZ。

試験のヒント:「データベース負荷を軽減する」「サブミリ秒の読み取りレイテンシ」「セッション管理」「リアルタイムリーダーボード」→ ElastiCache Redis。

---

**Amazon MemoryDB for Redis** *(第10章)*

耐久性のある、Redis 互換のインメモリプライマリデータベースです。ElastiCache（データ損失が許容されるキャッシュ）とは異なり、MemoryDB は Multi-AZ トランザクションログを保存し、耐久性を保証します。MemoryDB をプライマリデータベースとして使用できます。別のデータベースの前面に置く単なるキャッシュではありません。

主要な概念: Redis API 互換性、Multi-AZ トランザクションログ（耐久性の保証）、インメモリのパフォーマンス、プライマリデータベース（キャッシュ層ではない）。

試験のヒント:「Redis 互換かつデータ損失が許容されない」「耐久性のあるインメモリデータベース」→ MemoryDB。「キャッシュとしての Redis、データ損失は許容される」→ ElastiCache Redis。

---

**用途別データベース** *(第9章、第10章、第24章)*

データの形状をエンジンに合わせます。DocumentDB: MongoDB 互換のドキュメント。Neptune: グラフデータベース（関係、トラバーサル — Gremlin/SPARQL）。Keyspaces: Cassandra 互換のワイドカラム。Timestream: 時系列（現在の提供形態: Timestream for InfluxDB）。MemoryDB: 耐久性のある Redis 互換の*プライマリ*データベース（ElastiCache = キャッシュ に対して）。QLDB（「不変の暗号化台帳」）は2025年に提供終了となったため、レガシーなディストラクター（誤答の選択肢）として扱います。

試験のヒント:「ソーシャルグラフ / レコメンデーション / 不正リング」→ Neptune。「MongoDB」→ DocumentDB。「Cassandra」→ Keyspaces。「時間経過に伴う IoT テレメトリ」→ Timestream。

---

**AWS DMS — Database Migration Service** *(第8章)*

最小限のダウンタイムでデータベースを AWS に移行します。フルロード（初回コピー）に加えて CDC（Change Data Capture）をサポートし、移行の実行中にソースとターゲットを同期させ続けます。同じエンジンタイプ間（MySQL → MySQL、PostgreSQL → PostgreSQL）の移行では、DMS を直接使用します。異なるエンジンタイプ間（Oracle → Aurora PostgreSQL）の移行では、まず AWS Schema Conversion Tool（SCT）でスキーマを変換し、その後 DMS でデータを移行します。

主要な概念: レプリケーションインスタンス、ソースおよびターゲットエンドポイント、フルロード + CDC、異種移行向けの SCT（Schema Conversion Tool）。

試験のヒント:「最小限のダウンタイムでデータベースを移行する」→ DMS。「Oracle から Aurora へ」やあらゆる異種移行 → SCT + DMS。「同じエンジン、同じタイプ」→ DMS を直接。

---

## ネットワーキング

**VPC — Virtual Private Cloud** *(第11章)*

AWS 内の隔離されたネットワークです。リージョン内のすべての AZ にまたがります。IP アドレス空間（CIDR ブロック）を定義し、サブネット（パブリックまたはプライベート）を作成し、ルートテーブルを構成し、セキュリティグループと NACL でアクセスを制御します。

主要な概念: パブリックサブネット（Internet Gateway へのルート）、プライベートサブネット（アウトバウンド向けの NAT Gateway へのルート）、Internet Gateway（インターネットへのインバウンド + アウトバウンド）、NAT Gateway（プライベートインスタンス向けのアウトバウンドのみ）、VPC ピアリング（2つの VPC を接続）、VPC エンドポイント（インターネットなしで AWS サービスに接続）。

試験のヒント:「AWS 上のプライベートネットワーク」「リソースをインターネットから隔離する」「ネットワークトラフィックを制御する」→ VPC。

---

**セキュリティグループと NACL** *(第15章)*

セキュリティグループはインスタンスレベルのステートフルなファイアウォールです。許可ルールのみで、戻りトラフィックは自動的に許可されます。NACL（Network Access Control List）はサブネットレベルのステートレスなファイアウォールです。インバウンドとアウトバウンドの両方のルールが必要で、ルール番号順に評価されます。

試験のヒント:「特定の IP がサブネットにアクセスするのをブロックする」→ NACL。「インスタンスとの間のトラフィックを制御する」→ セキュリティグループ。

---

**Route 53** *(第12章)*

AWS の DNS サービスおよびドメインレジストラーです。インターネットトラフィックを AWS リソースや外部エンドポイントにルーティングします。ルーティングポリシー: シンプル、加重、レイテンシーベース、フェイルオーバー、位置情報、地理的近接性、複数値回答。

主要な概念: ホストゾーン（パブリックおよびプライベート）、レコードタイプ（A、AAAA、CNAME、Alias）、ヘルスチェック、Traffic Flow（ビジュアルなポリシーエディタ — なお、地理的近接性はレコード上の直接的なルーティングポリシーとしても、調整可能なバイアス付きで、Traffic Flow を必要とせずに利用できます）。

試験のヒント:「DNS ルーティング」「リージョン間のフェイルオーバー」「レイテンシまたは場所に基づくルーティング」→ 適切なルーティングポリシーを使った Route 53。

---

**CloudFront** *(第13章)*

コンテンツ配信ネットワーク（CDN）です。エッジロケーション（世界中に 750 以上のポイントオブプレゼンス）でコンテンツをキャッシュします。エンドユーザーのレイテンシを削減します。キャッシングによりオリジンの転送コストを削減します。S3、EC2、ALB、API Gateway をオリジンとして統合します。

主要な概念: ディストリビューション、オリジン、ビヘイビア（オリジンへのパスベースのルーティング）、TTL（キャッシュ制御）、キャッシュの無効化、署名付き URL とクッキー（アクセス制御）、Lambda@Edge と CloudFront Functions（エッジでのコード実行）、Origin Shield（オリジン負荷の軽減）。

試験のヒント:「グローバルな低レイテンシ」「静的コンテンツのキャッシュ」「オリジン負荷の軽減」「Shield による DDoS 対策」→ CloudFront。

---

**Direct Connect と VPN** *(第25章)*

AWS Direct Connect は、オンプレミスのデータセンターから AWS への専用の物理ネットワーク接続です。パブリックインターネットを回避します。より一貫した帯域幅とレイテンシを提供します。AWS Site-to-Site VPN は、パブリックインターネット上の暗号化されたトンネルです。セットアップが速くコストも低いものの、パフォーマンスは変動します。

主要な概念: 仮想インターフェイス（VIF）、Direct Connect Gateway（複数リージョンへの接続）、Transit Gateway（ハブアンドスポーク型ネットワークトポロジ）、VPN トンネルの冗長性。

試験のヒント:「AWS への専用プライベート接続」→ Direct Connect。「暗号化された接続、より速いセットアップ」→ VPN。「複数の VPC を接続」→ Transit Gateway。

---

**VPC エンドポイント** *(第30章)*

パブリックインターネットや NAT Gateway を使わずに、プライベートリソースを AWS サービスに接続します。ゲートウェイエンドポイント: 無料、S3 と DynamoDB のみで利用可能。インターフェイスエンドポイント（PrivateLink）: 1時間あたり + 1GB あたりの料金、ほとんどの AWS サービスで利用可能。

試験のヒント:「プライベートサブネットの EC2 が S3/DynamoDB を呼び出す — NAT Gateway のコストを削減する」→ ゲートウェイエンドポイント（無料）。「プライベートサブネットから SQS、SSM、Secrets Manager へのプライベート接続」→ インターフェイスエンドポイント。

---

**AWS Client VPN** *(第11章)*

個々のデバイス（ノート PC、ワークステーション）がインターネット経由で VPC に安全に接続できる、マネージドの OpenVPN エンドポイントです。認証オプション: Active Directory、ID プロバイダーとの SAML 2.0 フェデレーション、または相互 TLS（証明書ベース）。スプリットトンネル（VPC 宛のトラフィックのみがトンネルを通る）とフルトンネル（すべてのトラフィックが AWS 経由でルーティングされる）をサポートします。

主要な概念: Client VPN エンドポイント、ターゲットネットワーク（VPC サブネットの関連付け）、認可ルール、スプリットトンネル と フルトンネル。

試験のヒント:「リモートのエンジニアが自宅から VPC に安全にアクセスする必要がある」「個々のデバイスから VPC への接続」→ Client VPN。対比: Site-to-Site VPN = ネットワーク間。Client VPN = デバイスからネットワークへ。

---

**Network Load Balancer（NLB）と Gateway Load Balancer（GWLB）** *(第7章)*

NLB は Layer 4（TCP/UDP/TLS）で動作します。HTTP の検査は行わず、極めて高速なパケットルーティングのみを行います。毎秒数百万リクエストを、AZ ごとの静的 IP とソース IP の保持とともに処理します。GWLB は Layer 3 で動作し、ただ1つの目的のために存在します。サードパーティの仮想ネットワークアプライアンス（ファイアウォール、IDS/IPS、ディープパケットインスペクション）をトラフィックフローにインラインで挿入することです。

主要な概念: NLB = Layer 4、静的 IP、超低レイテンシ、非 HTTP プロトコル。GWLB = Layer 3、GENEVE カプセル化、単一のエントリポイントの背後にあるアプライアンスフリート。ALB = Layer 7（パス/ホストルーティング）。

試験のヒント:「毎秒数百万の TCP リクエスト」「ロードバランサー用の静的 IP」「ソース IP を保持する」→ NLB。「サードパーティのセキュリティアプライアンスをトラフィックパスに挿入する」→ GWLB。

---

**AWS Global Accelerator** *(第25章)*

ユーザートラフィックを、パブリックインターネットを通る代わりに、最も近いエッジロケーションで AWS のプライベートなグローバルバックボーンに乗せてルーティングします。1つ以上のリージョンにある ALB、NLB、または EC2 インスタンスの前面に立つ、2つの静的な Anycast IP アドレスを提供します。*動的な*（キャッシュ不可能な）トラフィックのレイテンシと一貫性を向上させます。

主要な概念: 静的 Anycast IP、AWS バックボーンへのエッジオンボーディング、ヘルスチェックに基づく数秒単位のリージョンフェイルオーバー、トラフィックダイヤル付きのエンドポイントグループ。

試験のヒント:「グローバルなユーザー、動的/非 HTTP トラフィック、静的 IP、高速なリージョンフェイルオーバー」→ Global Accelerator。「キャッシュ可能/静的コンテンツ」→ 代わりに CloudFront。

---

## セキュリティと ID

**IAM — Identity and Access Management** *(第3章および第14章)*

AWS アカウント内で誰が何をできるかを制御します。ユーザー（長期認証情報）、グループ（権限を共有するユーザー）、ロール（サービスおよびクロスアカウントアクセス向けの一時認証情報）、ポリシー（許可/拒否ルールを定義する JSON ドキュメント）。

主要な概念: Principal、Action、Resource、Condition、明示的な拒否 > 明示的な許可 > 暗黙的な拒否、SCP（AWS Organizations の Service Control Policy）、アクセス許可境界、AssumeRole。

試験のヒント: IAM はすべてのセキュリティ問題に関与します。主要なパターン: サービスは IAM ロール（ユーザーではない）を使用します。クロスアカウントアクセスはロールの引き受けを使用します。最小権限 — 必要なものだけを付与します。

---

**KMS — Key Management Service** *(第16章)*

マネージドの暗号化キーサービスです。暗号化キーを作成、保存、制御します。カスタマー管理キー（CMK）では、ローテーション、使用、アクセスポリシーを定義できます。AWS 管理キーは自動的に管理されます。

主要な概念: キーポリシー（IAM ポリシーとは別）、エンベロープ暗号化（データはデータキーで暗号化され、データキーは CMK で暗号化される）、自動キーローテーション、マルチリージョンキー、グラント。

試験のヒント:「保存データの暗号化」「カスタマー管理の暗号化キー」「キーローテーション」→ KMS。

---

**Secrets Manager** *(第16章)*

機密性の高い値（データベース認証情報、API キー、OAuth トークン）を保存し、自動的にローテーションします。RDS と統合してパスワードを自動ローテーションします。アプリケーションは実行時に API 経由でシークレットを取得します。認証情報をハードコードしてはいけません。

試験のヒント:「データベース認証情報を保存・ローテーションする」「ハードコードされたシークレットを避ける」→ Secrets Manager。「シークレットではなく構成値を保存する」→ Parameter Store（SSM）。

---

**AWS Shield** *(第17章)*

DDoS 保護です。Shield Standard は自動かつ無料で、一般的なボリューム型およびプロトコル型の攻撃から保護します。Shield Advanced は、財務的保護、24時間365日の DDoS 対応チーム、詳細な攻撃の可視化を追加します。

試験のヒント:「DDoS から保護する」→ Shield Standard（自動）または Shield Advanced（エンタープライズ向け、SLA 付き）。

---

**WAF — Web Application Firewall** *(第17章)*

ルールに基づいて HTTP/HTTPS トラフィックをフィルタリングします: IP ブロック、レート制限、SQL インジェクションパターン、XSS パターン、地理的制限、カスタムルール。CloudFront、ALB、API Gateway、または AppSync にアタッチします。

試験のヒント:「特定の IP アドレスをブロックする」「エッジで SQL インジェクションを防ぐ」「API 呼び出しをレート制限する」→ WAF。

---

**GuardDuty** *(第17章)*

脅威検出サービスです。ML と脅威インテリジェンスを使用して、CloudTrail ログ、VPC フローログ、DNS ログを分析します。異常な API アクティビティ、既知の悪意のある IP との通信、侵害された認証情報を検出します。

試験のヒント:「異常なアクティビティを検出する」「侵害された IAM 認証情報を特定する」「継続的な脅威監視」→ GuardDuty。

---

**Amazon Inspector** *(第17章)*

自動化された脆弱性評価サービスです。EC2 インスタンス、Amazon ECR コンテナイメージ、Lambda 関数を、ソフトウェアの脆弱性（CVE）と意図しないネットワーク露出について継続的にスキャンします。検出結果は一元管理のため AWS Security Hub に送信されます。

主要な概念: CVE スキャン、（一回限りではなく）継続的な評価、EC2 + ECR + Lambda のカバレッジ、Security Hub 統合。

試験のヒント:「EC2 の既知の脆弱性を自動的にスキャンする」「コンテナイメージの CVE スキャン」「継続的な脆弱性評価」→ Inspector。

---

**Amazon Cognito** *(第14章)*

アプリケーションのエンドユーザー向けのマネージド認証 — 自分で構築する必要のないユーザーディレクトリです。User Pool はサインアップ、サインイン、MFA、パスワードリセット、ソーシャル ID プロバイダー（Google、Facebook、任意の OIDC プロバイダー）を処理し、アプリケーションが検証する JWT を発行します。Identity Pool はそれらのトークンを一時的な AWS 認証情報と交換します。

主要な概念: User Pool（認証、JWT）と Identity Pool（一時的な AWS 認証情報）、ホスト型 UI、ソーシャル/OIDC/SAML フェデレーション、API Gateway Cognito オーソライザー。

試験のヒント:「アプリケーションにユーザーのサインアップ/サインインが必要」「ソーシャルログイン」「モバイルアプリのユーザーに AWS リソースへの一時的なアクセスを与える」→ Cognito。対比: IAM はエンジニアとサービス向け、Cognito は顧客向け。

---

**AWS Certificate Manager（ACM）** *(第16章)*

AWS マネージドサービス（ALB、CloudFront、API Gateway）向けに無料のパブリック TLS/SSL 証明書をプロビジョニングし、ライフサイクル全体を処理します — 更新カレンダーも秘密鍵の取り扱いも不要です。DNS 検証により自動更新します。

主要な概念: DNS 検証と E メール検証、自動更新、CloudFront 用の証明書は us-east-1 にある必要がある、無料のパブリック証明書はエクスポートできない（2025年以降、有料のエクスポート可能なオプションが存在します）。

試験のヒント:「ロードバランサーまたは CDN での HTTPS」「証明書の自動更新」→ ACM。

---

**Amazon Macie** *(第17章)*

S3 向けの機密データ検出です。機械学習とパターンマッチングを使用して、バケット内の PII（氏名、カード番号、認証情報）を見つけ、パブリック露出などのアクセスリスクをフラグ付けします。GuardDuty を補完します: GuardDuty は動作を監視し、Macie は保存されているものを監査します。

主要な概念: マネージドデータ識別子（PII パターン）、S3 のみのスコープ、Security Hub/EventBridge への検出結果。

試験のヒント:「S3 内の PII を検出する」「機密データの露出を特定する」→ Macie。

---

**AWS Control Tower** *(第14章)*

マルチアカウント環境のセットアップとガバナンスを自動化します。ランディングゾーン — Organizations、CloudTrail、Config、ガードレールがあらかじめ配線された管理アカウント、ログアーカイブアカウント、監査アカウント — を、手作業での何日もの配線ではなく数分で作成します。

主要な概念: ランディングゾーン、ガードレール（予防的 = SCP、検出的 = Config ルール）、標準化された新規アカウントのための Account Factory。

試験のヒント:「ベストプラクティスを自動的に備えた新しいマルチアカウント環境をセットアップしガバナンスする」→ Control Tower。対比: Organizations は素の構成要素、Control Tower は自動化された組み立て。

---

## メッセージングとイベント処理

**SQS — Simple Queue Service** *(第19章)*

マネージドのメッセージキューです。プロデューサーがメッセージを送信し、コンシューマーがそれを読み取って削除します。サービスを疎結合にします: 送信者は受信者が利用可能かどうかを知る必要がありません。標準キュー: 最低1回の配信、ベストエフォートの順序付け。FIFO キュー: 厳密に1回の処理、厳格な順序付け。

主要な概念: 可視性タイムアウト（処理中、メッセージは他のコンシューマーから隠される）、繰り返し失敗するメッセージのためのデッドレターキュー（DLQ）、メッセージ保持期間（デフォルト4日、最大14日）、ロングポーリング（空のレスポンスを削減）、最大ペイロードはデフォルト256KB（2025年以降は 1 MiB まで引き上げ可能。それより大きなペイロードでは、Extended Client Library が本文を S3 に保存）。

試験のヒント:「サービスを疎結合にする」「負荷スパイク時にリクエストをバッファリングする」「非同期処理」→ SQS。「順序が重要で、厳密に1回が必要」→ SQS FIFO。

---

**SNS — Simple Notification Service** *(第19章)*

マネージドの pub/sub サービスです。パブリッシャーがトピックにメッセージを送信し、すべてのサブスクライバーがコピーを受信します。ファンアウトパターン: 1つのメッセージ → 多数のコンシューマー。プロトコル: SQS、Lambda、HTTP/HTTPS、E メール、SMS、モバイルプッシュ。

主要な概念: トピック、サブスクリプション、ファンアウトパターン（SNS → 複数の SQS キュー）、メッセージフィルタリング（サブスクライバーは一致するメッセージのみを受信）。

試験のヒント:「複数のエンドポイントに同時に通知を送る」「単一のイベントを複数のコンシューマーにファンアウトする」→ SNS。一般的なパターン: 耐久性のあるファンアウトのための SNS + SQS。

---

**EventBridge** *(第22章)*

イベント駆動アーキテクチャを構築するためのイベントバスです。AWS サービス、SaaS パートナー、カスタムソースからのイベントを、Lambda、SQS、SNS、Step Functions、その他のターゲットにルーティングします。スケジュールされたルール（cron）とパターンマッチングをサポートします。

試験のヒント:「AWS サービスからターゲットへイベントをルーティングする」「Lambda 関数をスケジュールする」「イベント駆動のオーケストレーション」→ EventBridge。

---

**Step Functions** *(第22章)*

サーバーレスのワークフローオーケストレーションです。Lambda 関数、ECS タスク、DynamoDB、SNS、SQS、その他のサービスを、ビジュアルなステートマシンに統合します。リトライ、エラー処理、並列分岐、待機状態を処理します。

主要な概念: ステートマシン、状態タイプ（Task、Wait、Choice、Parallel、Map、Pass、Succeed、Fail）、Standard ワークフロー（厳密に1回、長時間実行）と Express ワークフロー: 非同期（最低1回、大量 — タスクは冪等に設計する）と同期（最大1回、API 呼び出しのように結果を直接返す）。

試験のヒント:「複数の Lambda 関数をオーケストレーションする」「リトライロジックを備えた長時間実行ワークフロー」「人間の承認ステップ」→ Step Functions。

---

**Kinesis** *(第26章)*

リアルタイムのデータストリーミングです。Kinesis Data Streams: 耐久性のある、順序付けられたレコードのストリーム（分散コミットログのようなもの）。コンシューマーがレコードを処理します。データはデフォルトで24時間（Extended Data Retention で最大365日）保持されます。Amazon Data Firehose（旧称 Kinesis Data Firehose）: S3、Redshift、OpenSearch、Splunk へのフルマネージドな配信 — コンシューマーの管理は不要です。

主要な概念: シャード（スループットの単位: 書き込み 1MB/秒、読み取り 2MB/秒）、パーティションキー（シャードの割り当てを決定）、シーケンス番号、チェックポイント（KCL または Lambda）、Firehose と Streams。

試験のヒント:「リアルタイムストリーミング」「順序付けられたレコード」「イベントの再生」→ Kinesis Data Streams。「コンシューマーを管理せずにストリーミングデータを S3/Redshift に配信する」→ Amazon Data Firehose（古い問題では「Kinesis Data Firehose」と表記される場合あり）。「ストリーミングデータに対する SQL」→ Amazon Managed Service for Apache Flink（旧称 Kinesis Data Analytics）。SQS との対比: Kinesis は保持・再生する、SQS は消費時に削除する。

---

**Amazon MQ** *(第19章)*

Apache ActiveMQ と RabbitMQ をサポートするマネージドのメッセージブローカーサービスです。業界標準のメッセージングプロトコル（AMQP、STOMP、MQTT、OpenWire、WebSocket）をサポートします。主なユースケースは、オンプレミスのメッセージブローカーワークロードのリフトアンドシフト移行です。すでに ActiveMQ または RabbitMQ を使用しているアプリケーションは、コード変更なしで接続できます。

主要な概念: ActiveMQ と RabbitMQ のエンジン選択、プロトコルサポート（AMQP/STOMP/MQTT）、HA のためのシングルインスタンスまたはアクティブ/スタンバイのブローカー構成。

試験のヒント:「オンプレミスの ActiveMQ または RabbitMQ を、アプリケーションコードを変更せずに AWS に移行する」→ Amazon MQ。「グリーンフィールドの AWS ネイティブメッセージング」→ SQS または SNS（よりシンプルでスケーラブル）。

---

## 分析

**Athena** *(第26章)*

S3 に保存されたデータに対するサーバーレスの SQL クエリです。管理するインフラはありません。クエリごと（スキャンした TB ごと）に支払います。列指向フォーマット（Parquet、ORC）とパーティション化されたデータで最も効果を発揮します。

試験のヒント:「S3 のデータを SQL でクエリする」「データレイクに対するアドホック分析」「インフラ管理なし」→ Athena。

---

**Glue** *(第26章)*

サーバーレスの ETL（抽出、変換、ロード）サービスです。Glue クローラーがデータを検出し、Glue Data Catalog を更新します。Glue ジョブが Spark または Python の変換を実行します。Data Catalog は Athena、Redshift Spectrum、EMR と統合されます。

試験のヒント:「分析のためにデータを変換・ロードする」「S3 データのスキーマを検出する」「ETL パイプライン」→ Glue。

---

**Amazon QuickSight** *(第26章)*

マネージドのビジネスインテリジェンスおよびデータ可視化サービスです。SPICE（Super-fast, Parallel, In-memory Calculation Engine）というインメモリエンジンを使用し、高速なダッシュボードレンダリングのためにインポートされたデータをキャッシュします。Athena、S3、Redshift、RDS、その他の AWS データソースに接続します。管理する BI サーバーはありません。

主要な概念: SPICE（インメモリエンジン）、データセット、分析、ダッシュボード、ML Insights（異常検出、予測）、行レベルおよび列レベルのセキュリティ。

試験のヒント:「サーバーを管理せずに AWS 上で BI ダッシュボードを作る」「Athena または Redshift のデータを可視化する」→ QuickSight。

---

**AWS Lake Formation** *(第26章)*

S3 と Glue Data Catalog の上に位置する、一元化されたデータレイクのアクセス制御層です。テーブル、列、行のレベルできめ細かい権限を提供します — S3 バケットポリシー単体よりも詳細です。セキュアなデータレイクのセットアップを簡素化します: Lake Formation が権限モデルを処理し、Glue がカタログを処理し、S3 がデータを保持します。

主要な概念: データレイクの権限（テーブル/列/行レベル）、Glue Data Catalog 統合、属性ベースのアクセス制御のための LF-tags、Athena と Redshift Spectrum のクエリに対する一元化された付与/取り消し。

試験のヒント:「データレイクのきめ細かいアクセス制御」「S3 データに対する列レベルまたは行レベルのセキュリティ」→ Lake Formation。

---

## 高可用性と災害復旧

**Multi-AZ と Multi-Region** *(第18章)*

Multi-AZ: 自動フェイルオーバーのためのリージョン内での同期レプリケーション（RDS Multi-AZ、AZ をまたぐロードバランサー）。RDS では RPO ～0、RTO ～60秒。Multi-Region: 地理的冗長性とグローバルユーザー向けの低レイテンシのための非同期レプリケーション。

主要な概念: RTO（Recovery Time Objective — 復旧までの時間）、RPO（Recovery Point Objective — どれだけのデータを失えるか）。Pilot Light、Warm Standby、Active-Active の DR 戦略。

試験のヒント: AZ レベルの障害（Multi-AZ が対処）とリージョンレベルの障害（Multi-Region が対処）を区別します。Multi-Region ではコストと複雑さが大幅に増加します。

---

**AWS Elastic Disaster Recovery（DRS）** *(第18章)*

サーバー（オンプレミスまたは EC2）向けのマネージド災害復旧です。ソースサーバーをブロック単位で低コストなステージング領域に継続的に複製し、必要なときに数分で完全なリカバリインスタンスを起動します — マネージドな pilot light であり、バックアップ・アンド・リストアに近い価格で warm standby に近い復旧時間を実現します。

主要な概念: 継続的なブロックレベルレプリケーション、低コストなステージング領域、オンデマンドのリカバリ起動、ポイントインタイムリカバリ。

試験のヒント:「マネージドな DR サービスでサーバーベースのワークロードのダウンタイムとデータ損失を最小化する」「自分で構築せずに pilot light を実現する」→ DRS。

---

## コスト最適化

**EC2 の料金モデル** *(第27章)*

オンデマンド: 全額、コミットメントなし。Reserved Instances（1年または3年）: 特定のインスタンスタイプに対して 30～72% の割引。Savings Plans（Compute または EC2 Instance）: 柔軟性のためにコミットした時間単位の支出。スポット: 中断可能なワークロードに対して 60～90% オフ。

試験のヒント:「予測可能なワークロードのコストを最小化する」→ Savings Plans または Reserved Instances。「フォールトトレラントなバッチ処理」→ スポット。「予測不能または短期」→ オンデマンド。

---

**データ転送の料金** *(第30章)*

AWS へのインバウンド: 無料。同一 AZ 内: 無料。AZ をまたぐ: 各方向 $0.01/GB。リージョンをまたぐ: $0.02～0.08/GB。インターネット（アウトバウンド）: 約 $0.09/GB。NAT Gateway の処理: $0.045/GB。CloudFront のデータ転送は EC2 から直接インターネットへ転送するより安く、キャッシングが総量を削減します。

試験のヒント:「プライベートサブネットからの S3/DynamoDB のデータ転送コストを削減する」→ ゲートウェイエンドポイント（無料）。「他のサービスの NAT Gateway コストを削減する」→ インターフェイスエンドポイント。

---

## オブザーバビリティ

**CloudWatch** *(本書全体で参照)*

モニタリングとオブザーバビリティです。CloudWatch メトリクス: AWS サービスとカスタムアプリケーションからの数値の時系列データ。CloudWatch Logs: ログデータの収集、検索、分析。CloudWatch アラーム: メトリクスのしきい値に基づいて通知や自動スケーリングをトリガー。CloudWatch ダッシュボード: メトリクスの可視化。

主要な概念: メトリクスのディメンション、保持期間、ロググループとログストリーム、メトリクスフィルター、CloudWatch エージェント（EC2 からの OS レベルのメトリクスとログ向け）、Container Insights。

---

**CloudTrail** *(本書全体で参照)*

AWS アカウントで行われたすべての API 呼び出しを記録します: 誰が、どこから、いつ、レスポンスは何だったか。マルチリージョンの証跡はログを S3 に無期限に保存します。セキュリティ監査、コンプライアンス、インシデント調査に使用されます。

試験のヒント:「誰がそのリソースを削除したか？」「すべての API アクティビティを監査する」→ CloudTrail。

---

**X-Ray** *(第20章)*

分散トレーシングです。個々のリクエストをサービス間で追跡し（トレース → セグメント → サブセグメント）、ホップごとのレイテンシとエラー率を含むサービスマップを構築します。サンプリングによりオーバーヘッドを低く抑え、アノテーションによりトレースを検索可能にします。アクティブトレーシングは Lambda と API Gateway のステージで切り替えられます。

試験のヒント:「マイクロサービス間でリクエストをトレースする」「サービス間のボトルネックを見つける」→ X-Ray（CloudWatch でも CloudTrail でもない）。

---

**AWS Config** *(第31章で参照)*

時間の経過に伴うリソース構成の変更を追跡します。リソースをコンプライアンスルールに照らして評価します。すべてのリソースのすべての構成変更の履歴を記録します。修復のために Systems Manager と統合されます。

試験のヒント:「このリソースは当社のセキュリティポリシーに準拠しているか？」「先週このリソースの構成はどうなっていたか？」→ AWS Config。

---

## Well-Architected

**6つの柱** *(第31章)*

| 柱 | 中心的な問い | 主要なサービス |
|------------------------|-----------------------------------------|---------------------------------------------------|
| 運用上の優秀性 | 適切に運用できているか？ | CloudWatch、CloudTrail、SSM、Config |
| セキュリティ | 保護されているか？ | IAM、KMS、GuardDuty、WAF、Shield、Secrets Manager |
| 信頼性 | 障害から復旧できるか？ | Multi-AZ、Route 53 フェイルオーバー、バックアップ/リストア、SQS |
| パフォーマンス効率 | 適切なリソースを使用しているか？ | ライトサイジング、Auto Scaling、CloudFront、Kinesis |
| コスト最適化 | 賢く支出しているか？ | Savings Plans、スポット、S3 ライフサイクル、VPC エンドポイント |
| 持続可能性 | 環境への影響を最小化しているか？ | ライトサイジング、Graviton、効率的なストレージ階層 |

AWS Well-Architected Tool: アーキテクチャを6つの柱に照らして評価します。各柱の問いの背後にある根拠を理解するために、試験前に使用してください。
