# 付録 A: AWS サービスクイックリファレンス

この本で扱われているすべてのサービスを、導入された順序で示します。この資料を学習リファレンスとして、試験対策の際のクイックルックアップとして使用してください。

---

## 計算

**EC2 — Elastic Compute Cloud** *(第4章)*

クラウド上の仮想マシンです。インスタンスタイプ（CPU、メモリ、ストレージ）、オペレーティングシステム、リージョンを選択します。オンデマンド（1時間あたりの支払い）、予約インスタンス/セービングプラン（コミットメント）、スペア容量スロット（スポット）で支払います。基本的な計算プリミティブです。

主要な概念：AMI（Amazon Machine Image）、インスタンスタイプ（t3、m6g、r6g、c6g ファミリー）、キーペア、インスタンスプロファイル、配置グループ。

試験のヒント：永続的な状態、長時間の実行が必要な計算、またはEC2またはECSが必要なシナリオ。短期間、イベントトリガー、またはアイドル時間なしの計算が必要なシナリオでは、Lambdaを使用します。

---

**Auto Scaling + Application Load Balancer** *(第7章)*

Auto Scaling Groups (ASGs) は、負荷に基づいてEC2インスタンスを追加および削除します。Application Load Balancers (ALBs) は、トラフィックをインスタンス間で分散し、パスまたはホストに基づいてルーティングします。これらは、水平スケーリング層を形成します。

主要な概念：Launch テンプレート、スケーリングポリシー（ターゲット追跡、ステップ、スケジュール）、ヘルスチェック、ALB ターゲットグループ、リスナールール、重み付きルーティング。

試験のヒント：「変動する負荷」または「AZ全体での高可用性」→ ASG + ALB。

---

**Lambda** *(第20章)*

サーバーレス関数です。コードを記述し、AWSがイベントに応答してそれを実行します。サーバーを管理する必要はありません。呼び出しごと、および実行ミリ秒ごとに支払います。数千の同時実行例に自動的にスケーリングされます。

主要な概念：イベントソース（API Gateway、S3、SQS、EventBridge、Kinesis）、役割、同時実行制限、予約済みおよびプロビジョニング済み同時実行、コールドスタート、レイヤー、15分最大実行時間。

試験のヒント：「サーバーレス」、「イベント駆動」、「短時間のタスク」、「アイドルコストなし」→ Lambda。

---

**ECS — Elastic Container Service** *(第21章)*

AWSでDockerコンテナを実行します。2つの起動タイプ：EC2（ホストを管理します）とFargate（AWSがホストを管理します）。ECSは、タスク定義、サービス、クラスタスケジューリング、ロードバランサーおよびサービスディスカバリとの統合を管理します。

主要な概念：タスク定義、ECSサービス、Fargate vs. EC2 起動タイプ、ECR（コンテナレジストリ）、タスクIAMロール、サービス自動スケーリング。

試験のヒント：「コンテナ化されたワークロード」、「マイクロサービス」、「Docker on AWS」→ ECS（通常はサーバーレスコンテナの場合はFargateを使用します）。

---

**EKS — Elastic Kubernetes Service** *(第21章)*

マネージドKubernetesです。AWSがコントロールプレーンを実行し、ユーザーがワーカーノード（EC2またはFargate）を実行します。EKSを使用する場合は、チームがすでにKubernetesを使用しているか、Kubernetes固有の機能が必要なワークロードを実行する場合に使用します。

試験のヒント：「Kubernetes」、「既存のK8sワークロードへの移行」→ EKS。「コンテナが必要だがK8sのオーバーヘッドは不要」→ ECS。

---

## ストレージ

**S3 — Simple Storage Service** *(第5章)*

オブジェクトストレージです。無限容量、99.999999999%（11ナイン）の耐久性。ファイルをオブジェクトとしてバケットに保存します。バケットはリージョンに存在します。オブジェクトは0バイトから5TBの範囲です。

主要な概念：バケットポリシー、オブジェクトACL、バージョン管理、静的ウェブサイトホスティング、署名付きURL、マルチパートアップロード、Transfer Acceleration、ストレージクラス（Standard、Intelligent-Tiering、Standard-IA、One Zone-IA、Glacier Instant Retrieval、Glacier Flexible Retrieval、Glacier Deep Archive）。

試験のヒント：「ファイルを保存および取得」、「静的アセット」、「バックアップ」、「データレイク」→ S3。適切なストレージクラスは、アクセス頻度と取得速度によって異なります。

---

**EBS — Elastic Block Store** *(第6章)*

単一のEC2インスタンスにアタッチされるブロックストレージです。ハードドライブのように機能します。インスタンスライフサイクルの独立して永続です（取り外して再アタッチできます）。最も一般的なタイプ：gp3（汎用SSD、デフォルト）、io2（データベース用のプロビジョニングされたIOPS）、st1（順方向読み取り向けHDD、シーケンシャル読み取り）。

主要な概念：スナップショット（増分、S3に保存）、暗号化（KMS）、マルチアタッチ（io1/io2のみ）、IOPSおよび帯域幅のプロビジョニング。

試験のヒント：「EC2用の永続ストレージ」、「データベースストレージ」、「低レイテンシのブロックアクセスが必要」→ EBS。

---

**EFS — Elastic File System** *(第6章)*

複数のEC2インスタンスから同時にアクセスできる共有ファイルシステムです。NFSプロトコルを使用します。自動的にスケーリングされます。EBSよりもGBあたりコストが高くなります。2つのストレージクラス：StandardとInfrequent Access。Intelligent-Tieringは、アクセス頻度に基づいてファイルを自動的に階層間で移動します。

試験のヒント：「複数のEC2インスタンスが同じファイルを必要とする」、「共有ファイルシステム」、「NFS」→ EFS。

---

**S3 ストレージクラスとライフサイクルポリシー** *(第23章)*

S3 Intelligent-Tieringは、アクセス頻度に基づいてオブジェクトを自動的に階層間で移動します。ライフサイクルポリシーは、年齢ルールに基づいてオブジェクトを階層間で移行します（Standard → Standard-IA → Glacier）。Glacierストレージクラスの取得遅延は、分（Glacier Instant）から12時間（Glacier Deep Archive）です。

Exam signal: "Reduce storage costs for infrequently accessed data" → lifecycle policies, Intelligent-Tiering, または Glacier。

---

## データベース

**RDS —  関係データベースサービス** *(第8章)*

管理されたリレーショナルデータベース。サポートされているエンジン: MySQL、PostgreSQL、MariaDB、Oracle、SQL Server、および Aurora（AWS独自のエンジン）。AWSがバックアップ、パッチ適用、フェイルオーバー、およびレプリケーションを処理します。スキーマ設計、クエリ、およびインスタンスサイズの管理は、お客様が行います。

主要な概念: Multi-AZ デプロイメント（自動フェイルオーバー、同期レプリケーション）、Read レプリカ（非同期、読み取りスケーリング）、自動バックアップ（1～35日間の保持）、手動スナップショット（削除されるまで保持）、RDS Proxy（接続プーリング）。

Exam signal: "リレーショナルデータベース," "ACID トランザクション," "既存のSQLワークロード" → RDS または Aurora。

---

**Aurora** *(第24章)*

AWSの、MySQLおよびPostgreSQLと互換性のあるリレーショナルデータベースエンジン。3 AZにデータを複製する分散ストレージエンジン。通常、MySQLの5倍速です。Aurora Serverless v2は、ACU（Aurora容量ユニット）で測定された容量を自動的にスケーリングします。

主要な概念: Auroraクラスタ（ライター+最大15個のリーダーエンドポイント）、Auroraグローバルデータベース（<1秒のレプリケーション遅延でクロスリージョン読み取りレプリカ）、Aurora Serverless v2。

Exam signal: "高パフォーマンスのリレーショナルデータベース," "MySQL/PostgreSQL互換," "グローバル読み取り," "変動するワークロード" → Aurora。

---

**DynamoDB** *(第9章)*

フルマネージドのNoSQLデータベース。キーバリューおよびドキュメントモデル。単筆ミリ秒のパフォーマンスで、任意のスループットにスケールします。2つの容量モード: on-demand（リクエストごとの支払い）およびプロビジョニング（1時間あたりの容量ユニットの支払い、Auto Scaling付き）。

主要な概念: パーティションキー（必須）、ソートキー（オプション）、グローバルセカンダリインデックス（GSI）、ローカルセカンダリインデックス（LSI）、DynamoDB Streams（変更データキャプチャ）、DynamoDB Accelerator（DAX）— メモリキャッシュ、TTL（Time to Live）、トランザクション。

Exam signal: "高スループットのキーベースアクセス," "柔軟なスキーマ," "サーバーレスNoSQL" → DynamoDB。

---

**ElastiCache** *(第10章)*

管理されたインメモリキャッシュ。2つのエンジン: Redis（永続的、pub/sub、Luaスクリプト、データ構造）およびMemcached（純粋キャッシュ、シンプル、マルチスレッド）。データベース負荷を軽減し、頻繁に読み取りされるデータをマイクロ秒で提供するために使用します。

主要な概念: キャッシュアサイドパターン、書き込みスルーパターン、エビクションポリシー、TTL、クラスタモード（Redis）、Multi-AZ（自動フェイルオーバー）。

Exam signal: "データベース負荷の軽減," "サブミリ秒の読み取りレイテンシ," "セッション管理," "リアルタイムリーダーボード" → ElastiCache Redis。

---

## ネットワーク

**VPC — 仮想プライベートクラウド** *(第11章)*

AWS内の隔離されたネットワーク。すべてのAZ（アベイラビリティゾーン）にわたります。IPアドレス空間（CIDRブロック）を定義し、サブネット（パブリックまたはプライベート）を作成し、ルーティングテーブルを設定し、セキュリティグループとNACLを使用してアクセスを制御します。

主要な概念: パブリックサブネット（インターネットゲートウェイへのルーティング）、プライベートサブネット（エキソートへのルーティングのためのNATゲートウェイ）、インターネットゲートウェイ（インターネットへのインバウンドおよびアウトバウンド）、NATゲートウェイ（プライベートインスタンスへのアウトバウンドのみ）、VPCピアリング（2つのVPCを接続）、VPCエンドポイント（AWSサービスへの接続なしでインターネットを使用）。

Exam signal: "AWS上のプライベートネットワーク," "インターネットからリソースを隔離," "ネットワークトラフィックを制御" → VPC。

---

**セキュリティグループとNACL** *(第15章)*

セキュリティグループはインスタンスレベルのステートフルファイアウォール—許可ルールのみ、返送トラフィックは自動です。NACL（ネットワークアクセス制御リスト）はサブネットレベルのステートレスファイアウォール—インバウンドおよびアウトバウンドの両方のルールが必要で、ルール番号の順序で評価されます。

Exam signal: "特定のIPアドレスがサブネットへのアクセスをブロックする" → NACL。 "インスタンスへのトラフィックを制御する" → セキュリティグループ。

---

**Route 53** *(第12章)*

AWSのDNSサービスおよびドメイン登録サービス。インターネットトラフィックをAWSリソースおよび外部エンドポイントにルーティングします。ルーティングポリシー: Simple、Weighted、Latency-based、Failover、Geolocation、Geoproximity、Multi-value answer。

主要な概念: ホストゾーン（パブリックおよびプライベート）、レコードタイプ（A、AAAA、CNAME、Alias）、ヘルスチェック、トラフィックフロー（視覚的なポリシーエディター）。

Exam signal: "DNSルーティング," "リージョン間のフェイルオーバー," "遅延または場所に基づいてルーティング" → Route 53 を適切なルーティングポリシーとともに使用。

---

**CloudFront** *(第13章)*

コンテンツデリバリーネットワーク（CDN）。エッジロケーション（400人以上世界規模）でコンテンツをキャッシュします。エンドユーザーのレイテンシを削減します。S3、EC2、ALB、API Gatewayなどのオリジンへの転送コストを削減します。

主要な概念: ディストリビューション、オリジン、動作（パスベースのルーティング）、TTL（キャッシュ制御）、キャッシュ無効化、署名されたURLとCookie（アクセス制御）、Lambda@EdgeとCloudFront Functions（エッジでコードを実行）、オリジンシールド（オリジン負荷の軽減）。

Exam signal: "グローバルな低レイテンシ," "静的コンテンツのキャッシュ," "オリジン負荷の軽減," "ShieldによるDDoS保護" → CloudFront。

---

**Direct ConnectとVPN** *(第25章)*

AWS Direct Connect は、オンプレミスデータセンターから AWS に向かう専用の物理ネットワーク接続です。パブリックインターネットをバイパスし、より一貫した帯域幅とレイテンシを提供します。AWS Site-to-Site VPN は、パブリックインターネットを介した暗号化されたトンネルであり、設定が速く、コストが低く、パフォーマンスは変動します。

主要な概念：仮想インターフェース (VIF)、Direct Connect Gateway (複数のリージョンへの接続)、Transit Gateway (ハブアンドスポークネットワークトポロジー)、VPN トンネル冗長性。

試験のヒント：「専用のプライベート接続を AWS に」→ Direct Connect。「暗号化された接続、設定が速い」→ VPN。「複数の VPC に接続」→ Transit Gateway。

---

**VPC エンドポイント** *(第30章)*

プライベートリソースをパブリックインターネットまたは NAT Gateway を使用せずに AWS サービスに接続します。Gateway エンドポイントは無料であり、S3 と DynamoDB のみに対して利用可能です。Interface エンドポイント (PrivateLink) は、1 時間あたり + 1 GB あたりの料金で、ほとんどの AWS サービスに対して利用可能です。

試験のヒント：「EC2 がプライベートサブネットから S3/DynamoDB を呼び出す—NAT Gateway のコストを削減」→ Gateway エンドポイント (無料)。「プライベートサブネットから SQS、SSM、Secrets Manager への接続」→ Interface エンドポイント。

---

## セキュリティとアイデンティティ

**IAM — アイデンティティとアクセス管理** *(第3章と第14章)*

アカウント内で誰が何を実行できるかを制御します。ユーザー (長期の認証情報)、グループ (権限を共有するユーザー)、ロール (サービスとクロスアカウントアクセス用の一時認証情報)、ポリシー (許可/拒否のルールを定義する JSON ドキュメント)。

主要な概念：プリンシパル、アクション、リソース、条件、明示的な拒否 > 明示的な許可 > 黙示的な拒否、SCP (AWS Organizations でのサービス制御ポリシー)、Permission boundary、AssumeRole。

試験のヒント：IAM はすべてのセキュリティ質問に関与します。主要なパターン：サービスは IAM ロール (ユーザーではない) を使用します。クロスアカウントアクセスはロールによる仮名を使用します。最小特権—必要なものだけを付与します。

---

**KMS — キー管理サービス** *(第16章)*

管理された暗号化キーサービスです。暗号化キーを作成、保存、制御します。顧客管理キー (CMK) を使用すると、ローテーション、使用状況、アクセスポリシーを定義できます。AWS 管理キーは自動的に管理されます。

主要な概念：キーポリシー (IAM ポリシーとは別)、エンベロープ暗号化 (データキーで暗号化されたデータ、データキーを CMK で暗号化)、自動キーローテーション、マルチリージョンキー、 Grants。

試験のヒント：「データを暗号化する」、「顧客管理暗号化キー」、「キーローテーション」→ KMS。

---

**Secrets Manager** *(第16章)*

機密値を自動的にローテーションする: データベースの認証情報、API キー、OAuth トークン。RDS で自動パスワードローテーションを統合します。アプリケーションは API を通じて実行時に秘密値を取得し—認証情報をハードコーディングしません。

試験のヒント：「データベースの認証情報を保存してローテーションする」、「ハードコーディングされた秘密を避ける」→ Secrets Manager。「構成値を保存するのではなく、秘密を保存する」→ Parameter Store (SSM)。

---

**AWS Shield** *(第17章)*

DDoS 保護。Shield Standard は自動で無料であり—一般的な体積攻撃とプロトコル攻撃を保護します。Shield Advanced は、財務保護、24 時間 7 時間の DDoS 応答チーム、詳細な攻撃可視性を追加します。

試験のヒント：「DDoS から保護する」→ Shield Standard (自動) または Shield Advanced (エンタープライズ、SLA 付き)。

---

**WAF — Web アプリケーションファイアウォール** *(第17章)*

HTTP/HTTPS トラフィックをルールに基づいてフィルタリングします：IP ブロック、レート制限、SQL インジェクションパターン、XSS パターン、地理的制限、カスタムルール。CloudFront、ALB、API Gateway、AppSync にアタッチされます。

試験のヒント：「特定の IP アドレスをブロックする」、「エッジで SQL インジェクションを防止する」、「API 呼び出しをレート制限する」→ WAF。

---

**GuardDuty** *(第17章)*

脅威検出サービス。CloudTrail ログ、VPC Flow Logs、DNS ログを ML と脅威インテリジェンスを使用して分析します。異常な API アクティビティ、既知の悪意のある IP アドレスへの通信、侵害された認証情報を検出します。

試験のヒント：「異常なアクティビティを検出する」、「侵害された IAM 認証情報を識別する」、「継続的な脅威監視」→ GuardDuty。

---

## メッセージングとイベント処理

**SQS — シンプルキューサービス** *(第19章)*

管理されたメッセージキューです。プロデューサーはメッセージを送信し、消費者はそのメッセージを読み取り、削除します。サービス間の疎結合を実現します：送信側が受信側の可用性を知る必要はありません。標準キュー：少なくとも一度の配信、最良の努力による順序付け。FIFO キュー：一度だけ正確な処理、厳密な順序付け。

主要な概念：視認性タイムアウト (メッセージが他の消費者によって処理中に隠される)、死葉キュー (DLQ) は、繰り返し失敗するメッセージ用のもの、メッセージの保持期間 (デフォルト 4 日、最大 14 日)、ロングポーリング (空の応答を減らす)。

試験のヒント：「サービスを疎結合にする」、「負荷の変動中にリクエストをバッファリングする」、「非同期処理」→ SQS。「順序が重要で、一度だけ正確な処理が必要」→ SQS FIFO。

---

**SNS — シンプル通知サービス** *(第19章)*

管理された pub/sub サービスです。発行者はトピックにメッセージを送信し、すべてのサブスクライバーがコピーを受け取ります。ファンアウトパターン：1 メッセージ → 多数の消費者。プロトコル：SQS、Lambda、HTTP/HTTPS、電子メール、SMS、モバイルプッシュ。

Key concepts: トピック、サブスクリプション、ファンアウトパターン（SNS → 複数のSQSキュー）、メッセージフィルタリング（サブスクライバーは一致するメッセージのみを受信）

Exam signal: 「複数のエンドポイントに同時に通知を送信する」、「単一のイベントを複数の消費者へファンアウトする」→ SNS。一般的なパターン：SNS + SQSによる耐久性のあるファンアウト。

---

**EventBridge** *(第22章)*

イベントバスは、イベント駆動型アーキテクチャを構築するために使用されます。AWSのサービス、SaaSパートナー、カスタムソースからのイベントを、Lambda、SQS、SNS、Step Functions、その他のターゲットにルーティングします。スケジュールされたルール（cron）とパターンマッチングをサポートします。

Exam signal: 「AWSのサービスからターゲットにイベントをルーティングする」、「Lambda関数をスケジュールする」、「イベント駆動型オーケストレーション」→ EventBridge。

---

**Step Functions** *(第22章)*

サーバーレスワークフローオーケストレーション。Lambda関数、ECSタスク、DynamoDB、SNS、SQS、その他のサービスを視覚的なステートマシンに統合します。リトライ、エラー処理、並行ブランチ、待機状態を処理します。

Key concepts: ステートマシン、ステートタイプ（タスク、待機、選択、並行、マッピング、パス、成功、失敗）、標準ワークフロー（一貫性のある、長時間の実行）と表現ワークフロー（少なくとも一度、高スループット）。

Exam signal: 「複数のLambda関数をオーケストレーションする」、「リトライロジックを備えた長時間のワークフロー」、「人間による承認ステップ」→ Step Functions。

---

**Kinesis** *(第26章)*

リアルタイムデータストリーミング。Kinesis Data Streams: 記録の耐久性があり、順序付けられたストリーム（分散型コミットログのようなもの）。消費者で記録を処理し、データは24時間から7日間保持されます。Kinesis Data Firehose: S3、Redshift、OpenSearch、Splunkへの完全管理された配信—消費者の管理が不要。

Key concepts: シャード（スループットの単位：1MB/sの書き込み、2MB/sの読み込み）、パーティションキー（シャード割り当てを決定する）、シーケンス番号、チェックポイント（KCLまたはLambda）、Firehose vs. Streams。

Exam signal: 「リアルタイムストリーミング」、「順序付けられた記録」、「イベントの再再生」→ Kinesis Data Streams。「ストリーミングデータをS3/Redshiftに管理しなくても配信する」→ Kinesis Firehose。SQSとの対比：Kinesisは保持し、再生しますが、SQSは消費時に削除します。

---

## 分析

**Athena** *(第26章)*

S3に保存されたデータをSQLでクエリするサーバーレスサービス。インフラストラクチャの管理は不要です。クエリごとに料金が発生（スキャンされたTBあたり）。カラム形式（Parquet、ORC）とパーティション分割されたデータに適しています。

Exam signal: 「S3データをSQLでクエリする」、「データレイク上のアドホック分析」、「インフラストラクチャ管理の不要」→ Athena。

---

**Glue** *(第26章)*

サーバーレスETL（抽出、変換、ロード）サービス。Glue Crawlersはデータを検出し、Glue Data Catalogを更新します。Glue JobsはSparkまたはPythonの変換を実行します。Data CatalogはAthena、Redshift Spectrum、EMRと統合されます。

Exam signal: 「分析のためにデータを変換およびロードする」、「S3データのスキーマを発見する」、「ETLパイプライン」→ Glue。

---

## 高可用性と災害復旧

**Multi-AZとMulti-Region** *(第18章)*

Multi-AZ: 地域の同期レプリケーションによる自動フェイルオーバー（RDS Multi-AZ、AZ間でロードバランサー）。RPO〜0、RDSの場合RTO〜60秒。Multi-Region: 地理的な冗長性とグローバルユーザーに対する低遅延のための非同期レプリケーション。

Key concepts: RTO（復旧時間目標—回復にかかる時間）、RPO（復旧ポイント目標—失われる可能性のあるデータの量）。Pilot Light、Warm Standby、Active-Active DR戦略。

Exam signal: AZレベルの障害（Multi-AZで処理）と地域レベルの障害（Multi-Regionで処理）を区別します。Multi-Regionはコストと複雑性が大幅に増加します。

---

## コスト最適化

**EC2の価格モデル** *(第27章)*

On-Demand: フルプライス、コミットメントなし。Reserved Instances（1または3年）：特定のインスタンスタイプに対して30〜72%の割引。Savings Plans（ComputeまたはEC2 Instance）：柔軟性のある時間ベースのコミットメント費用。Spot: 60〜90%オフで中断可能なワークロード向け。

Exam signal: 「予測可能なワークロードに対して最小限のコストを実現する」→ Savings PlansまたはReserved Instances。「フォールトトレラントなバッチ処理」→ Spot。「予測不可能または短期的」→ On-Demand。

---

**データ転送の価格** *(第30章)*

インバウンドAWS: 無料。同じAZ: 無料。AZ間でクロス: 1方向あたり0.01GB。クロス地域: 1方向あたり0.02〜0.08GB。インターネット（アウトバウンド）: 約0.09GB。NAT Gatewayの処理: 0.045GB。CloudFrontのデータ転送は、直接EC2-to-internetよりも安く、キャッシュにより総ボリュームを削減します。

Exam signal: 「S3/DynamoDBからプライベートサブネットへのデータ転送コストを削減する」→ Gateway Endpoints（無料）。「他のサービス向けのNAT Gatewayのコストを削減する」→ Interface Endpoints。

---

## 可観測性

**CloudWatch** *(全体を通して参照)*

監視と可観測性。CloudWatch Metrics: AWSサービスとカスタムアプリケーションからの数値時間系列データ。CloudWatch Logs: ログデータを収集、検索、分析します。CloudWatch Alarms: メトリックの閾値に基づいて通知をトリガーしたり、スケーリングを自動化したりします。CloudWatch Dashboards: データを視覚化します。

Key concepts: メトリック次元、保持期間、ロググループとログストリーム、メトリックフィルター、CloudWatch Agent（OSレベルのメトリックとEC2からのログを含む）、Container Insights。

---

**CloudTrail** *(章全体を通して参照)*

AWS アカウントで行われたすべての API 呼び出しを記録します。誰が実行したのか、どこから実行したのか、いつ実行したのか、そしてどのような応答だったのかを把握します。マルチリージョントレイルは、S3 にログを永久に保存します。セキュリティ監査、コンプライアンス、インシデント調査に使用されます。

試験のヒント：「そのリソースを削除したのは誰ですか？」「すべての API アクティビティを監査する」→ CloudTrail。

---

**AWS Config** *(第31章で参照)*

リソースの構成変更を時間経過とともに追跡します。リソースをコンプライアンスルールと評価します。すべてのリソースの構成変更履歴を記録します。Systems Manager と連携して修復を行います。

試験のヒント：「このリソースが当社のセキュリティポリシーに準拠していますか？」「このリソースの構成は先週どうなっていたのですか？」→ AWS Config。

---

## 優れたアーキテクチャ

**6つの柱** *(第31章)*

| 柱                 | 核心的な質問                           | 主要なサービス                               |
|------------------------|-----------------------------------------|---------------------------------------------|
| 運用卓越性           | 私たちはうまく稼働していますか？             | CloudWatch, CloudTrail, SSM, Config         |
| セキュリティ           | 私たちは保護されていますか？               | IAM, KMS, GuardDuty, WAF, Shield, Secrets Manager |
| 信頼性               | 障害から回復できますか？                 | マルチAZ、Route 53 フェールオーバー、バックアップ/リストア、SQS |
| パフォーマンス効率     | 適切なリソースを使用していますか？       | サイズ調整、Auto Scaling、CloudFront、Kinesis |
| コスト最適化         | 賢くお金を使っていますか？               | 従量課金プラン、スポットインスタンス、S3ライフサイクル、VPCエンドポイント |
| 持続可能性         | 環境への影響を最小限に抑えていますか？ | サイズ調整、Graviton、効率的なストレージ階層 |

AWS Well-Architected ツール：アーキテクチャを 6 つの柱と評価します。試験の前に、各柱の質問の背後にある理由を理解するために使用してください。
