**3つの脅威カテゴリ**

クラウドアプリケーションに対するセキュリティ脅威は、一般的に以下の3つのカテゴリに分類される：

**ボリューム攻撃（DDoS）**: 攻撃者が大量のトラフィックを送信し、アプリケーションが正当なユーザーへの応答を返せない状態になる。攻撃は、何百万ものHTTPリクエスト、またはサーバーの接続テーブルを枯渇させるように設計されたTCP SYNパケットの洪水である可能性がある。

**アプリケーション攻撃（エクスプロイト）**: 攻撃者は、アプリケーションの脆弱性を悪用するように設計された、特定のコンテンツを持つリクエストを送信する。SQLインジェクション、クロスサイトスクリプティング、パースをクラッシュさせるような不正な入力など。

**行動的異常（偵察と侵害）**: 発生してはならないAPI呼び出し（ユーザーデータベース全体を3時にクエリするなど）、不審なIAMアクティビティ（新しい国からの認証情報の使用）、予期しない宛先へのネットワークトラフィックなど。

AWSはそれぞれ専用のサービスを提供している：

- **AWS Shield**: DDoS保護
- **AWS WAF**: アプリケーション層保護
- **Amazon GuardDuty**: 行動的脅威検出

**AWS Shield: DDoS吸収器**

**AWS Shield Standard**は、すべてのAWS顧客に対して追加料金なしで自動的に有効になっている。最も一般的なレイヤー3（ネットワーク）およびレイヤー4（トランスポート）DDoS攻撃—SYN floods、UDP floods、DNSアンプリファケーション攻撃を保護する。

CloudFront、Route 53、Elastic Load Balancingは、AWSネットワークのエッジに位置している。DDoS攻撃がアプリケーションを標的にした場合、これらの管理されたサービスに最初にヒットする。AWSのネットワークインフラストラクチャは、攻撃がEC2インスタンスに到達する前に攻撃を吸収する。

**AWS Shield Advanced**は、月額3,000ドル（組織あたり）のプレミアム階層である。以下の機能を追加する：

- EC2、ELB、CloudFront、Global Accelerator、Route 53の保護
- ほぼリアルタイムの攻撃通知
- 攻撃に対応するためのAWS Shield Response Team（SRT）へのアクセス—セキュリティエンジニア
- コスト保護：攻撃が請求額を急増させる場合、AWSは急増したコストをクレジットする
- 7層（アプリケーション層）での高度なDDoS検出と軽減

「1か月3,000ドル？」トムは言った。

「何百万ドル規模の収益を扱う企業にとって、2時間もダウンしてしまうDDoS攻撃が3,000ドルよりも高くなる」プリヤは言った。

トムは静かに計算をした。

「標準版から始めよう」と彼はついに言った。

**AWS WAF: アプリケーションフィルター**

**AWS WAF (Web Application Firewall)**は、HTTPレベルで動作する—Webリクエストの内容をアプリケーションに到達する前に検査する。

WAFは**Web ACL (アクセス制御リスト)**—許可、ブロック、またはカウントするものを定義するルールセットで構成される。

WAFは以下の場所に添付できる：

- CloudFrontディストリビューション（グローバルレベルでエッジでリクエストを検査）
- アプリケーションロードバランサー（地域レベルでリクエストを検査）
- API Gateway
- AWS AppSync

**WAF Managed Rules**: AWSとサードパーティベンダーが公開するプレビルドのルールセット：

- **AWS Managed Rules - Core Rule Set**: OWASP Top 10の脆弱性（SQLインジェクション、XSS、コマンドインジェクション、パストレースなど）を保護する
- **AWS Managed Rules - Known Bad Inputs**: 既知の攻撃パターンに一致するリクエストをブロックする
- **AWS Managed Rules - Amazon IP Reputation List**: ボットネットやスキャナーに関連するIPアドレスをブロックする
- **AWS Managed Rules - Bot Control**: ボットトラフィックを特定し、管理する

独自のルールを作成することも可能：

- 「User-Agentヘッダーに'sqlmap'が含まれているリクエストをブロックする」
- 「許可するリクエストの最大数を5分あたり1,000件に制限する」
- 「パラメータ値に`<script>`が含まれているリクエストをブロックする」

Nimbusの場合、実用的な設定：CloudFrontディストリビューションにWAFを適用し、Core Rule Setを有効にする。これにより、最も一般的な攻撃パターンがEC2インスタンスに到達する前にブロックされる。

**Amazon GuardDuty: 行動的アナリスト**

GuardDutyはShieldやWAFとは根本的に異なる。攻撃をブロックするのではなく、**異常な行動を検出する**。

GuardDutyは継続的に分析する：

- **AWS CloudTrailログ**: IAM変更、API呼び出し、コンソールログイン
- **VPC Flow Logs**: VPC内のネットワークトラフィックパターン
- **DNSクエリログ**: インスタンスが解決しているもの（既知のマルウェアは通常、特定のC2ドメインを解決する）

機械学習モデルは、あなたの基準からの逸脱を示すパターンを特定します。GuardDutyは、異常を検出した場合にカテゴリ分けされたアラートである**発見事項**を生成します。

GuardDutyが検出できる例としては、以下のようなものがあります。

- IAMユーザーが認識されていないIPアドレス（それ以前に使用したことのない国）からのログイン
- TorエクスイトノードからのAPI呼び出し
- 既知の暗号通貨マイニングプールへのEC2インスタンスの通信
- 通常外のAPI呼び出し量の増加（資格情報の悪用またはスキャン）
- 悪意のある活動の疑いのあるIPアドレスでアクセスされたS3バケット
- マルウェアコマンドアンドコントロールに関連するドメインへのエクスポートトラフィック

「これがロマネリアのIPアドレスをキャッチしたところだ」とレオは静かに言いました。

「GuardDutyを有効にしていれば、2時に外部の認識されていないIPアドレスへのエクスポート接続を行っているEC2インスタンスを検出し、アラートを発行していたに違いありません」とプリヤが確認しました。

「コストはいくらですか？」

GuardDutyの価格は、分析されるログの量に基づいており、CloudTrailイベント、VPCフローデータ、DNSクエリです。小規模から中規模のアプリケーションの場合、通常は月額50〜150ドルです。大規模の場合は、依然としてインフラストラクチャコストのほんの一部です。

トムはコンソールをプルアップし、有効にしました。

**3つのサービスの接続**

Shield、WAF、GuardDutyは異なる層で動作し、互いに補完し合います。

| サービス    | レイヤー                     | 守るもの                               | 行動                               |
|------------|---------------------------|---------------------------------------------|------------------------------------|
| AWS Shield | ネットワーク/輸送 (L3/L4) | DDoS洪水                                 | 吸収/攻撃を軽減                    |
| AWS WAF    | アプリケーション (L7)          | OWASP Top 10、ボット、スクレイパー                | リクエストを許可、ブロック、またはカウント |
| GuardDuty  | 行動 (すべてのログ)     | 異常、侵害された資格情報、マルウェア           | 検出とアラート                     |

Shieldは洪水を止める。WAFは水をろ過する。GuardDutyは、通常外のフローパターンを監視する。

**CloudTrail: 基盤**

3つのサービスはすべてログに依存しています。**AWS CloudTrail**は、あなたのAWSアカウントのすべてのAPI呼び出しをキャプチャするロギングサービスです。誰が何を、いつ、どこから、どのような結果で呼び出しているかを確認できます。

CloudTrailはコンソールで90日間の履歴に対してデフォルトで有効になります。ログを長期的に保持するには、以下の手順を実行します。

1. S3バケットに書き込むトレイルを作成する
2. リアルタイムアラートのためにオプションでCloudWatch Logsに送信する
3. ログファイル検証を有効にする（ログが改ざんされていないか検出するため）

GuardDuty、AWS Config、Security HubはすべてCloudTrailのログを読み取ります。CloudTrailログがない場合、これらのサービスは分析するものがありません。

**AWS Security Hub: ダッシュボード**

複数のAWSアカウントを運用している場合、またはセキュリティの発見事項を統合されたビューで確認したい場合は、**AWS Security Hub**はGuardDuty、Inspector（脆弱性評価）、Macie（データプライバシー）、Config、Firewall Managerからの発見事項を単一のダッシュボードに集約します。

また、AWS Foundational Security Best Practices標準およびCIS AWS Foundations Benchmarkのセキュリティベストプラクティスに準拠しているかを確認します。

ソフィア: Security Hubはまだ必要ではありませんでした。3つのアカウント（開発、ステージング、本番）に成長するまででした。

## 強みと限界

**AWS Shield**:

- 標準: 無料で自動—使用する理由はありません
- 高度: 高い優先順位のターゲットに最適—小規模チームには高価

**AWS WAF**:

- 管理されたルールグループにより、設定が大幅に簡素化されます
- カスタムルールには、HTTP攻撃パターンに関する理解が必要です
- リアルタイム制限は強力な機能であり、しばしば見過ごされます
- WAFは、安全なアプリケーションコードの代わりにはなりません—それは防御の深さのレイヤーです

**GuardDuty**:

- 構成が非常に簡単（数クリック）
- 発見事項には人間のレビューと応答が必要です—GuardDutyは検出しますが、修正しません
- 偽陽性が発生します—一部の正当なアクティビティは、MLモデルによって異常と見なされます
- 30日間の無料トライアル—すぐに有効にすることをお勧めします

## 概要

- **AWS Shield Standard**: 無料で自動の、レイヤー3/4のDDoS保護。常にオンです。
- **AWS Shield Advanced**: SRTアクセスとコスト保護を備えた、プレミアムDDoS保護。エンタープライズユースケースです。
- **AWS WAF**: アプリケーション層のファイアウォール。HTTPリクエストを検査およびフィルタリングします。CloudFront、ALB、API Gatewayにアタッチします。OWASP Top 10の保護のために管理されたルールグループを使用します。
- **Amazon GuardDuty**: 行動的脅威検出。CloudTrail、VPC Flow Logs、DNSログを分析します。異常なアクティビティの発見事項を生成します。
- **CloudTrail**: すべてのAWSセキュリティロギングの基盤です。S3バケットに書き込むトレイルを有効にして、長期的な保持のためにログを保持します。
- これらのサービスは互いに補完し合います：Shieldはネットワーク層で、WAFはアプリケーション層で、GuardDutyは行動層で動作します。

## 試験のヒント

*SAA-C03 ドメイン：安全なアーキテクチャの設計（ドメイン1、タスク1.2）*

- **Shield Standard と Advanced**: Standard は無料かつ自動化されています。Advanced は費用がかかり、SRT、コスト保護、およびより高度な検出機能を追加します。Advanced の検見信号: 「大規模な DDoS 攻撃」、「攻撃中の SLA 保証」、「DDoS 関連のコストスパイクに対する金融保護」。

- **GuardDuty の検見**: 「異常な API アクティビティの検出」、「漏洩した認証情報の特定」、「異常な EC2 ネットワーク接続のフラグ付け」、「脅威インテリジェンス」→ GuardDuty。
- **WAF のアタッチ**: CloudFront (グローバル)、ALB (リージョン)、API Gateway (リージョン)、AppSync にアタッチできます。

## 練習問題

**練習問題 1 — 回想**

AWS WAF と Amazon GuardDuty の違いを説明してください。各サービスはどのような脅威から保護し、それぞれどの層で動作しますか？

*(ヒント: WAF を入力リクエストのフィルターと捉え、GuardDuty をあなたのログを監視する行動分析家と捉えてください。)*

**練習問題 2 — 試験練習**

*シナリオ*: 零售企業のウェブサイトが、1 時間あたり数百万件の要求を送信するボットネットによって標的にされています。リクエストは有効な User-Agent 文字列やセッション Cookie を使用して合法に見えますが、購入は行われず、製品価格のスクレイピングを行っています。攻撃により、正規顧客は応答時間が遅くなっています。

この脅威に対処するために最適なサービスの組み合わせはどれですか？

A) AWS Shield Advanced と CloudFront
B) AWS WAF とレート制限ルールおよび CloudFront
C) Amazon GuardDuty と AWS Shield Standard
D) NACL がボットネットの IP 範囲をブロック

*(ヒント 1: リクエストは HTTP レベル (アプリケーション層) です。HTTP レベルを操作するサービスはどれですか？)*

*(ヒント 2: ボットネットは多数の異なる IP アドレスを使用します。NACL レベルで特定の IP 範囲をブロックすることは、大規模なボットネットに対して効果的ではありません。)*

*(ヒント 3: IP アドレスごとにレート制限を行うと、スクレイピングを完全にブロックすることはできませんが、速度を遅くすることができます。)*

**答え**: B

**説明**: AWS WAF は、IP アドレスあたりのリクエストをレート制限できるため、単一のソースからの大量のスクレイピングの影響を軽減します。CloudFront は、入力を AWS エッジネットワークに分散することで、ボリュームを吸収し、オリジンを保護します。WAF ルールは、同じ API エンドポイントへの順次リクエスト (スクレイピングの特定パターン) に一致して、スクレイピングの行動を識別することもできます。

**A が適切でない理由**: Shield Advanced は DDoS 洪水 (レイヤー 3/4) を保護します。このシナリオは、アプリケーション層のスクレイピング (レイヤー 7 HTTP リクエスト) を記述しており、Shield は検査しません。

**C が適切でない理由**: GuardDuty は、AWS アカウントの行動の異常を検出します。これは、入力リクエストをブロックしません。Shield Standard は、アプリケーション層の攻撃を処理しません。

**D が適切でない理由**: 大規模なボットネットは、分散されたソースからの数千の IP アドレスを使用します。特定の範囲をブロックすることは、洗練されたボットネットに対して効果的ではありません。

*SAA-C03 ドメイン: セキュアアーキテクチャの設計 — タスク 1.2*

**練習問題 3 — アーキテクチャチャレンジ** *(オプション)*

Nimbus は、クレジットカードデータを処理する際の脅威モデルを検討しています。PCI-DSS コンプライアンスレビューには、次の要件が含まれています。

- ネットワーク層の DDoS 攻撃からの保護
- 既知のウェブ攻撃のアプリケーション層でのフィルタリング
- すべての API コールの tamper-evident な長期保存のためのロギング
- 支払いサービスへの異常なアクセスパターン検出

各要件を特定の AWS サービスまたは構成にマッピングしてください。Shield Standard で十分ですか、それとも PCI-DSS のコンテキストが Advanced を示唆しますか？WAF をどこにアタッチしますか？

*(正解は 1 つではありません。目標は、コンプライアンス要件を AWS サービスにマッピングする練習です。)*

「それは内部監視インスタンスです。ネットワーク診断を実行するために設定したものです」と言いました。

「それは Tor エクスポートノードと通信する必要がありますか？」

「いいえ。」彼は一時停止しました。「なぜそうなるのでしょうか？」

「つまり、ツールがホームに電話をかけていたのです」プリヤは言いました。

「これはこれで、こんなに警戒レベルなのか？」マヤは尋ねた。
