# 付録 D: 完全模擬試験（65問）

これは本格的な SAA-C03 模擬試験です。65問で、実際の試験のドメイン比重を反映しています——セキュアなアーキテクチャの設計（問題1～20、約30%）、弾力性のあるアーキテクチャの設計（21～37、約26%）、高パフォーマンスなアーキテクチャの設計（38～53、約24%）、コスト最適化されたアーキテクチャの設計（54～65、約20%）。

**取り組み方:**

- **130分**のタイマーをセットしましょう——実際の試験の時間です。ペース配分を練習してください。1問あたり2分です。
- 7問は **「（2つ選択。）」** と書かれています——これらには5つの選択肢があり、ちょうど2つの正解があります。実際の試験の複数回答形式と同じです。問題を正解とするには両方が正しくなければなりません。
- 65問すべてを終えるまで解答キーを見ないでください。実際の試験では途中のフィードバックはなく、不確実性への耐性を鍛えることも準備の一部です。
- 実際の試験には、識別できない15問の採点されない試験問題が含まれます。ここでの65問はすべて「採点される」ものです。合格の目安: **47問以上正解（約72%）** で、720/1000 のスケールド合格スコアの範囲に入ります。47問未満なら、試験を予約する前に、弱いドメインについて付録 B でマッピングされた章を見直してください。
- 間違えたすべての問題——そして正解したが迷ったすべての問題——について、ディストラクター（誤答）分析を読んでください。試験はもっともらしい選択肢の*違い*をテストし、学びはそこにあります。

**51. 解答: C** — cluster 配置グループは、密結合の MPI ワークロードに理想的な、最も低いレイテンシと最も高いパケット毎秒のために、インスタンスを1つの AZ に近接して詰め込みます。*他の選択肢が違う理由:* A — spread グループはインスタンスを別々のハードウェアに分離してレイテンシを増やし、AZ あたり7に制限されます。B — partition グループは低レイテンシ MPI ではなく分散データシステムのために障害ドメインを分離します。D — 別々のサブネットはインスタンスを共置するのに何の役にも立ちません。

**52. 解答: B** — Amazon Data Firehose はフルマネージドで、コンシューマーやシャード管理を必要とせず、レコードをバッファリングし、S3 に配信する前に JSON を Parquet に変換できます。*他の選択肢が違う理由:* A — Kinesis Data Streams はコンシューマーの記述/管理を必要とします。C — SQS + EC2 ポーラーは構築・運用するカスタムインフラです。D — MSK は Kafka クラスターとコネクタの管理を必要とします。

**53. 解答: B** — Glue クローラーはスキーマを推論して Data Catalog に入れ、Athena は S3 ファイルに対して直接サーバーレス SQL を実行します。*他の選択肢が違う理由:* A — Redshift はクラスターのプロビジョニングとデータのロードを必要とします。C — EMR は長時間稼働するクラスターの管理を意味します。D — RDS はデータをデータベースサーバーにロードする必要があります。

### パート 4 — 問題54～65

**54. 解答: C** — チェックポイントされ再起動可能なバッチジョブは理想的なスポットワークロードであり、インスタンスタイプ/AZ にわたって多様化された Spot Fleet は最大約90% の節約で中断の影響を最小化します。*他の選択肢が違う理由:* A — オンデマンドはここでは何の利益もなく割引を放棄します。B と D — コミットメントはスポットより小さい割引で、中断に適したジョブに支出をロックインします。

**55. 解答: C** — Compute Savings Plans は EC2（任意のファミリー/リージョン）、Fargate、Lambda にわたって自動的に適用され、近代化の道筋に適合します。*他の選択肢が違う理由:* A — EC2 Instance Savings Plans はリージョン内のインスタンスファミリーにロックされ、Fargate/Lambda を除外します。B と D — Reserved Instances は EC2 のみをカバーし、Fargate や Lambda には適用されません。

**56. 解答: B** — EC2 Standard Reserved Instances のみ Reserved Instance Marketplace に出品でき、RDS（およびその他のサービス）の RI は再販できません。*他の選択肢が違う理由:* A と C — RDS の RI はマーケットプレイス対象外です。D — EC2 Standard RI は実際にマーケットプレイスで売却可能です。

**57. 解答: B** — AWS はインスタンスを回収する2分前にスポット中断通知を配信し、ドレインとチェックポイントの時間を与えます。*他の選択肢が違う理由:* A — 警告は提供されます。C と D — 15分と24時間はスポット中断ウィンドウではありません（再調整の推奨はもっと早く来ることがありますが、保証された固定ウィンドウではありません）。

**58. 解答: B** — Glacier Flexible Retrieval は低いアーカイブストレージコストと、1～5分でデータを返す Expedited 取得（約 $0.03/GB）を提供し、5分の要件を満たします。*他の選択肢が違う理由:* A — Deep Archive の最速取得は約12時間です。C — Bulk 取得は5～12時間かかります。D — Standard-IA は即座に取得しますが、7年間めったにアクセスされないストレージにはるかに高くつきます。

**59. 解答: B** — One Zone-IA は Standard-IA より約20% 安く、単一 AZ の耐久性のトレードオフは再生成可能なサムネイルには許容できます。*他の選択肢が違う理由:* A — Standard-IA はデータが必要としない冗長性のためにより高くつきます。C — Intelligent-Tiering は監視料金を追加し、既知の低頻度アクセスのコストを最小化しません。D — Glacier Instant Retrieval には90日の最小期間があり、このパターンには異なる取得コストプロファイルです。

**60. 解答: A, C** — Intelligent-Tiering は小さなオブジェクトごとの監視/自動化料金を課し、128 KB 未満のオブジェクトは保存されるが監視も階層化もされません（Frequent Access の料金で請求されます）。*他の選択肢が違う理由:* B — Intelligent-Tiering はその自動階層間で取得料金がありません。D — それは決してクロスリージョンでレプリケートしません。E — このクラスのすべてのオブジェクトに90日の最小はありません。

**61. 解答: B** — 不完全なマルチパートアップロードのパーツはストレージとして請求されますがオブジェクトとしては見えません。AbortIncompleteMultipartUpload を持つライフサイクルルールがそれらを自動的に削除します。*他の選択肢が違う理由:* A — バージョニングはストレージを増やすのであり、パーツをクリーンアップしません。C — ストレージクラスの変更は孤立したパーツを削除しません。D — Transfer Acceleration は転送を高速化しますが、すでに放棄されたアップロードをクリーンアップしません。

**62. 解答: B** — gp3 は IOPS/スループットをサイズから切り離し、GB あたり gp2 より約20% 安いため、必要な IOPS を保ちながら容量をライトサイジングできます。移行はオンラインの ModifyVolume 操作です。*他の選択肢が違う理由:* A — io2 はより安くではなくより高価です。C — st1 は必要な IOPS を提供できません。D — ボリュームの削除はライブデータを破壊します。

**63. 解答: B** — S3 用のゲートウェイ VPC エンドポイントは無料で、同一リージョンの S3 トラフィックに対する NAT gateway のデータ処理料金を排除します。*他の選択肢が違う理由:* A — NAT インスタンスは依然として EC2 と運用のコストが発生します。C — インターフェイスエンドポイントは時間あたりと GB あたりで請求され、無料のゲートウェイエンドポイントより高くつきます。D — パブリックサブネットはパブリック IPv4 料金を追加しセキュリティを弱めます。

**64. 解答: B, E** — AWS はすべての使用中のパブリック IPv4 アドレスに対して課金するため、不要なものを削除するとコストが削減され、AWS Budgets は予測/実際の支出に対するプロアクティブなしきい値アラートを提供します。*他の選択肢が違う理由:* A — Elastic IP もアタッチされていてもパブリック IPv4 料金の対象として請求されます。C — Compute Optimizer はライトサイジングを推奨しますが、支出しきい値をブロックしたりアラートしたりできません。D — Shield Advanced はコストを追加する DDoS サービスです。

**65. 解答: A** — Aurora Serverless v2 は 0 ACU へのスケーリング（自動一時停止、2024年後半から利用可能）をサポートし、接続時に自動的に再開するため、手動ステップなしでアイドル中のコンピューティングコストを排除します。知っておくべきニュアンス: 自動一時停止は最近のエンジンバージョンを必要とします（Aurora PostgreSQL 13.15+/14.12+/15.7+/16.3+、Aurora MySQL 3.08+）。一時停止後の最初の接続は再開に約15秒かかります（24時間以上一時停止した後はより長くなります）。コンピューティングが一時停止している間もストレージは請求され続けます。そして接続を開いたままにするもの——RDS Proxy、キープアライブのヘルスチェック——は一時停止を完全に妨げます。*他の選択肢が違う理由:* B — 停止されたプロビジョンドクラスターは開発者が接続しても自動的には起動しません（そして7日後に再起動します）。C — ヘッドレスなグローバルデータベースのセカンダリは DR に対処するのであり、アイドルコストではありません。D — スケールインされたリーダーでもライターインスタンスは依然として稼働し請求されます。
