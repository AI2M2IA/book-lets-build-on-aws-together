# 付録 B: SAA-C03 ドメインマップ

AWS Solutions Architect Associate 試験（SAA-C03）は、4つのドメインで構成されています。この付録では、本書の各章を関連するドメインとタスクにマッピングし、章の順序ではなく試験領域ごとに学習できるようにしています。

---

## ドメイン概要

| ドメイン | 比重 | 説明 |
|------------------------------------------------|--------|--------------------------------------------------------|
| ドメイン 1: セキュアなアーキテクチャの設計 | 30% | IAM、ネットワークセキュリティ、データ保護 |
| ドメイン 2: 弾力性のあるアーキテクチャの設計 | 26% | 高可用性、フォールトトレランス、災害復旧 |
| ドメイン 3: 高パフォーマンスなアーキテクチャの設計 | 24% | コンピューティング、ストレージ、データベース、ネットワークのパフォーマンス |
| ドメイン 4: コスト最適化されたアーキテクチャの設計 | 20% | 料金モデル、コスト管理、リソースの最適化 |

---

## ドメイン 1: セキュアなアーキテクチャの設計（30%）

**タスク 1.1 — AWS リソースへのセキュアなアクセスを設計する**

中心的な概念: IAM のユーザー、グループ、ロール、ポリシー。最小権限の原則。クロスアカウントアクセス。サービスロール。AWS Organizations の SCP（Service Control Policy）。

| 章 | トピック |
|------------|------------------------------------------------------------------------------|
| 第3章 | IAM の基礎: ユーザー、グループ、ロール、ポリシー、ポリシー評価 |
| 第14章 | IAM の応用: サービス向けのロール、アクセス許可境界、クロスアカウントロール |
| 第3章 | ポリシー評価ロジック: 明示的な拒否 > 明示的な許可 > 暗黙的な拒否 |
| 第14章 | AWS Organizations、SCP、Control Tower、Account Factory |
| 第14章 | Cognito: User Pool（アプリのサインイン、JWT）と Identity Pool（一時的な AWS 認証情報） |

主要な試験パターン:

- 「EC2 がハードコードされた認証情報なしで S3 にアクセスする必要がある」→ S3 ポリシーをアタッチした IAM ロールを EC2 インスタンスプロファイルに付与
- 「異なるアカウント間でリソースを共有する必要がある」→ クロスアカウント信頼ポリシーを持つ IAM ロール
- 「OU 内のすべての IAM ユーザーがあるサービスにアクセスするのを防ぐ」→ AWS Organizations の SCP

---

**タスク 1.2 — セキュアなワークロードとアプリケーションを設計する**

中心的な概念: VPC 設計、セキュリティグループと NACL、ネットワーク隔離、DDoS 保護、WAF、GuardDuty。

| 章 | トピック |
|------------|--------------------------------------------------------------------------------------------|
| 第11章 | VPC 設計: パブリック/プライベートサブネット、NAT Gateway、Internet Gateway、ルートテーブル |
| 第15章 | セキュリティグループ（ステートフル、インスタンスレベル）と NACL（ステートレス、サブネットレベル） |
| 第17章 | Shield（DDoS）、WAF（アプリファイアウォール）、GuardDuty（脅威検出）、Inspector（CVE スキャン） |
| 第17章 | Macie: S3 内の機密データ検出（PII、認証情報） |
| 第25章 | Direct Connect、VPN、Transit Gateway、PrivateLink |

主要な試験パターン:

- 「特定の IP をサブネットからブロックする」→ NACL の拒否ルール
- 「HTTP のインバウンドを許可し、HTTP のレスポンスを自動的にアウトバウンドで許可する」→ セキュリティグループ（ステートフル）
- 「Web アプリケーションを SQL インジェクションから保護する」→ SQL インジェクションルールを使った WAF
- 「侵害された IAM 認証情報を検出する」→ GuardDuty

---

**タスク 1.3 — 適切なデータセキュリティ制御を決定する**

中心的な概念: 保存時および転送時の暗号化、KMS、Secrets Manager、Parameter Store、S3 サーバーサイド暗号化。

| 章 | トピック |
|------------|--------------------------------------------------------------------------|
| 第16章 | KMS: カスタマー管理キー、キーローテーション、エンベロープ暗号化 |
| 第16章 | Secrets Manager: 認証情報の自動ローテーション、実行時のシークレット取得 |
| 第16章 | ACM（AWS Certificate Manager）: ALB、CloudFront 向けの SSL/TLS 証明書 |
| 第5章 | S3 暗号化オプション: SSE-S3、SSE-KMS、SSE-C |
| 第8章 | RDS の保存時暗号化（作成時に有効化する必要がある） |

主要な試験パターン:

- 「データベース認証情報を自動的にローテーションする」→ RDS 統合を使った Secrets Manager
- 「アカウントをまたいで誰が暗号化キーを使用できるかを制御する」→ KMS キーポリシー
- 「シークレットではない構成値を保存する」→ SSM Parameter Store（Secrets Manager ではない）
- 「会社管理のキーで S3 オブジェクトを暗号化する」→ CMK を使った SSE-KMS

## ドメイン 2: 弾力性のあるアーキテクチャの設計（26%）

**タスク 2.1 — スケーラブルで疎結合なアーキテクチャを設計する**

中心的な概念: Auto Scaling、ロードバランサー、SQS/SNS による疎結合化、Lambda イベントトリガー、ECS/EKS、Step Functions。

| 章 | トピック |
|------------|--------------------------------------------------------------------|
| 第7章 | Auto Scaling Group、Application Load Balancer、スケーリングポリシー |
| 第19章 | SQS（キューによる疎結合化）、SNS（ファンアウト通知） |
| 第20章 | Lambda: サーバーレスコンピューティング、イベントトリガー、同時実行 |
| 第20章 | API Gateway: マネージドな REST/HTTP/WebSocket API、単独または + Lambda |
| 第21章 | ECS と EKS: コンテナ化されたマイクロサービス |
| 第22章 | Step Functions: ワークフローのオーケストレーション |
| 第26章 | Kinesis: リアルタイムデータストリーミング |

主要な試験パターン:

- 「注文処理と在庫更新を疎結合にする」→ サービス間の SQS キュー
- 「新しい注文が行われたときに複数のサービスに通知する」→ SQS サブスクリプション付きの SNS トピック（ファンアウト）
- 「S3 アップロードを自動的に処理する」→ S3 イベント通知 → Lambda
- 「リトライロジック付きの複数ステップワークフローを実行する」→ Step Functions

**タスク 2.2 — 高可用性および/またはフォールトトレラントなアーキテクチャを設計する**

中心的な概念: Multi-AZ、Multi-Region、Route 53 フェイルオーバー、RDS リードレプリカ、Aurora Global Database、バックアップ・アンド・リストア。

| 章 | トピック |
|------------|----------------------------------------------------------------------------------------------|
| 第2章 | AWS グローバルインフラ: リージョン、AZ、エッジロケーション |
| 第7章 | 複数 AZ にまたがる ALB、ASG が異常なインスタンスを置き換える |
| 第8章 | RDS Multi-AZ: 同期レプリケーション、自動フェイルオーバー |
| 第12章 | Route 53: フェイルオーバールーティング、レイテンシールーティング、ヘルスチェック |
| 第18章 | Multi-AZ と Multi-Region: RTO/RPO、DR 戦略（pilot light、warm standby、active-active） |
| 第18章 | AWS Backup（一元化された、クロスアカウントのバックアップ）、Elastic Disaster Recovery（マネージドな pilot light） |
| 第24章 | Aurora Global Database: クロスリージョンリードレプリカ、レプリケーション遅延 < 1秒 |

主要な試験パターン:

- 「プライマリ RDS が落ちたら自動的にフェイルオーバーする」→ RDS Multi-AZ（リードレプリカではない）
- 「低レイテンシでグローバルに読み取りを提供する」→ Aurora Global Database
- 「プライマリリージョンが利用不可になったらセカンダリリージョンにトラフィックをルーティングする」→ フェイルオーバールーティング + ヘルスチェックを使った Route 53
- 「RTO 1分、RPO 0」→ Multi-AZ デプロイ（Multi-Region ではない）
- 「RTO 15分、クロスリージョン」→ Pilot Light 戦略

## ドメイン 3: 高パフォーマンスなアーキテクチャの設計（24%）

**タスク 3.1 — 高パフォーマンスおよび/またはスケーラブルなストレージソリューションを決定する**

中心的な概念: S3 と EBS と EFS、ストレージクラスの選択、S3 Transfer Acceleration、マルチパートアップロード、アセット向けの CloudFront。

| 章 | トピック |
|------------|-------------------------------------------------------------------------|
| 第5章 | S3: オブジェクトストレージ、ストレージクラス、バージョニング、ライフサイクル |
| 第6章 | EBS: ブロックストレージタイプ（gp3、io2、st1）、EFS: 共有ファイルストレージ |
| 第6章 | Storage Gateway: オンプレミスから S3 へのハイブリッドブリッジ（File、Volume、Tape） |
| 第23章 | S3 ストレージクラスの移行、Glacier の取得オプション |
| 第25章 | DataSync（オンラインのファイル同期）、Transfer Family（マネージド SFTP→S3）、Snow ファミリー（オフラインの大量転送 — レガシー: 2025年11月に新規顧客の受付を終了。AWS は現在 DataSync と Data Transfer Terminals を案内）、MGN（サーバーのリホスト） |
| 第28章 | EBS のライトサイジング、gp2→gp3 移行、スナップショット管理 |

主要な試験パターン:

- 「複数の EC2 インスタンスからアクセスできる共有ファイルシステム」→ EFS（EBS ではない。EBS は1つのインスタンスにアタッチされる）
- 「データベースワークロード向けの高 IOPS」→ io2 EBS
- 「90日間アクセスされないファイルのコストを削減する」→ S3 ライフサイクルポリシー → Glacier
- 「離れた場所から大きなファイルをより速くアップロードする」→ S3 Transfer Acceleration
- 「限られた帯域幅で数週間かかる転送」→ Snow ファミリーは2025年に新規顧客の受付を終了したものの、SAA-C03 試験では依然として Snowball が期待される

## 試験前チェックリスト

SAA-C03 を受験する前に:

**比重の高い領域（最も出題されやすい）**

- [ ] IAM ポリシー評価ロジック（明示的な拒否 → 明示的な許可 → 暗黙的な拒否）
- [ ] VPC コンポーネント: サブネット、ルートテーブル、IGW、NAT Gateway、セキュリティグループ、NACL
- [ ] S3 ストレージクラスと、それぞれをいつ使うか
- [ ] RDS Multi-AZ とリードレプリカ（フェイルオーバーと読み取りスケーリング）
- [ ] SQS と SNS と EventBridge（プルとプッシュとイベントルーティング）

**よくある罠**

- [ ] EBS は1つのインスタンスにアタッチ、EFS は共有
- [ ] RDS リードレプリカは読み取りスケーリング向けで、自動フェイルオーバー向けではない（それは Multi-AZ）
- [ ] NACL はステートレス（インバウンドとアウトバウンドの両方のルールが必要）
- [ ] ゲートウェイエンドポイントは無料で、S3 と DynamoDB 専用
- [ ] Kinesis は保持・再生する、SQS は消費時に削除する
- [ ] 「疎結合」が常に SQS を意味するとは限らない — SNS ファンアウトと EventBridge も疎結合パターン
- [ ] Shield Standard は無料かつ自動、Advanced は有料サブスクリプション
- [ ] ElastiCache と MemoryDB: ElastiCache = キャッシュ（データ損失 OK）。MemoryDB = 耐久性のあるプライマリデータベース。
- [ ] Client VPN と Site-to-Site VPN: Client VPN = 個々のデバイス。Site-to-Site = ネットワーク間。
- [ ] Outposts と Wavelength: Outposts = オンプレミスの AWS ラック。Wavelength = 5G エッジ。
- [ ] DMS: 同種 = DMS を直接。異種 = まず SCT、その後 DMS。
- [ ] DataSync は*ファイル*を移動、DMS は*データベース*を移動、MGN は*サーバー全体*を移動。
