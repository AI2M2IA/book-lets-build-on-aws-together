# 付録 B: SAA-C03 ドメインマップ

AWS Solutions Architect Associate 試験 (SAA-C03) は、4 つのドメインに編成されています。この付録は、本書の各章を対応するドメインとタスクにマッピングしており、試験範囲ごとに学習できるようにします。章の順序ではなく、試験領域ごとに学習できます。

---

## ドメイン概要

| ドメイン                                         | 重み  | 説明                                                  |
|-------------------------------------------------|-------|-------------------------------------------------------|
| ドメイン 1: 安全なアーキテクチャを設計する          | 30%   | IAM、ネットワークセキュリティ、データ保護               |
| ドメイン 2: 回復性のあるアーキテクチャを設計する       | 26%   | 高可用性、フォールトトレランス、災害復旧                |
| ドメイン 3: 高性能アーキテクチャを設計する          | 24%   | コンピューティング、ストレージ、データベース、ネットワーク性能 |
| ドメイン 4: コスト最適化されたアーキテクチャを設計する | 20%   | 定価モデル、コスト管理、リソース最適化                |

## ドメイン 1: 安全なアーキテクチャを設計する (30%)

**タスク 1.1 — AWS リソースへの安全なアクセスを設計する**

コアコンセプト: IAM ユーザー、グループ、役割、ポリシー。最小特権の原則。クロスアカウントアクセス。サービス役割。AWS Organizations でのサービス制御ポリシー (SCP)。

| 章     | トピック                                                              |
|--------|--------------------------------------------------------------------|
| 第 3 章 | IAM の基礎: ユーザー、グループ、役割、ポリシー、ポリシー評価          |
| 第 14 章 | IAM の高度: サービス向けの役割、権限境界、クロスアカウント役割 |
| 第 3 章 | ポリシー評価ロジック: 拒否 > 許可 > 暗黙的拒否                      |
| 第 14 章 | AWS Organizations と SCPs                                         |

試験パターン:

- 「EC2 がハードコードされたクレデンシャルなしで S3 にアクセスする必要がある」→ S3 ポリシーを EC2 インスタンスプロファイルにアタッチした IAM ロール
- 「異なるアカウント間でリソースを共有する必要がある」→ クロスアカウント信頼ポリシーを持つ IAM ロール
- 「OU 内のすべての IAM ユーザーがサービスへのアクセスをブロックする必要がある」→ AWS Organizations での SCP

---

**タスク 1.2 — 安全なワークロードとアプリケーションを設計する**

コアコンセプト: VPC 設計、セキュリティグループ vs. NACL、ネットワーク分離、DDoS 保護、WAF、GuardDuty。

| 章     | トピック                                                                              |
|--------|------------------------------------------------------------------------------------|
| 第 11 章 | VPC 設計: パブリック/プライベート サブネット、NAT Gateway、インターネットゲートウェイ、ルーティングテーブル |
| 第 15 章 | セキュリティグループ (ステートフル、インスタンスレベル) vs. NACL (ステートレス、サブネットレベル) |
| 第 17 章 | Shield (DDoS 保護)、WAF (アプリケーションファイアウォール)、GuardDuty (脅威検出) |
| 第 25 章 | Direct Connect、VPN、Transit Gateway、PrivateLink                                  |

試験パターン:

- 「特定の IP アドレスをサブネットからブロックする」→ NACL デンリルール
- 「HTTP を受信し、自動的に HTTP レスポンスを送信する」→ セキュリティグループ (ステートフル)
- 「SQL インジェクションから Web アプリケーションを保護する」→ SQL インジェクションルールを備えた WAF
- 「侵害された IAM クレデンシャルを検出する」→ GuardDuty

---

**タスク 1.3 — 適切なデータセキュリティ制御を決定する**

コアコンセプト: データの暗号化 (静的および転送中)、KMS、Secrets Manager、Parameter Store、S3 サーバーサイド暗号化。

| 章     | トピック                                                                    |
|--------|--------------------------------------------------------------------------|
| 第 16 章 | KMS: 顧客管理キー、キーローテーション、エンベロープ暗号化            |
| 第 16 章 | Secrets Manager: 自動クレデンシャルローテーション、実行時クレデンシャル取得 |
| 第 5 章  | S3 暗号化オプション: SSE-S3、SSE-KMS、SSE-C                            |
| 第 8 章  | RDS 暗号化 (作成時に有効にする必要があります)                     |

試験パターン:

- 「データベースのクレデンシャルを自動的にローテーションする」→ RDS と統合された Secrets Manager
- 「アカウント間で暗号化キーの使用を制御する」→ KMS キーポリシー
- 「設定値を SSM パラメータストア (Secrets Manager ではありません) に保存する」
- 「S3 オブジェクトを会社管理キーで暗号化する」→ SSE-KMS と CMK

## ドメイン 2: 回復性のあるアーキテクチャを設計する (26%)

**タスク 2.1 — スケーラブルで疎結合なアーキテクチャを設計する**

コアコンセプト: Auto Scaling、ロードバランサー、SQS/SNS のデカップリング、Lambda イベントトリガー、ECS/EKS、Step Functions。

| Chapter    | Topic                                                            |
|------------|------------------------------------------------------------------|
| Chapter 7  | Auto Scaling グループ、アプリケーションロードバランサー、スケーリングポリシー |
| Chapter 19 | SQS (キューによる疎結合)、SNS (ファンアウト通知)        |
| Chapter 20 | Lambda: サーバーレスコンピューティング、イベントトリガー、同時実行 |
| Chapter 21 | ECS と EKS: コンテナ化されたマイクロサービス                         |
| Chapter 22 | Step Functions: ワークフローオーケストレーション                           |
| Chapter 26 | Kinesis: リアルタイムデータストリーミング                                |

Key exam patterns:

- "注文処理を在庫更新から分離する" → SQS キューを使用したサービス間の分離
- "新しい注文が作成されたときに複数のサービスに通知する" → SQS サブスクリプションを使用した SNS トピック (ファンアウト)
- "S3 アップロードを自動的に処理する" → S3 イベント通知 → Lambda
- "リトライロジックを含む複数ステップのワークフローを実行する" → Step Functions

**Task 2.2 — 高可用性と/またはフォールトトレラントなアーキテクチャを設計**

コアコンセプト: マルチAZ、マルチリージョン、Route 53 フェールオーバー、RDS リードレプリカ、Aurora グローバルデータベース、バックアップと復元。

| Chapter    | Topic                                                                                        |

| Chapter 8  | RDS Multi-AZ: 同期レプリケーション、自動フェールオーバー                                    |
| Chapter 12 | Route 53: フェールオーバールーティング、レイテンシールーティング、ヘルスチェック                                   |
| Chapter 18 | マルチAZ と マルチリージョン: RTO/RPO、DR 戦略 (パイロットライト、ウォームスタンバイ、アクティブアクティブ) |
| Chapter 24 | Aurora グローバルデータベース: 複数リージョンでのリードレプリカ、< 1 秒のレプリケーション遅延                     |

- "プライマリ RDS が失敗した場合に自動的にフェールオーバーする" → RDS Multi-AZ (Read Replica ではない)

## 試験前のチェックリスト

SAA-C03 の試験を受ける前に:

**重要度の高い分野 (最も出現する可能性が高い)**

- [ ] IAM ポリシーの評価ロジック (明示的な拒否 → 明示的な許可 → 暗黙的な拒否)
- [ ] VPC コンポーネント: サブネット、ルートテーブル、IGW、NAT Gateway、セキュリティグループ、NACL
- [ ] S3 ストレージクラスと、それぞれの使用状況
- [ ] RDS Multi-AZ vs. Read Replica (フェイルオーバー vs. 読み取りスケール)
- [ ] SQS vs. SNS vs. EventBridge (プル vs. プッシュ vs. イベントルーティング)
- [ ] EC2 の価格モデル: Spot はフォールトトレラント、Savings Plans はコミットメントワークロード
- [ ] Lambda トリガーとコンカーレレンシー
- [ ] DynamoDB vs. Aurora vs. Redshift (アクセスパターンに基づいて選択)
- [ ] CloudFront: 静的コンテンツ用の CDN、Global Accelerator は動的コンテンツ用

**陥りやすい落とし穴**

- [ ] EBS は 1 つのインスタンスにアタッチされ、EFS は共有される
- [ ] RDS Read Replicas は読み取りスケール用であり、自動フェイルオーバーではない (Multi-AZ がフェイルオーバー)
- [ ] NACLs はステートレスである (インバウンドとアウトバウンドの両方のルールが必要)
- [ ] Gateway Endpoints は無料であり、S3 と DynamoDB のみで使用可能
- [ ] Kinesis は保持し、再生し、SQS は消費時に削除
- [ ] "Decouple" が必ずしも SQS を意味するとは限らない - SNS のファンアウトと EventBridge もデカップリングパターン
- [ ] Shield Standard は無料かつ自動であり、Advanced は有料サブスクリプション

**試験の構成**

- 65 問、130 分 (2 時間 10 分)
- 選択肢形式 (1 つの正解) と複数選択形式 (N 個の正解を選択)
- 合格点: 1000 点の 720 点
- 不明な質問は埋め込まれており、どの質問であるか分かりません
- 時間管理: 1 問あたり約 2 分; 難しい質問をマークし、戻ってきます
