# الملحق ب: خريطة نطاقات SAA-C03

اختبار AWS Solutions Architect Associate (SAA-C03) مُنظَّم في أربعة نطاقات. يربط هذا الملحق كل فصل في الكتاب بالنطاق والمهمة ذات الصلة، حتى تتمكن من الدراسة حسب مجال الاختبار بدلاً من ترتيب الفصول.

---

## نظرة عامة على النطاقات

| النطاق | الوزن | الوصف |
|------------------------------------------------|--------|--------------------------------------------------------|
| النطاق 1: تصميم بنى آمنة | 30% | IAM، أمن الشبكة، حماية البيانات |
| النطاق 2: تصميم بنى مرنة | 26% | التوافر العالي، التسامح مع الأعطال، التعافي من الكوارث |
| النطاق 3: تصميم بنى عالية الأداء | 24% | أداء الحوسبة والتخزين وقواعد البيانات والشبكة |
| النطاق 4: تصميم بنى مُحسَّنة التكلفة | 20% | نماذج التسعير، إدارة التكلفة، تحسين الموارد |

---

## النطاق 1: تصميم بنى آمنة (30%)

**المهمة 1.1 — تصميم وصول آمن إلى موارد AWS**

المفاهيم الجوهرية: مستخدمو IAM، المجموعات، الأدوار، السياسات. مبدأ أقل امتياز. الوصول عبر الحسابات. أدوار الخدمة. SCP (سياسات التحكم بالخدمة) في AWS Organizations.

| الفصل | الموضوع |
|------------|------------------------------------------------------------------------------|
| الفصل 3 | أساسيات IAM: المستخدمون، المجموعات، الأدوار، السياسات، تقييم السياسات |
| الفصل 14 | IAM المتقدم: أدوار للخدمات، حدود الصلاحيات، أدوار عبر الحسابات |
| الفصل 3 | منطق تقييم السياسات: المنع الصريح > السماح الصريح > المنع الضمني |
| الفصل 14 | AWS Organizations، SCPs، Control Tower، Account Factory |
| الفصل 14 | Cognito: User Pools (تسجيل دخول التطبيق، رموز JWT) وIdentity Pools (بيانات اعتماد AWS مؤقتة) |

أنماط الاختبار الرئيسية:

- "EC2 يحتاج الوصول إلى S3 دون بيانات اعتماد مُضمَّنة في الكود" ← دور IAM بسياسة S3 مرفقة بملف تعريف نسخة EC2
- "حسابات مختلفة تحتاج مشاركة الموارد" ← دور IAM بسياسة ثقة عبر الحسابات
- "منع جميع مستخدمي IAM في وحدة تنظيمية من الوصول إلى خدمة" ← SCP في AWS Organizations

---

**المهمة 1.2 — تصميم أحمال عمل وتطبيقات آمنة**

المفاهيم الجوهرية: تصميم VPC، مجموعات الأمان مقابل شبكات NACL، عزل الشبكة، الحماية من DDoS، WAF، GuardDuty.

| الفصل | الموضوع |
|------------|--------------------------------------------------------------------------------------------|
| الفصل 11 | تصميم VPC: شبكات فرعية عامة/خاصة، NAT Gateway، Internet Gateway، جداول التوجيه |
| الفصل 15 | مجموعات الأمان (ذات حالة، مستوى النسخة) مقابل شبكات NACL (عديمة الحالة، مستوى الشبكة الفرعية) |
| الفصل 17 | Shield (DDoS)، WAF (جدار ناري للتطبيق)، GuardDuty (كشف التهديدات)، Inspector (فحص CVE) |
| الفصل 17 | Macie: اكتشاف البيانات الحساسة في S3 (PII، بيانات اعتماد) |
| الفصل 25 | Direct Connect، VPN، Transit Gateway، PrivateLink |

أنماط الاختبار الرئيسية:

- "حظر عنوان IP محدد من الشبكة الفرعية" ← قاعدة منع NACL
- "السماح بـ HTTP داخلاً، والسماح تلقائياً باستجابة HTTP خارجةً" ← مجموعة أمان (ذات حالة)
- "حماية تطبيق الويب من حقن SQL" ← WAF بقاعدة حقن SQL
- "كشف بيانات اعتماد IAM المخترقة" ← GuardDuty

---

**المهمة 1.3 — تحديد ضوابط أمن البيانات المناسبة**

المفاهيم الجوهرية: التشفير في الراحة وأثناء النقل، KMS، Secrets Manager، Parameter Store، تشفير S3 من جانب الخادم.

| الفصل | الموضوع |
|------------|--------------------------------------------------------------------------|
| الفصل 16 | KMS: المفاتيح التي يديرها العميل، تدوير المفاتيح، تشفير الغلاف |
| الفصل 16 | Secrets Manager: تدوير بيانات الاعتماد التلقائي، استرجاع السرّ في وقت التشغيل |
| الفصل 16 | ACM (AWS Certificate Manager): شهادات SSL/TLS لـ ALB، CloudFront |
| الفصل 5 | خيارات تشفير S3: SSE-S3، SSE-KMS، SSE-C |
| الفصل 8 | تشفير RDS في الراحة (يجب تفعيله عند الإنشاء) |

أنماط الاختبار الرئيسية:

- "تدوير بيانات اعتماد قاعدة البيانات تلقائياً" ← Secrets Manager مع تكامل RDS
- "التحكم فيمن يستطيع استخدام مفاتيح التشفير عبر الحسابات" ← سياسة مفتاح KMS
- "تخزين قيم تهيئة غير سرية" ← SSM Parameter Store (لا Secrets Manager)
- "تشفير كائنات S3 بمفاتيح تديرها الشركة" ← SSE-KMS مع CMK

## النطاق 2: تصميم بنى مرنة (26%)

**المهمة 2.1 — تصميم بنى قابلة للتوسع وضعيفة الارتباط**

المفاهيم الجوهرية: Auto Scaling، موازنات التحميل، فك ارتباط SQS/SNS، مُشغِّلات أحداث Lambda، ECS/EKS، Step Functions.

| الفصل | الموضوع |
|------------|--------------------------------------------------------------------|
| الفصل 7 | مجموعات التوسع التلقائي، Application Load Balancer، سياسات التوسع |
| الفصل 19 | SQS (فك الارتباط بالطوابير)، SNS (إشعارات التوزيع) |
| الفصل 20 | Lambda: حوسبة بلا خادم، مُشغِّلات الأحداث، التزامن |
| الفصل 20 | API Gateway: واجهات REST/HTTP/WebSocket مُدارة، منفردة أو + Lambda |
| الفصل 21 | ECS وEKS: خدمات مصغَّرة مُعبَّأة في حاويات |
| الفصل 22 | Step Functions: تنسيق سير العمل |
| الفصل 26 | Kinesis: تدفّق بيانات في الزمن الفعلي |

أنماط الاختبار الرئيسية:

- "فك ارتباط معالجة الطلبات عن تحديث المخزون" ← طابور SQS بين الخدمات
- "إشعار خدمات متعددة عند تقديم طلب جديد" ← موضوع SNS باشتراكات SQS (توزيع)
- "معالجة عمليات رفع S3 تلقائياً" ← إشعار حدث S3 ← Lambda
- "تشغيل سير عمل متعدد الخطوات بمنطق إعادة محاولة" ← Step Functions

---

**المهمة 2.2 — تصميم بنى عالية التوافر و/أو متسامحة مع الأعطال**

المفاهيم الجوهرية: Multi-AZ، Multi-Region، تحوّل Route 53 عند الفشل، نسخ قراءة RDS، Aurora Global Database، النسخ الاحتياطي والاستعادة.

| الفصل | الموضوع |
|------------|----------------------------------------------------------------------------------------------|
| الفصل 2 | بنية AWS التحتية العالمية: المناطق، مناطق التوافر، مواقع الحافة |
| الفصل 7 | ALB عبر مناطق توافر متعددة، ASG يستبدل النسخ غير السليمة |
| الفصل 8 | RDS Multi-AZ: تكرار متزامن، تحوّل تلقائي عند الفشل |
| الفصل 12 | Route 53: توجيه التحوّل عند الفشل، توجيه زمن الوصول، فحوصات الصحة |
| الفصل 18 | Multi-AZ مقابل Multi-Region: RTO/RPO، استراتيجيات التعافي من الكوارث (الضوء الإرشادي، الاستعداد الدافئ، نشط-نشط) |
| الفصل 18 | AWS Backup (نسخ احتياطية مركزية عبر الحسابات)، Elastic Disaster Recovery (ضوء إرشادي مُدار) |
| الفصل 24 | Aurora Global Database: نسخ قراءة عبر المناطق، تأخير تكرار < ثانية واحدة |

أنماط الاختبار الرئيسية:

- "تحوّل تلقائي عند الفشل إذا فشلت RDS الأساسية" ← RDS Multi-AZ (لا نسخة القراءة)
- "خدمة قراءات عالمياً بزمن وصول منخفض" ← Aurora Global Database
- "توجيه الزيارة إلى المنطقة الثانوية إذا كانت الأساسية غير متاحة" ← Route 53 بتوجيه التحوّل عند الفشل + فحوصات الصحة
- "RTO قدره دقيقة واحدة، RPO قدره 0" ← نشر Multi-AZ (لا Multi-Region)
- "RTO قدره 15 دقيقة، عبر المناطق" ← استراتيجية الضوء الإرشادي

## النطاق 3: تصميم بنى عالية الأداء (24%)

**المهمة 3.1 — تحديد حلول تخزين عالية الأداء و/أو قابلة للتوسع**

المفاهيم الجوهرية: S3 مقابل EBS مقابل EFS، اختيار فئة التخزين، S3 Transfer Acceleration، الرفع متعدد الأجزاء، CloudFront للأصول.

| الفصل | الموضوع |
|------------|-------------------------------------------------------------------------|
| الفصل 5 | S3: تخزين الكائنات، فئات التخزين، إصدار النسخ، دورة الحياة |
| الفصل 6 | EBS: أنواع التخزين الكتلي (gp3، io2، st1)، EFS: تخزين ملفات مشترك |
| الفصل 6 | Storage Gateway: جسر هجين من المحلي إلى S3 (File، Volume، Tape) |
| الفصل 23 | انتقالات فئات تخزين S3، خيارات استرجاع Glacier |
| الفصل 25 | DataSync (مزامنة ملفات عبر الإنترنت)، Transfer Family (SFTP←S3 مُدار)، Snow Family (نقل بالجملة دون اتصال — قديم: مُغلق أمام العملاء الجدد في نوفمبر 2025؛ تشير AWS الآن إلى DataSync وData Transfer Terminals)، MGN (إعادة استضافة الخادم) |
| الفصل 28 | ضبط حجم EBS، هجرة gp2←gp3، إدارة اللقطات |

أنماط الاختبار الرئيسية:

- "نظام ملفات مشترك يمكن الوصول إليه من نسخ EC2 متعددة" ← EFS (لا EBS؛ EBS يرتبط بنسخة واحدة)
- "IOPS عالٍ لحمل عمل قاعدة بيانات" ← io2 EBS
- "تقليل التكلفة للملفات غير المُوصَل إليها منذ 90 يوماً" ← سياسة دورة حياة S3 ← Glacier
- "رفع ملفات كبيرة من مواقع بعيدة أسرع" ← S3 Transfer Acceleration
- "أسابيع من النقل عبر عرض نطاق محدود" ← لا يزال اختبار SAA-C03 يتوقع Snowball، رغم إغلاق Snow Family أمام العملاء الجدد في 2025

**المهمة 3.2 — تحديد حلول حوسبة عالية الأداء و/أو قابلة للتوسع**

المفاهيم الجوهرية: عائلات نسخ EC2، معالجات Graviton، Auto Scaling، Lambda، Fargate، نسخ Spot.

| الفصل 7 | Auto Scaling: توسع أفقي لطبقات الويب |
| الفصل 20 | Lambda: التزامن، التزامن المُخصَّص (لزمن وصول متسق) |
| الفصل 21 | ECS Fargate: حاويات بلا خادم |

أنماط الاختبار الرئيسية:

- "استجابة Lambda متسقة دون 100 مللي ثانية" ← التزامن المُخصَّص (يُلغي البدء البارد)

**المهمة 3.3 — تحديد حلول قواعد بيانات عالية الأداء**

المفاهيم الجوهرية: RDS مقابل DynamoDB مقابل Aurora مقابل Redshift مقابل ElastiCache، أنماط الوصول، نسخ القراءة، DAX.

| الفصل | الموضوع |

أنماط الاختبار الرئيسية:

- "قراءات بالميكروثانية لمخزن جلسات" ← ElastiCache Redis أو DAX (إذا كانت الخلفية DynamoDB)
- "وصول مفتاح-قيمة عالي الإنتاجية بمخطط مرن" ← DynamoDB
- "ربطات معقّدة ومعاملات ACID" ← Aurora أو RDS
- "تحليلات على بيتابايت من البيانات المُهيكلة" ← Redshift (غير مُغطّى بالتفصيل لكن الإشارة: "مستودع بيانات" ← Redshift)

**المهمة 3.4 — تحديد بنى شبكية عالية الأداء و/أو قابلة للتوسع**

المفاهيم الجوهرية: CloudFront، Global Accelerator، Direct Connect، VPN، مجموعات الموضع، الشبكات المحسَّنة.

- "تقليل زمن الوصول للأصول الثابتة عالمياً" ← CloudFront
- "اتصال خاص متسق بـ AWS من المحلي" ← Direct Connect
- "رفع سريع من العملاء حول العالم إلى دلو S3 لديك" ← S3 Transfer Acceleration

**المهمة 3.5 — تحديد حلول ابتلاع وتحويل بيانات عالية الأداء**

المفاهيم الجوهرية: Kinesis Data Streams، Amazon Data Firehose، Glue، Athena، EMR.

| الفصل | الموضوع |

- "تحويل وفهرسة البيانات من مصادر متعددة" ← AWS Glue
- "استعلام بيانات تاريخية مخزّنة في S3 بـ SQL" ← Athena

**المهمة 4.4 — تصميم بنى شبكية مُحسَّنة التكلفة**

| الفصل | الموضوع |

| الفصل 30 | تسعير نقل البيانات: الوارد (مجاني)، عبر مناطق التوافر (0.01$/GB)، عبر المناطق، الإنترنت (0.09$/GB) |

| الفصل 30 | CloudFront كمُحسِّن لتكلفة نقل البيانات |

أنماط الاختبار الرئيسية:

- "EC2 في شبكة فرعية خاصة يستدعي S3 — إلغاء تكاليف NAT Gateway" ← S3 Gateway Endpoint (مجاني)
- "EC2 في شبكة فرعية خاصة يستدعي SQS — تقليل تكاليف NAT Gateway" ← SQS Interface Endpoint
- "تقليل تكاليف نقل البيانات لتوصيل المحتوى عالمياً" ← CloudFront (التخزين المؤقت يقلّل طلبات الأصل)

## قائمة التحقق قبل الاختبار

قبل خوض SAA-C03:

**المجالات عالية الوزن (الأرجح ظهوراً)**

- [ ] منطق تقييم سياسات IAM (المنع الصريح ← السماح الصريح ← المنع الضمني)
- [ ] مكوّنات VPC: الشبكات الفرعية، جداول التوجيه، IGW، NAT Gateway، مجموعات الأمان، شبكات NACL
- [ ] فئات تخزين S3 ومتى تستخدم كلاً منها
- [ ] RDS Multi-AZ مقابل نسخة القراءة (تحوّل عند الفشل مقابل توسيع القراءة)
- [ ] SQS مقابل SNS مقابل EventBridge (سحب مقابل دفع مقابل توجيه الأحداث)
- [ ] نماذج تسعير EC2: Spot للمتسامح مع الأعطال، خطط التوفير لأحمال العمل المُلتزَم بها
- [ ] مُشغِّلات Lambda والتزامن
- [ ] DynamoDB مقابل Aurora مقابل Redshift (نمط الوصول يحدد الاختيار)
- [ ] CloudFront: CDN للثابت، Global Accelerator للديناميكي

**الأفخاخ الشائعة**

- [ ] EBS يرتبط بنسخة واحدة؛ EFS مشترك
- [ ] نسخ القراءة في RDS لتوسيع القراءة، لا للتحوّل التلقائي عند الفشل (ذلك Multi-AZ)
- [ ] شبكات NACL عديمة الحالة (تحتاج قواعد دخول وخروج معاً)
- [ ] Gateway Endpoints مجانية ولـ S3 وDynamoDB فقط
- [ ] يحتفظ Kinesis ويعيد التشغيل؛ ويحذف SQS عند الاستهلاك
- [ ] "فك الارتباط" لا يعني دائماً SQS — توزيع SNS وEventBridge أيضاً نمطا فك ارتباط
- [ ] Shield Standard مجاني وتلقائي؛ Advanced اشتراك مدفوع
- [ ] ElastiCache مقابل MemoryDB: ElastiCache = ذاكرة تخزين مؤقت (فقدان البيانات مقبول). MemoryDB = قاعدة بيانات أساسية متينة.
- [ ] Client VPN مقابل Site-to-Site VPN: Client VPN = أجهزة فردية. Site-to-Site = شبكة إلى شبكة.
- [ ] Outposts مقابل Wavelength: Outposts = رفّ AWS محلي. Wavelength = حافة 5G.
- [ ] DMS: متجانس = DMS مباشرةً. غير متجانس = SCT أولاً، ثم DMS.
- [ ] ينقل DataSync *الملفات*؛ وينقل DMS *قواعد البيانات*؛ وينقل MGN *الخوادم بأكملها*.

**بنية الاختبار**

- 65 سؤالاً، 130 دقيقة (ساعتان و10 دقائق)
- اختيار من متعدد (إجابة صحيحة واحدة) واستجابة متعددة (اختر N صحيحة)
- درجة النجاح: 720 من 1000
- الأسئلة غير المُحتسَبة مُضمَّنة؛ لا يمكنك تمييز أيها
- أدِر الوقت: ~2 دقيقة لكل سؤال؛ علّم الصعبة وعُد إليها
