# الملحق ب: خريطة مجالات SAA-C03

اختبار AWS Solutions Architect Associate (SAA-C03) مُنظَّم في أربعة مجالات. يُعيّن هذا الملحق كل فصل في الكتاب إلى المجال والمهمة ذات الصلة، حتى تتمكن من الدراسة حسب مجال الاختبار بدلاً من ترتيب الفصول.

---

## نظرة عامة على المجالات

| المجال | الوزن | الوصف |
|--------|-------|-------|
| المجال الأول: تصميم معماريات آمنة | 30% | IAM، أمان الشبكة، حماية البيانات |
| المجال الثاني: تصميم معماريات مرنة | 26% | التوافر العالي، تحمّل الأعطال، الاسترداد من الكوارث |
| المجال الثالث: تصميم معماريات عالية الأداء | 24% | أداء الحوسبة والتخزين وقاعدة البيانات والشبكة |
| المجال الرابع: تصميم معماريات محسّنة التكلفة | 20% | نماذج التسعير، إدارة التكاليف، تحسين الموارد |

---

## المجال الأول: تصميم معماريات آمنة (30%)

**المهمة 1.1 — تصميم وصول آمن لموارد AWS**

المفاهيم الأساسية: مستخدمو IAM، المجموعات، الأدوار، السياسات. مبدأ أقل الامتيازات. الوصول بين الحسابات. أدوار الخدمة. SCP (سياسات التحكم في الخدمة) في AWS Organizations.

| الفصل | الموضوع |
|-------|---------|
| الفصل الثالث | أساسيات IAM: المستخدمون، المجموعات، الأدوار، السياسات، تقييم السياسة |
| الفصل الرابع عشر | IAM المتقدم: الأدوار للخدمات، حدود الأذونات، الأدوار بين الحسابات |
| الفصل الثالث | منطق تقييم السياسة: الرفض الصريح > الإذن الصريح > الرفض الضمني |
| الفصل الرابع عشر | AWS Organizations وSCPs |

أنماط الاختبار الرئيسية:

- "EC2 تحتاج الوصول لـ S3 بدون بيانات اعتماد مُرمَّزة" ← دور IAM مع سياسة S3 مُرفقة بملف تعريف نسخة EC2
- "حسابات مختلفة تحتاج مشاركة الموارد" ← دور IAM مع سياسة ثقة بين الحسابات
- "منع جميع مستخدمي IAM في وحدة تنظيمية من الوصول لخدمة" ← SCP في AWS Organizations

---

**المهمة 1.2 — تصميم أحمال عمل وتطبيقات آمنة**

المفاهيم الأساسية: تصميم VPC، مجموعات الأمان مقابل NACLs، عزل الشبكة، حماية DDoS، WAF، GuardDuty.

| الفصل | الموضوع |
|-------|---------|
| الفصل الحادي عشر | تصميم VPC: شبكات فرعية عامة/خاصة، بوابة NAT، بوابة الإنترنت، جداول التوجيه |
| الفصل الخامس عشر | مجموعات الأمان (ذات حالة، على مستوى النسخة) مقابل NACLs (عديمة الحالة، على مستوى الشبكة الفرعية) |
| الفصل السابع عشر | Shield (حماية DDoS)، WAF (جدار حماية التطبيق)، GuardDuty (كشف التهديدات) |
| الفصل الخامس والعشرون | Direct Connect، VPN، Transit Gateway، PrivateLink |

أنماط الاختبار الرئيسية:

- "حجب IP محدد من الشبكة الفرعية" ← قاعدة رفض NACL
- "السماح بـ HTTP داخلاً، السماح تلقائياً بالاستجابة خارجاً" ← مجموعة الأمان (ذات حالة)
- "حماية تطبيق الويب من حقن SQL" ← WAF بقاعدة حقن SQL
- "كشف بيانات اعتماد IAM المخترقة" ← GuardDuty

---

**المهمة 1.3 — تحديد ضوابط أمان البيانات المناسبة**

المفاهيم الأساسية: التشفير في حالة الراحة وأثناء النقل، KMS، Secrets Manager، Parameter Store، تشفير S3 من جانب الخادم.

| الفصل | الموضوع |
|-------|---------|
| الفصل السادس عشر | KMS: مفاتيح العميل المُدارة، تجديد المفاتيح، التشفير بالغلاف |
| الفصل السادس عشر | Secrets Manager: تجديد بيانات الاعتماد تلقائياً، استرداد السر في وقت التشغيل |
| الفصل الخامس | خيارات تشفير S3: SSE-S3، SSE-KMS، SSE-C |
| الفصل الثامن | تشفير RDS في حالة الراحة (يجب التفعيل وقت الإنشاء) |

أنماط الاختبار الرئيسية:

- "تجديد بيانات اعتماد قاعدة البيانات تلقائياً" ← Secrets Manager مع تكامل RDS
- "التحكم في من يمكنه استخدام مفاتيح التشفير عبر الحسابات" ← سياسة مفاتيح KMS
- "تخزين قيم التكوين غير الحساسة" ← SSM Parameter Store (وليس Secrets Manager)
- "تشفير كائنات S3 بمفاتيح مُدارة من الشركة" ← SSE-KMS مع CMK

## المجال الثاني: تصميم معماريات مرنة (26%)

**المهمة 2.1 — تصميم معماريات قابلة للتوسع ومفصولة بشكل فضفاض**

المفاهيم الأساسية: التوسع التلقائي، موازنات التحميل، فصل SQS/SNS، مشغّلات أحداث Lambda، ECS/EKS، Step Functions.

| الفصل | الموضوع |
|-------|---------|
| الفصل السابع | مجموعات التوسع التلقائي، Application Load Balancer، سياسات التوسع |
| الفصل التاسع عشر | SQS (الفصل مع قوائم الانتظار)، SNS (إشعارات توزيع المروحة) |
| الفصل العشرون | Lambda: الحوسبة البلا خادم، مشغّلات الأحداث، التزامن |
| الفصل الحادي والعشرون | ECS وEKS: خدمات مصغَّرة مُعبَّأة |
| الفصل الثاني والعشرون | Step Functions: تنسيق سير العمل |
| الفصل السادس والعشرون | Kinesis: تدفق البيانات في الوقت الفعلي |

أنماط الاختبار الرئيسية:

- "فصل معالجة الطلبات عن تحديث المخزون" ← قائمة انتظار SQS بين الخدمات
- "إشعار خدمات متعددة حين يُسجَّل طلب جديد" ← موضوع SNS مع اشتراكات SQS (توزيع المروحة)
- "معالجة رفوعات S3 تلقائياً" ← إشعار حدث S3 ← Lambda
- "تشغيل سير عمل متعدد الخطوات مع منطق إعادة المحاولة" ← Step Functions

---

**المهمة 2.2 — تصميم معماريات متوفرة بشكل عالٍ و/أو متحمّلة للأعطال**

المفاهيم الأساسية: Multi-AZ، Multi-Region، تحوّل Route 53، نسخ قراءة RDS، Aurora Global Database، نسخ احتياطي واستعادة.

| الفصل | الموضوع |
|-------|---------|
| الفصل الثاني | البنية التحتية العالمية لـ AWS: المناطق، مناطق التوافر، مواقع الحافة |
| الفصل السابع | ALB عبر مناطق توافر متعددة، ASG يستبدل النسخ غير الصحية |
| الفصل الثامن | RDS Multi-AZ: نسخ متزامن، تحوّل تلقائي |
| الفصل الثاني عشر | Route 53: توجيه التحوّل، توجيه الاستجابة، فحوصات الصحة |
| الفصل الثامن عشر | Multi-AZ مقابل Multi-Region: RTO/RPO، استراتيجيات DR (ضوء الطيار، استعداد دافئ، نشط-نشط) |
| الفصل الرابع والعشرون | Aurora Global Database: نسخ قراءة بين المناطق، تأخر نسخ أقل من ثانية |

أنماط الاختبار الرئيسية:

- "التحوّل التلقائي إذا تعطّل RDS الأساسي" ← RDS Multi-AZ (وليس نسخة القراءة)
- "خدمة القراءات عالمياً بزمن استجابة منخفض" ← Aurora Global Database
- "توجيه الزيارات إلى المنطقة الثانوية إذا كانت الأولى غير متاحة" ← Route 53 مع توجيه التحوّل + فحوصات الصحة
- "RTO دقيقة واحدة، RPO يساوي صفر" ← نشر Multi-AZ (وليس Multi-Region)
- "RTO 15 دقيقة، بين المناطق" ← استراتيجية ضوء الطيار

## المجال الثالث: تصميم معماريات عالية الأداء (24%)

**المهمة 3.1 — تحديد حلول تخزين عالية الأداء و/أو قابلة للتوسع**

المفاهيم الأساسية: S3 مقابل EBS مقابل EFS، اختيار فئة التخزين، S3 Transfer Acceleration، الرفع متعدد الأجزاء، CloudFront للأصول.

| الفصل | الموضوع |
|-------|---------|
| الفصل الخامس | S3: تخزين الكائنات، فئات التخزين، الإصدارات، دورة الحياة |
| الفصل السادس | EBS: أنواع تخزين الكتلة (gp3، io2، st1)، EFS: تخزين الملفات المشترك |
| الفصل الثالث والعشرون | انتقالات فئات تخزين S3، خيارات استرداد Glacier |
| الفصل الثامن والعشرون | التحجيم الصحيح لـ EBS، انتقال gp2→gp3، إدارة اللقطات |

أنماط الاختبار الرئيسية:

- "نظام ملفات مشترك يمكن الوصول إليه من نسخ EC2 متعددة" ← EFS (وليس EBS؛ EBS يرفق بنسخة واحدة)
- "IOPS مرتفعة لحمل عمل قاعدة البيانات" ← io2 EBS
- "تقليل التكلفة للملفات التي لم يُصل إليها منذ 90 يوماً" ← سياسة دورة حياة S3 ← Glacier
- "تحميل ملفات كبيرة من مواقع بعيدة بشكل أسرع" ← S3 Transfer Acceleration

---

**المهمة 3.2 — تحديد حلول حوسبة عالية الأداء و/أو قابلة للتوسع**

المفاهيم الأساسية: عائلات نسخ EC2، معالجات Graviton، التوسع التلقائي، Lambda، Fargate، نسخ Spot.

| الفصل | الموضوع |
|-------|---------|
| الفصل الرابع | أنواع نسخ EC2: مُحسَّنة الحوسبة (c)، مُحسَّنة الذاكرة (r)، للأغراض العامة (m، t) |
| الفصل السابع | التوسع التلقائي: التوسع الأفقي لطبقات الويب |
| الفصل العشرون | Lambda: التزامن، التزامن المُخصَّص (للاستجابة المتسقة دون بدء بارد) |
| الفصل الحادي والعشرون | ECS Fargate: حاويات بلا خادم |
| الفصل السابع والعشرون | نسخ Spot للأحمال الدفعية المتحمّلة للأعطال |

أنماط الاختبار الرئيسية:

- "حمل عمل تدريب ML، تقليل التكلفة، يمكن المقاطعة" ← نسخ Spot
- "استجابة Lambda متسقة دون ثانية 100 مللي ثانية" ← التزامن المُخصَّص (يُلغي البدء البارد)
- "خدمة مصغَّرة مُعبَّأة، بدون إدارة بنية تحتية" ← ECS Fargate

---

**المهمة 3.3 — تحديد حلول قواعد بيانات عالية الأداء**

المفاهيم الأساسية: RDS مقابل DynamoDB مقابل Aurora مقابل Redshift مقابل ElastiCache، أنماط الوصول، نسخ القراءة، DAX.

| الفصل | الموضوع |
|-------|---------|
| الفصل الثامن | RDS: قواعد البيانات العلائقية المُدارة، متى تستخدم RDBMS |
| الفصل التاسع | DynamoDB: NoSQL، مفاتيح التقسيم، GSI، DAX (تخزين مؤقت في الذاكرة) |
| الفصل العاشر | ElastiCache: Redis مقابل Memcached، استراتيجيات التخزين المؤقت |
| الفصل الرابع والعشرون | Aurora: الأداء، Serverless v2، نسخ القراءة، Global Database |
| الفصل التاسع والعشرون | DynamoDB عند الطلب مقابل السعة المُخصَّصة مع التوسع التلقائي |

أنماط الاختبار الرئيسية:

- "قراءات ميكرو ثانية لمخزن جلسة" ← ElastiCache Redis أو DAX (إذا كانت الواجهة الخلفية DynamoDB)
- "وصول قيمة-مفتاح عالي الإنتاجية مع مخطط مرن" ← DynamoDB
- "ضمّات معقدة ومعاملات ACID" ← Aurora أو RDS
- "التحليلات على بيتابايتات من البيانات المنظّمة" ← Redshift (لم يُغطَّ بالتفصيل لكن الإشارة: "مستودع البيانات" ← Redshift)

---

**المهمة 3.4 — تحديد معماريات شبكة عالية الأداء و/أو قابلة للتوسع**

المفاهيم الأساسية: CloudFront، Global Accelerator، Direct Connect، VPN، مجموعات الموضع، الشبكات المحسّنة.

| الفصل | الموضوع |
|-------|---------|
| الفصل الثاني عشر | Route 53: سياسات التوجيه: قائمة على زمن الاستجابة، جغرافية، موزونة |
| الفصل الثالث عشر | CloudFront: CDN، تخزين مؤقت في الحافة، Lambda@Edge |
| الفصل الخامس والعشرون | Direct Connect: اتصال خاص مخصص |
| الفصل الخامس والعشرون | AWS Global Accelerator: توجيه Anycast لأقرب حافة AWS |
| الفصل الثلاثون | نقاط نهاية VPC: اتصال خاص بخدمات AWS |

أنماط الاختبار الرئيسية:

- "تقليل الاستجابة للمستخدمين العالميين الذين يصلون لاستجابات API الديناميكية" ← Global Accelerator (وليس CloudFront، الأفضل للمحتوى القابل للتخزين المؤقت)
- "تقليل الاستجابة للأصول الثابتة عالمياً" ← CloudFront
- "اتصال خاص متسق بـ AWS من المحلي" ← Direct Connect
- "تحميل سريع من العملاء حول العالم إلى دلو S3 الخاص بك" ← S3 Transfer Acceleration

---

**المهمة 3.5 — تحديد حلول استيعاب وتحويل البيانات عالية الأداء**

المفاهيم الأساسية: Kinesis Data Streams، Kinesis Firehose، Glue، Athena، EMR.

| الفصل | الموضوع |
|-------|---------|
| الفصل السادس والعشرون | Kinesis Data Streams: معالجة أحداث مُرتَّبة فورية |
| الفصل السادس والعشرون | Kinesis Data Firehose: تسليم مُدار لـ S3 وRedshift وOpenSearch |
| الفصل السادس والعشرون | AWS Glue: ETL بلا خادم، Data Catalog، Crawlers |
| الفصل السادس والعشرون | Athena: SQL بلا خادم على S3 |

أنماط الاختبار الرئيسية:

- "معالجة بيانات نقر-دفق في الوقت الفعلي" ← Kinesis Data Streams + Lambda أو KDA
- "تسليم بيانات التدفق لـ S3 للتحليل لاحقاً" ← Kinesis Firehose
- "تحويل وفهرسة البيانات من مصادر متعددة" ← AWS Glue
- "استعلام البيانات التاريخية المخزّنة في S3 بـ SQL" ← Athena

## المجال الرابع: تصميم معماريات محسّنة التكلفة (20%)

**المهمة 4.1 — تصميم حلول تخزين محسّنة التكلفة**

| الفصل | الموضوع |
|-------|---------|
| الفصل الثالث والعشرون | سياسات دورة حياة S3، انتقالات فئات التخزين |
| الفصل الثامن والعشرون | التحجيم الصحيح لـ EBS، انتقال gp2→gp3، قواعد دورة حياة إصدارات S3 |
| الفصل الثامن والعشرون | EFS Intelligent-Tiering، علامات تخصيص التكاليف، AWS Budgets |

أنماط الاختبار الرئيسية:

- "تحديد أي فريق يُولّد أكثر تكاليف S3" ← علامات تخصيص التكاليف + Cost Explorer
- "تقليل التكاليف للكائنات نادرة الوصول تلقائياً" ← S3 Intelligent-Tiering
- "تنبيه حين تتجاوز التكاليف الشهرية 10,000 دولار" ← AWS Budgets

---

**المهمة 4.2 — تصميم حلول حوسبة محسّنة التكلفة**

| الفصل | الموضوع |
|-------|---------|
| الفصل السابع والعشرون | تسعير EC2: عند الطلب، نسخ محجوزة، خطط التوفير، Spot، مضيفون مخصصون |
| الفصل العشرون | Lambda: ادفع لكل استدعاء (بدون تكلفة في وقت الخمول) |

أنماط الاختبار الرئيسية:

- "تقليل التكلفة للأحمال المستقرة في بيئة الإنتاج" ← خطط التوفير (أكثر مرونة) أو نسخ محجوزة
- "تقليل التكلفة للوظائف الدفعية القابلة للمقاطعة" ← نسخ Spot
- "معالجة مدفوعة بالأحداث بدون تكلفة في وقت الخمول" ← Lambda

---

**المهمة 4.3 — تصميم حلول قواعد بيانات محسّنة التكلفة**

| الفصل | الموضوع |
|-------|---------|
| الفصل التاسع والعشرون | DynamoDB عند الطلب مقابل مُخصَّص + توسع تلقائي |
| الفصل التاسع والعشرون | نسخ RDS المحجوزة / العقد المحجوزة لـ ElastiCache |
| الفصل التاسع والعشرون | إدارة لقطات RDS |

أنماط الاختبار الرئيسية:

- "زيارات DynamoDB غير متوقعة" ← وضع السعة عند الطلب
- "زيارات DynamoDB متسقة مع ذروات معروفة" ← مُخصَّصة + توسع تلقائي
- "تقليل تكاليف RDS للحمل المستقر" ← نسخ محجوزة (1 أو 3 سنوات)

---

**المهمة 4.4 — تصميم معماريات شبكة محسّنة التكلفة**

| الفصل | الموضوع |
|-------|---------|
| الفصل الثلاثون | تسعير نقل البيانات: واردة (مجانية)، بين مناطق التوافر (0.01/جيجابايت)، بين المناطق، الإنترنت (0.09/جيجابايت) |
| الفصل الثلاثون | بوابة NAT (0.045/جيجابايت) مقابل نقاط نهاية VPC (بوابة: مجانية؛ واجهة: مُقيَّمة) |
| الفصل الثلاثون | CloudFront كمُحسِّن تكلفة نقل البيانات |

أنماط الاختبار الرئيسية:

- "EC2 في شبكة فرعية خاصة تستدعي S3 — تقليل تكاليف بوابة NAT" ← S3 Gateway Endpoint (مجاني)
- "EC2 في شبكة فرعية خاصة تستدعي SQS — تقليل تكاليف بوابة NAT" ← SQS Interface Endpoint
- "تقليل تكاليف نقل البيانات لتقديم المحتوى العالمي" ← CloudFront (التخزين المؤقت يُقلل الطلبات على الأصل)

## قائمة تدقيق ما قبل الاختبار

قبل الجلوس لـ SAA-C03:

**المجالات عالية الوزن (الأكثر احتمالاً للظهور)**

- [ ] منطق تقييم سياسة IAM (الرفض الصريح ← الإذن الصريح ← الرفض الضمني)
- [ ] مكوّنات VPC: الشبكات الفرعية، جداول التوجيه، بوابة الإنترنت، بوابة NAT، مجموعات الأمان، NACLs
- [ ] فئات تخزين S3 ومتى تستخدم كل منها
- [ ] RDS Multi-AZ مقابل نسخة القراءة (التحوّل مقابل توسيع القراءة)
- [ ] SQS مقابل SNS مقابل EventBridge (سحب مقابل دفع مقابل توجيه الأحداث)
- [ ] نماذج تسعير EC2: Spot للمتحمّل للأعطال، خطط التوفير للأحمال الملتزمة
- [ ] مشغّلات Lambda والتزامن
- [ ] DynamoDB مقابل Aurora مقابل Redshift (نمط الوصول يُحدد الاختيار)
- [ ] CloudFront: CDN للثابت، Global Accelerator للديناميكي

**الفخاخ الشائعة**

- [ ] EBS يرفق بنسخة واحدة؛ EFS مشترك
- [ ] نسخ قراءة RDS لتوسيع القراءة، وليس التحوّل التلقائي (هذا Multi-AZ)
- [ ] NACLs عديمة الحالة (تحتاج قواعد واردة وصادرة كليهما)
- [ ] نقاط نهاية البوابة مجانية وفقط لـ S3 وDynamoDB
- [ ] Kinesis يحتفظ ويُعيد التشغيل؛ SQS يحذف عند الاستهلاك
- [ ] "فصل" لا يعني دائماً SQS — توزيع مروحة SNS وEventBridge أيضاً أنماط فصل
- [ ] Shield Standard مجاني وتلقائي؛ Advanced اشتراك مدفوع

**هيكل الاختبار**

- 65 سؤالاً، 130 دقيقة (ساعتان و10 دقائق)
- اختيار متعدد (إجابة صحيحة واحدة) واستجابة متعددة (اختر N صحيحة)
- درجة النجاح: 720 من 1000
- أسئلة غير مُقيَّمة مضمّنة؛ لا يمكنك معرفة أيها
- إدارة الوقت: ~دقيقتان لكل سؤال؛ ضع علامة على الصعبة وارجع إليها
