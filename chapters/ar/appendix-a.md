# الملحق أ: المرجع السريع لخدمات AWS

كل خدمة مُغطّاة في هذا الكتاب، بترتيب تقديمها. استخدم هذا كمرجع دراسة وبحث سريع أثناء التحضير للاختبار.

---

## الحوسبة

**EC2 — Elastic Compute Cloud** *(الفصل الرابع)*

آلات افتراضية في السحابة. تختار نوع النسخة (CPU، ذاكرة، تخزين)، ونظام التشغيل، والمنطقة. تدفع بالساعة (عند الطلب)، أو بالالتزام (النسخ المحجوزة / خطط التوفير)، أو بفتحة الطاقة الاحتياطية (Spot). العنصر الأساسي للحوسبة.

المفاهيم الرئيسية: AMI (صورة Amazon Machine Image)، أنواع النسخ (عائلات t3، m6g، r6g، c6g)، أزواج المفاتيح، ملفات تعريف النسخ، مجموعات الموضع.

إشارة الاختبار: حين يتطلب السيناريو حوسبة مستمرة أو ذات حالة ثابتة أو طويلة التشغيل — EC2 أو ECS. حين يتطلب السيناريو حوسبة قصيرة المدة أو مدفوعة بالأحداث أو بدون تكلفة في وقت الخمول — Lambda.

---

**Auto Scaling + Application Load Balancer** *(الفصل السابع)*

تُضيف مجموعات التوسع التلقائي (ASGs) نسخ EC2 وتُزيلها بحسب الحمل. توزّع Application Load Balancers (ALBs) الزيارات عبر النسخ وتُوجّه بحسب المسار أو المضيف. معاً يُشكّلان طبقة التوسع الأفقي.

المفاهيم الرئيسية: قالب الإطلاق، سياسات التوسع (تتبع الهدف، خطوية، مجدولة)، فحوصات الصحة، مجموعات هدف ALB، قواعد الاستماع، التوجيه الموزون.

إشارة الاختبار: "التعامل مع حمل متغيّر" أو "توافر عالٍ عبر مناطق التوافر" ← ASG + ALB.

---

**Lambda** *(الفصل العشرون)*

دوال بلا خادم. تكتب الكود؛ وAWS تُشغّله استجابةً للأحداث. لا خوادم للإدارة. تدفع لكل استدعاء ولكل مللي ثانية تنفيذ. يتوسع تلقائياً إلى آلاف التنفيذات المتزامنة.

المفاهيم الرئيسية: مصادر الأحداث (API Gateway، S3، SQS، EventBridge، Kinesis)، دور التنفيذ، حدود التزامن، التزامن المحجوز والمُخصَّص، البدء البارد، الطبقات، مدة أقصى 15 دقيقة.

إشارة الاختبار: "بلا خادم"، "مدفوع بالأحداث"، "مهام قصيرة المدة"، "بدون تكلفة في وقت الخمول" ← Lambda.

---

**ECS — Elastic Container Service** *(الفصل الحادي والعشرون)*

يُشغّل حاويات Docker على AWS. نوعا الإطلاق: EC2 (تُدير المضيف) وFargate (AWS تُدير المضيف). يُدير ECS تعريفات المهام والخدمات وجدولة الكتلة والتكامل مع موازنات التحميل واكتشاف الخدمات.

المفاهيم الرئيسية: تعريف المهمة، خدمة ECS، نوع إطلاق Fargate مقابل EC2، ECR (سجل الحاويات)، دور IAM للمهمة، التوسع التلقائي للخدمة.

إشارة الاختبار: "أحمال عمل مُعبَّأة في حاويات"، "خدمات مصغَّرة"، "Docker على AWS" ← ECS (عادةً Fargate للحاويات بلا خادم).

---

**EKS — Elastic Kubernetes Service** *(الفصل الحادي والعشرون)*

Kubernetes مُدار. تُشغّل AWS طبقة التحكم؛ وأنت تُشغّل عقد العمال (EC2 أو Fargate). استخدم EKS حين يستخدم فريقك بالفعل Kubernetes أو لديه أحمال عمل تتطلب ميزات خاصة بـ Kubernetes.

إشارة الاختبار: "Kubernetes"، "الحاجة إلى نقل أحمال K8s الموجودة" ← EKS. "فقط أحتاج الحاويات بدون تعقيد K8s" ← ECS.

---

**AWS Batch** *(الفصل الحادي والعشرون)*

حوسبة دفعية مُدارة لحاويات Docker. تُعرّف مهمة (صورة Docker + أمر)، وطابور مهام، وبيئة حوسبة (EC2 أو Fargate). يُهيّئ AWS Batch الحوسبة ويوسّعها تلقائياً، ثم يُنهيها عند انتهاء المهمة. يدعم نسخ Spot لتقليل التكلفة.

المفاهيم الرئيسية: تعريف المهمة (ما يُشغَّل)، طابور المهام (حيث تنتظر المهام)، بيئة الحوسبة (EC2 أو Fargate، عند الطلب أو Spot)، مهام المصفوفة (تشغيل نسخ متوازية كثيرة من المهمة نفسها).

إشارة الاختبار: "معالجة دفعية تتجاوز مهلة Lambda البالغة 15 دقيقة"، "مهام حوسبة محدودة على حاويات"، "أحمال HPC على AWS" ← AWS Batch.

---

**AWS Outposts** *(الفصل الثاني)*

رفّ مُدار بالكامل من عتاد AWS مُثبَّت في مركز بياناتك الخاص أو منشأة استضافة مشتركة. يُشغّل خدمات AWS وواجهاتها البرمجية وأدواتها ذاتها كالسحابة العامة (EC2، EBS، RDS، EKS، S3 على Outposts) لكن فيزيائياً في الموقع المحلي.

المفاهيم الرئيسية: واجهات AWS البرمجية ذاتها في الموقع المحلي، AWS تدير التثبيت والترقيع، العميل يوفّر مساحة الرفّ والطاقة، بوابة محلية (Local Gateway — LGW) تربط Outposts بالشبكات المحلية.

إشارة الاختبار: "تشغيل AWS في مركز بياناتك الخاص"، "إقامة البيانات تتطلب بقاء الحوسبة في الموقع المحلي"، "واجهات AWS البرمجية دون اعتماد على الإنترنت" ← Outposts.

---

**AWS Wavelength** *(الفصل الثاني)*

بنية AWS التحتية المنشورة داخل شبكات مزوّدي اتصالات 5G. تقع مناطق Wavelength عند حافة شبكة 5G، مُتيحةً زمن وصول بالمللي ثانية أحادية الرقم إلى الأجهزة المحمولة.

المفاهيم الرئيسية: مناطق Wavelength امتدادات لمناطق AWS داخل شبكات الاتصالات، تبقى الزيارة على شبكة المشغّل بين الجهاز ومنطقة Wavelength.

إشارة الاختبار: "زمن وصول بالمللي ثانية أحادية الرقم إلى مستخدمي 5G المحمولين"، "AR/VR المحمول"، "ألعاب الزمن الفعلي على المحمول"، "قياسات بُعد المركبات الذاتية القيادة" ← Wavelength.

---

**AWS Application Migration Service (MGN)** *(الفصل الخامس والعشرون)*

خدمة هجرة بإعادة الاستضافة (رفع وتحويل). يُكرِّر وكيل أقراص الخوادم المصدر كتلةً بكتلة إلى منطقة تجهيز منخفضة التكلفة في AWS؛ وتُطلِق نسخاً تجريبية عند الطلب؛ وعند التحوّل النهائي، يحوّل MGN الخوادم المُكرَّرة إلى نسخ EC2 أصلية. لا يلزم تغيير التطبيق.

المفاهيم الرئيسية: تكرار مستمر على مستوى الكتلة، منطقة تجهيز، إطلاقات تجريبية قبل التحوّل، استراتيجيات الهجرة "7 Rs" (MGN = إعادة الاستضافة).

إشارة الاختبار: "نقل مئات الأجهزة الافتراضية بسرعة دون تغييرات في الكود"، "رفع وتحويل الخوادم إلى EC2" ← MGN. ينقل DataSync *الملفات*؛ وينقل DMS *قواعد البيانات*؛ وينقل MGN *الخوادم بأكملها*.

---

## التخزين

**S3 — Simple Storage Service** *(الفصل الخامس)*

تخزين كائنات. سعة غير محدودة، ومتانة 99.999999999% (أحد عشر تسعةً). يخزّن الملفات ككائنات في دلاء. تعيش الدلاء في منطقة. يمكن أن يتراوح حجم الكائنات من 0 بايت إلى 5 تيرابايت.

المفاهيم الرئيسية: سياسة الدلو، قائمة تحكم وصول الكائن (ACL)، إصدار النسخ، استضافة موقع ثابت، عناوين URL مُوقَّعة مسبقاً، الرفع متعدد الأجزاء، تسريع النقل، فئات التخزين (Standard، Intelligent-Tiering، Standard-IA، One Zone-IA، Glacier Instant Retrieval، Glacier Flexible Retrieval، Glacier Deep Archive، إضافةً إلى S3 Express One Zone لأحمال دلاء الدليل أحادية منطقة التوافر الحرجة لزمن الوصول).

إشارة الاختبار: "تخزين الملفات واسترجاعها"، "أصول ثابتة"، "نسخ احتياطية"، "بحيرة بيانات" ← S3. تعتمد فئة التخزين الصحيحة على تكرار الوصول وسرعة الاسترجاع.

---

**EBS — Elastic Block Store** *(الفصل السادس)*

تخزين كتلي مرفق بنسخة EC2 واحدة. يعمل كقرص صلب. يبقى مستقلاً عن دورة حياة النسخة (يمكنك فصله وإعادة إرفاقه). أكثر الأنواع شيوعاً: gp3 (SSD للأغراض العامة، الافتراضي)، io2 (IOPS مُخصَّص لقواعد البيانات)، st1 (HDD مُحسَّن للإنتاجية للقراءات المتسلسلة).

المفاهيم الرئيسية: اللقطات (تزايدية، مخزّنة في S3)، التشفير (KMS)، الإرفاق المتعدد (io1/io2 فقط)، تخصيص الـ IOPS والإنتاجية.

إشارة الاختبار: "تخزين دائم لـ EC2"، "تخزين قاعدة بيانات"، "يتطلب وصولاً كتلياً منخفض زمن الوصول" ← EBS.

---

**EFS — Elastic File System** *(الفصل السادس)*

نظام ملفات مشترك، يمكن الوصول إليه من نسخ EC2 متعددة في آنٍ واحد. بروتوكول NFS. يتوسع تلقائياً. أغلى من EBS لكل GB. تشمل فئات التخزين Standard وInfrequent Access وArchive. يُحرِّك Intelligent-Tiering الملفات تلقائياً.

إشارة الاختبار: "نظام ملفات مشترك"، "نسخ EC2 متعددة تحتاج الملفات نفسها"، "NFS" ← EFS.

---

**عائلة FSx** *(الفصل السادس)*

خوادم ملفات مُدارة لتقنيات مُسمّاة. FSx for Windows File Server: بروتوكول SMB، NTFS، تكامل Active Directory، Multi-AZ. FSx for Lustre: نظام ملفات متوازٍ عالي الأداء لـ HPC/ML، يعرض كائنات S3 كملفات (تحميل كسول). FSx for NetApp ONTAP: متعدد البروتوكولات (NFS + SMB + iSCSI)، لقطات، تكرار SnapMirror. FSx for OpenZFS: NFS منخفض زمن الوصول، لقطات فورية ونُسخ مستنسخة قابلة للكتابة.

إشارة الاختبار: "SMB/Active Directory" ← FSx for Windows. "تدريب HPC/ML على بيانات S3" ← FSx for Lustre. "NFS وSMB للبيانات نفسها / هجرة NetApp" ← FSx for ONTAP. "هجرة ZFS / نُسخ مستنسخة فورية" ← FSx for OpenZFS.

---

**فئات تخزين S3 وسياسات دورة الحياة** *(الفصل الثالث والعشرون)*

ينقل S3 Intelligent-Tiering الكائنات تلقائياً بين طبقات الوصول بناءً على تكرار الوصول. تنقل سياسات دورة الحياة الكائنات بين الفئات (Standard ← Standard-IA ← Glacier) بناءً على قواعد العمر. لفئات تخزين Glacier تأخير استرجاع يتراوح من دقائق (Glacier Instant) إلى 12 ساعة (Glacier Deep Archive).

إشارة الاختبار: "تقليل تكاليف التخزين للبيانات المُوصَل إليها بشكل غير متكرر" ← سياسات دورة الحياة، أو Intelligent-Tiering، أو Glacier.

---

**AWS Storage Gateway** *(الفصل السادس)*

خدمة تخزين هجينة تربط البيئات المحلية بتخزين AWS. تعرض التخزين عبر البروتوكولات التي تفهمها التطبيقات بالفعل مع حفظ البيانات في S3 أو S3 Glacier أو كلقطات EBS.

المفاهيم الرئيسية: File Gateway (NFS/SMB ← S3)، Volume Gateway (iSCSI، وضع مُخزَّن مؤقتاً أو مُخزَّن)، Tape Gateway (مكتبة أشرطة افتراضية ← Glacier).

إشارة الاختبار: "تطبيق محلي يحتاج تخزيناً سحابياً دون تغييرات في الكود" ← Storage Gateway. "استبدال النسخ الاحتياطي الشريطي" ← Tape Gateway.

---

**AWS DataSync** *(الفصل الخامس والعشرون)*

خدمة هجرة وتكرار بيانات قائمة على وكيل. يتصل وكيل خفيف بخوادم الملفات المحلية عبر NFS أو SMB ويزامن المشاركات مع S3 أو EFS أو FSx — مع جدولة، وتقييد عرض النطاق، والتحقق من السلامة مدمجة.

المفاهيم الرئيسية: وكيل DataSync (آلة افتراضية محلية أو EC2)، مصادر NFS/SMB، وجهات S3/EFS/FSx، عمليات نقل تزايدية مجدولة.

إشارة الاختبار: "نقل أو مزامنة أعداد كبيرة من الملفات باستمرار من NAS محلي إلى AWS عبر الشبكة" ← DataSync.

---

**AWS Transfer Family** *(الفصل الخامس والعشرون)*

خادم SFTP وFTPS وFTP مُدار بالكامل مدعوم بـ S3 أو EFS كوجهة تخزين. يتصل العملاء ببرمجيات SFTP الحالية لديهم؛ وتصل الملفات المرفوعة مباشرةً إلى دلو أو نظام ملفات.

المفاهيم الرئيسية: نقطة نهاية مُدارة (اختيارياً بعنوان IP ثابت)، تخزين داعم في S3 أو EFS، توافق البروتوكول الحالي للشركاء الخارجيين.

إشارة الاختبار: "يجب أن يستمر الشركاء في الرفع عبر SFTP، لكن يجب أن تصل الملفات إلى S3" ← Transfer Family.

---

**AWS Snow Family** *(الفصل الخامس والعشرون)*

أجهزة نقل بيانات فيزيائية للهجرة بالجملة دون اتصال. Snowball Edge Storage Optimized: 80 TB قابلة للاستخدام، حاوية مُقوّاة، تُشحَن إلى موقعك؛ تُحمِّل البيانات محلياً وتعيد شحنها للابتلاع في S3.

المفاهيم الرئيسية: أجرِ حساب النقل أولاً — إذا كان النقل عبر الشبكة سيستغرق نحو أسبوع أو أكثر، فالجهاز الفيزيائي يفوز. *ملاحظة عن الإرث (2026)*: ما فتئت AWS تسحب العائلة تدريجياً — اختفى Snowmobile (2024) وSnowcone (أواخر 2024)، وأُغلقت أجهزة Snow أمام العملاء الجدد في نوفمبر 2025 (تشير AWS الآن إلى DataSync وData Transfer Terminals). بنك أسئلة SAA-C03 يسبق هذا، لذا لا يزال الاختبار يتوقع Snowball كإجابة.

إشارة الاختبار: "هجرة بمقياس بيتابايت"، "عرض نطاق محدود، أسابيع من وقت النقل" ← Snow Family.

---

**AWS Backup** *(الفصلان 18 و23)*

خدمة نسخ احتياطي مركزية قائمة على السياسات عبر EBS وRDS وDynamoDB وEFS وStorage Gateway. تُعرّف خطط النسخ الاحتياطي الجداول والاحتفاظ؛ وتخزّن الأقبية نقاط الاستعادة.

المفاهيم الرئيسية: خطط النسخ الاحتياطي والأقبية، النسخ عبر المناطق وعبر الحسابات، Vault Lock للثبات (immutability).

إشارة الاختبار: "مركزة وأتمتة النسخ الاحتياطية عبر خدمات AWS متعددة"، "نسخ احتياطية عبر الحسابات للحماية من برامج الفدية/اختراق الحساب" ← AWS Backup.

## قواعد البيانات

**RDS — Relational Database Service** *(الفصل الثامن)*

قواعد بيانات علائقية مُدارة. المحرّكات المدعومة: MySQL وPostgreSQL وMariaDB وOracle وSQL Server وAurora (محرّك AWS الخاص). تتولّى AWS النسخ الاحتياطية والترقيع والتحوّل عند الفشل والتكرار. أنت تدير تصميم المخطط والاستعلامات وتحجيم النسخة.

المفاهيم الرئيسية: نشر Multi-AZ (تحوّل تلقائي عند الفشل، تكرار متزامن)، نسخ القراءة (غير متزامن، لتوسيع القراءة)، النسخ الاحتياطية الآلية (احتفاظ 1–35 يوماً)، اللقطات اليدوية (تُحفَظ حتى الحذف)، RDS Proxy (تجميع الاتصالات).

إشارة الاختبار: "قاعدة بيانات علائقية"، "معاملات ACID"، "حمل عمل SQL موجود" ← RDS أو Aurora.

---

**Aurora** *(الفصل الرابع والعشرون)*

محرّك قاعدة بيانات AWS العلائقي، متوافق مع MySQL وPostgreSQL. محرّك تخزين موزّع يكرّر البيانات عبر 3 مناطق توافر في 6 نُسخ. عادةً أسرع 5 مرات من MySQL. يوسّع Aurora Serverless v2 السعة تلقائياً (تُقاس بـ ACUs — وحدات سعة Aurora) ويمكنه، على إصدارات المحرّك المدعومة، الإيقاف المؤقت تلقائياً إلى 0 ACUs حين لا تُبقى أي اتصالات مفتوحة.

المفاهيم الرئيسية: كتلة Aurora (كاتب + حتى 15 نسخة Aurora Replicas خلف نقطة نهاية قارئ واحدة)، Aurora Global Database (نسخ قراءة عبر المناطق بتأخير تكرار < ثانية واحدة)، Aurora Serverless v2، ACUs، سلوك الإيقاف/الاستئناف المؤقت التلقائي.

إشارة الاختبار: "قاعدة بيانات علائقية عالية الأداء"، "متوافق مع MySQL/PostgreSQL"، "قراءات عالمية"، "حمل عمل متغيّر" ← Aurora.

---

**DynamoDB** *(الفصل التاسع)*

قاعدة بيانات NoSQL مُدارة بالكامل. نموذج مفتاح-قيمة ومستند. يتوسع لأي إنتاجية بأداء بالمللي ثانية أحادية الرقم. وضعا سعة: عند الطلب (الدفع لكل طلب) ومُخصَّص (الدفع لكل وحدة سعة في الساعة، مع التوسع التلقائي).

المفاهيم الرئيسية: مفتاح التقسيم (مطلوب)، مفتاح الفرز (اختياري)، الفهرس الثانوي العام (GSI)، الفهرس الثانوي المحلي (LSI)، DynamoDB Streams (التقاط البيانات التغييري)، DynamoDB Accelerator (DAX) — ذاكرة تخزين مؤقت في الذاكرة، TTL (مدة البقاء)، المعاملات.

إشارة الاختبار: "وصول قائم على المفتاح عالي الإنتاجية"، "مخطط مرن"، "NoSQL بلا خادم" ← DynamoDB.

---

**ElastiCache** *(الفصل العاشر)*

تخزين مؤقت مُدار في الذاكرة. محرّكان: Redis (دائم، نشر/اشتراك، برمجة Lua، هياكل بيانات) وMemcached (تخزين مؤقت محض، أبسط، متعدد الخيوط). استخدمه لتقليل حمل قاعدة البيانات وخدمة البيانات كثيرة القراءة بالميكروثانية.

المفاهيم الرئيسية: نمط Cache-aside، نمط Write-through، سياسات الإزاحة، TTL، وضع الكتلة (Redis)، Multi-AZ مع تحوّل تلقائي عند الفشل.

إشارة الاختبار: "تقليل حمل قاعدة البيانات"، "زمن وصول قراءة دون المللي ثانية"، "إدارة الجلسات"، "لوحة صدارة في الزمن الفعلي" ← ElastiCache Redis.

---

**Amazon MemoryDB for Redis** *(الفصل العاشر)*

قاعدة بيانات أساسية متينة في الذاكرة متوافقة مع Redis. بخلاف ElastiCache (وهو ذاكرة تخزين مؤقت يُقبَل فيها فقدان البيانات)، يخزّن MemoryDB سجل معاملات Multi-AZ ويضمن المتانة. يمكنك استخدام MemoryDB كقاعدة بياناتك الأساسية — لا مجرد ذاكرة تخزين مؤقت أمام قاعدة بيانات أخرى.

المفاهيم الرئيسية: توافق واجهة Redis البرمجية، سجل معاملات Multi-AZ (ضمان المتانة)، أداء في الذاكرة، قاعدة بيانات أساسية (لا طبقة تخزين مؤقت).

إشارة الاختبار: "متوافق مع Redis وفقدان البيانات غير مقبول"، "قاعدة بيانات متينة في الذاكرة" ← MemoryDB. "Redis كذاكرة تخزين مؤقت، فقدان البيانات مقبول" ← ElastiCache Redis.

---

**قواعد البيانات ذات الغرض المُحدَّد** *(الفصول 9 و10 و24)*

طابِق شكل البيانات بالمحرّك. DocumentDB: مستندات متوافقة مع MongoDB. Neptune: قاعدة بيانات رسوم بيانية (علاقات، اجتيازات — Gremlin/SPARQL). Keyspaces: عمود عريض متوافق مع Cassandra. Timestream: سلاسل زمنية (العرض الحالي: Timestream for InfluxDB). MemoryDB: قاعدة بيانات *أساسية* متينة متوافقة مع Redis (مقابل ElastiCache = ذاكرة تخزين مؤقت). أُوقِف QLDB ("سجل تشفيري غير قابل للتغيير") في 2025 — عامله كمشتِّت قديم.

إشارة الاختبار: "رسم بياني اجتماعي / توصيات / حلقات احتيال" ← Neptune. "MongoDB" ← DocumentDB. "Cassandra" ← Keyspaces. "قياسات بُعد IoT عبر الزمن" ← Timestream.

---

**AWS DMS — Database Migration Service** *(الفصل الثامن)*

ينقل قواعد البيانات إلى AWS بأدنى توقّف. يدعم التحميل الكامل (النسخ الأولي) إضافةً إلى CDC (التقاط البيانات التغييري) لإبقاء المصدر والهدف متزامنين أثناء تشغيل الهجرة. عند الهجرة بين نوع المحرّك نفسه (MySQL ← MySQL، PostgreSQL ← PostgreSQL)، استخدم DMS مباشرةً. عند الهجرة بين أنواع محرّكات مختلفة (Oracle ← Aurora PostgreSQL)، استخدم AWS Schema Conversion Tool (SCT) أولاً لتحويل المخطط، ثم DMS للبيانات.

المفاهيم الرئيسية: نسخة التكرار، نقطتا نهاية المصدر والهدف، التحميل الكامل + CDC، SCT (أداة تحويل المخطط) للهجرات غير المتجانسة.

إشارة الاختبار: "نقل قاعدة بيانات بأدنى توقّف" ← DMS. "Oracle إلى Aurora" أو أي هجرة غير متجانسة ← SCT + DMS. "المحرّك نفسه، النوع نفسه" ← DMS مباشرةً.

---

## الشبكات

**VPC — Virtual Private Cloud** *(الفصل الحادي عشر)*

شبكة معزولة داخل AWS. تمتد عبر جميع مناطق التوافر في منطقة. تُعرّف مساحة عناوين IP (كتلة CIDR)، وتُنشئ شبكات فرعية (عامة أو خاصة)، وتُهيّئ جداول التوجيه، وتتحكم في الوصول عبر مجموعات الأمان وشبكات NACL.

المفاهيم الرئيسية: شبكة فرعية عامة (توجيه إلى Internet Gateway)، شبكة فرعية خاصة (توجيه إلى NAT Gateway للخروج)، Internet Gateway (داخل + خارج إلى الإنترنت)، NAT Gateway (خروج فقط للنسخ الخاصة)، VPC Peering (ربط شبكتي VPC)، VPC Endpoints (الاتصال بخدمات AWS دون إنترنت).

إشارة الاختبار: "شبكة خاصة على AWS"، "عزل الموارد عن الإنترنت"، "التحكم في زيارة الشبكة" ← VPC.

---

**مجموعات الأمان وشبكات NACL** *(الفصل الخامس عشر)*

مجموعات الأمان جدران نارية ذات حالة على مستوى النسخة — قواعد سماح فقط، وزيارة العودة تلقائية. شبكات NACL (قوائم تحكم الوصول للشبكة) جدران نارية عديمة الحالة على مستوى الشبكة الفرعية — تتطلب قواعد دخول وخروج معاً، وتُقيَّم بالترتيب حسب رقم القاعدة.

إشارة الاختبار: "حظر عنوان IP محدد من الوصول إلى الشبكة الفرعية" ← NACL. "التحكم في الزيارة من/إلى نسخة" ← مجموعة أمان.

---

**Route 53** *(الفصل الثاني عشر)*

خدمة DNS ومُسجِّل نطاقات AWS. توجّه زيارة الإنترنت إلى موارد AWS ونقاط النهاية الخارجية. سياسات التوجيه: بسيط، موزون، قائم على زمن الوصول، تحوّل عند الفشل، جغرافي، جغرافي بالقرب، إجابة متعددة القيم.

المفاهيم الرئيسية: المناطق المُستضافة (عامة وخاصة)، أنواع السجلات (A، AAAA، CNAME، Alias)، فحوصات الصحة، Traffic Flow (محرّر سياسات مرئي — لاحظ أن geoproximity متاح أيضاً كسياسة توجيه مباشرة على السجلات، بانحياز قابل للتعديل، دون الحاجة إلى Traffic Flow).

إشارة الاختبار: "توجيه DNS"، "تحوّل عند الفشل بين المناطق"، "توجيه بناءً على زمن الوصول أو الموقع" ← Route 53 بسياسة التوجيه المناسبة.

---

**CloudFront** *(الفصل الثالث عشر)*

شبكة توصيل محتوى (CDN). تخزّن المحتوى مؤقتاً في مواقع الحافة (750+ نقطة تواجد حول العالم). تقلّل زمن الوصول للمستخدمين النهائيين. تقلّل تكاليف نقل الأصل عبر التخزين المؤقت. تتكامل مع S3 وEC2 وALB وAPI Gateway كأصول.

المفاهيم الرئيسية: التوزيع، الأصول (origins)، السلوكيات (توجيه قائم على المسار إلى الأصول)، TTL (التحكم في التخزين المؤقت)، إبطال التخزين المؤقت، عناوين URL والكوكيز المُوقَّعة (التحكم في الوصول)، Lambda@Edge وCloudFront Functions (تشغيل الكود عند الحافة)، Origin Shield (تقليل حمل الأصل).

إشارة الاختبار: "زمن وصول عالمي منخفض"، "تخزين محتوى ثابت مؤقتاً"، "تقليل حمل الأصل"، "الحماية من DDoS بـ Shield" ← CloudFront.

---

**Direct Connect وVPN** *(الفصل الخامس والعشرون)*

AWS Direct Connect اتصال شبكي فيزيائي مُكرَّس من مركز بياناتك المحلي إلى AWS. يتجاوز الإنترنت العام. عرض نطاق وزمن وصول أكثر اتساقاً. AWS Site-to-Site VPN نفق مشفّر عبر الإنترنت العام — أسرع في الإعداد، وأقل تكلفة، لكن بأداء متغيّر.

المفاهيم الرئيسية: الواجهة الافتراضية (VIF)، Direct Connect Gateway (الاتصال بمناطق متعددة)، Transit Gateway (طوبولوجيا شبكة محورية شعاعية)، تكرار نفق VPN.

إشارة الاختبار: "اتصال خاص مُكرَّس بـ AWS" ← Direct Connect. "اتصال مشفّر، إعداد أسرع" ← VPN. "ربط شبكات VPC متعددة" ← Transit Gateway.

---

**VPC Endpoints** *(الفصل الثلاثون)*

تربط الموارد الخاصة بخدمات AWS دون استخدام الإنترنت العام أو NAT Gateway. نقاط نهاية Gateway: مجانية، متاحة لـ S3 وDynamoDB فقط. نقاط نهاية Interface (PrivateLink): تُسعَّر بالساعة + بالـ GB، متاحة لمعظم خدمات AWS.

إشارة الاختبار: "EC2 في شبكة فرعية خاصة يستدعي S3/DynamoDB — تقليل تكاليف NAT Gateway" ← Gateway Endpoint (مجاني). "اتصال خاص بـ SQS وSSM وSecrets Manager من شبكة فرعية خاصة" ← Interface Endpoint.

---

**AWS Client VPN** *(الفصل الحادي عشر)*

نقطة نهاية OpenVPN مُدارة تتيح للأجهزة الفردية (الحواسيب المحمولة، محطات العمل) الاتصال بأمان بـ VPC عبر الإنترنت. خيارات المصادقة: Active Directory، أو موحَدة SAML 2.0 مع مزوّد هوية، أو TLS متبادل (قائم على الشهادة). يدعم النفق المنقسم (split-tunnel — زيارة الـ VPC فقط تمرّ عبر النفق) والنفق الكامل (full-tunnel — كل الزيارة تمرّ عبر AWS).

المفاهيم الرئيسية: نقطة نهاية Client VPN، الشبكة المستهدفة (ربط شبكة VPC الفرعية)، قواعد التفويض، النفق المنقسم مقابل الكامل.

إشارة الاختبار: "مهندسون عن بُعد يحتاجون وصولاً آمناً إلى VPC من المنزل"، "اتصال جهاز فردي بـ VPC" ← Client VPN. للمقارنة: Site-to-Site VPN = شبكة إلى شبكة. Client VPN = جهاز إلى شبكة.

---

**Network Load Balancer (NLB) وGateway Load Balancer (GWLB)** *(الفصل السابع)*

يعمل NLB في الطبقة 4 (TCP/UDP/TLS): لا فحص HTTP، فقط توجيه الحزم بسرعة فائقة — ملايين الطلبات في الثانية، بعنوان IP ثابت لكل منطقة توافر وحفظ IP المصدر. يعمل GWLB في الطبقة 3 وله غرض واحد: إدراج أجهزة شبكة افتراضية من طرف ثالث (جدران نارية، IDS/IPS، فحص حزم عميق) مضمّنةً في تدفّقات الزيارة.

المفاهيم الرئيسية: NLB = الطبقة 4، عناوين IP ثابتة، زمن وصول منخفض للغاية، بروتوكولات غير HTTP. GWLB = الطبقة 3، تغليف GENEVE، أساطيل أجهزة خلف نقطة دخول واحدة. ALB = الطبقة 7 (توجيه مسار/مضيف).

إشارة الاختبار: "ملايين طلبات TCP في الثانية"، "عنوان IP ثابت لموازِن التحميل"، "حفظ IP المصدر" ← NLB. "إدراج أجهزة أمان من طرف ثالث في مسار الزيارة" ← GWLB.

---

**AWS Global Accelerator** *(الفصل الخامس والعشرون)*

يوجّه زيارة المستخدمين إلى عمود AWS العالمي الخاص عند أقرب موقع حافة، بدل عبور الإنترنت العام. يوفّر عنواني IP ثابتين من نوع Anycast يتصدّران ALBs أو NLBs أو نسخ EC2 في منطقة واحدة أو أكثر. يحسّن زمن الوصول والاتساق للزيارة *الديناميكية* (غير القابلة للتخزين المؤقت).

المفاهيم الرئيسية: عناوين IP ثابتة من نوع Anycast، دخول الحافة إلى عمود AWS الفقري، تحوّل إقليمي عند الفشل قائم على فحص الصحة خلال ثوانٍ، مجموعات نقاط نهاية بأقراص زيارة (traffic dials).

إشارة الاختبار: "مستخدمون عالميون، زيارة ديناميكية/غير HTTP، عنوان IP ثابت، تحوّل إقليمي سريع عند الفشل" ← Global Accelerator. "محتوى قابل للتخزين المؤقت/ثابت" ← CloudFront بدلاً منه.

---

## الأمن والهوية

**IAM — Identity and Access Management** *(الفصلان 3 و14)*

يتحكم في من يستطيع فعل ماذا في حساب AWS لديك. المستخدمون (بيانات اعتماد طويلة الأمد)، المجموعات (مستخدمون يتشاركون الصلاحيات)، الأدوار (بيانات اعتماد مؤقتة للخدمات والوصول عبر الحسابات)، السياسات (مستندات JSON تُعرّف قواعد السماح/المنع).

المفاهيم الرئيسية: الكيان (Principal)، الإجراء (Action)، المورد (Resource)، الشرط (Condition)، المنع الصريح > السماح الصريح > المنع الضمني، SCP (سياسة التحكم بالخدمة في AWS Organizations)، حدّ الصلاحيات (Permission boundary)، AssumeRole.

إشارة الاختبار: IAM متورّط في كل سؤال أمني. النمط الأساسي: الخدمات تستخدم أدوار IAM (لا المستخدمين). الوصول عبر الحسابات يستخدم تولّي الدور. أقل امتياز — امنح فقط ما هو مطلوب.

---

**KMS — Key Management Service** *(الفصل السادس عشر)*

خدمة مفاتيح تشفير مُدارة. تُنشئ المفاتيح التشفيرية وتخزّنها وتتحكم فيها. تتيح المفاتيح التي يديرها العميل (CMKs) لك تحديد التدوير والاستخدام وسياسات الوصول. تُدار المفاتيح التي تديرها AWS تلقائياً.

المفاهيم الرئيسية: سياسة المفتاح (منفصلة عن سياسة IAM)، تشفير الغلاف (تُشفَّر البيانات بمفتاح بيانات؛ ويُشفَّر مفتاح البيانات بـ CMK)، التدوير التلقائي للمفاتيح، المفاتيح متعددة المناطق، المنح (Grants).

إشارة الاختبار: "تشفير البيانات في الراحة"، "مفاتيح تشفير يديرها العميل"، "تدوير المفاتيح" ← KMS.

---

**Secrets Manager** *(الفصل السادس عشر)*

يخزّن القيم الحساسة ويدوّرها تلقائياً: بيانات اعتماد قواعد البيانات، مفاتيح الواجهات البرمجية، رموز OAuth. يتكامل مع RDS للتدوير التلقائي لكلمات المرور. تسترجع التطبيقات الأسرار في وقت التشغيل عبر الواجهة البرمجية — لا تُضمِّن بيانات الاعتماد أبداً في الكود.

إشارة الاختبار: "تخزين وتدوير بيانات اعتماد قاعدة البيانات"، "تجنّب الأسرار المُضمَّنة في الكود" ← Secrets Manager. "تخزين قيم تهيئة، لا أسرار" ← Parameter Store (SSM).

---

**AWS Shield** *(الفصل السابع عشر)*

حماية من DDoS. Shield Standard تلقائي ومجاني — يحمي من الهجمات الحجمية وبروتوكولية الشائعة. يضيف Shield Advanced حماية مالية، وفريق استجابة DDoS على مدار الساعة طوال الأسبوع، ورؤية تفصيلية للهجمات.

إشارة الاختبار: "الحماية من DDoS" ← Shield Standard (تلقائي) أو Shield Advanced (للمؤسسات، مع SLA).

---

**WAF — Web Application Firewall** *(الفصل السابع عشر)*

يصفّي زيارة HTTP/HTTPS بناءً على قواعد: حظر IP، حدود معدل، أنماط حقن SQL، أنماط XSS، قيود جغرافية، قواعد مخصصة. يرتبط بـ CloudFront أو ALB أو API Gateway أو AppSync.

إشارة الاختبار: "حظر عناوين IP محددة"، "منع حقن SQL عند الحافة"، "تحديد معدل استدعاءات الواجهة البرمجية" ← WAF.

---

**GuardDuty** *(الفصل السابع عشر)*

خدمة كشف التهديدات. تحلّل سجلات CloudTrail وVPC Flow Logs وسجلات DNS باستخدام تعلّم الآلة ومعلومات التهديدات. تكتشف نشاط الواجهة البرمجية غير المعتاد، والاتصال بعناوين IP الخبيثة المعروفة، وبيانات الاعتماد المخترقة.

إشارة الاختبار: "كشف النشاط غير المعتاد"، "تحديد بيانات اعتماد IAM المخترقة"، "مراقبة تهديدات مستمرة" ← GuardDuty.

---

**Amazon Inspector** *(الفصل السابع عشر)*

خدمة تقييم ثغرات آلية. تفحص باستمرار نسخ EC2، وصور حاويات Amazon ECR، ودوال Lambda بحثاً عن ثغرات البرمجيات (CVEs) والتعرّض الشبكي غير المقصود. تُرسَل النتائج إلى AWS Security Hub للإدارة المركزية.

المفاهيم الرئيسية: فحص CVE، تقييم مستمر (لا لمرة واحدة)، تغطية EC2 + ECR + Lambda، تكامل Security Hub.

إشارة الاختبار: "فحص EC2 تلقائياً بحثاً عن الثغرات المعروفة"، "فحص CVE لصور الحاويات"، "تقييم ثغرات مستمر" ← Inspector.

---

**Amazon Cognito** *(الفصل الرابع عشر)*

مصادقة مُدارة للمستخدمين النهائيين لتطبيقك — دليل مستخدمين لا يلزمك بناؤه. تتولّى User Pools التسجيل وتسجيل الدخول والمصادقة متعددة العوامل وإعادة تعيين كلمة المرور ومزوّدي الهوية الاجتماعيين (Google، Facebook، أي مزوّد OIDC)، مُصدِرةً رموز JWT يتحقق منها تطبيقك. تبادل Identity Pools تلك الرموز مقابل بيانات اعتماد AWS مؤقتة.

المفاهيم الرئيسية: User Pool (مصادقة، رموز JWT) مقابل Identity Pool (بيانات اعتماد AWS مؤقتة)، واجهة مُستضافة، موحَدة اجتماعية/OIDC/SAML، مُفوِّض Cognito لـ API Gateway.

إشارة الاختبار: "التطبيق يحتاج تسجيل/تسجيل دخول المستخدمين"، "تسجيل دخول اجتماعي"، "منح مستخدمي تطبيق المحمول وصولاً مؤقتاً إلى موارد AWS" ← Cognito. للمقارنة: IAM لمهندسيك وخدماتك؛ Cognito لعملائك.

---

**AWS Certificate Manager (ACM)** *(الفصل السادس عشر)*

يُهيّئ شهادات TLS/SSL عامة مجانية للخدمات التي تديرها AWS (ALB، CloudFront، API Gateway) ويتولّى دورة الحياة بأكملها — لا تقويم تجديد، ولا تعامل مع المفاتيح الخاصة. يجدّد تلقائياً عبر التحقق من DNS.

المفاهيم الرئيسية: التحقق عبر DNS مقابل البريد الإلكتروني، التجديد التلقائي، يجب أن تكون شهادات CloudFront في us-east-1، الشهادات العامة المجانية لا يمكن تصديرها (يوجد خيار قابل للتصدير مدفوع منذ 2025).

إشارة الاختبار: "HTTPS على موازِن تحميل أو CDN"، "تجديد شهادة تلقائي" ← ACM.

---

**Amazon Macie** *(الفصل السابع عشر)*

اكتشاف البيانات الحساسة لـ S3. يستخدم تعلّم الآلة ومطابقة الأنماط للعثور على معلومات التعريف الشخصية (أسماء، أرقام بطاقات، بيانات اعتماد) في الدلاء ويُعلِّم على مخاطر الوصول مثل التعرّض العام. يكمّل GuardDuty: يراقب GuardDuty السلوك؛ ويُدقّق Macie ما هو مُخزَّن.

المفاهيم الرئيسية: مُعرِّفات بيانات مُدارة (أنماط PII)، نطاق S3 فقط، النتائج إلى Security Hub/EventBridge.

إشارة الاختبار: "اكتشاف PII في S3"، "تحديد تعرّض البيانات الحساسة" ← Macie.

---

**AWS Control Tower** *(الفصل الرابع عشر)*

يُؤتمت إعداد وحوكمة بيئة متعددة الحسابات. يُنشئ منطقة هبوط (landing zone) — حسابات الإدارة وأرشيف السجلات والتدقيق مُهيّأة مسبقاً بـ Organizations وCloudTrail وConfig والحواجز — في دقائق بدلاً من أيام من التوصيل اليدوي.

المفاهيم الرئيسية: منطقة الهبوط، الحواجز (وقائية = SCPs، كاشفة = قواعد Config)، Account Factory للحسابات الجديدة المُوحَّدة.

إشارة الاختبار: "إعداد وحوكمة بيئة متعددة الحسابات جديدة بأفضل الممارسات تلقائياً" ← Control Tower. للمقارنة: Organizations هي اللبنة الخام؛ Control Tower هو التجميع المُؤتمت.

---

## المراسلة ومعالجة الأحداث

**SQS — Simple Queue Service** *(الفصل التاسع عشر)*

طابور رسائل مُدار. يرسل المُنتِجون الرسائل؛ ويقرؤها المستهلكون ويحذفونها. يفكّ ارتباط الخدمات: لا يحتاج المُرسِل لمعرفة ما إذا كان المُستقبِل متاحاً. الطوابير القياسية: تسليم مرة واحدة على الأقل، ترتيب بأفضل جهد. طوابير FIFO: معالجة مرة واحدة بالضبط، ترتيب صارم.

المفاهيم الرئيسية: مهلة الرؤية (الرسالة مخفية عن المستهلكين الآخرين أثناء المعالجة)، طابور الرسائل الميتة (DLQ) للرسائل التي تفشل مراراً، الاحتفاظ بالرسائل (4 أيام افتراضياً، حتى 14)، الاستطلاع الطويل (تقليل الاستجابات الفارغة)، أقصى حمولة 256KB افتراضياً (قابلة للرفع إلى 1 MiB منذ 2025؛ للحمولات الأكبر، تخزّن Extended Client Library الجسم في S3).

إشارة الاختبار: "فك ارتباط الخدمات"، "حجز الطلبات أثناء طفرات الحمل"، "معالجة غير متزامنة" ← SQS. "الترتيب مهم ومرة واحدة بالضبط مطلوبة" ← SQS FIFO.

---

**SNS — Simple Notification Service** *(الفصل التاسع عشر)*

خدمة نشر/اشتراك مُدارة. ينشر الناشرون رسالة إلى موضوع؛ ويتلقى كل المشتركين نسخة. نمط التوزيع (fan-out): رسالة واحدة ← مستهلكون كثيرون. البروتوكولات: SQS، Lambda، HTTP/HTTPS، بريد إلكتروني، SMS، إشعار محمول.

المفاهيم الرئيسية: الموضوع، الاشتراك، نمط التوزيع (SNS ← طوابير SQS متعددة)، تصفية الرسائل (يتلقى المشتركون الرسائل المطابقة فقط).

إشارة الاختبار: "إرسال إشعارات إلى نقاط نهاية متعددة في آنٍ واحد"، "توزيع حدث واحد إلى مستهلكين متعددين" ← SNS. النمط الشائع: SNS + SQS للتوزيع الدائم.

---

**EventBridge** *(الفصل الثاني والعشرون)*

ناقل أحداث لبناء بنى مدفوعة بالأحداث. يوجّه الأحداث من خدمات AWS وشركاء SaaS والمصادر المخصصة إلى Lambda وSQS وSNS وStep Functions وأهداف أخرى. يدعم القواعد المجدولة (cron) ومطابقة الأنماط.

إشارة الاختبار: "توجيه الأحداث من خدمات AWS إلى الأهداف"، "جدولة دوال Lambda"، "تنسيق مدفوع بالأحداث" ← EventBridge.

---

**Step Functions** *(الفصل الثاني والعشرون)*

تنسيق سير عمل بلا خادم. ينسّق دوال Lambda، ومهام ECS، وDynamoDB، وSNS، وSQS، وخدمات أخرى في آلات حالة مرئية. يتولّى إعادة المحاولات، ومعالجة الأخطاء، والفروع المتوازية، وحالات الانتظار.

المفاهيم الرئيسية: آلة الحالة، أنواع الحالات (Task، Wait، Choice، Parallel، Map، Pass، Succeed، Fail)، أسير عمل Standard (مرة واحدة بالضبط، طويلة التشغيل) مقابل أسير عمل Express: غير متزامن (مرة واحدة على الأقل، عالي الحجم — صمّم المهام لتكون idempotent) ومتزامن (مرة واحدة على الأكثر، يُرجِع النتيجة مباشرةً كاستدعاء واجهة برمجية).

إشارة الاختبار: "تنسيق دوال Lambda متعددة"، "أسير عمل طويلة التشغيل بمنطق إعادة محاولة"، "خطوات موافقة بشرية" ← Step Functions.

---

**Kinesis** *(الفصل السادس والعشرون)*

تدفّق بيانات في الزمن الفعلي. Kinesis Data Streams: تدفّق سجلات دائم ومرتّب (كسجل التزام موزّع). يعالج المستهلكون السجلات؛ تُحتفَظ البيانات 24 ساعة (افتراضياً) إلى 365 يوماً (مع الاحتفاظ الموسّع بالبيانات). Amazon Data Firehose (المعروف سابقاً بـ Kinesis Data Firehose): تسليم مُدار بالكامل إلى S3 وRedshift وOpenSearch وSplunk — لا حاجة لإدارة المستهلكين.

المفاهيم الرئيسية: التقسيم (وحدة الإنتاجية: 1MB/s كتابة، 2MB/s قراءة)، مفتاح التقسيم (يحدد تعيين التقسيم)، رقم التسلسل، نقاط التفتيش (KCL أو Lambda)، Firehose مقابل Streams.

إشارة الاختبار: "تدفّق في الزمن الفعلي"، "سجلات مرتّبة"، "إعادة تشغيل الأحداث" ← Kinesis Data Streams. "تسليم بيانات متدفّقة إلى S3/Redshift دون إدارة مستهلكين" ← Amazon Data Firehose (قد تقول الأسئلة الأقدم "Kinesis Data Firehose"). "SQL على البيانات المتدفّقة" ← Amazon Managed Service for Apache Flink (المعروف سابقاً بـ Kinesis Data Analytics). للمقارنة مع SQS: يحتفظ Kinesis ويعيد التشغيل؛ ويحذف SQS عند الاستهلاك.

---

**Amazon MQ** *(الفصل التاسع عشر)*

خدمة وسيط رسائل مُدارة تدعم Apache ActiveMQ وRabbitMQ. تدعم بروتوكولات مراسلة معيارية في الصناعة: AMQP، STOMP، MQTT، OpenWire، وWebSocket. حالة الاستخدام الأساسية هي هجرة رفع وتحويل لأحمال وسطاء الرسائل المحلية — التطبيقات التي تستخدم ActiveMQ أو RabbitMQ بالفعل يمكنها الاتصال دون تغييرات في الكود.

المفاهيم الرئيسية: اختيار محرّك ActiveMQ مقابل RabbitMQ، دعم البروتوكولات (AMQP/STOMP/MQTT)، تهيئة وسيط أحادي النسخة أو نشط/احتياطي للتوافر العالي.

إشارة الاختبار: "نقل ActiveMQ أو RabbitMQ المحلي إلى AWS دون تغيير كود التطبيق" ← Amazon MQ. "مراسلة أصلية على AWS من الصفر" ← SQS أو SNS (أبسط، أكثر قابلية للتوسع).

---

## التحليلات

**Athena** *(الفصل السادس والعشرون)*

استعلامات SQL بلا خادم على البيانات المخزّنة في S3. لا بنية تحتية للإدارة. الدفع لكل استعلام (لكل TB مفحوص). أفضل مع الصيغ العمودية (Parquet، ORC) والبيانات المُقسَّمة.

إشارة الاختبار: "استعلام بيانات S3 بـ SQL"، "تحليلات مخصصة على بحيرة بيانات"، "لا إدارة بنية تحتية" ← Athena.

---

**Glue** *(الفصل السادس والعشرون)*

خدمة ETL (استخراج، تحويل، تحميل) بلا خادم. تكتشف Glue Crawlers البيانات وتحدّث Glue Data Catalog. تُشغّل Glue Jobs تحويلات Spark أو Python. يتكامل Data Catalog مع Athena وRedshift Spectrum وEMR.

إشارة الاختبار: "تحويل وتحميل البيانات للتحليلات"، "اكتشاف مخطط بيانات S3"، "خط أنابيب ETL" ← Glue.

---

**Amazon QuickSight** *(الفصل السادس والعشرون)*

خدمة ذكاء أعمال وتصوّر بيانات مُدارة. تستخدم SPICE (محرّك حساب فائق السرعة، متوازٍ، في الذاكرة)، محرّك في الذاكرة يخزّن البيانات المستوردة مؤقتاً لعرض لوحات معلومات سريع. تتصل بـ Athena وS3 وRedshift وRDS ومصادر بيانات AWS أخرى. لا خادم BI للإدارة.

المفاهيم الرئيسية: SPICE (محرّك في الذاكرة)، مجموعات البيانات، التحليلات، لوحات المعلومات، ML Insights (كشف الشذوذ، التنبؤ)، أمان على مستوى الصف والعمود.

إشارة الاختبار: "لوحة معلومات BI على AWS دون إدارة خادم"، "تصوّر البيانات من Athena أو Redshift" ← QuickSight.

---

**AWS Lake Formation** *(الفصل السادس والعشرون)*

طبقة تحكم وصول مركزية لبحيرة البيانات فوق S3 وGlue Data Catalog. توفّر صلاحيات دقيقة على مستوى الجدول والعمود والصف — أدق من سياسات دلو S3 وحدها. تبسّط إعداد بحيرة بيانات آمنة: تتولّى Lake Formation نموذج الصلاحيات؛ ويتولّى Glue الفهرس؛ ويحمل S3 البيانات.

المفاهيم الرئيسية: صلاحيات بحيرة البيانات (مستوى جدول/عمود/صف)، تكامل Glue Data Catalog، وسوم LF-tags للوصول القائم على السمات، منح/سحب مركزي لاستعلامات Athena وRedshift Spectrum.

إشارة الاختبار: "تحكم وصول دقيق على بحيرة بيانات"، "أمان على مستوى العمود أو الصف على بيانات S3" ← Lake Formation.

---

## التوافر العالي والتعافي من الكوارث

**Multi-AZ وMulti-Region** *(الفصل الثامن عشر)*

Multi-AZ: تكرار متزامن داخل منطقة للتحوّل التلقائي عند الفشل (RDS Multi-AZ، موازِن تحميل عبر مناطق التوافر). RPO ~0، RTO ~60 ثانية لـ RDS. Multi-Region: تكرار غير متزامن للتكرار الجغرافي وزمن وصول أقل للمستخدمين العالميين.

المفاهيم الرئيسية: RTO (هدف زمن التعافي — كم يستغرق التعافي)، RPO (هدف نقطة التعافي — كم من البيانات يمكن أن تُفقَد). استراتيجيات Pilot Light، Warm Standby، Active-Active للتعافي من الكوارث.

إشارة الاختبار: ميّز بين أعطال مستوى منطقة التوافر (يتولّاها Multi-AZ) مقابل الأعطال الإقليمية (يتولّاها Multi-Region). تزداد التكلفة والتعقيد بشكل كبير مع Multi-Region.

---

**AWS Elastic Disaster Recovery (DRS)** *(الفصل الثامن عشر)*

تعافٍ من الكوارث مُدار للخوادم (محلية أو EC2). يكرّر الخوادم المصدر باستمرار كتلةً بكتلة إلى منطقة تجهيز منخفضة التكلفة ويُطلِق نسخ تعافٍ كاملة في دقائق عند الحاجة — ضوء إرشادي مُدار: أزمنة تعافٍ قريبة من الاستعداد الدافئ بأسعار قريبة من النسخ الاحتياطي والاستعادة.

المفاهيم الرئيسية: تكرار مستمر على مستوى الكتلة، منطقة تجهيز منخفضة التكلفة، إطلاق تعافٍ عند الطلب، تعافٍ لنقطة زمنية.

إشارة الاختبار: "تقليل التوقّف وفقدان البيانات لأحمال العمل القائمة على الخوادم بخدمة تعافٍ مُدارة"، "ضوء إرشادي دون بنائه بنفسك" ← DRS.

---

## تحسين التكلفة

**نماذج تسعير EC2** *(الفصل السابع والعشرون)*

عند الطلب: السعر الكامل، بلا التزام. النسخ المحجوزة (سنة أو 3 سنوات): خصم 30–72% لنوع نسخة محدد. خطط التوفير (الحوسبة أو نسخة EC2): إنفاق ساعي مُلتزَم به للمرونة. Spot: خصم 60–90% لأحمال العمل القابلة للمقاطعة.

إشارة الاختبار: "تقليل التكلفة لحمل عمل متوقَّع" ← خطط التوفير أو النسخ المحجوزة. "معالجة دفعية متسامحة مع الأعطال" ← Spot. "غير متوقَّع أو قصير الأجل" ← عند الطلب.

---

**تسعير نقل البيانات** *(الفصل الثلاثون)*

الوارد إلى AWS: مجاني. داخل منطقة التوافر نفسها: مجاني. عبر مناطق التوافر: 0.01$/GB لكل اتجاه. عبر المناطق: 0.02–0.08$/GB. الإنترنت (الصادر): ~0.09$/GB. معالجة NAT Gateway: 0.045$/GB. نقل بيانات CloudFront أرخص من نقل EC2 إلى الإنترنت مباشرةً، والتخزين المؤقت يقلّل الحجم الإجمالي.

إشارة الاختبار: "تقليل تكاليف نقل البيانات لـ S3/DynamoDB من شبكة فرعية خاصة" ← Gateway Endpoints (مجانية). "تقليل تكاليف NAT Gateway للخدمات الأخرى" ← Interface Endpoints.

---

## القابلية للملاحظة

**CloudWatch** *(مُشار إليه في كل الكتاب)*

المراقبة والقابلية للملاحظة. CloudWatch Metrics: بيانات سلاسل زمنية رقمية من خدمات AWS والتطبيقات المخصصة. CloudWatch Logs: جمع وبحث وتحليل بيانات السجلات. CloudWatch Alarms: تشغيل الإشعارات أو التوسع التلقائي بناءً على عتبات المقاييس. CloudWatch Dashboards: تصوّر المقاييس.

المفاهيم الرئيسية: أبعاد المقياس، فترات الاحتفاظ، مجموعات السجلات وتدفّقات السجلات، مرشّحات المقاييس، CloudWatch Agent (لمقاييس وسجلات مستوى نظام التشغيل من EC2)، Container Insights.

---

**CloudTrail** *(مُشار إليه في كل الكتاب)*

يسجّل كل استدعاء واجهة برمجية في حساب AWS لديك: من أجراه، ومن أين، ومتى، وما كانت الاستجابة. يخزّن مسار متعدد المناطق السجلات في S3 إلى أجل غير مسمى. يُستخدَم للتدقيق الأمني والامتثال والتحقيق في الحوادث.

إشارة الاختبار: "من حذف هذا المورد؟"، "تدقيق كل نشاط الواجهة البرمجية" ← CloudTrail.

---

**X-Ray** *(الفصل العشرون)*

تتبّع موزّع: يتتبّع الطلبات الفردية عبر الخدمات (آثار ← مقاطع ← مقاطع فرعية)، ويبني خريطة خدمة بمعدلات زمن وصول وأخطاء لكل قفزة. تُبقي العيّنات (sampling) العبء منخفضاً؛ والتعليقات التوضيحية تجعل الآثار قابلة للبحث. التتبّع النشط يُفعَّل على Lambda ومراحل API Gateway.

إشارة الاختبار: "تتبّع الطلبات عبر الخدمات المصغَّرة"، "إيجاد عنق الزجاجة بين الخدمات" ← X-Ray (لا CloudWatch، لا CloudTrail).

---

**AWS Config** *(مُشار إليه في الفصل الحادي والثلاثين)*

يتتبّع تغييرات تهيئة الموارد عبر الزمن. يُقيِّم الموارد مقابل قواعد الامتثال. يسجّل تاريخ كل تغيير تهيئة لكل مورد. يتكامل مع Systems Manager للمعالجة.

إشارة الاختبار: "هل هذا المورد مُمتثِل لسياستنا الأمنية؟"، "كيف بدت تهيئة هذا المورد الأسبوع الماضي؟" ← AWS Config.

---

## Well-Architected

**الركائز الست** *(الفصل الحادي والثلاثون)*

| الركيزة | السؤال الجوهري | الخدمات الرئيسية |
|------------------------|-----------------------------------------|---------------------------------------------------|
| التميّز التشغيلي | هل نعمل بشكل جيد؟ | CloudWatch، CloudTrail، SSM، Config |
| الأمن | هل نحن محميون؟ | IAM، KMS، GuardDuty، WAF، Shield، Secrets Manager |
| الموثوقية | هل نتعافى من الفشل؟ | Multi-AZ، تحوّل Route 53 عند الفشل، نسخ احتياطي/استعادة، SQS |
| كفاءة الأداء | هل نستخدم الموارد الصحيحة؟ | ضبط الحجم، Auto Scaling، CloudFront، Kinesis |
| تحسين التكلفة | هل ننفق بحكمة؟ | خطط التوفير، Spot، دورة حياة S3، VPC Endpoints |
| الاستدامة | هل نقلّل الأثر البيئي؟ | ضبط الحجم، Graviton، طبقات تخزين فعّالة |

AWS Well-Architected Tool: يُقيِّم بنيتك مقابل الركائز الست. استخدمه قبل الاختبار لفهم المنطق وراء أسئلة كل ركيزة.
