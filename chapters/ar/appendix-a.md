# الملحق أ: المرجع السريع لخدمات AWS

كل خدمة مُغطّاة في هذا الكتاب، بترتيب تقديمها. استخدم هذا كمرجع دراسة وبحث سريع أثناء التحضير للاختبار.

---

## الحوسبة

**EC2 — Elastic Compute Cloud** *(الفصل الرابع)*

آلات افتراضية في السحابة. تختار نوع النسخة (CPU، ذاكرة، تخزين)، نظام التشغيل، والمنطقة. تدفع بالساعة (عند الطلب)، بالالتزام (النسخ المحجوزة / خطط التوفير)، أو بفتحة الطاقة الاحتياطية (Spot). العنصر الأساسي للحوسبة.

المفاهيم الرئيسية: AMI (صورة Amazon Machine Image)، أنواع النسخ (عائلات t3، m6g، r6g، c6g)، أزواج المفاتيح، ملفات تعريف النسخ، مجموعات الموضع.

إشارة الاختبار: حين يتطلب السيناريو حوسبة مستمرة أو حالة ثابتة أو طويلة التشغيل — EC2 أو ECS. حين يتطلب السيناريو حوسبة قصيرة المدة أو مدفوعة بالأحداث أو بدون تكلفة في وقت الخمول — Lambda.

---

**Auto Scaling + Application Load Balancer** *(الفصل السابع)*

تُضيف مجموعات التوسع التلقائي (ASGs) نسخ EC2 وتُزيلها بحسب الحمل. توزّع Application Load Balancers (ALBs) الزيارات عبر النسخ وتُوجّه بحسب المسار أو المضيف. معاً يُشكّلان طبقة التوسع الأفقي.

المفاهيم الرئيسية: قالب الإطلاق، سياسات التوسع (تتبع الهدف، خطوية، مجدولة)، فحوصات الصحة، مجموعات هدف ALB، قواعد الاستماع، التوجيه الموزون.

إشارة الاختبار: "التعامل مع حمل متغيّر" أو "توافر عالٍ عبر مناطق التوافر" ← ASG + ALB.

---

**Lambda** *(الفصل العشرون)*

دوال بلا خادم. تكتب الكود؛ AWS تُشغّله استجابةً للأحداث. لا خوادم للإدارة. تدفع لكل استدعاء ولكل مللي ثانية تنفيذ. يتوسع تلقائياً إلى آلاف التنفيذات المتزامنة.

المفاهيم الرئيسية: مصادر الأحداث (API Gateway، S3، SQS، EventBridge، Kinesis)، دور التنفيذ، حدود التزامن، التزامن المحجوز والمُخصَّص، البدء البارد، الطبقات، مدة أقصى 15 دقيقة.

إشارة الاختبار: "بلا خادم"، "مدفوع بالأحداث"، "مهام قصيرة المدة"، "بدون تكلفة في وقت الخمول" ← Lambda.

---

**ECS — Elastic Container Service** *(الفصل الحادي والعشرون)*

يُشغّل حاويات Docker على AWS. نوعا الإطلاق: EC2 (تُدير المضيف) وFargate (AWS تُدير المضيف). يُدير ECS تعريفات المهام والخدمات وجدولة الكتلة والتكامل مع موازنات التحميل واكتشاف الخدمات.

المفاهيم الرئيسية: تعريف المهمة، خدمة ECS، نوع إطلاق Fargate مقابل EC2، ECR (سجل الحاويات)، دور IAM للمهمة، التوسع التلقائي للخدمة.

إشارة الاختبار: "أحمال عمل مُعبَّأة"، "خدمات مصغَّرة"، "Docker على AWS" ← ECS (عادةً Fargate للحاويات البلا خادم).

---

**EKS — Elastic Kubernetes Service** *(الفصل الحادي والعشرون)*

Kubernetes مُدار. تُشغّل AWS طبقة التحكم؛ أنت تُشغّل عقد العمال (EC2 أو Fargate). استخدم EKS حين يستخدم فريقك بالفعل Kubernetes أو لديه أحمال عمل تتطلب ميزات خاصة بـ Kubernetes.

إشارة الاختبار: "Kubernetes"، "الحاجة إلى نقل أحمال K8s الموجودة" ← EKS. "فقط أحتاج الحاويات بدون تعقيد K8s" ← ECS.

---

## التخزين

**S3 — Simple Storage Service** *(الفصل الخامس)*

تخزين الكائنات. سعة غير محدودة، ومتانة 99.999999999% (أحد عشر تسعة). يخزّن الملفات ككائنات في دلوات. الدلوات تعيش في منطقة. يمكن أن تتراوح الكائنات من 0 بايت إلى 5 تيرابايت.

المفاهيم الرئيسية: سياسة الدلو، قائمة التحكم في الوصول للكائن، الإصدارات، استضافة موقع ويب ثابت، URLs موقّعة مسبقاً، الرفع متعدد الأجزاء، Transfer Acceleration، فئات التخزين (Standard، Intelligent-Tiering، Standard-IA، One Zone-IA، Glacier Instant Retrieval، Glacier Flexible Retrieval، Glacier Deep Archive).

إشارة الاختبار: "تخزين واسترداد الملفات"، "الأصول الثابتة"، "النسخ الاحتياطية"، "بحيرة البيانات" ← S3. تعتمد فئة التخزين الصحيحة على تكرار الوصول وسرعة الاسترداد.

---

**EBS — Elastic Block Store** *(الفصل السادس)*

تخزين كتلي مُرفق بنسخة EC2 واحدة. يعمل كقرص صلب. يبقى مستقلاً عن دورة حياة النسخة (يمكن فصله وإعادة إرفاقه). الأنواع الأكثر شيوعاً: gp3 (SSD للأغراض العامة، الافتراضي)، io2 (IOPS مُخصَّصة لقواعد البيانات)، st1 (HDD مُحسَّن للإنتاجية للقراءة التسلسلية).

المفاهيم الرئيسية: اللقطات (تراكمية، مخزّنة في S3)، التشفير (KMS)، Multi-Attach (io1/io2 فقط)، توفير IOPS والإنتاجية.

إشارة الاختبار: "تخزين مستمر لـ EC2"، "تخزين قاعدة البيانات"، "يتطلب وصولاً للكتلة منخفض الاستجابة" ← EBS.

---

**EFS — Elastic File System** *(الفصل السادس)*

نظام ملفات مشترك، يمكن الوصول إليه من نسخ EC2 متعددة في وقت واحد. بروتوكول NFS. يتوسع تلقائياً. أكثر تكلفة من EBS لكل جيجابايت. فئتا تخزين: Standard وInfrequent Access. يُحرّك Intelligent-Tiering الملفات تلقائياً.

إشارة الاختبار: "نظام ملفات مشترك"، "نسخ EC2 متعددة تحتاج نفس الملفات"، "NFS" ← EFS.

---

**فئات تخزين S3 وسياسات دورة الحياة** *(الفصل الثالث والعشرون)*

S3 Intelligent-Tiering ينقل الكائنات تلقائياً بين مستويات الوصول بحسب تكرار الوصول. سياسات دورة الحياة تُنقل الكائنات بين الفئات (Standard → Standard-IA → Glacier) بحسب قواعد العمر. لفئات Glacier أوقات استرداد تتراوح من دقائق (Glacier Instant) إلى 12 ساعة (Glacier Deep Archive).

إشارة الاختبار: "تقليل تكاليف التخزين للبيانات نادرة الوصول" ← سياسات دورة الحياة، Intelligent-Tiering، أو Glacier.

---

## قواعد البيانات

**RDS — Relational Database Service** *(الفصل الثامن)*

قواعد بيانات علائقية مُدارة. المحركات المدعومة: MySQL، PostgreSQL، MariaDB، Oracle، SQL Server، وAurora (محرك AWS الخاص). تتعامل AWS مع النسخ الاحتياطية والتصحيح والتحوّل والنسخ المتماثل. تتعامل أنت مع تصميم المخطط والاستعلامات وتحجيم النسخ.

المفاهيم الرئيسية: نشر Multi-AZ (تحوّل تلقائي، نسخ متزامن)، نسخ القراءة (غير متزامن، لتوسيع القراءة)، النسخ الاحتياطية التلقائية (احتفاظ 1-35 يوم)، اللقطات اليدوية (تُحتفظ حتى الحذف)، RDS Proxy (تجميع الاتصالات).

إشارة الاختبار: "قاعدة بيانات علائقية"، "معاملات ACID"، "حمل عمل SQL موجود" ← RDS أو Aurora.

---

**Aurora** *(الفصل الرابع والعشرون)*

محرك قاعدة البيانات العلائقية الخاص بـ AWS، متوافق مع MySQL وPostgreSQL. محرك تخزين موزّع ينسخ البيانات عبر 3 مناطق توافر في 6 نسخ. أسرع عادةً بـ 5 مرات من MySQL. يتوسع Aurora Serverless v2 سعته تلقائياً (مُقاس بـ ACUs — وحدات سعة Aurora).

المفاهيم الرئيسية: كتلة Aurora (كاتب + حتى 15 نقطة نهاية قارئة)، Aurora Global Database (نسخ قراءة بين المناطق بتأخر أقل من ثانية)، Aurora Serverless v2.

إشارة الاختبار: "قاعدة بيانات علائقية عالية الأداء"، "متوافقة مع MySQL/PostgreSQL"، "قراءات عالمية"، "حمل عمل متغيّر" ← Aurora.

---

**DynamoDB** *(الفصل التاسع)*

قاعدة بيانات NoSQL مُدارة بالكامل. نموذج قيمة-مفتاح ومستند. يتوسع لأي إنتاجية باستجابة بأرقام أحادية بالمللي ثانية. وضعان للسعة: عند الطلب (ادفع لكل طلب) ومُخصَّص (ادفع لكل وحدة سعة في الساعة، مع التوسع التلقائي).

المفاهيم الرئيسية: مفتاح التقسيم (مطلوب)، مفتاح الترتيب (اختياري)، الفهرس الثانوي العالمي (GSI)، الفهرس الثانوي المحلي (LSI)، DynamoDB Streams (التقاط تغييرات البيانات)، DAX (DynamoDB Accelerator) — تخزين مؤقت في الذاكرة، TTL (مدة الصلاحية)، المعاملات.

إشارة الاختبار: "وصول عالي الإنتاجية قائم على المفاتيح"، "مخطط مرن"، "NoSQL بلا خادم" ← DynamoDB.

---

**ElastiCache** *(الفصل العاشر)*

تخزين مؤقت في الذاكرة مُدار. محركان: Redis (مستمر، نشر/اشتراك، برمجة Lua، هياكل البيانات) وMemcached (تخزين مؤقت صرف، أبسط، متعدد الخيوط). استخدم لتقليل حمل قاعدة البيانات وخدمة البيانات المقروءة بشكل متكرر في ميكرو ثانية.

المفاهيم الرئيسية: نمط cache-aside، نمط الكتابة الشاملة، سياسات الإخلاء، TTL، وضع الكتلة (Redis)، Multi-AZ مع تحوّل تلقائي.

إشارة الاختبار: "تقليل حمل قاعدة البيانات"، "زمن استجابة قراءة دون مللي ثانية"، "إدارة الجلسة"، "لوحة نتائج فورية" ← ElastiCache Redis.

---

## الشبكات

**VPC — Virtual Private Cloud** *(الفصل الحادي عشر)*

شبكة افتراضية معزولة داخل AWS. تمتد عبر جميع مناطق التوافر في المنطقة. تُعرّف مساحة عناوين IP (كتلة CIDR)، وتُنشئ الشبكات الفرعية (عامة أو خاصة)، وتضبط جداول التوجيه، وتتحكم في الوصول عبر مجموعات الأمان وNACLs.

المفاهيم الرئيسية: شبكة فرعية عامة (مسار لبوابة الإنترنت)، شبكة فرعية خاصة (مسار لبوابة NAT للخروج)، بوابة الإنترنت (ثنائية الاتجاه للإنترنت)، بوابة NAT (خروج فقط للنسخ الخاصة)، إقران VPC (توصيل VPCs اثنين)، نقاط نهاية VPC (توصيل لخدمات AWS بدون إنترنت).

إشارة الاختبار: "شبكة خاصة على AWS"، "عزل الموارد عن الإنترنت"، "التحكم في حركة الشبكة" ← VPC.

---

**مجموعات الأمان وNACLs** *(الفصل الخامس عشر)*

مجموعات الأمان جدران حماية ذات حالة على مستوى النسخة — قواعد السماح فقط، زيارات العودة تلقائية. NACLs (قوائم التحكم في الوصول للشبكة) جدران حماية عديمة الحالة على مستوى الشبكة الفرعية — تتطلب قواعد واردة وصادرة، تُقيَّم بالترتيب الرقمي.

إشارة الاختبار: "حجب IP محدد من الوصول للشبكة الفرعية" ← قاعدة رفض NACL. "التحكم في الزيارات من/إلى نسخة" ← مجموعة الأمان.

---

**Route 53** *(الفصل الثاني عشر)*

خدمة DNS ومُسجّل نطاقات من AWS. تُوجّه زيارات الإنترنت لموارد AWS ونقاط النهاية الخارجية. سياسات التوجيه: بسيطة، موزونة، قائمة على زمن الاستجابة، تحوّل، جغرافية، جغرافية قرب، إجابة متعددة القيم.

المفاهيم الرئيسية: المناطق المستضافة (عامة وخاصة)، أنواع السجلات (A، AAAA، CNAME، Alias)، فحوصات الصحة، Traffic Flow (محرر السياسة المرئي).

إشارة الاختبار: "توجيه DNS"، "تحوّل بين المناطق"، "توجيه بحسب زمن الاستجابة أو الموقع" ← Route 53 مع سياسة التوجيه المناسبة.

---

**CloudFront** *(الفصل الثالث عشر)*

شبكة توصيل المحتوى (CDN). تُخزّن المحتوى مؤقتاً في مواقع الحافة (400+ حول العالم). تُقلل الاستجابة للمستخدمين النهائيين. تُقلل تكاليف نقل الأصل من خلال التخزين المؤقت. تتكامل مع S3 وEC2 وALB وAPI Gateway كأصول.

المفاهيم الرئيسية: التوزيع، الأصول، السلوكيات (توجيه قائم على المسار للأصول)، TTL (التحكم في ذاكرة التخزين المؤقتة)، إبطال الذاكرة المؤقتة، URLs الموقّعة والكوكيز (التحكم في الوصول)، Lambda@Edge وCloudFront Functions (تشغيل الكود في الحافة)، Origin Shield (تقليل حمل الأصل).

إشارة الاختبار: "زمن استجابة عالمي منخفض"، "تخزين مؤقت للمحتوى الثابت"، "تقليل حمل الأصل"، "الحماية من DDoS مع Shield" ← CloudFront.

---

**Direct Connect وVPN** *(الفصل الخامس والعشرون)*

AWS Direct Connect اتصال شبكة فيزيائي مخصص من مركز البيانات المحلي لديك إلى AWS. يتجاوز الإنترنت العام. نطاق ترددي واستجابة أكثر اتساقاً. AWS Site-to-Site VPN نفق مُشفَّر عبر الإنترنت العام — أسرع في الإعداد، أقل تكلفة، لكن أداء متغيّر.

المفاهيم الرئيسية: الواجهة الافتراضية (VIF)، Direct Connect Gateway (الاتصال بمناطق متعددة)، Transit Gateway (طبولوجيا شبكة Hub-and-Spoke)، تكرار نفق VPN.

إشارة الاختبار: "اتصال خاص مخصص بـ AWS" ← Direct Connect. "اتصال مُشفَّر، إعداد أسرع" ← VPN. "توصيل VPCs متعددة" ← Transit Gateway.

---

**نقاط نهاية VPC** *(الفصل الثلاثون)*

توصيل الموارد الخاصة بخدمات AWS عبر الشبكة الخاصة لـ AWS دون استخدام الإنترنت العام أو بوابة NAT. نقاط نهاية البوابة: مجانية، متاحة لـ S3 وDynamoDB فقط. نقاط نهاية الواجهة (PrivateLink): مُقيَّمة بالساعة + بالجيجابايت، متاحة لمعظم خدمات AWS.

إشارة الاختبار: "EC2 في شبكة فرعية خاصة تستدعي S3/DynamoDB — تقليل تكاليف بوابة NAT" ← نقطة نهاية بوابة (مجانية). "اتصال خاص بـ SQS، SSM، Secrets Manager من الشبكة الفرعية الخاصة" ← نقطة نهاية الواجهة.

---

## الأمان والهوية

**IAM — Identity and Access Management** *(الفصلان الثالث والرابع عشر)*

يتحكم في من يمكنه فعل ماذا في حساب AWS الخاص بك. المستخدمون (بيانات اعتماد طويلة الأجل)، المجموعات (مستخدمون يشتركون في أذونات)، الأدوار (بيانات اعتماد مؤقتة للخدمات والوصول بين الحسابات)، السياسات (وثائق JSON تُعرّف قواعد السماح/الرفض).

المفاهيم الرئيسية: المبدأ، الإجراء، المورد، الشرط، الرفض الصريح > الإذن الصريح > الرفض الضمني، SCP (سياسة التحكم في الخدمة في AWS Organizations)، حد الأذونات، AssumeRole.

إشارة الاختبار: IAM مُدرج في كل سؤال أمان. النمط الرئيسي: الخدمات تستخدم أدوار IAM (وليس مستخدمين). الوصول بين الحسابات يستخدم افتراض الدور. أقل الامتيازات — امنح فقط ما هو مطلوب.

---

**KMS — Key Management Service** *(الفصل السادس عشر)*

خدمة مفاتيح تشفير مُدارة. تُنشئ المفاتيح التشفيرية وتخزّنها وتتحكم فيها. تسمح مفاتيح العميل المُدارة (CMKs) بتعريف التجديد والاستخدام وسياسات الوصول. المفاتيح المُدارة من AWS تُدار تلقائياً.

المفاهيم الرئيسية: سياسة المفاتيح (منفصلة عن سياسة IAM)، التشفير بالغلاف (البيانات مُشفَّرة بمفتاح بيانات؛ مفتاح البيانات مُشفَّر بـ CMK)، التجديد التلقائي للمفاتيح، المفاتيح متعددة المناطق، المنح.

إشارة الاختبار: "تشفير البيانات في حالة الراحة"، "مفاتيح تشفير مُدارة من العميل"، "تجديد المفاتيح" ← KMS.

---

**Secrets Manager** *(الفصل السادس عشر)*

يخزّن القيم الحساسة ويُجدّدها تلقائياً: بيانات اعتماد قواعد البيانات، مفاتيح API، رموز OAuth. يتكامل مع RDS للتجديد التلقائي للكلمة المرور. التطبيقات تسترجع الأسرار في وقت التشغيل عبر API — لا تُرمَّز بيانات الاعتماد أبداً.

إشارة الاختبار: "تخزين وتجديد بيانات اعتماد قاعدة البيانات"، "تجنب الأسرار المُرمَّزة بشكل ثابت" ← Secrets Manager. "تخزين قيم التكوين، وليس الأسرار" ← Parameter Store (SSM).

---

**AWS Shield** *(الفصل السابع عشر)*

حماية DDoS. Shield Standard تلقائي ومجاني — يحمي من هجمات حجمية وبروتوكول شائعة. Shield Advanced يضيف حماية مالية وفريق استجابة DDoS على مدار الساعة ورؤية هجمات مُفصَّلة.

إشارة الاختبار: "الحماية من DDoS" ← Shield Standard (تلقائي) أو Shield Advanced (للمؤسسات، مع SLA).

---

**WAF — Web Application Firewall** *(الفصل السابع عشر)*

يُصفّي زيارات HTTP/HTTPS بحسب القواعد: حجب IPs، تحديد المعدل، أنماط حقن SQL، أنماط XSS، قيود جغرافية، قواعد مخصصة. يُرفق بـ CloudFront وALB وAPI Gateway وAppSync.

إشارة الاختبار: "حجب عناوين IP محددة"، "منع حقن SQL في الحافة"، "تحديد معدل استدعاءات API" ← WAF.

---

**GuardDuty** *(الفصل السابع عشر)*

خدمة كشف التهديدات. تُحلّل سجلات CloudTrail وسجلات تدفق VPC وسجلات DNS باستخدام ML ومعلومات التهديد. تكتشف نشاط API غير عادي والتواصل مع IPs ضارة معروفة وبيانات اعتماد مخترقة.

إشارة الاختبار: "كشف نشاط غير عادي"، "تحديد بيانات اعتماد IAM المخترقة"، "مراقبة التهديدات باستمرار" ← GuardDuty.

---

## المراسلة ومعالجة الأحداث

**SQS — Simple Queue Service** *(الفصل التاسع عشر)*

قائمة انتظار رسائل مُدارة. يُرسل المنتجون الرسائل؛ يقرأها المستهلكون ويحذفونها. يُفصل الخدمات: المُرسِل لا يحتاج معرفة ما إذا كان المُستقبِل متاحاً. القوائم القياسية: تسليم مرة على الأقل، ترتيب يبذل قصارى جهده. قوائم FIFO: معالجة مرة واحدة بالضبط، ترتيب صارم.

المفاهيم الرئيسية: مهلة الرؤية (الرسالة مخفية أثناء المعالجة)، قائمة الرسائل الميتة (DLQ) للرسائل التي تفشل بشكل متكرر، الاحتفاظ بالرسائل (4 أيام افتراضي، حتى 14)، الاستقراء الطويل (تقليل الاستجابات الفارغة).

إشارة الاختبار: "فصل الخدمات"، "تخزين الطلبات مؤقتاً أثناء ارتفاعات الحمل"، "معالجة غير متزامنة" ← SQS. "الترتيب مهم والتسليم مرة واحدة بالضبط مطلوب" ← SQS FIFO.

---

**SNS — Simple Notification Service** *(الفصل التاسع عشر)*

خدمة نشر/اشتراك مُدارة. يُرسل الناشرون رسالة إلى موضوع؛ يستقبل جميع المشتركين نسخة. نمط توزيع المروحة: رسالة واحدة ← مستهلكون متعددون. البروتوكولات: SQS، Lambda، HTTP/HTTPS، بريد إلكتروني، SMS، دفع جوال.

المفاهيم الرئيسية: الموضوع، الاشتراك، نمط توزيع المروحة (SNS ← قوائم SQS متعددة)، تصفية الرسائل (يستقبل المشتركون الرسائل المطابقة فقط).

إشارة الاختبار: "إرسال إشعارات إلى نقاط نهاية متعددة في آن واحد"، "توزيع حدث واحد إلى مستهلكين متعددين" ← SNS. النمط الشائع: SNS + SQS للتوزيع الدائم.

---

**EventBridge** *(الفصل الثاني والعشرون)*

ناقل أحداث لبناء معماريات مدفوعة بالأحداث. يُوجّه الأحداث من خدمات AWS وشركاء SaaS ومصادر مخصصة إلى Lambda وSQS وSNS وStep Functions وأهداف أخرى. يدعم القواعد المجدولة (cron) ومطابقة الأنماط.

إشارة الاختبار: "توجيه الأحداث من خدمات AWS إلى أهداف"، "جدولة دوال Lambda"، "تنسيق مدفوع بالأحداث" ← EventBridge.

---

**Step Functions** *(الفصل الثاني والعشرون)*

تنسيق سير العمل البلا خادم. يُنسّق دوال Lambda ومهام ECS وDynamoDB وSNS وSQS وخدمات أخرى في آلات حالة مرئية. يتعامل مع إعادة المحاولات ومعالجة الأخطاء والفروع المتوازية وحالات الانتظار.

المفاهيم الرئيسية: آلة الحالة، أنواع الحالات (مهمة، انتظار، اختيار، متوازي، خريطة، تمرير، نجاح، فشل)، سير العمل القياسي (مرة واحدة بالضبط، طويل التشغيل) مقابل سير العمل السريع (مرة على الأقل، حجم كبير).

إشارة الاختبار: "تنسيق دوال Lambda متعددة"، "سير عمل طويل التشغيل مع منطق إعادة المحاولة"، "خطوات موافقة بشرية" ← Step Functions.

---

**Kinesis** *(الفصل السادس والعشرون)*

تدفق البيانات في الوقت الفعلي. Kinesis Data Streams: تدفق مُرتَّب ومتين من السجلات (مثل سجل الإيداع الموزع). يُعالج المستهلكون السجلات؛ تُحتفظ بالبيانات من 24 ساعة إلى 7 أيام. Kinesis Data Firehose: تسليم مُدار بالكامل لـ S3 وRedshift وOpenSearch وSplunk — لا إدارة مستهلك مطلوبة.

المفاهيم الرئيسية: الحيز (وحدة الإنتاجية: 1 ميجابايت/ثانية كتابة، 2 ميجابايت/ثانية قراءة)، مفتاح التقسيم (يُحدد تعيين الحيز)، رقم التسلسل، نقاط التفتيش (KCL أو Lambda)، Firehose مقابل Streams.

إشارة الاختبار: "تدفق فوري"، "سجلات مُرتَّبة"، "إعادة تشغيل الأحداث" ← Kinesis Data Streams. "تسليم بيانات التدفق لـ S3/Redshift بدون إدارة المستهلكين" ← Kinesis Firehose. تمييز عن SQS: Kinesis يحتفظ ويُعيد التشغيل؛ SQS يحذف عند الاستهلاك.

---

## التحليلات

**Athena** *(الفصل السادس والعشرون)*

استعلامات SQL بلا خادم على البيانات المخزّنة في S3. لا بنية تحتية للإدارة. ادفع لكل استعلام (لكل تيرابايت مُفحوص). الأفضل مع التنسيقات العمودية (Parquet، ORC) والبيانات المُقسَّمة.

إشارة الاختبار: "استعلام بيانات S3 بـ SQL"، "تحليلات مخصصة على بحيرة البيانات"، "لا إدارة بنية تحتية" ← Athena.

---

**Glue** *(الفصل السادس والعشرون)*

خدمة ETL (استخراج، تحويل، تحميل) بلا خادم. تكشف Glue Crawlers البيانات وتُحدّث Glue Data Catalog. Glue Jobs تُشغّل تحويلات Spark أو Python. يتكامل Data Catalog مع Athena وRedshift Spectrum وEMR.

إشارة الاختبار: "تحويل وتحميل البيانات للتحليلات"، "اكتشاف مخطط بيانات S3"، "خط أنابيب ETL" ← Glue.

---

## التوافر العالي والاسترداد من الكوارث

**Multi-AZ وMulti-Region** *(الفصل الثامن عشر)*

Multi-AZ: نسخ متزامن داخل المنطقة للتحوّل التلقائي (RDS Multi-AZ، موازن التحميل عبر مناطق التوافر). RPO ~0، RTO ~60 ثانية لـ RDS. Multi-Region: نسخ غير متزامن للتكرار الجغرافي وزمن استجابة أقل للمستخدمين العالميين.

المفاهيم الرئيسية: RTO (هدف وقت الاسترداد — كم من الوقت للاسترداد)، RPO (هدف نقطة الاسترداد — كم من البيانات يمكن فقدانه). استراتيجيات Pilot Light، Warm Standby، Active-Active للاسترداد من الكوارث.

إشارة الاختبار: ميّز بين الإخفاقات على مستوى منطقة التوافر (Multi-AZ يتعامل) مقابل الإخفاقات الإقليمية (Multi-Region يتعامل). التكلفة والتعقيد يزيدان بشكل ملحوظ مع Multi-Region.

## تحسين التكاليف

**نماذج تسعير EC2** *(الفصل السابع والعشرون)*

عند الطلب: سعر كامل، بدون التزام. نسخ محجوزة (سنة 1 أو 3): خصم 30-72% لنوع نسخة محدد. خطط التوفير (Compute أو EC2 Instance): إنفاق ساعي ملتزم للمرونة. Spot: خصم 60-90% للأحمال القابلة للمقاطعة.

إشارة الاختبار: "تقليل التكلفة لحمل عمل قابل للتنبؤ" ← خطط التوفير أو النسخ المحجوزة. "معالجة دفعية متحمّلة للأعطال" ← Spot. "غير متوقع أو قصير الأجل" ← عند الطلب.

---

**تسعير نقل البيانات** *(الفصل الثلاثون)*

واردة إلى AWS: مجانية. نفس منطقة التوافر: مجانية. بين مناطق التوافر: 0.01 دولار/جيجابايت كل اتجاه. بين المناطق: 0.02-0.08 دولار/جيجابايت. الإنترنت (صادرة): ~0.09 دولار/جيجابايت. معالجة بوابة NAT: 0.045 دولار/جيجابايت. نقل بيانات CloudFront أرخص من EC2-إلى-الإنترنت المباشر، ويُقلل حجم نقل الأصل بشكل كبير من خلال التخزين المؤقت.

إشارة الاختبار: "تقليل تكاليف نقل البيانات لـ S3/DynamoDB من الشبكة الفرعية الخاصة" ← نقاط نهاية البوابة (مجانية لـ S3 وDynamoDB). "تقليل تكاليف بوابة NAT للخدمات الأخرى" ← نقاط نهاية الواجهة.

## قابلية الملاحظة

**CloudWatch** *(مُشار إليه طوال الكتاب)*

المراقبة وقابلية الملاحظة. مقاييس CloudWatch: بيانات متسلسلة زمنياً رقمية من خدمات AWS والتطبيقات المخصصة. سجلات CloudWatch: جمع وبحث وتحليل بيانات السجل. منبّهات CloudWatch: تشغيل الإشعارات أو التوسع التلقائي بحسب عتبات المقاييس. لوحات CloudWatch: تصوير المقاييس.

المفاهيم الرئيسية: أبعاد المقاييس، فترات الاحتفاظ، مجموعات السجلات وتدفقات السجلات، مرشحات المقاييس، CloudWatch Agent (لمقاييس نظام التشغيل وسجلات EC2)، Container Insights.

---

**CloudTrail** *(مُشار إليه طوال الكتاب)*

يسجّل كل استدعاء API في حسابك على AWS: من استدعاه، من أين، متى، وما الاستجابة. المسار متعدد المناطق يخزّن السجلات في S3 إلى أجل غير مسمّى. يُستخدم للتدقيق الأمني والامتثال والتحقيق في الحوادث.

إشارة الاختبار: "من حذف ذلك المورد؟" "تدقيق جميع نشاط API" ← CloudTrail.

---

**AWS Config** *(مُشار إليه في الفصل الحادي والثلاثون)*

يتتبع تغييرات تكوين موارد AWS عبر الزمن. يُقيّم الموارد مقابل قواعد الامتثال. يسجّل تاريخ كل تغيير في التكوين لكل مورد. يتكامل مع Systems Manager للمعالجة.

إشارة الاختبار: "هل هذا المورد متوافق مع سياستنا الأمنية؟" "كيف كان تكوين هذا المورد الأسبوع الماضي؟" ← AWS Config.

**الأعمدة الستة** *(الفصل الحادي والثلاثون)*

| العمود | السؤال الأساسي | الخدمات الرئيسية |
|--------|----------------|-----------------|
| التميز التشغيلي | هل نعمل بشكل جيد؟ | CloudWatch، CloudTrail، SSM، Config |
| الأمان | هل نحن محميون؟ | IAM، KMS، GuardDuty، WAF، Shield، Secrets Manager |
| الموثوقية | هل نتعافى من الفشل؟ | Multi-AZ، تحوّل Route 53، نسخ احتياطي/استعادة، SQS |
| كفاءة الأداء | هل نستخدم الموارد الصحيحة؟ | التحجيم الصحيح، التوسع التلقائي، CloudFront، Kinesis |
| تحسين التكاليف | هل ننفق بحكمة؟ | خطط التوفير، Spot، دورة حياة S3، نقاط نهاية VPC |
