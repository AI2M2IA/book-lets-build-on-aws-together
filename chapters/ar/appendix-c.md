# الملحق ج: سجل المفاهيم

كل مفهوم رئيسي مُقدَّم في الكتاب، مُعيَّن إلى فصله والتشبيه المستخدم ونطاق SAA-C03 الذي يظهر فيه.

استخدم هذا كفهرس دراسة: إذا كنت غير متأكد من مفهوم قبل الاختبار، فابحث عنه هنا وعُد إلى فصله للسياق.

---

## A

**ACM (AWS Certificate Manager)** — شهادات TLS عامة مجانية لـ ALB وCloudFront وAPI Gateway، مع تجديد تلقائي عبر التحقق من DNS. يجب أن تعيش شهادات CloudFront في us-east-1. الفصل 16. النطاق 1.

**ACU (Aurora Capacity Unit)** — وحدة قياس سعة Aurora Serverless v2. تتوسع تلقائياً ويمكنها، على إصدارات المحرّك المدعومة، الإيقاف المؤقت تلقائياً إلى 0 ACUs حين لا تُبقى أي اتصالات مفتوحة. الفصل 24. النطاق 3.

**التنبيه (CloudWatch Alarm)** — قاعدة تُطلَق حين يعبر مقياس عتبة، مُشغِّلةً إشعاراً أو إجراء توسع تلقائي. الفصل 7. النطاق 2.

**ALB (Application Load Balancer)** — موازِن تحميل في الطبقة 7 يوجّه زيارة HTTP/HTTPS بناءً على قواعد المسار والمضيف. الفصل 7. النطاق 2.

**AMI (Amazon Machine Image)** — قالب يحوي نظام التشغيل والبرمجيات والتهيئة لنسخة EC2. الفصل 4. النطاق 3.

**عقلية المهندس (Architect mindset)** — طرح سؤال "ما الذي يفشل أولاً، وكيف نعرف، وماذا يفعل أحدهم في الثالثة فجراً؟" بدلاً من سؤال "كيف يعمل هذا؟" فقط. الفصل 32، الفصل 34. عبر النطاقات.

**سجل قرار البنية (ADR)** — مستند موجز يلتقط قراراً وبدائله ومنطقه وما قد يدعو لإعادة النظر فيه. الفصل 32. عبر النطاقات.

**مراجعة البنية** — عملية مُهيكلة تغطي: القيود ← المجهولات ← الخيارات ← أنماط الفشل ← المراقبة ← أدلة التشغيل. الفصل 32. عبر النطاقات.

**Athena** — خدمة استعلام SQL بلا خادم للبيانات في S3. الدفع لكل TB مفحوص. أفضل مع صيغ Parquet/ORC العمودية. الفصل 26. النطاق 3.

**مجموعة التوسع التلقائي (ASG)** — مجموعة من نسخ EC2 تُدار معاً، تستبدل النسخ غير السليمة تلقائياً وتتوسع بناءً على الحمل. الفصل 7. النطاقان 2، 3.

**منطقة التوافر (AZ)** — مركز بيانات واحد أو أكثر مفصول فيزيائياً داخل منطقة، متصل بروابط منخفضة زمن الوصول. الفصل 2. النطاق 2.

## B

**AWS Backup** — نسخ احتياطي مركزي قائم على السياسات عبر EBS وRDS وDynamoDB وEFS وStorage Gateway. يدعم النسخ عبر المناطق وعبر الحسابات. الفصلان 18، 23. النطاق 2.

**AWS Batch** — حوسبة دفعية مُدارة لحاويات Docker. مُكوَّنة من تعريف مهمة (ما يُشغَّل)، وطابور مهام (حيث تنتظر المهام)، وبيئة حوسبة (EC2 أو Fargate، عند الطلب أو Spot). لأحمال العمل التي تتجاوز حد Lambda البالغ 15 دقيقة. الفصل 21. النطاق 3.

**الدلو (Bucket في S3)** — حاوية لكائنات S3. للدلاء أسماء عالمية فريدة وتعيش في منطقة محددة. الفصل 5. النطاق 3.

**سياسة الدلو (Bucket policy)** — سياسة قائمة على المورد مرفقة بدلو S3 تتحكم في الوصول لكيانات IAM والحسابات الخارجية. الفصل 5. النطاق 1.

## C

**نمط Cache-aside** — يفحص التطبيق ذاكرة التخزين المؤقت أولاً؛ وعند عدم الإصابة، يستعلم قاعدة البيانات، ثم يخزّن النتيجة في ذاكرة التخزين المؤقت. الفصل 10. النطاق 3.

**معدل إصابة ذاكرة التخزين المؤقت (Cache hit rate)** — نسبة الطلبات المُخدَّمة من ذاكرة التخزين المؤقت بدلاً من الأصل. الأعلى أفضل. الفصل 13. النطاق 3.

**AWS Client VPN** — نقطة نهاية OpenVPN مُدارة. تربط الأجهزة الفردية (الحواسيب المحمولة، محطات العمل) بـ VPC عبر الإنترنت. مصادقة عبر Active Directory، أو موحَدة SAML 2.0 مع مزوّد هوية، أو TLS متبادل. تدعم وضعي النفق المنقسم والكامل. للمقارنة مع Site-to-Site VPN (شبكة إلى شبكة). الفصل 11. النطاق 1.

**CloudFront** — CDN من AWS. يخزّن المحتوى مؤقتاً في 750+ موقع حافة حول العالم. يقلّل زمن الوصول وتكاليف نقل بيانات الأصل. الفصل 13. النطاقان 3، 4.

**CloudTrail** — يسجّل كل استدعاء واجهة برمجية في AWS: من، وماذا، ومتى، ومن أين. يُخزَّن في S3. يُستخدَم للتدقيق والتحقيق في الحوادث. النطاق 1.

**CloudWatch** — مقاييس وسجلات وتنبيهات ولوحات معلومات لموارد AWS والتطبيقات المخصصة. مُشار إليه في كل الكتاب. كل النطاقات.

**Amazon Cognito** — مصادقة للمستخدمين النهائيين لتطبيقك: User Pools دليل مستخدمين مُدار (تسجيل، تسجيل دخول، MFA، تسجيل دخول اجتماعي، رموز JWT)؛ Identity Pools تُصدِر بيانات اعتماد AWS مؤقتة. IAM لمهندسيك؛ Cognito لعملائك. الفصل 14. النطاق 1.

**البدء البارد (Cold start في Lambda)** — تأخير عند أول استدعاء (أو بعد الخمول) بينما تُهيّئ Lambda بيئة التنفيذ. استخدم التزامن المُخصَّص لإلغائه. الفصل 20. النطاق 3.

**Compute Savings Plan** — التزام بمبلغ بالدولار من الإنفاق الساعي لـ EC2، يُطبَّق على أي نوع أو حجم نسخة. الفصل 27. النطاق 4.

**Config (AWS)** — يتتبّع تغييرات التهيئة لموارد AWS عبر الزمن ويُقيِّم الامتثال مقابل القواعد. الفصل 31. النطاق 1.

**AWS Control Tower** — يُؤتمت حوكمة متعددة الحسابات: يبني منطقة هبوط (حسابات الإدارة وأرشيف السجلات والتدقيق) بحواجز في دقائق — النسخة الجاهزة من توصيل Organizations وCloudTrail وConfig يدوياً. الفصل 14. النطاق 1.

**نقل البيانات عبر مناطق التوافر (Cross-AZ data transfer)** — الزيارة بين مناطق التوافر داخل منطقة. تُحتسَب بـ 0.01$/GB لكل اتجاه. الفصل 30. النطاق 4.

**التكرار عبر المناطق (Cross-region replication)** — نسخ البيانات (S3 CRR، Aurora Global، DynamoDB Global Tables) إلى منطقة مختلفة. يتكبّد رسوم نقل بيانات. الفصول 18، 23، 30. النطاق 2.

## D

**AWS DataSync** — هجرة ومزامنة قائمة على وكيل لمشاركات الملفات (NFS/SMB) إلى S3 أو EFS أو FSx. "rsync مُعزَّز، مع وحدة تحكم AWS." الفصل 25. النطاق 3.

**DAX (DynamoDB Accelerator)** — ذاكرة تخزين مؤقت في الذاكرة خاصة بـ DynamoDB تحديداً. زمن وصول قراءة بالميكروثانية. الفصل 9. النطاق 3.

**طابور الرسائل الميتة (DLQ)** — طابور تُرسَل إليه الرسائل التي تفشل معالجتها مراراً، مانعاً انسداد الطابور. الفصل 19. النطاق 2.

**AWS DMS (Database Migration Service)** — ينقل قواعد البيانات إلى AWS بأدنى توقّف. التحميل الكامل (النسخ الأولي) إضافةً إلى CDC (التقاط البيانات التغييري) يُبقي المصدر والهدف متزامنين أثناء الهجرة. الهجرات المتجانسة (نوع المحرّك نفسه): استخدم DMS مباشرةً. الهجرات غير المتجانسة (أنواع محرّكات مختلفة، مثل Oracle ← Aurora PostgreSQL): استخدم SCT (أداة تحويل المخطط) أولاً، ثم DMS. الفصل 8. النطاق 3.

**Dedicated Host** — خادم EC2 فيزيائي محجوز حصرياً لاستخدامك. مطلوب لتراخيص برمجيات معينة. الفصل 27. النطاق 4.

**الدفاع في العمق (Defense in depth)** — تطبيق طبقات من ضوابط أمنية متعددة (IAM + مجموعات الأمان + شبكات NACL + WAF + GuardDuty) بحيث لا يكشف اختراق طبقة واحدة النظام. الفصل 33. النطاق 1.

**Direct Connect** — اتصال شبكي خاص مُكرَّس من موقع محلي إلى AWS. أكثر اتساقاً من VPN. الفصل 25. النطاق 3.

**DLQ** — انظر طابور الرسائل الميتة.

**DynamoDB** — قاعدة بيانات NoSQL مُدارة بالكامل بزمن وصول بالمللي ثانية أحادية الرقم في أي مقياس. نموذج مفتاح-قيمة ومستند. الفصل 9. النطاق 3.

**DynamoDB Auto Scaling** — يضبط سعة القراءة/الكتابة المُخصَّصة تلقائياً بناءً على مقاييس CloudWatch. الفصل 29. النطاق 4.

**DynamoDB Streams** — سجل تغييرات مرتّب زمنياً لكل تغييرات العناصر في جدول DynamoDB. يُستخدَم مع Lambda للمعالجة المدفوعة بالأحداث. الفصل 9. النطاق 2.

## E

**EBS (Elastic Block Store)** — تخزين كتلي مرفق بنسخة EC2 واحدة. يبقى مستقلاً. الأنواع: gp3، io2، st1. الفصل 6. النطاق 3.

**EC2 (Elastic Compute Cloud)** — آلات افتراضية في السحابة. الفصل 4. النطاق 3.

**ECS (Elastic Container Service)** — تنسيق حاويات مُدار. نوع إطلاق Fargate يزيل إدارة الخادم. الفصل 21. النطاقان 2، 3.

**EFS (Elastic File System)** — نظام ملفات NFS مشترك يمكن الوصول إليه من نسخ EC2 متعددة. يتوسع تلقائياً. تشمل فئات التخزين Standard وInfrequent Access وArchive، مع Intelligent-Tiering للنقل التلقائي بين الطبقات. الفصل 6. النطاق 3.

**EKS (Elastic Kubernetes Service)** — طبقة تحكم Kubernetes مُدارة على AWS. الفصل 21. النطاق 3.

**Elastic Disaster Recovery (DRS)** — تكرار مستمر على مستوى الكتلة للخوادم (محلية أو EC2) إلى منطقة تجهيز منخفضة التكلفة، مع إطلاق نسخ تعافٍ في دقائق — ضوء إرشادي مُدار. الفصل 18. النطاق 2.

**ElastiCache** — تخزين مؤقت مُدار في الذاكرة. Redis (ميزات أغنى) أو Memcached (أبسط). الفصل 10. النطاق 3.

**Elastic IP** — عنوان IP عام ثابت يمكنك تخصيصه وإعادة ربطه بنسخ EC2. الفصل 11. النطاق 3.

**تشفير الغلاف (Envelope encryption)** — نمط تُشفَّر فيه البيانات بمفتاح بيانات (DEK)، ويُشفَّر مفتاح البيانات بمفتاح رئيسي (CMK في KMS). الفصل 16. النطاق 1.

**EventBridge** — ناقل أحداث لتوجيه الأحداث من خدمات AWS وشركاء SaaS والمصادر المخصصة إلى الأهداف. يدعم القواعد المجدولة. الفصل 22. النطاق 2.

**المنع الصريح (Explicit deny)** — عبارة منع IAM لا يمكن تجاوزها بأي سماح. لها الأسبقية على كل السماحات. الفصل 3. النطاق 1.

## F

**توجيه التحوّل عند الفشل (Failover routing في Route 53)** — يوجّه الزيارة إلى نقطة نهاية ثانوية حين تفشل الأساسية في فحوصات الصحة. الفصل 12. النطاق 2.

**Fargate** — محرّك حوسبة بلا خادم لـ ECS وEKS. لا نسخ EC2 للإدارة. الفصل 21. النطاق 3.

**نمط التوزيع (Fan-out pattern)** — موضوع SNS واحد يسلّم الرسالة نفسها إلى طوابير SQS متعددة في آنٍ واحد. الفصل 19. النطاق 2.

**طابور FIFO (في SQS)** — معالجة مرة واحدة بالضبط، ترتيب صارم. إنتاجية أقل من الطوابير القياسية. الفصل 19. النطاق 2.

**نمط الفشل (Failure mode)** — طريقة محددة يمكن للنظام أن يفشل بها. تحديد أنماط الفشل قبل الإنتاج هو جوهر مراجعة البنية. الفصل 32. عبر النطاقات.

## G

**Gateway Endpoint** — نوع نقطة نهاية VPC مجاني لـ S3 وDynamoDB. يوجّه الزيارة عبر شبكة AWS الخاصة، مُلغياً رسوم NAT Gateway. الفصل 30. النطاق 4.

**Gateway Load Balancer (GWLB)** — موازِن تحميل في الطبقة 3 لإدراج أجهزة شبكة افتراضية من طرف ثالث (جدران نارية، IDS/IPS) مضمّنةً في تدفّقات الزيارة. الفصل 7. النطاق 1.

**التوجيه الجغرافي (Geolocation routing في Route 53)** — يوجّه بناءً على الموقع الجغرافي لأصل استعلام DNS. الفصل 12. النطاق 3.

**Global Accelerator** — يوجّه الزيارة إلى أقرب حافة AWS عبر Anycast، مُحسِّناً زمن الوصول للتطبيقات الديناميكية. الفصل 25. النطاق 3.

**Glue (AWS)** — ETL بلا خادم. تكتشف Glue Crawlers المخطط؛ وتحوّل Glue Jobs البيانات؛ ويخزّن Data Catalog البيانات الوصفية. الفصل 26. النطاق 3.

**GSI (Global Secondary Index)** — فهرس بديل على جدول DynamoDB بمفتاح تقسيم مختلف ومفتاح فرز اختياري. يُتيح أنماط استعلام مرنة. الفصل 9. النطاق 3.

**GuardDuty** — خدمة كشف تهديدات تستخدم تعلّم الآلة على CloudTrail وVPC Flow Logs وسجلات DNS لكشف النشاط غير المعتاد. الفصل 17. النطاق 1.

## H

**فحص الصحة (Health check في Route 53)** — يراقب توافر نقطة النهاية. فحوصات الصحة الفاشلة تُشغِّل توجيه التحوّل عند الفشل. الفصل 12. النطاق 2.

**التقسيم الساخن (Hot partition في DynamoDB)** — تقسيم يتلقى زيارة غير متناسبة لأن طلبات كثيرة تشترك في مفتاح التقسيم نفسه. الفصل 9. النطاق 3.

## I

**IAM (Identity and Access Management)** — يتحكم في المصادقة والتفويض لحسابات AWS. المستخدمون، المجموعات، الأدوار، السياسات. الفصلان 3، 14. النطاق 1.

**دور IAM (IAM role)** — هوية IAM ببيانات اعتماد مؤقتة، تتولّاها الخدمات أو المستخدمون أو الحسابات الأخرى. الفصلان 3، 14. النطاق 1.

**اللاتباينية (Idempotency)** — خاصية العملية التي تُنتِج النتيجة نفسها سواء استُدعيت مرة أو مرات كثيرة. حاسمة للأنظمة الموزّعة (المبالغ المستردة، المدفوعات، معالجة الطلبات). الفصل 32. عبر النطاقات.

**مفتاح اللاتباينية (Idempotency key)** — مُعرِّف فريد لعملية، يُفحَص قبل التنفيذ لمنع المعالجة المكرّرة. الفصل 32. عبر النطاقات.

**Interface Endpoint (PrivateLink)** — نقطة نهاية VPC لمعظم خدمات AWS. تُسعَّر بالساعة + بالـ GB. توفّر اتصالاً خاصاً دون إنترنت أو NAT. الفصل 30. النطاق 4.

**Internet Gateway (IGW)** — يتيح للنسخ في الشبكات الفرعية العامة التواصل مع الإنترنت. يتطلب أن يكون لجدول توجيه الشبكة الفرعية مسار إلى الـ IGW. الفصل 11. النطاق 3.

**"الأمر يعتمد" ("It depends")** — الإجابة الصادقة لمعظم أسئلة البنية، التي يجب إكمالها دائماً: "الأمر يعتمد على نمط الوصول / المقياس / عاقبة الفشل / قيد التكلفة." الفصل 33. عبر النطاقات.

## K

**Kinesis Data Firehose** — الاسم السابق لـ Amazon Data Firehose: تسليم مُدار للبيانات المتدفّقة إلى S3 وRedshift وOpenSearch. لا إدارة مستهلكين. قد تستخدم أسئلة الاختبار الأقدم الاسم القديم. الفصل 26. النطاق 3.

**Kinesis Data Streams** — تدفّق أحداث مرتّب في الزمن الفعلي. دائم، قابل لإعادة التشغيل ضمن نافذة الاحتفاظ (24 ساعة افتراضياً، حتى 365 يوماً). يُقاس بالتقسيمات. الفصل 26. النطاق 3.

**KMS (Key Management Service)** — يُنشئ المفاتيح التشفيرية ويخزّنها ويتحكم فيها للتشفير في الراحة. الفصل 16. النطاق 1.

## L

**Lambda** — دوال بلا خادم تُشغَّل بالأحداث. الدفع لكل استدعاء ولكل مللي ثانية. مدة أقصى 15 دقيقة. الفصل 20. النطاقات 2، 3، 4.

**Lambda@Edge** — دوال Lambda تعمل في مواقع حافة CloudFront، مُعدِّلةً الطلبات والاستجابات. الفصل 13. النطاق 3.

**AWS Lake Formation** — طبقة تحكم وصول مركزية لبحيرة البيانات فوق S3 وGlue Data Catalog. توفّر صلاحيات دقيقة على مستوى الجدول والعمود والصف. تبسّط إعداد بحيرة بيانات آمنة. الفصل 26. النطاق 3.

**التوجيه القائم على زمن الوصول (Latency-based routing في Route 53)** — يوجّه استعلامات DNS إلى منطقة AWS ذات أدنى زمن وصول مقاس. الفصل 12. النطاق 3.

**قالب الإطلاق (Launch template)** — قالب مُصدَّر يحدد تهيئة نسخة EC2 لمجموعات التوسع التلقائي. الفصل 7. النطاق 3.

**أقل امتياز (Least privilege)** — أفضل ممارسة في IAM: امنح فقط الصلاحيات اللازمة، لا أكثر. الفصل 3. النطاق 1.

**سياسة دورة الحياة (Lifecycle policy في S3)** — قواعد تنقل الكائنات تلقائياً إلى فئات تخزين أرخص أو تحذفها بناءً على العمر. الفصل 23. النطاق 4.

**LSI (Local Secondary Index)** — فهرس بديل على جدول DynamoDB يستخدم مفتاح التقسيم نفسه لكن مفتاح فرز مختلف. يجب إنشاؤه عند إنشاء الجدول. الفصل 9. النطاق 3.

## M

**Amazon Macie** — اكتشاف قائم على تعلّم الآلة للبيانات الحساسة (PII) في S3 وتعليم مخاطر التعرّض. يراقب GuardDuty السلوك؛ ويُدقّق Macie ما هو مُخزَّن. الفصل 17. النطاق 1.

**Memcached** — محرّك تخزين مؤقت بسيط متعدد الخيوط في الذاكرة. لا بقاء، لا هياكل بيانات. استخدم Redis ما لم تحتج تحديداً تعدد الخيوط على حساب الميزات. الفصل 10. النطاق 3.

**Amazon MemoryDB for Redis** — قاعدة بيانات أساسية متينة في الذاكرة متوافقة مع Redis. بخلاف ElastiCache، يكتب MemoryDB إلى سجل معاملات Multi-AZ، ضامناً متانة البيانات. استخدمه حين يُطلَب توافق واجهة Redis البرمجية وفقدان البيانات غير مقبول. الفصل 10. النطاق 3.

**MGN (AWS Application Migration Service)** — إعادة استضافة/رفع وتحويل: تكرار على مستوى الكتلة للخوادم بأكملها إلى AWS، إطلاقات تجريبية، ثم تحوّل إلى نسخ EC2 أصلية. ينقل DataSync الملفات؛ وينقل DMS قواعد البيانات؛ وينقل MGN الخوادم. الفصل 25. النطاق 3.

**Amazon MQ** — وسيط ActiveMQ/RabbitMQ مُدار يتحدث بروتوكولات معيارية (AMQP، MQTT، STOMP). لرفع وتحويل أحمال وسطاء موجودة دون تغييرات في الكود؛ المراسلة من الصفر ← SQS/SNS. الفصل 19. النطاق 2.

**Multi-AZ (RDS)** — نسخة احتياطية متزامنة في منطقة توافر مختلفة مع تحوّل تلقائي عند الفشل. RPO ~0، RTO ~60 ثانية. للتوافر العالي، لا لتوسيع القراءة. الفصلان 8، 18. النطاق 2.

**Multi-Region** — نشر مكوّنات التطبيق عبر مناطق AWS متعددة للتكرار الجغرافي والأداء العالمي. تعقيد وتكلفة أعلى. الفصل 18. النطاق 2.

## N

**Network Load Balancer (NLB)** — موازِن تحميل في الطبقة 4 (TCP/UDP/TLS): ملايين الطلبات في الثانية، عنوان IP ثابت لكل منطقة توافر، يحفظ IP المصدر. لا وعي بـ HTTP — تلك مهمة ALB. الفصل 7. النطاق 3.

**NACL (Network Access Control List)** — جدار ناري عديم الحالة على مستوى الشبكة الفرعية. يتطلب قواعد دخول وخروج معاً. تُقيَّم القواعد بترتيب رقمي. الفصل 15. النطاق 1.

**NAT Gateway** — يتيح للنسخ في الشبكات الفرعية الخاصة إجراء اتصالات صادرة إلى الإنترنت. يُحتسَب بـ 0.045$/GB مُعالَج. الفصلان 11، 30. النطاق 4.

---

## O

**الكائن (Object في S3)** — ملف مخزّن في S3. يتكوّن من مفتاح (اسم)، وقيمة (بيانات)، وبيانات وصفية. أقصى حجم 5 تيرابايت. الفصل 5. النطاق 3.

**السعة عند الطلب (On-Demand capacity في DynamoDB)** — وضع الدفع لكل طلب. أغلى لكل طلب من المُخصَّص، لكن لا حاجة لتخطيط السعة. الفصل 29. النطاق 4.

**النسخ عند الطلب (On-Demand instances في EC2)** — الدفع بالساعة دون التزام. أقصى مرونة، أقصى سعر. الفصل 27. النطاق 4.

**AWS Outposts** — رفّ مُدار بالكامل من عتاد AWS مُثبَّت في مركز بيانات العميل الخاص أو منشأة استضافة مشتركة. يُشغّل خدمات AWS وواجهاتها البرمجية وأدواتها ذاتها كالسحابة العامة في الموقع المحلي. تدير AWS التثبيت والترقيع؛ ويوفّر العميل مساحة الرفّ والطاقة. لإقامة البيانات، أو أحمال العمل المحلية منخفضة زمن الوصول، أو السيناريوهات المنفصلة. الفصل 2. النطاق 4.

---

## P

**مفتاح التقسيم (Partition key في DynamoDB)** — مكوّن المفتاح الأساسي الذي يحدد أي تقسيم يخزّن عنصراً. اختر مفتاحاً عالي التمايز للتوزيع المتساوي. الفصل 9. النطاق 3.

**حدّ الصلاحيات (Permission boundary)** — سياسة IAM تحدد الحد الأقصى للصلاحيات التي يمكن لهوية IAM امتلاكها، حتى لو منحت سياسات أخرى أكثر. الفصل 14. النطاق 1.

**مجموعة الموضع (Placement group)** — تتحكم في الموضع الفيزيائي لنسخ EC2 لتقليل زمن الوصول (cluster) أو زيادة التوافر (spread). الفصل 4. النطاق 3.

**PrivateLink** — خدمة AWS لإنشاء نقاط نهاية خاصة لخدمات مستضافة في AWS، يمكن الوصول إليها عبر Interface Endpoints. الفصل 30. النطاق 1.

**التزامن المُخصَّص (Provisioned concurrency في Lambda)** — بيئات تنفيذ مُهيّأة مسبقاً تُلغي تأخيرات البدء البارد. الفصل 20. النطاق 3.

**السعة المُخصَّصة (Provisioned capacity في DynamoDB)** — إنتاجية قراءة وكتابة مُخصَّصة مسبقاً، تُقاس بوحدات السعة في الثانية. أرخص من عند الطلب للزيارة المتوقَّعة. الفصلان 9، 29. النطاق 4.

---

## Q

**Amazon QuickSight** — خدمة ذكاء أعمال وتصوّر بيانات مُدارة. تستخدم SPICE (محرّك حساب فائق السرعة، متوازٍ، في الذاكرة) لتخزين البيانات مؤقتاً لعرض لوحات معلومات سريع. تتصل بـ Athena وS3 وRedshift وRDS ومصادر بيانات AWS أخرى. لا خادم BI للإدارة. الفصل 26. النطاق 3.

---

## R

**RDS (Relational Database Service)** — قاعدة بيانات علائقية مُدارة. تتولّى النسخ الاحتياطية والترقيع والتحوّل عند الفشل. الفصل 8. النطاق 3.

**RDS Proxy** — يدير مجمع اتصالات بين Lambda/التطبيق وRDS، مانعاً استنزاف الاتصالات. الفصل 8. النطاق 3.

**نسخة القراءة (Read Replica في RDS)** — نسخة غير متزامنة من قاعدة البيانات لتوسيع القراءة. لا توفّر تحوّلاً تلقائياً عند الفشل. الفصلان 8، 24. النطاق 3.

**Redis** — مخزن هياكل بيانات في الذاكرة يُستخدَم للتخزين المؤقت، وإدارة الجلسات، ولوحات الصدارة في الزمن الفعلي، والنشر/الاشتراك. الفصل 10. النطاق 3.

**النسخة المحجوزة (Reserved Instance في EC2)** — التزام باستخدام نوع نسخة محدد في منطقة محددة لمدة سنة أو 3 سنوات مقابل خصم. الفصل 27. النطاق 4.

**Route 53** — خدمة DNS ومُسجِّل نطاقات AWS. تدعم سياسات توجيه متعددة. الفصل 12. النطاقان 2، 3.

**RPO (Recovery Point Objective)** — أقصى فقدان بيانات مقبول مقيساً بالزمن. "كم من البيانات يمكننا تحمّل فقدانه؟" الفصل 18. النطاق 2.

**RTO (Recovery Time Objective)** — أقصى زمن مقبول لاستعادة الخدمة بعد فشل. "كم يمكننا أن نبقى متوقفين؟" الفصل 18. النطاق 2.

**دليل التشغيل (Runbook)** — تعليمات خطوة بخطوة لتشغيل نظام، تحديداً للاستجابة للحوادث. "ماذا يفعل أحدهم في الثالثة فجراً؟" الفصل 32. عبر النطاقات.

---

## S

**S3 Intelligent-Tiering** — ينقل كائنات S3 تلقائياً بين طبقات الوصول بناءً على أنماط الوصول. لا رسوم استرجاع. الفصل 23. النطاق 4.

**S3 Select** — يسترجع مجموعة فرعية من محتوى كائن S3 باستخدام تعبيرات SQL، مقلّلاً نقل البيانات. قديم: غير متاح للعملاء الجدد منذ منتصف 2024 — Athena الآن المسار الأساسي لتصفية البيانات في S3 والاستعلام عنها. S3 Object Lambda، البديل المقترح سابقاً، قديم بذاته (مُغلق أمام العملاء الجدد في نوفمبر 2025؛ تستمر أحمال العمل الموجودة في العمل). الفصل 30. النطاق 4.

**Savings Plan** — نموذج تسعير مرن يلتزم بمبلغ بالدولار من الإنفاق الساعي مقابل خصم. أكثر مرونة من النسخ المحجوزة. الفصل 27. النطاق 4.

**SCP (Service Control Policy)** — سياسة AWS Organizations تقيّد الحد الأقصى للصلاحيات المتاحة للحسابات في وحدة تنظيمية. الفصل 14. النطاق 1.

**Secrets Manager** — يخزّن الأسرار ويدوّرها تلقائياً (كلمات مرور قواعد البيانات، مفاتيح الواجهات البرمجية). الفصل 16. النطاق 1.

**مجموعة الأمان (Security group)** — جدار ناري افتراضي ذو حالة على مستوى النسخة. قواعد سماح فقط؛ زيارة العودة تلقائية. الفصل 15. النطاق 1.

**التقسيم (Shard في Kinesis)** — وحدة الإنتاجية الأساسية في Kinesis Data Streams: 1 MB/s كتابة، 2 MB/s قراءة. الفصل 26. النطاق 3.

**نموذج المسؤولية المشتركة (Shared Responsibility Model)** — AWS مسؤولة عن أمن *السحابة* (البنية التحتية)؛ وأنت مسؤول عن الأمن *في* السحابة (البيانات، التهيئة، الوصول). الفصل 1. النطاق 1.

**Shield** — حماية من DDoS. Standard: مجاني، تلقائي. Advanced: مدفوع، مع دعم DRT وحماية مالية. الفصل 17. النطاق 1.

**Snow Family** — أجهزة فيزيائية لنقل البيانات بالجملة دون اتصال (Snowball Edge: 80 TB) — استئجار رحلة شحن جوية بدل القيادة على الطريق السريع. قديم (2026): أُوقِف Snowmobile وSnowcone؛ وأُغلقت أجهزة Snow أمام العملاء الجدد في نوفمبر 2025 (تشير AWS إلى DataSync وData Transfer Terminals)، لكن لا يزال اختبار SAA-C03 يتوقع Snowball لـ "أسابيع من النقل، عرض نطاق محدود." الفصل 25. النطاق 3.

**SNS (Simple Notification Service)** — مراسلة نشر/اشتراك. يدفع الرسائل إلى كل المشتركين في آنٍ واحد. نمط التوزيع. الفصل 19. النطاق 2.

**مفتاح الفرز (Sort key في DynamoDB)** — المكوّن الثاني الاختياري للمفتاح الأساسي. يُتيح استعلامات النطاق داخل تقسيم. الفصل 9. النطاق 3.

**نسخ Spot (Spot Instances)** — نسخ EC2 تستخدم السعة الاحتياطية بخصم 60–90%. يمكن مقاطعتها بإشعار قبل دقيقتين. لأحمال العمل المتسامحة مع الأعطال فقط. الفصل 27. النطاق 4.

**SQS (Simple Queue Service)** — طابور رسائل مُدار. يفكّ ارتباط المُنتِجين عن المستهلكين. طوابير قياسية (مرة واحدة على الأقل) وFIFO (مرة واحدة بالضبط). الفصل 19. النطاق 2.

**Step Functions** — خدمة تنسيق سير عمل بلا خادم. آلات حالة لتنسيق خدمات AWS. الفصل 22. النطاق 2.

**AWS Storage Gateway** — الجسر بين التخزين المحلي والسحابي: يعرض واجهات NFS/SMB (File)، أو iSCSI (Volume)، أو شريط افتراضي (Tape) محلياً مع حفظ البيانات في S3 أو Glacier أو لقطات EBS. الفصل 6. النطاق 3.

---

## T

**توسع تتبع الهدف (Target tracking scaling)** — سياسة توسع تلقائي تضبط السعة للحفاظ على قيمة مقياس مستهدفة (مثلاً 60% استخدام معالج). الفصل 7. النطاق 2.

**AWS Transfer Family** — نقطة نهاية SFTP/FTPS/FTP مُدارة مدعومة بـ S3 أو EFS. يُبقي الشركاء على عملاء SFTP الحاليين؛ وتصل الملفات مباشرةً إلى دلوك. الفصل 25. النطاق 3.

**Transit Gateway** — طوبولوجيا شبكة محورية شعاعية تربط شبكات VPC متعددة والشبكات المحلية عبر بوابة مركزية. الفصل 25. النطاق 3.

**TTL (Time to Live)** — طابع زمني تحذف DynamoDB بعده عنصراً تلقائياً. يُستخدَم أيضاً في DNS (مدة تخزين المُحلِّلات لسجل) والتخزين المؤقت (مدة صلاحية قيمة مخزّنة مؤقتاً). الفصلان 9، 12. النطاق 3.

---

## V

**VIF (Virtual Interface)** — الاتصال المنطقي المستخدم مع AWS Direct Connect. يصل Public VIF إلى نقاط نهاية AWS العامة؛ ويصل Private VIF إلى موارد VPC. الفصل 25. النطاق 3.

**مهلة الرؤية (Visibility timeout في SQS)** — الفترة التي تكون فيها الرسالة المُستلَمة مخفية عن المستهلكين الآخرين. تتيح المعالجة دون رؤية مستهلكين آخرين للرسالة نفسها. الفصل 19. النطاق 2.

**VPC (Virtual Private Cloud)** — شبكة افتراضية معزولة في AWS. تحوي شبكات فرعية وجداول توجيه وبوابات. الفصل 11. النطاق 1.

**VPC Endpoint** — يربط موارد VPC بخدمات AWS عبر شبكة AWS الخاصة. Gateway (مجاني، S3/DynamoDB) وInterface (مُسعَّر، معظم الخدمات الأخرى). الفصل 30. النطاقان 1، 4.

**VPC Flow Logs** — يلتقط معلومات عن زيارة IP الواردة والصادرة من واجهات الشبكة في VPC. يستخدمها GuardDuty ولاستكشاف أخطاء الشبكة. الفصل 17. النطاق 1.

**VPC Peering** — اتصال شبكي بين شبكتي VPC يُتيح توجيه الزيارة بينهما باستخدام عناوين IP خاصة. الفصل 11. النطاق 3.

---

## W

**WAF (Web Application Firewall)** — يصفّي زيارة HTTP/HTTPS باستخدام قواعد (حظر IP، حقن SQL، حدود معدل). يرتبط بـ CloudFront أو ALB أو API Gateway. الفصل 17. النطاق 1.

**AWS Wavelength** — بنية AWS التحتية المنشورة داخل شبكات مزوّدي اتصالات 5G عند حافة الراديو. تُتيح زمن وصول بالمللي ثانية أحادية الرقم إلى الأجهزة المحمولة. لـ AR/VR المحمول، وألعاب الزمن الفعلي، وقياسات بُعد المركبات الذاتية القيادة، والفيديو الحي عند حافة 5G. مناطق Wavelength امتدادات لمناطق AWS داخل شبكات الاتصالات. الفصل 2. النطاق 3.

**إطار Well-Architected (Well-Architected Framework)** — إطار التقييم سداسي الركائز من AWS: التميّز التشغيلي، الأمن، الموثوقية، كفاءة الأداء، تحسين التكلفة، الاستدامة. الفصل 31. عبر النطاقات.

**التوجيه الموزون (Weighted routing في Route 53)** — يوزّع استعلامات DNS عبر نقاط النهاية بالوزن. يُستخدَم للنشر الأزرق-الأخضر واختبار A/B. الفصل 12. النطاق 3.

**التخزين المؤقت بالكتابة المباشرة (Write-through caching)** — يحدّث ذاكرة التخزين المؤقت كلما حُدِّثت قاعدة البيانات. البيانات متسقة دائماً لكن قد تحمل ذاكرة التخزين المؤقت عناصر كثيرة لا تُقرأ أبداً مجدداً. الفصل 10. النطاق 3.
