**ثلاث فئات من التهديدات**

تقع التهديدات الأمنية ضد التطبيقات السحابية عموماً في ثلاث فئات:

**هجمات الحجم (DDoS)**: يُرسل مهاجم حركة مرور هائلة حتى لا يتمكن تطبيقك من الاستجابة للمستخدمين الشرعيين. قد يكون الهجوم ملايين طلبات HTTP، أو فيضان من حزم SYN مصمَّمة لاستنفاد جدول اتصالات خادمك.

**هجمات التطبيق (الاستغلال)**: يُرسل مهاجم طلبات مُعدَّة خصيصاً لاستغلال نقاط ضعف في تطبيقك — حقن SQL، سكريبت عبر المواقع، إدخال مشوَّه يُعطّل محلّلاً.

**الشذوذات السلوكية (الاستكشاف والاختراق)**: استدعاءات API لا ينبغي أن تحدث (شخص يستعلم قاعدة مستخدميك كاملة الساعة 3 صباحاً)، نشاط IAM غير عادي (بيانات اعتماد تُستخدم من دولة جديدة)، أو حركة شبكة لوجهات غير متوقعة.

لدى AWS خدمة مخصصة لكل منها:

- **AWS Shield**: حماية من DDoS
- **AWS WAF**: حماية طبقة التطبيق
- **Amazon GuardDuty**: كشف التهديدات السلوكية

**AWS Shield: ماصّ DDoS**

**AWS Shield Standard** مُفعَّل تلقائياً لجميع عملاء AWS بدون رسوم إضافية. يحمي من هجمات DDoS الطبقة 3 (الشبكة) والطبقة 4 (النقل) الأكثر شيوعاً — فيضانات SYN، فيضانات UDP، هجمات تضخيم DNS.

CloudFront وRoute 53 وElastic Load Balancing تقع على حافة شبكة AWS. حين يستهدف هجوم DDoS تطبيقك، يضرب هذه الخدمات المُدارة أولاً. البنية التحتية لشبكة AWS تمتصّ الهجوم قبل وصوله إلى نسخ EC2 الخاصة بك.

**AWS Shield Advanced** هو الطبقة المميزة (3,000 دولار/شهر لكل منظمة). تضيف:

- حماية لـ EC2 وELB وCloudFront وGlobal Accelerator وRoute 53
- إشعارات هجمات شبه آنية
- وصول إلى فريق AWS Shield Response (SRT) — مهندسو أمن يمكنهم مساعدتك في الاستجابة للهجمات
- حماية التكلفة: إذا تسبّب هجوم في ارتفاع فاتورتك، تُضيف AWS رصيداً لتكاليف الارتفاع
- كشف وتخفيف DDoS محسّن على الطبقة 7 (طبقة التطبيق)

**AWS WAF: مرشّح التطبيق**

يعمل **AWS WAF (جدار حماية تطبيقات الويب)** على مستوى HTTP — يفحص محتوى طلبات الويب قبل وصولها إلى تطبيقك.

يُضبط WAF بـ **قوائم تحكم الويب في الوصول (Web ACLs)** — مجموعات قواعد تُحدد ما يُسمح به أو يُحجب أو يُعدّ.

يمكن إرفاق WAF بـ:

- توزيعات CloudFront (فحص الطلبات في الحافة، عالمياً)
- Application Load Balancers (فحص الطلبات على المستوى الإقليمي)
- API Gateway
- AWS AppSync

**قواعد WAF المُدارة**: تنشر AWS وبائعون خارجيون مجموعات قواعد جاهزة:

- **قواعد AWS المُدارة - مجموعة القواعد الأساسية**: تحمي من ثغرات OWASP Top 10 (حقن SQL، XSS، حقن الأوامر، اجتياز المسار، إلخ)
- **قواعد AWS المُدارة - المدخلات السيئة المعروفة**: تحجب الطلبات المطابقة لأنماط هجوم معروفة
- **قواعد AWS المُدارة - قائمة سمعة IP الخاصة بـ Amazon**: تحجب IPs المرتبطة بشبكات روبوتات ومحركات فحص
- **قواعد AWS المُدارة - التحكم في الروبوتات**: تُحدد حركة الروبوتات وتُديرها

يمكنك أيضاً إنشاء قواعد مخصصة:

- "احجب أي طلب يحتوي User-Agent على 'sqlmap'" (ماسح حقن SQL شائع)
- "تحديد المعدل: لا تسمح بأكثر من 1000 طلب لكل IP كل 5 دقائق"
- "احجب الطلبات التي تحتوي `<script>` في أي قيمة معامل"

بالنسبة لـ Nimbus، الإعداد العملي: WAF على توزيع CloudFront مع تفعيل مجموعة القواعد الأساسية. هذا يحجب أكثر أنماط الهجوم شيوعاً قبل وصول الطلبات إلى نسخ EC2.

**Amazon GuardDuty: المحلل السلوكي**

GuardDuty مختلف جوهرياً عن Shield وWAF. لا يحجب الهجمات — يـ**كشف السلوك غير العادي**.

تُحلّل GuardDuty باستمرار:

- **سجلات AWS CloudTrail**: تغييرات IAM، استدعاءات API، تسجيلات الدخول للوحة التحكم
- **سجلات تدفق VPC**: أنماط حركة الشبكة داخل VPC
- **سجلات استعلامات DNS**: ما الذي تحلّه نسخك (البرمجيات الخبيثة تحلّ كثيراً نطاقات C2 محددة)

نماذج تعلم الآلة تُحدد الأنماط التي تنحرف عن خطّك الأساسي. تُنشئ GuardDuty **نتائج** — تنبيهات مُصنَّفة — عند اكتشاف شذوذات.

أمثلة على ما يمكن لـ GuardDuty كشفه:

- مستخدم IAM يسجّل دخولاً من عنوان IP غير معروف (في بلد لم يستخدمه من قبل)
- استدعاءات API تُجرى من عقدة خروج Tor
- نسخة EC2 تتواصل مع تجمّع تعدين عملة مشفّرة معروف
- حجم استدعاء API مرتفع بشكل غير عادي (إساءة استخدام بيانات اعتماد أو فحص)
- وصول إلى دلو S3 من عنوان IP مُبلَّغ عنه لنشاط خبيث
- حركة صادرة إلى نطاق معروف بارتباطه ببرمجيات خبيثة لأوامر والتحكم

قال Leo بهدوء: "هذا ما كان سيكتشف IP الروماني."

أكدت Priya: "لو كانت GuardDuty مُفعَّلة، كانت ستُعلّم على نسخة EC2 التي تُجري اتصالات صادرة إلى IP خارجي غير معروف الساعة 2 صباحاً."

"كم تكلف؟"

تسعير GuardDuty مبني على حجم السجلات المُحلَّلة — أحداث CloudTrail، بيانات تدفق VPC، استعلامات DNS. لتطبيق صغير إلى متوسط، عادةً 50-150 دولار/شهر. على نطاق واسع، لا تزال جزءاً صغيراً من تكاليف البنية التحتية.

**ربط الخدمات الثلاث**

Shield وWAF وGuardDuty تعمل على طبقات مختلفة وتُكمل بعضها:

| الخدمة | الطبقة | تحمي من | الإجراء |
|--------|---------|---------|---------|
| AWS Shield | الشبكة/النقل (L3/L4) | فيضانات DDoS | تمتصّ/تخفّف الهجمات |
| AWS WAF | التطبيق (L7) | OWASP Top 10، روبوتات، كاشطات | تسمح أو تحجب أو تعدّ الطلبات |
| GuardDuty | السلوكي (جميع السجلات) | الشذوذات، بيانات الاعتماد المخترقة، البرمجيات الخبيثة | تكتشف وتُنبّه |

Shield يوقف الفيضان. WAF يُرشّح الماء. GuardDuty يراقب السباكة للأنماط غير العادية.

**CloudTrail: الأساس**

تعتمد جميع الخدمات الثلاث على السجلات. **AWS CloudTrail** هي خدمة التسجيل التي تلتقط كل استدعاء API في حسابك على AWS — من استدعاها، من أين، متى، وما النتيجة.

CloudTrail مُفعَّلة افتراضياً لسجل 90 يوماً في لوحة التحكم. للاحتفاظ بالسجلات على المدى الطويل:

1. إنشاء مسار يكتب إلى دلو S3
2. اختيارياً، الإرسال إلى سجلات CloudWatch للتنبيه الفوري
3. تفعيل التحقق من ملف السجل (للكشف عن التلاعب بالسجلات)

GuardDuty وAWS Config وSecurity Hub يقرأون جميعاً من CloudTrail. بدون سجلات CloudTrail، هذه الخدمات ليس لديها ما تُحلّله.

**AWS Security Hub: لوحة التحكم**

إذا كنت تُشغّل حسابات AWS متعددة أو تحتاج إلى رؤية موحّدة للنتائج الأمنية، تُجمّع **AWS Security Hub** النتائج من GuardDuty وInspector (تقييم الثغرات) وMacie (خصوصية البيانات) وConfig وFirewall Manager في لوحة تحكم واحدة.

كما يتحقق من تكوينك مقابل أفضل ممارسات الأمان (معيار AWS Foundational Security Best Practices) ومعيار CIS AWS Foundations Benchmark.

بالنسبة لـ Nimbus: لم يكن Security Hub ضرورياً بعد. حين ينمو إلى ثلاثة حسابات (تطوير، تجريب، إنتاج)، سيصبح مفيداً.

## نقاط القوة والقيود

**AWS Shield**:

- Standard: مجاني وتلقائي — لا سبب لعدم استخدامه
- Advanced: ممتاز للأهداف عالية الملف الشخصي؛ مكلف للفرق الصغيرة

**AWS WAF**:

- مجموعات القواعد المُدارة تُبسّط الإعداد بشكل كبير
- القواعد المخصصة تتطلب فهم أنماط هجوم HTTP
- تحديد المعدل ميزة قوية كثيراً ما تُهمَل
- WAF ليس بديلاً لكود تطبيق آمن — إنه طبقة دفاع معمّق

**GuardDuty**:

- جهد منخفض جداً للتفعيل (بضع نقرات)
- النتائج تتطلب مراجعة بشرية وإجابة — GuardDuty تكتشف، لا تُصلح
- تحدث إيجابيات زائفة — بعض النشاط المشروع يبدو شاذاً لنماذج ML
- تجربة مجانية 30 يوماً — يستحق التفعيل فوراً

## الملخص

- **AWS Shield Standard**: حماية مجانية وتلقائية من DDoS في الطبقة 3/4. دائماً مُفعَّلة.
- **AWS Shield Advanced**: حماية DDoS مميزة مع وصول SRT وحماية التكلفة. حالة استخدام المؤسسات.
- **AWS WAF**: جدار حماية طبقة التطبيق. فحص وترشيح طلبات HTTP. الإرفاق بـ CloudFront أو ALB أو API Gateway. استخدام مجموعات القواعد المُدارة لحماية OWASP Top 10.
- **Amazon GuardDuty**: كشف التهديدات السلوكية. تُحلّل CloudTrail وسجلات تدفق VPC وسجلات DNS. تُنشئ نتائج للنشاط الشاذ.
- **CloudTrail**: أساس جميع تسجيل أمان AWS. فعّل مساراً يكتب إلى S3 للاحتفاظ على المدى الطويل.
- هذه الخدمات تُكمل بعضها: Shield في الطبقة الشبكية، WAF في طبقة التطبيق، GuardDuty في الطبقة السلوكية.

## نصائح الاختبار

*SAA-C03 المجال: تصميم معماريات آمنة (المجال الأول، المهمة 1.2)*

- **Shield Standard مقابل Advanced**: Standard مجاني وتلقائي. Advanced يكلف مالاً ويضيف SRT وحماية التكلفة وكشفاً أفضل. إشارات الاختبار لـ Advanced: "DDoS واسع النطاق"، "ضمان SLA أثناء الهجمات"، "الحماية المالية من ارتفاع تكاليف DDoS."
- **إشارات حالة استخدام WAF**: "حجب حقن SQL"، "حجب سكريبت عبر المواقع"، "تحديد معدل استدعاءات API"، "حجب عوامل مستخدم محددة"، "حماية OWASP Top 10" ← WAF.
- **إشارات GuardDuty**: "كشف نشاط API غير عادي"، "تحديد بيانات اعتماد مخترقة"، "الإبلاغ عن اتصالات EC2 الشبكية الشاذة"، "معلومات التهديد" ← GuardDuty.
- **إرفاق WAF**: يمكن إرفاقه بـ CloudFront (عالمي)، ALB (إقليمي)، API Gateway (إقليمي)، AppSync.
- **مصادر بيانات GuardDuty**: أحداث إدارة CloudTrail، أحداث بيانات S3 في CloudTrail، سجلات تدفق VPC، سجلات DNS. قد يسأل الاختبار أي مصدر بيانات ذو صلة بسيناريو كشف محدد.
- **Macie**: كثيراً ما يُخلط بينها وبين GuardDuty. **Macie** تستخدم ML لكشف البيانات الحساسة في S3 (المعلومات الشخصية، بيانات الاعتماد، البيانات المالية). **GuardDuty** تكتشف التهديدات والشذوذات في السلوك. حالات استخدام مختلفة.

*(تلميح: فكّر في WAF كمرشّح على الطلبات الواردة، وGuardDuty كمحلل سلوكي يراقب سجلاتك.)*

**تمرين 2 — تدريب على الاختبار**

*سيناريو*: موقع شركة تجزئة يتعرض لهجوم من شبكة روبوتات ترسل ملايين الطلبات في الساعة إلى API البحث عن المنتجات. تبدو الطلبات مشروعة (سلاسل User-Agent صالحة، كوكيز جلسة صالحة) لكنها لا تُفضي إلى مشتريات — إنها تكشط أسعار المنتجات. الهجوم يُسبّب تجربة استجابة بطيئة للعملاء الشرعيين.

أي مجموعة خدمات تعالج هذا التهديد على أفضل وجه؟

أ) AWS Shield Advanced وCloudFront  
ب) AWS WAF بقواعد تحديد المعدل وCloudFront  
ج) Amazon GuardDuty وAWS Shield Standard  
د) NACLs تحجب نطاقات IP لشبكة الروبوتات

**تلميح 1**: الطلبات على مستوى HTTP (طبقة التطبيق). أي خدمة تعمل على طبقة HTTP؟

**تلميح 2**: تستخدم شبكات الروبوتات عناوين IP مختلفة كثيرة — حجب نطاقات IP محددة في NACL غير فعّال ضد شبكات روبوتات كبيرة.

**تلميح 3**: تحديد المعدل بحسب عنوان IP يمكنه إبطاء الكشط حتى لو لم تتمكن من حجبه كلياً.

**الإجابة**: ب

**الشرح**: يمكن لـ AWS WAF تحديد معدل الطلبات لكل عنوان IP، مما يُقلل تأثير الكشط الكبير الحجم من أي مصدر واحد. CloudFront توزّع الزيارات الواردة عبر شبكة حافة AWS، تمتصّ الحجم وتحمي الأصل. يمكن لقواعد WAF أيضاً مطابقة أنماط الطلبات (طلبات متسلسلة سريعة لنفس نقطة نهاية API) للتعرف على سلوك الكشط.

**لماذا ليس أ؟** Shield Advanced يحمي من فيضانات DDoS (الطبقة 3/4). السيناريو يصف كشطاً على مستوى التطبيق (طلبات HTTP الطبقة 7)، التي لا يفحصها Shield.

**لماذا ليس ج؟** تكتشف GuardDuty الشذوذات في سلوك حسابك على AWS — لا تحجب طلبات HTTP الواردة. Shield Standard لا يتعامل مع هجمات طبقة التطبيق.

**لماذا ليس د؟** تستخدم شبكات الروبوتات الكبيرة آلاف عناوين IP من مصادر موزّعة. حجب نطاقات محددة نهج لا جدوى منه ضد شبكات الروبوتات المتطورة.

*SAA-C03 المجال: تصميم معماريات آمنة — المهمة 1.2*

**تمرين 3 — تحدي المعمارية** *(اختياري)*

Nimbus تفكّر في نموذج تهديدها استعداداً للتعامل مع بيانات بطاقات الائتمان. تراجع امتثال PCI-DSS يتطلب:

- الحماية من هجمات DDoS على طبقة الشبكة
- ترشيح طبقة التطبيق للاستغلالات المعروفة على الويب
- تسجيل جميع استدعاءات API في مخزن مقاوم للتلاعب طويل الأمد
- كشف أنماط وصول غير عادية لخدمة الدفع

عيّن كل متطلب إلى خدمة AWS محددة أو تكوين. هل Shield Standard كافٍ، أم يُشير سياق PCI-DSS إلى Advanced؟ أين ستُرفق WAF؟

*(لا توجد إجابة صحيحة واحدة. الهدف التدرب على تعيين متطلبات الامتثال إلى خدمات AWS.)*
