# 附录 C：概念注册表

本书中介绍的每个关键概念，映射到其章节、所用类比以及出现的 SAA-C03 领域。

将此用作学习索引：如果考试前你对某个概念感到模糊，在这里找到它，然后返回其章节查看背景。

---

## A

**ACM（AWS Certificate Manager）** — 为 ALB、CloudFront 和 API Gateway 提供免费的公有 TLS 证书，通过 DNS 验证自动续期。CloudFront 使用的证书必须位于 us-east-1。第 16 章。领域 1。

**ACU（Aurora 容量单位）** — Aurora Serverless v2 容量的度量单位。自动扩展，并且在受支持的引擎版本上，当没有连接保持打开时可以自动暂停到 0 ACU。第 24 章。领域 3。

**警报（CloudWatch）** — 当指标超过阈值时触发的规则，会触发通知或自动扩展操作。第 7 章。领域 2。

**ALB（Application Load Balancer）** — 第 7 层负载均衡器，根据路径和主机规则路由 HTTP/HTTPS 流量。第 7 章。领域 2。

**AMI（Amazon Machine Image）** — 包含 EC2 实例的操作系统、软件和配置的模板。第 4 章。领域 3。

**架构师思维** — 问"什么会最先崩溃，我们如何得知，凌晨 3 点该有人做什么？"而不只是"这是怎么工作的？"第 32 章、第 34 章。跨领域。

**架构决策记录（ADR）** — 记录一项决策、其备选方案、理由以及什么情况会导致重新考虑的简短文档。第 32 章。跨领域。

**架构评审** — 涵盖以下内容的结构化流程：约束 → 未知数 → 选项 → 失效模式 → 监控 → 操作手册。第 32 章。跨领域。

**Athena** — 针对 S3 数据的无服务器 SQL 查询服务。按扫描的 TB 计费。最适合 Parquet/ORC 列式格式。第 26 章。领域 3。

**Auto Scaling Group（ASG）** — 一组统一管理的 EC2 实例，自动替换不健康的实例并根据负载扩展。第 7 章。领域 2、3。

**可用区（AZ）** — 区域内一个或多个物理上分离的数据中心，通过低延迟链路连接。第 2 章。领域 2。

---

## B

**AWS Backup** — 跨 EBS、RDS、DynamoDB、EFS 和 Storage Gateway 的集中式、基于策略的备份。支持跨区域和跨账户副本。第 18、23 章。领域 2。

**AWS Batch** — 面向 Docker 容器的托管批量计算。由作业定义（运行什么）、作业队列（作业在哪里等待）和计算环境（EC2 或 Fargate、按需或竞价）组成。适用于超过 Lambda 15 分钟限制的工作负载。第 21 章。领域 3。

**桶（S3）** — S3 对象的容器。桶具有全局唯一名称，位于特定区域。第 5 章。领域 3。

**桶策略** — 附加到 S3 桶的基于资源的策略，控制 IAM 主体和外部账户的访问。第 5 章。领域 1。

---

## C

**Cache-aside 模式** — 应用程序先检查缓存；未命中时查询数据库，然后将结果存入缓存。第 10 章。领域 3。

**缓存命中率** — 由缓存而非源站提供服务的请求百分比。越高越好。第 13 章。领域 3。

**AWS Client VPN** — 托管的 OpenVPN 端点。将单个设备（笔记本电脑、工作站）通过互联网连接到 VPC。通过 Active Directory、与身份提供商的 SAML 2.0 联合或双向 TLS 进行身份验证。支持分割隧道和全隧道模式。对比 Site-to-Site VPN（网络到网络）。第 11 章。领域 1。

**CloudFront** — AWS 的 CDN。在全球 750 多个边缘位置缓存内容。降低延迟和源站数据传输成本。第 13 章。领域 3、4。

**CloudTrail** — 记录每个 AWS API 调用：谁、做了什么、何时、从哪里。存储在 S3 中。用于审计和事故调查。领域 1。

**CloudWatch** — AWS 资源和自定义应用程序的指标、日志、警报和仪表板。全书引用。所有领域。

**Amazon Cognito** — 面向你的应用程序最终用户的身份验证：User Pools 是托管的用户目录（注册、登录、MFA、社交登录、JWT）；Identity Pools 颁发临时 AWS 凭证。IAM 面向你的工程师；Cognito 面向你的客户。第 14 章。领域 1。

**冷启动（Lambda）** — 首次调用（或长时间不活动后）时，Lambda 初始化执行环境产生的延迟。使用预置并发来消除。第 20 章。领域 3。

**Compute Savings Plan** — 承诺每小时 EC2 支出的特定金额，适用于任何实例类型或规格。第 27 章。领域 4。

**Config（AWS）** — 随时间追踪 AWS 资源的配置变更，并根据规则评估合规性。第 31 章。领域 1。

**AWS Control Tower** — 自动化多账户治理：在几分钟内构建带护栏的着陆区（管理、日志归档和审计账户）——相当于手动配置 Organizations、CloudTrail 和 Config 的"预制板"版本。第 14 章。领域 1。

**跨 AZ 数据传输** — 同一区域内可用区之间的流量。每个方向按 $0.01/GB 收费。第 30 章。领域 4。

**跨区域复制** — 将数据（S3 CRR、Aurora Global、DynamoDB Global Tables）复制到不同区域。产生数据传输费用。第 18、23、30 章。领域 2。

---

## D

**AWS DataSync** — 基于代理的文件共享（NFS/SMB）迁移和同步，目标为 S3、EFS 或 FSx。"加强版 rsync，外加一个 AWS 控制台。"第 25 章。领域 3。

**DAX（DynamoDB Accelerator）** — 专为 DynamoDB 设计的内存缓存。微秒级读取延迟。第 9 章。领域 3。

**死信队列（DLQ）** — 反复处理失败的消息被发送到的队列，防止队列阻塞。第 19 章。领域 2。

**AWS DMS（Database Migration Service）** — 以最小停机时间将数据库迁移到 AWS。全量加载（初始复制）加 CDC（变更数据捕获），在迁移期间保持源和目标同步。同构迁移（相同引擎类型）：直接使用 DMS。异构迁移（不同引擎类型，如 Oracle → Aurora PostgreSQL）：先使用 SCT（Schema Conversion Tool），再用 DMS。第 8 章。领域 3。

**专用主机** — 专供你使用的物理 EC2 服务器。某些软件许可证需要。第 27 章。领域 4。

**纵深防御** — 分层多个安全控制（IAM + 安全组 + NACL + WAF + GuardDuty），使单层被攻破不会暴露整个系统。第 33 章。领域 1。

**Direct Connect** — 从本地位置到 AWS 的专用私有网络连接。比 VPN 更稳定。第 25 章。领域 3。

**DLQ** — 参见死信队列。

**DynamoDB** — 完全托管的 NoSQL 数据库，在任意规模下提供个位数毫秒级延迟。键值和文档模型。第 9 章。领域 3。

**DynamoDB Auto Scaling** — 根据 CloudWatch 指标自动调整预置读/写容量。第 29 章。领域 4。

**DynamoDB Streams** — DynamoDB 表中所有项目变更的按时间排序的变更日志。与 Lambda 配合用于事件驱动处理。第 9 章。领域 2。

---

## E

**EBS（Elastic Block Store）** — 附加到单个 EC2 实例的块存储。独立持久。类型：gp3、io2、st1。第 6 章。领域 3。

**EC2（Elastic Compute Cloud）** — 云中的虚拟机。第 4 章。领域 3。

**ECS（Elastic Container Service）** — 托管容器编排。Fargate 启动类型免除了服务器管理。第 21 章。领域 2、3。

**EFS（Elastic File System）** — 可从多个 EC2 实例访问的共享 NFS 文件系统。自动扩展。存储类包括 Standard、Infrequent Access 和 Archive，并提供 Intelligent-Tiering 在层之间自动移动文件。第 6 章。领域 3。

**EKS（Elastic Kubernetes Service）** — AWS 上的托管 Kubernetes 控制平面。第 21 章。领域 3。

**Elastic Disaster Recovery（DRS）** — 将服务器（本地或 EC2）持续逐块复制到低成本暂存区，并在几分钟内启动恢复实例——一个托管的 pilot light。第 18 章。领域 2。

**ElastiCache** — 托管的内存缓存。Redis（功能更丰富）或 Memcached（更简单）。第 10 章。领域 3。

**弹性 IP** — 可以分配并重新关联到 EC2 实例的静态公有 IP 地址。第 11 章。领域 3。

**信封加密** — 数据用数据密钥（DEK）加密、DEK 用主密钥（KMS 中的 CMK）加密的模式。第 16 章。领域 1。

**EventBridge** — 将来自 AWS 服务、SaaS 合作伙伴和自定义来源的事件路由到目标的事件总线。支持计划规则。第 22 章。领域 2。

**明确拒绝** — 无法被任何允许覆盖的 IAM 拒绝声明。优先于所有允许。第 3 章。领域 1。

---

## F

**故障转移路由（Route 53）** — 当主端点健康检查失败时，将流量路由到次要端点。第 12 章。领域 2。

**Fargate** — ECS 和 EKS 的无服务器计算引擎。无需管理 EC2 实例。第 21 章。领域 3。

**扇出模式** — 一个 SNS 主题同时向多个 SQS 队列传递相同的消息。第 19 章。领域 2。

**FIFO 队列（SQS）** — 恰好一次处理，严格顺序。吞吐量低于标准队列。第 19 章。领域 2。

**失效模式** — 系统可能失败的特定方式。在上线前识别失效模式是架构评审的核心。第 32 章。跨领域。

---

## G

**网关终端节点** — 免费的 VPC 终端节点类型，用于 S3 和 DynamoDB。流量通过 AWS 私有网络路由，消除 NAT Gateway 费用。第 30 章。领域 4。

**Gateway Load Balancer（GWLB）** — 第 3 层负载均衡器，用于将第三方虚拟网络设备（防火墙、IDS/IPS）内联插入到流量路径中。第 7 章。领域 1。

**地理位置路由（Route 53）** — 根据 DNS 查询来源的地理位置路由。第 12 章。领域 3。

**Global Accelerator** — 通过 Anycast 将流量路由到最近的 AWS 边缘，改善动态应用程序的延迟。第 25 章。领域 3。

**Glue（AWS）** — 无服务器 ETL。Glue 爬虫发现模式；Glue 作业转换数据；Data Catalog 存储元数据。第 26 章。领域 3。

**GSI（全局二级索引）** — DynamoDB 表上具有不同分区键和可选排序键的备用索引。支持灵活的查询模式。第 9 章。领域 3。

**GuardDuty** — 威胁检测服务，使用机器学习对 CloudTrail、VPC Flow Logs 和 DNS 日志进行分析以检测异常活动。第 17 章。领域 1。

---

## H

**健康检查（Route 53）** — 监控端点可用性。健康检查失败触发故障转移路由。第 12 章。领域 2。

**热分区（DynamoDB）** — 由于许多请求共享同一个分区键而接收不成比例流量的分区。第 9 章。领域 3。

---

## I

**IAM（Identity and Access Management）** — 控制 AWS 账户的身份验证和授权。用户、组、角色、策略。第 3、14 章。领域 1。

**IAM 角色** — 具有临时凭证的 IAM 身份，由服务、用户或其他账户代入。第 3、14 章。领域 1。

**幂等性** — 操作无论被调用一次还是多次都产生相同结果的属性。对分布式系统（退款、支付、订单处理）至关重要。第 32 章。跨领域。

**幂等性密钥** — 操作的唯一标识符，在执行前检查以防止重复处理。第 32 章。跨领域。

**接口终端节点（PrivateLink）** — 适用于大多数 AWS 服务的 VPC 终端节点。按小时 + 按 GB 计费。提供无需互联网或 NAT 的私有连接。第 30 章。领域 4。

**Internet Gateway（IGW）** — 允许公有子网中的实例与互联网通信。要求子网的路由表中有一条指向 IGW 的路由。第 11 章。领域 3。

**"视情况而定"** — 大多数架构问题的诚实答案，但必须始终补全："这取决于访问模式/规模/失败后果/成本约束。"第 33 章。跨领域。

---

## K

**Kinesis Data Firehose** — Amazon Data Firehose 的旧名称：将流数据托管传递到 S3、Redshift、OpenSearch。无需管理消费者。较旧的考题可能仍使用旧名称。第 26 章。领域 3。

**Kinesis Data Streams** — 实时有序事件流。持久，可在保留窗口内重播（默认 24 小时，最长 365 天）。以分片为单位衡量。第 26 章。领域 3。

**KMS（Key Management Service）** — 为静态加密创建、存储和控制加密密钥。第 16 章。领域 1。

---

## L

**Lambda** — 由事件触发的无服务器函数。按调用次数和每毫秒付费。最长 15 分钟持续时间。第 20 章。领域 2、3、4。

**Lambda@Edge** — 在 CloudFront 边缘位置运行的 Lambda 函数，修改请求和响应。第 13 章。领域 3。

**AWS Lake Formation** — 构建在 S3 和 Glue Data Catalog 之上的集中式数据湖访问控制层。提供表、列和行级别的细粒度权限。简化安全数据湖的搭建。第 26 章。领域 3。

**基于延迟的路由（Route 53）** — 将 DNS 查询路由到实测延迟最低的 AWS 区域。第 12 章。领域 3。

**启动模板** — 为 Auto Scaling Groups 指定 EC2 实例配置的版本化模板。第 7 章。领域 3。

**最小权限** — IAM 最佳实践：只授予所需的权限，不多授。第 3 章。领域 1。

**生命周期策略（S3）** — 根据对象使用时长自动将其转换到更便宜的存储类或删除的规则。第 23 章。领域 4。

**LSI（本地二级索引）** — DynamoDB 表上使用相同分区键但不同排序键的备用索引。必须在创建表时创建。第 9 章。领域 3。

---

## M

**Amazon Macie** — 基于机器学习发现 S3 中的敏感数据（PII）并标记暴露风险。GuardDuty 监视行为；Macie 审计存储的内容。第 17 章。领域 1。

**Memcached** — 简单的多线程内存缓存引擎。无持久化，无数据结构。除非你特别需要以功能换多线程，否则使用 Redis。第 10 章。领域 3。

**Amazon MemoryDB for Redis** — 持久的、Redis 兼容的内存主数据库。与 ElastiCache 不同，MemoryDB 写入 Multi-AZ 事务日志，保证数据持久性。在需要 Redis API 兼容性且不可接受数据丢失时使用。第 10 章。领域 3。

**MGN（AWS Application Migration Service）** — 重新托管/直接迁移：将整台服务器块级复制到 AWS，测试启动，然后切换为原生 EC2 实例。DataSync 迁移文件；DMS 迁移数据库；MGN 迁移服务器。第 25 章。领域 3。

**Amazon MQ** — 托管的 ActiveMQ/RabbitMQ 代理，支持标准协议（AMQP、MQTT、STOMP）。用于在不修改代码的情况下直接迁移现有的消息代理工作负载；全新的消息传递 → SQS/SNS。第 19 章。领域 2。

**Multi-AZ（RDS）** — 位于不同 AZ 中的同步备用副本，具有自动故障转移。RPO 约为 0，RTO 约为 60 秒。用于高可用性，而非读取扩展。第 8、18 章。领域 2。

**Multi-Region** — 跨多个 AWS 区域部署应用程序组件，以实现地理冗余和全球性能。复杂性和成本更高。第 18 章。领域 2。

---

## N

**Network Load Balancer（NLB）** — 第 4 层（TCP/UDP/TLS）负载均衡器：每秒数百万请求，每个 AZ 有静态 IP，保留源 IP。不感知 HTTP——那是 ALB 的工作。第 7 章。领域 3。

**NACL（网络访问控制列表）** — 子网级别的无状态防火墙。需要入站和出站规则。规则按数字顺序评估。第 15 章。领域 1。

**NAT Gateway** — 允许私有子网中的实例向互联网建立出站连接。按处理的流量收取 $0.045/GB。第 11、30 章。领域 4。

---

## O

**对象（S3）** — 存储在 S3 中的文件。由键（名称）、值（数据）和元数据组成。最大 5TB。第 5 章。领域 3。

**按需容量（DynamoDB）** — 按请求付费模式。每次请求比预置模式贵，但无需容量规划。第 29 章。领域 4。

**按需实例（EC2）** — 按小时付费，无承诺。最大灵活性，最高价格。第 27 章。领域 4。

**AWS Outposts** — 安装在客户自己的数据中心或托管设施中的、完全托管的 AWS 硬件机架。在本地运行与公有云相同的 AWS 服务、API 和工具。AWS 负责安装和打补丁；客户提供机架空间和电力。适用于数据驻留、低延迟本地工作负载或断连场景。第 2 章。领域 4。

---

## P

**分区键（DynamoDB）** — 决定项目存储在哪个分区的主键组件。选择高基数键以实现均匀分布。第 9 章。领域 3。

**权限边界** — 设置 IAM 身份可拥有的最大权限的 IAM 策略，即使其他策略授予更多权限也不例外。第 14 章。领域 1。

**置放群组** — 控制 EC2 实例的物理放置，以最小化延迟（集群）或最大化可用性（分散）。第 4 章。领域 3。

**PrivateLink** — 用于创建到 AWS 中托管服务的私有端点的 AWS 服务，可通过接口终端节点访问。第 30 章。领域 1。

**预置并发（Lambda）** — 消除冷启动延迟的预初始化执行环境。第 20 章。领域 3。

**预置容量（DynamoDB）** — 预分配的每秒读写吞吐量，以容量单位衡量。对可预测流量比按需模式更便宜。第 9、29 章。领域 4。

---

## Q

**Amazon QuickSight** — 托管的商业智能和数据可视化服务。使用 SPICE（Super-fast, Parallel, In-memory Calculation Engine）缓存数据以快速渲染仪表板。连接到 Athena、S3、Redshift、RDS 和其他 AWS 数据源。无需管理 BI 服务器。第 26 章。领域 3。

---

## R

**RDS（Relational Database Service）** — 托管关系数据库。处理备份、补丁、故障转移。第 8 章。领域 3。

**RDS Proxy** — 管理 Lambda/应用程序与 RDS 之间的连接池，防止连接耗尽。第 8 章。领域 3。

**读副本（RDS）** — 用于读取扩展的数据库异步副本。不提供自动故障转移。第 8、24 章。领域 3。

**Redis** — 用于缓存、会话管理、实时排行榜、发布/订阅的内存数据结构存储。第 10 章。领域 3。

**预留实例（EC2）** — 承诺在特定区域使用特定实例类型 1 年或 3 年，以换取折扣。第 27 章。领域 4。

**Route 53** — AWS 的 DNS 服务和域名注册商。支持多种路由策略。第 12 章。领域 2、3。

**RPO（恢复点目标）** — 以时间衡量的最大可接受数据丢失。"我们能承受丢失多少数据？"第 18 章。领域 2。

**RTO（恢复时间目标）** — 故障后恢复服务的最大可接受时间。"我们能宕机多长时间？"第 18 章。领域 2。

**操作手册** — 操作系统的分步指令，专门用于事故响应。"凌晨 3 点该有人做什么？"第 32 章。跨领域。

---

## S

**S3 Intelligent-Tiering** — 根据访问模式自动在访问层之间移动 S3 对象。无检索费用。第 23 章。领域 4。

**S3 Select** — 使用 SQL 表达式检索 S3 对象内容的子集，减少数据传输。遗留：自 2024 年年中起不对新客户开放——Athena 现在是过滤和查询 S3 数据的主要途径。曾被建议作为替代方案的 S3 Object Lambda 本身也已成为遗留服务（2025 年 11 月起停止接受新客户；现有工作负载继续运行）。第 30 章。领域 4。

**Savings Plan** — 承诺每小时支出的特定金额以换取折扣的灵活定价模型。比预留实例更灵活。第 27 章。领域 4。

**SCP（服务控制策略）** — AWS Organizations 策略，限制 OU 中账户可用的最大权限。第 14 章。领域 1。

**Secrets Manager** — 存储并自动轮换机密（数据库密码、API 密钥）。第 16 章。领域 1。

**安全组** — 实例级别的有状态虚拟防火墙。只有允许规则；返回流量自动放行。第 15 章。领域 1。

**分片（Kinesis）** — Kinesis Data Streams 中吞吐量的基本单位：1 MB/s 写，2 MB/s 读。第 26 章。领域 3。

**共享责任模型** — AWS 负责云*本身*的安全（基础设施）；你负责云*中*的安全（数据、配置、访问）。第 1 章。领域 1。

**Shield** — DDoS 防护。Standard：免费，自动。Advanced：付费，提供 DRT 支持和财务保护。第 17 章。领域 1。

**Snow 系列** — 用于离线批量数据传输的物理设备（Snowball Edge：80 TB）——相当于包租货运航班而不是走高速公路。遗留（2026）：Snowmobile 和 Snowcone 已停产；Snow 设备于 2025 年 11 月停止接受新客户（AWS 推荐 DataSync 和 Data Transfer Terminals），但 SAA-C03 考试对"数周传输时间、带宽有限"仍然期望 Snowball 作为答案。第 25 章。领域 3。

**SNS（Simple Notification Service）** — 发布/订阅消息传递。同时向所有订阅者推送消息。扇出模式。第 19 章。领域 2。

**排序键（DynamoDB）** — 主键的可选第二个组件。支持在分区内进行范围查询。第 9 章。领域 3。

**竞价实例** — 以 60-90% 折扣使用空闲容量的 EC2 实例。可能在 2 分钟通知后被中断。仅适用于容错工作负载。第 27 章。领域 4。

**SQS（Simple Queue Service）** — 托管消息队列。将生产者与消费者解耦。Standard（至少一次）和 FIFO（恰好一次）队列。第 19 章。领域 2。

**Step Functions** — 无服务器工作流编排服务。用于协调 AWS 服务的状态机。第 22 章。领域 2。

**AWS Storage Gateway** — 本地与云存储之间的桥梁：在本地提供 NFS/SMB（File）、iSCSI（Volume）或虚拟磁带（Tape）接口，同时将数据持久化到 S3、Glacier 或 EBS 快照。第 6 章。领域 3。

---

## T

**目标追踪扩展** — 调整容量以维持目标指标值（例如 60% CPU 利用率）的 Auto Scaling 策略。第 7 章。领域 2。

**AWS Transfer Family** — 以 S3 或 EFS 作为后端的托管 SFTP/FTPS/FTP 端点。合作伙伴保留其现有的 SFTP 客户端；文件直接落入你的桶。第 25 章。领域 3。

**Transit Gateway** — 中心辐射式网络拓扑，通过中央网关连接多个 VPC 和本地网络。第 25 章。领域 3。

**TTL（生存时间）** — DynamoDB 自动删除项目的时间戳。也用于 DNS（解析器缓存记录多久）和缓存（缓存值有效多久）。第 9、12 章。领域 3。

---

## V

**VIF（虚拟接口）** — 与 AWS Direct Connect 一起使用的逻辑连接。Public VIF 访问 AWS 公共端点；Private VIF 访问 VPC 资源。第 25 章。领域 3。

**可见性超时（SQS）** — 已接收的消息对其他消费者隐藏的时间段。允许在其他消费者看不到同一消息的情况下进行处理。第 19 章。领域 2。

**VPC（Virtual Private Cloud）** — AWS 中的隔离虚拟网络。包含子网、路由表和网关。第 11 章。领域 1。

**VPC 终端节点** — 通过 AWS 私有网络将 VPC 资源连接到 AWS 服务。网关（免费，S3/DynamoDB）和接口（收费，大多数其他服务）。第 30 章。领域 1、4。

**VPC Flow Logs** — 捕获进出 VPC 中网络接口的 IP 流量信息。被 GuardDuty 使用，也用于网络故障排查。第 17 章。领域 1。

**VPC 对等连接** — 两个 VPC 之间的网络连接，使流量能够使用私有 IP 地址在它们之间路由。第 11 章。领域 3。

---

## W

**WAF（Web Application Firewall）** — 使用规则（IP 封锁、SQL 注入、速率限制）过滤 HTTP/HTTPS 流量。附加到 CloudFront、ALB 或 API Gateway。第 17 章。领域 1。

**AWS Wavelength** — 部署在 5G 电信运营商网络内部无线电边缘的 AWS 基础设施。为移动设备提供个位数毫秒级延迟。适用于移动 AR/VR、实时游戏、自动驾驶车辆遥测和 5G 边缘的实时视频。Wavelength Zones 是 AWS 区域在电信网络中的延伸。第 2 章。领域 3。

**Well-Architected Framework** — AWS 的六支柱评估框架：运营卓越、安全、可靠性、性能效率、成本优化、可持续性。第 31 章。跨领域。

**加权路由（Route 53）** — 按权重在端点之间分配 DNS 查询。用于蓝绿部署和 A/B 测试。第 12 章。领域 3。

**Write-through 缓存** — 每当数据库更新时同步更新缓存。数据始终一致，但缓存中可能持有许多再也不会被读取的项目。第 10 章。领域 3。
