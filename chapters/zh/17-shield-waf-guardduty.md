# 第17章：监视者们

罗马尼亚 IP 事件已被控制。秘密在 Secrets Manager 中。凭证已轮换。网络控制已收紧。

但 Priya 提出了结束第16章的那个问题："如果 CloudTrail 中出现了不寻常的东西，我们怎么知道？"

CloudTrail 每天记录数千个事件。没有人能读完所有这些。Priya 每周手动检查，但这意味着某件事可能在周二发生，直到下周一才被注意到。

"我们需要一些东西来替我们监视日志，" 她说。

Maya 抬起头。"自动地？"

"自动地。"

Tom 当天的第二个问题："这要多少钱？"

**三类威胁**

云应用程序面临的安全威胁通常分为三类：

**容量攻击（DDoS）**：攻击者发送如此多的流量，以至于你的应用程序无法响应合法用户。攻击可能是数百万个 HTTP 请求，或一场旨在耗尽服务器连接表的 TCP SYN 包洪水。

**应用程序攻击（漏洞利用）**：攻击者发送专门设计的请求，以利用应用程序中的弱点——SQL 注入、跨站脚本、使解析器崩溃的格式错误输入。

**行为异常（侦察和入侵）**：不应该发生的 API 调用（有人在凌晨3点查询你的整个用户数据库）、不寻常的 IAM 活动（凭证被从新的国家使用）或到意外目标的网络流量。

AWS 为每种情况都有一个专用服务：

- **AWS Shield**：DDoS 保护
- **AWS WAF**：应用层保护
- **Amazon GuardDuty**：行为威胁检测

**AWS Shield：DDoS 吸收器**

**AWS Shield 标准版**对所有 AWS 客户自动免费启用。它保护免受最常见的第3层（网络）和第4层（传输）DDoS 攻击——SYN 洪水、UDP 洪水、DNS 放大攻击。

CloudFront、Route 53 和弹性负载均衡坐在 AWS 网络的边缘。当 DDoS 攻击针对你的应用程序时，它首先到达这些托管服务。AWS 的网络基础设施在攻击到达你的 EC2 实例之前吸收它。

**AWS Shield 高级版**是高级层（每个组织每月3000美元）。它增加了：

- 保护 EC2、ELB、CloudFront、Global Accelerator 和 Route 53
- 近实时攻击通知
- 访问 AWS Shield 响应团队（SRT）——可以帮助你应对攻击的安全工程师
- 成本保护：如果攻击导致你的账单激增，AWS 会抵消激增成本
- 增强的第7层（应用层）DDoS 检测和缓解

"每月三千美元？" Tom 说。

"对于处理数百万收入的企业来说，一次让他们宕机两小时的 DDoS 攻击的成本超过三千美元，" Priya 说。

Tom 默默地做了数学计算。

"我们先用标准版，" 他最终说。

**AWS WAF：应用程序过滤器**

**AWS WAF（Web 应用程序防火墙）**在 HTTP 级别操作——它在请求到达你的应用程序之前检查 Web 请求的内容。

WAF 配置了 **Web ACL（访问控制列表）**——定义允许、阻止或计数的规则集。

WAF 可以附加到：

- CloudFront 发行版（在边缘全球检查请求）
- 应用负载均衡器（在区域级别检查请求）
- API Gateway
- AWS AppSync

**WAF 托管规则**：AWS 和第三方供应商发布预构建的规则集：

- **AWS 托管规则——核心规则集**：保护免受 OWASP 十大漏洞（SQL 注入、XSS、命令注入、路径遍历等）
- **AWS 托管规则——已知恶意输入**：阻止与已知攻击模式匹配的请求
- **AWS 托管规则——Amazon IP 信誉列表**：阻止已知与僵尸网络和扫描器相关的 IP
- **AWS 托管规则——机器人控制**：识别和管理机器人流量

你也可以创建自定义规则：

- "阻止任何 User-Agent 头包含'sqlmap'的请求"（常见的 SQL 注入扫描器）
- "速率限制：每个 IP 每5分钟最多允许1000个请求"
- "阻止任何参数值包含 `<script>` 的请求"

对于 Nimbus，实际设置：CloudFront 发行版上的 WAF，启用核心规则集。这在请求到达 EC2 实例之前阻止了最常见的攻击模式。

**Amazon GuardDuty：行为分析师**

GuardDuty 与 Shield 和 WAF 根本不同。它不阻止攻击——它**检测异常行为**。

GuardDuty 持续分析：

- **AWS CloudTrail 日志**：IAM 更改、API 调用、控制台登录
- **VPC 流量日志**：VPC 内的网络流量模式
- **DNS 查询日志**：你的实例在解析什么（已知恶意软件通常解析特定的 C2 域名）

机器学习模型识别偏离你基线的模式。GuardDuty 在检测到异常时生成**发现结果**——分类告警。

GuardDuty 可以检测到的例子：

- IAM 用户从无法识别的 IP 地址登录（在他们从未使用过的国家）
- 从 Tor 出口节点进行 API 调用
- EC2 实例与已知的加密货币挖矿池通信
- 异常高的 API 调用量（凭证滥用或扫描）
- S3 桶被被标记为恶意活动的 IP 地址访问
- 到与恶意软件命令和控制相关的已知域名的出站流量

"这就是本可以抓住罗马尼亚 IP 的东西，" Leo 安静地说。

"如果我们启用了 GuardDuty，它会标记 EC2 实例在凌晨2点向无法识别的外部 IP 建立出站连接，" Priya 确认道。

"它要多少钱？"

GuardDuty 定价基于分析的日志量——CloudTrail 事件、VPC 流量数据、DNS 查询。对于小到中型应用程序，通常每月50-150美元。在规模上，它仍然是基础设施成本的一小部分。

Tom 打开了控制台并启用了它。

**连接三个服务**

Shield、WAF 和 GuardDuty 在不同层面运行，相互补充：

| 服务 | 层 | 保护对象 | 操作 |
|---|---|---|---|
| AWS Shield | 网络/传输（L3/L4） | DDoS 洪水 | 吸收/缓解攻击 |
| AWS WAF | 应用程序（L7） | OWASP 十大、机器人、爬虫 | 允许、阻止或计数请求 |
| GuardDuty | 行为（所有日志） | 异常、被盗凭证、恶意软件 | 检测和告警 |

Shield 阻挡洪水。WAF 过滤水。GuardDuty 监视管道中的异常流量模式。

**CloudTrail：基础**

这三个服务都依赖日志。**AWS CloudTrail** 是捕获你 AWS 账户中每次 API 调用的日志服务——谁调用了什么，何时调用，从哪里调用，结果如何。

CloudTrail 在控制台中默认启用，有90天的历史。要长期保留日志：

1. 创建一个写入 S3 桶的跟踪
2. 可选地，发送到 CloudWatch Logs 以进行实时告警
3. 启用日志文件验证（检测日志是否被篡改）

GuardDuty、AWS Config 和 Security Hub 都从 CloudTrail 读取。没有 CloudTrail 日志，这些服务就没有任何东西可以分析。

**AWS Security Hub：仪表板**

如果你在多个 AWS 账户中运行，或者需要安全发现结果的整合视图，**AWS Security Hub** 将来自 GuardDuty、Inspector（漏洞评估）、Macie（数据隐私）、Config 和 Firewall Manager 的发现结果聚合到单个仪表板中。

它还根据安全最佳实践（AWS 基础安全最佳实践标准）和 CIS AWS 基础基准检查你的配置。

对于 Nimbus：Security Hub 目前还不需要。当他们成长为三个账户（开发、测试、生产）时，它将变得有用。

## 优势与局限性

**AWS Shield**：

- 标准版：免费且自动——没有理由不使用
- 高级版：对于高知名度目标非常好；对小团队来说很贵

**AWS WAF**：

- 托管规则组显著简化设置
- 自定义规则需要了解 HTTP 攻击模式
- 速率限制是一个经常被忽视的强大功能
- WAF 不能替代安全的应用程序代码——它是深度防御层

**GuardDuty**：

- 启用非常容易（几次点击）
- 发现结果需要人工审查和响应——GuardDuty 检测，不修复
- 会有误报——一些合法活动对 ML 模型来说看起来很异常
- 30天免费试用——值得立即启用

## 摘要

- **AWS Shield 标准版**：免费的，自动的第3/4层 DDoS 保护。始终开启。
- **AWS Shield 高级版**：带 SRT 访问和成本保护的高级 DDoS 保护。企业使用案例。
- **AWS WAF**：应用层防火墙。检查和过滤 HTTP 请求。附加到 CloudFront、ALB 或 API Gateway。使用托管规则组进行 OWASP 十大保护。
- **Amazon GuardDuty**：行为威胁检测。分析 CloudTrail、VPC 流量日志和 DNS 日志。为异常活动生成发现结果。
- **CloudTrail**：所有 AWS 安全日志的基础。启用写入 S3 的跟踪以进行长期保留。
- 这些服务相互补充：Shield 在网络层，WAF 在应用层，GuardDuty 在行为层。

## 考试技巧

*SAA-C03 领域：设计安全架构（领域1，任务1.2）*

- **Shield 标准版 vs 高级版**：标准版免费且自动。高级版花钱，增加了 SRT、成本保护和更好的检测。考试的高级版信号："大规模 DDoS"、"攻击期间的 SLA 保证"、"抵御 DDoS 相关成本激增的财务保护"。
- **WAF 使用信号**："阻止 SQL 注入"、"阻止跨站脚本"、"速率限制 API 调用"、"阻止特定用户代理"、"OWASP 十大保护" → WAF。
- **GuardDuty 信号**："检测异常 API 活动"、"识别被盗凭证"、"标记异常 EC2 网络连接"、"威胁情报" → GuardDuty。
- **WAF 附加点**：可以附加到 CloudFront（全球）、ALB（区域）、API Gateway（区域）、AppSync。
- **GuardDuty 数据源**：CloudTrail 管理事件、CloudTrail S3 数据事件、VPC 流量日志、DNS 日志。考试可能询问哪个数据源与特定检测场景相关。
- **Macie**：经常与 GuardDuty 混淆。**Macie** 使用 ML 检测 S3 中的敏感数据（个人身份信息、凭证、财务数据）。**GuardDuty** 检测行为中的威胁和异常。不同的使用案例。

**练习 2——考试练习**

*场景*：一家零售公司的网站正在被一个每小时发送数百万个请求到其产品搜索 API 的僵尸网络攻击。请求看起来合法（有效的 User-Agent 字符串、有效的会话 Cookie），但不会导致购买——它们在抓取产品价格。攻击导致合法客户响应时间变慢。

哪种服务组合*最能*应对这种威胁？

A) AWS Shield 高级版和 CloudFront  
B) 带速率限制规则的 AWS WAF 和 CloudFront  
C) Amazon GuardDuty 和 AWS Shield 标准版  
D) 阻止僵尸网络 IP 范围的网络 ACL

**提示 1**：请求是 HTTP 级别的（应用层）。哪个服务在 HTTP 层操作？

**提示 2**：僵尸网络使用很多不同的 IP 地址——在 NACL 级别阻止特定 IP 范围对大型僵尸网络无效。

**提示 3**：按 IP 地址的速率限制可以减缓抓取，即使你无法完全阻止它。

**答案**：B

**解析**：AWS WAF 可以按 IP 地址限制请求速率，减少来自任何单个来源的大量抓取的影响。CloudFront 将传入流量分布到 AWS 的边缘网络，吸收流量并保护源。WAF 规则还可以匹配请求模式（对同一 API 端点的快速连续请求）来识别抓取行为。

**为什么不是 A？** Shield 高级版保护免受 DDoS 洪水（第3/4层）。这个场景描述了应用层抓取（第7层 HTTP 请求），Shield 不检查这些。

**为什么不是 C？** GuardDuty 检测你 AWS 账户行为中的异常——它不阻止传入的 HTTP 请求。Shield 标准版不处理应用层攻击。

**为什么不是 D？** 大型僵尸网络使用来自分布式来源的数千个 IP 地址。阻止特定范围对复杂僵尸网络来说是打地鼠的方法。

GuardDuty 已启用。
