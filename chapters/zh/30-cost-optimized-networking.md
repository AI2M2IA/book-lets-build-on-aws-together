**AWS 如何收取数据传输费用**

AWS 的数据传输定价是不对称的：

**进入 AWS（入站）**：免费。你可以上传任意多的数据。

**从 AWS 传到互联网（出站）**：收费。前 100GB/月免费。之后：

- 前 10TB/月 $0.09/GB（美国区域）
- 接下来 40TB $0.085/GB
- 更高量时更低

**在同一可用区内**：免费。同一 AZ 中的 EC2 实例相互通信不收任何费用。

**在可用区之间（同一区域）**：每个方向 $0.01/GB。成本小但真实存在。

**在区域之间**：$0.02-0.08/GB，取决于区域。跨区域流量明显更贵。

**NAT Gateway**：处理每 GB $0.045。你的私有 EC2 实例通过 NAT Gateway 发送到互联网的每一个字节——以及每一个返回字节——都会被收费。

**CloudFront**：数据传输率低于直接 AWS 到互联网的费率。前 10TB $0.085/GB（略低于直接数据传出）。CloudFront 通常降低总传输成本，因为其边缘缓存意味着原始服务提供数据的频率更低。

**Tom 的细分**

在分类每个行项目之后：

**到互联网的出站数据**：每月 $214

- 全球客户的 API 响应
- CloudFront 缓存填充（边缘位置从原始获取时）

**NAT Gateway 处理**：每月 $289

- 应用服务器调用外部 API（支付处理器、电子邮件服务、地图数据）
- 通过 NAT Gateway 的 DynamoDB 调用（在为某些表设置 VPC 终端节点之前）

**跨 AZ 数据传输**：每月 $178

- 负载均衡器到 EC2 实例（负载均衡器在一个 AZ，一些实例在另一个 AZ）
- 应用服务器到 RDS 读副本（在不同的 AZ）

**跨区域数据传输**：每月 $166

- Aurora Global Database 复制（主库在 us-east-1，读库在 us-west-2）
- S3 跨区域复制用于备份

**NAT Gateway：最大的惊喜**

NAT Gateway 处理费 $289/月 是最大的项目。而且部分是不必要的。

在第 11 章中，Tom 为 S3 和 DynamoDB 设置了 VPC 网关终端节点。这些是免费的。但他忘记为其他几个服务设置接口终端节点：

- 用于补丁管理的 Systems Manager（SSM）
- 用于凭证检索的 Secrets Manager
- 用于指标和日志传输的 CloudWatch
- 用于消息轮询的 SQS

来自私有 EC2 实例对这些服务的每一个调用都通过 NAT Gateway。每次调用收费 $0.045/GB。

这些服务的**接口终端节点**：每个 AZ 每小时 $0.01 + 处理每 GB $0.01。

按 Nimbus 的量计算，SSM 接口终端节点的成本约为每月 $15，节省约每月 $43 的 NAT Gateway 费用（因为 SSM 为补丁管理和参数存储调用产生大量数据量）。

终端节点成本和节省因服务和量而异。Tom 计算出为四个高流量服务设置接口终端节点总成本约 $62/月，节省约 $140/月 的 NAT Gateway 处理费。

净节省：仅终端节点设置就节省每月 $78。

**跨 AZ 流量：架构问题**

每月 $178 的跨 AZ 数据传输更棘手。

其中一些是不可避免的：负载均衡器在 AZ 之间分配流量，所以一些请求来自一个 AZ，负载均衡器将它们转发到另一个 AZ 的实例。

其中一些是可以优化的：应用程序被配置为写入 RDS 主库（在 us-east-1a）并从读副本读取（在 us-east-1b）。每个读查询都跨越 AZ 边界。

对于读取，一个解决方案是：将应用程序配置为优先使用与请求实例在同一 AZ 中的读副本。每个 AZ 都有自己的读副本。流量保持本地。

权衡：更多读副本 = 更多成本。如果跨 AZ 流量成本为每月 $50，而额外的读副本成本为每月 $190，那么 AZ 本地优化就不划算了。

Tom 计算了：在他们当前的查询量下，跨 AZ 流量只有 $178 中的 $31。不值得为此添加副本。

其他跨 AZ 成本是负载均衡器路由和服务间通信——在当前架构层面基本上是不可避免的。

"这是理解成本并不意味着你应该修复它的情况之一，"Tom 说。

"完全消除跨 AZ 流量的成本是多少？"Maya 问。

"把一切都放在一个 AZ 违背了 Multi-AZ 的目的。这是以丧失高可用性为代价节省 $31/月。"

"所以我们保持现状，"她说。

"我们保持现状。"

这是成熟的成本对话：有时候你为某些东西付费是因为替代方案在风险上花费更多。

**CloudFront：数据传输折扣**

这里有一个反直觉的事实：通过 CloudFront 提供数据通常比直接从 EC2 或 S3 提供更便宜。

**直接 EC2 到互联网**：$0.09/GB
**CloudFront 到互联网**：$0.085/GB（略便宜）

但真正的节省不在每 GB 费率——而在于 CloudFront 在边缘位置缓存数据。如果 1,000 个用户请求同一张菜单照片：

- **没有 CloudFront**：1,000 个请求访问 S3 原始 × 照片大小 × $0.09/GB
- **有 CloudFront**：1 个请求访问 S3（缓存未命中）+ 999 个请求从边缘缓存以 CloudFront 费率提供

对于 Nimbus 83% 的缓存命中率（来自第 13 章），他们从边缘缓存提供 83% 的请求。实际原始数据传输只有总请求的 17%——83% 的"出站"流量在边缘被缓存了。

"CloudFront 不只是一个用于性能的 CDN，"Tom 说，"它也是数据传输的成本优化。"

Leo 若有所思地说，"我们应该通过 CloudFront 传递所有静态内容，即使对于不敏感于延迟的资产也是如此。"

"正确。如果用户从 AWS 下载它，它应该通过 CloudFront。"

**S3 Select：减少查询中的数据传输**

一个微妙的优化：**S3 Select** 允许你从 S3 对象（CSV、JSON、Parquet）中只检索你需要的行和列，而不是下载整个文件在你的应用程序中过滤。

没有 S3 Select：
```python
# 下载 500MB 文件，在内存中处理
data = s3.get_object(Bucket='analytics', Key='orders-2024.csv')
df = pd.read_csv(data['Body'])
result = df[df['restaurant_id'] == '47'][['order_id', 'total']]
```

有 S3 Select：
```python
# 让 S3 先过滤，只传输匹配的行（约 2MB 而不是 500MB）
response = s3.select_object_content(
    Bucket='analytics',
    Key='orders-2024.csv',
    Expression="SELECT order_id, total FROM S3Object WHERE restaurant_id = '47'"
)
```

S3 Select 减少了从 S3 传输到应用程序的数据。对于具有选择性查询的大文件，这可以减少 10-100 倍的数据量——因此降低成本。

**完整网络优化**

经过三周的分析和实施：

| 成本项目 | 之前 | 之后 | 每月节省 |
|---------|------|------|----------|
| NAT Gateway（接口终端节点） | $289 | $211 | $78 |
| CloudFront 优化（移动更多资产） | $214 | $147 | $67 |
| 跨 AZ 流量（接受现状） | $178 | $178 | $0 |
| 跨区域流量（接受现状） | $166 | $166 | $0 |
| **总计** | **$847** | **$702** | **$145/月** |

每月 $145，每年 $1,740 的网络节省。与计算和存储相比不大，但有意义。

更重要的是：Tom 现在理解了网络账单的每一行。他可以解释每项成本，并有意识地决定优化哪些以及接受哪些。

## 优势与局限

**NAT Gateway 成本**：

- 通过 NAT Gateway 的大量数据会迅速积累
- VPC 终端节点完全消除了某些 NAT 成本
- 检查你的私有实例调用哪些服务以及终端节点是否可用

**CloudFront 用于降低成本**：

- 缓存命中率直接决定节省
- 高缓存命中率 = 更低的原始传输 + 更低的总传输成本
- 通过 CloudFront 传递所有静态资产传递

**跨 AZ 权衡**：

- 消除跨 AZ 流量通常需要比节省更贵的架构变更
- 在优化之前仔细计算

**S3 Select**：

- 对 S3 大对象上的选择性查询有显著节省
- 当你需要整个文件时没有帮助

在下一章：六柱框架，它提出每次架构审查都应该从这些问题开始。

## 总结

- AWS 收取**出站数据**（互联网：约 $0.09/GB）、**跨 AZ 流量**（每个方向 $0.01/GB）、**跨区域流量**（$0.02-0.08/GB）和 **NAT Gateway 处理**（$0.045/GB）的费用。
- **入站数据**是免费的。**同一 AZ 流量**是免费的。
- **VPC 网关终端节点**（S3、DynamoDB）：免费。消除这些服务的 NAT Gateway 成本。
- **VPC 接口终端节点**：按小时加按 GB 计费。对于高流量服务比 NAT Gateway 更便宜。
- **CloudFront** 以低于直接 EC2 到互联网的费率提供数据，并通过缓存大幅减少原始传输量。
- **S3 Select** 通过在源头过滤来减少 S3 的数据传输。
- 一些网络成本是架构权衡（高可用性的跨 AZ）——了解它们，不要总是消除它们。

## 考试技巧

*SAA-C03 领域：设计成本优化架构（领域 4，任务 4.4）*

- **NAT Gateway 与 VPC 终端节点**：考试场景："私有子网中的 EC2 频繁调用 S3/DynamoDB——如何降低 NAT Gateway 成本？"→ VPC 网关终端节点（S3 和 DynamoDB 免费）。
- **数据传输定价规则**：
  - 进入 AWS：免费
  - 同一 AZ：免费
  - 跨 AZ：收费
  - 跨区域：收费（费率更高）
  - 互联网：收费（费率显著）
- **CloudFront 作为成本优化**："降低全球内容传递的数据传输成本"→ CloudFront。缓存层减少了原始请求。
- **S3 Transfer Acceleration**：使用 CloudFront 边缘位置加速上传*到* S3。比标准 S3 成本更高。用于从地理位置较远的地方上传大文件的客户。
- **跨区域复制成本**：跨区域复制数据会产生数据传输费用。对于 S3 CRR，你同时支付数据传出率和 S3 请求成本。
- **PrivateLink（VPC 接口终端节点）**：提供到 AWS 服务和其他 AWS 客户托管的服务的私有连接。比通过 NAT 更安全，对于高流量服务通常更便宜。

**练习 2 — 考试练习**

*场景*：一家公司的应用程序在私有子网中的 EC2 实例上运行。实例频繁调用 Amazon SQS 和 Amazon S3 的 API。目前，所有流量通过 NAT Gateway 退出。团队希望降低 NAT Gateway 成本。数据安全必须得到维护——不得有流量经过公共互联网。

哪种方案以最低的持续成本最符合这些要求？

A) 为 SQS 创建网关终端节点，为 S3 创建网关终端节点  
B) 为 SQS 创建接口终端节点，为 S3 创建网关终端节点  
C) 为 SQS 和 S3 都创建接口终端节点  
D) 移除 NAT Gateway 并直接使用互联网网关进行 API 调用

**提示 1**：网关终端节点只适用于 S3 和 DynamoDB。

**提示 2**：接口终端节点适用于 SQS 和许多其他服务（但要花钱）。

**提示 3**：在私有子网路由表中添加互联网网关路由将使其成为公共子网——违反安全要求。

**答案**：B

**解释**：S3 使用网关终端节点（免费）。SQS 需要接口终端节点（按价格收费）。这种组合消除了两个服务的 NAT Gateway 数据处理成本。所有流量保持在 AWS 私有网络内——不经过公共互联网。

**为什么不选 A？** 网关终端节点不适用于 SQS。只有 S3 和 DynamoDB 有网关终端节点。

**为什么不选 C？** 虽然这可以工作，但使用 S3 的接口终端节点（而不是免费的网关终端节点）会产生不必要的小时费用。对于 S3 和 DynamoDB，始终使用免费的网关终端节点。

**为什么不选 D？** 在私有子网中添加到互联网网关的路由会使其成为公共子网。私有子网中的 EC2 实例通常没有弹性 IP，所以它们实际上无法通过互联网网关路由而不做额外更改——而这样做会将它们暴露在入站互联网流量中。
