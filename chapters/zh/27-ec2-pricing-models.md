# 第二十七章：为所需付费

Tom 每个月都会查看 AWS 账单，自 Nimbus 成立以来就是如此。第一年，他大约能理解所看到内容的 60%。现在，他几乎能理解一切——除了 EC2 部分。

EC2 部分是按各种实例类型的"按需实例"的混合，都按小时定价，加起来每月 $2,340。

"我知道我们需要这些实例，"Tom 说，"但我不明白为什么我们要为它们支付完整价格。"

"完整价格？"Leo 问。

"按需定价，"Tom 说，"就像在你需要的那天早上预订酒店房间一样。最大灵活性。最高价格。"

"那替代方案是什么？"

Tom 调出了 EC2 定价页面。

"有四种定价模式，"他说，"而我们只使用了一种。"

**酒店类比**

EC2 定价与酒店客房预订策略出奇地吻合：

**按需**：走到前台无需预订。你支付全额房价，但想退房随时可以。完美适用于不可预测的住宿。

**预留实例/Savings Plans**：提前一年预订房间。你获得显著折扣——比全价低 30-72%——以换取承诺使用。

**竞价实例**：以酒店当时愿意接受的价格出价购买未售出的房间。最高可享受 90% 折扣。但如果酒店需要为全价客户腾出房间，他们会给你两分钟通知并要求你离开。

**专用主机**：专门为你租用整个楼层的酒店。不与其他客人共享。价格明显更贵。当软件许可证或合规规则禁止共享物理主机时需要使用。

每种模式都有其用例。Nimbus 犯的错误：对所有工作负载都使用按需定价，包括全天候运行且完全可预测的工作负载。

**按需实例：最大灵活性，最高成本**

**何时使用**：

- 不可预测的工作负载（无法预测的流量峰值）
- 开发和测试（频繁启动和停止）
- 短期工作负载（运行一周的实验）
- 首次部署（在了解使用模式之前）

**何时不使用**：

- 你知道会运行超过一年的稳定生产工作负载
- 任何具有可预测基线负载的工作负载

Tom 确认了 Nimbus 的按需实例：

- Web API 服务器：4 台 EC2 实例，全天候运行了 18 个月。*可预测基线。*
- 数据库代理（RDS Proxy）：始终运行。*可预测基线。*
- VPN 服务器：始终运行。*可预测基线。*
- 用于流量峰值的额外 API 服务器：不可预测。*按需定价在这里是正确的。*

**预留实例：一年期承诺**

**预留实例（RIs）**是一种计费承诺——你同意在特定区域使用特定实例类型 1 年或 3 年。作为交换，AWS 按更低的小时费率收费。

**折扣等级**：

- 1 年，不预付：约比按需低 30-40%
- 1 年，部分预付：约低 35-45%（现在支付部分，每小时少付一些）
- 1 年，全部预付：约低 40-50%（现在支付全年费用）
- 3 年，全部预付：约低 55-72%（最大折扣，最大承诺）

**标准与可转换 RI**：

- **标准**：锁定到确切的实例类型和区域。如果不再需要，可以在预留实例市场上出售。
- **可转换**：可以在承诺期间更改实例类型、操作系统和租赁。折扣少于标准（最高约 50% 对比 72%）。

Tom 为 4 台 API 服务器（r6g.large，按需 $0.252/小时）做了计算：

- 年度按需成本：$0.252 × 24 × 365 × 4 = $8,820
- 1 年全部预付 RI（1 台实例）：约 $1,600 预付
- 4 台实例：约 $6,400 预付 = **第一年节省 $2,420**

"仅仅通过做出承诺，我们就可以节省 $2,420，"Tom 说。

"这是一个承诺，"Maya 说，"如果我们需要更换实例类型怎么办？"

"如果我们认为可能需要更换，就买可转换 RI。"

"如果 AWS 发布更好的实例类型怎么办？"

"我们在 RI 到期时查看。如果新类型更好，我们购买新的 RI。"

**Savings Plans：灵活的承诺**

**Savings Plans** 是比预留实例更新、更灵活的替代方案。你不是承诺特定的实例类型，而是承诺特定的*每小时支出金额*（以美元计）。

**Compute Savings Plans**：适用于任何 EC2 实例，无论类型、大小、区域或操作系统如何。最灵活。最高 66% 折扣。

**EC2 Instance Savings Plans**：适用于某个区域中的特定实例系列（例如，"us-east-1 中的 c6g 实例"）。比 Compute 限制更多，但最高 72% 折扣（与 RI 最大折扣相同）。

**SageMaker Savings Plans**：专用于 SageMaker 机器学习训练和推理。

对于 Nimbus：为其 API 服务器使用 Compute Savings Plans。他们承诺每小时 $1.50 的 EC2 支出。任何实例类型，任何大小。当他们扩展机队或更换实例类型时，Savings Plan 仍然适用。

"这对我们来说比预留实例更好，"Leo 说，"我们仍在试验实例类型。Compute Savings Plan 给了我们折扣，而不用锁定到特定的 r6g。"

**竞价实例：90% 折扣**

**竞价实例**使用 AWS 的空闲 EC2 容量。当 AWS 有未使用的服务器时，你可以以比按需价格低 60-90% 的价格租用它们。当 AWS 需要收回容量（用于按需或预留客户）时，他们会给你 2 分钟警告并终止你的实例。

中断风险是其决定性特征。竞价实例只适用于：

- **容错工作负载**：如果实例在任务中途终止，任务可以重新启动而不会损坏任何内容
- **无状态处理**：图片调整大小、视频编码、批量分析、机器学习训练
- **短期批量作业**：2 分钟警告足以保存状态和检查点
- **Auto Scaling 混合机队**：将竞价实例用于 ASG 的大部分，按需作为基线

对于 Nimbus：竞价实例对每晚运行的批量分析作业（处理当天的订单数据到汇总报告）很有意义。如果竞价实例在作业中途被终止，作业失败，但在新实例上从头重新启动。S3 中的数据是安全的。

"将竞价实例用于夜间作业将其成本从每晚 $12 降至 $2，"Leo 报告。

**专用主机：合规选项**

某些软件许可证（Oracle、在某些配置中的 Windows Server）按物理插槽或核心计价。当你在共享主机上运行此软件（EC2 的默认设置）时，你可能在为未使用的容量付费。

**专用主机**让你可以独占访问完全属于你使用的物理服务器。你可以带来现有的按插槽许可证。没有其他 AWS 客户的实例在同一硬件上运行。

专用主机比标准 EC2 明显更贵。它们是一种合规和许可工具，而非成本优化工具。

Nimbus 没有需要专用主机的许可证要求。大多数云原生应用程序都不需要。

**构建混合机队**

成熟的方法：同时使用多种定价模式。

对于 Nimbus 的 API 机队：

- **基线负载（4 台实例，始终运行）**：由 Savings Plan 承诺覆盖
- **可预测的高峰（工作时间额外 2 台实例）**：如果承诺覆盖了它们，则由 Savings Plan 覆盖，否则按需
- **流量峰值溢出**：竞价实例（可接受，因为 API 服务器是无状态的——如果实例终止，请求会重新分配）

结果：一个在每个层面都优化成本的机队——承诺定价用于可预测部分，按需用于不可预测增长，竞价用于突发容量。

## 优势与局限

**按需**：无承诺。全价。用于不可预测或短期工作负载。

**预留实例**：最高 72% 折扣。锁定到特定实例类型/区域/操作系统。在 RI 市场上出售未使用的容量。

**Savings Plans**：最高 66-72% 折扣。比 RI 更灵活（Compute Savings Plans 适用于任何实例类型）。自动应用于匹配的使用量。

**竞价实例**：最高 90% 折扣。有 2 分钟中断风险。只用于容错、无状态、可中断的工作负载。

**专用主机**：完整的物理服务器。最贵。某些许可证或合规场景需要。

## 总结

- EC2 定价有四种模式：**按需**（全价，无承诺）、**预留实例/Savings Plans**（承诺支出以获得显著折扣）、**竞价**（以 60-90% 折扣使用空闲容量，可中断）、**专用主机**（物理服务器独占）。
- **Savings Plans** 因灵活性通常优于预留实例。
- **竞价实例**需要容错、无状态的工作负载——只用于批量作业、机器学习训练和可中断处理。
- 最优策略是**混合机队**：Savings Plans 用于基线，按需用于不可预测增长，竞价用于可中断批量工作。
- 当工作负载稳定运行超过 3 个月时审查定价模式——那时按需定价就开始变成浪费了。

## 考试技巧

*SAA-C03 领域：设计成本优化架构（领域 4，任务 4.2）*

- **Savings Plans 与预留实例**：Savings Plans 更灵活（Compute Savings Plans 适用于任何 EC2 实例）。预留实例锁定到特定实例类型。考试场景："需要在获得折扣的同时保持最大灵活性"→ Savings Plans。"确定会使用特定实例类型 3 年"→ Standard RI 以获得最大折扣。
- **竞价实例信号**："对成本敏感"、"容错"、"批量处理"、"可以处理中断"、"无状态工作负载"、"机器学习训练"→ 竞价实例。
- **竞价实例中断处理**：竞价实例在终止前获得 2 分钟警告。你的应用程序必须优雅地处理这一点（保存状态、耗尽连接、干净退出）。
- **按需与竞价实例用于 Web 服务器**：为实时用户流量提供服务的 Web 服务器不应使用竞价实例（中断导致请求失败）。Web 层使用按需或 Savings Plans。
- **EC2 Savings Plans 与 Compute Savings Plans**：EC2 Savings Plans 适用于特定实例系列和区域（更高折扣）。Compute Savings Plans 适用于任何 EC2 实例、Lambda 和 Fargate（最大折扣较低，更灵活）。
- **RI 市场**：未使用的标准预留实例可以出售给其他 AWS 客户。可转换 RI 不能出售。

**练习 2 — 考试练习**

*场景*：一家媒体公司运行一个视频转码流水线，将上传的视频转换为多种格式。转码作业在视频被上传时连续运行（全天候运行，数量可变）。每个作业需要 5-30 分钟。如果转码作业被中断，可以从头重新启动而不会丢失数据。公司希望最大限度地降低成本。

哪种 EC2 定价模式最符合这些要求？

A) Auto Scaling Group 中的按需实例  
B) 预留实例（1 年，全部预付）  
C) 带 Spot Fleet 以实现自动实例多样化的竞价实例  
D) 使用公司现有媒体软件许可证的专用主机

**提示 1**："可以从头重新启动而不会丢失数据"——这是允许特定定价模式的关键短语。

**提示 2**：对于可中断工作负载，"最大限度降低成本"指向最大折扣选项。

**提示 3**：Spot Fleet 从多个实例类型和可用区请求实例，降低中断的可能性。

**答案**：C

**解释**：转码作业是容错的——如果中断可以重新启动。这使它们成为竞价实例的理想选择，相比按需实例提供 60-90% 的折扣。Spot Fleet 跨实例类型和可用区多样化，降低大规模中断的可能性。

**为什么不选 A？** 按需是成本最高的选项。对于持续运行的容错工作负载，这是一种浪费。

**为什么不选 B？** 预留实例提供 50-72% 的折扣，但不提供竞价实例对容错工作负载可能达到的 90% 折扣。此外，RI 适用于可预测、稳定的工作负载——竞价实例专门用于可中断的批量处理。

**为什么不选 D？** 专用主机是用于许可证合规的，不是成本优化。它们是最贵的选项。

Tom 提交了 Savings Plan 购买。

每小时 $5.76 的承诺。三年期。Compute Savings Plans 以提供灵活性。

预计节省：三年内 $42,500。

"与三年内相同实例的按需定价相比。"
