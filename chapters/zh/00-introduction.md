# 第0章：开始之前

Maya 站在家族餐厅的吧台后面，那是一个周五的晚上，一个念头突然击中了她。

餐厅已经开了四年。食物很好——人们驱车穿越整个城市只为吃上那碗玉米饼。但每次有人打电话点餐，总是占线。每次有人驱车来取餐，只是因为他们打过电话却没人接，最终放弃了。

订单在流失。钱还没进门就溜走了。

而最糟糕的是，没有人能指出某个明显的失败点。

没有爆炸。没有崩溃。没有恶意破坏者，没有系统宕机的横幅，也没有明显损坏的屏幕。

这只是摩擦。细小的、悄无声息的、代价高昂的摩擦。

"我们需要一个网站，" Maya 对着空气说道。

她的表弟 Tom 从他正在手动更新的电子表格中抬起头。Tom 过去两年一直在管理餐厅的"系统"——这个说法其实过于好听，实际上不过是一个共享的 Google 表格和一块白板。

"网站，" 他重复道。"那网站究竟住在哪里？"

Maya 张了张嘴，又闭上了。

她完全不知道。

**一个听起来简单的问题**

网站住在哪里？

你可能从来没想过这个问题。大多数人都没有。你在浏览器里输入一个地址，页面就出现了，在这两件事之间的某个地方，魔法发生了。

直到有一天，你是那个要为这份魔法付钱的人。

但这不是魔法。这是计算机。

在世界的某个角落，就在此刻，有一台物理计算机——一台服务器——正在存储着构成那个网站的文件。当你的浏览器请求那个页面时，你的请求穿越互联网，到达那台计算机，然后计算机把文件发回给你。

就是这样。这就是网站。

所以真正的问题是：*谁的*计算机？

**三个选项，一个问题**

在餐厅里，Maya 和 Tom 在白板上草拟了几个选项。

**选项一**：买一台计算机，把它安置在餐厅里，从这里运行网站。（在行业里，这叫做"本地部署"——你自己的建筑，你自己的机器。你会经常看到这个术语。）

Tom 在这个选项旁边写下了"电费"和"坏了怎么办"。

**选项二**：付钱给一家托管公司，让他们为你们运行一台小型服务器。便宜，简单。2008年用来托管个人博客还行。对于一个不断成长的企业来说，可能不够灵活。

"如果我们突然同时收到一千个订单怎么办？" Maya 问道。

Tom 在选项二旁边加上了"无法扩展"。

**选项三**：别的什么。他们一直在听说的东西。一种叫做"云"的东西。

Tom 在白板上画了一朵云。一个真实的云朵形状，就像小孩画的那种。

"我其实不知道那是什么意思，" 他承认道。

"我也不知道，" Maya 说。

这就是一切的开始。

**"云"究竟是什么**

让我们立刻把这个说清楚，因为"云"这个词是技术领域里被滥用最多、解释最少的术语之一。

云不是一个让你的数据漂浮其中的神奇地方。

云是别人的计算机。

就是这样。当你把一张照片保存到 iCloud 或 Google Drive，你的照片被存储在苹果或谷歌拥有的某台物理计算机上，放在世界某处的一栋建筑里。当你使用 Netflix，你正在观看的视频正在从全球各地数据中心的物理服务器上发送过来。

"云"只是意味着：你通过互联网访问的计算机，你不必自己拥有或维护。

而亚马逊——没错，就是那家送快递的公司——建造了世界上最大的这类计算机集合之一。他们称之为亚马逊网络服务，或者 AWS。

**为什么是亚马逊？**

这是个合理的问题。亚马逊最初是一家书店。

事情是这样发展的：亚马逊增长得如此之快，以至于他们需要巨大的计算能力来运行自己的系统。他们建造了数据中心。他们雇用了工程师来管理这些中心。他们在大规模运行计算机方面变得非常、非常擅长。

然后亚马逊的某个人有了一个想法：如果我们把这些计算能力的访问权卖给其他人呢？

2006年，亚马逊网络服务正式上线。如今，AWS 运行着互联网的相当大一部分。你用来订机票的网站、追踪你快递的应用程序、你昨晚看的流媒体服务——它们中有很大一部分至少运行在 AWS 上。

这不是垄断。Google Cloud 和 Microsoft Azure 是真正的竞争者。但 AWS 是第一家，它规模庞大，而这本书就是讲 AWS 的。

**认识团队**

Maya 不是独自建造 Nimbus 的。

她首先打电话给 Tom——当然如此。Tom 有电子表格、供应商联系方式，以及真正执行一个想法所需要的那种固执。

Tom 认识一个开发者。Leo。二十四岁，自学成才，那种在你还没解释完问题之前就已经做好原型的人。他来参加第一次会议时带着一台笔记本电脑和一个做了一半的应用程序。

"我已经开始了，" 他说，打开了屏幕。"我想我把它部署到某个地方了。"

确实部署了。在一台他没完全搞明白的服务器上，在一个他没有刻意选择的地区，运行着一定会在高负载下崩溃的代码。

他们立刻喜欢上了他。

Priya 是后来才加入的——由共同的朋友介绍。工程学学位，专注于安全，那种在周末晚上阅读著名技术故障事后分析报告的人。她在第一次会议上只提了一个问题。

"有人想过如果有人试图入侵会发生什么吗？"

沉默。

"欢迎加入团队，" Maya 说。

**这本书是什么**

这是 Nimbus 的故事。

Nimbus 从一个餐厅订单系统开始，变成了更大的东西。在它成长的过程中，它遇到了所有成长中的软件都会遇到的每一个问题：无法承受流量的系统、丢失的数据、在最糟糕的时刻宕机的服务器、比营收增长更快的成本。

每次他们遇到问题，他们都找到了一个专门为解决这类问题而设计的 AWS 服务。

这本书通过跟随这段旅程来教你 AWS。

你不仅会学到每个服务*是什么*，还会学到它*为什么*存在，*何时*使用它，以及——同样重要的——*何时不*使用它。每个工具都有权衡。每个决定都有成本。这就是高级工程师理解的、而初级工程师还在学习的东西。

当你读完这本书，你将准备好参加 AWS 解决方案架构师助理考试（SAA-C03）。不仅如此：你将准备好走进真正的技术对话，并站稳脚跟。

这是承诺。

**开始之前的几件事**

**这本书假设你对云计算几乎一无所知。** 如果你听说过 AWS 但从未使用过，你来对地方了。如果你从未听说过 AWS，你也来对地方了。

**这本书不假设你是一名开发者。** Maya 不是。Tom 勉强算是。你不需要写代码来理解架构。你需要理解问题和解决方案。

**这本书有时会故意犯错。** 团队会犯错误。他们会选择错误的服务。他们会跳过一个将来会后悔的安全步骤。他们会过度配置，也会配置不足。这就是他们学习的方式，也是你学习的方式。

**考试技巧都是真实的。** SAA-C03 是一个真实的考试。每章末尾的情景题被设计得像真实的考试题一样。如果你能回答它们，你就在正确的轨道上。

还有一件事。

拿着铅笔读这本书，或者一个笔记应用，或者一个持续记录"我认为答案是……"的时刻的清单。

在团队做决定之前暂停一下。自己先做出判断。然后继续读，看看你是否会做出同样的权衡。

## 摘要

- **云**是通过互联网按需访问计算资源——别人的计算机，你无需自己拥有或维护。
- 三种托管选项：本地部署（你的硬件，你的成本）、共享托管（有限，无法扩展）、云（按使用付费，随需求扩展）。
- **AWS** 于 2006 年推出，当时亚马逊将其数据中心基础设施向外部客户开放。它仍然是最大的云提供商，其后是 Microsoft Azure 和 Google Cloud。
- Nimbus——本书所追随的故事——从一个餐厅订单系统开始，成长为一个生产级云架构。
- 这本书不仅教你每个 AWS 服务*是什么*，还教你它*为什么*存在，*何时*使用它，以及*何时不*使用它。

## 考试技巧

*SAA-C03 考试领域：跨领域——云概念基础*

- **考试中的云**是指通过互联网按需、按使用付费的计算。这是一种交付模式，而非一种技术。
- **CapEx 与 OpEx**：本地基础设施是资本支出（CapEx——预先购买硬件）。云是运营支出（OpEx——按期使用费用）。考试场景中询问"消除前期成本"或"从 CapEx 转变为 OpEx"指向云的采用。
- **云的优势**：无前期硬件投入，弹性扩展，只为使用的部分付费，无需管理物理基础设施。"流量不可预测"或"小团队，没有硬件专业知识"的场景是云的有力信号。
- **AWS 不是唯一的云**——Azure 和 GCP 是真正的竞争者——但 SAA-C03 考试是 AWS 专项的。你不会被要求比较不同的提供商。

## 优势与局限性

**这种方法的优势**：通过连续叙事学习，让概念在获得名字之前就有了背景。当你读到 IAM 或 RDS 时，你已经感受过它们所解决的问题——因为 Nimbus 先感受过了。这使得记忆更深刻，权衡推理比死记硬背特性列表更自然。

**需要注意的局限性**：本书涵盖 AWS SAA-C03 解决方案架构师助理课程。这是相当大的范围，但并非每个 AWS 服务——而且生产架构总是涉及特定于你所在行业和规模的服务和约束。Nimbus 的故事是虚构的；真实的初创公司以更凌乱的理由做出更凌乱的决定。用这本书来建立推理能力，而不是复制架构。

## 练习

**练习 1——回忆**

用你自己的话：什么是"云"，为什么一个小企业会选择它而不是购买自己的服务器？

*（提示：想想 Maya 和 Tom 在白板上选项 1 旁边写了什么。）*

**练习 2——考试练习**

*场景*：一个小型初创公司正在推出一个外卖应用程序。他们预计初期流量较低，但如果产品成功，预计会快速增长。创始团队没有管理物理服务器的经验。他们希望最大限度地减少前期成本，避免维护硬件的运营负担。

以下哪种方案*最能*满足他们的需求？

A) 购买一台专用服务器，在办公室托管应用程序  
B) 使用云提供商托管应用程序，只为使用的部分付费  
C) 与托管数据中心合作，自行安装服务器  
D) 将应用程序构建为完全离线运行，不需要互联网基础设施

**提示 1**：想想初创公司需要*避免*什么，就像他们需要*拥有*什么一样。

**提示 2**：场景明确提到"没有管理硬件的经验"和"最小化前期成本"。哪个选项消除了这些顾虑？

**提示 3**：我们在本章中将此选项描述为为"别人的计算机"付费。

**答案**：B

**解析**：AWS 等云提供商提供按使用付费的定价，无需前期硬件成本，并处理所有物理基础设施维护。这正是对流量不确定、没有硬件专业知识的初创公司有意义的模式——就像 Nimbus 一样。

**为什么不是 A？** 购买专用服务器需要前期资金、持续维护，且没有内置的随流量增长而扩展的能力。

**为什么不是 C？** 托管解决了空间问题，但初创公司仍然需要购买、维护和管理自己的服务器。

**为什么不是 D？** 外卖应用程序按定义需要互联网连接。

*SAA-C03 考试领域：跨领域——云概念基础*
