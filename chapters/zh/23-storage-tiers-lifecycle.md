# 第二十三章：自动整理的归档系统

一家律师事务所把活跃的案件文件放在桌上。已结案的案件放进文件柜。三年前的案件放进地下室的储物箱。十年前的案件放进场外的档案设施，每箱只需几分分钱，但取回任何东西需要两天时间。

相同的信息，根据访问频率以不同的成本存储。

S3 自动执行此操作。

Tom 正在审查 Nimbus 的 AWS 账单。行项目：S3 存储。每月 $847。

他叫来了 Leo。

"我们在 S3 中有 4.2 太字节，"Leo 检查后说。

"什么内容？"

"餐厅照片。订单收据。分析导出。18 个月前的备份快照。"

"上次有人访问 18 个月前的备份是什么时候？"

Leo 查了访问日志。

"去年十月，"他说，"一次。是为了验证备份格式。"

"所以我们按 S3 Standard 全价支付了 18 个月的备份费用。"

"是的。"

Tom 看了看 S3 定价页面。S3 Standard：每 GB 每月 $0.023。S3 Glacier Instant Retrieval：每 GB 每月 $0.004。

他做了计算。几个快速算术。

"只要将旧数据移动到更便宜的存储，我们就可以大幅减少这个账单，"他说。

"我们需要知道什么是旧的，"Leo 说。

"S3 知道。它追踪最后访问时间。"

**S3 存储类：完整谱系**

第 5 章介绍了 S3 Standard 作为主要存储类。S3 实际上有七个存储类，每个都为不同的访问模式设计：

**S3 Standard**：用于频繁访问的数据。低延迟（毫秒级）。成本最高。没有最短存储时长。用于活跃数据：当前的菜单照片、今天的订单、最近的日志。

**S3 Standard-Infrequent Access（S3 Standard-IA）**：用于每月访问不超过一次的数据。与 Standard 相同的毫秒级检索，但存储成本更低，加上每 GB 检索费。用于你访问时需要立即获取但很少访问的数据：较早的订单收据、6 个月前的分析导出。

**S3 One Zone-Infrequent Access（S3 One Zone-IA）**：与 S3 Standard-IA 相同，但只存储在一个可用区（而不是三个）。耐久性较低（如果该 AZ 发生灾难，数据可能丢失），但便宜 20%。用于可以重建的数据：缩略图缓存、临时处理输出。

**S3 Glacier Instant Retrieval**：偶尔需要的存档数据。毫秒级检索。存储成本很低，每 GB 检索成本较高。最短存储 90 天。用于每季度或更少访问一次的数据：季度合规报告、12 个月前的备份快照。

**S3 Glacier Flexible Retrieval**：深度存档，在几分钟到几小时内检索。成本低于 Glacier Instant Retrieval。用于不那么紧急的存档数据。

**S3 Glacier Deep Archive**：成本最低的选项。12 小时内检索。最短存储 180 天。用于必须保留以满足监管合规但预计永远不会被访问的数据：7 年税务记录、10 年审计日志。

模式：随着访问频率降低，成本降低，但检索时间增加（每次检索成本也增加）。选择与你的访问模式相匹配的类。

**S3 生命周期策略：自动归档系统**

手动在存储类之间移动文件既容易出错又耗时。S3 **生命周期策略**根据你定义的规则自动执行此操作。

生命周期规则有两个组成部分：

**过滤器**：规则适用于哪些对象（所有对象、具有特定前缀的对象、具有特定标签的对象）。

**操作**：要做什么，多少天后执行。

Nimbus 订单收据的示例生命周期策略：

```
90 天后转换到 S3 Standard-IA
365 天后转换到 S3 Glacier Instant Retrieval
2555 天后转换到 S3 Glacier Deep Archive（7 年）
2920 天后删除（8 年）
```

这一个策略确保：

- 活跃收据（< 90 天）：S3 Standard，快速访问
- 近期收据（90-365 天）：Standard-IA，便宜但立即可用
- 历史收据（1-7 年）：Glacier，非常便宜，偶尔需要
- 过期收据（> 8 年）：自动删除

Tom 审查了预测的节省：从每月 $847 降至约 $220。

"只是……定义什么是旧的以及它应该去哪里？"他说。

"S3 自动移动它，"Leo 确认，"没有定时任务。没有手动迁移。没有遗忘。"

**S3 Intelligent-Tiering：自组织类**

如果你不知道你的数据会被访问多频繁怎么办？

**S3 Intelligent-Tiering** 监控每个对象的访问模式，并自动在访问层之间移动：

- **频繁访问层**：针对最近访问的对象
- **不频繁访问层**：30 天未访问的对象
- **即时存档访问层**：90 天未访问的对象
- **存档访问层**：90-730 天未访问的对象（可选）
- **深度存档访问层**：180-730 天以上未访问的对象（可选）

S3 Intelligent-Tiering 对每个对象每月收取少量监控费用（每 1,000 个对象 $0.0025），但频繁和不频繁层没有检索费。

在以下情况使用 Intelligent-Tiering：

- 访问模式不可预测或随时间变化
- 你有无法轻松分类的热数据和冷数据混合
- 你有大于 128KB 的对象（小对象的监控费用可能超过节省）

在以下情况使用显式存储类（配合生命周期策略）：

- 访问模式可预测
- 你希望最小化每个对象的监控费用
- 对象较小（< 128KB）

**分段上传：针对大对象**

S3 的单次上传限制为 5GB。对于更大的对象，必须使用**分段上传**：将对象分成若干部分，并行上传每个部分，S3 将它们组装在一起。

好处：

- 上传更快（并行）
- 可以恢复失败的上传（只需重新上传失败的部分）
- 对于大于 5GB 的对象是必需的

生命周期规则技巧：设置生命周期规则，在 7 天后删除未完成的分段上传。如果上传中途失败且没有清理，那些部分仍然会被存储和计费——而没有组装好的对象可以展示。

Tom 非常欣赏这个提示。

**S3 复制：在桶之间复制数据**

S3 可以自动将对象从一个桶复制到另一个桶：

**同区域复制（SRR）**：在同一区域内复制对象。用于合规（在不同账户中保留单独的副本）、聚合来自多个桶的日志或从生产数据创建测试环境。

**跨区域复制（CRR）**：将对象复制到不同的区域。用于灾难恢复（跨区域的数据冗余）、合规（数据必须位于特定地理位置）以及为全球用户降低延迟。

复制不是备份解决方案——如果你删除源桶中的对象，它也会在副本中被删除（除非禁用了删除标记复制）。使用 AWS Backup 或带有对象锁定的版本控制进行备份。

**S3 Object Lock：合规的不可变性**

某些法规要求数据是**不可变的**——一旦写入，在指定期间内不能修改或删除。

**S3 Object Lock** 实现了 WORM（一次写入，多次读取）存储：

**保留期**：对象在指定时间内不能被删除或覆盖。

**合法保留**：无论保留期如何，对象都不能被删除，直到明确删除合法保留。

在受监管的行业中使用 S3 Object Lock：金融记录（SEC Rule 17a-4）、医疗记录（HIPAA）、合规存档。

## 优势与局限

**S3 存储层的重要性**：

- 在不牺牲实际访问数据的耐久性或可用性的情况下显著降低成本
- 生命周期策略自动化整个过程——没有运维负担
- S3 Intelligent-Tiering 消除了预测访问模式的需要

**复杂性所在**：

- Glacier 类的最短存储时长费用（Glacier Instant 为 90 天，Deep Archive 为 180 天）——提前删除仍会产生最低费用
- 如果你频繁访问存档数据，检索费可能会让你意外
- 生命周期转换需要时间——对象不会在规则触发后立即移动
- 对于拥有数百万个小对象的桶，Intelligent-Tiering 监控费用会累积

## 总结

- S3 有七个存储类：Standard、Standard-IA、Intelligent-Tiering、One Zone-IA、Glacier Instant Retrieval、Glacier Flexible Retrieval 和 Glacier Deep Archive。
- **生命周期策略**根据使用时长自动在存储类之间进行转换——定义一次，S3 永远处理。
- **S3 Intelligent-Tiering** 根据实际访问模式自动在层之间移动对象——用于不可预测的工作负载。
- 对于大于 5GB 的对象需要**分段上传**，对于大于 100MB 的任何内容推荐使用。
- **S3 复制**（SRR 和 CRR）跨桶和区域复制对象——用于灾难恢复、合规或聚合。
- **S3 Object Lock** 为合规场景提供 WORM 存储。

## 考试技巧

*SAA-C03 领域：设计成本优化架构（领域 4，任务 4.1）*

- **存储类选择信号**：
  - "频繁访问" → Standard
  - "每月访问一次，需要立即检索" → Standard-IA
  - "可以容忍数小时检索时间，很少访问" → Glacier Flexible Retrieval
  - "监管合规，7+ 年保留，从不访问" → Glacier Deep Archive
  - "未知或不断变化的访问模式" → Intelligent-Tiering
- **生命周期策略考试模式**："随着数据变老自动降低存储成本"、"90 天后转换到存档"→ 生命周期策略。
- **Intelligent-Tiering 监控费**：每个对象的少量费用。对于大量小对象，这可能超过节省。考试可能会测试这一点。
- **CRR 要求**：源桶和目标桶都必须启用版本控制。源和目标必须在不同的区域。
- **S3 Object Lock**："WORM"、"不可变"、"SEC 17a-4"、"不能被删除或修改"→ Object Lock。治理模式（可以被管理员覆盖）。合规模式（任何人包括 root 都无法覆盖）。
- **Glacier 恢复**：Glacier 中的对象不会立即可用。你必须"恢复"一个副本到 S3 Standard 以访问。恢复的副本是临时的（你设置时间）。原始文件仍在 Glacier 中。

**练习 2 — 考试练习**

*场景*：一家公司每天生成 500GB 的应用日志。日志在前 7 天内被频繁查询（用于调试和监控）。7 天后，日志很少被访问，但如有需要必须在 30 分钟内可用。1 年后，日志必须保留以满足合规要求，但从不被访问。公司需要在满足这些要求的同时最大限度地降低存储成本。

哪种 S3 生命周期策略最符合这些要求？

A) 在 S3 Standard 中存储 7 天；7 天后转换到 S3 Glacier Deep Archive；365 天后过期  
B) 在 S3 Standard 中存储 7 天；7 天后转换到 S3 Standard-IA；365 天后转换到 S3 Glacier Flexible Retrieval  
C) 从第 1 天起将所有日志存储在 S3 Intelligent-Tiering 中  
D) 在 S3 Standard 中存储 7 天；7 天后转换到 S3 Glacier Instant Retrieval；365 天后转换到 S3 Glacier Deep Archive

**提示 1**："30 分钟内可用"排除了哪个存储类？

**提示 2**：Deep Archive 需要 12 小时检索——不符合第 7-365 天的 30 分钟要求。

**提示 3**：365 天后，检索时间无关紧要（从不访问），所以最便宜的选项适用。

**答案**：D

**解释**：S3 Standard 在 7 天内处理频繁访问。Glacier Instant Retrieval 为第 7-365 天提供毫秒级访问——以显著低于 Standard-IA 的成本满足 30 分钟要求。365 天后，Glacier Deep Archive 是从不访问的数据的最便宜选项。

**为什么不选 A？** Glacier Deep Archive 需要 12 小时检索——不符合第 7-365 天的"30 分钟可用性"要求。

**为什么不选 B？** 7 天后的 Standard-IA 有效，但 Glacier Instant Retrieval 明显更便宜。Standard-IA 更适合在你需要即时检索但访问不频繁的时候——这里，第 7 天后数据根本很少被访问，使 Glacier 更具成本效益。

**为什么不选 C？** Intelligent-Tiering 对每个对象有监控费，对于具有可预测访问模式的大量日志，可能不会像显式生命周期规则那样积极地将日志移到存档层。对于具有可预测访问模式的大量日志，显式生命周期规则更具成本效益。
