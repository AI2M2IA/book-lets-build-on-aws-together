# পরিশিষ্ট D: সম্পূর্ণ অনুশীলন পরীক্ষা (65টি প্রশ্ন)

এটি একটি পূর্ণ-দৈর্ঘ্যের SAA-C03 অনুশীলন পরীক্ষা: 65টি প্রশ্ন, প্রকৃত পরীক্ষার ডোমেইন ওজন প্রতিফলিত করে — নিরাপদ আর্কিটেকচার ডিজাইন করুন (প্রশ্ন 1–20, ~30%), স্থিতিস্থাপক আর্কিটেকচার ডিজাইন করুন (21–37, ~26%), হাই-পারফর্মিং আর্কিটেকচার ডিজাইন করুন (38–53, ~24%), এবং কস্ট-অপ্টিমাইজড আর্কিটেকচার ডিজাইন করুন (54–65, ~20%)।

**কীভাবে এটি দেবেন:**

- একটি টাইমার **130 মিনিটের** জন্য সেট করুন — প্রকৃত পরীক্ষার সময়কাল। পেসিং অনুশীলন করুন: এটি প্রতি প্রশ্নে দুই মিনিট।
- সাতটি প্রশ্ন **"(দুটি বেছে নিন।)"** বলে — তাদের পাঁচটি বিকল্প এবং ঠিক দুটি সঠিক উত্তর আছে, ঠিক প্রকৃত পরীক্ষার মাল্টিপল-রেসপন্স আইটেমগুলির মতো। প্রশ্নে স্কোর করতে উভয়ই সঠিক হতে হবে।
- 65টিই শেষ না করা পর্যন্ত উত্তর কী-তে তাকাবেন না। প্রকৃত পরীক্ষায় মাঝপথে কোনো ফিডব্যাক নেই, এবং অনিশ্চয়তার প্রতি আপনার সহনশীলতা প্রশিক্ষণ দেওয়া প্রস্তুতির একটি অংশ।
- প্রকৃত পরীক্ষায় 15টি আনস্কোরড পরীক্ষামূলক প্রশ্ন অন্তর্ভুক্ত যা আপনি শনাক্ত করতে পারবেন না। এখানে 65টিই "স্কোরড।" একটি উত্তীর্ণ বেঞ্চমার্ক: **47 বা তার বেশি সঠিক (~72%)** আপনাকে 720/1000 স্কেলড উত্তীর্ণ স্কোরের পরিসরে রাখে। 47-এর নিচে, পরীক্ষা বুক করার আগে আপনার দুর্বল ডোমেইনের জন্য পরিশিষ্ট B-তে ম্যাপ করা অধ্যায়গুলি পুনরায় দেখুন।
- প্রতিটি প্রশ্নের জন্য যা আপনি মিস করেন — এবং প্রতিটি প্রশ্ন যা আপনি সঠিক পান কিন্তু দ্বিধা করেন — distractor বিশ্লেষণ পড়ুন। পরীক্ষা প্রশংসনীয় বিকল্পগুলির মধ্যে *পার্থক্য* পরীক্ষা করে, এবং সেখানেই শেখাটা থাকে।

## অংশ 1 — নিরাপদ আর্কিটেকচার ডিজাইন করুন (প্রশ্ন 1–20)

**প্রশ্ন 1** *(Domain 1 — Task 1.1)*
একটি আর্থিক সেবা কোম্পানি সমস্ত বৈশিষ্ট্য সক্ষম সহ AWS Organizations ব্যবহার করে। নিরাপত্তা দল সংস্থার রুটে একটি service control policy (SCP) সংযুক্ত করেছে যা eu-west-1 ছাড়া সমস্ত AWS Regions-এর ব্যবহার অস্বীকার করে। একটি অডিটের সময়, দল আবিষ্কার করে যে SCP সত্ত্বেও একটি অ্যাকাউন্টের একজন প্রশাসক এখনও us-east-2-এ EC2 ইনস্ট্যান্স লঞ্চ করতে সক্ষম ছিলেন। কোন অ্যাকাউন্ট সম্ভবত এই অ্যাকশন অনুমতি দিয়েছে?

A) একটি নেস্টেড অর্গানাইজেশনাল ইউনিট (OU)-এর একটি সদস্য অ্যাকাউন্ট, কারণ SCPs নেস্টেড OU-তে প্রচার করে না
B) ম্যানেজমেন্ট অ্যাকাউন্ট, কারণ SCPs ম্যানেজমেন্ট অ্যাকাউন্টে প্রযোজ্য নয়
C) একটি সদস্য অ্যাকাউন্ট যার IAM প্রশাসক পলিসিতে একটি explicit Allow অন্তর্ভুক্ত, যা SCPs ওভাররাইড করে
D) SCP সংযুক্ত করার পরে তৈরি একটি সদস্য অ্যাকাউন্ট, কারণ SCPs শুধুমাত্র সংযুক্তির সময় বিদ্যমান অ্যাকাউন্টগুলিতে প্রযোজ্য

**প্রশ্ন 2** *(Domain 1 — Task 1.1)*
একটি স্টার্টআপ তার ডেভেলপারদের তাদের অ্যাপ্লিকেশনের জন্য IAM রোল তৈরি করতে দিতে চায়, কিন্তু নিরাপত্তা দল উদ্বিগ্ন যে ডেভেলপাররা নিজেদের চেয়ে বেশি অনুমতি সহ রোল তৈরি করতে পারে, যা privilege escalation-এর দিকে নিয়ে যায়। নিরাপত্তা দল চায় ডেভেলপাররা স্ব-সেবা রোল তৈরি বজায় রাখুক। সবচেয়ে উপযুক্ত সমাধান কোনটি?

A) ডেভেলপারদের নিরাপত্তা দল দ্বারা পর্যালোচিত একটি টিকিটিং সিস্টেমের মাধ্যমে রোল তৈরির অনুরোধ জমা দিতে বাধ্য করুন
B) ডেভেলপারদের অ্যাকাউন্টে একটি SCP সংযুক্ত করুন যা iam:CreateRole অ্যাকশন সম্পূর্ণরূপে অস্বীকার করে
C) ডেভেলপারদের তৈরি সমস্ত রোলে একটি নির্দিষ্ট permissions boundary অন্তর্ভুক্ত করা আবশ্যক করুন, iam:CreateRole এবং iam:AttachRolePolicy-তে একটি IAM condition দিয়ে প্রয়োগ করা
D) AWS CloudTrail সক্ষম করুন এবং একজন ডেভেলপার একটি নতুন IAM রোল তৈরি করলেই সতর্কতা কনফিগার করুন

**প্রশ্ন 3** *(Domain 1 — Task 1.1)*
একজন SaaS প্রদানকারীকে স্বয়ংক্রিয় খরচ বিশ্লেষণ করতে তার গ্রাহকদের AWS অ্যাকাউন্টে রিসোর্স অ্যাক্সেস করতে হবে। গ্রাহকরা একটি IAM রোল তৈরি করে যা SaaS প্রদানকারীর অ্যাকাউন্ট অনুমান করতে পারে। একজন নিরাপত্তা পরামর্শদাতা সতর্ক করেন যে একটি তৃতীয় পক্ষ যে একজন গ্রাহকের রোল ARN জানতে পারে তা SaaS প্রদানকারীকে তৃতীয় পক্ষের পক্ষে সেই গ্রাহকের অ্যাকাউন্ট অ্যাক্সেস করতে প্রতারিত করতে পারে। কোন প্রক্রিয়া এই "confused deputy" ঝুঁকি প্রশমিত করে?

A) ক্রস-অ্যাকাউন্ট রোলের trust পলিসিতে multi-factor authentication (MFA) আবশ্যক করুন
B) SaaS প্রদানকারীকে sts:AssumeRole কলে গ্রাহক দ্বারা সংজ্ঞায়িত একটি অনন্য ExternalId পাস করতে এবং রোলের trust পলিসিতে একটি condition দ্বারা যাচাই করতে আবশ্যক করুন
C) SaaS প্রদানকারীর সাথে শেয়ার করার আগে AWS KMS দিয়ে রোল ARN এনক্রিপ্ট করুন
D) ক্রস-অ্যাকাউন্ট রোলকে একটি IAM ব্যবহারকারী দিয়ে প্রতিস্থাপন করুন যার অ্যাক্সেস কী প্রতি 90 দিনে রোটেট করা হয়

**প্রশ্ন 4** *(Domain 1 — Task 1.1)*
AWS Organizations-এ 40টি AWS অ্যাকাউন্ট সহ একটি কোম্পানি চায় তার কর্মচারীরা তাদের বিদ্যমান Microsoft Entra ID (Azure AD) ক্রেডেনশিয়াল দিয়ে একবার সাইন ইন করুক এবং একটি একক পোর্টালের মাধ্যমে সমস্ত AWS অ্যাকাউন্ট অ্যাক্সেস করুক, প্রতি অ্যাকাউন্টে কেন্দ্রীয়ভাবে অনুমতি বরাদ্দ সহ। কোন সমাধান সবচেয়ে কম অপারেশনাল ওভারহেড সহ এই প্রয়োজনীয়তা পূরণ করে?

A) 40টি অ্যাকাউন্টের প্রতিটিতে IAM ব্যবহারকারী তৈরি করুন এবং Entra ID-এর সাথে পাসওয়ার্ড সিঙ্ক্রোনাইজ করুন
B) Entra ID-কে বহিরাগত আইডেন্টিটি প্রদানকারী হিসাবে সহ AWS IAM Identity Center কনফিগার করুন এবং প্রতি অ্যাকাউন্টে ব্যবহারকারী ও গ্রুপে permission set বরাদ্দ করুন
C) প্রতিটি অ্যাকাউন্টে Amazon Cognito user pool স্থাপন করুন এবং সেগুলিকে Entra ID-তে ফেডারেট করুন
D) প্রতিটি অ্যাকাউন্টে একটি SAML আইডেন্টিটি প্রদানকারী তৈরি করুন এবং প্রতি-অ্যাকাউন্ট IAM রোল এবং trust পলিসি ম্যানুয়ালি লিখুন

**প্রশ্ন 7** *(Domain 1 — Task 1.3)*
একজন সলিউশন আর্কিটেক্ট ব্যাখ্যা করছেন কীভাবে AWS KMS একটি অ্যাপ্লিকেশন দ্বারা সংরক্ষিত একটি 4 GB ফাইল এনক্রিপ্ট করে, যেহেতু KMS সরাসরি শুধুমাত্র 4 KB পর্যন্ত ডেটা এনক্রিপ্ট করতে পারে। কোন বিবৃতি সঠিকভাবে envelope encryption বর্ণনা করে?

A) KMS ফাইলটিকে 4 KB খণ্ডে বিভক্ত করে এবং প্রতিটি খণ্ড KMS কী দিয়ে এনক্রিপ্ট করে

**1. উত্তর: B** — SCPs কখনও সংস্থার ম্যানেজমেন্ট অ্যাকাউন্টে প্রযোজ্য নয়, তাই এর principal Region সীমাবদ্ধতা দ্বারা অপ্রভাবিত। *কেন অন্যগুলি নয়:* A — SCPs নেস্টেড OU-এর মাধ্যমে উত্তরাধিকার পায়; C — সদস্য অ্যাকাউন্টে IAM Allow একটি SCP Deny ওভাররাইড করতে পারে না; D — SCPs সংযুক্তি পয়েন্টের অধীনে সমস্ত বর্তমান এবং ভবিষ্যত অ্যাকাউন্টে অবিলম্বে প্রযোজ্য।

**2. উত্তর: C** — রোল-তৈরি অ্যাকশনে একটি condition হিসাবে প্রয়োগ করা একটি permissions boundary ডেভেলপারদের তৈরি যেকোনো রোলের সর্বোচ্চ অনুমতি ক্যাপ করে, স্ব-সেবা সংরক্ষণ করার সময় privilege escalation প্রতিরোধ করে। *কেন অন্যগুলি নয়:* A — ম্যানুয়াল পর্যালোচনা অপারেশনাল ওভারহেড যোগ করে এবং স্ব-সেবা সরিয়ে দেয়; B — iam:CreateRole অস্বীকার করা বৈধ ওয়ার্কফ্লো ব্লক করে; D — CloudTrail সতর্কতা সনাক্তকারী, প্রতিরোধমূলক নয়।

**3. উত্তর: B** — trust পলিসির condition-এ যাচাই করা একটি গ্রাহক-সংজ্ঞায়িত ExternalId নিশ্চিত করে যে SaaS প্রদানকারী শুধুমাত্র সঠিক গ্রাহকের পক্ষে রোল অনুমান করে, confused deputy সমস্যা প্রশমিত করে। *কেন অন্যগুলি নয়:* A — MFA স্বয়ংক্রিয় সার্ভিস-টু-সার্ভিস অনুমানের জন্য অবাস্তব এবং deputy বিভ্রান্তি মোকাবেলা করে না; C — একটি ARN এনক্রিপ্ট করা (যা গোপনীয় নয়) কিছুই সমাধান করে না; D — দীর্ঘস্থায়ী IAM ব্যবহারকারী কী রোলের চেয়ে কম নিরাপদ।

**4. উত্তর: B** — IAM Identity Center একবার Entra ID-এর সাথে ফেডারেট করে এবং একটি একক অ্যাক্সেস পোর্টালের মাধ্যমে সমস্ত সংস্থার অ্যাকাউন্ট জুড়ে কেন্দ্রীয়ভাবে permission set বরাদ্দ করে। *কেন অন্যগুলি নয়:* A — প্রতি-অ্যাকাউন্ট IAM ব্যবহারকারী ঠিক সেই ওভারহেড যা এড়াতে হবে; C — Cognito অ্যাপ্লিকেশন (গ্রাহক) আইডেন্টিটির জন্য, AWS অ্যাকাউন্টে workforce অ্যাক্সেসের জন্য নয়; D — ম্যানুয়াল প্রতি-অ্যাকাউন্ট SAML সেটআপ কাজ করে কিন্তু অনেক বেশি অপারেশনাল ওভারহেড আছে।

**5. উত্তর: A** — User pool প্রমাণীকরণ পরিচালনা করে (ইমেইল/সোশ্যাল সাইন-ইন); identity pool S3 অ্যাক্সেস করতে IAM রোল দ্বারা স্কোপ করা অস্থায়ী AWS ক্রেডেনশিয়ালের জন্য ফলস্বরূপ টোকেন বিনিময় করে। *কেন অন্যগুলি নয়:* B — দুটি সার্ভিসের উদ্দেশ্য উল্টে দেয়; C — IAM Identity Center workforce ব্যবহারকারীদের জন্য, অ্যাপ গ্রাহকদের জন্য নয়; D — user pool টোকেন (JWTs) নিজে থেকে AWS সার্ভিস অ্যাক্সেস প্রদান করে না।

**6. উত্তর: B** — একটি customer managed key কী পলিসি, ব্যবহার লগিং এবং নিষ্ক্রিয়করণের সম্পূর্ণ নিয়ন্ত্রণ দেয় এবং স্বয়ংক্রিয় রোটেশন সমর্থন করে (ডিফল্টভাবে বার্ষিক)। *কেন অন্যগুলি নয়:* A — AWS managed keys আপনাকে কী পলিসি সম্পাদনা বা কী নিষ্ক্রিয় করতে দেয় না; C — AWS owned keys গ্রাহকের কাছে সম্পূর্ণরূপে অদৃশ্য; D — imported (BYOK) key material স্বয়ংক্রিয় রোটেশন সমর্থন করে না।

**7. উত্তর: B** — Envelope encryption: KMS একটি data key তৈরি করে; ডেটা plaintext data key দিয়ে স্থানীয়ভাবে এনক্রিপ্ট করা হয়, যা বাতিল করা হয়, যখন data key-এর KMS-এনক্রিপ্ট করা কপি ciphertext-এর সাথে সংরক্ষণ করা হয়। *কেন অন্যগুলি নয়:* A এবং C — KMS কখনও বড় পেলোড সরাসরি বা স্ট্রিমিংয়ের মাধ্যমে এনক্রিপ্ট করে না; D — হার্ড-কোডেড কী একটি অ্যান্টি-প্যাটার্ন এবং envelope encryption নয়।

**8. উত্তর: C** — Secrets Manager-এর alternating-users কৌশল দুটি ক্রেডেনশিয়াল বজায় রাখে এবং পালাক্রমে সেগুলি রোটেট করে, তাই পূর্ববর্তী ক্রেডেনশিয়াল ব্যবহারকারী বিদ্যমান কানেকশন রোটেশনের সময় কাজ করতে থাকে। *কেন অন্যগুলি নয়:* A — Parameter Store-এর কোনো অন্তর্নির্মিত রোটেশন নেই; আপনাকে সবকিছু নিজে তৈরি করতে হবে; B — single-user রোটেশন পুরোনো পাসওয়ার্ড অবিলম্বে অবৈধ করে, কানেকশন ব্যর্থতার ঝুঁকি; D — KMS রোটেশন এনক্রিপশন কী material রোটেট করে, ডেটাবেস পাসওয়ার্ড নয়।

**9. উত্তর: C** — SSE-C গ্রাহককে প্রতিটি অনুরোধের সাথে এনক্রিপশন কী সরবরাহ করতে দেয়; AWS অপারেশনের জন্য এটি মেমরিতে ব্যবহার করে এবং কখনও সংরক্ষণ করে না। *কেন অন্যগুলি নয়:* A — SSE-S3 কী সম্পূর্ণরূপে AWS-পরিচালিত; B — SSE-KMS কী AWS KMS-এ সংরক্ষিত; D — aws/s3 একটি AWS-পরিচালিত KMS কী এবং একেবারেই client-side নয়।

**10. উত্তর: B** — Object Lock compliance মোড retention মেয়াদ শেষ না হওয়া পর্যন্ত root সহ যেকোনো ব্যবহারকারী দ্বারা মুছে ফেলা বা ওভাররাইট করা প্রতিরোধ করে, এবং Object Lock-এর জন্য versioning প্রয়োজন। *কেন অন্যগুলি নয়:* A — governance মোড s3:BypassGovernanceRetention সহ ব্যবহারকারীদের দ্বারা বাইপাস করা যেতে পারে; C — একটি বাকেট পলিসি root ব্যবহারকারী দ্বারা পরিবর্তন বা সরানো যেতে পারে; D — লাইফসাইকেল মেয়াদ শেষ হওয়া পিরিয়ডের সময় মুছে ফেলা প্রতিরোধ করে না।

**11. উত্তর: B** — NACL stateless, তাই ক্লায়েন্টদের ephemeral সোর্স পোর্টে প্রতিক্রিয়া ট্র্যাফিক অবশ্যই স্পষ্টভাবে আউটবাউন্ড অনুমতি দিতে হবে। *কেন অন্যগুলি নয়:* A — NACL stateless, stateful নয়; C — নিরাপত্তা গোষ্ঠী stateful, তাই রিটার্ন ট্র্যাফিক স্বয়ংক্রিয়; D — 0.0.0.0/0 NACL নিয়মে পুরোপুরি বৈধ।

**12. উত্তর: A, B** — নিরাপত্তা গোষ্ঠী stateful (রিটার্ন ট্র্যাফিক স্বয়ংক্রিয়-অনুমোদিত), এবং NACL নম্বরযুক্ত নিয়ম ক্রমে প্রসেস করে এবং Deny সমর্থন করে। *কেন অন্যগুলি নয়:* C — নিরাপত্তা গোষ্ঠী শুধুমাত্র Allow নিয়ম সমর্থন করে; D — NACL সাবনেটে সংযুক্ত হয়, ENI-তে নয় (নিরাপত্তা গোষ্ঠী ENI-তে সংযুক্ত হয়); E — নিরাপত্তা গোষ্ঠীর নিয়ম কোনো অর্ডারিং ছাড়াই সব একসাথে মূল্যায়ন করা হয়।

**13. উত্তর: B** — Shield Advanced CloudFront এবং ALB-এর মতো সুরক্ষিত রিসোর্সের জন্য Shield Response Team, DDoS খরচ সুরক্ষা এবং আক্রমণ দৃশ্যমানতা/ডায়াগনস্টিকস প্রদান করে। *কেন অন্যগুলি নয়:* A — Shield Standard স্বয়ংক্রিয় কিন্তু কোনো SRT অ্যাক্সেস বা খরচ সুরক্ষা অন্তর্ভুক্ত করে না; C — WAF layer-7 অনুরোধ প্যাটার্ন মোকাবেলা করে, সম্পূর্ণ প্রয়োজনীয়তা সেট নয়; D — GuardDuty হুমকি সনাক্তকরণ, DDoS সুরক্ষা নয়।

**14. উত্তর: B** — ALB-তে AWS WAF SQLi managed rule group এবং একটি rate-based নিয়ম সহ কোনো অ্যাপ্লিকেশন কোড পরিবর্তন ছাড়াই উভয় আক্রমণ প্যাটার্ন ব্লক করে। *কেন অন্যগুলি নয়:* A — উচ্চ ডেভেলপমেন্ট প্রচেষ্টা; C — Shield Standard L3/L4 flood কভার করে, SQL injection নয়; D — নিরাপত্তা গোষ্ঠী অনুরোধের কন্টেন্ট পরিদর্শন করতে পারে না।

**15. উত্তর: B** — GuardDuty = লগ এবং হুমকি ইন্টেল থেকে হুমকি সনাক্তকরণ; Macie = S3-তে সংবেদনশীল-ডেটা (PII) আবিষ্কার; Inspector = EC2, ECR ইমেজ এবং Lambda-এর দুর্বলতা (CVE) স্ক্যানিং। *কেন অন্যগুলি নয়:* A, C, D — প্রতিটি কমপক্ষে দুটি সার্ভিস-টু-উদ্দেশ্য ম্যাপিং বিভ্রান্ত করে।

**16. উত্তর: B** — Gateway endpoint ঠিক S3 এবং DynamoDB-এর জন্য বিদ্যমান, ট্র্যাফিক AWS নেটওয়ার্কে রাখে এবং কোনো ঘণ্টা বা ডেটা প্রসেসিং চার্জ নেই। *কেন অন্যগুলি নয়:* A — NAT gateway পাবলিক IP স্পেসের মাধ্যমে রুট করে এবং প্রতি-ঘণ্টা/প্রতি-GB খরচ করে; C — interface endpoint ঘণ্টা এবং ডেটা চার্জ লাগে, তাই সর্বনিম্ন খরচ নয়; D — একটি internet gateway পাবলিক ইন্টারনেটে ট্র্যাফিক পাঠায়।

**17. উত্তর: A** — IMDSv2 একটি PUT অনুরোধের মাধ্যমে প্রাপ্ত একটি session token প্রয়োজন, যা সাধারণ SSRF ভেক্টর সম্পাদন করতে পারে না; HttpTokens=required প্রয়োগ করা IMDSv1 ক্রেডেনশিয়াল চুরি ব্লক করে। *কেন অন্যগুলি নয়:* B — অনেক এজেন্ট এবং SDK বৈধভাবে IMDS প্রয়োজন; C — NACL একটি ইনস্ট্যান্স এবং তার নিজের মেটাডেটা এন্ডপয়েন্টের মধ্যে link-local ট্র্যাফিক প্রভাবিত করে না; D — ফাইলে স্ট্যাটিক ক্রেডেনশিয়াল রোল ক্রেডেনশিয়ালের চেয়ে অনেক খারাপ।

**18. উত্তর: C** — Standard Parameter Store প্যারামিটার বিনামূল্যে এবং plaintext config-এর জন্য ঠিক; Secrets Manager শুধুমাত্র 5টি পাসওয়ার্ডের জন্য অন্তর্নির্মিত রোটেশন যোগ করে, খরচ কমায়। *কেন অন্যগুলি নয়:* A — 200টি প্লেইন config মানের জন্য Secrets Manager প্রতি-সিক্রেট মূল্য দেওয়া অপচয়মূলক; B — একা Parameter Store-এর পাসওয়ার্ডের জন্য নেটিভ রোটেশন নেই; D — Parameter Store-এর কোনো অন্তর্নির্মিত স্বয়ংক্রিয় রোটেশন নেই, তাই এই বিকল্পটি একটি ক্ষমতা বলে যা বিদ্যমান নেই।

**19. উত্তর: B** — S3 Bucket Keys S3-কে KMS কী থেকে একটি সময়-সীমিত বাকেট-স্তরের data key তৈরি করতে দেয়, SSE-KMS থাকা অবস্থায় প্রতি-অবজেক্ট KMS অনুরোধ (এবং খরচ) নাটকীয়ভাবে কমায়। *কেন অন্যগুলি নয়:* A — SSE-S3 KMS প্রয়োজনীয়তা পরিত্যাগ করে; C — রোটেশন ফ্রিকোয়েন্সি প্রতি-অনুরোধ API ভলিউম প্রভাবিত করে না; D — imported key material অনুরোধ সংখ্যা পরিবর্তন করে না।

**20. উত্তর: B, D** — পলিসি মূল্যায়নে যেকোনো Allow-এর উপর explicit Deny সর্বদা জেতে, এবং permissions boundary শুধুমাত্র অনুমতি ক্যাপ করে (কখনও প্রদান করে না)। *কেন অন্যগুলি নয়:* A — SCPs গার্ডরেল যা উপলব্ধ অনুমতি সীমাবদ্ধ করে; তারা কিছুই প্রদান করে না; C — resource-based পলিসি নিয়মিতভাবে নিজে থেকে ক্রস-অ্যাকাউন্ট অ্যাক্সেস প্রদান করে; E — কিছু একটি অ্যাকশন অনুমতি না দিলে IAM ডিফল্টভাবে implicit deny-তে যায়।

### অংশ 2 — প্রশ্ন 21–37

**21. উত্তর: C** — Multi-AZ AZ ব্যর্থতার জন্য স্বয়ংক্রিয় ফেলওভার প্রদান করে; read replica রিপোর্টিং রিড ট্র্যাফিক শোষণ করে — দুটি স্বতন্ত্র সমস্যার জন্য দুটি বৈশিষ্ট্য। *কেন অন্যগুলি নয়:* A — একটি প্রথাগত Multi-AZ স্ট্যান্ডবাই রিড পরিবেশন করতে পারে না; B — রেপ্লিকা প্রমোশন ম্যানুয়াল (বা স্ক্রিপ্ট করা) এবং একা রেপ্লিকা স্বয়ংক্রিয় HA ফেলওভার দেয় না; D — একটি বড় single-AZ ইনস্ট্যান্স AZ স্থিতিস্থাপকতায় উভয় প্রয়োজনীয়তা ব্যর্থ করে।

**22. উত্তর: B** — একটি Multi-AZ DB cluster ডিপ্লয়মেন্ট তিনটি AZ জুড়ে একটি writer এবং দুটি পঠনযোগ্য স্ট্যান্ডবাই চালায়, একটি reader endpoint সহ, তাই স্ট্যান্ডবাই ক্যাপাসিটি দ্রুত স্বয়ংক্রিয় ফেলওভার সমর্থন করার সময় রিড পরিবেশন করে। *কেন অন্যগুলি নয়:* A — একটি instance ডিপ্লয়মেন্টে একক স্ট্যান্ডবাই কোনো ট্র্যাফিক পরিবেশন করে না; C — read replica পরিচালিত স্বয়ংক্রিয় ফেলওভার প্রদান করে না এবং RDS ডেটাবেস ALB-এর মাধ্যমে লোড-ব্যালেন্স করা হয় না; D — Single-AZ-এর কোনো ফেলওভার নেই।

**23. উত্তর: B** — Aurora Global Database রেপ্লিকেশন স্টোরেজ স্তরে অ্যাসিঙ্ক্রোনাস সাধারণত সাব-সেকেন্ড ল্যাগ সহ, তাই ক্রস-Region RPO শূন্যের কাছাকাছি কিন্তু কখনও ঠিক 0 নিশ্চিত করা যায় না। *কেন অন্যগুলি নয়:* A — রেপ্লিকেশন Region জুড়ে সিঙ্ক্রোনাস নয়; C — write forwarding প্রাইমারিতে রাইট রুট করে; এটি রেপ্লিকেশন সিম্যান্টিক্স পরিবর্তন করে না; D — রেপ্লিকেশন ল্যাগ সাধারণত এক সেকেন্ডের কম, একটি 5-মিনিট শিডিউল নয়।

**24. উত্তর: B** — Recovery Time Objective হল সর্বাধিক সহনীয় ডাউনটাইম (4 ঘণ্টা); Recovery Point Objective হল সর্বাধিক সহনীয় ডেটা হারানো উইন্ডো (15 মিনিট)। *কেন অন্যগুলি নয়:* A — সংজ্ঞা উল্টে দেয়; C — MTBF/MTTR নির্ভরযোগ্যতা পরিসংখ্যান, DR উদ্দেশ্য নয়; D — SLA একটি চুক্তিভিত্তিক প্রতিশ্রুতি, একটি ডেটা-হারানো মেট্রিক নয়।

**25. উত্তর: B** — Pilot light ডেটা একটানা রেপ্লিকেট রাখে এবং মূল রিসোর্স প্রভিশন করে কিন্তু বন্ধ রাখে, কম খরচে দশ মিনিটের একটি RTO দেয় — একটি সঠিক ম্যাচ। *কেন অন্যগুলি নয়:* A — backup and restore-এর কোনো লাইভ রেপ্লিকেশন নেই এবং অনেক দীর্ঘ RTO; C — warm standby স্ট্যাক চলমান রাখে, প্রয়োজনের চেয়ে বেশি খরচ করে; D — active/active সবচেয়ে ব্যয়বহুল এবং প্রয়োজনীয়তা অনেক ছাড়িয়ে যায়।

**26. উত্তর: C, E** — Warm standby একটি স্কেল-ডাউন, সর্বদা-চলমান সম্পূর্ণ কপি; multi-site active/active একাধিক Region থেকে শূন্যের কাছাকাছি RTO সহ সর্বোচ্চ খরচে পরিবেশন করে। *কেন অন্যগুলি নয়:* A — backup and restore রিসোর্স পূর্ব-না-চালানো দ্বারা সংজ্ঞায়িত; B — backup and restore-এর সর্বোচ্চ (সবচেয়ে খারাপ) RTO; D — pilot light প্রভিশন-করা-কিন্তু-বন্ধ, ট্র্যাফিক পরিবেশন করা পূর্ণ ক্ষমতা নয়।

**27. উত্তর: B** — যখন 30-সেকেন্ড visibility timeout প্রসেসিং-মধ্যে শেষ হয়, মেসেজ পুনরায় উপস্থিত হয় এবং অন্য কনজিউমার এটি আবার প্রসেস করে; সর্বাধিক প্রসেসিং সময়ের চেয়ে visibility timeout দীর্ঘ সেট করুন (যেমন একটি সর্বোত্তম অনুশীলন হিসাবে 6×)। *কেন অন্যগুলি নয়:* A — FIFO বনাম standard কারণ নয়; C — long polling খালি-রিসিভ দক্ষতা প্রভাবিত করে, ডুপ্লিকেট নয়; D — retention period মেসেজ কতক্ষণ টিকে থাকে তা নিয়ন্ত্রণ করে, পুনঃ-ডেলিভারি নয়।

**28. উত্তর: A** — maxReceiveCount সহ একটি redrive পলিসি বারবার ব্যর্থ হওয়া ("poison pill") মেসেজগুলিকে অফলাইন বিশ্লেষণের জন্য একটি dead-letter queue-তে সরায়, অসীম retry লুপ থামায়। *কেন অন্যগুলি নয়:* B — একটি ছোট visibility timeout লুপটিকে আরও দ্রুত ঘোরায়; C — FIFO malformed মেসেজ বাতিল করে না; D — একটি 1-মিনিট retention বৈধ মেসেজও মেয়াদ শেষ করবে।

**29. উত্তর: B** — FIFO কিউ একটি MessageGroupId-এর মধ্যে exactly-once প্রসেসিং এবং কঠোর অর্ডারিং নিশ্চিত করে; group ID হিসাবে অ্যাকাউন্ট ID ব্যবহার ক্রস-অ্যাকাউন্ট সমান্তরালতা সহ প্রতি-অ্যাকাউন্ট অর্ডারিং দেয় (এবং হাই-থ্রুপুট FIFO মোড আরও স্কেল করতে পারে)। *কেন অন্যগুলি নয়:* A — standard কিউ অর্ডার বা exactly-once নিশ্চিত করতে পারে না; C — SNS এই প্যাটার্নের জন্য কোনো অর্ডারিং বা exactly-once প্রসেসিং গ্যারান্টি প্রদান করে না; D — একটি একক group ID সবকিছু সিরিয়ালাইজ করে, থ্রুপুট ধ্বংস করে।

**30. উত্তর: B** — SNS-থেকে-SQS fan-out প্রতিটি কিউতে প্রতিটি ইভেন্ট ডেলিভার করে, যেখানে প্রতিটি কনজিউমার টেকসই বাফারিং এবং স্বাধীন প্রসেসিং গতি পায়। *কেন অন্যগুলি নয়:* A — একটি কিউতে তিনটি কনজিউমার মেসেজ ভাগ করে; প্রতিটি মেসেজ শুধুমাত্র একটি কনজিউমারে যায়; C — ক্রমিক আহ্বান বাফারিং সহ স্বাধীন সমান্তরাল প্রসেসিং নয়; D — ইমেইল সাবস্ক্রিপশন মানুষের কাছে ডেলিভার করে, টেকসই অ্যাপ্লিকেশন বাফারে নয়।

**31. উত্তর: B** — Reserved concurrency সমালোচনামূলক ফাংশনের জন্য ডেডিকেটেড concurrency খোদাই করে (এবং সেল ফাংশন ক্যাপ করা এর blast radius সীমিত করে), একটি ফাংশনকে ভাগ করা অ্যাকাউন্ট পুল নিঃশেষ করা থেকে প্রতিরোধ করে। *কেন অন্যগুলি নয়:* A — একটি দীর্ঘ timeout concurrency স্লট দীর্ঘক্ষণ ধরে রাখে, throttling খারাপ করে; C — provisioned concurrency পরিবেশ প্রি-ওয়ার্ম করে কিন্তু অ্যাকাউন্ট concurrency কোটা বাড়ায় না; D — মেমরি সাইজ concurrency সীমা প্রভাবিত করে না।

**32. উত্তর: B** — Standard ওয়ার্কফ্লো এক বছর পর্যন্ত চলে এবং waitForTaskToken callback প্যাটার্ন SendTaskSuccess/SendTaskFailure টোকেন ফেরত না দেওয়া পর্যন্ত কোনো কম্পিউট খরচ ছাড়াই এক্সিকিউশন থামায়। *কেন অন্যগুলি নয়:* A — Express ওয়ার্কফ্লো 5 মিনিটে সর্বোচ্চ; C — Lambda সর্বোচ্চ 15 মিনিট চলতে পারে এবং ঘুমানো অর্থ অপচয় করে; D — EventBridge শিডিউল ইভেন্ট ট্রিগার করতে পারে কিন্তু ওয়ার্কফ্লো স্টেট থামাতে এবং পুনরায় শুরু করতে পারে না।

**33. উত্তর: A** — Express ওয়ার্কফ্লো খুব উচ্চ-হার, স্বল্প-সময়ের, at-least-once এক্সিকিউশনের জন্য কম খরচে তৈরি; Standard ওয়ার্কফ্লো পুনর্মিলন জবের জন্য exactly-once সিম্যান্টিক্স, এক বছর পর্যন্ত সময়কাল এবং সম্পূর্ণ এক্সিকিউশন ইতিহাস প্রদান করে। *কেন অন্যগুলি নয়:* B — Standard এই ব্যবহারের ক্ষেত্রে প্রতি সেকেন্ডে 90,000 শুরু অর্থনৈতিকভাবে টিকিয়ে রাখতে পারে না; C — Express 5 মিনিটে সর্বোচ্চ এবং at-least-once, 12-ঘণ্টা exactly-once জব ব্যর্থ করে; D — উল্টানো অ্যাসাইনমেন্ট উভয় ওয়ার্কলোড ব্যর্থ করে।

**34. উত্তর: B** — Failover রাউটিং প্রাইমারির স্বাস্থ্য পরীক্ষা পাস করার সময় সমস্ত ট্র্যাফিক প্রাইমারিতে পাঠায়, তারপর ব্যর্থ হলে স্বয়ংক্রিয়ভাবে সেকেন্ডারি রেকর্ড দিয়ে সাড়া দেয়। *কেন অন্যগুলি নয়:* A — weighted 50/50 সর্বদা অর্ধেক ট্র্যাফিক প্যাসিভ কপিতে পাঠায়; C — latency-based রাউটিং পারফরম্যান্স দ্বারা ট্র্যাফিক বিভক্ত করে, active/passive উদ্দেশ্য নয়; D — geolocation ব্যবহারকারীর অবস্থান দ্বারা রুট করে, এন্ডপয়েন্ট স্বাস্থ্য-ভিত্তিক ফেলওভারের সাথে সম্পর্কহীন।

**35. উত্তর: B** — ELB health check টাইপ যোগ করা ASG-কে ALB target-health ব্যর্থতাকে অস্বাস্থ্যকর হিসাবে গণ্য করতে দেয়, তাই EC2 status check পাস করলেও ক্র্যাশ-করা-অ্যাপ ইনস্ট্যান্স টার্মিনেট এবং প্রতিস্থাপন করা হয়। *কেন অন্যগুলি নয়:* A — detailed monitoring শুধুমাত্র মেট্রিক granularity পরিবর্তন করে; C — grace period স্বাস্থ্য মূল্যায়ন বিলম্বিত করে, যা প্রয়োজন তার বিপরীত; D — লোড ব্যালেন্সার টাইপ সমস্যা নয়।

**36. উত্তর: B** — Network Load Balancer layer 4 (TCP/UDP)-এ কাজ করে, অতি-নিম্ন লেটেন্সি সহ প্রতি সেকেন্ডে লক্ষ লক্ষ অনুরোধ পরিচালনা করে, এবং প্রতি AZ-এ একটি স্ট্যাটিক (বা Elastic) IP সমর্থন করে। *কেন অন্যগুলি নয়:* A — ALB layer 7 (HTTP/HTTPS) এবং নেটিভভাবে কোনো স্ট্যাটিক IP অফার করে না; C — Gateway Load Balancer ইনলাইন ভার্চুয়াল অ্যাপ্লায়েন্স স্থাপনের জন্য; D — Classic Load Balancer লিগ্যাসি এবং কোনো প্রয়োজনীয়তা পূরণ করে না।

**37. উত্তর: B, C** — CRR-এর উভয় বাকেটে versioning সক্ষম প্রয়োজন, এবং EFS Standard ক্লাস আঞ্চলিক (multi-AZ) ফাইল সিস্টেম যা AZ জুড়ে একসাথে মাউন্টযোগ্য। *কেন অন্যগুলি নয়:* A — CRR কনফিগারেশনের পরে শুধুমাত্র নতুন অবজেক্ট রেপ্লিকেট করে যদি না আপনি বিদ্যমানগুলির জন্য S3 Batch Replication চালান; D — EFS হাজার হাজার সমকালীন NFS ক্লায়েন্ট সমর্থন করে, single-attach EBS-এর বিপরীতে; E — versioning রেপ্লিকেশনের একটি পূর্বশর্ত কিন্তু নিজে কিছু রেপ্লিকেট করে না।

### অংশ 3 — প্রশ্ন 38–53

**38. উত্তর: B** — io2 Block Express 256,000 IOPS পর্যন্ত, সাব-মিলিসেকেন্ড লেটেন্সি এবং 99.999% স্থায়িত্ব প্রদান করে, তিনটি প্রয়োজনীয়তাই পূরণ করে। *কেন অন্যগুলি নয়:* A — gp3 এখন IOPS সংখ্যায় পৌঁছাতে পারে (এর ক্যাপ 2025-এর শেষে 80,000-এ উন্নীত হয়েছিল), কিন্তু এটি অন্য দুটি প্রয়োজনীয়তা ব্যর্থ করে: স্থায়িত্ব 99.8–99.9% (প্রশ্নটি 99.999% দাবি করে) এবং এর লেটেন্সি একক-সংখ্যা মিলিসেকেন্ড, নিশ্চিত সাব-মিলিসেকেন্ড নয়; B হল একমাত্র টাইপ যা তিনটিই পূরণ করে; C — st1 HDD-ভিত্তিক এবং IOPS-নিবিড় ডেটাবেসের জন্য অনুপযুক্ত; D — gp2 16,000 IOPS-এ সর্বোচ্চ এবং bursting একটি টেকসই গ্যারান্টি নয়।

**39. উত্তর: C** — FSx for Lustre সাব-মিলিসেকেন্ড লেটেন্সি, শত শত GB/s থ্রুপুট এবং নেটিভ S3 ইন্টিগ্রেশন (lazy-loading এবং exporting) সহ HPC-এর জন্য উদ্দেশ্য-নির্মিত। *কেন অন্যগুলি নয়:* A — EFS Lustre-এর HPC থ্রুপুট/লেটেন্সি প্রোফাইল মেলাতে পারে না; B — FSx for Windows SMB/Windows ওয়ার্কলোড লক্ষ্য করে, Linux HPC নয়; D — Mountpoint for S3 ভাগ করা POSIX ফাইল সিস্টেম সিম্যান্টিক্স বা প্রয়োজনীয় লেটেন্সি প্রদান করে না।

**40. উত্তর: B** — FSx for Windows File Server নেটিভভাবে SMB, Active Directory ইন্টিগ্রেশন এবং NTFS ACL সমর্থন করে, এবং Multi-AZ মোড দুই-AZ প্রয়োজনীয়তা কভার করে। *কেন অন্যগুলি নয়:* A — EFS NFS/POSIX এবং NTFS অনুমতি সংরক্ষণ করে না; C — S3 অবজেক্ট স্টোরেজ, একটি SMB ফাইল শেয়ার নয়; D — Lustre একটি Linux HPC ফাইল সিস্টেম SMB/AD সমর্থন ছাড়াই।

**41. উত্তর: D, E** — Transfer Acceleration দীর্ঘ-দূরত্বের ট্রান্সফার দ্রুত করতে AWS এজ/ব্যাকবোন নেটওয়ার্কের মাধ্যমে আপলোড রুট করে, এবং multipart upload ট্রান্সফার সমান্তরাল করে এবং সম্পূর্ণ 40 GB ফাইল পুনরায় শুরু না করে ব্যর্থ পার্ট পুনরায় চেষ্টা করতে দেয়। *কেন অন্যগুলি নয়:* A — One Zone-IA রিডানডেন্সি পরিবর্তন করে, আপলোড পারফরম্যান্স নয়; B — আপনি আপলোডের জন্য S3-এর সামনে একটি ALB রাখতে পারবেন না; C — CRR আপলোডের পরে রেপ্লিকেট করে এবং ingest-এ সাহায্য করে না।

**42. উত্তর: B** — Instance store NVMe SSD শারীরিকভাবে হোস্টের সাথে সংযুক্ত, পুনর্জন্ম করা যায় এমন ephemeral ডেটার জন্য সর্বনিম্ন লেটেন্সি অফার করে। *কেন অন্যগুলি নয়:* A এবং D — EBS নেটওয়ার্ক অতিক্রম করে এবং লেটেন্সি যোগ করে; C — EFS উভয়ের চেয়ে উচ্চ লেটেন্সি সহ একটি নেটওয়ার্ক ফাইল সিস্টেম।

**43. উত্তর: B** — কম সামগ্রিক ব্যবহার সহ hot partition-এ throttling হল ক্লাসিক লো-কার্ডিনালিটি পার্টিশন কী সমস্যা; একটি হাই-কার্ডিনালিটি কী (যেমন game_id#player_id) ট্র্যাফিক সমানভাবে বিতরণ করে। *কেন অন্যগুলি নয়:* A — ক্যাপাসিটি মোড পরিবর্তন hot partition ঠিক করে না; C — একটি LSI একই পার্টিশন কী এবং একই hot partition ভাগ করে; D — Streams পরিবর্তন ক্যাপচার করে, তারা রাইট পুনর্বিতরণ করে না।

**44. উত্তর: B** — DAX একটি DynamoDB-সামঞ্জস্যপূর্ণ, API-স্বচ্ছ ইন-মেমরি ক্যাশ যা ন্যূনতম কোড পরিবর্তন সহ মাইক্রোসেকেন্ড রিড প্রদান করে। *কেন অন্যগুলি নয়:* A — ElastiCache ক্যাশ পরিচালনা করতে অ্যাপ্লিকেশন পুনর্লিখন প্রয়োজন; C — একটি GSI hot আইটেম ক্যাশ করে না বা মাইক্রোসেকেন্ড লেটেন্সি দেয় না; D — Global Tables মাল্টি-রিজিয়ন অ্যাক্সেস মোকাবেলা করে, একক-আইটেম রিড লেটেন্সি নয়।

**45. উত্তর: B** — একটি GSI যেকোনো সময় একটি বিদ্যমান টেবিলে যোগ করা যায়, একটি নতুন partition/sort key সংমিশ্রণ সমর্থন করে, এবং বেস টেবিল থেকে বিচ্ছিন্ন তার নিজস্ব provisioned throughput আছে। *কেন অন্যগুলি নয়:* A — LSI শুধুমাত্র টেবিল তৈরিতে তৈরি করা যায়, টেবিলের পার্টিশন কী ভাগ করে এবং টেবিল throughput ভাগ করে; C — টেবিল পুনরায় তৈরি করা বিঘ্নকারী এবং অপ্রয়োজনীয়; D — Streams পরিবর্তন ক্যাপচারের জন্য, অ্যাড হক কোয়েরির জন্য নয়।

**46. উত্তর: B** — DynamoDB TTL মেয়াদ শেষ হওয়া আইটেমগুলিকে কোনো অতিরিক্ত খরচ ছাড়াই ব্যাকগ্রাউন্ডে স্বয়ংক্রিয়ভাবে মুছে দেয়। *কেন অন্যগুলি নয়:* A — শিডিউল করা স্ক্যান read/write ক্যাপাসিটি গ্রাস করে এবং অর্থ খরচ করে; C — লাইফসাইকেল পলিসি একটি S3/EFS ধারণা, DynamoDB নয়; D — Streams ডাউনস্ট্রিম ইভেন্ট ফিল্টার করে কিন্তু টেবিল থেকে আইটেম মুছে দেয় না।

**63. উত্তর: B** — S3-এর জন্য একটি gateway VPC endpoint বিনামূল্যে এবং একই-অঞ্চলের S3 ট্র্যাফিকের জন্য NAT gateway ডেটা প্রসেসিং চার্জ দূর করে। *কেন অন্যগুলি নয়:* A — একটি NAT instance এখনও EC2 এবং অপারেশনাল খরচ লাগে; C — interface endpoint প্রতি-ঘণ্টা এবং প্রতি-GB বিল করে, বিনামূল্যে gateway endpoint-এর চেয়ে বেশি খরচ করে; D — পাবলিক সাবনেট পাবলিক IPv4 চার্জ যোগ করে এবং নিরাপত্তা দুর্বল করে।

**64. উত্তর: B, E** — AWS প্রতিটি in-use পাবলিক IPv4 অ্যাড্রেসের জন্য চার্জ করে, তাই অপ্রয়োজনীয়গুলি সরানো খরচ কমায়, এবং AWS Budgets পূর্বাভাস/প্রকৃত ব্যয়ে সক্রিয় থ্রেশহোল্ড সতর্কতা প্রদান করে। *কেন অন্যগুলি নয়:* A — Elastic IPs সংযুক্ত থাকা অবস্থায়ও পাবলিক IPv4 চার্জের অধীনে বিল করা হয়; C — Compute Optimizer right-sizing সুপারিশ করে কিন্তু ব্যয় থ্রেশহোল্ডে ব্লক বা সতর্ক করতে পারে না; D — Shield Advanced একটি DDoS সার্ভিস যা খরচ যোগ করে।

**65. উত্তর: A** — Aurora Serverless v2 0 ACUs-এ স্কেলিং সমর্থন করে (auto-pause, 2024-এর শেষ থেকে উপলব্ধ) এবং কানেকশনে স্বয়ংক্রিয়ভাবে পুনরায় শুরু হয়, কোনো ম্যানুয়াল ধাপ ছাড়াই নিষ্ক্রিয় থাকাকালীন কম্পিউট খরচ দূর করে। জানার মতো সূক্ষ্মতা: auto-pause-এর জন্য সাম্প্রতিক ইঞ্জিন সংস্করণ প্রয়োজন (Aurora PostgreSQL 13.15+/14.12+/15.7+/16.3+, Aurora MySQL 3.08+); একটি pause-এর পরে প্রথম কানেকশন পুনরায় শুরু হতে ~15 সেকেন্ড নেয় (24+ ঘণ্টা pause-এর পরে আরও বেশি); কম্পিউট paused থাকাকালীন স্টোরেজ বিল করতে থাকে; এবং কানেকশন খোলা রাখা যেকোনো কিছু — একটি RDS Proxy, একটি keep-alive স্বাস্থ্য পরীক্ষা — pause সম্পূর্ণরূপে প্রতিরোধ করে। *কেন অন্যগুলি নয়:* B — একটি বন্ধ provisioned ক্লাস্টার ডেভেলপাররা সংযুক্ত হলে স্বয়ংক্রিয়ভাবে জাগে না (এবং 7 দিন পরে পুনরায় শুরু হয়); C — headless global database সেকেন্ডারি DR মোকাবেলা করে, নিষ্ক্রিয় খরচ নয়; D — স্কেল-ইন করা reader এখনও writer ইনস্ট্যান্স চলমান এবং বিলিং রেখে দেয়।
