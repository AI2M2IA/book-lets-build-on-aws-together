# পরিশিষ্ট A: AWS সার্ভিস দ্রুত রেফারেন্স

এই বইয়ে কভার করা প্রতিটি সার্ভিস, প্রবর্তনের ক্রমে। এটি একটি অধ্যয়ন রেফারেন্স এবং পরীক্ষার প্রস্তুতির সময় দ্রুত লুকআপ হিসাবে ব্যবহার করুন।

---

## কম্পিউট

**EC2 — Elastic Compute Cloud** *(অধ্যায় ৪)*

ক্লাউডে ভার্চুয়াল মেশিন। আপনি ইনস্ট্যান্স টাইপ (CPU, মেমরি, স্টোরেজ), অপারেটিং সিস্টেম এবং অঞ্চল বেছে নিন। আপনি ঘণ্টা হিসাবে (On-Demand), প্রতিশ্রুতি অনুযায়ী (Reserved Instances / Savings Plans), অথবা স্পেয়ার-ক্যাপাসিটি স্লট অনুযায়ী (Spot) দেন। মৌলিক কম্পিউট প্রিমিটিভ।

মূল ধারণা: AMI (Amazon Machine Image), ইনস্ট্যান্স টাইপ (t3, m6g, r6g, c6g পরিবার), কী পেয়ার, ইনস্ট্যান্স প্রোফাইল, প্লেসমেন্ট গ্রুপ।

পরীক্ষার সংকেত: পরিস্থিতিতে স্থায়ী, স্টেটফুল বা দীর্ঘ-চলমান কম্পিউট প্রয়োজন — EC2 বা ECS। পরিস্থিতিতে স্বল্প-সময়ের, ইভেন্ট-ট্রিগার বা শূন্য-নিষ্ক্রিয়-খরচ কম্পিউট প্রয়োজন — Lambda।

---

**Auto Scaling + Application Load Balancer** *(অধ্যায় ৭)*

Auto Scaling Groups (ASGs) লোডের উপর ভিত্তি করে EC2 ইনস্ট্যান্স যোগ এবং সরায়। Application Load Balancers (ALBs) ইনস্ট্যান্স জুড়ে ট্র্যাফিক বিতরণ করে এবং পথ বা হোস্ট দ্বারা রুট করে। একসাথে তারা অনুভূমিক স্কেলিং লেয়ার গঠন করে।

মূল ধারণা: লঞ্চ টেমপ্লেট, স্কেলিং পলিসি (target tracking, step, scheduled), স্বাস্থ্য পরীক্ষা, ALB টার্গেট গ্রুপ, লিসেনার নিয়ম, ওজনযুক্ত রাউটিং।

পরীক্ষার সংকেত: "পরিবর্তনশীল লোড পরিচালনা করুন" বা "AZ জুড়ে উচ্চ প্রাপ্যতা" → ASG + ALB।

---

**Lambda** *(অধ্যায় ২০)*

সার্ভারলেস ফাংশন। আপনি কোড লেখেন; AWS ইভেন্টের প্রতিক্রিয়ায় এটি চালায়। কোনো সার্ভার পরিচালনা করতে হয় না। আপনি প্রতি ইনভোকেশন এবং প্রতি মিলিসেকেন্ড এক্সিকিউশনের জন্য দেন। স্বয়ংক্রিয়ভাবে হাজার হাজার সমকালীন এক্সিকিউশনে স্কেল করে।

মূল ধারণা: ইভেন্ট সোর্স (API Gateway, S3, SQS, EventBridge, Kinesis), এক্সিকিউশন রোল, কনকারেন্সি সীমা, reserved এবং provisioned concurrency, কোল্ড স্টার্ট, Layers, ১৫-মিনিটের সর্বোচ্চ সময়।

পরীক্ষার সংকেত: "সার্ভারলেস," "ইভেন্ট-চালিত," "স্বল্প-সময়ের কাজ," "কোনো নিষ্ক্রিয় খরচ নেই" → Lambda।

---

**ECS — Elastic Container Service** *(অধ্যায় ২১)*

AWS-এ Docker কন্টেইনার চালায়। দুটি লঞ্চ টাইপ: EC2 (আপনি হোস্ট পরিচালনা করেন) এবং Fargate (AWS হোস্ট পরিচালনা করে)। ECS টাস্ক ডেফিনিশন, সার্ভিস, ক্লাস্টার শিডিউলিং এবং লোড ব্যালেন্সার ও সার্ভিস ডিসকভারির সাথে ইন্টিগ্রেশন পরিচালনা করে।

মূল ধারণা: টাস্ক ডেফিনিশন, ECS সার্ভিস, Fargate বনাম EC2 লঞ্চ টাইপ, ECR (কন্টেইনার রেজিস্ট্রি), টাস্ক IAM রোল, সার্ভিস অটো স্কেলিং।

পরীক্ষার সংকেত: "কন্টেইনারাইজড ওয়ার্কলোড," "মাইক্রোসার্ভিস," "AWS-এ Docker" → ECS (সার্ভারলেস কন্টেইনারের জন্য সাধারণত Fargate)।

---

**EKS — Elastic Kubernetes Service** *(অধ্যায় ২১)*

পরিচালিত Kubernetes। AWS কন্ট্রোল প্লেন চালায়; আপনি ওয়ার্কার নোড চালান (EC2 বা Fargate)। EKS ব্যবহার করুন যখন আপনার দল ইতিমধ্যে Kubernetes ব্যবহার করে বা আপনার Kubernetes-নির্দিষ্ট বৈশিষ্ট্যের প্রয়োজন।

পরীক্ষার সংকেত: "Kubernetes," "বিদ্যমান K8s ওয়ার্কলোড মাইগ্রেট করা প্রয়োজন" → EKS। "K8s ওভারহেড ছাড়াই শুধু কন্টেইনার দরকার" → ECS।

---

## স্টোরেজ

**S3 — Simple Storage Service** *(অধ্যায় ৫)*

অবজেক্ট স্টোরেজ। সীমাহীন ক্যাপাসিটি, ৯৯.৯৯৯৯৯৯৯৯৯% (এগারো নয়) স্থায়িত্ব। বাকেটে অবজেক্ট হিসাবে ফাইল সংরক্ষণ করে। বাকেট একটি অঞ্চলে থাকে। অবজেক্ট ০ বাইট থেকে ৫TB পর্যন্ত হতে পারে।

মূল ধারণা: বাকেট পলিসি, অবজেক্ট ACL, ভার্সনিং, স্ট্যাটিক ওয়েবসাইট হোস্টিং, presigned URL, মাল্টিপার্ট আপলোড, Transfer Acceleration, স্টোরেজ ক্লাস (Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive)।

পরীক্ষার সংকেত: "ফাইল সংরক্ষণ এবং পুনরুদ্ধার করুন," "স্ট্যাটিক অ্যাসেট," "ব্যাকআপ," "ডেটা লেক" → S3। সঠিক স্টোরেজ ক্লাস অ্যাক্সেস ফ্রিকোয়েন্সি এবং পুনরুদ্ধার গতির উপর নির্ভর করে।

---

**EBS — Elastic Block Store** *(অধ্যায় ৬)*

একটি একক EC2 ইনস্ট্যান্সের সাথে সংযুক্ত ব্লক স্টোরেজ। একটি হার্ড ড্রাইভের মতো কাজ করে। ইনস্ট্যান্স লাইফসাইকেল থেকে স্বাধীনভাবে টিকে থাকে (আপনি ডিট্যাচ এবং পুনরায় সংযুক্ত করতে পারেন)। সবচেয়ে সাধারণ ধরন: gp3 (সাধারণ উদ্দেশ্য SSD, ডিফল্ট), io2 (ডেটাবেসের জন্য provisioned IOPS), st1 (ক্রমিক রিডের জন্য থ্রুপুট-অপ্টিমাইজড HDD)।

মূল ধারণা: স্ন্যাপশট (ইনক্রিমেন্টাল, S3-এ সংরক্ষিত), এনক্রিপশন (KMS), Multi-Attach (io1/io2 শুধুমাত্র), IOPS এবং থ্রুপুট প্রভিশনিং।

পরীক্ষার সংকেত: "EC2-এর জন্য স্থায়ী স্টোরেজ," "ডেটাবেস স্টোরেজ," "লো-লেটেন্সি ব্লক অ্যাক্সেস প্রয়োজন" → EBS।

---

**EFS — Elastic File System** *(অধ্যায় ৬)*

ভাগ করা ফাইল সিস্টেম, একসাথে একাধিক EC2 ইনস্ট্যান্স থেকে অ্যাক্সেসযোগ্য। NFS প্রোটোকল। স্বয়ংক্রিয়ভাবে স্কেল করে। EBS-এর চেয়ে প্রতি GB বেশি ব্যয়বহুল। দুটি স্টোরেজ ক্লাস: Standard এবং Infrequent Access। Intelligent-Tiering স্বয়ংক্রিয়ভাবে ফাইল সরায়।

পরীক্ষার সংকেত: "ভাগ করা ফাইল সিস্টেম," "একাধিক EC2 ইনস্ট্যান্সের একই ফাইল প্রয়োজন," "NFS" → EFS।

---

**S3 স্টোরেজ ক্লাস এবং লাইফসাইকেল পলিসি** *(অধ্যায় ২৩)*

S3 Intelligent-Tiering অ্যাক্সেস ফ্রিকোয়েন্সির উপর ভিত্তি করে স্বয়ংক্রিয়ভাবে অবজেক্টগুলিকে অ্যাক্সেস টায়ারের মধ্যে সরায়। লাইফসাইকেল পলিসি বয়সের নিয়মের উপর ভিত্তি করে ক্লাসের মধ্যে অবজেক্ট ট্রানজিট করে (Standard → Standard-IA → Glacier)। Glacier স্টোরেজ ক্লাসের পুনরুদ্ধার বিলম্ব মিনিট (Glacier Instant) থেকে ১২ ঘণ্টা (Glacier Deep Archive) পর্যন্ত।

পরীক্ষার সংকেত: "বিরলভাবে অ্যাক্সেস করা ডেটার স্টোরেজ খরচ কমান" → লাইফসাইকেল পলিসি, Intelligent-Tiering, বা Glacier।

---

## ডেটাবেস

**RDS — Relational Database Service** *(অধ্যায় ৮)*

পরিচালিত রিলেশনাল ডেটাবেস। সমর্থিত ইঞ্জিন: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server এবং Aurora (AWS-এর মালিকানাধীন ইঞ্জিন)। AWS ব্যাকআপ, প্যাচিং, ফেলওভার এবং রেপ্লিকেশন পরিচালনা করে। আপনি স্কিমা ডিজাইন, কোয়েরি এবং ইনস্ট্যান্স সাইজিং পরিচালনা করেন।

মূল ধারণা: Multi-AZ ডিপ্লয়মেন্ট (স্বয়ংক্রিয় ফেলওভার, সিঙ্ক্রোনাস রেপ্লিকেশন), Read Replicas (অ্যাসিঙ্ক্রোনাস, রিড স্কেলিংয়ের জন্য), স্বয়ংক্রিয় ব্যাকআপ (১-৩৫ দিন রিটেনশন), ম্যানুয়াল স্ন্যাপশট (মুছা না হওয়া পর্যন্ত রাখা), RDS Proxy (কানেকশন পুলিং)।

পরীক্ষার সংকেত: "রিলেশনাল ডেটাবেস," "ACID লেনদেন," "বিদ্যমান SQL ওয়ার্কলোড" → RDS বা Aurora।

---

**Aurora** *(অধ্যায় ২৪)*

AWS-এর রিলেশনাল ডেটাবেস ইঞ্জিন, MySQL এবং PostgreSQL-এর সাথে সামঞ্জস্যপূর্ণ। বিতরণকৃত স্টোরেজ ইঞ্জিন যা ৩টি AZ-এ ৬টি কপিতে ডেটা রেপ্লিকেট করে। সাধারণত MySQL-এর ৫x দ্রুত। Aurora Serverless v2 স্বয়ংক্রিয়ভাবে ক্যাপাসিটি স্কেল করে (ACUs — Aurora Capacity Units-এ মাপা)।

মূল ধারণা: Aurora ক্লাস্টার (writer + সর্বোচ্চ ১৫টি reader endpoint), Aurora Global Database (< ১ সেকেন্ড রেপ্লিকেশন ল্যাগ সহ ক্রস-রিজিয়ন রিড রেপ্লিকা), Aurora Serverless v2।

পরীক্ষার সংকেত: "হাই-পারফরম্যান্স রিলেশনাল ডেটাবেস," "MySQL/PostgreSQL সামঞ্জস্যপূর্ণ," "গ্লোবাল রিড," "পরিবর্তনশীল ওয়ার্কলোড" → Aurora।

---

**DynamoDB** *(অধ্যায় ৯)*

সম্পূর্ণরূপে পরিচালিত NoSQL ডেটাবেস। কী-ভ্যালু এবং ডকুমেন্ট মডেল। একক-সংখ্যা মিলিসেকেন্ড পারফরম্যান্স সহ যেকোনো থ্রুপুটে স্কেল করে। দুটি ক্যাপাসিটি মোড: on-demand (প্রতি অনুরোধে দেন) এবং provisioned (প্রতি ঘণ্টায় ক্যাপাসিটি ইউনিটে দেন, Auto Scaling সহ)।

মূল ধারণা: পার্টিশন কী (প্রয়োজনীয়), সর্ট কী (ঐচ্ছিক), Global Secondary Index (GSI), Local Secondary Index (LSI), DynamoDB Streams (পরিবর্তন ডেটা ক্যাপচার), DynamoDB Accelerator (DAX) — ইন-মেমরি ক্যাশ, TTL (Time to Live), লেনদেন।

পরীক্ষার সংকেত: "হাই-থ্রুপুট কী-ভিত্তিক অ্যাক্সেস," "ফ্লেক্সিবল স্কিমা," "সার্ভারলেস NoSQL" → DynamoDB।

---

**ElastiCache** *(অধ্যায় ১০)*

পরিচালিত ইন-মেমরি ক্যাশিং। দুটি ইঞ্জিন: Redis (স্থায়ী, pub/sub, Lua স্ক্রিপ্টিং, ডেটা স্ট্রাকচার) এবং Memcached (বিশুদ্ধ ক্যাশ, সহজ, মাল্টি-থ্রেডেড)। ডেটাবেস লোড কমাতে এবং মাইক্রোসেকেন্ডে ঘন ঘন পড়া ডেটা পরিবেশন করতে ব্যবহার করুন।

মূল ধারণা: Cache-aside প্যাটার্ন, write-through প্যাটার্ন, eviction পলিসি, TTL, ক্লাস্টার মোড (Redis), স্বয়ংক্রিয় ফেলওভার সহ Multi-AZ।

পরীক্ষার সংকেত: "ডেটাবেস লোড কমান," "সাব-মিলিসেকেন্ড রিড লেটেন্সি," "সেশন ম্যানেজমেন্ট," "রিয়েল-টাইম লিডারবোর্ড" → ElastiCache Redis।

---

## নেটওয়ার্কিং

**VPC — Virtual Private Cloud** *(অধ্যায় ১১)*

AWS-এর মধ্যে একটি বিচ্ছিন্ন নেটওয়ার্ক। একটি অঞ্চলের সব AZ বিস্তৃত। আপনি IP ঠিকানার জায়গা (CIDR ব্লক) সংজ্ঞায়িত করেন, সাবনেট (পাবলিক বা প্রাইভেট) তৈরি করেন, রুট টেবিল কনফিগার করেন এবং নিরাপত্তা গোষ্ঠী ও NACL-এর মাধ্যমে অ্যাক্সেস নিয়ন্ত্রণ করেন।

মূল ধারণা: পাবলিক সাবনেট (Internet Gateway-এ রুট), প্রাইভেট সাবনেট (আউটবাউন্ডের জন্য NAT Gateway-এ রুট), Internet Gateway (ইন্টারনেটে ইনবাউন্ড + আউটবাউন্ড), NAT Gateway (প্রাইভেট ইনস্ট্যান্সের জন্য শুধুমাত্র আউটবাউন্ড), VPC Peering (দুটি VPC সংযুক্ত করুন), VPC Endpoints (ইন্টারনেট ছাড়াই AWS সার্ভিসের সাথে সংযুক্ত হন)।

পরীক্ষার সংকেত: "AWS-এ প্রাইভেট নেটওয়ার্ক," "ইন্টারনেট থেকে রিসোর্স বিচ্ছিন্ন করুন," "নেটওয়ার্ক ট্র্যাফিক নিয়ন্ত্রণ করুন" → VPC।

---

**নিরাপত্তা গোষ্ঠী এবং NACL** *(অধ্যায় ১৫)*

নিরাপত্তা গোষ্ঠী ইনস্ট্যান্স স্তরে স্টেটফুল ফায়ারওয়াল — শুধুমাত্র অনুমতির নিয়ম, রিটার্ন ট্র্যাফিক স্বয়ংক্রিয়। NACL (Network Access Control Lists) সাবনেট স্তরে স্টেটলেস ফায়ারওয়াল — ইনবাউন্ড এবং আউটবাউন্ড উভয় নিয়ম প্রয়োজন, নিয়ম নম্বর অনুযায়ী মূল্যায়ন করা হয়।

পরীক্ষার সংকেত: "সাবনেট থেকে একটি নির্দিষ্ট IP ব্লক করুন" → NACL অস্বীকার নিয়ম। "একটি ইনস্ট্যান্সে/থেকে ট্র্যাফিক নিয়ন্ত্রণ করুন" → নিরাপত্তা গোষ্ঠী।

---

**Route 53** *(অধ্যায় ১২)*

AWS-এর DNS সার্ভিস এবং ডোমেইন রেজিস্ট্রার। AWS রিসোর্স এবং বাহ্যিক এন্ডপয়েন্টে ইন্টারনেট ট্র্যাফিক রুট করে। রাউটিং পলিসি: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, Multi-value answer।

মূল ধারণা: Hosted zones (পাবলিক এবং প্রাইভেট), রেকর্ড টাইপ (A, AAAA, CNAME, Alias), স্বাস্থ্য পরীক্ষা, Traffic Flow (ভিজ্যুয়াল পলিসি এডিটর)।

পরীক্ষার সংকেত: "DNS রাউটিং," "অঞ্চলের মধ্যে ফেলওভার," "লেটেন্সি বা অবস্থানের উপর ভিত্তি করে রুট করুন" → Route 53 উপযুক্ত রাউটিং পলিসি সহ।

---

**CloudFront** *(অধ্যায় ১৩)*

Content Delivery Network (CDN)। এজ লোকেশনে (বিশ্বব্যাপী ৪০০+) বিষয়বস্তু ক্যাশ করে। শেষ ব্যবহারকারীদের জন্য লেটেন্সি কমায়। ক্যাশিংয়ের মাধ্যমে অরিজিন ট্রান্সফার খরচ কমায়। S3, EC2, ALB এবং API Gateway অরিজিন হিসাবে ইন্টিগ্রেট করে।

মূল ধারণা: Distribution, origins, behaviors (অরিজিনে পাথ-ভিত্তিক রাউটিং), TTL (ক্যাশ নিয়ন্ত্রণ), ক্যাশ invalidation, signed URLs এবং cookies (অ্যাক্সেস নিয়ন্ত্রণ), Lambda@Edge এবং CloudFront Functions (এজে কোড চালান), Origin Shield (অরিজিন লোড কমান)।

পরীক্ষার সংকেত: "গ্লোবাল কম লেটেন্সি," "স্ট্যাটিক বিষয়বস্তু ক্যাশ করুন," "অরিজিন লোড কমান," "Shield দিয়ে DDoS-এর বিরুদ্ধে সুরক্ষা করুন" → CloudFront।

---

**Direct Connect এবং VPN** *(অধ্যায় ২৫)*

AWS Direct Connect আপনার অন-প্রিমিসেস ডেটা সেন্টার থেকে AWS-এ একটি ডেডিকেটেড ফিজিক্যাল নেটওয়ার্ক সংযোগ। পাবলিক ইন্টারনেট বাইপাস করে। আরো সামঞ্জস্যপূর্ণ ব্যান্ডউইথ এবং লেটেন্সি। AWS Site-to-Site VPN পাবলিক ইন্টারনেটের মাধ্যমে একটি এনক্রিপ্টেড টানেল — দ্রুত সেটআপ, কম খরচ, পরিবর্তনশীল পারফরম্যান্স।

মূল ধারণা: Virtual Interface (VIF), Direct Connect Gateway (একাধিক অঞ্চলের সাথে সংযুক্ত হন), Transit Gateway (হাব-এন্ড-স্পোক নেটওয়ার্ক টপোলজি), VPN টানেল রিডান্ডেন্সি।

পরীক্ষার সংকেত: "AWS-এ ডেডিকেটেড প্রাইভেট সংযোগ" → Direct Connect। "এনক্রিপ্টেড সংযোগ, দ্রুত সেটআপ" → VPN। "একাধিক VPC সংযুক্ত করুন" → Transit Gateway।

---

**VPC Endpoints** *(অধ্যায় ৩০)*

পাবলিক ইন্টারনেট বা NAT Gateway ব্যবহার না করে AWS সার্ভিসে প্রাইভেট রিসোর্স সংযুক্ত করুন। Gateway Endpoints: বিনামূল্যে, শুধুমাত্র S3 এবং DynamoDB-এর জন্য উপলব্ধ। Interface Endpoints (PrivateLink): প্রতি ঘণ্টা + প্রতি GB মূল্য নির্ধারিত, বেশিরভাগ AWS সার্ভিসের জন্য উপলব্ধ।

পরীক্ষার সংকেত: "প্রাইভেট সাবনেটে EC2 S3/DynamoDB কল করে — NAT Gateway খরচ কমান" → Gateway Endpoint (বিনামূল্যে)। "প্রাইভেট সাবনেট থেকে SQS, SSM, Secrets Manager-এ প্রাইভেট সংযোগ" → Interface Endpoint।

---

## নিরাপত্তা এবং পরিচয়

**IAM — Identity and Access Management** *(অধ্যায় ৩ এবং ১৪)*

আপনার AWS অ্যাকাউন্টে কে কী করতে পারে তা নিয়ন্ত্রণ করে। ব্যবহারকারী (দীর্ঘমেয়াদী ক্রেডেনশিয়াল), গ্রুপ (অনুমতি ভাগ করা ব্যবহারকারী), রোল (সার্ভিস এবং ক্রস-অ্যাকাউন্ট অ্যাক্সেসের জন্য অস্থায়ী ক্রেডেনশিয়াল), পলিসি (allow/deny নিয়ম সংজ্ঞায়িত JSON নথি)।

মূল ধারণা: Principal, Action, Resource, Condition, explicit deny > explicit allow > implicit deny, SCP (AWS Organizations-এ Service Control Policy), Permission boundary, AssumeRole।

পরীক্ষার সংকেত: IAM প্রতিটি নিরাপত্তা প্রশ্নে জড়িত। মূল প্যাটার্ন: সার্ভিস IAM রোল ব্যবহার করে (ব্যবহারকারী নয়)। ক্রস-অ্যাকাউন্ট অ্যাক্সেস রোল অনুমান ব্যবহার করে। ন্যূনতম সুবিধা — শুধুমাত্র প্রয়োজনীয় অনুমতি দিন।

---

**KMS — Key Management Service** *(অধ্যায় ১৬)*

পরিচালিত এনক্রিপশন কী সার্ভিস। ক্রিপ্টোগ্রাফিক কী তৈরি, সংরক্ষণ এবং নিয়ন্ত্রণ করে। Customer-managed keys (CMKs) আপনাকে রোটেশন, ব্যবহার এবং অ্যাক্সেস পলিসি সংজ্ঞায়িত করতে দেয়। AWS-managed keys স্বয়ংক্রিয়ভাবে পরিচালিত হয়।

মূল ধারণা: Key policy (IAM পলিসি থেকে আলাদা), Envelope encryption (ডেটা key (DEK) দিয়ে এনক্রিপ্টেড; DEK CMK দিয়ে এনক্রিপ্টেড), স্বয়ংক্রিয় কী রোটেশন, Multi-region keys, Grants।

পরীক্ষার সংকেত: "বিশ্রামে ডেটা এনক্রিপ্ট করুন," "গ্রাহক-পরিচালিত এনক্রিপশন কী," "কী রোটেশন" → KMS।

---

**Secrets Manager** *(অধ্যায় ১৬)*

সংবেদনশীল মান সংরক্ষণ এবং স্বয়ংক্রিয়ভাবে রোটেট করে: ডেটাবেস ক্রেডেনশিয়াল, API কী, OAuth টোকেন। স্বয়ংক্রিয় পাসওয়ার্ড রোটেশনের জন্য RDS-এর সাথে ইন্টিগ্রেট করে। অ্যাপ্লিকেশন রানটাইমে API-এর মাধ্যমে secret পুনরুদ্ধার করে — কখনো ক্রেডেনশিয়াল হার্ডকোড করবেন না।

পরীক্ষার সংকেত: "ডেটাবেস ক্রেডেনশিয়াল সংরক্ষণ এবং রোটেট করুন," "হার্ডকোডেড secret এড়িয়ে চলুন" → Secrets Manager। "কনফিগারেশন মান সংরক্ষণ করুন, secret নয়" → Parameter Store (SSM)।

---

**AWS Shield** *(অধ্যায় ১৭)*

DDoS সুরক্ষা। Shield Standard স্বয়ংক্রিয় এবং বিনামূল্যে — সাধারণ ভলিউমেট্রিক এবং প্রোটোকল আক্রমণের বিরুদ্ধে সুরক্ষা করে। Shield Advanced আর্থিক সুরক্ষা, ২৪/৭ DDoS প্রতিক্রিয়া দল এবং বিস্তারিত আক্রমণ দৃশ্যমানতা যোগ করে।

পরীক্ষার সংকেত: "DDoS-এর বিরুদ্ধে সুরক্ষা করুন" → Shield Standard (স্বয়ংক্রিয়) বা Shield Advanced (এন্টারপ্রাইজ, SLA সহ)।

---

**WAF — Web Application Firewall** *(অধ্যায় ১৭)*

নিয়মের উপর ভিত্তি করে HTTP/HTTPS ট্র্যাফিক ফিল্টার করে: IP ব্লক, রেট সীমা, SQL injection প্যাটার্ন, XSS প্যাটার্ন, ভৌগোলিক বিধিনিষেধ, কাস্টম নিয়ম। CloudFront, ALB, API Gateway, বা AppSync-এর সাথে সংযুক্ত করে।

পরীক্ষার সংকেত: "নির্দিষ্ট IP ঠিকানা ব্লক করুন," "এজে SQL injection প্রতিরোধ করুন," "API কল রেট সীমিত করুন" → WAF।

---

**GuardDuty** *(অধ্যায় ১৭)*

হুমকি সনাক্তকরণ সার্ভিস। অস্বাভাবিক API কার্যকলাপ, পরিচিত দুর্ভাবনামূলক IP-এর সাথে যোগাযোগ, আপস করা ক্রেডেনশিয়াল সনাক্ত করতে ML এবং হুমকির বুদ্ধিমত্তা ব্যবহার করে CloudTrail লগ, VPC Flow Logs এবং DNS লগ বিশ্লেষণ করে।

পরীক্ষার সংকেত: "অস্বাভাবিক কার্যকলাপ সনাক্ত করুন," "আপস করা IAM ক্রেডেনশিয়াল চিহ্নিত করুন," "ক্রমাগত হুমকি মনিটরিং" → GuardDuty।

---

## মেসেজিং এবং ইভেন্ট প্রক্রিয়াকরণ

**SQS — Simple Queue Service** *(অধ্যায় ১৯)*

পরিচালিত মেসেজ কিউ। প্রযোজক মেসেজ পাঠায়; গ্রাহক পড়ে এবং মুছে দেয়। সার্ভিস ডিকাপল করে: প্রেরক জানতে হয় না রিসিভার উপলব্ধ কিনা। Standard কিউ: অন্তত-একবার ডেলিভারি, সর্বোত্তম-প্রচেষ্টা অর্ডারিং। FIFO কিউ: ঠিক-একবার প্রক্রিয়াকরণ, কঠোর অর্ডারিং।

মূল ধারণা: Visibility timeout (প্রক্রিয়া করার সময় অন্য গ্রাহকদের থেকে মেসেজ লুকানো), Dead Letter Queue (DLQ) বারবার ব্যর্থ মেসেজের জন্য, মেসেজ রিটেনশন (ডিফল্ট ৪ দিন, সর্বোচ্চ ১৪), Long polling (খালি প্রতিক্রিয়া কমান)।

পরীক্ষার সংকেত: "সার্ভিস ডিকাপল করুন," "লোড স্পাইকের সময় অনুরোধ বাফার করুন," "অ্যাসিঙ্ক্রোনাস প্রক্রিয়াকরণ" → SQS। "ক্রম গুরুত্বপূর্ণ এবং ঠিক-একবার প্রয়োজন" → SQS FIFO।

---

**SNS — Simple Notification Service** *(অধ্যায় ১৯)*

পরিচালিত pub/sub সার্ভিস। প্রকাশকরা একটি টপিকে একটি মেসেজ পাঠায়; সমস্ত subscriber একটি কপি পায়। Fan-out প্যাটার্ন: একটি মেসেজ → অনেক গ্রাহক। প্রোটোকল: SQS, Lambda, HTTP/HTTPS, ইমেইল, SMS, মোবাইল পুশ।

মূল ধারণা: টপিক, subscription, fan-out প্যাটার্ন (SNS → একাধিক SQS কিউ), মেসেজ ফিল্টারিং (subscriber শুধুমাত্র মিলে যাওয়া মেসেজ পায়)।

পরীক্ষার সংকেত: "একসাথে একাধিক এন্ডপয়েন্টে বিজ্ঞপ্তি পাঠান," "একাধিক গ্রাহকের কাছে একটি ইভেন্ট fan-out করুন" → SNS। সাধারণ প্যাটার্ন: টেকসই fan-out-এর জন্য SNS + SQS।

---

**EventBridge** *(অধ্যায় ২২)*

ইভেন্ট-চালিত আর্কিটেকচার তৈরির জন্য ইভেন্ট বাস। AWS সার্ভিস, SaaS পার্টনার এবং কাস্টম সোর্স থেকে Lambda, SQS, SNS, Step Functions এবং অন্যান্য লক্ষ্যমাত্রায় ইভেন্ট রুট করে। নির্ধারিত নিয়ম (cron) এবং প্যাটার্ন ম্যাচিং সমর্থন করে।

পরীক্ষার সংকেত: "AWS সার্ভিস থেকে লক্ষ্যমাত্রায় ইভেন্ট রুট করুন," "Lambda ফাংশন নির্ধারণ করুন," "ইভেন্ট-চালিত অর্কেস্ট্রেশন" → EventBridge।

---

**Step Functions** *(অধ্যায় ২২)*

সার্ভারলেস ওয়ার্কফ্লো অর্কেস্ট্রেশন। ভিজ্যুয়াল স্টেট মেশিনে Lambda ফাংশন, ECS টাস্ক, DynamoDB, SNS, SQS এবং অন্যান্য সার্ভিস সমন্বয় করে। রিট্রাই, ত্রুটি পরিচালনা, সমান্তরাল শাখা এবং ওয়েট স্টেট পরিচালনা করে।

মূল ধারণা: স্টেট মেশিন, স্টেট টাইপ (Task, Wait, Choice, Parallel, Map, Pass, Succeed, Fail), Standard Workflows (ঠিক-একবার, দীর্ঘ-চলমান) বনাম Express Workflows (অন্তত-একবার, হাই-ভলিউম)।

পরীক্ষার সংকেত: "একাধিক Lambda ফাংশন অর্কেস্ট্রেট করুন," "রিট্রাই লজিক সহ দীর্ঘ-চলমান ওয়ার্কফ্লো," "মানুষের অনুমোদনের ধাপ" → Step Functions।

---

**Kinesis** *(অধ্যায় ২৬)*

রিয়েল-টাইম ডেটা স্ট্রিমিং। Kinesis Data Streams: রেকর্ডের টেকসই, অর্ডারড স্ট্রিম (একটি বিতরণকৃত commit log-এর মতো)। গ্রাহকরা রেকর্ড প্রক্রিয়া করেন; ডেটা ২৪ ঘণ্টা থেকে ৭ দিন রাখা হয়। Kinesis Data Firehose: S3, Redshift, OpenSearch, Splunk-এ সম্পূর্ণরূপে পরিচালিত ডেলিভারি — কোনো গ্রাহক ম্যানেজমেন্ট প্রয়োজন নেই।

মূল ধারণা: Shard (থ্রুপুটের একক: ১MB/s রাইট, ২MB/s রিড), partition key (shard নির্ধারণ করে), সিকোয়েন্স নম্বর, checkpointing (KCL বা Lambda), Firehose বনাম Streams।

পরীক্ষার সংকেত: "রিয়েল-টাইম স্ট্রিমিং," "অর্ডারড রেকর্ড," "ইভেন্ট রিপ্লে করুন" → Kinesis Data Streams। "গ্রাহক পরিচালনা না করে S3/Redshift-এ স্ট্রিমিং ডেটা ডেলিভারি করুন" → Kinesis Firehose। SQS-এর সাথে তুলনা: Kinesis ধরে রাখে এবং রিপ্লে করে; SQS সেবনের পরে মুছে দেয়।

## অ্যানালিটিক্স

**Athena** *(অধ্যায় ২৬)*

S3-এ সংরক্ষিত ডেটার উপর সার্ভারলেস SQL কোয়েরি। কোনো পরিচালিত অবকাঠামো নেই। কোয়েরি প্রতি (প্রতি TB স্ক্যান করা) দেন। কলামার ফর্ম্যাট (Parquet, ORC) এবং বিভাজিত ডেটার সাথে সর্বোত্তম।

পরীক্ষার সংকেত: "SQL দিয়ে S3 ডেটা কোয়েরি করুন," "ডেটা লেকে অ্যাড-হক অ্যানালিটিক্স," "কোনো অবকাঠামো ম্যানেজমেন্ট নেই" → Athena।

---

**Glue** *(অধ্যায় ২৬)*

সার্ভারলেস ETL (Extract, Transform, Load) সার্ভিস। Glue Crawlers ডেটা আবিষ্কার করে এবং Glue Data Catalog আপডেট করে। Glue Jobs Spark বা Python রূপান্তর চালায়। Data Catalog Athena, Redshift Spectrum এবং EMR-এর সাথে ইন্টিগ্রেট করে।

পরীক্ষার সংকেত: "অ্যানালিটিক্সের জন্য ডেটা রূপান্তর এবং লোড করুন," "S3 ডেটার স্কিমা আবিষ্কার করুন," "ETL পাইপলাইন" → Glue।

---

## উচ্চ প্রাপ্যতা এবং ডিজাস্টার রিকভারি

**Multi-AZ এবং Multi-Region** *(অধ্যায় ১৮)*

Multi-AZ: স্বয়ংক্রিয় ফেলওভারের জন্য একটি অঞ্চলের মধ্যে সিঙ্ক্রোনাস রেপ্লিকেশন (RDS Multi-AZ, AZ জুড়ে লোড ব্যালেন্সার)। RDS-এর জন্য RPO ~০, RTO ~৬০s। Multi-Region: ভৌগোলিক রিডান্ডেন্সি এবং বৈশ্বিক ব্যবহারকারীদের জন্য কম লেটেন্সির জন্য অ্যাসিঙ্ক্রোনাস রেপ্লিকেশন।

মূল ধারণা: RTO (Recovery Time Objective — পুনরুদ্ধার করতে কত সময়), RPO (Recovery Point Objective — কতটুকু ডেটা হারানো যাবে)। Pilot Light, Warm Standby, Active-Active DR কৌশল।

পরীক্ষার সংকেত: AZ-স্তরের ব্যর্থতা (Multi-AZ পরিচালনা করে) বনাম আঞ্চলিক ব্যর্থতা (Multi-Region পরিচালনা করে) মধ্যে পার্থক্য করুন। Multi-Region-এর সাথে খরচ এবং জটিলতা উল্লেখযোগ্যভাবে বৃদ্ধি পায়।

---

## খরচ অপ্টিমাইজেশন

**EC2 মূল্য নির্ধারণ মডেল** *(অধ্যায় ২৭)*

On-Demand: পূর্ণ মূল্য, কোনো প্রতিশ্রুতি নেই। Reserved Instances (১ বা ৩ বছর): নির্দিষ্ট ইনস্ট্যান্স টাইপের জন্য ৩০-৭২% ছাড়। Savings Plans (Compute বা EC2 Instance): নমনীয়তার জন্য প্রতিশ্রুত ঘণ্টার ব্যয়। Spot: বাধাযোগ্য ওয়ার্কলোডের জন্য ৬০-৯০% বন্ধ।

পরীক্ষার সংকেত: "পূর্বাভাসযোগ্য ওয়ার্কলোডের জন্য খরচ কমান" → Savings Plans বা Reserved Instances। "ফল্ট-টলেরেন্ট ব্যাচ প্রক্রিয়াকরণ" → Spot। "অপ্রত্যাশিত বা স্বল্পমেয়াদী" → On-Demand।

---

**ডেটা ট্রান্সফার মূল্য নির্ধারণ** *(অধ্যায় ৩০)*

AWS-এ ইনবাউন্ড: বিনামূল্যে। একই-AZ: বিনামূল্যে। ক্রস-AZ: প্রতিটি দিকে $০.০১/GB। ক্রস-রিজিয়ন: $০.০২-০.০৮/GB। ইন্টারনেট (আউটবাউন্ড): ~$০.০৯/GB। NAT Gateway প্রক্রিয়াকরণ: $০.০৪৫/GB। CloudFront ডেটা ট্রান্সফার সরাসরি EC2-থেকে-ইন্টারনেটের চেয়ে সস্তা, এবং ক্যাশিং মোট ভলিউম কমায়।

পরীক্ষার সংকেত: "প্রাইভেট সাবনেট থেকে S3/DynamoDB-এ ডেটা ট্রান্সফার খরচ কমান" → Gateway Endpoints (বিনামূল্যে)। "অন্যান্য সার্ভিসের জন্য NAT Gateway খরচ কমান" → Interface Endpoints।

## পর্যবেক্ষণযোগ্যতা

**CloudWatch** *(সর্বত্র রেফারেন্স করা)*

মনিটরিং এবং পর্যবেক্ষণযোগ্যতা। CloudWatch Metrics: AWS সার্ভিস এবং কাস্টম অ্যাপ্লিকেশন থেকে সংখ্যাসূচক টাইম-সিরিজ ডেটা। CloudWatch Logs: লগ ডেটা সংগ্রহ, অনুসন্ধান এবং বিশ্লেষণ করুন। CloudWatch Alarms: মেট্রিক থ্রেশহোল্ডের উপর ভিত্তি করে বিজ্ঞপ্তি বা অটো স্কেলিং ট্রিগার করুন। CloudWatch Dashboards: মেট্রিক ভিজ্যুয়ালাইজ করুন।

মূল ধারণা: মেট্রিক dimensions, রিটেনশন পিরিয়ড, লগ গ্রুপ এবং লগ স্ট্রিম, মেট্রিক ফিল্টার, CloudWatch Agent (EC2 থেকে OS-স্তরের মেট্রিক এবং লগের জন্য), Container Insights।

---

**CloudTrail** *(সর্বত্র রেফারেন্স করা)*

আপনার AWS অ্যাকাউন্টে করা প্রতিটি API কল লগ করে: কে এটি করেছে, কোথা থেকে, কখন এবং প্রতিক্রিয়া কী ছিল। মাল্টি-রিজিয়ন trail S3-এ অনির্দিষ্টকালের জন্য লগ সংরক্ষণ করে। নিরাপত্তা অডিটিং, সম্মতি এবং ঘটনা তদন্তের জন্য ব্যবহৃত।

পরীক্ষার সংকেত: "কে সেই রিসোর্স মুছেছে?" "সমস্ত API কার্যকলাপ অডিট করুন" → CloudTrail।

---

**AWS Config** *(অধ্যায় ৩১-এ রেফারেন্স করা)*

সময়ের সাথে রিসোর্স কনফিগারেশন পরিবর্তন ট্র্যাক করে। সম্মতির নিয়মের বিরুদ্ধে রিসোর্স মূল্যায়ন করে। প্রতিটি রিসোর্সের জন্য প্রতিটি কনফিগারেশন পরিবর্তনের ইতিহাস রেকর্ড করে। প্রতিকারের জন্য Systems Manager-এর সাথে ইন্টিগ্রেট করে।

পরীক্ষার সংকেত: "এই রিসোর্স কি আমাদের নিরাপত্তা পলিসির সাথে সামঞ্জস্যপূর্ণ?" "গত সপ্তাহে এই রিসোর্সের কনফিগারেশন কেমন ছিল?" → AWS Config।
