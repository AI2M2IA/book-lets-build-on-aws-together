# পরিশিষ্ট A: AWS সার্ভিস দ্রুত রেফারেন্স

এই বইয়ে কভার করা প্রতিটি সার্ভিস, প্রবর্তনের ক্রমে। এটি একটি অধ্যয়ন রেফারেন্স এবং পরীক্ষার প্রস্তুতির সময় দ্রুত লুকআপ হিসাবে ব্যবহার করুন।

---

## কম্পিউট

**EC2 — Elastic Compute Cloud** *(অধ্যায় 4)*

ক্লাউডে ভার্চুয়াল মেশিন। আপনি ইনস্ট্যান্স টাইপ (CPU, মেমরি, স্টোরেজ), অপারেটিং সিস্টেম এবং অঞ্চল বেছে নিন। আপনি ঘণ্টা হিসাবে (On-Demand), প্রতিশ্রুতি অনুযায়ী (Reserved Instances / Savings Plans), অথবা স্পেয়ার-ক্যাপাসিটি স্লট অনুযায়ী (Spot) দেন। মৌলিক কম্পিউট প্রিমিটিভ।

মূল ধারণা: AMI (Amazon Machine Image), ইনস্ট্যান্স টাইপ (t3, m6g, r6g, c6g পরিবার), কী পেয়ার, ইনস্ট্যান্স প্রোফাইল, প্লেসমেন্ট গ্রুপ।

পরীক্ষার সংকেত: যখন পরিস্থিতিতে স্থায়ী, স্টেটফুল বা দীর্ঘ-চলমান কম্পিউট প্রয়োজন — EC2 বা ECS। যখন পরিস্থিতিতে স্বল্প-সময়ের, ইভেন্ট-ট্রিগার বা শূন্য-নিষ্ক্রিয়-খরচ কম্পিউট প্রয়োজন — Lambda।

---

**Auto Scaling + Application Load Balancer** *(অধ্যায় 7)*

Auto Scaling Groups (ASGs) লোডের উপর ভিত্তি করে EC2 ইনস্ট্যান্স যোগ এবং সরায়। Application Load Balancers (ALBs) ইনস্ট্যান্স জুড়ে ট্র্যাফিক বিতরণ করে এবং পথ বা হোস্ট দ্বারা রুট করে। একসাথে তারা অনুভূমিক স্কেলিং লেয়ার গঠন করে।

মূল ধারণা: লঞ্চ টেমপ্লেট, স্কেলিং পলিসি (target tracking, step, scheduled), স্বাস্থ্য পরীক্ষা, ALB টার্গেট গ্রুপ, লিসেনার নিয়ম, ওজনযুক্ত রাউটিং।

পরীক্ষার সংকেত: "পরিবর্তনশীল লোড পরিচালনা করুন" বা "AZ জুড়ে উচ্চ প্রাপ্যতা" → ASG + ALB।

---

**Lambda** *(অধ্যায় 20)*

সার্ভারলেস ফাংশন। আপনি কোড লেখেন; AWS ইভেন্টের প্রতিক্রিয়ায় এটি চালায়। কোনো সার্ভার পরিচালনা করতে হয় না। আপনি প্রতি ইনভোকেশন এবং প্রতি মিলিসেকেন্ড এক্সিকিউশনের জন্য দেন। স্বয়ংক্রিয়ভাবে হাজার হাজার সমকালীন এক্সিকিউশনে স্কেল করে।

মূল ধারণা: ইভেন্ট সোর্স (API Gateway, S3, SQS, EventBridge, Kinesis), এক্সিকিউশন রোল, কনকারেন্সি সীমা, reserved এবং provisioned concurrency, কোল্ড স্টার্ট, Layers, 15-মিনিটের সর্বোচ্চ সময়।

পরীক্ষার সংকেত: "সার্ভারলেস," "ইভেন্ট-চালিত," "স্বল্প-সময়ের কাজ," "কোনো নিষ্ক্রিয় খরচ নেই" → Lambda।

---

**ECS — Elastic Container Service** *(অধ্যায় 21)*

AWS-এ Docker কন্টেইনার চালায়। দুটি লঞ্চ টাইপ: EC2 (আপনি হোস্ট পরিচালনা করেন) এবং Fargate (AWS হোস্ট পরিচালনা করে)। ECS টাস্ক ডেফিনিশন, সার্ভিস, ক্লাস্টার শিডিউলিং এবং লোড ব্যালেন্সার ও সার্ভিস ডিসকভারির সাথে ইন্টিগ্রেশন পরিচালনা করে।

মূল ধারণা: টাস্ক ডেফিনিশন, ECS সার্ভিস, Fargate বনাম EC2 লঞ্চ টাইপ, ECR (কন্টেইনার রেজিস্ট্রি), টাস্ক IAM রোল, সার্ভিস অটো স্কেলিং।

পরীক্ষার সংকেত: "কন্টেইনারাইজড ওয়ার্কলোড," "মাইক্রোসার্ভিস," "AWS-এ Docker" → ECS (সার্ভারলেস কন্টেইনারের জন্য সাধারণত Fargate)।

---

**EKS — Elastic Kubernetes Service** *(অধ্যায় 21)*

পরিচালিত Kubernetes। AWS কন্ট্রোল প্লেন চালায়; আপনি ওয়ার্কার নোড চালান (EC2 বা Fargate)। EKS ব্যবহার করুন যখন আপনার দল ইতিমধ্যে Kubernetes ব্যবহার করে বা আপনার Kubernetes-নির্দিষ্ট বৈশিষ্ট্যের প্রয়োজন এমন ওয়ার্কলোড আছে।

পরীক্ষার সংকেত: "Kubernetes," "বিদ্যমান K8s ওয়ার্কলোড মাইগ্রেট করা প্রয়োজন" → EKS। "K8s ওভারহেড ছাড়াই শুধু কন্টেইনার দরকার" → ECS।

---

**AWS Batch** *(অধ্যায় 21)*

Docker কন্টেইনারের জন্য পরিচালিত ব্যাচ কম্পিউট। আপনি একটি জব (Docker ইমেজ + কমান্ড), একটি জব কিউ এবং একটি কম্পিউট এনভায়রনমেন্ট (EC2 বা Fargate) সংজ্ঞায়িত করেন। AWS Batch স্বয়ংক্রিয়ভাবে কম্পিউট প্রভিশন ও স্কেল করে, তারপর জব শেষ হলে এটি বন্ধ করে দেয়। খরচ কমাতে Spot Instances সমর্থন করে।

মূল ধারণা: জব ডেফিনিশন (কী চালাতে হবে), জব কিউ (যেখানে জব অপেক্ষা করে), কম্পিউট এনভায়রনমেন্ট (EC2 বা Fargate, On-Demand বা Spot), অ্যারে জব (একই জবের অনেক সমান্তরাল কপি চালানো)।

পরীক্ষার সংকেত: "Lambda-র 15-মিনিট টাইমআউট অতিক্রমকারী ব্যাচ প্রসেসিং," "কন্টেইনারে সসীম কম্পিউট জব," "AWS-এ HPC ওয়ার্কলোড" → AWS Batch।

---

**AWS Outposts** *(অধ্যায় 2)*

আপনার নিজের ডেটা সেন্টার বা কো-লোকেশন সুবিধায় ইনস্টল করা AWS হার্ডওয়্যারের একটি সম্পূর্ণরূপে পরিচালিত র‍্যাক। পাবলিক ক্লাউডের মতো একই AWS সার্ভিস, API এবং টুলিং (EC2, EBS, RDS, EKS, Outposts-এ S3) চালায় কিন্তু শারীরিকভাবে অন-প্রিমিসেস।

মূল ধারণা: অন-প্রিমিসেস একই AWS API, AWS ইনস্টলেশন ও প্যাচিং পরিচালনা করে, গ্রাহক র‍্যাক স্পেস ও পাওয়ার সরবরাহ করে, Local Gateway (LGW) Outposts-কে অন-প্রিমিসেস নেটওয়ার্কের সাথে সংযুক্ত করে।

পরীক্ষার সংকেত: "আপনার নিজের ডেটা সেন্টারে AWS চালান," "ডেটা রেসিডেন্সির জন্য কম্পিউট অন-প্রিমিসেস থাকা প্রয়োজন," "ইন্টারনেট নির্ভরতা ছাড়া AWS API" → Outposts।

---

**AWS Wavelength** *(অধ্যায় 2)*

5G টেলিকমিউনিকেশন প্রদানকারীদের নেটওয়ার্কের ভিতরে স্থাপিত AWS অবকাঠামো। Wavelength Zones 5G নেটওয়ার্ক এজে অবস্থিত, মোবাইল ডিভাইসে একক-সংখ্যা মিলিসেকেন্ড লেটেন্সি সক্ষম করে।

মূল ধারণা: Wavelength Zones হল টেলিকম নেটওয়ার্কের মধ্যে AWS Regions-এর সম্প্রসারণ, ডিভাইস এবং Wavelength Zone-এর মধ্যে ট্র্যাফিক ক্যারিয়ার নেটওয়ার্কে থাকে।

পরীক্ষার সংকেত: "5G মোবাইল ব্যবহারকারীদের একক-সংখ্যা মিলিসেকেন্ড লেটেন্সি," "মোবাইল AR/VR," "মোবাইলে রিয়েল-টাইম গেমিং," "স্বয়ংক্রিয় যানবাহন টেলিমেট্রি" → Wavelength।

---

**AWS Application Migration Service (MGN)** *(অধ্যায় 25)*

রিহোস্ট (lift-and-shift) মাইগ্রেশন সার্ভিস। একটি এজেন্ট সোর্স সার্ভারের ডিস্কগুলিকে ব্লক বাই ব্লক AWS-এ একটি কম খরচের স্টেজিং এরিয়ায় রেপ্লিকেট করে; আপনি চাহিদা অনুযায়ী টেস্ট কপি লঞ্চ করেন; কাটওভারে, MGN রেপ্লিকেট করা সার্ভারগুলিকে নেটিভ EC2 ইনস্ট্যান্সে রূপান্তর করে। কোনো অ্যাপ্লিকেশন পরিবর্তন প্রয়োজন নেই।

মূল ধারণা: ব্লক-স্তরের একটানা রেপ্লিকেশন, স্টেজিং এরিয়া, কাটওভারের আগে টেস্ট লঞ্চ, "7 Rs" মাইগ্রেশন কৌশল (MGN = রিহোস্ট)।

পরীক্ষার সংকেত: "কোড পরিবর্তন ছাড়াই দ্রুত শত শত VM মাইগ্রেট করুন," "EC2-তে সার্ভার lift-and-shift করুন" → MGN। DataSync *ফাইল* সরায়; DMS *ডেটাবেস* সরায়; MGN *সম্পূর্ণ সার্ভার* সরায়।

## স্টোরেজ

**S3 — Simple Storage Service** *(অধ্যায় 5)*

অবজেক্ট স্টোরেজ। সীমাহীন ক্যাপাসিটি, 99.999999999% (এগারো নয়) স্থায়িত্ব। বাকেটে অবজেক্ট হিসাবে ফাইল সংরক্ষণ করে। বাকেট একটি অঞ্চলে থাকে। অবজেক্ট 0 বাইট থেকে 5TB পর্যন্ত হতে পারে।

মূল ধারণা: বাকেট পলিসি, অবজেক্ট ACL, ভার্সনিং, স্ট্যাটিক ওয়েবসাইট হোস্টিং, presigned URL, মাল্টিপার্ট আপলোড, Transfer Acceleration, স্টোরেজ ক্লাস (Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive, এবং একক-AZ, লেটেন্সি-সংকটপূর্ণ ডিরেক্টরি-বাকেট ওয়ার্কলোডের জন্য S3 Express One Zone)।

পরীক্ষার সংকেত: "ফাইল সংরক্ষণ এবং পুনরুদ্ধার করুন," "স্ট্যাটিক অ্যাসেট," "ব্যাকআপ," "ডেটা লেক" → S3। সঠিক স্টোরেজ ক্লাস অ্যাক্সেস ফ্রিকোয়েন্সি এবং পুনরুদ্ধার গতির উপর নির্ভর করে।

---

**EBS — Elastic Block Store** *(অধ্যায় 6)*

একটি একক EC2 ইনস্ট্যান্সের সাথে সংযুক্ত ব্লক স্টোরেজ। একটি হার্ড ড্রাইভের মতো কাজ করে। ইনস্ট্যান্স লাইফসাইকেল থেকে স্বাধীনভাবে টিকে থাকে (আপনি ডিট্যাচ এবং পুনরায় সংযুক্ত করতে পারেন)। সবচেয়ে সাধারণ ধরন: gp3 (সাধারণ উদ্দেশ্য SSD, ডিফল্ট), io2 (ডেটাবেসের জন্য provisioned IOPS), st1 (ক্রমিক রিডের জন্য থ্রুপুট-অপ্টিমাইজড HDD)।

মূল ধারণা: স্ন্যাপশট (ইনক্রিমেন্টাল, S3-এ সংরক্ষিত), এনক্রিপশন (KMS), Multi-Attach (io1/io2 শুধুমাত্র), IOPS এবং থ্রুপুট প্রভিশনিং।

পরীক্ষার সংকেত: "EC2-এর জন্য স্থায়ী স্টোরেজ," "ডেটাবেস স্টোরেজ," "লো-লেটেন্সি ব্লক অ্যাক্সেস প্রয়োজন" → EBS।

---

**EFS — Elastic File System** *(অধ্যায় 6)*

ভাগ করা ফাইল সিস্টেম, একসাথে একাধিক EC2 ইনস্ট্যান্স থেকে অ্যাক্সেসযোগ্য। NFS প্রোটোকল। স্বয়ংক্রিয়ভাবে স্কেল করে। EBS-এর চেয়ে প্রতি GB বেশি ব্যয়বহুল। স্টোরেজ ক্লাসের মধ্যে রয়েছে Standard, Infrequent Access এবং Archive। Intelligent-Tiering স্বয়ংক্রিয়ভাবে ফাইল সরায়।

পরীক্ষার সংকেত: "ভাগ করা ফাইল সিস্টেম," "একাধিক EC2 ইনস্ট্যান্সের একই ফাইল প্রয়োজন," "NFS" → EFS।

---

**FSx পরিবার** *(অধ্যায় 6)*

নামকৃত প্রযুক্তির জন্য পরিচালিত ফাইল সার্ভার। FSx for Windows File Server: SMB প্রোটোকল, NTFS, Active Directory ইন্টিগ্রেশন, Multi-AZ। FSx for Lustre: HPC/ML-এর জন্য সমান্তরাল হাই-পারফরম্যান্স ফাইল সিস্টেম, S3 অবজেক্টগুলিকে ফাইল হিসাবে উপস্থাপন করে (lazy loading)। FSx for NetApp ONTAP: মাল্টি-প্রোটোকল (NFS + SMB + iSCSI), স্ন্যাপশট, SnapMirror রেপ্লিকেশন। FSx for OpenZFS: লো-লেটেন্সি NFS, তাৎক্ষণিক স্ন্যাপশট এবং রাইটেবল ক্লোন।

পরীক্ষার সংকেত: "SMB/Active Directory" → FSx for Windows। "S3 ডেটায় HPC/ML প্রশিক্ষণ" → FSx for Lustre। "একই ডেটায় NFS এবং SMB / NetApp মাইগ্রেশন" → FSx for ONTAP। "ZFS মাইগ্রেশন / তাৎক্ষণিক ক্লোন" → FSx for OpenZFS।

---

**S3 স্টোরেজ ক্লাস এবং লাইফসাইকেল পলিসি** *(অধ্যায় 23)*

S3 Intelligent-Tiering অ্যাক্সেস ফ্রিকোয়েন্সির উপর ভিত্তি করে স্বয়ংক্রিয়ভাবে অবজেক্টগুলিকে অ্যাক্সেস টায়ারের মধ্যে সরায়। লাইফসাইকেল পলিসি বয়সের নিয়মের উপর ভিত্তি করে ক্লাসের মধ্যে অবজেক্ট ট্রানজিশন করে (Standard → Standard-IA → Glacier)। Glacier স্টোরেজ ক্লাসের পুনরুদ্ধার বিলম্ব মিনিট (Glacier Instant) থেকে 12 ঘণ্টা (Glacier Deep Archive) পর্যন্ত।

পরীক্ষার সংকেত: "বিরলভাবে অ্যাক্সেস করা ডেটার স্টোরেজ খরচ কমান" → লাইফসাইকেল পলিসি, Intelligent-Tiering, বা Glacier।

---

**AWS Storage Gateway** *(অধ্যায় 6)*

হাইব্রিড স্টোরেজ সার্ভিস যা অন-প্রিমিসেস পরিবেশকে AWS স্টোরেজের সাথে সংযুক্ত করে। অ্যাপ্লিকেশনগুলি ইতিমধ্যে বোঝে এমন প্রোটোকলের মাধ্যমে স্টোরেজ উপস্থাপন করে যখন ডেটা S3, S3 Glacier-এ বা EBS স্ন্যাপশট হিসাবে স্থায়ী করে।

মূল ধারণা: File Gateway (NFS/SMB → S3), Volume Gateway (iSCSI, cached বা stored মোড), Tape Gateway (ভার্চুয়াল টেপ লাইব্রেরি → Glacier)।

পরীক্ষার সংকেত: "অন-প্রিমিসেস অ্যাপ্লিকেশনের কোড পরিবর্তন ছাড়াই ক্লাউড স্টোরেজ প্রয়োজন" → Storage Gateway। "টেপ ব্যাকআপ প্রতিস্থাপন করুন" → Tape Gateway।

---

**AWS DataSync** *(অধ্যায় 25)*

এজেন্ট-ভিত্তিক ডেটা মাইগ্রেশন এবং রেপ্লিকেশন সার্ভিস। একটি হালকা এজেন্ট NFS বা SMB-এর মাধ্যমে অন-প্রিমিসেস ফাইল সার্ভারের সাথে সংযুক্ত হয় এবং শেয়ারগুলিকে S3, EFS, বা FSx-এ সিঙ্ক্রোনাইজ করে — শিডিউলিং, ব্যান্ডউইথ থ্রটলিং এবং ইন্টিগ্রিটি যাচাইকরণ অন্তর্নির্মিত।

মূল ধারণা: DataSync এজেন্ট (অন-প্রিমিসেস বা EC2-তে VM), NFS/SMB সোর্স, S3/EFS/FSx গন্তব্য, শিডিউল করা ইনক্রিমেন্টাল ট্রান্সফার।

পরীক্ষার সংকেত: "অন-প্রিমিসেস NAS থেকে নেটওয়ার্কের মাধ্যমে বিপুল সংখ্যক ফাইল AWS-এ মাইগ্রেট বা একটানা সিঙ্ক করুন" → DataSync।

---

**AWS Transfer Family** *(অধ্যায় 25)*

স্টোরেজ গন্তব্য হিসাবে S3 বা EFS দ্বারা সমর্থিত সম্পূর্ণরূপে পরিচালিত SFTP, FTPS এবং FTP সার্ভার। ক্লায়েন্টরা তাদের বিদ্যমান SFTP সফটওয়্যার দিয়ে সংযুক্ত হয়; আপলোড করা ফাইল সরাসরি একটি বাকেট বা ফাইল সিস্টেমে অবতরণ করে।

মূল ধারণা: পরিচালিত এন্ডপয়েন্ট (ঐচ্ছিকভাবে স্ট্যাটিক IP সহ), S3 বা EFS ব্যাকিং স্টোরেজ, বহিরাগত অংশীদারদের জন্য বিদ্যমান-প্রোটোকল সামঞ্জস্যতা।

পরীক্ষার সংকেত: "অংশীদারদের অবশ্যই SFTP-এর মাধ্যমে আপলোড চালিয়ে যেতে হবে, কিন্তু ফাইলগুলি S3-তে অবতরণ করা উচিত" → Transfer Family।

---

**AWS Snow Family** *(অধ্যায় 25)*

অফলাইন, বাল্ক ডেটা মাইগ্রেশনের জন্য শারীরিক ডেটা ট্রান্সফার ডিভাইস। Snowball Edge Storage Optimized: 80 TB ব্যবহারযোগ্য, কঠিন এনক্লোজার, আপনার অবস্থানে পাঠানো হয়; আপনি স্থানীয়ভাবে ডেটা লোড করেন এবং S3-তে ইনজেশনের জন্য এটি ফেরত পাঠান।

মূল ধারণা: প্রথমে ট্রান্সফারের গণিত করুন — যদি নেটওয়ার্ক ট্রান্সফারে প্রায় এক সপ্তাহ বা তার বেশি সময় লাগে, একটি শারীরিক ডিভাইস জেতে। *লিগ্যাসি নোট (2026)*: AWS পরিবারটি অবসর দিচ্ছে — Snowmobile (2024) এবং Snowcone (2024-এর শেষ) চলে গেছে, এবং Snow ডিভাইস নভেম্বর 2025-এ নতুন গ্রাহকদের জন্য বন্ধ হয়ে গেছে (AWS এখন DataSync এবং Data Transfer Terminals-এর দিকে নির্দেশ করে)। SAA-C03 প্রশ্নভাণ্ডার এর আগের, তাই পরীক্ষা এখনও উত্তর হিসাবে Snowball আশা করে।

পরীক্ষার সংকেত: "পেটাবাইট-স্কেল মাইগ্রেশন," "সীমিত ব্যান্ডউইথ, সপ্তাহের ট্রান্সফার সময়" → Snow Family।

**AWS Backup** *(অধ্যায় 18 এবং 23)*

EBS, RDS, DynamoDB, EFS এবং Storage Gateway জুড়ে কেন্দ্রীভূত, পলিসি-ভিত্তিক ব্যাকআপ সার্ভিস। ব্যাকআপ প্ল্যান শিডিউল এবং রিটেনশন সংজ্ঞায়িত করে; ভল্ট রিকভারি পয়েন্ট সংরক্ষণ করে।

মূল ধারণা: ব্যাকআপ প্ল্যান এবং ভল্ট, ক্রস-রিজিয়ন এবং ক্রস-অ্যাকাউন্ট কপি, অপরিবর্তনীয়তার জন্য Vault Lock।

পরীক্ষার সংকেত: "একাধিক AWS সার্ভিস জুড়ে ব্যাকআপ কেন্দ্রীভূত এবং স্বয়ংক্রিয় করুন," "র‍্যানসমওয়্যার/অ্যাকাউন্ট-আপস সুরক্ষার জন্য ক্রস-অ্যাকাউন্ট ব্যাকআপ কপি" → AWS Backup।

## ডেটাবেস

**RDS — Relational Database Service** *(অধ্যায় 8)*

পরিচালিত রিলেশনাল ডেটাবেস। সমর্থিত ইঞ্জিন: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server এবং Aurora (AWS-এর মালিকানাধীন ইঞ্জিন)। AWS ব্যাকআপ, প্যাচিং, ফেলওভার এবং রেপ্লিকেশন পরিচালনা করে। আপনি স্কিমা ডিজাইন, কোয়েরি এবং ইনস্ট্যান্স সাইজিং পরিচালনা করেন।

মূল ধারণা: Multi-AZ ডিপ্লয়মেন্ট (স্বয়ংক্রিয় ফেলওভার, সিঙ্ক্রোনাস রেপ্লিকেশন), Read Replicas (অ্যাসিঙ্ক্রোনাস, রিড স্কেলিংয়ের জন্য), স্বয়ংক্রিয় ব্যাকআপ (1-35 দিন রিটেনশন), ম্যানুয়াল স্ন্যাপশট (মুছা না হওয়া পর্যন্ত রাখা), RDS Proxy (কানেকশন পুলিং)।

পরীক্ষার সংকেত: "রিলেশনাল ডেটাবেস," "ACID লেনদেন," "বিদ্যমান SQL ওয়ার্কলোড" → RDS বা Aurora।

---

**Aurora** *(অধ্যায় 24)*

AWS-এর রিলেশনাল ডেটাবেস ইঞ্জিন, MySQL এবং PostgreSQL-এর সাথে সামঞ্জস্যপূর্ণ। বিতরণকৃত স্টোরেজ ইঞ্জিন যা 3টি AZ-এ 6টি কপিতে ডেটা রেপ্লিকেট করে। সাধারণত MySQL-এর 5x দ্রুত। Aurora Serverless v2 স্বয়ংক্রিয়ভাবে ক্যাপাসিটি স্কেল করে (ACUs — Aurora Capacity Units-এ মাপা) এবং, সমর্থিত ইঞ্জিন সংস্করণে, কোনো কানেকশন খোলা না থাকলে 0 ACUs-এ auto-pause করতে পারে।

মূল ধারণা: Aurora ক্লাস্টার (writer + একটি একক reader endpoint-এর পিছনে সর্বোচ্চ 15টি Aurora Replicas), Aurora Global Database (< 1 সেকেন্ড রেপ্লিকেশন ল্যাগ সহ ক্রস-রিজিয়ন রিড রেপ্লিকা), Aurora Serverless v2, ACUs, auto-pause/resume আচরণ।

পরীক্ষার সংকেত: "হাই-পারফরম্যান্স রিলেশনাল ডেটাবেস," "MySQL/PostgreSQL সামঞ্জস্যপূর্ণ," "গ্লোবাল রিড," "পরিবর্তনশীল ওয়ার্কলোড" → Aurora।

---

**DynamoDB** *(অধ্যায় 9)*

সম্পূর্ণরূপে পরিচালিত NoSQL ডেটাবেস। কী-ভ্যালু এবং ডকুমেন্ট মডেল। একক-সংখ্যা মিলিসেকেন্ড পারফরম্যান্স সহ যেকোনো থ্রুপুটে স্কেল করে। দুটি ক্যাপাসিটি মোড: on-demand (প্রতি অনুরোধে দেন) এবং provisioned (প্রতি ঘণ্টায় ক্যাপাসিটি ইউনিটে দেন, Auto Scaling সহ)।

মূল ধারণা: পার্টিশন কী (আবশ্যক), সর্ট কী (ঐচ্ছিক), Global Secondary Index (GSI), Local Secondary Index (LSI), DynamoDB Streams (চেঞ্জ ডেটা ক্যাপচার), DynamoDB Accelerator (DAX) — ইন-মেমরি ক্যাশ, TTL (Time to Live), লেনদেন।

পরীক্ষার সংকেত: "হাই-থ্রুপুট কী-ভিত্তিক অ্যাক্সেস," "নমনীয় স্কিমা," "সার্ভারলেস NoSQL" → DynamoDB।

---

**ElastiCache** *(অধ্যায় 10)*

পরিচালিত ইন-মেমরি ক্যাশিং। দুটি ইঞ্জিন: Redis (স্থায়ী, pub/sub, Lua স্ক্রিপ্টিং, ডেটা স্ট্রাকচার) এবং Memcached (বিশুদ্ধ ক্যাশ, সহজতর, মাল্টি-থ্রেডেড)। ডেটাবেস লোড কমাতে এবং প্রায়শই-পঠিত ডেটা মাইক্রোসেকেন্ডে পরিবেশন করতে ব্যবহার করুন।

মূল ধারণা: cache-aside প্যাটার্ন, write-through প্যাটার্ন, এভিকশন পলিসি, TTL, ক্লাস্টার মোড (Redis), স্বয়ংক্রিয় ফেলওভার সহ Multi-AZ।

পরীক্ষার সংকেত: "ডেটাবেস লোড কমান," "সাব-মিলিসেকেন্ড রিড লেটেন্সি," "সেশন ম্যানেজমেন্ট," "রিয়েল-টাইম লিডারবোর্ড" → ElastiCache Redis।

---

**Amazon MemoryDB for Redis** *(অধ্যায় 10)*

টেকসই, Redis-সামঞ্জস্যপূর্ণ, ইন-মেমরি প্রাইমারি ডেটাবেস। ElastiCache-এর বিপরীতে (যা একটি ক্যাশ যেখানে ডেটা হারানো গ্রহণযোগ্য), MemoryDB একটি Multi-AZ ট্রানজেকশন লগ সংরক্ষণ করে এবং স্থায়িত্বের নিশ্চয়তা দেয়। আপনি MemoryDB-কে আপনার প্রাইমারি ডেটাবেস হিসাবে ব্যবহার করতে পারেন — কেবল অন্য ডেটাবেসের সামনে একটি ক্যাশ নয়।

মূল ধারণা: Redis API সামঞ্জস্যতা, Multi-AZ ট্রানজেকশন লগ (স্থায়িত্বের নিশ্চয়তা), ইন-মেমরি পারফরম্যান্স, প্রাইমারি ডেটাবেস (ক্যাশ লেয়ার নয়)।

পরীক্ষার সংকেত: "Redis-সামঞ্জস্যপূর্ণ এবং ডেটা হারানো গ্রহণযোগ্য নয়," "টেকসই ইন-মেমরি ডেটাবেস" → MemoryDB। "Redis ক্যাশ হিসাবে, ডেটা হারানো গ্রহণযোগ্য" → ElastiCache Redis।

---

**উদ্দেশ্য-নির্মিত ডেটাবেস** *(অধ্যায় 9, 10 এবং 24)*

ডেটার আকার ইঞ্জিনের সাথে মেলান। DocumentDB: MongoDB-সামঞ্জস্যপূর্ণ ডকুমেন্ট। Neptune: গ্রাফ ডেটাবেস (সম্পর্ক, ট্রাভার্সাল — Gremlin/SPARQL)। Keyspaces: Cassandra-সামঞ্জস্যপূর্ণ ওয়াইড-কলাম। Timestream: টাইম-সিরিজ (বর্তমান অফার: Timestream for InfluxDB)। MemoryDB: টেকসই Redis-সামঞ্জস্যপূর্ণ *প্রাইমারি* ডেটাবেস (বনাম ElastiCache = ক্যাশ)। QLDB ("অপরিবর্তনীয় ক্রিপ্টোগ্রাফিক লেজার") 2025-এ বন্ধ করা হয়েছিল — একটি লিগ্যাসি ডিস্ট্র্যাক্টর হিসাবে গণ্য করুন।

পরীক্ষার সংকেত: "সোশ্যাল গ্রাফ / রেকমেন্ডেশন / জালিয়াতি রিং" → Neptune। "MongoDB" → DocumentDB। "Cassandra" → Keyspaces। "সময়ের সাথে IoT টেলিমেট্রি" → Timestream।

---

**AWS DMS — Database Migration Service** *(অধ্যায় 8)*

ন্যূনতম ডাউনটাইম সহ ডেটাবেস AWS-এ মাইগ্রেট করে। মাইগ্রেশন চলাকালীন সোর্স এবং টার্গেটকে সিঙ্কে রাখতে full load (প্রাথমিক কপি) এবং CDC (Change Data Capture) সমর্থন করে। একই ইঞ্জিন টাইপের মধ্যে মাইগ্রেট করার সময় (MySQL → MySQL, PostgreSQL → PostgreSQL), সরাসরি DMS ব্যবহার করুন। ভিন্ন ইঞ্জিন টাইপের মধ্যে মাইগ্রেট করার সময় (Oracle → Aurora PostgreSQL), প্রথমে স্কিমা রূপান্তর করতে AWS Schema Conversion Tool (SCT) ব্যবহার করুন, তারপর ডেটার জন্য DMS।

মূল ধারণা: রেপ্লিকেশন ইনস্ট্যান্স, সোর্স এবং টার্গেট এন্ডপয়েন্ট, full load + CDC, হেটেরোজিনিয়াস মাইগ্রেশনের জন্য SCT (Schema Conversion Tool)।

পরীক্ষার সংকেত: "ন্যূনতম ডাউনটাইম সহ ডেটাবেস মাইগ্রেট করুন" → DMS। "Oracle থেকে Aurora" বা যেকোনো হেটেরোজিনিয়াস মাইগ্রেশন → SCT + DMS। "একই ইঞ্জিন, একই টাইপ" → সরাসরি DMS।

## নেটওয়ার্কিং

**VPC — Virtual Private Cloud** *(অধ্যায় 11)*

AWS-এর মধ্যে একটি বিচ্ছিন্ন নেটওয়ার্ক। একটি অঞ্চলের সমস্ত AZ জুড়ে বিস্তৃত। আপনি IP অ্যাড্রেস স্পেস (CIDR ব্লক) সংজ্ঞায়িত করেন, সাবনেট (পাবলিক বা প্রাইভেট) তৈরি করেন, রুট টেবিল কনফিগার করেন এবং নিরাপত্তা গোষ্ঠী ও NACL-এর মাধ্যমে অ্যাক্সেস নিয়ন্ত্রণ করেন।

মূল ধারণা: পাবলিক সাবনেট (Internet Gateway-তে রুট), প্রাইভেট সাবনেট (আউটবাউন্ডের জন্য NAT Gateway-তে রুট), Internet Gateway (ইন্টারনেটে ইনবাউন্ড + আউটবাউন্ড), NAT Gateway (প্রাইভেট ইনস্ট্যান্সের জন্য শুধুমাত্র আউটবাউন্ড), VPC Peering (দুটি VPC সংযুক্ত করুন), VPC Endpoints (ইন্টারনেট ছাড়া AWS সার্ভিসে সংযুক্ত হন)।

পরীক্ষার সংকেত: "AWS-এ প্রাইভেট নেটওয়ার্ক," "ইন্টারনেট থেকে রিসোর্স বিচ্ছিন্ন করুন," "নেটওয়ার্ক ট্র্যাফিক নিয়ন্ত্রণ করুন" → VPC।

---

**নিরাপত্তা গোষ্ঠী এবং NACL** *(অধ্যায় 15)*

নিরাপত্তা গোষ্ঠী হল ইনস্ট্যান্স স্তরে stateful ফায়ারওয়াল — শুধুমাত্র অনুমতির নিয়ম, রিটার্ন ট্র্যাফিক স্বয়ংক্রিয়। NACL (Network Access Control Lists) হল সাবনেট স্তরে stateless ফায়ারওয়াল — ইনবাউন্ড এবং আউটবাউন্ড উভয় নিয়ম প্রয়োজন, নিয়ম নম্বর অনুসারে ক্রমে মূল্যায়ন করা হয়।

পরীক্ষার সংকেত: "সাবনেট অ্যাক্সেস থেকে একটি নির্দিষ্ট IP ব্লক করুন" → NACL। "একটি ইনস্ট্যান্সে/থেকে ট্র্যাফিক নিয়ন্ত্রণ করুন" → নিরাপত্তা গোষ্ঠী।

---

**Route 53** *(অধ্যায় 12)*

AWS-এর DNS সার্ভিস এবং ডোমেইন রেজিস্ট্রার। AWS রিসোর্স এবং বহিরাগত এন্ডপয়েন্টে ইন্টারনেট ট্র্যাফিক রুট করে। রাউটিং পলিসি: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, Multivalue answer।

মূল ধারণা: হোস্টেড জোন (পাবলিক এবং প্রাইভেট), রেকর্ড টাইপ (A, AAAA, CNAME, Alias), স্বাস্থ্য পরীক্ষা, Traffic Flow (ভিজ্যুয়াল পলিসি এডিটর — লক্ষ্য করুন যে geoproximity রেকর্ডে সরাসরি রাউটিং পলিসি হিসাবেও উপলব্ধ, একটি সামঞ্জস্যযোগ্য বায়াস সহ, Traffic Flow প্রয়োজন ছাড়াই)।

পরীক্ষার সংকেত: "DNS রাউটিং," "অঞ্চলের মধ্যে ফেলওভার," "লেটেন্সি বা অবস্থানের উপর ভিত্তি করে রুট করুন" → উপযুক্ত রাউটিং পলিসি সহ Route 53।

---

**CloudFront** *(অধ্যায় 13)*

কন্টেন্ট ডেলিভারি নেটওয়ার্ক (CDN)। এজ লোকেশনে কন্টেন্ট ক্যাশ করে (বিশ্বব্যাপী 750+ পয়েন্ট অফ প্রেজেন্স)। শেষ ব্যবহারকারীদের জন্য লেটেন্সি কমায়। ক্যাশিংয়ের মাধ্যমে অরিজিন ট্রান্সফার খরচ কমায়। অরিজিন হিসাবে S3, EC2, ALB এবং API Gateway-এর সাথে ইন্টিগ্রেট হয়।

মূল ধারণা: ডিস্ট্রিবিউশন, অরিজিন, behaviors (অরিজিনে পথ-ভিত্তিক রাউটিং), TTL (ক্যাশ নিয়ন্ত্রণ), ক্যাশ ইনভ্যালিডেশন, সাইন করা URL এবং কুকি (অ্যাক্সেস নিয়ন্ত্রণ), Lambda@Edge এবং CloudFront Functions (এজে কোড চালান), Origin Shield (অরিজিন লোড কমান)।

পরীক্ষার সংকেত: "গ্লোবাল লো লেটেন্সি," "স্ট্যাটিক কন্টেন্ট ক্যাশ করুন," "অরিজিন লোড কমান," "Shield দিয়ে DDoS থেকে সুরক্ষা করুন" → CloudFront।

---

**Direct Connect এবং VPN** *(অধ্যায় 25)*

AWS Direct Connect হল আপনার অন-প্রিমিসেস ডেটা সেন্টার থেকে AWS-এ একটি ডেডিকেটেড শারীরিক নেটওয়ার্ক সংযোগ। পাবলিক ইন্টারনেট বাইপাস করে। আরও সামঞ্জস্যপূর্ণ ব্যান্ডউইথ এবং লেটেন্সি। AWS Site-to-Site VPN হল পাবলিক ইন্টারনেটের উপর একটি এনক্রিপ্টেড টানেল — দ্রুত সেটআপ, কম খরচ, কিন্তু পরিবর্তনশীল পারফরম্যান্স।

মূল ধারণা: Virtual Interface (VIF), Direct Connect Gateway (একাধিক অঞ্চলে সংযুক্ত হন), Transit Gateway (হাব-অ্যান্ড-স্পোক নেটওয়ার্ক টপোলজি), VPN টানেল রিডানডেন্সি।

পরীক্ষার সংকেত: "AWS-এ ডেডিকেটেড প্রাইভেট সংযোগ" → Direct Connect। "এনক্রিপ্টেড সংযোগ, দ্রুত সেটআপ" → VPN। "একাধিক VPC সংযুক্ত করুন" → Transit Gateway।

---

**VPC Endpoints** *(অধ্যায় 30)*

পাবলিক ইন্টারনেট বা NAT Gateway ব্যবহার না করে প্রাইভেট রিসোর্সগুলিকে AWS সার্ভিসের সাথে সংযুক্ত করুন। Gateway Endpoints: বিনামূল্যে, শুধুমাত্র S3 এবং DynamoDB-এর জন্য উপলব্ধ। Interface Endpoints (PrivateLink): প্রতি ঘণ্টা + প্রতি GB মূল্য, বেশিরভাগ AWS সার্ভিসের জন্য উপলব্ধ।

পরীক্ষার সংকেত: "প্রাইভেট সাবনেটে EC2 S3/DynamoDB কল করে — NAT Gateway খরচ কমান" → Gateway Endpoint (বিনামূল্যে)। "প্রাইভেট সাবনেট থেকে SQS, SSM, Secrets Manager-এ প্রাইভেট সংযোগ" → Interface Endpoint।

---

**AWS Client VPN** *(অধ্যায় 11)*

পরিচালিত OpenVPN এন্ডপয়েন্ট যা পৃথক ডিভাইসকে (ল্যাপটপ, ওয়ার্কস্টেশন) ইন্টারনেটের মাধ্যমে নিরাপদে একটি VPC-তে সংযুক্ত হতে দেয়। প্রমাণীকরণ বিকল্প: Active Directory, একটি আইডেন্টিটি প্রদানকারীর সাথে SAML 2.0 ফেডারেশন, বা mutual TLS (সার্টিফিকেট-ভিত্তিক)। split-tunnel (শুধুমাত্র VPC-আবদ্ধ ট্র্যাফিক টানেলের মধ্য দিয়ে যায়) এবং full-tunnel (সমস্ত ট্র্যাফিক AWS-এর মাধ্যমে রুট হয়) সমর্থন করে।

মূল ধারণা: Client VPN এন্ডপয়েন্ট, টার্গেট নেটওয়ার্ক (VPC সাবনেট অ্যাসোসিয়েশন), অনুমোদন নিয়ম, split-tunnel বনাম full-tunnel।

পরীক্ষার সংকেত: "দূরবর্তী ইঞ্জিনিয়ারদের বাড়ি থেকে একটি VPC-তে নিরাপদ অ্যাক্সেস প্রয়োজন," "পৃথক ডিভাইস থেকে VPC সংযোগ" → Client VPN। তুলনা: Site-to-Site VPN = নেটওয়ার্ক-টু-নেটওয়ার্ক। Client VPN = ডিভাইস-টু-নেটওয়ার্ক।

---

**Network Load Balancer (NLB) এবং Gateway Load Balancer (GWLB)** *(অধ্যায় 7)*

NLB Layer 4 (TCP/UDP/TLS)-এ কাজ করে: কোনো HTTP পরিদর্শন নেই, শুধু চরম গতিতে প্যাকেট রাউটিং — প্রতি সেকেন্ডে লক্ষ লক্ষ অনুরোধ, প্রতি AZ-এ একটি স্ট্যাটিক IP এবং সোর্স IP সংরক্ষণ সহ। GWLB Layer 3-এ কাজ করে এবং একটি উদ্দেশ্যে বিদ্যমান: তৃতীয়-পক্ষের ভার্চুয়াল নেটওয়ার্ক অ্যাপ্লায়েন্স (ফায়ারওয়াল, IDS/IPS, ডিপ প্যাকেট ইন্সপেকশন) ইনলাইন ট্র্যাফিক প্রবাহে সন্নিবেশ করা।

মূল ধারণা: NLB = Layer 4, স্ট্যাটিক IP, অতি-নিম্ন লেটেন্সি, নন-HTTP প্রোটোকল। GWLB = Layer 3, GENEVE এনক্যাপসুলেশন, একটি একক প্রবেশ পয়েন্টের পিছনে অ্যাপ্লায়েন্স ফ্লিট। ALB = Layer 7 (পথ/হোস্ট রাউটিং)।

পরীক্ষার সংকেত: "প্রতি সেকেন্ডে লক্ষ লক্ষ TCP অনুরোধ," "লোড ব্যালেন্সারের জন্য স্ট্যাটিক IP," "সোর্স IP সংরক্ষণ করুন" → NLB। "ট্র্যাফিক পাথে তৃতীয়-পক্ষের নিরাপত্তা অ্যাপ্লায়েন্স সন্নিবেশ করুন" → GWLB।

---

**AWS Global Accelerator** *(অধ্যায় 25)*

পাবলিক ইন্টারনেট অতিক্রম করার পরিবর্তে নিকটতম এজ লোকেশনে AWS-এর প্রাইভেট গ্লোবাল ব্যাকবোনে ব্যবহারকারীর ট্র্যাফিক রুট করে। দুটি স্ট্যাটিক Anycast IP অ্যাড্রেস সরবরাহ করে যা এক বা একাধিক অঞ্চলে আপনার ALB, NLB বা EC2 ইনস্ট্যান্সের সামনে থাকে। *ডায়নামিক* (নন-ক্যাশেবল) ট্র্যাফিকের জন্য লেটেন্সি এবং সামঞ্জস্যতা উন্নত করে।

মূল ধারণা: স্ট্যাটিক Anycast IP, AWS ব্যাকবোনে এজ অনবোর্ডিং, সেকেন্ডে স্বাস্থ্য-পরীক্ষা-ভিত্তিক আঞ্চলিক ফেলওভার, ট্র্যাফিক ডায়াল সহ এন্ডপয়েন্ট গ্রুপ।

পরীক্ষার সংকেত: "গ্লোবাল ব্যবহারকারী, ডায়নামিক/নন-HTTP ট্র্যাফিক, স্ট্যাটিক IP, দ্রুত আঞ্চলিক ফেলওভার" → Global Accelerator। "ক্যাশেবল/স্ট্যাটিক কন্টেন্ট" → পরিবর্তে CloudFront।

## নিরাপত্তা এবং আইডেন্টিটি

**IAM — Identity and Access Management** *(অধ্যায় 3 এবং 14)*

আপনার AWS অ্যাকাউন্টে কে কী করতে পারে তা নিয়ন্ত্রণ করে। ব্যবহারকারী (দীর্ঘমেয়াদী ক্রেডেনশিয়াল), গ্রুপ (অনুমতি ভাগকারী ব্যবহারকারী), রোল (সার্ভিস এবং ক্রস-অ্যাকাউন্ট অ্যাক্সেসের জন্য অস্থায়ী ক্রেডেনশিয়াল), পলিসি (অনুমতি/অস্বীকার নিয়ম সংজ্ঞায়িতকারী JSON ডকুমেন্ট)।

মূল ধারণা: Principal, Action, Resource, Condition, explicit deny > explicit allow > implicit deny, SCP (AWS Organizations-এ Service Control Policy), Permission boundary, AssumeRole।

পরীক্ষার সংকেত: প্রতিটি নিরাপত্তা প্রশ্নে IAM জড়িত। মূল প্যাটার্ন: সার্ভিস IAM রোল ব্যবহার করে (ব্যবহারকারী নয়)। ক্রস-অ্যাকাউন্ট অ্যাক্সেস রোল অনুমান ব্যবহার করে। ন্যূনতম সুবিধা — শুধুমাত্র যা প্রয়োজন তা প্রদান করুন।

**KMS — Key Management Service** *(অধ্যায় 16)*

পরিচালিত এনক্রিপশন কী সার্ভিস। ক্রিপ্টোগ্রাফিক কী তৈরি, সংরক্ষণ এবং নিয়ন্ত্রণ করে। Customer-managed keys (CMKs) আপনাকে রোটেশন, ব্যবহার এবং অ্যাক্সেস পলিসি সংজ্ঞায়িত করতে দেয়। AWS-managed keys স্বয়ংক্রিয়ভাবে পরিচালিত হয়।

মূল ধারণা: কী পলিসি (IAM পলিসি থেকে আলাদা), Envelope encryption (ডেটা একটি ডেটা কী দিয়ে এনক্রিপ্ট করা হয়; ডেটা কী CMK দিয়ে এনক্রিপ্ট করা হয়), স্বয়ংক্রিয় কী রোটেশন, Multi-region keys, Grants।

পরীক্ষার সংকেত: "বিশ্রামে ডেটা এনক্রিপ্ট করুন," "customer-managed এনক্রিপশন কী," "কী রোটেশন" → KMS।

**Secrets Manager** *(অধ্যায় 16)*

সংবেদনশীল মান সংরক্ষণ এবং স্বয়ংক্রিয়ভাবে রোটেট করে: ডেটাবেস ক্রেডেনশিয়াল, API কী, OAuth টোকেন। স্বয়ংক্রিয় পাসওয়ার্ড রোটেশনের জন্য RDS-এর সাথে ইন্টিগ্রেট হয়। অ্যাপ্লিকেশনগুলি API-এর মাধ্যমে রানটাইমে সিক্রেট পুনরুদ্ধার করে — কখনও ক্রেডেনশিয়াল হার্ডকোড করবেন না।

পরীক্ষার সংকেত: "ডেটাবেস ক্রেডেনশিয়াল সংরক্ষণ এবং রোটেট করুন," "হার্ডকোডেড সিক্রেট এড়ান" → Secrets Manager। "কনফিগারেশন মান সংরক্ষণ করুন, সিক্রেট নয়" → Parameter Store (SSM)।

**AWS Shield** *(অধ্যায় 17)*

DDoS সুরক্ষা। Shield Standard স্বয়ংক্রিয় এবং বিনামূল্যে — সাধারণ ভলিউমেট্রিক এবং প্রোটোকল আক্রমণ থেকে রক্ষা করে। Shield Advanced আর্থিক সুরক্ষা, 24/7 DDoS রেসপন্স টিম এবং বিস্তারিত আক্রমণ দৃশ্যমানতা যোগ করে।

পরীক্ষার সংকেত: "DDoS থেকে সুরক্ষা করুন" → Shield Standard (স্বয়ংক্রিয়) বা Shield Advanced (এন্টারপ্রাইজ, SLA সহ)।

**WAF — Web Application Firewall** *(অধ্যায় 17)*

নিয়মের উপর ভিত্তি করে HTTP/HTTPS ট্র্যাফিক ফিল্টার করে: IP ব্লক, রেট লিমিট, SQL injection প্যাটার্ন, XSS প্যাটার্ন, ভৌগোলিক সীমাবদ্ধতা, কাস্টম নিয়ম। CloudFront, ALB, API Gateway, বা AppSync-এর সাথে সংযুক্ত হয়।

পরীক্ষার সংকেত: "নির্দিষ্ট IP অ্যাড্রেস ব্লক করুন," "এজে SQL injection প্রতিরোধ করুন," "API কলে রেট লিমিট করুন" → WAF।

**GuardDuty** *(অধ্যায় 17)*

হুমকি সনাক্তকরণ সার্ভিস। ML এবং হুমকি ইন্টেলিজেন্স ব্যবহার করে CloudTrail লগ, VPC Flow Logs এবং DNS লগ বিশ্লেষণ করে। অস্বাভাবিক API কার্যকলাপ, পরিচিত ক্ষতিকারক IP-র সাথে যোগাযোগ, আপস করা ক্রেডেনশিয়াল সনাক্ত করে।

পরীক্ষার সংকেত: "অস্বাভাবিক কার্যকলাপ সনাক্ত করুন," "আপস করা IAM ক্রেডেনশিয়াল শনাক্ত করুন," "একটানা হুমকি পর্যবেক্ষণ" → GuardDuty।

**Amazon Inspector** *(অধ্যায় 17)*

স্বয়ংক্রিয় দুর্বলতা মূল্যায়ন সার্ভিস। সফটওয়্যার দুর্বলতা (CVE) এবং অনিচ্ছাকৃত নেটওয়ার্ক এক্সপোজারের জন্য EC2 ইনস্ট্যান্স, Amazon ECR কন্টেইনার ইমেজ এবং Lambda ফাংশন একটানা স্ক্যান করে। ফাইন্ডিংগুলি কেন্দ্রীভূত ব্যবস্থাপনার জন্য AWS Security Hub-এ পাঠানো হয়।

মূল ধারণা: CVE স্ক্যানিং, একটানা (একবারের নয়) মূল্যায়ন, EC2 + ECR + Lambda কভারেজ, Security Hub ইন্টিগ্রেশন।

পরীক্ষার সংকেত: "পরিচিত দুর্বলতার জন্য EC2 স্বয়ংক্রিয়ভাবে স্ক্যান করুন," "কন্টেইনার ইমেজের জন্য CVE স্ক্যানিং," "একটানা দুর্বলতা মূল্যায়ন" → Inspector।

**Amazon Cognito** *(অধ্যায় 14)*

আপনার অ্যাপ্লিকেশনের শেষ ব্যবহারকারীদের জন্য পরিচালিত প্রমাণীকরণ — একটি ব্যবহারকারী ডিরেক্টরি যা আপনাকে তৈরি করতে হয় না। User Pools সাইন-আপ, সাইন-ইন, MFA, পাসওয়ার্ড রিসেট এবং সোশ্যাল আইডেন্টিটি প্রদানকারী (Google, Facebook, যেকোনো OIDC প্রদানকারী) পরিচালনা করে, JWT ইস্যু করে যা আপনার অ্যাপ্লিকেশন যাচাই করে। Identity Pools সেই টোকেনগুলিকে অস্থায়ী AWS ক্রেডেনশিয়ালের জন্য বিনিময় করে।

মূল ধারণা: User Pool (প্রমাণীকরণ, JWT) বনাম Identity Pool (অস্থায়ী AWS ক্রেডেনশিয়াল), hosted UI, সোশ্যাল/OIDC/SAML ফেডারেশন, API Gateway Cognito authorizer।

পরীক্ষার সংকেত: "অ্যাপ্লিকেশনের ব্যবহারকারী সাইন-আপ/সাইন-ইন প্রয়োজন," "সোশ্যাল লগইন," "মোবাইল অ্যাপ ব্যবহারকারীদের AWS রিসোর্সে অস্থায়ী অ্যাক্সেস দিন" → Cognito। তুলনা: IAM আপনার ইঞ্জিনিয়ার এবং সার্ভিসের জন্য; Cognito আপনার গ্রাহকদের জন্য।

**AWS Certificate Manager (ACM)** *(অধ্যায় 16)*

AWS-পরিচালিত সার্ভিসের (ALB, CloudFront, API Gateway) জন্য বিনামূল্যে পাবলিক TLS/SSL সার্টিফিকেট প্রভিশন করে এবং সম্পূর্ণ লাইফসাইকেল পরিচালনা করে — কোনো নবায়ন ক্যালেন্ডার নেই, কোনো প্রাইভেট কী হ্যান্ডলিং নেই। DNS যাচাইকরণের মাধ্যমে স্বয়ংক্রিয়ভাবে নবায়ন করে।

মূল ধারণা: DNS বনাম ইমেইল যাচাইকরণ, স্বয়ংক্রিয় নবায়ন, CloudFront-এর জন্য সার্টিফিকেট অবশ্যই us-east-1-এ থাকতে হবে, বিনামূল্যে পাবলিক সার্টিফিকেট রপ্তানি করা যায় না (2025 থেকে একটি অর্থপ্রদানের রপ্তানিযোগ্য বিকল্প বিদ্যমান)।

পরীক্ষার সংকেত: "একটি লোড ব্যালেন্সার বা CDN-এ HTTPS," "স্বয়ংক্রিয় সার্টিফিকেট নবায়ন" → ACM।

**Amazon Macie** *(অধ্যায় 17)*

S3-এর জন্য সংবেদনশীল ডেটা আবিষ্কার। বাকেটে PII (নাম, কার্ড নম্বর, ক্রেডেনশিয়াল) খুঁজতে এবং পাবলিক এক্সপোজারের মতো অ্যাক্সেস ঝুঁকি চিহ্নিত করতে মেশিন লার্নিং এবং প্যাটার্ন ম্যাচিং ব্যবহার করে। GuardDuty-কে পরিপূরক করে: GuardDuty আচরণ দেখে; Macie কী সংরক্ষিত আছে তা অডিট করে।

মূল ধারণা: পরিচালিত ডেটা শনাক্তকারী (PII প্যাটার্ন), শুধুমাত্র S3 স্কোপ, Security Hub/EventBridge-এ ফাইন্ডিং।

পরীক্ষার সংকেত: "S3-এ PII আবিষ্কার করুন," "সংবেদনশীল ডেটা এক্সপোজার শনাক্ত করুন" → Macie।

---

**AWS Control Tower** *(অধ্যায় 14)*

একটি মাল্টি-অ্যাকাউন্ট পরিবেশের সেটআপ এবং গভর্নেন্স স্বয়ংক্রিয় করে। একটি landing zone তৈরি করে — Organizations, CloudTrail, Config এবং গার্ডরেল সহ পূর্ব-ওয়্যার করা ম্যানেজমেন্ট, লগ আর্কাইভ এবং অডিট অ্যাকাউন্ট — দিনের ম্যানুয়াল ওয়্যারিংয়ের পরিবর্তে মিনিটে।

মূল ধারণা: Landing zone, গার্ডরেল (প্রতিরোধমূলক = SCP, সনাক্তকারী = Config নিয়ম), মানসম্মত নতুন অ্যাকাউন্টের জন্য Account Factory।

পরীক্ষার সংকেত: "সর্বোত্তম অনুশীলন স্বয়ংক্রিয়ভাবে সহ একটি নতুন মাল্টি-অ্যাকাউন্ট পরিবেশ সেটআপ এবং গভর্ন করুন" → Control Tower। তুলনা: Organizations হল কাঁচা বিল্ডিং ব্লক; Control Tower হল স্বয়ংক্রিয় সংযোজন।

## মেসেজিং এবং ইভেন্ট প্রসেসিং

**SQS — Simple Queue Service** *(অধ্যায় 19)*

পরিচালিত মেসেজ কিউ। প্রোডিউসাররা মেসেজ পাঠায়; কনজিউমাররা সেগুলি পড়ে এবং মুছে দেয়। সার্ভিস ডিকাপল করে: প্রেরককে জানতে হবে না রিসিভার উপলব্ধ কিনা। Standard কিউ: at-least-once ডেলিভারি, best-effort অর্ডারিং। FIFO কিউ: exactly-once প্রসেসিং, কঠোর অর্ডারিং।

মূল ধারণা: Visibility timeout (প্রসেসিংয়ের সময় অন্য কনজিউমার থেকে মেসেজ লুকানো থাকে), Dead Letter Queue (DLQ) বারবার ব্যর্থ হওয়া মেসেজের জন্য, Message retention (ডিফল্ট 4 দিন, 14 পর্যন্ত), Long polling (খালি প্রতিক্রিয়া কমান), ডিফল্ট সর্বোচ্চ পেলোড 256KB (2025 থেকে 1 MiB পর্যন্ত বাড়ানো যায়; বড় পেলোডের জন্য, Extended Client Library বডিটি S3-তে সংরক্ষণ করে)।

পরীক্ষার সংকেত: "সার্ভিস ডিকাপল করুন," "লোড স্পাইকের সময় অনুরোধ বাফার করুন," "অ্যাসিঙ্ক প্রসেসিং" → SQS। "অর্ডার গুরুত্বপূর্ণ এবং exactly-once প্রয়োজন" → SQS FIFO।

---

**SNS — Simple Notification Service** *(অধ্যায় 19)*

পরিচালিত pub/sub সার্ভিস। প্রকাশকরা একটি টপিকে একটি মেসেজ পাঠায়; সমস্ত সাবস্ক্রাইবার একটি কপি পায়। Fan-out প্যাটার্ন: একটি মেসেজ → অনেক কনজিউমার। প্রোটোকল: SQS, Lambda, HTTP/HTTPS, ইমেইল, SMS, মোবাইল পুশ।

মূল ধারণা: টপিক, সাবস্ক্রিপশন, fan-out প্যাটার্ন (SNS → একাধিক SQS কিউ), মেসেজ ফিল্টারিং (সাবস্ক্রাইবাররা শুধুমাত্র মিলে যাওয়া মেসেজ পায়)।

পরীক্ষার সংকেত: "একসাথে একাধিক এন্ডপয়েন্টে নোটিফিকেশন পাঠান," "একটি একক ইভেন্টকে একাধিক কনজিউমারে fan-out করুন" → SNS। সাধারণ প্যাটার্ন: টেকসই fan-out-এর জন্য SNS + SQS।

---

**EventBridge** *(অধ্যায় 22)*

ইভেন্ট-চালিত আর্কিটেকচার তৈরির জন্য ইভেন্ট বাস। AWS সার্ভিস, SaaS অংশীদার এবং কাস্টম সোর্স থেকে Lambda, SQS, SNS, Step Functions এবং অন্যান্য টার্গেটে ইভেন্ট রুট করে। শিডিউল করা নিয়ম (cron) এবং প্যাটার্ন ম্যাচিং সমর্থন করে।

পরীক্ষার সংকেত: "AWS সার্ভিস থেকে টার্গেটে ইভেন্ট রুট করুন," "Lambda ফাংশন শিডিউল করুন," "ইভেন্ট-চালিত অর্কেস্ট্রেশন" → EventBridge।

---

**Step Functions** *(অধ্যায় 22)*

সার্ভারলেস ওয়ার্কফ্লো অর্কেস্ট্রেশন। Lambda ফাংশন, ECS টাস্ক, DynamoDB, SNS, SQS এবং অন্যান্য সার্ভিসকে ভিজ্যুয়াল স্টেট মেশিনে সমন্বয় করে। retry, error handling, সমান্তরাল শাখা এবং wait state পরিচালনা করে।

মূল ধারণা: স্টেট মেশিন, স্টেট টাইপ (Task, Wait, Choice, Parallel, Map, Pass, Succeed, Fail), Standard Workflows (exactly-once, দীর্ঘ-চলমান) বনাম Express Workflows: Asynchronous (at-least-once, হাই-ভলিউম — টাস্কগুলিকে idempotent হিসাবে ডিজাইন করুন) এবং Synchronous (at-most-once, একটি API কলের মতো সরাসরি ফলাফল ফেরত দেয়)।

পরীক্ষার সংকেত: "একাধিক Lambda ফাংশন অর্কেস্ট্রেট করুন," "retry লজিক সহ দীর্ঘ-চলমান ওয়ার্কফ্লো," "মানব অনুমোদনের ধাপ" → Step Functions।

---

**Kinesis** *(অধ্যায় 26)*

রিয়েল-টাইম ডেটা স্ট্রিমিং। Kinesis Data Streams: রেকর্ডের টেকসই, ক্রমিক স্ট্রিম (একটি বিতরণকৃত কমিট লগের মতো)। কনজিউমাররা রেকর্ড প্রসেস করে; ডেটা 24 ঘণ্টা (ডিফল্ট) থেকে 365 দিন (Extended Data Retention সহ) ধরে রাখা হয়। Amazon Data Firehose (পূর্বে Kinesis Data Firehose): S3, Redshift, OpenSearch, Splunk-এ সম্পূর্ণরূপে পরিচালিত ডেলিভারি — কোনো কনজিউমার ম্যানেজমেন্ট প্রয়োজন নেই।

মূল ধারণা: Shard (থ্রুপুটের একক: 1MB/s রাইট, 2MB/s রিড), পার্টিশন কী (shard অ্যাসাইনমেন্ট নির্ধারণ করে), সিকোয়েন্স নম্বর, চেকপয়েন্টিং (KCL বা Lambda), Firehose বনাম Streams।

পরীক্ষার সংকেত: "রিয়েল-টাইম স্ট্রিমিং," "ক্রমিক রেকর্ড," "ইভেন্ট রিপ্লে করুন" → Kinesis Data Streams। "কনজিউমার ম্যানেজ না করে S3/Redshift-এ স্ট্রিমিং ডেটা ডেলিভার করুন" → Amazon Data Firehose (পুরোনো প্রশ্ন "Kinesis Data Firehose" বলতে পারে)। "স্ট্রিমিং ডেটায় SQL" → Amazon Managed Service for Apache Flink (পূর্বে Kinesis Data Analytics)। SQS-এর সাথে তুলনা: Kinesis ধরে রাখে এবং রিপ্লে করে; SQS গ্রহণের সময় মুছে দেয়।

---

**Amazon MQ** *(অধ্যায় 19)*

Apache ActiveMQ এবং RabbitMQ সমর্থনকারী পরিচালিত মেসেজ ব্রোকার সার্ভিস। শিল্প-মান মেসেজিং প্রোটোকল সমর্থন করে: AMQP, STOMP, MQTT, OpenWire এবং WebSocket। প্রাথমিক ব্যবহারের ক্ষেত্র হল অন-প্রিমিসেস মেসেজ ব্রোকার ওয়ার্কলোডের lift-and-shift মাইগ্রেশন — যে অ্যাপ্লিকেশনগুলি ইতিমধ্যে ActiveMQ বা RabbitMQ ব্যবহার করে সেগুলি কোড পরিবর্তন ছাড়াই সংযুক্ত হতে পারে।

মূল ধারণা: ActiveMQ বনাম RabbitMQ ইঞ্জিন পছন্দ, প্রোটোকল সমর্থন (AMQP/STOMP/MQTT), HA-এর জন্য একক-ইনস্ট্যান্স বা active/standby ব্রোকার কনফিগারেশন।

পরীক্ষার সংকেত: "অ্যাপ্লিকেশন কোড পরিবর্তন ছাড়াই অন-প্রিমিসেস ActiveMQ বা RabbitMQ AWS-এ মাইগ্রেট করুন" → Amazon MQ। "গ্রিনফিল্ড AWS-নেটিভ মেসেজিং" → SQS বা SNS (সহজতর, আরও স্কেলযোগ্য)।

## অ্যানালিটিক্স

**Athena** *(অধ্যায় 26)*

S3-তে সংরক্ষিত ডেটায় সার্ভারলেস SQL কোয়েরি। পরিচালনার কোনো অবকাঠামো নেই। প্রতি কোয়েরিতে দেন (প্রতি TB স্ক্যান করা)। কলামার ফরম্যাট (Parquet, ORC) এবং পার্টিশন করা ডেটার সাথে সেরা।

পরীক্ষার সংকেত: "SQL দিয়ে S3 ডেটা কোয়েরি করুন," "ডেটা লেকে অ্যাড-হক অ্যানালিটিক্স," "কোনো অবকাঠামো ম্যানেজমেন্ট নেই" → Athena।

---

**Glue** *(অধ্যায় 26)*

সার্ভারলেস ETL (Extract, Transform, Load) সার্ভিস। Glue Crawlers ডেটা আবিষ্কার করে এবং Glue Data Catalog আপডেট করে। Glue Jobs Spark বা Python রূপান্তর চালায়। Data Catalog Athena, Redshift Spectrum এবং EMR-এর সাথে ইন্টিগ্রেট হয়।

পরীক্ষার সংকেত: "অ্যানালিটিক্সের জন্য ডেটা রূপান্তর এবং লোড করুন," "S3 ডেটার স্কিমা আবিষ্কার করুন," "ETL পাইপলাইন" → Glue।

---

**Amazon QuickSight** *(অধ্যায় 26)*

পরিচালিত বিজনেস ইন্টেলিজেন্স এবং ডেটা ভিজ্যুয়ালাইজেশন সার্ভিস। SPICE (Super-fast, Parallel, In-memory Calculation Engine) ব্যবহার করে, একটি ইন-মেমরি ইঞ্জিন যা দ্রুত ড্যাশবোর্ড রেন্ডারিংয়ের জন্য আমদানি করা ডেটা ক্যাশ করে। Athena, S3, Redshift, RDS এবং অন্যান্য AWS ডেটা সোর্সের সাথে সংযুক্ত হয়। পরিচালনার জন্য কোনো BI সার্ভার নেই।

মূল ধারণা: SPICE (ইন-মেমরি ইঞ্জিন), ডেটাসেট, বিশ্লেষণ, ড্যাশবোর্ড, ML Insights (অ্যানোমালি সনাক্তকরণ, পূর্বাভাস), রো-লেভেল এবং কলাম-লেভেল নিরাপত্তা।

পরীক্ষার সংকেত: "একটি সার্ভার পরিচালনা না করে AWS-এ BI ড্যাশবোর্ড," "Athena বা Redshift থেকে ডেটা ভিজ্যুয়ালাইজ করুন" → QuickSight।

---

**AWS Lake Formation** *(অধ্যায় 26)*

S3 এবং Glue Data Catalog-এর উপরে কেন্দ্রীভূত ডেটা লেক অ্যাক্সেস নিয়ন্ত্রণ লেয়ার। টেবিল, কলাম এবং রো স্তরে সূক্ষ্ম-দানাদার অনুমতি প্রদান করে — শুধুমাত্র S3 বাকেট পলিসির চেয়ে আরও দানাদার। একটি নিরাপদ ডেটা লেক সেটআপ সহজ করে: Lake Formation অনুমতি মডেল পরিচালনা করে; Glue ক্যাটালগ পরিচালনা করে; S3 ডেটা ধারণ করে।

মূল ধারণা: ডেটা লেক অনুমতি (টেবিল/কলাম/রো-স্তর), Glue Data Catalog ইন্টিগ্রেশন, অ্যাট্রিবিউট-ভিত্তিক অ্যাক্সেস নিয়ন্ত্রণের জন্য LF-tags, Athena এবং Redshift Spectrum কোয়েরির জন্য কেন্দ্রীভূত grant/revoke।

পরীক্ষার সংকেত: "ডেটা লেকে সূক্ষ্ম-দানাদার অ্যাক্সেস নিয়ন্ত্রণ," "S3 ডেটায় কলাম-লেভেল বা রো-লেভেল নিরাপত্তা" → Lake Formation।

## উচ্চ প্রাপ্যতা এবং ডিজাস্টার রিকভারি

**Multi-AZ এবং Multi-Region** *(অধ্যায় 18)*

Multi-AZ: স্বয়ংক্রিয় ফেলওভারের জন্য একটি অঞ্চলের মধ্যে সিঙ্ক্রোনাস রেপ্লিকেশন (RDS Multi-AZ, AZ জুড়ে লোড ব্যালেন্সার)। RDS-এর জন্য RPO ~0, RTO ~60s। Multi-Region: ভৌগোলিক রিডানডেন্সি এবং গ্লোবাল ব্যবহারকারীদের জন্য কম লেটেন্সির জন্য অ্যাসিঙ্ক্রোনাস রেপ্লিকেশন।

মূল ধারণা: RTO (Recovery Time Objective — পুনরুদ্ধারে কত সময়), RPO (Recovery Point Objective — কতটা ডেটা হারাতে পারে)। Pilot Light, Warm Standby, Active-Active DR কৌশল।

পরীক্ষার সংকেত: AZ-স্তরের ব্যর্থতা (Multi-AZ পরিচালনা করে) বনাম আঞ্চলিক ব্যর্থতা (Multi-Region পরিচালনা করে) এর মধ্যে পার্থক্য করুন। Multi-Region-এর সাথে খরচ এবং জটিলতা উল্লেখযোগ্যভাবে বৃদ্ধি পায়।

---

**AWS Elastic Disaster Recovery (DRS)** *(অধ্যায় 18)*

সার্ভারের (অন-প্রিমিসেস বা EC2) জন্য পরিচালিত ডিজাস্টার রিকভারি। সোর্স সার্ভারগুলিকে একটানা ব্লক বাই ব্লক একটি কম খরচের স্টেজিং এরিয়ায় রেপ্লিকেট করে এবং প্রয়োজনে মিনিটে সম্পূর্ণ রিকভারি ইনস্ট্যান্স লঞ্চ করে — একটি পরিচালিত pilot light: ব্যাকআপ-অ্যান্ড-রিস্টোরের কাছাকাছি দামে কাছাকাছি-warm-standby রিকভারি সময়।

মূল ধারণা: একটানা ব্লক-স্তরের রেপ্লিকেশন, কম খরচের স্টেজিং এরিয়া, চাহিদা অনুযায়ী রিকভারি লঞ্চ, পয়েন্ট-ইন-টাইম রিকভারি।

পরীক্ষার সংকেত: "একটি পরিচালিত DR সার্ভিস দিয়ে সার্ভার-ভিত্তিক ওয়ার্কলোডের জন্য ডাউনটাইম এবং ডেটা হারানো কমান," "নিজে এটি তৈরি না করে pilot light" → DRS।

## কস্ট অপ্টিমাইজেশন

**EC2 মূল্য নির্ধারণ মডেল** *(অধ্যায় 27)*

On-Demand: পূর্ণ মূল্য, কোনো প্রতিশ্রুতি নেই। Reserved Instances (1 বা 3 বছর): নির্দিষ্ট ইনস্ট্যান্স টাইপের জন্য 30-72% ছাড়। Savings Plans (Compute বা EC2 Instance): নমনীয়তার জন্য প্রতিশ্রুত ঘণ্টা ব্যয়। Spot: বিঘ্নযোগ্য ওয়ার্কলোডের জন্য 60-90% ছাড়।

পরীক্ষার সংকেত: "পূর্বানুমেয় ওয়ার্কলোডের খরচ কমান" → Savings Plans বা Reserved Instances। "ফল্ট-টলারেন্ট ব্যাচ প্রসেসিং" → Spot। "অপূর্বানুমেয় বা স্বল্পমেয়াদী" → On-Demand।

---

**ডেটা ট্রান্সফার মূল্য নির্ধারণ** *(অধ্যায় 30)*

AWS-এ ইনবাউন্ড: বিনামূল্যে। একই-AZ: বিনামূল্যে। ক্রস-AZ: প্রতি দিকে $0.01/GB। ক্রস-রিজিয়ন: $0.02-0.08/GB। ইন্টারনেট (আউটবাউন্ড): ~$0.09/GB। NAT Gateway প্রসেসিং: $0.045/GB। CloudFront ডেটা ট্রান্সফার সরাসরি EC2-থেকে-ইন্টারনেটের চেয়ে সস্তা, এবং ক্যাশিং মোট ভলিউম কমায়।

পরীক্ষার সংকেত: "প্রাইভেট সাবনেট থেকে S3/DynamoDB-এর ডেটা ট্রান্সফার খরচ কমান" → Gateway Endpoints (বিনামূল্যে)। "অন্যান্য সার্ভিসের জন্য NAT Gateway খরচ কমান" → Interface Endpoints।

## অবজার্ভেবিলিটি

**CloudWatch** *(সর্বত্র উল্লেখিত)*

মনিটরিং এবং অবজার্ভেবিলিটি। CloudWatch Metrics: AWS সার্ভিস এবং কাস্টম অ্যাপ্লিকেশন থেকে সংখ্যাসূচক টাইম-সিরিজ ডেটা। CloudWatch Logs: লগ ডেটা সংগ্রহ, অনুসন্ধান এবং বিশ্লেষণ করুন। CloudWatch Alarms: মেট্রিক থ্রেশহোল্ডের উপর ভিত্তি করে নোটিফিকেশন বা অটো স্কেলিং ট্রিগার করুন। CloudWatch Dashboards: মেট্রিক ভিজ্যুয়ালাইজ করুন।

মূল ধারণা: মেট্রিক ডাইমেনশন, রিটেনশন পিরিয়ড, লগ গ্রুপ এবং লগ স্ট্রিম, মেট্রিক ফিল্টার, CloudWatch Agent (EC2 থেকে OS-স্তরের মেট্রিক এবং লগের জন্য), Container Insights।

---

**CloudTrail** *(সর্বত্র উল্লেখিত)*

আপনার AWS অ্যাকাউন্টে করা প্রতিটি API কল লগ করে: কে এটি করেছে, কোথা থেকে, কখন এবং প্রতিক্রিয়া কী ছিল। Multi-region trail অনির্দিষ্টকালের জন্য S3-তে লগ সংরক্ষণ করে। নিরাপত্তা অডিটিং, কমপ্লায়েন্স এবং ঘটনা তদন্তের জন্য ব্যবহৃত হয়।

পরীক্ষার সংকেত: "কে সেই রিসোর্স মুছে দিয়েছে?" "সমস্ত API কার্যকলাপ অডিট করুন" → CloudTrail।

---

**X-Ray** *(অধ্যায় 20)*

ডিস্ট্রিবিউটেড ট্রেসিং: সার্ভিস জুড়ে পৃথক অনুরোধ অনুসরণ করে (trace → segment → subsegment), প্রতি হপে লেটেন্সি এবং ত্রুটির হার সহ একটি সার্ভিস ম্যাপ তৈরি করে। স্যাম্পলিং ওভারহেড কম রাখে; annotation ট্রেসগুলিকে অনুসন্ধানযোগ্য করে তোলে। Active tracing Lambda এবং API Gateway স্টেজে টগল করে।

পরীক্ষার সংকেত: "মাইক্রোসার্ভিস জুড়ে অনুরোধ ট্রেস করুন," "সার্ভিসগুলির মধ্যে বটলনেক খুঁজুন" → X-Ray (CloudWatch নয়, CloudTrail নয়)।

---

**AWS Config** *(অধ্যায় 31-এ উল্লেখিত)*

সময়ের সাথে রিসোর্স কনফিগারেশন পরিবর্তন ট্র্যাক করে। কমপ্লায়েন্স নিয়মের বিপরীতে রিসোর্স মূল্যায়ন করে। প্রতিটি রিসোর্সের প্রতিটি কনফিগারেশন পরিবর্তনের ইতিহাস রেকর্ড করে। প্রতিকারের জন্য Systems Manager-এর সাথে ইন্টিগ্রেট হয়।

পরীক্ষার সংকেত: "এই রিসোর্স কি আমাদের নিরাপত্তা পলিসির সাথে সঙ্গতিপূর্ণ?" "গত সপ্তাহে এই রিসোর্সের কনফিগারেশন কেমন দেখাচ্ছিল?" → AWS Config।

## Well-Architected

**ছয়টি স্তম্ভ** *(অধ্যায় 31)*

| স্তম্ভ                 | মূল প্রশ্ন                           | মূল সার্ভিস                                      |
|------------------------|-----------------------------------------|---------------------------------------------------|
| Operational Excellence | আমরা কি ভালোভাবে চলছি?                    | CloudWatch, CloudTrail, SSM, Config               |
| Security               | আমরা কি সুরক্ষিত?                       | IAM, KMS, GuardDuty, WAF, Shield, Secrets Manager |
| Reliability            | আমরা কি ব্যর্থতা থেকে পুনরুদ্ধার করি?             | Multi-AZ, Route 53 failover, backup/restore, SQS  |
| Performance Efficiency | আমরা কি সঠিক রিসোর্স ব্যবহার করছি?       | Right-sizing, Auto Scaling, CloudFront, Kinesis   |
| Cost Optimization      | আমরা কি বুদ্ধিমানের সাথে খরচ করছি?                 | Savings Plans, Spot, S3 lifecycle, VPC Endpoints  |
| Sustainability         | আমরা কি পরিবেশগত প্রভাব কমাচ্ছি? | Right-sizing, Graviton, efficient storage tiers   |

AWS Well-Architected Tool: ছয়টি স্তম্ভের বিপরীতে আপনার আর্কিটেকচার মূল্যায়ন করে। প্রতিটি স্তম্ভের প্রশ্নের পিছনের যুক্তি বুঝতে পরীক্ষার আগে এটি ব্যবহার করুন।
