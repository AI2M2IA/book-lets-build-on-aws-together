# পরিশিষ্ট B: SAA-C03 ডোমেইন ম্যাপ

AWS Solutions Architect Associate পরীক্ষা (SAA-C03) চারটি ডোমেইনে সংগঠিত। এই পরিশিষ্ট পরীক্ষার ক্ষেত্র অনুযায়ী বইয়ের প্রতিটি অধ্যায়কে প্রাসঙ্গিক ডোমেইন এবং টাস্কে ম্যাপ করে, যাতে অধ্যায়ের ক্রমের পরিবর্তে পরীক্ষার ক্ষেত্র অনুযায়ী অধ্যয়ন করতে পারেন।

## ডোমেইন 1: নিরাপদ আর্কিটেকচার ডিজাইন করুন (30%)

**টাস্ক 1.1 — AWS রিসোর্সে নিরাপদ অ্যাক্সেস ডিজাইন করুন**

মূল ধারণা: IAM ব্যবহারকারী, গ্রুপ, রোল, পলিসি। ন্যূনতম সুবিধার নীতি। ক্রস-অ্যাকাউন্ট অ্যাক্সেস। সার্ভিস রোল। AWS Organizations-এ SCP (Service Control Policies)।

| অধ্যায়    | বিষয়                                                                        |
|------------|------------------------------------------------------------------------------|
| অধ্যায় 3  | IAM মৌলিক বিষয়: ব্যবহারকারী, গ্রুপ, রোল, পলিসি, পলিসি মূল্যায়ন          |
| অধ্যায় 14 | IAM উন্নত: সার্ভিসের জন্য রোল, permission boundaries, ক্রস-অ্যাকাউন্ট রোল |
| অধ্যায় 3  | পলিসি মূল্যায়ন লজিক: explicit deny > explicit allow > implicit deny      |
| অধ্যায় 14 | AWS Organizations, SCPs, Control Tower, Account Factory                      |
| অধ্যায় 14 | Cognito: User Pools (অ্যাপ সাইন-ইন, JWTs) এবং Identity Pools (অস্থায়ী AWS ক্রেডেনশিয়াল) |

মূল পরীক্ষার প্যাটার্ন:

- "হার্ডকোডেড ক্রেডেনশিয়াল ছাড়াই EC2-এর S3 অ্যাক্সেস প্রয়োজন" → S3 পলিসি সহ IAM রোল EC2 ইনস্ট্যান্স প্রোফাইলের সাথে সংযুক্ত
- "ভিন্ন অ্যাকাউন্টের রিসোর্স ভাগ করার প্রয়োজন" → ক্রস-অ্যাকাউন্ট trust পলিসি সহ IAM রোল
- "একটি OU-র সমস্ত IAM ব্যবহারকারীদের একটি সার্ভিস অ্যাক্সেস করা থেকে বিরত রাখুন" → AWS Organizations-এ SCP

---

**টাস্ক 1.2 — নিরাপদ ওয়ার্কলোড এবং অ্যাপ্লিকেশন ডিজাইন করুন**

মূল ধারণা: VPC ডিজাইন, নিরাপত্তা গোষ্ঠী বনাম NACL, নেটওয়ার্ক বিচ্ছিন্নতা, DDoS সুরক্ষা, WAF, GuardDuty।

| অধ্যায়    | বিষয়                                                                              |
|------------|------------------------------------------------------------------------------------|
| অধ্যায় 11 | VPC ডিজাইন: পাবলিক/প্রাইভেট সাবনেট, NAT Gateway, Internet Gateway, রুট টেবিল    |
| অধ্যায় 15 | নিরাপত্তা গোষ্ঠী (stateful, ইনস্ট্যান্স-স্তর) বনাম NACL (stateless, সাবনেট-স্তর)     |
| অধ্যায় 17 | Shield (DDoS), WAF (অ্যাপ ফায়ারওয়াল), GuardDuty (হুমকি সনাক্তকরণ), Inspector (CVE স্ক্যানিং)  |
| অধ্যায় 17 | Macie: S3-তে সংবেদনশীল ডেটা আবিষ্কার (PII, ক্রেডেনশিয়াল)                                   |
| অধ্যায় 25 | Direct Connect, VPN, Transit Gateway, PrivateLink                                          |

মূল পরীক্ষার প্যাটার্ন:

- "সাবনেট থেকে একটি নির্দিষ্ট IP ব্লক করুন" → NACL deny নিয়ম
- "HTTP ইন অনুমতি দিন, HTTP প্রতিক্রিয়া স্বয়ংক্রিয়ভাবে বাইরে অনুমতি দিন" → নিরাপত্তা গোষ্ঠী (stateful)
- "SQL injection থেকে ওয়েব অ্যাপ্লিকেশন সুরক্ষা করুন" → SQL injection নিয়ম সহ WAF
- "আপস করা IAM ক্রেডেনশিয়াল সনাক্ত করুন" → GuardDuty

**টাস্ক 1.3 — উপযুক্ত ডেটা নিরাপত্তা নিয়ন্ত্রণ নির্ধারণ করুন**

মূল ধারণা: বিশ্রামে এবং ট্রানজিটে এনক্রিপশন, KMS, Secrets Manager, Parameter Store, S3 server-side এনক্রিপশন।

| অধ্যায়    | বিষয়                                                                    |
|------------|--------------------------------------------------------------------------|
| অধ্যায় 16 | KMS: customer-managed keys, কী রোটেশন, envelope encryption            |
| অধ্যায় 16 | Secrets Manager: স্বয়ংক্রিয় ক্রেডেনশিয়াল রোটেশন, রানটাইম সিক্রেট পুনরুদ্ধার |
| অধ্যায় 16 | ACM (AWS Certificate Manager): ALB, CloudFront-এর জন্য SSL/TLS সার্টিফিকেট  |
| অধ্যায় 5  | S3 এনক্রিপশন বিকল্প: SSE-S3, SSE-KMS, SSE-C                            |
| অধ্যায় 8  | RDS বিশ্রামে এনক্রিপশন (তৈরির সময় অবশ্যই সক্ষম করতে হবে)                     |

মূল পরীক্ষার প্যাটার্ন:

- "স্বয়ংক্রিয়ভাবে ডেটাবেস ক্রেডেনশিয়াল রোটেট করুন" → RDS ইন্টিগ্রেশন সহ Secrets Manager
- "অ্যাকাউন্ট জুড়ে কে এনক্রিপশন কী ব্যবহার করতে পারে তা নিয়ন্ত্রণ করুন" → KMS কী পলিসি
- "নন-সিক্রেট কনফিগারেশন মান সংরক্ষণ করুন" → SSM Parameter Store (Secrets Manager নয়)
- "কোম্পানি-পরিচালিত কী দিয়ে S3 অবজেক্ট এনক্রিপ্ট করুন" → CMK সহ SSE-KMS

## ডোমেইন 2: স্থিতিস্থাপক আর্কিটেকচার ডিজাইন করুন (26%)

**টাস্ক 2.1 — স্কেলযোগ্য এবং loosely coupled আর্কিটেকচার ডিজাইন করুন**

মূল ধারণা: Auto Scaling, লোড ব্যালেন্সার, SQS/SNS ডিকাপলিং, Lambda ইভেন্ট ট্রিগার, ECS/EKS, Step Functions।

| অধ্যায়    | বিষয়                                                              |
|------------|--------------------------------------------------------------------|
| অধ্যায় 7  | Auto Scaling Groups, Application Load Balancer, স্কেলিং পলিসি   |
| অধ্যায় 19 | SQS (কিউ দিয়ে ডিকাপলিং), SNS (fan-out নোটিফিকেশন)          |
| অধ্যায় 20 | Lambda: সার্ভারলেস কম্পিউট, ইভেন্ট ট্রিগার, কনকারেন্সি            |
| অধ্যায় 20 | API Gateway: পরিচালিত REST/HTTP/WebSocket API, স্ট্যান্ডঅ্যালোন বা + Lambda |
| অধ্যায় 21 | ECS এবং EKS: কন্টেইনারাইজড মাইক্রোসার্ভিস                           |
| অধ্যায় 22 | Step Functions: ওয়ার্কফ্লো অর্কেস্ট্রেশন                             |
| অধ্যায় 26 | Kinesis: রিয়েল-টাইম ডেটা স্ট্রিমিং                                  |

মূল পরীক্ষার প্যাটার্ন:

- "ইনভেন্টরি আপডেট থেকে অর্ডার প্রসেসিং ডিকাপল করুন" → সার্ভিসগুলির মধ্যে SQS কিউ
- "একটি নতুন অর্ডার দেওয়া হলে একাধিক সার্ভিসকে অবহিত করুন" → SQS সাবস্ক্রিপশন সহ SNS টপিক (fan-out)
- "S3 আপলোড স্বয়ংক্রিয়ভাবে প্রসেস করুন" → S3 ইভেন্ট নোটিফিকেশন → Lambda
- "retry লজিক সহ একটি মাল্টি-স্টেপ ওয়ার্কফ্লো চালান" → Step Functions

---

**টাস্ক 2.2 — অত্যন্ত উপলব্ধ এবং/অথবা ফল্ট-টলারেন্ট আর্কিটেকচার ডিজাইন করুন**

মূল ধারণা: Multi-AZ, Multi-Region, Route 53 failover, RDS read replicas, Aurora Global Database, backup and restore।

| অধ্যায়    | বিষয়                                                                                        |
|------------|----------------------------------------------------------------------------------------------|
| অধ্যায় 2  | AWS গ্লোবাল অবকাঠামো: Regions, AZs, এজ লোকেশন                                      |
| অধ্যায় 7  | একাধিক AZ জুড়ে ALB, ASG অস্বাস্থ্যকর ইনস্ট্যান্স প্রতিস্থাপন করে                                    |
| অধ্যায় 8  | RDS Multi-AZ: সিঙ্ক্রোনাস রেপ্লিকেশন, স্বয়ংক্রিয় ফেলওভার                                    |
| অধ্যায় 12 | Route 53: failover রাউটিং, latency রাউটিং, স্বাস্থ্য পরীক্ষা                                   |
| অধ্যায় 18 | Multi-AZ বনাম Multi-Region: RTO/RPO, DR কৌশল (pilot light, warm standby, active-active) |
| অধ্যায় 18 | AWS Backup (কেন্দ্রীভূত, ক্রস-অ্যাকাউন্ট ব্যাকআপ), Elastic Disaster Recovery (পরিচালিত pilot light) |
| অধ্যায় 24 | Aurora Global Database: ক্রস-রিজিয়ন রিড রেপ্লিকা, < 1s রেপ্লিকেশন ল্যাগ                     |

মূল পরীক্ষার প্যাটার্ন:

- "প্রাইমারি RDS ব্যর্থ হলে স্বয়ংক্রিয়ভাবে ফেলওভার" → RDS Multi-AZ (Read Replica নয়)
- "কম লেটেন্সিতে বিশ্বব্যাপী রিড পরিবেশন করুন" → Aurora Global Database
- "প্রাইমারি অনুপলব্ধ হলে সেকেন্ডারি অঞ্চলে ট্র্যাফিক রুট করুন" → Failover রাউটিং + স্বাস্থ্য পরীক্ষা সহ Route 53
- "RTO 1 মিনিট, RPO 0" → Multi-AZ ডিপ্লয়মেন্ট (Multi-Region নয়)
- "RTO 15 মিনিট, ক্রস-রিজিয়ন" → Pilot Light কৌশল

## ডোমেইন 3: হাই-পারফর্মিং আর্কিটেকচার ডিজাইন করুন (24%)

**টাস্ক 3.1 — হাই-পারফর্মিং এবং/অথবা স্কেলযোগ্য স্টোরেজ সমাধান নির্ধারণ করুন**

মূল ধারণা: S3 বনাম EBS বনাম EFS, স্টোরেজ ক্লাস নির্বাচন, S3 Transfer Acceleration, মাল্টিপার্ট আপলোড, অ্যাসেটের জন্য CloudFront।

| অধ্যায়    | বিষয়                                                                   |
|------------|-------------------------------------------------------------------------|
| অধ্যায় 5  | S3: অবজেক্ট স্টোরেজ, স্টোরেজ ক্লাস, ভার্সনিং, লাইফসাইকেল              |
| অধ্যায় 6  | EBS: ব্লক স্টোরেজ টাইপ (gp3, io2, st1), EFS: ভাগ করা ফাইল স্টোরেজ      |
| অধ্যায় 6  | Storage Gateway: হাইব্রিড অন-প্রিমিসেস থেকে S3 ব্রিজ (File, Volume, Tape)   |
| অধ্যায় 23 | S3 স্টোরেজ ক্লাস ট্রানজিশন, Glacier পুনরুদ্ধার বিকল্প                 |
| অধ্যায় 25 | DataSync (অনলাইন ফাইল সিঙ্ক), Transfer Family (পরিচালিত SFTP→S3), Snow Family (অফলাইন বাল্ক ট্রান্সফার — লিগ্যাসি: নভেম্বর 2025-এ নতুন গ্রাহকদের জন্য বন্ধ; AWS এখন DataSync এবং Data Transfer Terminals-এর দিকে নির্দেশ করে), MGN (সার্ভার রিহোস্ট) |
| অধ্যায় 28 | EBS right-sizing, gp2→gp3 মাইগ্রেশন, স্ন্যাপশট ম্যানেজমেন্ট                |

মূল পরীক্ষার প্যাটার্ন:

- "একাধিক EC2 ইনস্ট্যান্স থেকে অ্যাক্সেসযোগ্য ভাগ করা ফাইল সিস্টেম" → EFS (EBS নয়; EBS একটি ইনস্ট্যান্সে সংযুক্ত হয়)
- "ডেটাবেস ওয়ার্কলোডের জন্য হাই IOPS" → io2 EBS
- "90 দিন অ্যাক্সেস না করা ফাইলের খরচ কমান" → S3 লাইফসাইকেল পলিসি → Glacier
- "দূরবর্তী অবস্থান থেকে বড় ফাইল দ্রুত আপলোড করুন" → S3 Transfer Acceleration
- "সীমিত ব্যান্ডউইথের উপর সপ্তাহের ট্রান্সফার" → Snow Family-এর 2025-এ নতুন গ্রাহকদের জন্য বন্ধ হওয়া সত্ত্বেও SAA-C03 পরীক্ষা এখনও Snowball আশা করে

- [ ] ElastiCache বনাম MemoryDB: ElastiCache = ক্যাশ (ডেটা হারানো ঠিক আছে)। MemoryDB = টেকসই প্রাইমারি ডেটাবেস।

- [ ] Outposts বনাম Wavelength: Outposts = অন-প্রিমিসেস AWS র‍্যাক। Wavelength = 5G এজ।
- [ ] DMS: homogeneous = সরাসরি DMS। Heterogeneous = প্রথমে SCT, তারপর DMS।
