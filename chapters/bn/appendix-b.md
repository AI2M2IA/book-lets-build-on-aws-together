# পরিশিষ্ট B: SAA-C03 ডোমেইন ম্যাপ

AWS Solutions Architect Associate পরীক্ষা (SAA-C03) চারটি ডোমেইনে সংগঠিত। এই পরিশিষ্ট পরীক্ষার ক্ষেত্র অনুযায়ী বইয়ের প্রতিটি অধ্যায়কে প্রাসঙ্গিক ডোমেইন এবং টাস্কে ম্যাপ করে, যাতে অধ্যায়ের ক্রমের পরিবর্তে পরীক্ষার ক্ষেত্র অনুযায়ী অধ্যয়ন করতে পারেন।

## ডোমেইন ১: নিরাপদ আর্কিটেকচার ডিজাইন করুন (৩০%)

**টাস্ক ১.১ — AWS রিসোর্সে নিরাপদ অ্যাক্সেস ডিজাইন করুন**

মূল ধারণা: IAM ব্যবহারকারী, গ্রুপ, রোল, পলিসি। ন্যূনতম সুবিধার নীতি। ক্রস-অ্যাকাউন্ট অ্যাক্সেস। সার্ভিস রোল। AWS Organizations-এ SCP (Service Control Policies)।

| অধ্যায়    | বিষয়                                                                        |
|------------|------------------------------------------------------------------------------|
| অধ্যায় ৩  | IAM মৌলিক বিষয়: ব্যবহারকারী, গ্রুপ, রোল, পলিসি, পলিসি মূল্যায়ন          |
| অধ্যায় ১৪ | IAM উন্নত: সার্ভিসের জন্য রোল, permission boundaries, ক্রস-অ্যাকাউন্ট রোল |
| অধ্যায় ৩  | পলিসি মূল্যায়ন লজিক: explicit deny > explicit allow > implicit deny      |
| অধ্যায় ১৪ | AWS Organizations এবং SCPs                                                   |

মূল পরীক্ষার প্যাটার্ন:

- "হার্ডকোডেড ক্রেডেনশিয়াল ছাড়াই EC2-এর S3 অ্যাক্সেস প্রয়োজন" → S3 পলিসি সহ IAM রোল EC2 ইনস্ট্যান্স প্রোফাইলের সাথে সংযুক্ত
- "ভিন্ন অ্যাকাউন্টের রিসোর্স ভাগ করার প্রয়োজন" → ক্রস-অ্যাকাউন্ট trust পলিসি সহ IAM রোল
- "একটি OU-র সমস্ত IAM ব্যবহারকারীদের একটি সার্ভিস অ্যাক্সেস করা থেকে বিরত রাখুন" → AWS Organizations-এ SCP

---

**টাস্ক ১.২ — নিরাপদ ওয়ার্কলোড এবং অ্যাপ্লিকেশন ডিজাইন করুন**

মূল ধারণা: VPC ডিজাইন, নিরাপত্তা গোষ্ঠী বনাম NACL, নেটওয়ার্ক বিচ্ছিন্নতা, DDoS সুরক্ষা, WAF, GuardDuty।

| অধ্যায়    | বিষয়                                                                              |
|------------|------------------------------------------------------------------------------------|
| অধ্যায় ১১ | VPC ডিজাইন: পাবলিক/প্রাইভেট সাবনেট, NAT Gateway, Internet Gateway, রুট টেবিল    |
| অধ্যায় ১৫ | নিরাপত্তা গোষ্ঠী (stateful, ইনস্ট্যান্স-স্তর) বনাম NACL (stateless, সাবনেট-স্তর)     |
| অধ্যায় ১৭ | Shield (DDoS সুরক্ষা), WAF (অ্যাপ্লিকেশন ফায়ারওয়াল), GuardDuty (হুমকি সনাক্তকরণ) |
| অধ্যায় ২৫ | Direct Connect, VPN, Transit Gateway, PrivateLink                                  |

মূল পরীক্ষার প্যাটার্ন:

- "সাবনেট থেকে একটি নির্দিষ্ট IP ব্লক করুন" → NACL অস্বীকার নিয়ম
- "HTTP ইন অনুমতি দিন, HTTP প্রতিক্রিয়া স্বয়ংক্রিয়ভাবে বাইরে অনুমতি দিন" → নিরাপত্তা গোষ্ঠী (stateful)
- "SQL injection থেকে ওয়েব অ্যাপ্লিকেশন সুরক্ষা করুন" → SQL injection নিয়ম সহ WAF
- "আপস করা IAM ক্রেডেনশিয়াল সনাক্ত করুন" → GuardDuty

---

**টাস্ক ১.৩ — উপযুক্ত ডেটা নিরাপত্তা নিয়ন্ত্রণ নির্ধারণ করুন**

মূল ধারণা: বিশ্রামে এবং ট্রানজিটে এনক্রিপশন, KMS, Secrets Manager, Parameter Store, S3 সার্ভার-সাইড এনক্রিপশন।

| অধ্যায়    | বিষয়                                                                    |
|------------|--------------------------------------------------------------------------|
| অধ্যায় ১৬ | KMS: customer-managed keys, কী রোটেশন, envelope encryption            |
| অধ্যায় ১৬ | Secrets Manager: স্বয়ংক্রিয় ক্রেডেনশিয়াল রোটেশন, রানটাইম secret পুনরুদ্ধার |
| অধ্যায় ৫  | S3 এনক্রিপশন বিকল্প: SSE-S3, SSE-KMS, SSE-C                            |
| অধ্যায় ৮  | বিশ্রামে RDS এনক্রিপশন (তৈরিতে সক্ষম করতে হবে)                     |

মূল পরীক্ষার প্যাটার্ন:

- "স্বয়ংক্রিয়ভাবে ডেটাবেস ক্রেডেনশিয়াল রোটেট করুন" → RDS ইন্টিগ্রেশন সহ Secrets Manager
- "অ্যাকাউন্ট জুড়ে কে এনক্রিপশন কী ব্যবহার করতে পারে তা নিয়ন্ত্রণ করুন" → KMS key policy
- "non-secret কনফিগারেশন মান সংরক্ষণ করুন" → SSM Parameter Store (Secrets Manager নয়)
- "কোম্পানি-পরিচালিত কী দিয়ে S3 অবজেক্ট এনক্রিপ্ট করুন" → CMK সহ SSE-KMS

## ডোমেইন ২: স্থিতিস্থাপক আর্কিটেকচার ডিজাইন করুন (২৬%)

**টাস্ক ২.১ — স্কেলযোগ্য এবং আলগাভাবে মিলিত আর্কিটেকচার ডিজাইন করুন**

মূল ধারণা: Auto Scaling, লোড ব্যালেন্সার, SQS/SNS ডিকাপলিং, Lambda ইভেন্ট ট্রিগার, ECS/EKS, Step Functions।

| অধ্যায়    | বিষয়                                                            |
|------------|------------------------------------------------------------------|
| অধ্যায় ৭  | Auto Scaling Groups, Application Load Balancer, স্কেলিং পলিসি |
| অধ্যায় ১৯ | SQS (কিউ দিয়ে ডিকাপলিং), SNS (fan-out বিজ্ঞপ্তি)        |
| অধ্যায় ২০ | Lambda: সার্ভারলেস কম্পিউট, ইভেন্ট ট্রিগার, concurrency          |
| অধ্যায় ২১ | ECS এবং EKS: কন্টেইনারাইজড মাইক্রোসার্ভিস                   |
| অধ্যায় ২২ | Step Functions: ওয়ার্কফ্লো অর্কেস্ট্রেশন                           |
| অধ্যায় ২৬ | Kinesis: রিয়েল-টাইম ডেটা স্ট্রিমিং                                |

মূল পরীক্ষার প্যাটার্ন:

- "অর্ডার প্রক্রিয়াকরণকে ইনভেন্টরি আপডেট থেকে ডিকাপল করুন" → সার্ভিসের মধ্যে SQS কিউ
- "একটি নতুন অর্ডার দেওয়া হলে একাধিক সার্ভিসকে বিজ্ঞাপিত করুন" → SQS subscriptions সহ SNS topic (fan-out)
- "স্বয়ংক্রিয়ভাবে S3 আপলোড প্রক্রিয়া করুন" → S3 ইভেন্ট নোটিফিকেশন → Lambda
- "রিট্রাই লজিক সহ একটি মাল্টি-স্টেপ ওয়ার্কফ্লো চালান" → Step Functions

---

**টাস্ক ২.২ — অত্যন্ত উপলব্ধ এবং/অথবা ফল্ট-টলেরেন্ট আর্কিটেকচার ডিজাইন করুন**

মূল ধারণা: Multi-AZ, Multi-Region, Route 53 failover, RDS রিড রেপ্লিকা, Aurora Global Database, ব্যাকআপ এবং রিস্টোর।

| অধ্যায়    | বিষয়                                                                                        |
|------------|----------------------------------------------------------------------------------------------|
| অধ্যায় ২  | AWS গ্লোবাল অবকাঠামো: অঞ্চল, AZ, এজ লোকেশন                                                  |
| অধ্যায় ৭  | একাধিক AZ জুড়ে ALB, ASG অস্বাস্থ্যকর ইনস্ট্যান্স প্রতিস্থাপন করে                                    |
| অধ্যায় ৮  | RDS Multi-AZ: সিঙ্ক্রোনাস রেপ্লিকেশন, স্বয়ংক্রিয় ফেলওভার                                    |
| অধ্যায় ১২ | Route 53: failover রাউটিং, latency রাউটিং, স্বাস্থ্য পরীক্ষা                                   |
| অধ্যায় ১৮ | Multi-AZ বনাম Multi-Region: RTO/RPO, DR কৌশল (pilot light, warm standby, active-active) |
| অধ্যায় ২৪ | Aurora Global Database: ক্রস-রিজিয়ন রিড রেপ্লিকা, < ১s রেপ্লিকেশন ল্যাগ                     |

মূল পরীক্ষার প্যাটার্ন:

- "প্রাইমারি RDS ব্যর্থ হলে স্বয়ংক্রিয়ভাবে failover করুন" → RDS Multi-AZ (Read Replica নয়)
- "কম লেটেন্সি সহ বৈশ্বিকভাবে রিড পরিবেশন করুন" → Aurora Global Database
- "প্রাইমারি অনুপলব্ধ হলে সেকেন্ডারি অঞ্চলে ট্র্যাফিক রুট করুন" → Failover রাউটিং + স্বাস্থ্য পরীক্ষা সহ Route 53
- "১ মিনিটের RTO, ০-র RPO" → Multi-AZ ডিপ্লয়মেন্ট (Multi-Region নয়)
- "১৫ মিনিটের RTO, ক্রস-রিজিয়ন" → Pilot Light কৌশল

## ডোমেইন ৩: হাই-পারফর্মিং আর্কিটেকচার ডিজাইন করুন (২৪%)

**টাস্ক ৩.১ — হাই-পারফর্মিং এবং/অথবা স্কেলযোগ্য স্টোরেজ সমাধান নির্ধারণ করুন**

মূল ধারণা: S3 বনাম EBS বনাম EFS, স্টোরেজ ক্লাস নির্বাচন, S3 Transfer Acceleration, মাল্টিপার্ট আপলোড, অ্যাসেটের জন্য CloudFront।

| অধ্যায়    | বিষয়                                                              |
|------------|--------------------------------------------------------------------|
| অধ্যায় ৫  | S3: অবজেক্ট স্টোরেজ, স্টোরেজ ক্লাস, ভার্সনিং, লাইফসাইকেল         |
| অধ্যায় ৬  | EBS: ব্লক স্টোরেজ টাইপ (gp3, io2, st1), EFS: শেয়ার্ড ফাইল স্টোরেজ |
| অধ্যায় ২৩ | S3 স্টোরেজ ক্লাস ট্রানজিশন, Glacier পুনরুদ্ধার বিকল্প            |
| অধ্যায় ২৮ | EBS রাইট-সাইজিং, gp2→gp3 মাইগ্রেশন, স্ন্যাপশট ম্যানেজমেন্ট           |

মূল পরীক্ষার প্যাটার্ন:

- "একাধিক EC2 ইনস্ট্যান্স থেকে অ্যাক্সেসযোগ্য শেয়ার্ড ফাইল সিস্টেম" → EFS (EBS নয়; EBS একটি ইনস্ট্যান্সে সংযুক্ত)
- "ডেটাবেস ওয়ার্কলোডের জন্য হাই IOPS" → io2 EBS
- "৯০ দিনে অ্যাক্সেস না হওয়া ফাইলের খরচ কমান" → S3 লাইফসাইকেল পলিসি → Glacier
- "দূরবর্তী অবস্থান থেকে বড় ফাইল আপলোড দ্রুত করুন" → S3 Transfer Acceleration

---

**টাস্ক ৩.২ — হাই-পারফর্মিং এবং/অথবা স্কেলযোগ্য কম্পিউট সমাধান নির্ধারণ করুন**

মূল ধারণা: EC2 ইনস্ট্যান্স পরিবার, Graviton প্রসেসর, Auto Scaling, Lambda, Fargate, Spot Instances।

| অধ্যায়    | বিষয়                                                                                   |
|------------|-----------------------------------------------------------------------------------------|
| অধ্যায় ৪  | EC2 ইনস্ট্যান্স টাইপ: compute-optimized (c), memory-optimized (r), general purpose (m, t) |
| অধ্যায় ৭  | Auto Scaling: ওয়েব টায়ারের জন্য অনুভূমিক স্কেলিং                                          |
| অধ্যায় ২০ | Lambda: concurrency, সামঞ্জস্যপূর্ণ লেটেন্সির জন্য provisioned concurrency                   |
| অধ্যায় ২১ | ECS Fargate: সার্ভারলেস কন্টেইনার                                                      |
| অধ্যায় ২৭ | ফল্ট-টলেরেন্ট ব্যাচ ওয়ার্কলোডের জন্য Spot Instances                                     |

মূল পরীক্ষার প্যাটার্ন:

## পরীক্ষার আগে চেকলিস্ট

**উচ্চ-ওজনের ক্ষেত্র (সর্বাধিক দেখা যাওয়ার সম্ভাবনা)**

- [ ] SQS বনাম SNS বনাম EventBridge (pull বনাম push বনাম ইভেন্ট রাউটিং)

- [ ] CloudFront: স্ট্যাটিকের জন্য CDN, গতিশীলের জন্য Global Accelerator

- [ ] "ডিকাপল" সবসময় SQS মানে নয় — SNS fan-out এবং EventBridge ও ডিকাপলিং প্যাটার্ন
- [ ] Shield Standard বিনামূল্যে এবং স্বয়ংক্রিয়; Advanced একটি প্রদত্ত subscription
