# অধ্যায় ৩০: লুকানো খরচ

স্টোরেজ খরচ একটি লাইনে দেখা যায়: "S3: $১৯৮।" কম্পিউট খরচ একটি লাইনে দেখা যায়: "EC2: $২,৩৪০।" নেটওয়ার্কিং খরচ "Data Transfer Out," "NAT Gateway Processing," "VPC Peering Data Transfer," এবং "CloudFront Data Transfer"-এর মতো নামের এক ডজন লাইন আইটেমে ছড়িয়ে থাকে। বেশিরভাগ ইঞ্জিনিয়ার সেগুলি একবার যোগ করেন, পলক ফেলেন এবং আবার যোগ করেন।

Tom বলেছিলেন: "নেটওয়ার্কিং খরচ। এটাই পরের।"

তিনি বিল টেনে আনলেন। ডেটা ট্রান্সফার বিভাগ খুঁজে পেলেন। সমস্ত লাইন আইটেম যোগ করলেন।

AWS-এ নেটওয়ার্কিং খরচ একটি শহরের টোল সিস্টেমের মতো: শহরে প্রবেশ করা বিনামূল্যে, কিন্তু আপনি নেওয়া প্রতিটি সুড়ঙ্গে অর্থ খরচ হয়, এবং আশেপাশে যেতেও একটু সময় লাগে। বেশিরভাগ মানুষ টোলের কথা ভাবেন না যতক্ষণ না মাসের শেষে একটি বিল পান এবং বুঝতে পারেন তারা প্রতিদিন টানেলে যাচ্ছিলেন যখন সারাটা সময় একটি বিনামূল্যের সারফেস রোড ছিল। এই অধ্যায়ের লক্ষ্য হলো প্রতিটি টোল বুথ বোঝা — এবং সিদ্ধান্ত নেওয়া কোনগুলি দেওয়া মূল্য।

$৮৪৭/মাস।

"আমরা ডেটা ট্রান্সফারে মাসে $৮৪৭ খরচ করছি," তিনি বললেন।

"এটা কি অনেক?" Leo জিজ্ঞেস করলেন।

"আমরা অপ্টিমাইজ করার আগে আমাদের S3 বিলের চেয়ে বেশি। এবং আমি এমন ডেটা ট্রান্সফার বিল আছে জানতামই না।"

Maya তাকালেন। "ডেটা ট্রান্সফার ঠিক কী?"

"AWS বাইট সরানোর জন্য যা চার্জ করে। AWS-এ বাইট: সাধারণত বিনামূল্যে। ইন্টারনেটে AWS থেকে বাইট আউট: চার্জ করা হয়। ভিন্ন অঞ্চলে সার্ভিসগুলির মধ্যে বাইট: চার্জ করা হয়। NAT Gateway-এর মাধ্যমে যাওয়া বাইট: চার্জ করা হয়।"

"আপনি কি এটি ভাঙতে পারেন?"

Tom পারলেন। এবং যা পেলেন তা দলটির আর্কিটেকচার সম্পর্কে চিন্তা করার পদ্ধতি পরিবর্তন করল।

**AWS কীভাবে ডেটা ট্রান্সফারের জন্য চার্জ করে**

AWS-এর ডেটা ট্রান্সফার মূল্য নির্ধারণ অপ্রতিসম:

**AWS-এ (ইনবাউন্ড)**: বিনামূল্যে। আপনি যত ডেটা চান আপলোড করতে পারেন।

**ইন্টারনেটে AWS থেকে আউট (আউটবাউন্ড)**: চার্জ করা হয়। প্রথম ১০০GB/মাস বিনামূল্যে। এরপর:

- প্রথম ১০TB/মাসের জন্য $০.০৯/GB (US অঞ্চল)
- পরবর্তী ৪০TB-এর জন্য $০.০৮৫/GB
- উচ্চতর ভলিউমে কম

**একই Availability Zone-এর মধ্যে**: বিনামূল্যে। একই AZ-এ EC2 ইনস্ট্যান্সগুলি একে অপরের সাথে কথা বলা কিছু দেয় না।

**Availability Zones-এর মধ্যে (একই অঞ্চল)**: প্রতিটি দিকে $০.০১/GB। একটি ছোট কিন্তু বাস্তব খরচ।

**অঞ্চলগুলির মধ্যে**: অঞ্চলগুলির উপর নির্ভর করে $০.০২-০.০৮/GB। ক্রস-রিজিয়ন ট্র্যাফিক উল্লেখযোগ্যভাবে বেশি ব্যয়বহুল।

**NAT Gateway**: প্রক্রিয়া করা প্রতি GB-তে $০.০৪৫। আপনার প্রাইভেট EC2 ইনস্ট্যান্স ইন্টারনেটে পৌঁছাতে NAT Gateway-এর মাধ্যমে পাঠানো প্রতিটি বাইট — এবং ফেরা আসা প্রতিটি বাইট — চার্জ করা হয়।

**CloudFront**: সরাসরি AWS-থেকে-ইন্টারনেটের চেয়ে কম ডেটা ট্রান্সফার রেট। প্রথম ১০TB-এর জন্য $০.০৮৫/GB (সরাসরি ডেটা ট্রান্সফার আউটের চেয়ে সামান্য কম)। CloudFront প্রায়ই মোট ট্রান্সফার খরচ কমায় কারণ এর এজ ক্যাশিং মানে অরিজিন কম ঘন ঘন ডেটা পরিবেশন করে।

**Tom-এর বিশ্লেষণ**

প্রতিটি লাইন আইটেম শ্রেণীবদ্ধ করার পরে:

**ইন্টারনেটে আউটবাউন্ড ডেটা**: $২১৪/মাস

- বৈশ্বিকভাবে গ্রাহকদের API প্রতিক্রিয়া
- CloudFront ক্যাশ ফিল (যখন এজ লোকেশন অরিজিন থেকে ফেচ করে)

**NAT Gateway প্রক্রিয়াকরণ**: $২৮৯/মাস

- বাহ্যিক API (পেমেন্ট প্রসেসর, ইমেইল সার্ভিস, ম্যাপ ডেটা) কল করা অ্যাপ্লিকেশন সার্ভার
- DynamoDB কল NAT Gateway-এর মাধ্যমে যাওয়া (কিছু টেবিলের জন্য VPC endpoints সেটআপ করার আগে)

**ক্রস-AZ ডেটা ট্রান্সফার**: $১৭৮/মাস

- EC2 ইনস্ট্যান্সে লোড ব্যালেন্সার (লোড ব্যালেন্সার একটি AZ-এ, কিছু ইনস্ট্যান্স অন্যটিতে)
- অ্যাপ্লিকেশন সার্ভার থেকে RDS রিড রেপ্লিকা (একটি ভিন্ন AZ-এ)

**ক্রস-রিজিয়ন ডেটা ট্রান্সফার**: $১৬৬/মাস

- Aurora Global Database রেপ্লিকেশন (us-east-1-এ প্রাইমারি, us-west-2-এ reader)
- ব্যাকআপের জন্য S3 Cross-Region Replication

**NAT Gateway: সবচেয়ে বড় বিস্ময়**

NAT Gateway প্রক্রিয়াকরণ ফিতে $২৮৯/মাস ছিল সবচেয়ে বড় আইটেম। এবং এটি আংশিকভাবে অপ্রয়োজনীয় ছিল।

অধ্যায় ১১-এ, Tom S3 এবং DynamoDB-এর জন্য VPC Gateway Endpoints সেটআপ করেছিলেন। এগুলি বিনামূল্যে ছিল। কিন্তু তিনি অন্যান্য বেশ কিছু সার্ভিসের জন্য Interface Endpoints সেটআপ করা মিস করেছিলেন:

- প্যাচ ম্যানেজমেন্টের জন্য Systems Manager (SSM)
- ক্রেডেনশিয়াল পুনরুদ্ধারের জন্য Secrets Manager
- মেট্রিক এবং লগ শিপিংয়ের জন্য CloudWatch
- মেসেজ পোলিংয়ের জন্য SQS

প্রাইভেট EC2 ইনস্ট্যান্স থেকে এই সার্ভিসগুলিতে প্রতিটি কল NAT Gateway-এর মাধ্যমে যাচ্ছিল। প্রতিটি কল $০.০৪৫/GB চার্জ হচ্ছিল।

এই সার্ভিসগুলির জন্য **Interface Endpoints**: $০.০১/ঘণ্টা প্রতি AZ + $০.০১/GB ডেটা প্রক্রিয়া করা।

Nimbus-এর ভলিউমে, SSM Interface Endpoint মাসে প্রায় $১৫ খরচ হবে এবং NAT Gateway চার্জে মাসে প্রায় $৪৩ সাশ্রয় করবে (কারণ SSM প্যাচ ম্যানেজমেন্ট এবং প্যারামিটার স্টোর কলের জন্য উল্লেখযোগ্য ডেটা ভলিউম তৈরি করে)।

Endpoint খরচ এবং সাশ্রয় সার্ভিস এবং ভলিউম অনুযায়ী পরিবর্তিত হয়। Tom গণনা করলেন যে চারটি হাই-ট্র্যাফিক সার্ভিসের জন্য Interface Endpoints সেটআপ করতে মোট $৬২/মাস খরচ হবে এবং NAT Gateway প্রক্রিয়াকরণে মাসে প্রায় $১৪০ সাশ্রয় করবে।

নেট সাশ্রয়: endpoint সেটআপ থেকেই $৭৮/মাস।

**ক্রস-AZ ট্র্যাফিক: একটি আর্কিটেকচারাল প্রশ্ন**

ক্রস-AZ ডেটা ট্রান্সফারে $১৭৮/মাস আরো জটিল ছিল।

এর কিছু অনিবার্য ছিল: লোড ব্যালেন্সার AZ-গুলিতে ট্র্যাফিক বিতরণ করে, তাই কিছু অনুরোধ একটি AZ-এ উদ্ভূত হয় এবং লোড ব্যালেন্সার অন্য AZ-এ একটি ইনস্ট্যান্সে ফরওয়ার্ড করে।

কিছু অপ্টিমাইজযোগ্য ছিল: অ্যাপ্লিকেশন us-east-1a-তে RDS প্রাইমারিতে লিখতে এবং us-east-1b-এ রিড রেপ্লিকা থেকে পড়তে কনফিগার করা হয়েছিল। প্রতিটি রিড কোয়েরি AZ সীমানা অতিক্রম করেছিল।

রিডগুলির জন্য, একটি সমাধান: অ্যাপ্লিকেশনটিকে অনুরোধকারী ইনস্ট্যান্সের মতো একই AZ-এ রিড রেপ্লিকা পছন্দ করতে কনফিগার করুন। প্রতিটি AZ তার নিজস্ব রিড রেপ্লিকা পায়। ট্র্যাফিক স্থানীয় থাকে।

ট্রেড-অফ: বেশি রিড রেপ্লিকা = বেশি খরচ। যদি ক্রস-AZ ট্র্যাফিক খরচ $৫০/মাস হয় এবং একটি অতিরিক্ত রিড রেপ্লিকা $১৯০/মাস খরচ হয়, AZ-স্থানীয় অপ্টিমাইজেশন পরিশোধ করে না।

Tom গণনা করলেন: তাদের বর্তমান কোয়েরি ভলিউমে, ক্রস-AZ ট্র্যাফিক মাত্র $৩১/মাস ছিল $১৭৮-এর মধ্যে। রেপ্লিকা যোগ করার মূল্য নেই।

অন্য ক্রস-AZ খরচ ছিল লোড ব্যালেন্সার রাউটিং এবং সার্ভিস-টু-সার্ভিস যোগাযোগ — বর্তমান আর্কিটেকচার স্তরে মূলত অনিবার্য।

"এটি এমন একটি ক্ষেত্রে যেখানে খরচ বোঝার মানে আপনার এটি ঠিক করা উচিত নয়," Tom বললেন।

"ক্রস-AZ ট্র্যাফিক সম্পূর্ণভাবে দূর করতে কত খরচ হবে?" Maya জিজ্ঞেস করলেন।

"সব কিছু এক AZ-এ রাখা Multi-AZ-এর উদ্দেশ্য পরাজিত করে। এটি $৩১/মাস সাশ্রয় উচ্চ প্রাপ্যতা হারানোর মূল্যে।"

"তাহলে আমরা এটি রেখে দিই," তিনি বললেন।

"আমরা এটি রেখে দিই।"

এটি পরিপক্ব খরচ কথোপকথন: কখনো কখনো আপনি কিছুর জন্য দেন কারণ বিকল্পটি ঝুঁকিতে বেশি খরচ করে।

**CloudFront: ডেটা ট্রান্সফার ছাড়**

এখানে একটি পাল্টা স্বজ্ঞাত সত্য: CloudFront-এর মাধ্যমে ডেটা পরিবেশন সাধারণত সরাসরি EC2 বা S3 থেকে পরিবেশনের চেয়ে সস্তা।

**সরাসরি EC2 থেকে ইন্টারনেটে**: $০.০৯/GB
**CloudFront থেকে ইন্টারনেটে**: $০.০৮৫/GB (সামান্য সস্তা)

কিন্তু আসল সাশ্রয় প্রতি-GB রেট নয় — এটি হলো CloudFront এজ লোকেশনে ডেটা ক্যাশ করে। যদি ১,০০০ ব্যবহারকারী একই মেনু ফটো অনুরোধ করেন:

- **CloudFront ছাড়া**: ১,০০০ অনুরোধ S3 অরিজিনে আঘাত করে × ফটোর আকার × $০.০৯/GB
- **CloudFront সহ**: ১টি অনুরোধ S3-এ আঘাত করে (ক্যাশ মিস) + ৯৯৯টি অনুরোধ এজ ক্যাশ থেকে CloudFront রেটে পরিবেশন করা

অধ্যায় ১৩ থেকে ৮৩% ক্যাশ হিট রেট সহ Nimbus-এর জন্য, তারা এজ ক্যাশ থেকে ৮৩% অনুরোধ পরিবেশন করছিল। প্রকৃত অরিজিন ডেটা ট্রান্সফার ছিল মোট অনুরোধের ১৭% — ৮৩% "আউটবাউন্ড" ট্র্যাফিক এজে ক্যাশ করা ছিল।

"CloudFront শুধু পারফরম্যান্সের জন্য CDN নয়," Tom বললেন। "এটি ডেটা ট্রান্সফারের জন্য খরচ অপ্টিমাইজেশনও।"

Leo চিন্তিতভাবে তাকালেন। "আমাদের CloudFront-এর মাধ্যমে সমস্ত স্ট্যাটিক কন্টেন্ট ডেলিভারি করা উচিত, এমনকি লেটেন্সি-সংবেদনশীল নয় এমন অ্যাসেটের জন্যও।"

"সঠিক। যদি ব্যবহারকারীরা AWS থেকে এটি ডাউনলোড করছেন, এটি CloudFront-এর মাধ্যমে যাওয়া উচিত।"

**S3 Select: কোয়েরিতে ডেটা ট্রান্সফার কমানো**

একটি সূক্ষ্ম অপ্টিমাইজেশন: **S3 Select** আপনাকে আপনার অ্যাপ্লিকেশনে পুরো ফাইল ডাউনলোড করে ফিল্টার করার পরিবর্তে একটি S3 অবজেক্ট (CSV, JSON, Parquet) থেকে শুধুমাত্র প্রয়োজনীয় সারি এবং কলামগুলি পুনরুদ্ধার করতে দেয়।

S3 Select ছাড়া:
```python
# ৫০০MB ফাইল ডাউনলোড করুন, মেমরিতে প্রক্রিয়া করুন
data = s3.get_object(Bucket='analytics', Key='orders-2024.csv')
df = pd.read_csv(data['Body'])
result = df[df['restaurant_id'] == '47'][['order_id', 'total']]
```

S3 Select সহ:
```python
# S3 প্রথমে ফিল্টার করুন, শুধুমাত্র মিলে যাওয়া সারি ট্রান্সফার করুন (~৫০০MB-এর পরিবর্তে ~২MB)
response = s3.select_object_content(
    Bucket='analytics',
    Key='orders-2024.csv',
    Expression="SELECT order_id, total FROM S3Object WHERE restaurant_id = '47'"
)
```

S3 Select আপনার অ্যাপ্লিকেশনে S3 থেকে ট্রান্সফার করা ডেটা কমায়। নির্বাচনী কোয়েরি সহ বড় ফাইলের জন্য, এটি ডেটা ভলিউমে ১০-১০০x হ্রাস হতে পারে — এবং তাই খরচে।

## শক্তি এবং সীমাবদ্ধতা

**NAT Gateway খরচ**:

- NAT Gateway-এর মাধ্যমে বড় ডেটা ভলিউম দ্রুত জমা হয়
- VPC Endpoints কিছু NAT খরচ সম্পূর্ণভাবে দূর করে
- আপনার প্রাইভেট ইনস্ট্যান্সগুলি কোন সার্ভিস কল করে এবং endpoint পাওয়া যায় কিনা তা পর্যালোচনা করুন

**খরচের জন্য CloudFront**:

- ক্যাশ হিট রেট সরাসরি খরচ সাশ্রয় নির্ধারণ করে
- উচ্চ ক্যাশ হিট রেট = কম অরিজিন ট্রান্সফার + কম সামগ্রিক ট্রান্সফার খরচ
- CloudFront-এর মাধ্যমে সমস্ত স্ট্যাটিক অ্যাসেট ডেলিভারি সরান

**ক্রস-AZ ট্রেড-অফ**:

- ক্রস-AZ ট্র্যাফিক দূর করতে সাধারণত আর্কিটেকচারাল পরিবর্তন প্রয়োজন যা সাশ্রয়ের চেয়ে বেশি খরচ
- অপ্টিমাইজ করার আগে সাবধানতার সাথে গণনা করুন

**S3 Select**:

- S3 অবজেক্টে নির্বাচনী কোয়েরির জন্য উল্লেখযোগ্য সাশ্রয়
- পুরো ফাইলের প্রয়োজন হলে সাহায্য করে না

পরবর্তী অধ্যায়ে: ছয়-স্তম্ভ ফ্রেমওয়ার্ক যা প্রতিটি আর্কিটেকচার পর্যালোচনা শুরু করা উচিত এমন প্রশ্ন জিজ্ঞেস করে।

## সারসংক্ষেপ

- AWS **আউটবাউন্ড ডেটার** জন্য চার্জ করে (ইন্টারনেট: ~$০.০৯/GB), **ক্রস-AZ ট্র্যাফিক** ($০.০১/GB প্রতিটি দিক), **ক্রস-রিজিয়ন ট্র্যাফিক** ($০.০২-০.০৮/GB), এবং **NAT Gateway প্রক্রিয়াকরণ** ($০.০৪৫/GB)।
- **ইনবাউন্ড ডেটা** বিনামূল্যে। **একই-AZ ট্র্যাফিক** বিনামূল্যে।
- **VPC Gateway Endpoints** (S3, DynamoDB): বিনামূল্যে। এই সার্ভিসগুলির জন্য NAT Gateway খরচ দূর করে।
- **VPC Interface Endpoints**: ঘণ্টা প্রতি এবং প্রতি GB মূল্য। হাই-ভলিউম সার্ভিসের জন্য NAT Gateway-এর চেয়ে সস্তা।
- **CloudFront** সরাসরি EC2-থেকে-ইন্টারনেটের চেয়ে কম রেটে ডেটা পরিবেশন করে এবং ক্যাশিংয়ের মাধ্যমে অরিজিন ট্রান্সফার ভলিউম নাটকীয়ভাবে কমায়।
- **S3 Select** সোর্সে ফিল্টার করে S3 থেকে ডেটা ট্রান্সফার কমায়।
- কিছু নেটওয়ার্কিং খরচ আর্কিটেকচারাল ট্রেড-অফ (HA-এর জন্য ক্রস-AZ) — সেগুলি বুঝুন, সবসময় দূর করবেন না।

## পরীক্ষার টিপস

*SAA-C03 ডোমেইন: কস্ট-অপ্টিমাইজড আর্কিটেকচার ডিজাইন করুন (ডোমেইন ৪, টাস্ক ৪.৪)*

- **NAT Gateway বনাম VPC Endpoints**: পরীক্ষার পরিস্থিতি: "প্রাইভেট সাবনেটে EC2 ঘন ঘন S3/DynamoDB কল করে — NAT Gateway খরচ কীভাবে কমাবেন?" → VPC Gateway Endpoints (S3 এবং DynamoDB-এর জন্য বিনামূল্যে)।
- **ডেটা ট্রান্সফার মূল্য নির্ধারণ নিয়ম**:
  - AWS-এ: বিনামূল্যে
  - একই-AZ: বিনামূল্যে
  - ক্রস-AZ: চার্জ
  - ক্রস-রিজিয়ন: চার্জ (উচ্চতর রেট)
  - ইন্টারনেট: চার্জ (উল্লেখযোগ্য রেট)
- **খরচ অপ্টিমাইজেশন হিসাবে CloudFront**: "বৈশ্বিক কন্টেন্ট ডেলিভারির জন্য ডেটা ট্রান্সফার খরচ কমান" → CloudFront। ক্যাশ লেয়ার অরিজিন অনুরোধ কমায়।
- **S3 Transfer Acceleration**: CloudFront এজ লোকেশন ব্যবহার করে S3-এ আপলোড গতিশীল করে। স্ট্যান্ডার্ড S3-এর চেয়ে উচ্চতর খরচ। ভৌগোলিকভাবে দূরবর্তী অবস্থান থেকে বড় ফাইল আপলোড করা গ্রাহকদের জন্য ব্যবহার করুন।
- **ক্রস-রিজিয়ন রেপ্লিকেশন খরচ**: অঞ্চল জুড়ে ডেটা রেপ্লিকেট করলে ডেটা ট্রান্সফার চার্জ হয়। S3 CRR-এর জন্য, আপনি ডেটা ট্রান্সফার আউট রেট এবং S3 রিকোয়েস্ট খরচ উভয় দেন।
- **PrivateLink (VPC Interface Endpoints)**: AWS সার্ভিসে এবং অন্য AWS গ্রাহকদের দ্বারা হোস্ট করা সার্ভিসে প্রাইভেট সংযোগ প্রদান করে। NAT-এর মাধ্যমে যাওয়ার চেয়ে বেশি নিরাপদ, হাই-ভলিউম সার্ভিসের জন্য প্রায়ই সস্তা।

## অনুশীলনী

**অনুশীলনী ১ — স্মরণ**

একটি VPC Gateway Endpoint এবং একটি VPC Interface Endpoint-এর মধ্যে পার্থক্য ব্যাখ্যা করুন। প্রতিটি কোন AWS সার্ভিসের জন্য উপলব্ধ, এবং প্রতিটির খরচ কী?

*(ইঙ্গিত: Gateway Endpoints বিনামূল্যে কিন্তু শুধুমাত্র S3 এবং DynamoDB-এর জন্য। Interface Endpoints ঘণ্টা প্রতি খরচ হয় কিন্তু বেশিরভাগ অন্যান্য AWS সার্ভিসের জন্য কাজ করে।)*

**অনুশীলনী ২ — পরীক্ষার অনুশীলন**

*পরিস্থিতি*: একটি কোম্পানির অ্যাপ্লিকেশন প্রাইভেট সাবনেটে EC2 ইনস্ট্যান্সে চলে। ইনস্ট্যান্সগুলি Amazon SQS এবং Amazon S3-এ ঘন ঘন API কল করে। বর্তমানে, সমস্ত ট্র্যাফিক NAT Gateway-এর মাধ্যমে প্রস্থান করে। দলটি NAT Gateway খরচ কমাতে চায়। ডেটা নিরাপত্তা বজায় রাখতে হবে — কোনো ট্র্যাফিক পাবলিক ইন্টারনেট অতিক্রম করবে না।

ন্যূনতম চলমান খরচ সহ কোন পদ্ধতি এই প্রয়োজনীয়তাগুলি সর্বোত্তমভাবে পূরণ করে?

A) SQS-এর জন্য একটি Gateway Endpoint এবং S3-এর জন্য একটি Gateway Endpoint তৈরি করুন  
B) SQS-এর জন্য একটি Interface Endpoint এবং S3-এর জন্য একটি Gateway Endpoint তৈরি করুন  
C) SQS এবং S3 উভয়ের জন্য Interface Endpoints তৈরি করুন  
D) API কলের জন্য সরাসরি ইন্টারনেট গেটওয়ে ব্যবহার করতে NAT Gateway সরিয়ে ফেলুন

**ইঙ্গিত ১**: Gateway Endpoints শুধুমাত্র S3 এবং DynamoDB-এর জন্য উপলব্ধ।

**ইঙ্গিত ২**: Interface Endpoints SQS এবং অন্যান্য অনেক সার্ভিসের জন্য উপলব্ধ (কিন্তু অর্থ খরচ হয়)।

**ইঙ্গিত ৩**: প্রাইভেট সাবনেট রুট টেবিলে Internet Gateway-এ একটি রুট যোগ করলে এটি পাবলিক সাবনেট হয়ে যাবে — নিরাপত্তা প্রয়োজনীয়তা লঙ্ঘন করে।

**উত্তর**: B

**ব্যাখ্যা**: S3 একটি Gateway Endpoint ব্যবহার করে (বিনামূল্যে)। SQS-এর জন্য একটি Interface Endpoint (মূল্য নির্ধারিত) প্রয়োজন। এই সংমিশ্রণ উভয় সার্ভিসের NAT Gateway ডেটা প্রক্রিয়াকরণ খরচ দূর করে। সমস্ত ট্র্যাফিক AWS-এর প্রাইভেট নেটওয়ার্কের মধ্যে থাকে — কোনো পাবলিক ইন্টারনেট ট্রাভার্সাল নেই।

**কেন A নয়?** Gateway Endpoints SQS-এর জন্য উপলব্ধ নয়। শুধুমাত্র S3 এবং DynamoDB-এর Gateway Endpoints আছে।

**কেন C নয়?** এটি কাজ করে, কিন্তু S3-এর জন্য Interface Endpoint ব্যবহার করা (বিনামূল্যের Gateway Endpoint-এর পরিবর্তে) অপ্রয়োজনীয় ঘণ্টার চার্জ বহন করে। S3 এবং DynamoDB-এর জন্য সবসময় বিনামূল্যের Gateway Endpoint ব্যবহার করুন।

**কেন D নয়?** প্রাইভেট সাবনেট রুট টেবিল থেকে Internet Gateway-এ একটি রুট যোগ করা এটিকে পাবলিক সাবনেট করে। প্রাইভেট সাবনেটে EC2 ইনস্ট্যান্সগুলিতে সাধারণত Elastic IP নেই, তাই তারা অতিরিক্ত পরিবর্তন ছাড়াই Internet Gateway-এর মাধ্যমে রুট করতে পারত না — এবং এটি করলে ইনবাউন্ড ইন্টারনেট ট্র্যাফিকে তাদের উন্মুক্ত করত।

*SAA-C03 ডোমেইন: কস্ট-অপ্টিমাইজড আর্কিটেকচার ডিজাইন করুন — টাস্ক ৪.৪*

**অনুশীলনী ৩ — আর্কিটেকচার চ্যালেঞ্জ** *(ঐচ্ছিক)*

Nimbus-এর পশ্চিম উপকূলের ব্যবহারকারীরা উল্লেখযোগ্য ট্র্যাফিক তৈরি করেন। অ্যাপ্লিকেশন us-east-1 (ভার্জিনিয়া) থেকে তাদের পরিবেশন করে। বর্তমানে:

- API প্রতিক্রিয়া সরাসরি us-east-1 EC2 ইনস্ট্যান্স থেকে পশ্চিম উপকূলের ব্যবহারকারীদের কাছে যায় (~৮০ms, $০.০৯/GB)
- মেনু ফটো S3 us-east-1 থেকে সিয়াটলের CloudFront এজের মাধ্যমে যায় (ক্যাশিংয়ের পরে ~৮ms)

দলটি পশ্চিম উপকূলের ব্যবহারকারীদের API লেটেন্সি কমাতে us-west-2 (ওরেগন)-এ একটি দ্বিতীয় অ্যাপ্লিকেশন অঞ্চল যোগ করার কথা বিবেচনা করছে।

এই পরিবর্তনের ডেটা ট্রান্সফার খরচ বিশ্লেষণ করুন। ডুয়াল-রিজিয়ন সেটআপ কোন নতুন ক্রস-রিজিয়ন ডেটা ট্রান্সফার খরচ বহন করবে? Route 53 লেটেন্সি-ভিত্তিক রাউটিং মোট ট্রান্সফার খরচ কমাবে বা বাড়াবে? কোন অবস্থার (ট্র্যাফিক ভলিউম, লেটেন্সি সংবেদনশীলতা) অধীনে ডুয়াল-রিজিয়ন সেটআপ পরিশোধ করবে?

*(কোনো একক সঠিক উত্তর নেই। লক্ষ্য হলো মাল্টি-রিজিয়ন কস্ট-বেনিফিট বিশ্লেষণ অনুশীলন করা।)*
