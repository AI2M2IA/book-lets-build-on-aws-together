**การเปรียบเปรยกับร้านอาหาร**

ลองนึกภาพครัวของร้านอาหาร ทุกครั้งที่พนักงานเสิร์ฟต้องการรู้เกี่ยวกับเมนูพิเศษวันนี้ พวกเขาเดินไปด้านหลัง ถามพ่อครัว แล้วเดินกลับมาที่โต๊ะ

ตอนนี้ลองนึกภาพพนักงานเสิร์ฟสองร้อยคนและโต๊ะหนึ่งพันโต๊ะ ทุกคนเดินไปด้านหลังถามคำถามเดิม ครัวกลายเป็น bottleneck

วิธีแก้ที่ชัดเจน: เขียนเมนูพิเศษบนกระดานที่ด้านหน้าของร้านอาหาร พนักงานเสิร์ฟทุกคนอ่านจากกระดาน ครัวได้พักผ่อน กระดานอัพเดตเมื่อเมนูพิเศษเปลี่ยน

กระดานนั้นคือ cache

Cache คือที่เก็บข้อมูลที่เร็วของข้อมูลที่ดึงมาล่าสุด แทนที่จะดึงสิ่งเดิมจากแหล่งที่ช้าซ้ำๆ คุณดึงครั้งเดียวและเก็บมันไว้ใกล้ๆ

**พบกับ ElastiCache**

Amazon ElastiCache คือ managed caching service มันรัน caching engines ยอดนิยม — Redis และ Memcached — โดยไม่ต้องจัดการเซิร์ฟเวอร์

**Redis** มีฟีเจอร์มากกว่า รองรับโครงสร้างข้อมูลที่ซับซ้อน (strings, lists, sets, hashes, sorted sets) persistence (ข้อมูลอยู่รอดผ่านการรีสตาร์ท) replication และ pub/sub messaging

**Memcached** เรียบง่ายกว่า Pure key-value caching ขยายในแนวนอน ไม่มี persistence

สำหรับ Nimbus: Redis พวกเขาต้องการ cache ข้อมูลเมนู (มีโครงสร้าง) session tokens (key-value) และต่อมาจะต้องการ sorted sets สำหรับการจัดอันดับ "ร้านอาหารยอดนิยม"

**วิธีที่ Caching ทำงานในทางปฏิบัติ**

รูปแบบ caching พื้นฐานเรียกว่า **cache-aside** (หรือ lazy loading):

1. แอปพลิเคชันต้องการข้อมูล
2. ตรวจสอบ cache ก่อน
3. ถ้าพบ (*cache hit*): ส่งคืนข้อมูลทันที
4. ถ้าไม่พบ (*cache miss*): ไปที่ฐานข้อมูล ดึงข้อมูล เก็บใน cache ส่งคืน

**TTL: จำนานแค่ไหน?**

ทุก cache entry มี **Time-To-Live (TTL)**: ระยะเวลาที่ entry จะหมดอายุและคำขอต่อไปกลับไปที่ฐานข้อมูลเพื่อข้อมูลใหม่

## สรุป

- Cache คือที่เก็บข้อมูลเร็วของข้อมูลที่ดึงมาล่าสุด
- ElastiCache คือ managed caching service ของ AWS รองรับ Redis และ Memcached
- **Redis** มีฟีเจอร์มากกว่า (โครงสร้างข้อมูลซับซ้อน persistence pub/sub) **Memcached** เรียบง่ายกว่า
- **DAX** คือ cache เฉพาะสำหรับ DynamoDB ElastiCache เป็น general-purpose

## เคล็ดลับการสอบ

- **Redis กับ Memcached ในการสอบ**: Redis = persistence, replication, โครงสร้างซับซ้อน, pub/sub Memcached = key-value เรียบง่าย การขยายแนวนอน
- **สัญญาณการใช้ ElastiCache**: "ฐานข้อมูลเป็น bottleneck," "งานที่อ่านหนัก," "ลดความหน่วง," "จัดการ session"
- **สัญญาณ DAX**: "ลดความหน่วงการอ่าน DynamoDB" → DAX ไม่ใช่ ElastiCache
