**Amazon RDS: ฐานข้อมูลที่จัดการ**

**Amazon RDS** — Relational Database Service — จัดการภาระในการดำเนินงานของการรันฐานข้อมูล relational เพื่อให้คุณไม่ต้องทำ

ด้วย RDS, AWS จัดการ:

- การติดตั้งและ patch database engine
- การสำรองข้อมูลอัตโนมัติ (เก็บใน S3 เก็บรักษาสูงสุด 35 วัน)
- Automatic failover (เมื่อ primary ล่ม standby เข้ามาแทนที่โดยอัตโนมัติ)
- การตรวจสอบและตัวชี้วัด
- การเข้ารหัสขณะพักและระหว่างส่ง
- Storage auto-scaling (ถ้าเปิดใช้งาน ดิสก์จะเติบโตเมื่อเต็ม)

คุณจัดการ:

- Database schema (โครงสร้างของตาราง)
- Queries และ application logic
- ใครมีสิทธิ์เข้าถึงฐานข้อมูล
- Instance type ใดที่รันฐานข้อมูล
- การปรับพารามิเตอร์ (แม้ว่า RDS จะให้ค่าเริ่มต้นที่สมเหตุสมผล)

การเปรียบเปรย: การจ้างผู้ดูแลฐานข้อมูลที่ไม่เคยลาป่วย ไม่เคยทำผิดพลาดการกำหนดค่า สำรองข้อมูลรายวันโดยอัตโนมัติ และซ่อมแซมตัวเองถ้าบางสิ่งพัง — แต่ไม่เขียน application logic ของคุณ

**Engines ที่รองรับ**

RDS รองรับ database engines หลายตัว:

- **MySQL** — ฐานข้อมูล relational open-source ที่ใช้กันมากที่สุด
- **PostgreSQL** — มีประสิทธิภาพ ขยายได้ นิยมมากขึ้นสำหรับ workloads ที่ซับซ้อน
- **MariaDB** — MySQL fork แบบ open-source เข้ากันได้อย่างสมบูรณ์
- **Oracle** — ระดับองค์กร
- **Microsoft SQL Server** — สำหรับสภาพแวดล้อม Windows
- **Amazon Aurora** — engine ของ AWS เองที่เข้ากันได้กับ MySQL/PostgreSQL (ครอบคลุมเจาะลึกในบทที่ 24)

สำหรับ Nimbus ตัวเลือกคือ PostgreSQL

**Multi-AZ: Standby ที่เข้ามาแทนที่**

นี่คือคุณสมบัติที่เปลี่ยนการคำนวณความน่าเชื่อถืออย่างสิ้นเชิง

**การ deploy แบบ Multi-AZ** หมายความว่า RDS รักษา standby instance แบบ synchronous ใน Availability Zone ที่แตกต่างจาก primary ทุกธุรกรรมที่ commit ไปยัง primary จะถูก replicate แบบ synchronous ไปยัง standby ก่อนที่การ commit จะได้รับการยืนยัน

เมื่อ primary ล้มเหลว — ความล้มเหลวของฮาร์ดแวร์ AZ outage ซอฟต์แวร์พัง — RDS จะ failover ไปยัง standby โดยอัตโนมัติ DNS record สำหรับ database endpoint ได้รับการอัพเดต แอปพลิเคชันของคุณเชื่อมต่อใหม่กับ primary ใหม่

Failover ใช้เวลา 60-120 วินาที ในช่วงเวลานั้น แอปพลิเคชันของคุณจะพบข้อผิดพลาดการเชื่อมต่อ

Standby ไม่ใช่ read replica มันไม่ให้บริการ read traffic มีวัตถุประสงค์เดียวคือพร้อมที่จะเข้ามาแทนที่

Tom: "Multi-AZ มีราคาเท่าไหร่?"

ประมาณสองเท่าของต้นทุน instance เดียว — เพราะคุณกำลังรัน database instances สองอัน standby มีราคาเท่ากับ primary

Multi-AZ ถูกเปิดใช้งานในบ่ายวันนั้น

**การสำรองข้อมูลอัตโนมัติและการกู้คืนแบบ Point-in-Time**

RDS สำรองข้อมูลอัตโนมัติทุกวัน AWS เก็บการสำรองข้อมูลเหล่านี้ใน S3 คุณสามารถกู้คืนฐานข้อมูลไปยังจุดใดก็ได้ในช่วงเวลาการเก็บรักษาการสำรองข้อมูล

**การกู้คืนแบบ Point-in-time** เป็นหนึ่งในคุณสมบัติที่มีค่าที่สุด: คุณสามารถกู้คืนไปยังวินาทีใดก็ได้ในช่วงเวลาการเก็บรักษา ไม่ใช่แค่ snapshot รายวัน — *วินาทีใดก็ได้*

ถ้าใครรัน `DELETE FROM orders WHERE 1=1` โดยบังเอิญเวลา 14:37 น. คุณสามารถกู้คืนไปยัง 14:36 น.

**Read Replicas: การขยาย Read Traffic**

Multi-AZ เกี่ยวกับความพร้อมใช้งาน **Read replicas** เกี่ยวกับประสิทธิภาพ

Read replica คือสำเนา asynchronous ของฐานข้อมูล primary ที่สามารถให้บริการ read queries ได้ สามารถมี read replicas ได้สูงสุดห้าตัวสำหรับ RDS engines ส่วนใหญ่

คุณสมบัติหลัก:

- Replication เป็น **asynchronous** — อาจมีความล่าช้าเล็กน้อยระหว่าง primary และ replica
- Read replicas สามารถอยู่ใน Region เดียวกันหรือ Region ต่างกัน
- Read replicas สามารถถูก promote เป็นฐานข้อมูลอิสระในสถานการณ์ disaster

## สรุป

- **Amazon RDS** คือ managed relational database service AWS จัดการ patching การสำรองข้อมูล failover และการจัดการพื้นที่เก็บข้อมูล
- **Multi-AZ** รักษา synchronous standby ใน AZ ที่แตกต่างกัน Automatic failover เกิดขึ้นใน 60-120 วินาทีถ้า primary ล้มเหลว
- **การสำรองข้อมูลอัตโนมัติ** พร้อม **point-in-time recovery** ช่วยให้กู้คืนไปยังวินาทีใดก็ได้ในช่วงเวลาการเก็บรักษา
- **Read replicas** คือสำเนา asynchronous ที่ให้บริการ read traffic ลดโหลดบน primary

## เคล็ดลับการสอบ

*SAA-C03 Domain 3 — Task 3.3 (โซลูชันฐานข้อมูล)*

- **Multi-AZ สำหรับ high availability ไม่ใช่ประสิทธิภาพ** Standby ไม่ให้บริการ read traffic Read replicas สำหรับประสิทธิภาพ
- **Multi-AZ failover เป็นอัตโนมัติ** คุณไม่ได้กำหนดค่าว่าเมื่อไหร่หรืออย่างไร
- **Replication lag สำคัญ** Read replicas อาจล้าหลัง primary เล็กน้อย
- **การสำรองข้อมูลอัตโนมัติเก็บไว้ 0-35 วัน** การตั้งค่าการเก็บรักษาเป็น 0 ปิดใช้งานการสำรองข้อมูลอัตโนมัติ
