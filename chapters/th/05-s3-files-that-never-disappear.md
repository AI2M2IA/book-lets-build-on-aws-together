**ปัญหากับการเก็บไฟล์ "บนเซิร์ฟเวอร์"**

เมื่อคุณเก็บไฟล์ไว้ใน EC2 instance โดยตรง — ภายในระบบไฟล์ของมัน — คุณกำลังผูกไฟล์เหล่านั้นเข้ากับวงจรชีวิตของเครื่องนั้นโดยเฉพาะ

สิ่งนี้สร้างปัญหาหลายอย่าง:

**ชั่วคราวโดยธรรมชาติ** EC2 instances สามารถหยุด ยุติ ถูกแทนที่ได้ ดิสก์ในเครื่องของพวกมันไม่ได้ออกแบบมาเพื่อถาวร

**จุดล้มเหลวเดียว** ถ้า instance ล้มเหลว ไฟล์ก็ไปด้วย ไม่มีความซ้ำซ้อน ไม่มีการสำรอง

**ไม่สามารถแชร์ระหว่าง instances** เมื่อคุณเพิ่มเซิร์ฟเวอร์ที่สอง (ซึ่งคุณจะทำ ในบทที่ 7) มันจะไม่เห็นไฟล์ที่เก็บไว้บนดิสก์ของเซิร์ฟเวอร์แรก

**ไม่สามารถขยายขนาด** พื้นที่ดิสก์ EC2 มีจำกัด

มีโมเดลที่ดีกว่า AWS สร้างมันขึ้นในปี 2549 และยังคงเป็นหนึ่งใน service คลาวด์ที่ใช้กันมากที่สุดในโลก

**Amazon S3: ฮาร์ดไดรฟ์ที่อยู่ออนไลน์**

**Amazon S3** — Simple Storage Service — คือ service จัดเก็บออบเจ็กต์ของ AWS

คิดว่ามันเหมือนฮาร์ดไดรฟ์ที่อยู่บนอินเทอร์เน็ต ฮาร์ดไดรฟ์ที่ไม่มีที่สิ้นสุด
อันหนึ่งที่สำรองข้อมูลโดยอัตโนมัติข้าม Availability Zones หลายอัน เพื่อให้การสูญเสียศูนย์ข้อมูลใดก็ตามไม่ทำให้คุณสูญเสียไฟล์

แนวคิดหลักใน S3 คือ **object (ออบเจ็กต์)**

object คือไฟล์ใดๆ: รูปภาพ วิดีโอ PDF CSV ไฟล์สำรอง ไฟล์บันทึก S3 ไม่สนใจประเภทหรือโครงสร้าง มันเก็บไบต์และส่งคืนเมื่อคุณขอ

Objects อาศัยอยู่ใน **buckets** Bucket เหมือนโฟลเดอร์ระดับบนสุด — container ที่ตั้งชื่อแล้วใน S3 ที่เก็บ objects ของคุณ แต่ละ bucket มีชื่อที่ไม่ซ้ำกันทั่วโลก (ไม่มีสอง bucket ในบัญชี AWS ทั้งหมดที่ใช้ชื่อเดียวกันได้) และมีอยู่ใน Region เฉพาะ

**วิธีที่ S3 ทำงาน**

โมเดลนั้นเรียบง่าย และความเรียบง่ายนั้นคือประเด็น

คุณ **อัพโหลด** object ไปยัง bucket S3 ให้มัน **key** — โดยพื้นฐานแล้วเป็นชื่อเส้นทางเช่น `menus/restaurant-001/photo-arepa.jpg` key นั้นระบุ object ภายใน bucket ได้อย่างไม่ซ้ำกัน

คุณ **ดาวน์โหลด** (หรือดึง) object โดยใช้ชื่อ bucket และ key

คุณยังสามารถทำให้ objects เข้าถึงได้สาธารณะ — หมายความว่าใครก็ตามที่มี URL สามารถดาวน์โหลดพวกมันได้ นี่คือวิธีที่เว็บไซต์ส่วนใหญ่ให้บริการรูปภาพ: เก็บรูปภาพใน S3 ทำให้เป็นสาธารณะ ฝัง URL ใน HTML ของพวกเขา

หรือคุณเก็บ objects ไว้เป็นส่วนตัว — เข้าถึงได้เฉพาะกับคำขอที่ผ่านการตรวจสอบ นี่คือโมเดลที่ถูกต้องสำหรับข้อมูลลูกค้า การสำรองข้อมูล และอะไรก็ตามที่ละเอียดอ่อน

**ทำไม S3 จึงแตกต่างจากฮาร์ดไดรฟ์ทั่วไป**

สามสิ่งที่ทำให้ S3 แตกต่างโดยพื้นฐานจากการจัดเก็บไฟล์บน EC2 instance:

**ความทนทาน** AWS ออกแบบ S3 สำหรับความทนทาน 99.999999999% (สิบเอ็ดเก้า) หมายความว่าถ้าคุณเก็บสิบล้าน objects คุณอาจคาดหวังว่าจะสูญเสีย object หนึ่งทุกหนึ่งหมื่นปีจากความล้มเหลวของฮาร์ดแวร์

**ความพร้อมใช้งาน** S3 ออกแบบมาให้เข้าถึงได้แม้เมื่อส่วนประกอบแต่ละส่วนล้มเหลว

**ขนาด** S3 เก็บข้อมูลในปริมาณที่ไม่มีที่สิ้นสุดเกือบๆ

**การกำหนดเวอร์ชัน: ปุ่มยกเลิก**

S3 รองรับ **versioning** เมื่อคุณเปิดใช้งาน versioning บน bucket S3 จะเก็บทุกเวอร์ชันของทุก object — รวมถึงเวอร์ชันก่อนหน้าและเวอร์ชันที่ถูกลบ

นี่คือปุ่มยกเลิกสำหรับไฟล์ของคุณ

อัพโหลดรูปถ่ายเมนูใหม่ที่เขียนทับของเก่าโดยไม่ตั้งใจ? เวอร์ชันเก่ายังอยู่ที่นั่น ลบไฟล์โดยผิดพลาด? สามารถกู้คืนได้

"การเก็บเวอร์ชันทั้งหมดนั้นมีค่าใช้จ่ายเท่าไหร่?" Tom ถาม

คุณจ่ายสำหรับที่เก็บของทุกเวอร์ชัน AWS มี **lifecycle policies** ที่ลบเวอร์ชันเก่าโดยอัตโนมัติหลังจากเวลาหนึ่ง — เราจะครอบคลุมในบทที่ 23

**การควบคุมการเข้าถึง: สาธารณะ vs ส่วนตัว**

โดยค่าเริ่มต้น ทุกอย่างใน S3 เป็นส่วนตัว เฉพาะบัญชี AWS ของคุณเท่านั้นที่เข้าถึงได้

คุณสามารถทำให้ objects แต่ละรายการเป็นสาธารณะ — นี่คือวิธีที่คุณจะให้บริการรูปเมนูแก่ผู้เยี่ยมชมเว็บไซต์ หรือคุณเก็บทุกอย่างไว้เป็นส่วนตัวและสร้าง **pre-signed URLs**: ลิงก์ที่จำกัดเวลาที่ให้ใครบางคนดาวน์โหลด object เฉพาะโดยไม่ต้องมีข้อมูลประจำตัว AWS

"อย่าทำให้ bucket เป็นสาธารณะอย่างสมบูรณ์เว้นแต่คุณจะตัดสินใจอย่างมีสติที่จะทำให้ทุก object ใน bucket นั้นเข้าถึงได้สำหรับอินเทอร์เน็ตทั้งหมด" เธอกล่าว "ความผิดพลาดด้านความปลอดภัย S3 ที่พบบ่อยที่สุดคือการเปิดเผย bucket ที่มีข้อมูลที่ละเอียดอ่อนโดยไม่ตั้งใจ"

AWS ตอนนี้มีการตั้งค่า "Block Public Access" ที่คุณสามารถใช้ในระดับบัญชี บังคับให้ buckets ทั้งหมดเป็นส่วนตัวเว้นแต่คุณจะแทนที่อย่างชัดเจนต่อ bucket

## สรุป

- **Amazon S3** คือพื้นที่เก็บข้อมูล object — ที่สำหรับเก็บไฟล์ (เรียกว่า objects) ใน containers ที่ตั้งชื่อ (เรียกว่า buckets)
- S3 ออกแบบมาสำหรับความทนทานสิบเอ็ดเก้าโดยการเก็บสำเนาของทุก object โดยอัตโนมัติข้ามอย่างน้อยสาม Availability Zones
- ไฟล์ที่เก็บบน EC2 instances ผูกกับวงจรชีวิตของ instance นั้น ไฟล์สำคัญควรอยู่ใน S3 ไม่ใช่บนเซิร์ฟเวอร์
- **Versioning** รักษาเวอร์ชันก่อนหน้าของ objects — ปุ่มยกเลิกของคุณ
- โดยค่าเริ่มต้น S3 เป็นส่วนตัว เปิดใช้งาน "Block Public Access" ในระดับบัญชี
- S3 มี **ระดับพื้นที่เก็บข้อมูล** หลายระดับสำหรับรูปแบบการเข้าถึงและค่าใช้จ่ายที่แตกต่างกัน

## เคล็ดลับการสอบ

*SAA-C03 Domain 3 — Task 3.1 (โซลูชันพื้นที่เก็บข้อมูลที่มีประสิทธิภาพสูง)*

- **S3 เป็นพื้นที่เก็บข้อมูล object ไม่ใช่ block storage** เมื่อสถานการณ์การสอบต้องการระบบไฟล์ที่เซิร์ฟเวอร์หลายเครื่องสามารถ mount ได้ นั่นคือ EFS เมื่อต้องการดิสก์สำหรับ EC2 instance เดียว นั่นคือ EBS เมื่อต้องการเก็บไฟล์ การสำรอง รูปภาพ — นั่นคือ S3
- **ความทนทานสิบเอ็ดเก้า** หมายความว่า S3 สำเนาข้อมูลข้าม AZs หลายอันโดยอัตโนมัติ คุณไม่ได้กำหนดค่านี้ — มันเป็นค่าเริ่มต้น
- **S3 เป็น Regional** แต่สามารถเข้าถึงได้ทั่วโลก
- **Pre-signed URLs** อนุญาตให้เข้าถึง objects ส่วนตัวได้จำกัดเวลา
