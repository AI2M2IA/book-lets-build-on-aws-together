**EC2 Instances เก็บข้อมูลอย่างไร**

เมื่อ EC2 instance ทำงาน ระบบปฏิบัติการของมันอยู่ที่ไหนสักแห่งบนดิสก์ ดิสก์นั้นเรียกว่า **root volume** โดยค่าเริ่มต้น นี่คือ **EBS volume** — แม้จะไม่ได้คิดถึงมัน

แต่ยังมีอีกอย่าง: EC2 instances ยังมีพื้นที่เก็บข้อมูล **instance store**

Instance store คือพื้นที่เก็บข้อมูลชั่วคราวที่ติดอยู่กับฮาร์ดแวร์พื้นฐานที่รันเครื่องเสมือนของคุณ มันเร็วมาก — เร็วกว่าตัวเลือกพื้นที่เก็บข้อมูลอื่นๆ ใน AWS เกือบทั้งหมด แต่มันมีข้อเสียหนึ่งอย่าง

Instance store เป็น **ชั่วคราว**

เมื่อ instance หยุดหรือยุติ ข้อมูล instance store จะหายไป ถาวร กู้คืนไม่ได้

Instance store เหมาะสำหรับ caches ไฟล์ประมวลผลชั่วคราว และ scratch space ไม่ใช่สำหรับข้อมูลที่คุณสนใจ

**EBS: ดิสก์ที่ถาวร**

**Amazon EBS** — Elastic Block Store — คือพื้นที่เก็บข้อมูล block ที่ถาวรสำหรับ EC2 instances

Block storage หมายความว่ามันทำงานเหมือนฮาร์ดไดรฟ์จริง: ระบบปฏิบัติการของคุณสามารถสร้างระบบไฟล์บนมันได้ อ่านและเขียน bytes ที่ต้องการในตำแหน่งที่ต้องการ รันฐานข้อมูลบนมันได้

คุณสมบัติหลัก:

**ถาวร** ต่างจาก instance store EBS volumes รอดผ่านการหยุด เริ่มใหม่ และแม้แต่การยุติ instance (ขึ้นอยู่กับการกำหนดค่า) ข้อมูลยังคงอยู่บน volume แม้เมื่อไม่มี instance ใช้งาน

**ถอดและต่อได้** EBS volume สามารถถอดออกจาก instance หนึ่งและต่อเข้ากับอีก instance หนึ่งได้

**ต่อเพียงครั้งเดียว (ส่วนใหญ่)** โดยค่าเริ่มต้น EBS volume ต่อกับ EC2 instance หนึ่งเครื่องในแต่ละครั้ง

การเปรียบเปรย: EBS คือฮาร์ดไดรฟ์ภายนอกที่คุณเสียบเข้ากับแล็ปท็อป แล็ปท็อป (EC2 instance) สามารถอ่านและเขียนลงไปได้ เมื่อเสร็จ คุณสามารถถอดออกและเสียบเข้ากับแล็ปท็อปอีกเครื่อง

**ประเภท EBS Volume**

**gp3 (General Purpose SSD)**: ตัวเลือกเริ่มต้นสำหรับงานส่วนใหญ่ สมดุลที่ดีระหว่างประสิทธิภาพและราคา

**io2 (Provisioned IOPS SSD)**: ตัวเลือกประสิทธิภาพสูงสำหรับงานที่ต้องการ I/O เข้มข้น

**st1 (Throughput Optimized HDD)**: พื้นที่เก็บข้อมูลแม่เหล็กที่ปรับให้เหมาะสำหรับการอ่านและเขียนตามลำดับขนาดใหญ่

**sc1 (Cold HDD)**: ตัวเลือก EBS ที่ถูกที่สุด สำหรับข้อมูลที่เข้าถึงไม่บ่อย

**EBS Snapshot: การสำรองข้อมูล**

**EBS snapshot** คือการสำรองข้อมูล ณ เวลาหนึ่งของ EBS volume ที่เก็บใน S3 Snapshot เป็นแบบ incremental: snapshot แรกบันทึก volume ทั้งหมด; snapshot ต่อๆ มาเก็บเฉพาะสิ่งที่เปลี่ยนแปลงจาก snapshot ล่าสุด

คุณสามารถสร้าง EBS volume ใหม่จาก snapshot — คืนค่าเป็นจุดก่อนที่ฐานข้อมูลจะเสียหาย

Priya ตั้งค่านี้ก่อนที่ฐานข้อมูลจะเข้าสู่การผลิต

Leo ไม่ได้คิดถึงมัน

**EFS: ตู้เก็บเอกสารร่วม**

EBS คือดิสก์ที่ต่อกับ instance เดียว จะเป็นอย่างไรถ้า instances หลายเครื่องต้องเข้าถึงไฟล์เดียวกันพร้อมกัน?

เข้ามา **Amazon EFS** — Elastic File System

EFS คือระบบไฟล์เครือข่ายที่จัดการ EC2 instances หลายเครื่องสามารถ mount ระบบไฟล์ EFS เดียวกันพร้อมกันและอ่าน/เขียนไฟล์ร่วม

EBS คือฮาร์ดไดรฟ์ภายนอกที่เสียบเข้ากับแล็ปท็อปหนึ่งเครื่อง มีเพียงแล็ปท็อปนั้นที่ใช้มันได้ในแต่ละครั้ง

EFS คือตู้เก็บเอกสารที่ตั้งอยู่กลางสำนักงาน สมาชิกทีมทุกคนสามารถเดินไป เปิดลิ้นชัก อ่านไฟล์ วางกลับ คนหลายคนพร้อมกัน เข้าถึงพื้นที่เก็บข้อมูลเดียวกัน

**เมื่อไหร่ที่คุณต้องการ EFS?**

- เมื่อ EC2 instances หลายเครื่องต้องการแชร์ไฟล์
- เมื่อคุณมีแอปพลิเคชันที่ขยายในแนวนอนที่ทุก instances ต้องการเข้าถึงข้อมูลเดียวกัน
- เมื่อคุณต้องการระบบไฟล์ถาวรที่รอดผ่านความล้มเหลวของ instance

**EFS กับ S3:** EFS คือระบบไฟล์ (โฟลเดอร์ ไฟล์ สิทธิ์ การล็อค) S3 คือพื้นที่เก็บข้อมูล object (อัพโหลด ดาวน์โหลด ไม่มีความหมายระบบไฟล์) EFS แพงกว่า S3 มาก

**การเลือกพื้นที่เก็บข้อมูลที่เหมาะสม**

| ความต้องการ                              | ประเภทพื้นที่เก็บข้อมูล |
|-----------------------------------------|-------------------------|
| ฐานข้อมูลต้องการดิสก์เร็วที่ถาวร        | EBS (gp3 or io2)        |
| เซิร์ฟเวอร์หลายเครื่องต้องการไฟล์ร่วม  | EFS                     |
| ไฟล์ สำรองข้อมูล รูปภาพ objects ขนาดใหญ่ | S3                    |
| Scratch space สำหรับการประมวลผลชั่วคราว | Instance Store          |
| เก็บถาวรระยะยาวด้วยต้นทุนต่ำสุด         | S3 Glacier              |

## สรุป

- **Instance store** คือพื้นที่เก็บข้อมูลเร็วชั่วคราวที่ติดอยู่กับโฮสต์ ข้อมูลหายเมื่อ instance หยุด สำหรับ scratch space เท่านั้น
- **EBS** (Elastic Block Store) คือพื้นที่เก็บข้อมูล block ที่ถาวรสำหรับ EC2 instance เดียว รอดผ่านการหยุด instance สามารถ snapshot เพื่อสำรองข้อมูล
- **EFS** (Elastic File System) คือระบบไฟล์เครือข่ายร่วมที่ instances หลายเครื่องสามารถ mount พร้อมกัน
- จับคู่ประเภทพื้นที่เก็บข้อมูลกับความต้องการ: ฐานข้อมูล → EBS; ไฟล์ร่วม → EFS; objects/สำรอง → S3; เก็บถาวร → S3 Glacier

- **EBS volumes อยู่ใน AZ เดียว** สามารถต่อกับ instance ใน AZ เดียวกันเท่านั้น
