# Приложение B: Карта доменов SAA-C03

Экзамен AWS Solutions Architect Associate (SAA-C03) организован в четыре домена. Это приложение сопоставляет каждую главу книги с соответствующим доменом и задачей, чтобы вы могли учиться по экзаменационным областям, а не по порядку глав.

---

## Обзор доменов

| Домен                                              | Вес    | Описание                                                |
|----------------------------------------------------|--------|---------------------------------------------------------|
| Домен 1: Design Secure Architectures               | 30 %   | IAM, сетевая безопасность, защита данных                 |
| Домен 2: Design Resilient Architectures            | 26 %   | Высокая доступность, отказоустойчивость, аварийное восстановление |
| Домен 3: Design High-Performing Architectures      | 24 %   | Производительность вычислений, хранилища, БД, сети       |
| Домен 4: Design Cost-Optimized Architectures       | 20 %   | Модели ценообразования, управление затратами, оптимизация ресурсов |

---

## Домен 1: Design Secure Architectures (30 %)

**Task 1.1 — Проектирование безопасного доступа к ресурсам AWS**

Ключевые концепции: пользователи, группы, роли и политики IAM. Принцип минимальных привилегий. Межаккаунтный доступ. Сервисные роли. SCP (Service Control Policies) в AWS Organizations.

| Глава      | Тема                                                                          |
|------------|-------------------------------------------------------------------------------|
| Глава 3    | Основы IAM: пользователи, группы, роли, политики, оценка политик               |
| Глава 14   | Продвинутый IAM: роли для сервисов, границы разрешений, межаккаунтные роли      |
| Глава 3    | Логика оценки политик: явный deny > явный allow > неявный deny                 |
| Глава 14   | AWS Organizations, SCP, Control Tower, Account Factory                         |
| Глава 14   | Cognito: User Pools (вход в приложение, JWT) и Identity Pools (временные учётные данные AWS) |

Ключевые экзаменационные паттерны:

- «EC2 нужен доступ к S3 без зашитых в код учётных данных» → IAM-роль с политикой S3, прикреплённая к профилю инстанса EC2
- «Разным аккаунтам нужно совместно использовать ресурсы» → IAM-роль с межаккаунтной trust-политикой
- «Запретить всем пользователям IAM в OU доступ к сервису» → SCP в AWS Organizations

---

**Task 1.2 — Проектирование безопасных нагрузок и приложений**

Ключевые концепции: проектирование VPC, группы безопасности vs. NACL, сетевая изоляция, защита от DDoS, WAF, GuardDuty.

| Глава      | Тема                                                                                       |
|------------|--------------------------------------------------------------------------------------------|
| Глава 11   | Проектирование VPC: публичные/приватные подсети, NAT Gateway, Internet Gateway, таблицы маршрутизации |
| Глава 15   | Группы безопасности (с состоянием, уровень инстанса) vs. NACL (без состояния, уровень подсети) |
| Глава 17   | Shield (DDoS), WAF (файрвол приложений), GuardDuty (обнаружение угроз), Inspector (сканирование CVE) |
| Глава 17   | Macie: обнаружение чувствительных данных в S3 (ПД, учётные данные)                          |
| Глава 25   | Direct Connect, VPN, Transit Gateway, PrivateLink                                           |

Ключевые экзаменационные паттерны:

- «Заблокировать конкретный IP от подсети» → правило deny в NACL
- «Разрешить входящий HTTP, автоматически разрешить исходящий ответ HTTP» → группа безопасности (с состоянием)
- «Защитить веб-приложение от SQL-инъекций» → WAF с правилом SQL-инъекций
- «Обнаружить скомпрометированные учётные данные IAM» → GuardDuty

---

**Task 1.3 — Определение подходящих средств контроля безопасности данных**

Ключевые концепции: шифрование в покое и при передаче, KMS, Secrets Manager, Parameter Store, серверное шифрование S3.

| Глава      | Тема                                                                      |
|------------|---------------------------------------------------------------------------|
| Глава 16   | KMS: управляемые клиентом ключи, ротация ключей, конвертное шифрование      |
| Глава 16   | Secrets Manager: автоматическая ротация учётных данных, извлечение секрета во время выполнения |
| Глава 16   | ACM (AWS Certificate Manager): сертификаты SSL/TLS для ALB, CloudFront      |
| Глава 5    | Варианты шифрования S3: SSE-S3, SSE-KMS, SSE-C                             |
| Глава 8    | Шифрование RDS в покое (должно быть включено при создании)                 |

Ключевые экзаменационные паттерны:

- «Автоматически ротировать учётные данные базы данных» → Secrets Manager с интеграцией RDS
- «Контролировать, кто может использовать ключи шифрования между аккаунтами» → политика ключа KMS
- «Хранить несекретные значения конфигурации» → SSM Parameter Store (не Secrets Manager)
- «Шифровать объекты S3 ключами компании» → SSE-KMS с CMK

## Домен 2: Design Resilient Architectures (26 %)

**Task 2.1 — Проектирование масштабируемых и слабосвязанных архитектур**

Ключевые концепции: Auto Scaling, балансировщики нагрузки, развязка через SQS/SNS, триггеры событий Lambda, ECS/EKS, Step Functions.

| Глава      | Тема                                                              |
|------------|-------------------------------------------------------------------|
| Глава 7    | Auto Scaling Groups, Application Load Balancer, политики масштабирования |
| Глава 19   | SQS (развязка через очереди), SNS (уведомления fan-out)           |
| Глава 20   | Lambda: бессерверные вычисления, триггеры событий, параллелизм     |
| Глава 20   | API Gateway: управляемые REST/HTTP/WebSocket API, отдельно или + Lambda |
| Глава 21   | ECS и EKS: контейнеризированные микросервисы                       |
| Глава 22   | Step Functions: оркестрация рабочих процессов                      |
| Глава 26   | Kinesis: потоковая передача данных в реальном времени             |

Ключевые экзаменационные паттерны:

- «Развязать обработку заказов от обновления склада» → очередь SQS между сервисами
- «Уведомить несколько сервисов при размещении нового заказа» → топик SNS с подписками SQS (fan-out)
- «Автоматически обрабатывать загрузки в S3» → уведомление о событии S3 → Lambda
- «Запустить многошаговый рабочий процесс с логикой повторов» → Step Functions

---

**Task 2.2 — Проектирование высокодоступных и/или отказоустойчивых архитектур**

Ключевые концепции: Multi-AZ, Multi-Region, переключение Route 53, реплики чтения RDS, Aurora Global Database, резервное копирование и восстановление.

| Глава      | Тема                                                                                         |
|------------|----------------------------------------------------------------------------------------------|
| Глава 2    | Глобальная инфраструктура AWS: регионы, AZ, граничные локации                                |
| Глава 7    | ALB в нескольких AZ, ASG заменяет неисправные инстансы                                       |
| Глава 8    | RDS Multi-AZ: синхронная репликация, автоматическое переключение при сбое                     |
| Глава 12   | Route 53: маршрутизация failover, маршрутизация по задержке, проверки работоспособности      |
| Глава 18   | Multi-AZ vs. Multi-Region: RTO/RPO, стратегии DR (pilot light, warm standby, active-active)  |
| Глава 18   | AWS Backup (централизованное, межаккаунтное резервное копирование), Elastic Disaster Recovery (управляемый pilot light) |
| Глава 24   | Aurora Global Database: межрегиональные реплики чтения, задержка репликации < 1 с            |

Ключевые экзаменационные паттерны:

- «Автоматическое переключение при сбое первичного RDS» → RDS Multi-AZ (не Read Replica)
- «Обслуживать чтение глобально с низкой задержкой» → Aurora Global Database
- «Направить трафик во вторичный регион, если первичный недоступен» → Route 53 с маршрутизацией Failover + проверки работоспособности
- «RTO 1 минута, RPO 0» → развёртывание Multi-AZ (не Multi-Region)
- «RTO 15 минут, межрегионально» → стратегия Pilot Light

## Домен 3: Design High-Performing Architectures (24 %)

**Task 3.1 — Определение высокопроизводительных и/или масштабируемых решений для хранения**

Ключевые концепции: S3 vs. EBS vs. EFS, выбор класса хранения, S3 Transfer Acceleration, многокомпонентная загрузка, CloudFront для ресурсов.

| Глава      | Тема                                                                     |
|------------|-------------------------------------------------------------------------|
| Глава 5    | S3: объектное хранилище, классы хранения, версионирование, жизненный цикл |
| Глава 6    | EBS: типы блочного хранилища (gp3, io2, st1), EFS: общее файловое хранилище |
| Глава 6    | Storage Gateway: гибридный мост от локальных площадок к S3 (File, Volume, Tape) |
| Глава 23   | Переходы между классами хранения S3, варианты извлечения из Glacier      |
| Глава 25   | DataSync (онлайн-синхронизация файлов), Transfer Family (управляемый SFTP→S3), Snow Family (офлайн массовая передача — legacy: закрыто для новых клиентов в ноябре 2025; AWS теперь рекомендует DataSync и Data Transfer Terminals), MGN (rehost серверов) |
| Глава 28   | Right-sizing EBS, миграция gp2→gp3, управление снимками                  |

Ключевые экзаменационные паттерны:

- «Общая файловая система, доступная с нескольких инстансов EC2» → EFS (не EBS; EBS подключается к одному инстансу)
- «Высокие IOPS для нагрузки базы данных» → io2 EBS
- «Снизить стоимость файлов, не использовавшихся 90 дней» → политика жизненного цикла S3 → Glacier
- «Быстрее загружать большие файлы из удалённых мест» → S3 Transfer Acceleration
- «Недели передачи по ограниченной пропускной способности» → экзамен SAA-C03 всё ещё ожидает Snowball, несмотря на закрытие Snow Family для новых клиентов в 2025 году

**Task 3.2 — Определение высокопроизводительных и/или масштабируемых вычислительных решений**

Ключевые концепции: семейства инстансов EC2, процессоры Graviton, Auto Scaling, Lambda, Fargate, Spot Instances.

| Глава      | Тема                                                                                     |
|------------|-----------------------------------------------------------------------------------------|
| Глава 4    | Типы инстансов EC2: оптимизированные по вычислениям (c), по памяти (r), универсальные (m, t) |
| Глава 7    | Auto Scaling: горизонтальное масштабирование для веб-уровней                             |
| Глава 20   | Lambda: параллелизм, предоставленный параллелизм (для стабильной задержки)               |
| Глава 21   | ECS Fargate: бессерверные контейнеры                                                     |
| Глава 21   | AWS Batch: управляемые пакетные вычисления для контейнеров Docker, на базе Spot          |
| Глава 27   | Spot Instances для отказоустойчивых пакетных нагрузок                                    |

Ключевые экзаменационные паттерны:

- «Нагрузка обучения ML, минимизировать стоимость, можно прерывать» → Spot Instances
- «Стабильный отклик Lambda менее 100 мс» → предоставленный параллелизм (устраняет холодный старт)
- «Контейнеризированный микросервис, без управления инфраструктурой» → ECS Fargate

**Task 3.3 — Определение высокопроизводительных решений баз данных**

Ключевые концепции: RDS vs. DynamoDB vs. Aurora vs. Redshift vs. ElastiCache, паттерны доступа, реплики чтения, DAX.

| Глава      | Тема                                                              |
|------------|-------------------------------------------------------------------|
| Глава 8    | RDS: управляемые реляционные базы данных, когда использовать РСУБД  |
| Глава 9    | DynamoDB: NoSQL, ключи раздела, GSI, DAX (кэш в памяти)            |
| Глава 10   | ElastiCache: Redis vs. Memcached, стратегии кэширования            |
| Глава 10   | MemoryDB for Redis: долговечная Redis-совместимая первичная база данных |
| Глава 24   | Aurora: производительность, Serverless v2, реплики чтения, Global Database |
| Глава 29   | DynamoDB on-demand vs. provisioned ёмкость с Auto Scaling          |

Ключевые экзаменационные паттерны:

- «Микросекундное чтение для хранилища сессий» → ElastiCache Redis или DAX (если бэкенд DynamoDB)
- «Высокая пропускная способность доступа ключ-значение с гибкой схемой» → DynamoDB
- «Сложные соединения и ACID-транзакции» → Aurora или RDS
- «Аналитика по петабайтам структурированных данных» → Redshift (подробно не рассматривается, но признак: «хранилище данных» → Redshift)

**Task 3.4 — Определение высокопроизводительных и/или масштабируемых сетевых архитектур**

Ключевые концепции: CloudFront, Global Accelerator, Direct Connect, VPN, группы размещения, расширенные сети.

| Глава      | Тема                                                              |
|------------|-------------------------------------------------------------------|
| Глава 7    | NLB (уровень 4) и GWLB (Gateway Load Balancer для сетевых устройств) |
| Глава 11   | Client VPN: зашифрованный доступ отдельного устройства к VPC       |
| Глава 12   | Route 53: политики маршрутизации: по задержке, geolocation, взвешенная |
| Глава 13   | CloudFront: CDN, граничное кэширование, Lambda@Edge               |
| Глава 25   | AWS Global Accelerator: Anycast-маршрутизация в магистраль AWS     |
| Глава 25   | Direct Connect: выделенное приватное соединение                    |
| Глава 30   | VPC Endpoints: приватное соединение с сервисами AWS                |

Ключевые экзаменационные паттерны:

- «Снизить задержку для глобальных пользователей, обращающихся к динамическим ответам API» → Global Accelerator (не CloudFront, который лучше для кэшируемого контента)
- «Снизить задержку для статических ресурсов глобально» → CloudFront
- «Стабильное приватное соединение с AWS с локальных площадок» → Direct Connect
- «Быстрая загрузка от клиентов по всему миру в ваш бакет S3» → S3 Transfer Acceleration

Ключевые концепции: Kinesis Data Streams, Amazon Data Firehose, Glue, Athena, EMR.

| Глава      | Тема                                                                |
|------------|---------------------------------------------------------------------|

| Глава 26   | Amazon Data Firehose (бывш. Kinesis Data Firehose): управляемая доставка в S3, Redshift, OpenSearch |

| Глава 26   | Athena: бессерверный SQL по S3                                      |

| Глава 26   | Lake Formation: точечный контроль доступа к озеру данных            |

Ключевые экзаменационные паттерны:

**Task 4.4 — Проектирование экономичных сетевых архитектур**

| Глава      | Тема                                                                                          |
|------------|-----------------------------------------------------------------------------------------------|
| Глава 30   | Ценообразование передачи данных: входящий (бесплатно), между AZ ($0,01/ГБ), между регионами, интернет ($0,09/ГБ) |
| Глава 30   | NAT Gateway ($0,045/ГБ) vs. VPC Endpoints (Gateway: бесплатно; Interface: тарифицируется)      |
| Глава 30   | CloudFront как оптимизатор затрат на передачу данных                                           |

Ключевые экзаменационные паттерны:

- «EC2 в приватной подсети обращается к S3 — устранить затраты на NAT Gateway» → S3 Gateway Endpoint (бесплатно)
- «EC2 в приватной подсети обращается к SQS — снизить затраты на NAT Gateway» → SQS Interface Endpoint
- «Снизить затраты на передачу данных для глобальной доставки контента» → CloudFront (кэширование снижает запросы к источнику)

## Предэкзаменационный чек-лист

Перед сдачей SAA-C03:

**Области с высоким весом (наиболее вероятны)**

- [ ] Логика оценки политик IAM (явный deny → явный allow → неявный deny)
- [ ] Компоненты VPC: подсети, таблицы маршрутизации, IGW, NAT Gateway, группы безопасности, NACL
- [ ] Классы хранения S3 и когда использовать каждый
- [ ] RDS Multi-AZ vs. Read Replica (переключение при сбое vs. масштабирование чтения)
- [ ] SQS vs. SNS vs. EventBridge (pull vs. push vs. маршрутизация событий)
- [ ] Модели ценообразования EC2: Spot для отказоустойчивых, Savings Plans для нагрузок с обязательствами

**Распространённые ловушки**

- [ ] EBS подключается к ОДНОМУ инстансу; EFS общий
- [ ] RDS Read Replicas для масштабирования чтения, НЕ для автоматического переключения при сбое (это Multi-AZ)
- [ ] NACL без состояния (нужны как входящие, так и исходящие правила)
- [ ] Gateway Endpoints бесплатны и только для S3 и DynamoDB
- [ ] Kinesis хранит и воспроизводит; SQS удаляет при потреблении
- [ ] «Развязать» не всегда означает SQS — fan-out через SNS и EventBridge тоже паттерны развязки
- [ ] Shield Standard бесплатен и автоматичен; Advanced — платная подписка
- [ ] ElastiCache vs. MemoryDB: ElastiCache = кэш (потеря данных допустима). MemoryDB = долговечная первичная база данных.
- [ ] Client VPN vs. Site-to-Site VPN: Client VPN = отдельные устройства. Site-to-Site = сеть-к-сети.
- [ ] Outposts vs. Wavelength: Outposts = локальная стойка AWS. Wavelength = граница 5G.
- [ ] DMS: гомогенная = DMS напрямую. Гетерогенная = сначала SCT, затем DMS.
- [ ] DataSync перемещает *файлы*; DMS перемещает *базы данных*; MGN перемещает *целые серверы*.
