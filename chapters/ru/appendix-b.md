# Приложение B: Карта областей SAA-C03

Экзамен AWS Solutions Architect Associate (SAA-C03) организован по четырём областям. Это приложение сопоставляет каждую главу книги с соответствующей областью и задачей, чтобы вы могли изучать материал по области экзамена, а не по порядку глав.

---

## Обзор областей

| Область                                                 | Вес | Описание                                                   |
|---------------------------------------------------------|-----|------------------------------------------------------------|
| Область 1: Проектирование защищённых архитектур         | 30% | IAM, сетевая безопасность, защита данных                   |
| Область 2: Проектирование отказоустойчивых архитектур   | 26% | Высокая доступность, отказоустойчивость, аварийное восстановление |
| Область 3: Проектирование высокопроизводительных архитектур | 24% | Вычисления, хранилище, база данных, производительность сети |
| Область 4: Проектирование архитектур с оптимизацией затрат | 20% | Модели ценообразования, управление затратами, оптимизация ресурсов |

## Область 1: Проектирование защищённых архитектур (30%)

**Задача 1.1 — Проектирование защищённого доступа к ресурсам AWS**

Основные концепции: IAM пользователи, группы, роли, политики. Принцип минимальных привилегий. Кросс-аккаунтный доступ. Сервисные роли. SCP (Service Control Policies) в AWS Organizations.

| Глава    | Тема                                                                                |
|----------|-------------------------------------------------------------------------------------|
| Глава 3  | Основы IAM: пользователи, группы, роли, политики, логика оценки политик            |
| Глава 14 | Продвинутый IAM: роли для сервисов, границы разрешений, кросс-аккаунтные роли      |
| Глава 3  | Логика оценки политик: явный запрет > явное разрешение > неявный запрет            |
| Глава 14 | AWS Organizations и SCP                                                             |

Ключевые паттерны экзамена:

- «EC2 нужно обращаться к S3 без хардкоженных учётных данных» → IAM-роль с политикой S3, прикреплённой к профилю инстанса EC2
- «Разным аккаунтам нужно делиться ресурсами» → IAM-роль с политикой доверия между аккаунтами
- «Запретить всем IAM-пользователям в OU доступ к сервису» → SCP в AWS Organizations

---

**Задача 1.2 — Проектирование защищённых нагрузок и приложений**

Основные концепции: дизайн VPC, группы безопасности против NACL, сетевая изоляция, защита от DDoS, WAF, GuardDuty.

| Глава    | Тема                                                                                                     |
|----------|----------------------------------------------------------------------------------------------------------|
| Глава 11 | Дизайн VPC: публичные/частные подсети, NAT Gateway, Internet Gateway, таблицы маршрутизации             |
| Глава 15 | Группы безопасности (stateful, уровень инстанса) против NACL (stateless, уровень подсети)               |
| Глава 17 | Shield (защита от DDoS), WAF (брандмауэр приложений), GuardDuty (обнаружение угроз)                     |
| Глава 25 | Direct Connect, VPN, Transit Gateway, PrivateLink                                                        |

Ключевые паттерны экзамена:

- «Заблокировать конкретный IP от подсети» → правило запрета NACL
- «Разрешить HTTP входящий, автоматически разрешить HTTP ответ исходящий» → группа безопасности (stateful)
- «Защитить веб-приложение от SQL-инъекций» → WAF с правилом SQL-инъекции
- «Обнаружить скомпрометированные IAM-учётные данные» → GuardDuty

---

**Задача 1.3 — Определение подходящих средств управления безопасностью данных**

Основные концепции: шифрование в покое и в транзите, KMS, Secrets Manager, Parameter Store, серверное шифрование S3.

| Глава    | Тема                                                                                |
|----------|-------------------------------------------------------------------------------------|
| Глава 16 | KMS: управляемые клиентом ключи, ротация ключей, конвертное шифрование              |
| Глава 16 | Secrets Manager: автоматическая ротация учётных данных, получение секретов во время выполнения |
| Глава 5  | Параметры шифрования S3: SSE-S3, SSE-KMS, SSE-C                                    |
| Глава 8  | Шифрование RDS в покое (должно быть включено при создании)                          |

Ключевые паттерны экзамена:

- «Ротировать учётные данные базы данных автоматически» → Secrets Manager с интеграцией RDS
- «Управлять тем, кто может использовать ключи шифрования между аккаунтами» → политика ключа KMS
- «Хранить несекретные конфигурационные значения» → SSM Parameter Store (не Secrets Manager)
- «Шифровать объекты S3 ключами, управляемыми компанией» → SSE-KMS с CMK

## Область 2: Проектирование отказоустойчивых архитектур (26%)

**Задача 2.1 — Проектирование масштабируемых и слабосвязанных архитектур**

Основные концепции: Auto Scaling, балансировщики нагрузки, развязка SQS/SNS, событийные триггеры Lambda, ECS/EKS, Step Functions.

| Глава    | Тема                                                                         |
|----------|------------------------------------------------------------------------------|
| Глава 7  | Auto Scaling Groups, Application Load Balancer, политики масштабирования     |
| Глава 19 | SQS (развязка с очередями), SNS (веерные уведомления)                        |
| Глава 20 | Lambda: бессерверные вычисления, событийные триггеры, параллелизм            |
| Глава 21 | ECS и EKS: контейнеризированные микросервисы                                 |
| Глава 22 | Step Functions: оркестрация рабочих процессов                                |
| Глава 26 | Kinesis: потоковая передача данных в реальном времени                        |

Ключевые паттерны экзамена:

- «Развязать обработку заказов от обновления инвентаря» → очередь SQS между сервисами
- «Уведомить несколько сервисов при новом заказе» → топик SNS с подписками SQS (веерная рассылка)
- «Автоматически обрабатывать загрузки S3» → уведомление о событии S3 → Lambda
- «Запустить многошаговый рабочий процесс с логикой повторов» → Step Functions

---

**Задача 2.2 — Проектирование высокодоступных и/или отказоустойчивых архитектур**

Основные концепции: Multi-AZ, Multi-Region, переключение Route 53, реплики для чтения RDS, Aurora Global Database, резервное копирование и восстановление.

| Глава    | Тема                                                                                                           |
|----------|----------------------------------------------------------------------------------------------------------------|
| Глава 2  | Глобальная инфраструктура AWS: регионы, AZ, граничные серверы                                                  |
| Глава 7  | ALB в нескольких AZ, ASG заменяет нездоровые инстансы                                                          |
| Глава 8  | RDS Multi-AZ: синхронная репликация, автоматическое переключение                                               |
| Глава 12 | Route 53: failover-маршрутизация, маршрутизация на основе задержки, проверки работоспособности                 |
| Глава 18 | Multi-AZ против Multi-Region: RTO/RPO, стратегии аварийного восстановления (Pilot Light, Warm Standby, Active-Active) |
| Глава 24 | Aurora Global Database: кросс-региональные реплики для чтения, задержка репликации < 1 с                      |

Ключевые паттерны экзамена:

- «Автоматически переключаться при сбое основного RDS» → RDS Multi-AZ (не реплика для чтения)
- «Обслуживать чтения глобально с малой задержкой» → Aurora Global Database
- «Маршрутизировать трафик во вторичный регион при недоступности основного» → Route 53 с Failover маршрутизацией + проверками работоспособности
- «RTO 1 минута, RPO 0» → развёртывание Multi-AZ (не Multi-Region)
- «RTO 15 минут, кросс-региональный» → стратегия Pilot Light

## Область 3: Проектирование высокопроизводительных архитектур (24%)

**Задача 3.1 — Определение высокопроизводительных и/или масштабируемых решений хранилища**

Основные концепции: S3 против EBS против EFS, выбор класса хранилища, S3 Transfer Acceleration, многочастная загрузка, CloudFront для ресурсов.

| Глава    | Тема                                                                                   |
|----------|----------------------------------------------------------------------------------------|
| Глава 5  | S3: объектное хранилище, классы хранилища, версионирование, жизненный цикл             |
| Глава 6  | EBS: типы блочного хранилища (gp3, io2, st1), EFS: общее файловое хранилище            |
| Глава 23 | Переходы классов хранилища S3, параметры извлечения Glacier                            |
| Глава 28 | Подбор размера EBS, миграция gp2→gp3, управление снимками                              |

Ключевые паттерны экзамена:

- «Общая файловая система, доступная с нескольких EC2-инстансов» → EFS (не EBS; EBS подключается к одному инстансу)
- «Высокий IOPS для нагрузки базы данных» → io2 EBS
- «Снизить затраты для файлов, к которым не обращались 90 дней» → политика жизненного цикла S3 → Glacier
- «Загружать большие файлы из удалённых мест быстрее» → S3 Transfer Acceleration

---

**Задача 3.2 — Определение высокопроизводительных и/или масштабируемых вычислительных решений**

Основные концепции: семейства инстансов EC2, процессоры Graviton, Auto Scaling, Lambda, Fargate, Spot Instances.

| Глава    | Тема                                                                                            |
|----------|-------------------------------------------------------------------------------------------------|
| Глава 4  | Типы инстансов EC2: оптимизированные для вычислений (c), для памяти (r), общего назначения (m, t) |
| Глава 7  | Auto Scaling: горизонтальное масштабирование для веб-уровней                                    |
| Глава 20 | Lambda: параллелизм, provisioned concurrency (для стабильной задержки)                          |
| Глава 21 | ECS Fargate: бессерверные контейнеры                                                            |
| Глава 27 | Spot Instances для отказоустойчивых пакетных нагрузок                                          |

Ключевые паттерны экзамена:

- «Нагрузка обучения ML, минимизировать затраты, может прерываться» → Spot Instances
- «Стабильный ответ Lambda менее 100 мс» → Provisioned concurrency (устраняет холодный старт)
- «Контейнеризированный микросервис, без управления инфраструктурой» → ECS Fargate

---

**Задача 3.3 — Определение высокопроизводительных решений баз данных**

Основные концепции: RDS против DynamoDB против Aurora против Redshift против ElastiCache, паттерны доступа, реплики для чтения, DAX.

| Глава    | Тема                                                                                  |
|----------|---------------------------------------------------------------------------------------|
| Глава 8  | RDS: управляемые реляционные базы данных, когда использовать RDBMS                    |
| Глава 9  | DynamoDB: NoSQL, partition keys, GSI, DAX (кэш в памяти)                              |
| Глава 10 | ElastiCache: Redis против Memcached, стратегии кэширования                            |
| Глава 24 | Aurora: производительность, Serverless v2, реплики для чтения, Global Database        |
| Глава 29 | DynamoDB on-demand против provisioned с Auto Scaling                                  |

Ключевые паттерны экзамена:

- «Микросекундное чтение для хранилища сессий» → ElastiCache Redis или DAX (если бэкенд DynamoDB)
- «Высокопроизводительный доступ по ключу с гибкой схемой» → DynamoDB
- «Сложные объединения и ACID-транзакции» → Aurora или RDS
- «Аналитика на петабайтах структурированных данных» → Redshift (не рассмотрен подробно, но признак: «хранилище данных» → Redshift)

**Задача 3.4 — Определение высокопроизводительных и/или масштабируемых сетевых архитектур**

Основные концепции: CloudFront, Global Accelerator, Direct Connect, VPN, группы размещения, расширенные сетевые возможности.

| Глава    | Тема                                                                              |
|----------|-----------------------------------------------------------------------------------|
| Глава 12 | Route 53: политики маршрутизации: на основе задержки, геолокации, взвешенная     |
| Глава 13 | CloudFront: CDN, граничное кэширование, Lambda@Edge                               |
| Глава 25 | Direct Connect: выделенное частное подключение                                    |
| Глава 25 | AWS Global Accelerator: Anycast-маршрутизация к ближайшему граничному серверу AWS|
| Глава 30 | VPC Endpoints: частное подключение к сервисам AWS                                 |

Ключевые паттерны экзамена:

- «Снизить задержку для глобальных пользователей, обращающихся к динамическим ответам API» → Global Accelerator (не CloudFront, который лучше для кэшируемого контента)
- «Снизить задержку для статических ресурсов глобально» → CloudFront
- «Стабильное частное подключение к AWS из локальной сети» → Direct Connect
- «Быстрая загрузка от клиентов по всему миру в ваш S3-бакет» → S3 Transfer Acceleration

**Задача 3.5 — Определение высокопроизводительных решений приёма и преобразования данных**

Основные концепции: Kinesis Data Streams, Kinesis Firehose, Glue, Athena, EMR.

| Глава    | Тема                                                                                      |
|----------|-------------------------------------------------------------------------------------------|
| Глава 26 | Kinesis Data Streams: упорядоченная обработка событий в реальном времени                  |
| Глава 26 | Kinesis Data Firehose: управляемая доставка в S3, Redshift, OpenSearch                    |
| Глава 26 | AWS Glue: бессерверный ETL, Data Catalog, Crawlers                                        |
| Глава 26 | Athena: бессерверный SQL к S3                                                             |

Ключевые паттерны экзамена:

- «Обрабатывать данные потока кликов в реальном времени» → Kinesis Data Streams + Lambda или KDA
- «Доставить потоковые данные в S3 для последующего анализа» → Kinesis Firehose
- «Преобразовать и каталогизировать данные из нескольких источников» → AWS Glue
- «Запрашивать исторические данные в S3 с SQL» → Athena

## Контрольный список перед экзаменом

Перед сдачей SAA-C03:

**Области с высоким весом (наиболее вероятны)**

- [ ] Логика оценки политик IAM (явный запрет → явное разрешение → неявный запрет)
- [ ] Компоненты VPC: подсети, таблицы маршрутизации, IGW, NAT Gateway, группы безопасности, NACL
- [ ] Классы хранилищ S3 и когда использовать каждый
- [ ] RDS Multi-AZ против реплики для чтения (переключение при сбое против масштабирования чтения)
- [ ] SQS против SNS против EventBridge (pull против push против маршрутизации событий)
- [ ] Модели ценообразования EC2: Spot для отказоустойчивых, Savings Plans для фиксированных нагрузок
- [ ] Триггеры Lambda и параллелизм
- [ ] DynamoDB против Aurora против Redshift (паттерн доступа определяет выбор)
- [ ] CloudFront: CDN для статического, Global Accelerator для динамического

**Распространённые ловушки**

- [ ] EBS подключается к ОДНОМУ инстансу; EFS — общий
- [ ] Реплики для чтения RDS предназначены для масштабирования чтения, а НЕ для автоматического переключения при сбое (это Multi-AZ)
- [ ] NACL без состояния (нужны правила и для входящего, и для исходящего)
- [ ] Gateway Endpoints бесплатны и только для S3 и DynamoDB
- [ ] Kinesis хранит и воспроизводит; SQS удаляет при потреблении
- [ ] «Развязать» не всегда означает SQS — веерная рассылка SNS и EventBridge тоже являются паттернами развязки
- [ ] Shield Standard бесплатен и автоматический; Advanced — платная подписка

**Структура экзамена**

- 65 вопросов, 130 минут (2 часа 10 минут)
- С одним правильным ответом (multiple choice) и с несколькими правильными ответами (multiple response — выбрать N правильных)
- Проходной балл: 720 из 1000
- Вопросы без оценки встроены; вы не можете определить, какие из них
- Управляйте временем: ~2 минуты на вопрос; помечайте трудные и возвращайтесь
