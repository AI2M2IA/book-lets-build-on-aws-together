# Приложение A: Краткий справочник по сервисам AWS

Каждый сервис, рассмотренный в этой книге, в порядке введения. Используйте это как учебный справочник и быстрый поиск при подготовке к экзамену.

---

## Вычисления

**EC2 — Elastic Compute Cloud** *(Глава 4)*

Виртуальные машины в облаке. Вы выбираете тип инстанса (CPU, память, хранилище), операционную систему и регион. Платите за час (On-Demand), за обязательство (Reserved Instances / Savings Plans) или за слот свободных мощностей (Spot). Базовый примитив вычислений.

Ключевые концепции: AMI (Amazon Machine Image), типы инстансов (семейства t3, m6g, r6g, c6g), пары ключей, профили инстансов, группы размещения.

Признак в экзамене: когда сценарий требует постоянных, с состоянием или длительных вычислений — EC2 или ECS. Когда требуются краткосрочные, событийно-запускаемые вычисления с нулевой стоимостью простоя — Lambda.

---

**Auto Scaling + Application Load Balancer** *(Глава 7)*

Auto Scaling Groups (ASG) добавляют и удаляют EC2-инстансы в зависимости от нагрузки. Application Load Balancers (ALB) распределяют трафик между инстансами и маршрутизируют по пути или хосту. Вместе они образуют уровень горизонтального масштабирования.

Ключевые концепции: шаблон запуска (launch template), политики масштабирования (целевое отслеживание, пошаговое, запланированное), проверки работоспособности, целевые группы ALB, правила слушателя, взвешенная маршрутизация.

Признак в экзамене: «Обрабатывать переменную нагрузку» или «высокая доступность в нескольких AZ» → ASG + ALB.

---

**Lambda** *(Глава 20)*

Бессерверные функции. Вы пишете код; AWS запускает его в ответ на события. Нет серверов для управления. Платите за вызов и за миллисекунду выполнения. Автоматически масштабируется до тысяч одновременных выполнений.

Ключевые концепции: источники событий (API Gateway, S3, SQS, EventBridge, Kinesis), роль выполнения, лимиты параллелизма, reserved и provisioned concurrency, холодный старт, Layers, максимальная продолжительность 15 минут.

Признак в экзамене: «Бессерверный», «событийно-управляемый», «краткосрочные задачи», «нулевая стоимость простоя» → Lambda.

---

**ECS — Elastic Container Service** *(Глава 21)*

Запускает Docker-контейнеры на AWS. Два типа запуска: EC2 (вы управляете хостом) и Fargate (AWS управляет хостом). ECS управляет определениями задач, сервисами, планировщиком кластера и интеграцией с балансировщиками нагрузки и сервисным обнаружением.

Ключевые концепции: определение задачи (task definition), сервис ECS, Fargate против типа запуска EC2, ECR (реестр контейнеров), IAM-роль задачи, авто-масштабирование сервиса.

Признак в экзамене: «Контейнеризированные нагрузки», «микросервисы», «Docker на AWS» → ECS (обычно Fargate для бессерверных контейнеров).

---

**EKS — Elastic Kubernetes Service** *(Глава 21)*

Управляемый Kubernetes. AWS управляет плоскостью управления; вы управляете рабочими узлами (EC2 или Fargate). Используйте EKS, когда ваша команда уже использует Kubernetes или имеет нагрузки, требующие специфических функций Kubernetes.

Признак в экзамене: «Kubernetes», «необходимо мигрировать существующие K8s-нагрузки» → EKS. «Просто нужны контейнеры без накладных расходов K8s» → ECS.

---

## Хранилище

**S3 — Simple Storage Service** *(Глава 5)*

Объектное хранилище. Неограниченная ёмкость, долговечность 99,999999999% (одиннадцать девяток). Хранит файлы как объекты в бакетах. Бакеты привязаны к региону. Объекты могут быть от 0 байт до 5 ТБ.

Ключевые концепции: политика бакета, ACL объекта, версионирование, статический веб-хостинг, presigned URL, многочастная загрузка, Transfer Acceleration, классы хранилища (Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive).

Признак в экзамене: «Хранить и извлекать файлы», «статические ресурсы», «резервные копии», «Data Lake» → S3. Правильный класс хранилища зависит от частоты доступа и скорости извлечения.

---

**EBS — Elastic Block Store** *(Глава 6)*

Блочное хранилище, подключённое к одному EC2-инстансу. Действует как жёсткий диск. Сохраняется независимо от жизненного цикла инстанса (можно отсоединить и снова подключить). Наиболее распространённые типы: gp3 (обычный SSD, стандарт по умолчанию), io2 (выделенные IOPS для баз данных), st1 (HDD с оптимизированной пропускной способностью для последовательного чтения).

Ключевые концепции: снимки (инкрементальные, хранятся в S3), шифрование (KMS), Multi-Attach (только io1/io2), выделение IOPS и пропускной способности.

Признак в экзамене: «Постоянное хранилище для EC2», «хранилище базы данных», «требуется блочный доступ с малой задержкой» → EBS.

---

**EFS — Elastic File System** *(Глава 6)*

Общая файловая система, доступная для нескольких EC2-инстансов одновременно. Протокол NFS. Масштабируется автоматически. Дороже EBS за ГБ. Два класса хранилища: Standard и Infrequent Access. Intelligent-Tiering перемещает файлы автоматически.

Признак в экзамене: «Общая файловая система», «нескольким EC2-инстансам нужны одинаковые файлы», «NFS» → EFS.

---

**Классы хранилищ S3 и политики жизненного цикла** *(Глава 23)*

S3 Intelligent-Tiering автоматически перемещает объекты между уровнями доступа в зависимости от частоты доступа. Политики жизненного цикла переводят объекты между классами (Standard → Standard-IA → Glacier) на основе правил возраста. Классы хранилища Glacier имеют задержку извлечения от минут (Glacier Instant) до 12 часов (Glacier Deep Archive).

Признак в экзамене: «Снизить затраты на хранилище для редко запрашиваемых данных» → политики жизненного цикла, Intelligent-Tiering или Glacier.

---

## Базы данных

**RDS — Relational Database Service** *(Глава 8)*

Управляемые реляционные базы данных. Поддерживаемые движки: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server и Aurora (собственный движок AWS). AWS управляет резервными копиями, обновлением патчей, переключением при сбое и репликацией. Вы управляете дизайном схемы, запросами и подбором размера инстанса.

Ключевые концепции: развёртывание Multi-AZ (автоматическое переключение, синхронная репликация), реплики для чтения (асинхронные, для масштабирования чтения), автоматические резервные копии (хранение 1–35 дней), ручные снимки (хранятся до удаления), RDS Proxy (пулинг соединений).

Признак в экзамене: «Реляционная база данных», «ACID-транзакции», «существующая SQL-нагрузка» → RDS или Aurora.

---

**Aurora** *(Глава 24)*

Собственный движок реляционных баз данных AWS, совместимый с MySQL и PostgreSQL. Распределённый движок хранилища, реплицирующий данные в трёх AZ в шести копиях. Обычно в 5 раз быстрее, чем MySQL. Aurora Serverless v2 автоматически масштабирует мощность (измеряется в ACU — Aurora Capacity Units).

Ключевые концепции: кластер Aurora (writer + до 15 конечных точек reader), Aurora Global Database (кросс-региональные реплики для чтения с задержкой репликации < 1 секунды), Aurora Serverless v2.

Признак в экзамене: «Высокопроизводительная реляционная база данных», «совместима с MySQL/PostgreSQL», «глобальные чтения», «переменная нагрузка» → Aurora.

---

**DynamoDB** *(Глава 9)*

Полностью управляемая NoSQL-база данных. Модель «ключ-значение» и документов. Масштабируется до любой пропускной способности с однозначными миллисекундами производительности. Два режима мощности: on-demand (платите за запрос) и provisioned (платите за единицу мощности в час с Auto Scaling).

Ключевые концепции: partition key (обязательный), sort key (опциональный), Global Secondary Index (GSI), Local Secondary Index (LSI), DynamoDB Streams (захват изменений данных), DynamoDB Accelerator (DAX) — кэш в памяти, TTL (Time to Live), транзакции.

Признак в экзамене: «Высокопроизводительный доступ по ключу», «гибкая схема», «бессерверная NoSQL» → DynamoDB.

---

**ElastiCache** *(Глава 10)*

Управляемое кэширование в памяти. Два движка: Redis (постоянный, pub/sub, Lua-скрипты, структуры данных) и Memcached (чистый кэш, проще, многопоточный). Используйте для снижения нагрузки на базу данных и обслуживания часто читаемых данных за микросекунды.

Ключевые концепции: паттерн cache-aside, паттерн write-through, политики вытеснения, TTL, кластерный режим (Redis), Multi-AZ с автоматическим переключением при сбое.

Признак в экзамене: «Снизить нагрузку на базу данных», «задержка чтения менее миллисекунды», «управление сессиями», «таблица лидеров в реальном времени» → ElastiCache Redis.

## Сеть

**VPC — Virtual Private Cloud** *(Глава 11)*

Изолированная сеть внутри AWS. Охватывает все AZ в регионе. Вы определяете пространство IP-адресов (блок CIDR), создаёте подсети (публичные или частные), настраиваете таблицы маршрутизации и управляете доступом через группы безопасности и NACL.

Ключевые концепции: публичная подсеть (маршрут к Internet Gateway), частная подсеть (маршрут к NAT Gateway для исходящего), Internet Gateway (входящий + исходящий в интернет), NAT Gateway (только исходящий для частных инстансов), пиринг VPC (соединение двух VPC), VPC Endpoints (подключение к сервисам AWS без интернета).

Признак в экзамене: «Частная сеть в AWS», «изолировать ресурсы от интернета», «управлять сетевым трафиком» → VPC.

---

**Группы безопасности и NACL** *(Глава 15)*

Группы безопасности — это контекстно-зависимые (stateful) брандмауэры на уровне инстанса — только разрешающие правила, обратный трафик автоматический. NACL (Network Access Control Lists) — это контекстно-независимые (stateless) брандмауэры на уровне подсети — требуют правил и для входящего, и для исходящего трафика, вычисляются в порядке номеров правил.

Признак в экзамене: «Заблокировать конкретный IP от доступа к подсети» → правило NACL. «Управлять трафиком к/от инстанса» → группа безопасности.

---

**Route 53** *(Глава 12)*

DNS-сервис и регистратор доменов AWS. Направляет интернет-трафик к ресурсам AWS и внешним конечным точкам. Политики маршрутизации: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, Multi-value answer.

Ключевые концепции: размещённые зоны (публичные и частные), типы записей (A, AAAA, CNAME, Alias), проверки работоспособности, Traffic Flow (визуальный редактор политик).

Признак в экзамене: «DNS-маршрутизация», «переключение при сбое между регионами», «маршрутизация на основе задержки или местоположения» → Route 53 с соответствующей политикой маршрутизации.

---

**CloudFront** *(Глава 13)*

Сеть доставки контента (CDN). Кэширует контент на граничных серверах (400+ по всему миру). Снижает задержку для конечных пользователей. Снижает затраты на передачу с источника через кэширование. Интегрируется с S3, EC2, ALB и API Gateway как источниками.

Ключевые концепции: дистрибутив, источники, поведения (маршрутизация по пути к источникам), TTL (управление кэшем), инвалидация кэша, подписанные URL и куки (управление доступом), Lambda@Edge и CloudFront Functions (выполнение кода на граничном сервере), Origin Shield (снижение нагрузки на источник).

Признак в экзамене: «Глобальная малая задержка», «кэшировать статический контент», «снизить нагрузку на источник», «защита от DDoS с Shield» → CloudFront.

---

**Direct Connect и VPN** *(Глава 25)*

AWS Direct Connect — выделенное физическое сетевое соединение из вашего локального дата-центра в AWS. Минует публичный интернет. Более стабильная пропускная способность и задержка. AWS Site-to-Site VPN — зашифрованный туннель через публичный интернет — быстрее настроить, дешевле, но переменная производительность.

Ключевые концепции: Virtual Interface (VIF), Direct Connect Gateway (подключение к нескольким регионам), Transit Gateway (топология сети «хаб и спица»), избыточность VPN-туннеля.

Признак в экзамене: «Выделенное частное соединение с AWS» → Direct Connect. «Зашифрованное соединение, более быстрая настройка» → VPN. «Соединить несколько VPC» → Transit Gateway.

---

**VPC Endpoints** *(Глава 30)*

Соединяют частные ресурсы с сервисами AWS без использования публичного интернета или NAT Gateway. Gateway Endpoints: бесплатно, доступны только для S3 и DynamoDB. Interface Endpoints (PrivateLink): платные за час + за ГБ, доступны для большинства сервисов AWS.

Признак в экзамене: «EC2 в частной подсети вызывает S3/DynamoDB — снизить затраты NAT Gateway» → Gateway Endpoint (бесплатно). «Частное соединение с SQS, SSM, Secrets Manager из частной подсети» → Interface Endpoint.

## Безопасность и идентификация

**IAM — Identity and Access Management** *(Главы 3 и 14)*

Управляет тем, кто что может делать в вашем AWS-аккаунте. Пользователи (долгосрочные учётные данные), Группы (пользователи с общими разрешениями), Роли (временные учётные данные для сервисов и кросс-аккаунтного доступа), Политики (JSON-документы, определяющие правила разрешения/запрета).

Ключевые концепции: Principal, Action, Resource, Condition, явный запрет > явное разрешение > неявный запрет, SCP (Service Control Policy в AWS Organizations), граница разрешений (Permission boundary), AssumeRole.

Признак в экзамене: IAM задействован в каждом вопросе безопасности. Ключевой паттерн: сервисы используют IAM-роли (не пользователей). Кросс-аккаунтный доступ использует принятие роли. Минимальные привилегии — предоставляйте только необходимое.

---

**KMS — Key Management Service** *(Глава 16)*

Управляемый сервис ключей шифрования. Создаёт, хранит и управляет криптографическими ключами. Управляемые клиентом ключи (CMK) позволяют определять ротацию, использование и политики доступа. Управляемые AWS ключи управляются автоматически.

Ключевые концепции: политика ключа (отдельная от политики IAM), конвертное шифрование (данные шифруются ключом данных; ключ данных шифруется CMK), автоматическая ротация ключа, мультирегиональные ключи, гранты.

Признак в экзамене: «Шифровать данные в покое», «управляемые клиентом ключи шифрования», «ротация ключей» → KMS.

---

**Secrets Manager** *(Глава 16)*

Хранит и автоматически ротирует конфиденциальные значения: учётные данные базы данных, API-ключи, OAuth-токены. Интегрируется с RDS для автоматической ротации паролей. Приложения получают секреты во время выполнения через API — никогда не хардкодируйте учётные данные.

Признак в экзамене: «Хранить и ротировать учётные данные базы данных», «избежать хардкоженных секретов» → Secrets Manager. «Хранить конфигурационные значения, не секреты» → Parameter Store (SSM).

---

**AWS Shield** *(Глава 17)*

Защита от DDoS. Shield Standard автоматический и бесплатный — защищает от распространённых объёмных и протокольных атак. Shield Advanced добавляет финансовую защиту, круглосуточную команду реагирования на DDoS и детальную видимость атак.

Признак в экзамене: «Защита от DDoS» → Shield Standard (автоматический) или Shield Advanced (корпоративный, с SLA).

---

**WAF — Web Application Firewall** *(Глава 17)*

Фильтрует HTTP/HTTPS трафик на основе правил: блокировка IP, ограничение частоты запросов, паттерны SQL-инъекций, паттерны XSS, географические ограничения, пользовательские правила. Подключается к CloudFront, ALB, API Gateway или AppSync.

Признак в экзамене: «Заблокировать конкретные IP-адреса», «предотвратить SQL-инъекции на граничном сервере», «ограничить скорость вызовов API» → WAF.

---

**GuardDuty** *(Глава 17)*

Сервис обнаружения угроз. Анализирует логи CloudTrail, VPC Flow Logs и DNS-логи с использованием ML и данных угроз. Обнаруживает необычную активность API, взаимодействие с известными вредоносными IP, скомпрометированные учётные данные.

Признак в экзамене: «Обнаружить необычную активность», «определить скомпрометированные IAM-учётные данные», «непрерывный мониторинг угроз» → GuardDuty.

---

## Обмен сообщениями и обработка событий

**SQS — Simple Queue Service** *(Глава 19)*

Управляемая очередь сообщений. Производители отправляют сообщения; потребители читают и удаляют их. Развязывает сервисы: отправитель не должен знать, доступен ли получатель. Стандартные очереди: доставка не менее одного раза, наилучшая упорядоченность. FIFO-очереди: точно однократная обработка, строгая упорядоченность.

Ключевые концепции: таймаут видимости (сообщение скрыто от других потребителей при обработке), Dead Letter Queue (DLQ) для сообщений, повторно не выполняемых, хранение сообщений (4 дня по умолчанию, до 14), длинный опрос (сокращает пустые ответы).

Признак в экзамене: «Развязать сервисы», «буферизовать запросы при пиках нагрузки», «асинхронная обработка» → SQS. «Порядок важен и требуется точно однократная обработка» → SQS FIFO.

---

**SNS — Simple Notification Service** *(Глава 19)*

Управляемый pub/sub-сервис. Издатели отправляют сообщение в топик; все подписчики получают копию. Паттерн веерной рассылки: одно сообщение → много потребителей. Протоколы: SQS, Lambda, HTTP/HTTPS, email, SMS, мобильный push.

Ключевые концепции: топик, подписка, паттерн веерной рассылки (SNS → несколько очередей SQS), фильтрация сообщений (подписчики получают только подходящие сообщения).

Признак в экзамене: «Отправлять уведомления нескольким конечным точкам одновременно», «веерная рассылка одного события нескольким потребителям» → SNS. Распространённый паттерн: SNS + SQS для надёжной веерной рассылки.

---

**EventBridge** *(Глава 22)*

Шина событий для построения событийно-управляемых архитектур. Маршрутизирует события от сервисов AWS, SaaS-партнёров и пользовательских источников к Lambda, SQS, SNS, Step Functions и другим целям. Поддерживает запланированные правила (cron) и сопоставление паттернов.

Признак в экзамене: «Маршрутизировать события от сервисов AWS к целям», «планировать Lambda-функции», «событийно-управляемая оркестрация» → EventBridge.

---

**Step Functions** *(Глава 22)*

Бессерверная оркестрация рабочих процессов. Координирует Lambda-функции, ECS-задачи, DynamoDB, SNS, SQS и другие сервисы в визуальные машины состояний. Обрабатывает повторы, обработку ошибок, параллельные ветки и состояния ожидания.

Ключевые концепции: машина состояний, типы состояний (Task, Wait, Choice, Parallel, Map, Pass, Succeed, Fail), Standard Workflows (точно однократно, длительные) против Express Workflows (не менее одного раза, высокий объём).

Признак в экзамене: «Оркестрировать несколько Lambda-функций», «длительные рабочие процессы с логикой повторов», «шаги одобрения человеком» → Step Functions.

---

**Kinesis** *(Глава 26)*

Потоковая передача данных в реальном времени. Kinesis Data Streams: надёжный, упорядоченный поток записей (как распределённый журнал коммитов). Потребители обрабатывают записи; данные хранятся 24 часа до 7 дней. Kinesis Data Firehose: полностью управляемая доставка в S3, Redshift, OpenSearch, Splunk — без управления потребителями.

Ключевые концепции: шард (единица пропускной способности: 1 МБ/с запись, 2 МБ/с чтение), ключ партиции (определяет назначение шарда), порядковый номер, контрольные точки (KCL или Lambda), Firehose против Streams.

Признак в экзамене: «Потоковая передача в реальном времени», «упорядоченные записи», «воспроизвести события» → Kinesis Data Streams. «Доставить потоковые данные в S3/Redshift без управления потребителями» → Kinesis Firehose. В отличие от SQS: Kinesis хранит и воспроизводит; SQS удаляет при потреблении.

## Аналитика

**Athena** *(Глава 26)*

Бессерверные SQL-запросы к данным в S3. Нет инфраструктуры для управления. Платите за запрос (за ТБ сканирования). Лучше всего с столбчатыми форматами (Parquet, ORC) и разбитыми данными.

Признак в экзамене: «Запрашивать данные S3 с SQL», «специализированная аналитика Data Lake», «без управления инфраструктурой» → Athena.

---

**Glue** *(Глава 26)*

Бессерверный ETL-сервис (Extract, Transform, Load). Glue Crawlers обнаруживают данные и обновляют Glue Data Catalog. Glue Jobs запускают преобразования Spark или Python. Data Catalog интегрируется с Athena, Redshift Spectrum и EMR.

Признак в экзамене: «Преобразовать и загрузить данные для аналитики», «обнаружить схему данных S3», «ETL-конвейер» → Glue.

## Высокая доступность и аварийное восстановление

**Multi-AZ и Multi-Region** *(Глава 18)*

Multi-AZ: синхронная репликация внутри региона для автоматического переключения при сбое (RDS Multi-AZ, балансировщик нагрузки между AZ). RPO ~0, RTO ~60 с для RDS. Multi-Region: асинхронная репликация для географической избыточности и меньшей задержки для глобальных пользователей.

Ключевые концепции: RTO (Recovery Time Objective — время восстановления), RPO (Recovery Point Objective — точка восстановления). Стратегии аварийного восстановления: Pilot Light, Warm Standby, Active-Active.

Признак в экзамене: различайте сбои на уровне AZ (обрабатывает Multi-AZ) против региональных сбоев (обрабатывает Multi-Region). Стоимость и сложность значительно возрастают с Multi-Region.

## Оптимизация затрат

**Модели ценообразования EC2** *(Глава 27)*

On-Demand: полная цена, без обязательств. Reserved Instances (1 или 3 года): скидка 30–72% для конкретного типа инстанса. Savings Plans (Compute или EC2 Instance): фиксированные почасовые расходы для гибкости. Spot: скидка 60–90% для прерываемых нагрузок.

Признак в экзамене: «Минимизировать затраты для предсказуемой нагрузки» → Savings Plans или Reserved Instances. «Отказоустойчивая пакетная обработка» → Spot. «Непредсказуемая или краткосрочная» → On-Demand.

---

**Ценообразование на передачу данных** *(Глава 30)*

Входящий в AWS: бесплатно. Внутри AZ: бесплатно. Между AZ: $0,01/ГБ в каждом направлении. Между регионами: $0,02–0,08/ГБ. Интернет (исходящий): ~$0,09/ГБ. Обработка NAT Gateway: $0,045/ГБ. Передача данных CloudFront дешевле, чем прямое EC2-в-интернет, а кэширование снижает общий объём.

Признак в экзамене: «Снизить затраты на передачу данных для S3/DynamoDB из частной подсети» → Gateway Endpoints (бесплатно). «Снизить затраты NAT Gateway для других сервисов» → Interface Endpoints.

## Наблюдаемость

**CloudWatch** *(упоминается на протяжении всей книги)*

Мониторинг и наблюдаемость. CloudWatch Metrics: числовые временны́е ряды от сервисов AWS и пользовательских приложений. CloudWatch Logs: сбор, поиск и анализ данных логов. CloudWatch Alarms: срабатывают уведомления или авто-масштабирование при пересечении порогов метрик. CloudWatch Dashboards: визуализация метрик.

Ключевые концепции: измерения метрик, периоды хранения, группы и потоки логов, фильтры метрик, CloudWatch Agent (для метрик уровня ОС и логов EC2), Container Insights.

---

**CloudTrail** *(упоминается на протяжении всей книги)*

Логирует каждый вызов API в вашем AWS-аккаунте: кто, откуда, когда и каков был ответ. Мультирегиональный журнал хранит логи в S3 бессрочно. Используется для аудита безопасности, соответствия требованиям и расследования инцидентов.

Признак в экзамене: «Кто удалил этот ресурс?» «Аудит всей API-активности» → CloudTrail.

---

**AWS Config** *(упоминается в Главе 31)*

Отслеживает изменения конфигурации ресурсов с течением времени. Оценивает ресурсы по правилам соответствия. Записывает историю каждого изменения конфигурации для каждого ресурса. Интегрируется с Systems Manager для исправления.

Признак в экзамене: «Соответствует ли этот ресурс нашей политике безопасности?» «Как выглядела конфигурация этого ресурса на прошлой неделе?» → AWS Config.
