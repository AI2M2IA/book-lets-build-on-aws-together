# Приложение A: Краткий справочник по сервисам AWS

Каждый сервис, рассмотренный в этой книге, в порядке его появления. Используйте это как учебный справочник и быстрый поиск при подготовке к экзамену.

---

## Вычисления

**EC2 — Elastic Compute Cloud** *(Глава 4)*

Виртуальные машины в облаке. Вы выбираете тип инстанса (CPU, память, хранилище), операционную систему и регион. Платите за час (On-Demand), за обязательство (Reserved Instances / Savings Plans) или за слот свободных мощностей (Spot). Базовый примитив вычислений.

Ключевые концепции: AMI (Amazon Machine Image), типы инстансов (семейства t3, m6g, r6g, c6g), пары ключей, профили инстансов, группы размещения.

Признак в экзамене: когда сценарий требует постоянных, с состоянием или длительных вычислений — EC2 или ECS. Когда требуются краткосрочные, событийно-запускаемые вычисления с нулевой стоимостью простоя — Lambda.

---

**Auto Scaling + Application Load Balancer** *(Глава 7)*

Auto Scaling Groups (ASG) добавляют и удаляют EC2-инстансы в зависимости от нагрузки. Application Load Balancers (ALB) распределяют трафик между инстансами и маршрутизируют по пути или хосту. Вместе они образуют уровень горизонтального масштабирования.

Ключевые концепции: шаблон запуска (launch template), политики масштабирования (целевое отслеживание, пошаговое, запланированное), проверки работоспособности, целевые группы ALB, правила слушателя, взвешенная маршрутизация.

Признак в экзамене: «Обрабатывать переменную нагрузку» или «высокая доступность в нескольких AZ» → ASG + ALB.

---

**Lambda** *(Глава 20)*

Бессерверные функции. Вы пишете код; AWS выполняет его в ответ на события. Серверами управлять не нужно. Платите за каждый вызов и за каждую миллисекунду выполнения. Автоматически масштабируется до тысяч одновременных выполнений.

Ключевые концепции: источники событий (API Gateway, S3, SQS, EventBridge, Kinesis), роль выполнения, лимиты параллелизма, зарезервированный и предоставленный параллелизм, холодный старт, Layers, максимальная длительность 15 минут.

Признак в экзамене: «бессерверное», «событийно-ориентированное», «краткосрочные задачи», «нет стоимости простоя» → Lambda.

---

**ECS — Elastic Container Service** *(Глава 21)*

Запускает контейнеры Docker в AWS. Два типа запуска: EC2 (хостом управляете вы) и Fargate (хостом управляет AWS). ECS управляет определениями задач, сервисами, планированием в кластере и интеграцией с балансировщиками нагрузки и обнаружением сервисов.

Ключевые концепции: определение задачи (task definition), сервис ECS, тип запуска Fargate vs. EC2, ECR (реестр контейнеров), IAM-роль задачи, автомасштабирование сервиса.

Признак в экзамене: «контейнеризированные нагрузки», «микросервисы», «Docker в AWS» → ECS (обычно Fargate для бессерверных контейнеров).

---

**EKS — Elastic Kubernetes Service** *(Глава 21)*

Управляемый Kubernetes. AWS управляет плоскостью управления (control plane); вы запускаете рабочие узлы (EC2 или Fargate). Используйте EKS, когда команда уже работает с Kubernetes или есть нагрузки, требующие специфичных для Kubernetes возможностей.

Признак в экзамене: «Kubernetes», «нужно перенести существующие нагрузки K8s» → EKS. «Просто нужны контейнеры без накладных расходов K8s» → ECS.

---

**AWS Batch** *(Глава 21)*

Управляемые пакетные вычисления для контейнеров Docker. Вы определяете задание (образ Docker + команду), очередь заданий и вычислительную среду (EC2 или Fargate). AWS Batch автоматически выделяет и масштабирует вычисления, затем завершает их по окончании задания. Поддерживает Spot Instances для снижения затрат.

Ключевые концепции: определение задания (что запускать), очередь заданий (где задания ожидают), вычислительная среда (EC2 или Fargate, On-Demand или Spot), массивы заданий (запуск многих параллельных копий одного задания).

Признак в экзамене: «пакетная обработка, превышающая 15-минутный таймаут Lambda», «конечные вычислительные задания в контейнерах», «HPC-нагрузки в AWS» → AWS Batch.

---

**AWS Outposts** *(Глава 2)*

Полностью управляемая стойка оборудования AWS, установленная в вашем собственном дата-центре или в колокейшн-помещении. Запускает те же сервисы, API и инструменты AWS, что и публичное облако (EC2, EBS, RDS, EKS, S3 на Outposts), но физически на ваших площадках.

Ключевые концепции: те же API AWS на ваших площадках, AWS управляет установкой и обновлениями, клиент предоставляет место в стойке и питание, Local Gateway (LGW) соединяет Outposts с локальными сетями.

Признак в экзамене: «запустить AWS в собственном дата-центре», «требование к резидентности данных требует, чтобы вычисления оставались на ваших площадках», «API AWS без зависимости от интернета» → Outposts.

---

**AWS Wavelength** *(Глава 2)*

Инфраструктура AWS, развёрнутая внутри сетей операторов 5G. Wavelength Zones находятся на границе сети 5G, обеспечивая задержку в единицы миллисекунд до мобильных устройств.

Ключевые концепции: Wavelength Zones — это расширения регионов AWS внутри сетей операторов связи, трафик остаётся в сети оператора между устройством и Wavelength Zone.

Признак в экзамене: «задержка в единицы миллисекунд до мобильных пользователей 5G», «мобильные AR/VR», «игры в реальном времени на мобильных», «телеметрия беспилотных автомобилей» → Wavelength.

---

**AWS Application Migration Service (MGN)** *(Глава 25)*

Сервис миграции методом rehost (lift-and-shift). Агент блок за блоком реплицирует диски исходных серверов в недорогую промежуточную область в AWS; вы по требованию запускаете тестовые копии; при переключении MGN преобразует реплицированные серверы в нативные инстансы EC2. Изменения приложения не требуются.

Ключевые концепции: непрерывная репликация на уровне блоков, промежуточная область, тестовые запуски перед переключением, стратегии миграции «7 R» (MGN = rehost).

Признак в экзамене: «быстро перенести сотни виртуальных машин без изменения кода», «lift-and-shift серверов в EC2» → MGN. DataSync перемещает *файлы*; DMS перемещает *базы данных*; MGN перемещает *целые серверы*.

## Хранилище

**S3 — Simple Storage Service** *(Глава 5)*

Объектное хранилище. Неограниченная ёмкость, надёжность 99,999999999 % (одиннадцать девяток). Хранит файлы как объекты в бакетах. Бакеты находятся в регионе. Объекты могут быть размером от 0 байт до 5 ТБ.

Ключевые концепции: политика бакета, ACL объекта, версионирование, хостинг статических сайтов, presigned URL, многокомпонентная загрузка (multipart upload), Transfer Acceleration, классы хранения (Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, Glacier Deep Archive, а также S3 Express One Zone для нагрузок в одной AZ, критичных к задержке, на directory-бакетах).

Признак в экзамене: «хранить и извлекать файлы», «статические ресурсы», «резервные копии», «озеро данных» → S3. Правильный класс хранения зависит от частоты доступа и скорости извлечения.

---

**EBS — Elastic Block Store** *(Глава 6)*

Блочное хранилище, подключённое к одному инстансу EC2. Работает как жёсткий диск. Сохраняется независимо от жизненного цикла инстанса (можно отключить и переподключить). Наиболее распространённые типы: gp3 (универсальный SSD, по умолчанию), io2 (provisioned IOPS для баз данных), st1 (HDD, оптимизированный по пропускной способности, для последовательного чтения).

Ключевые концепции: снимки (инкрементные, хранятся в S3), шифрование (KMS), Multi-Attach (только io1/io2), выделение IOPS и пропускной способности.

Признак в экзамене: «постоянное хранилище для EC2», «хранилище базы данных», «требуется блочный доступ с низкой задержкой» → EBS.

---

**EFS — Elastic File System** *(Глава 6)*

Общая файловая система, доступная одновременно с нескольких инстансов EC2. Протокол NFS. Масштабируется автоматически. Дороже EBS за ГБ. Классы хранения включают Standard, Infrequent Access и Archive. Intelligent-Tiering перемещает файлы автоматически.

Признак в экзамене: «общая файловая система», «нескольким инстансам EC2 нужны одни и те же файлы», «NFS» → EFS.

---

**Семейство FSx** *(Глава 6)*

Управляемые файловые серверы для конкретных технологий. FSx for Windows File Server: протокол SMB, NTFS, интеграция с Active Directory, Multi-AZ. FSx for Lustre: параллельная высокопроизводительная файловая система для HPC/ML, представляет объекты S3 как файлы (отложенная загрузка). FSx for NetApp ONTAP: мультипротокольная (NFS + SMB + iSCSI), снимки, репликация SnapMirror. FSx for OpenZFS: NFS с низкой задержкой, мгновенные снимки и записываемые клоны.

Признак в экзамене: «SMB/Active Directory» → FSx for Windows. «Обучение HPC/ML на данных S3» → FSx for Lustre. «NFS и SMB к одним и тем же данным / миграция NetApp» → FSx for ONTAP. «Миграция ZFS / мгновенные клоны» → FSx for OpenZFS.

---

**Классы хранения S3 и политики жизненного цикла** *(Глава 23)*

S3 Intelligent-Tiering автоматически перемещает объекты между уровнями доступа в зависимости от частоты обращений. Политики жизненного цикла переводят объекты между классами (Standard → Standard-IA → Glacier) по правилам, основанным на возрасте. Классы хранения Glacier имеют задержку извлечения от минут (Glacier Instant) до 12 часов (Glacier Deep Archive).

Признак в экзамене: «снизить стоимость хранения редко используемых данных» → политики жизненного цикла, Intelligent-Tiering или Glacier.

---

**AWS Storage Gateway** *(Глава 6)*

Гибридный сервис хранения, соединяющий локальные среды с хранилищем AWS. Предоставляет хранилище по протоколам, которые приложения уже понимают, при этом сохраняя данные в S3, S3 Glacier или в виде снимков EBS.

Ключевые концепции: File Gateway (NFS/SMB → S3), Volume Gateway (iSCSI, режим cached или stored), Tape Gateway (виртуальная ленточная библиотека → Glacier).

Признак в экзамене: «локальному приложению нужно облачное хранилище без изменения кода» → Storage Gateway. «Заменить ленточное резервное копирование» → Tape Gateway.

---

**AWS DataSync** *(Глава 25)*

Сервис миграции и репликации данных на основе агента. Лёгкий агент подключается к локальным файловым серверам по NFS или SMB и синхронизирует общие ресурсы в S3, EFS или FSx — со встроенными планированием, ограничением пропускной способности и проверкой целостности.

Ключевые концепции: агент DataSync (виртуальная машина на ваших площадках или EC2), источники NFS/SMB, получатели S3/EFS/FSx, запланированные инкрементные передачи.

Признак в экзамене: «перенести или непрерывно синхронизировать большое количество файлов с локального NAS в AWS по сети» → DataSync.

---

**AWS Transfer Family** *(Глава 25)*

Полностью управляемый сервер SFTP, FTPS и FTP с хранилищем-получателем на базе S3 или EFS. Клиенты подключаются своим существующим ПО SFTP; загруженные файлы попадают напрямую в бакет или файловую систему.

Ключевые концепции: управляемая конечная точка (опционально со статическим IP), хранилище на базе S3 или EFS, совместимость с существующими протоколами для внешних партнёров.

Признак в экзамене: «партнёры должны продолжать загрузку через SFTP, но файлы должны попадать в S3» → Transfer Family.

---

**AWS Snow Family** *(Глава 25)*

Физические устройства для офлайн-передачи данных, массовой миграции. Snowball Edge Storage Optimized: 80 ТБ полезного объёма, защищённый корпус, доставляется на ваш объект; вы загружаете данные локально и отправляете обратно для приёма в S3.

Ключевые концепции: сначала посчитайте передачу — если по сети передача заняла бы примерно неделю или больше, выигрывает физическое устройство. *Примечание о legacy (2026)*: AWS постепенно сворачивает это семейство — Snowmobile (2024) и Snowcone (конец 2024) больше нет, а устройства Snow закрыты для новых клиентов в ноябре 2025 (AWS теперь рекомендует DataSync и Data Transfer Terminals). Банк вопросов SAA-C03 предшествует этому, поэтому экзамен всё ещё ожидает Snowball в качестве ответа.

Признак в экзамене: «миграция в петабайтном масштабе», «ограниченная пропускная способность, недели на передачу» → Snow Family.

---

**AWS Backup** *(Главы 18 и 23)*

Централизованный, основанный на политиках сервис резервного копирования для EBS, RDS, DynamoDB, EFS и Storage Gateway. Планы резервного копирования определяют расписания и сроки хранения; хранилища (vaults) хранят точки восстановления.

Ключевые концепции: планы и хранилища резервных копий, межрегиональные и межаккаунтные копии, Vault Lock для неизменяемости.

Признак в экзамене: «централизовать и автоматизировать резервное копирование для нескольких сервисов AWS», «межаккаунтные копии для защиты от программ-вымогателей / компрометации аккаунта» → AWS Backup.

## Базы данных

**RDS — Relational Database Service** *(Глава 8)*

Управляемые реляционные базы данных. Поддерживаемые движки: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server и Aurora (собственный движок AWS). AWS берёт на себя резервное копирование, обновления, переключение при сбое и репликацию. Вы управляете проектированием схемы, запросами и размером инстанса.

Ключевые концепции: развёртывание Multi-AZ (автоматическое переключение при сбое, синхронная репликация), Read Replicas (асинхронные, для масштабирования чтения), автоматическое резервное копирование (срок хранения 1–35 дней), ручные снимки (хранятся до удаления), RDS Proxy (пул соединений).

Признак в экзамене: «реляционная база данных», «ACID-транзакции», «существующая SQL-нагрузка» → RDS или Aurora.

---

**Aurora** *(Глава 24)*

Реляционный движок базы данных AWS, совместимый с MySQL и PostgreSQL. Распределённый движок хранения, который реплицирует данные в 3 AZ в 6 копиях. Обычно в 5 раз быстрее MySQL. Aurora Serverless v2 масштабирует ёмкость автоматически (измеряется в ACU — Aurora Capacity Units) и на поддерживаемых версиях движка может автоматически приостанавливаться до 0 ACU, когда нет открытых соединений.

Ключевые концепции: кластер Aurora (writer + до 15 Aurora Replicas за единой конечной точкой чтения), Aurora Global Database (межрегиональные реплики чтения с задержкой репликации < 1 секунды), Aurora Serverless v2, ACU, поведение auto-pause/resume.

Признак в экзамене: «высокопроизводительная реляционная база данных», «совместимость с MySQL/PostgreSQL», «глобальное чтение», «переменная нагрузка» → Aurora.

---

**DynamoDB** *(Глава 9)*

Полностью управляемая база данных NoSQL. Модель «ключ-значение» и документная модель. Масштабируется до любой пропускной способности с производительностью в единицы миллисекунд. Два режима ёмкости: on-demand (оплата за запрос) и provisioned (оплата за единицу ёмкости в час, с Auto Scaling).

Ключевые концепции: ключ раздела (обязательный), ключ сортировки (опциональный), Global Secondary Index (GSI), Local Secondary Index (LSI), DynamoDB Streams (захват изменений), DynamoDB Accelerator (DAX) — кэш в памяти, TTL (Time to Live), транзакции.

Признак в экзамене: «высокая пропускная способность доступа по ключу», «гибкая схема», «бессерверный NoSQL» → DynamoDB.

---

**ElastiCache** *(Глава 10)*

Управляемое кэширование в памяти. Два движка: Redis (с сохранением, pub/sub, скрипты Lua, структуры данных) и Memcached (чистый кэш, проще, многопоточный). Используется для снижения нагрузки на базу данных и выдачи часто читаемых данных за микросекунды.

Ключевые концепции: паттерн cache-aside, паттерн write-through, политики вытеснения, TTL, режим кластера (Redis), Multi-AZ с автоматическим переключением при сбое.

Признак в экзамене: «снизить нагрузку на базу данных», «задержка чтения менее миллисекунды», «управление сессиями», «таблица лидеров в реальном времени» → ElastiCache Redis.

---

**Amazon MemoryDB for Redis** *(Глава 10)*

Долговечная, Redis-совместимая первичная база данных в памяти. В отличие от ElastiCache (кэш, где потеря данных допустима), MemoryDB хранит журнал транзакций Multi-AZ и гарантирует долговечность. MemoryDB можно использовать как основную базу данных — а не только как кэш перед другой базой.

Ключевые концепции: совместимость с Redis API, журнал транзакций Multi-AZ (гарантия долговечности), производительность в памяти, первичная база данных (не уровень кэша).

Признак в экзамене: «совместимость с Redis И потеря данных недопустима», «долговечная база данных в памяти» → MemoryDB. «Redis как кэш, потеря данных допустима» → ElastiCache Redis.

---

**Специализированные базы данных** *(Главы 9, 10 и 24)*

Подбирайте форму данных под движок. DocumentDB: документы, совместимые с MongoDB. Neptune: графовая база данных (связи, обходы — Gremlin/SPARQL). Keyspaces: широкие столбцы, совместимые с Cassandra. Timestream: временные ряды (текущее предложение: Timestream for InfluxDB). MemoryDB: долговечная, Redis-совместимая *первичная* база данных (vs ElastiCache = кэш). QLDB («неизменяемый криптографический реестр») был прекращён в 2025 году — воспринимайте как устаревший отвлекающий вариант.

Признак в экзамене: «социальный граф / рекомендации / кольца мошенничества» → Neptune. «MongoDB» → DocumentDB. «Cassandra» → Keyspaces. «телеметрия IoT во времени» → Timestream.

---

**AWS DMS — Database Migration Service** *(Глава 8)*

Переносит базы данных в AWS с минимальным простоем. Поддерживает полную загрузку (первоначальная копия) плюс CDC (Change Data Capture) для синхронизации источника и приёмника во время миграции. При миграции между одинаковыми типами движков (MySQL → MySQL, PostgreSQL → PostgreSQL) используйте DMS напрямую. При миграции между разными типами движков (Oracle → Aurora PostgreSQL) сначала используйте AWS Schema Conversion Tool (SCT) для преобразования схемы, затем DMS для данных.

Ключевые концепции: инстанс репликации, исходная и целевая конечные точки, полная загрузка + CDC, SCT (Schema Conversion Tool) для гетерогенных миграций.

Признак в экзамене: «перенести базу данных с минимальным простоем» → DMS. «Oracle в Aurora» или любая гетерогенная миграция → SCT + DMS. «Тот же движок, тот же тип» → DMS напрямую.

## Сети

**VPC — Virtual Private Cloud** *(Глава 11)*

Изолированная сеть внутри AWS. Охватывает все AZ в регионе. Вы определяете адресное пространство IP (блок CIDR), создаёте подсети (публичные или приватные), настраиваете таблицы маршрутизации и контролируете доступ через группы безопасности и NACL.

Ключевые концепции: публичная подсеть (маршрут к Internet Gateway), приватная подсеть (маршрут к NAT Gateway для исходящего трафика), Internet Gateway (входящий + исходящий трафик в интернет), NAT Gateway (только исходящий для приватных инстансов), VPC Peering (соединение двух VPC), VPC Endpoints (подключение к сервисам AWS без интернета).

Признак в экзамене: «приватная сеть в AWS», «изолировать ресурсы от интернета», «контролировать сетевой трафик» → VPC.

---

**Группы безопасности и NACL** *(Глава 15)*

Группы безопасности — это файрволы с сохранением состояния на уровне инстанса: только правила allow, обратный трафик разрешается автоматически. NACL (Network Access Control Lists) — это файрволы без сохранения состояния на уровне подсети: требуют как входящих, так и исходящих правил, оцениваются по порядку номеров правил.

Признак в экзамене: «заблокировать конкретный IP от доступа к подсети» → NACL. «Контролировать трафик к/от инстанса» → группа безопасности.

---

**Route 53** *(Глава 12)*

Сервис DNS и регистратор доменов AWS. Маршрутизирует интернет-трафик к ресурсам AWS и внешним конечным точкам. Политики маршрутизации: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, Multivalue answer.

Ключевые концепции: размещённые зоны (публичные и приватные), типы записей (A, AAAA, CNAME, Alias), проверки работоспособности, Traffic Flow (визуальный редактор политик — обратите внимание, что geoproximity также доступна как прямая политика маршрутизации на записях, с регулируемым смещением (bias), без необходимости в Traffic Flow).

Признак в экзамене: «маршрутизация DNS», «переключение между регионами при сбое», «маршрут на основе задержки или местоположения» → Route 53 с подходящей политикой маршрутизации.

---

**CloudFront** *(Глава 13)*

Сеть доставки контента (CDN). Кэширует контент в граничных локациях (750+ точек присутствия по всему миру). Снижает задержку для конечных пользователей. Снижает затраты на передачу из источника за счёт кэширования. Интегрируется с S3, EC2, ALB и API Gateway в качестве источников.

Ключевые концепции: дистрибутив, источники (origins), поведения (маршрутизация к источникам по пути), TTL (управление кэшем), инвалидация кэша, подписанные URL и cookie (контроль доступа), Lambda@Edge и CloudFront Functions (выполнение кода на границе), Origin Shield (снижение нагрузки на источник).

Признак в экзамене: «глобальная низкая задержка», «кэшировать статический контент», «снизить нагрузку на источник», «защита от DDoS с помощью Shield» → CloudFront.

---

**Direct Connect и VPN** *(Глава 25)*

AWS Direct Connect — это выделенное физическое сетевое соединение от вашего локального дата-центра до AWS. Обходит публичный интернет. Более стабильная пропускная способность и задержка. AWS Site-to-Site VPN — это зашифрованный туннель через публичный интернет: быстрее настроить, дешевле, но переменная производительность.

Ключевые концепции: Virtual Interface (VIF), Direct Connect Gateway (подключение к нескольким регионам), Transit Gateway (топология сети «звезда»), резервирование туннеля VPN.

Признак в экзамене: «выделенное приватное соединение с AWS» → Direct Connect. «Зашифрованное соединение, быстрая настройка» → VPN. «Соединить несколько VPC» → Transit Gateway.

---

**VPC Endpoints** *(Глава 30)*

Подключают приватные ресурсы к сервисам AWS без использования публичного интернета или NAT Gateway. Gateway Endpoints: бесплатны, доступны только для S3 и DynamoDB. Interface Endpoints (PrivateLink): тарификация за час + за ГБ, доступны для большинства сервисов AWS.

Признак в экзамене: «EC2 в приватной подсети обращается к S3/DynamoDB — снизить затраты на NAT Gateway» → Gateway Endpoint (бесплатно). «Приватное соединение с SQS, SSM, Secrets Manager из приватной подсети» → Interface Endpoint.

---

**AWS Client VPN** *(Глава 11)*

Управляемая конечная точка OpenVPN, позволяющая отдельным устройствам (ноутбукам, рабочим станциям) безопасно подключаться к VPC через интернет. Варианты аутентификации: Active Directory, федерация SAML 2.0 с поставщиком идентификации или взаимный TLS (на основе сертификатов). Поддерживает split-tunnel (через туннель идёт только трафик к VPC) и full-tunnel (весь трафик маршрутизируется через AWS).

Ключевые концепции: конечная точка Client VPN, целевая сеть (ассоциация с подсетью VPC), правила авторизации, split-tunnel vs. full-tunnel.

Признак в экзамене: «удалённым инженерам нужен безопасный доступ к VPC из дома», «подключение отдельного устройства к VPC» → Client VPN. Контраст: Site-to-Site VPN = сеть-к-сети. Client VPN = устройство-к-сети.

---

**Network Load Balancer (NLB) и Gateway Load Balancer (GWLB)** *(Глава 7)*

NLB работает на уровне 4 (TCP/UDP/TLS): без инспекции HTTP, просто маршрутизация пакетов на предельной скорости — миллионы запросов в секунду, со статическим IP на AZ и сохранением исходного IP. GWLB работает на уровне 3 и существует для одной цели: встраивание сторонних виртуальных сетевых устройств (файрволы, IDS/IPS, глубокая инспекция пакетов) в потоки трафика.

Ключевые концепции: NLB = уровень 4, статические IP, сверхнизкая задержка, не-HTTP протоколы. GWLB = уровень 3, инкапсуляция GENEVE, флоты устройств за единой точкой входа. ALB = уровень 7 (маршрутизация по пути/хосту).

Признак в экзамене: «миллионы TCP-запросов в секунду», «статический IP для балансировщика нагрузки», «сохранить исходный IP» → NLB. «Встроить сторонние устройства безопасности в путь трафика» → GWLB.

---

**AWS Global Accelerator** *(Глава 25)*

Направляет пользовательский трафик на приватный глобальный магистральный канал AWS в ближайшей граничной локации, вместо прохождения через публичный интернет. Предоставляет два статических Anycast-адреса IP, которые стоят перед вашими ALB, NLB или инстансами EC2 в одном или нескольких регионах. Улучшает задержку и стабильность для *динамического* (некэшируемого) трафика.

Ключевые концепции: статические Anycast-адреса IP, вход в магистраль AWS на границе, региональное переключение при сбое на основе проверок работоспособности за секунды, группы конечных точек с регуляторами трафика (traffic dials).

Признак в экзамене: «глобальные пользователи, динамический/не-HTTP трафик, статический IP, быстрое региональное переключение при сбое» → Global Accelerator. «Кэшируемый/статический контент» → вместо этого CloudFront.

---

## Безопасность и идентификация

**IAM — Identity and Access Management** *(Главы 3 и 14)*

Контролирует, кто и что может делать в вашем аккаунте AWS. Пользователи (долгосрочные учётные данные), группы (пользователи с общими разрешениями), роли (временные учётные данные для сервисов и межаккаунтного доступа), политики (документы JSON, определяющие правила allow/deny).

Ключевые концепции: Principal, Action, Resource, Condition, явный deny > явный allow > неявный deny, SCP (Service Control Policy в AWS Organizations), граница разрешений (Permission boundary), AssumeRole.

Признак в экзамене: IAM участвует в каждом вопросе о безопасности. Ключевой паттерн: сервисы используют IAM-роли (а не пользователей). Межаккаунтный доступ использует принятие роли. Минимальные привилегии — предоставляйте только то, что требуется.

---

**KMS — Key Management Service** *(Глава 16)*

Управляемый сервис ключей шифрования. Создаёт, хранит и контролирует криптографические ключи. Управляемые клиентом ключи (CMK) позволяют определять ротацию, использование и политики доступа. Управляемые AWS ключи управляются автоматически.

Ключевые концепции: политика ключа (отдельная от политики IAM), конвертное шифрование (данные шифруются ключом данных; ключ данных шифруется CMK), автоматическая ротация ключей, мультирегиональные ключи, гранты (grants).

Признак в экзамене: «шифровать данные в покое», «управляемые клиентом ключи шифрования», «ротация ключей» → KMS.

---

**Secrets Manager** *(Глава 16)*

Хранит и автоматически ротирует чувствительные значения: учётные данные базы данных, ключи API, токены OAuth. Интегрируется с RDS для автоматической ротации паролей. Приложения извлекают секреты во время выполнения через API — никогда не зашивайте учётные данные в код.

Признак в экзамене: «хранить и ротировать учётные данные базы данных», «избегать зашитых в код секретов» → Secrets Manager. «Хранить значения конфигурации, не секреты» → Parameter Store (SSM).

---

**AWS Shield** *(Глава 17)*

Защита от DDoS. Shield Standard включён автоматически и бесплатен — защищает от распространённых объёмных и протокольных атак. Shield Advanced добавляет финансовую защиту, круглосуточную команду реагирования на DDoS и детальную видимость атак.

Признак в экзамене: «защита от DDoS» → Shield Standard (автоматически) или Shield Advanced (корпоративный, с SLA).

---

**WAF — Web Application Firewall** *(Глава 17)*

Фильтрует трафик HTTP/HTTPS на основе правил: блокировки IP, ограничения частоты, паттерны SQL-инъекций, паттерны XSS, географические ограничения, пользовательские правила. Подключается к CloudFront, ALB, API Gateway или AppSync.

Признак в экзамене: «заблокировать конкретные IP-адреса», «предотвратить SQL-инъекции на границе», «ограничить частоту вызовов API» → WAF.

---

**GuardDuty** *(Глава 17)*

Сервис обнаружения угроз. Анализирует журналы CloudTrail, VPC Flow Logs и DNS-журналы с помощью ML и аналитики угроз. Обнаруживает необычную активность API, связь с известными вредоносными IP, скомпрометированные учётные данные.

Признак в экзамене: «обнаружить необычную активность», «выявить скомпрометированные учётные данные IAM», «непрерывный мониторинг угроз» → GuardDuty.

---

**Amazon Inspector** *(Глава 17)*

Автоматизированный сервис оценки уязвимостей. Непрерывно сканирует инстансы EC2, образы контейнеров Amazon ECR и функции Lambda на наличие уязвимостей ПО (CVE) и непреднамеренного сетевого доступа. Находки отправляются в AWS Security Hub для централизованного управления.

Ключевые концепции: сканирование CVE, непрерывная (а не разовая) оценка, охват EC2 + ECR + Lambda, интеграция с Security Hub.

Признак в экзамене: «автоматически сканировать EC2 на известные уязвимости», «сканирование CVE для образов контейнеров», «непрерывная оценка уязвимостей» → Inspector.

---

**Amazon Cognito** *(Глава 14)*

Управляемая аутентификация для конечных пользователей вашего приложения — каталог пользователей, который не нужно создавать самим. User Pools обрабатывают регистрацию, вход, MFA, сброс пароля и социальных поставщиков идентификации (Google, Facebook, любой OIDC-провайдер), выдавая JWT, которые проверяет ваше приложение. Identity Pools обменивают эти токены на временные учётные данные AWS.

Ключевые концепции: User Pool (аутентификация, JWT) vs. Identity Pool (временные учётные данные AWS), размещённый UI, федерация social/OIDC/SAML, авторизатор Cognito в API Gateway.

Признак в экзамене: «приложению нужна регистрация/вход пользователей», «вход через соцсети», «дать пользователям мобильного приложения временный доступ к ресурсам AWS» → Cognito. Контраст: IAM — для ваших инженеров и сервисов; Cognito — для ваших клиентов.

---

**AWS Certificate Manager (ACM)** *(Глава 16)*

Предоставляет бесплатные публичные сертификаты TLS/SSL для управляемых AWS сервисов (ALB, CloudFront, API Gateway) и берёт на себя весь жизненный цикл — никакого календаря продлений, никакой работы с приватным ключом. Автоматически продлевает через DNS-валидацию.

Ключевые концепции: DNS- vs. email-валидация, автопродление, сертификаты для CloudFront должны быть в us-east-1, бесплатные публичные сертификаты нельзя экспортировать (с 2025 года существует платный экспортируемый вариант).

Признак в экзамене: «HTTPS на балансировщике нагрузки или CDN», «автоматическое продление сертификатов» → ACM.

---

**Amazon Macie** *(Глава 17)*

Обнаружение чувствительных данных для S3. Использует машинное обучение и сопоставление с образцами для поиска ПД (имена, номера карт, учётные данные) в бакетах и помечает риски доступа, такие как публичный доступ. Дополняет GuardDuty: GuardDuty следит за поведением; Macie проверяет, что хранится.

Ключевые концепции: управляемые идентификаторы данных (паттерны ПД), область только S3, находки в Security Hub/EventBridge.

Признак в экзамене: «обнаружить ПД в S3», «выявить раскрытие чувствительных данных» → Macie.

---

**AWS Control Tower** *(Глава 14)*

Автоматизирует настройку и управление многоаккаунтной средой. Создаёт landing zone — аккаунты управления, архива журналов и аудита, заранее подключённые к Organizations, CloudTrail, Config и ограничителям (guardrails) — за минуты вместо дней ручной настройки.

Ключевые концепции: landing zone, ограничители (preventive = SCP, detective = правила Config), Account Factory для стандартизированных новых аккаунтов.

Признак в экзамене: «настроить и управлять новой многоаккаунтной средой с лучшими практиками автоматически» → Control Tower. Контраст: Organizations — это базовый строительный блок; Control Tower — автоматизированная сборка.

---

## Обмен сообщениями и обработка событий

**SQS — Simple Queue Service** *(Глава 19)*

Управляемая очередь сообщений. Производители отправляют сообщения; потребители читают и удаляют их. Развязывает сервисы: отправителю не нужно знать, доступен ли получатель. Стандартные очереди: доставка не менее одного раза, упорядочивание по возможности. Очереди FIFO: обработка ровно один раз, строгий порядок.

Ключевые концепции: тайм-аут видимости (сообщение скрыто от других потребителей во время обработки), очередь недоставленных сообщений (Dead Letter Queue, DLQ) для повторно сбоящих сообщений, срок хранения сообщений (4 дня по умолчанию, до 14), длинный опрос (long polling, снижает пустые ответы), максимальный размер полезной нагрузки 256 КБ по умолчанию (повышается до 1 MiB с 2025 года; для бóльших полезных нагрузок Extended Client Library хранит тело в S3).

Признак в экзамене: «развязать сервисы», «буферизовать запросы при пиках нагрузки», «асинхронная обработка» → SQS. «Важен порядок и требуется обработка ровно один раз» → SQS FIFO.

---

**SNS — Simple Notification Service** *(Глава 19)*

Управляемый сервис pub/sub. Издатели отправляют сообщение в топик; все подписчики получают копию. Паттерн fan-out: одно сообщение → много потребителей. Протоколы: SQS, Lambda, HTTP/HTTPS, email, SMS, мобильные push-уведомления.

Ключевые концепции: топик, подписка, паттерн fan-out (SNS → несколько очередей SQS), фильтрация сообщений (подписчики получают только соответствующие сообщения).

Признак в экзамене: «отправить уведомления нескольким конечным точкам одновременно», «разослать одно событие нескольким потребителям» → SNS. Распространённый паттерн: SNS + SQS для долговечного fan-out.

---

**EventBridge** *(Глава 22)*

Шина событий для построения событийно-ориентированных архитектур. Маршрутизирует события от сервисов AWS, SaaS-партнёров и пользовательских источников в Lambda, SQS, SNS, Step Functions и другие цели. Поддерживает запланированные правила (cron) и сопоставление с шаблонами.

Признак в экзамене: «маршрутизировать события от сервисов AWS к целям», «запланировать функции Lambda», «событийно-ориентированная оркестрация» → EventBridge.

---

**Step Functions** *(Глава 22)*

Бессерверная оркестрация рабочих процессов. Координирует функции Lambda, задачи ECS, DynamoDB, SNS, SQS и другие сервисы в визуальные конечные автоматы. Обрабатывает повторные попытки, обработку ошибок, параллельные ветви и состояния ожидания.

Ключевые концепции: конечный автомат (state machine), типы состояний (Task, Wait, Choice, Parallel, Map, Pass, Succeed, Fail), Standard Workflows (ровно один раз, длительные) vs. Express Workflows: асинхронные (не менее одного раза, высокая нагрузка — проектируйте задачи идемпотентными) и синхронные (не более одного раза, возвращают результат напрямую, как вызов API).

Признак в экзамене: «оркестрировать несколько функций Lambda», «длительные рабочие процессы с логикой повторов», «шаги одобрения человеком» → Step Functions.

---

**Kinesis** *(Глава 26)*

Потоковая передача данных в реальном времени. Kinesis Data Streams: долговечный, упорядоченный поток записей (как распределённый журнал коммитов). Потребители обрабатывают записи; данные хранятся от 24 часов (по умолчанию) до 365 дней (с Extended Data Retention). Amazon Data Firehose (ранее Kinesis Data Firehose): полностью управляемая доставка в S3, Redshift, OpenSearch, Splunk — управлять потребителями не нужно.

Ключевые концепции: шард (единица пропускной способности: 1 МБ/с на запись, 2 МБ/с на чтение), ключ раздела (определяет назначение шарда), порядковый номер, контрольные точки (KCL или Lambda), Firehose vs. Streams.

Признак в экзамене: «потоковая передача в реальном времени», «упорядоченные записи», «повтор воспроизведения событий» → Kinesis Data Streams. «Доставить потоковые данные в S3/Redshift без управления потребителями» → Amazon Data Firehose (в более старых вопросах может встречаться «Kinesis Data Firehose»). «SQL по потоковым данным» → Amazon Managed Service for Apache Flink (ранее Kinesis Data Analytics). Контраст с SQS: Kinesis хранит и воспроизводит; SQS удаляет при потреблении.

---

**Amazon MQ** *(Глава 19)*

Управляемый сервис брокера сообщений с поддержкой Apache ActiveMQ и RabbitMQ. Поддерживает отраслевые стандартные протоколы обмена сообщениями: AMQP, STOMP, MQTT, OpenWire и WebSocket. Основной сценарий использования — миграция методом lift-and-shift локальных нагрузок брокера сообщений: приложения, которые уже используют ActiveMQ или RabbitMQ, могут подключаться без изменения кода.

Ключевые концепции: выбор движка ActiveMQ vs. RabbitMQ, поддержка протоколов (AMQP/STOMP/MQTT), конфигурация брокера single-instance или active/standby для HA.

Признак в экзамене: «перенести локальный ActiveMQ или RabbitMQ в AWS без изменения кода приложения» → Amazon MQ. «Новый нативный для AWS обмен сообщениями» → SQS или SNS (проще, лучше масштабируется).

## Аналитика

**Athena** *(Глава 26)*

Бессерверные SQL-запросы к данным, хранящимся в S3. Инфраструктурой управлять не нужно. Оплата за запрос (за просканированный ТБ). Лучше всего работает с колоночными форматами (Parquet, ORC) и партиционированными данными.

Признак в экзамене: «запрашивать данные S3 с помощью SQL», «ad-hoc аналитика по озеру данных», «без управления инфраструктурой» → Athena.

---

**Glue** *(Глава 26)*

Бессерверный сервис ETL (Extract, Transform, Load). Glue Crawlers обнаруживают данные и обновляют Glue Data Catalog. Glue Jobs выполняют преобразования на Spark или Python. Data Catalog интегрируется с Athena, Redshift Spectrum и EMR.

Признак в экзамене: «преобразовать и загрузить данные для аналитики», «обнаружить схему данных S3», «конвейер ETL» → Glue.

---

**Amazon QuickSight** *(Глава 26)*

Управляемый сервис бизнес-аналитики и визуализации данных. Использует SPICE (Super-fast, Parallel, In-memory Calculation Engine), движок в памяти, который кэширует импортированные данные для быстрой отрисовки дашбордов. Подключается к Athena, S3, Redshift, RDS и другим источникам данных AWS. Сервером BI управлять не нужно.

Ключевые концепции: SPICE (движок в памяти), наборы данных, анализы, дашборды, ML Insights (обнаружение аномалий, прогнозирование), безопасность на уровне строк и столбцов.

Признак в экзамене: «дашборд BI в AWS без управления сервером», «визуализировать данные из Athena или Redshift» → QuickSight.

---

**AWS Lake Formation** *(Глава 26)*

Централизованный уровень контроля доступа к озеру данных поверх S3 и Glue Data Catalog. Предоставляет точечные разрешения на уровне таблиц, столбцов и строк — более гранулярно, чем одни лишь политики бакетов S3. Упрощает настройку безопасного озера данных: Lake Formation управляет моделью разрешений; Glue управляет каталогом; S3 хранит данные.

Ключевые концепции: разрешения озера данных (на уровне таблиц/столбцов/строк), интеграция с Glue Data Catalog, LF-теги для контроля доступа на основе атрибутов, централизованные grant/revoke для запросов Athena и Redshift Spectrum.

Признак в экзамене: «точечный контроль доступа к озеру данных», «безопасность на уровне столбцов или строк для данных S3» → Lake Formation.

---

## Высокая доступность и аварийное восстановление

**Multi-AZ и Multi-Region** *(Глава 18)*

Multi-AZ: синхронная репликация внутри региона для автоматического переключения при сбое (RDS Multi-AZ, балансировщик нагрузки между AZ). RPO ~0, RTO ~60 с для RDS. Multi-Region: асинхронная репликация для географической избыточности и меньшей задержки для глобальных пользователей.

Ключевые концепции: RTO (Recovery Time Objective — как долго восстанавливаться), RPO (Recovery Point Objective — сколько данных можно потерять). Стратегии DR: Pilot Light, Warm Standby, Active-Active.

Признак в экзамене: различайте сбои на уровне AZ (обрабатывает Multi-AZ) и региональные сбои (обрабатывает Multi-Region). Стоимость и сложность значительно возрастают с Multi-Region.

---

**AWS Elastic Disaster Recovery (DRS)** *(Глава 18)*

Управляемое аварийное восстановление для серверов (локальных или EC2). Непрерывно реплицирует исходные серверы блок за блоком в недорогую промежуточную область и при необходимости запускает полноценные инстансы восстановления за минуты — управляемый pilot light: время восстановления, близкое к warm-standby, по цене, близкой к backup-and-restore.

Ключевые концепции: непрерывная репликация на уровне блоков, недорогая промежуточная область, запуск восстановления по требованию, восстановление на момент времени.

Признак в экзамене: «минимизировать простой и потерю данных для серверных нагрузок управляемым сервисом DR», «pilot light без самостоятельной сборки» → DRS.

## Оптимизация затрат

**Модели ценообразования EC2** *(Глава 27)*

On-Demand: полная цена, без обязательств. Reserved Instances (1 или 3 года): скидка 30–72 % за конкретный тип инстанса. Savings Plans (Compute или EC2 Instance): обязательство по почасовым расходам в обмен на гибкость. Spot: скидка 60–90 % для прерываемых нагрузок.

Признак в экзамене: «минимизировать стоимость предсказуемой нагрузки» → Savings Plans или Reserved Instances. «Отказоустойчивая пакетная обработка» → Spot. «Непредсказуемая или краткосрочная» → On-Demand.

---

**Ценообразование передачи данных** *(Глава 30)*

Входящий в AWS: бесплатно. Внутри одной AZ: бесплатно. Между AZ: $0,01/ГБ в каждом направлении. Между регионами: $0,02–0,08/ГБ. Интернет (исходящий): ~$0,09/ГБ. Обработка NAT Gateway: $0,045/ГБ. Передача данных через CloudFront дешевле прямой передачи EC2-в-интернет, а кэширование снижает общий объём.

Признак в экзамене: «снизить затраты на передачу данных для S3/DynamoDB из приватной подсети» → Gateway Endpoints (бесплатно). «Снизить затраты на NAT Gateway для других сервисов» → Interface Endpoints.

## Наблюдаемость

**CloudWatch** *(упоминается на протяжении всей книги)*

Мониторинг и наблюдаемость. CloudWatch Metrics: числовые временные ряды от сервисов AWS и пользовательских приложений. CloudWatch Logs: сбор, поиск и анализ данных журналов. CloudWatch Alarms: запуск уведомлений или автомасштабирования по порогам метрик. CloudWatch Dashboards: визуализация метрик.

Ключевые концепции: измерения метрик (dimensions), сроки хранения, группы и потоки журналов, фильтры метрик, CloudWatch Agent (для метрик и журналов уровня ОС с EC2), Container Insights.

---

**CloudTrail** *(упоминается на протяжении всей книги)*

Журналирует каждый вызов API в вашем аккаунте AWS: кто его сделал, откуда, когда и каким был ответ. Мультирегиональный trail хранит журналы в S3 бессрочно. Используется для аудита безопасности, соответствия требованиям и расследования инцидентов.

Признак в экзамене: «Кто удалил этот ресурс?», «Аудит всей активности API» → CloudTrail.

---

**X-Ray** *(Глава 20)*

Распределённая трассировка: отслеживает отдельные запросы между сервисами (трассы → сегменты → подсегменты), строит карту сервисов с задержкой и частотой ошибок на каждом переходе. Сэмплирование удерживает накладные расходы низкими; аннотации делают трассы доступными для поиска. Активная трассировка включается на этапах Lambda и API Gateway.

Признак в экзамене: «трассировать запросы между микросервисами», «найти узкое место между сервисами» → X-Ray (не CloudWatch, не CloudTrail).

---

**AWS Config** *(упоминается в главе 31)*

Отслеживает изменения конфигурации ресурсов во времени. Оценивает ресурсы на соответствие правилам комплаенса. Записывает историю каждого изменения конфигурации для каждого ресурса. Интегрируется с Systems Manager для исправления.

Признак в экзамене: «Соответствует ли этот ресурс нашей политике безопасности?», «Как выглядела конфигурация этого ресурса на прошлой неделе?» → AWS Config.
