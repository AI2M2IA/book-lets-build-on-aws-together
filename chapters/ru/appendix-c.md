# Приложение C: Реестр концепций

Каждая ключевая концепция, введённая в книге, сопоставлена с её главой, использованной аналогией и доменом SAA-C03, в котором она встречается.

Используйте это как учебный индекс: если перед экзаменом вы не уверены в какой-либо концепции, найдите её здесь и вернитесь к её главе за контекстом.

---

## A

**ACM (AWS Certificate Manager)** — бесплатные публичные сертификаты TLS для ALB, CloudFront и API Gateway с автоматическим продлением через DNS-валидацию. Сертификаты CloudFront должны находиться в us-east-1. Глава 16. Домен 1.

**ACU (Aurora Capacity Unit)** — единица измерения ёмкости Aurora Serverless v2. Масштабируется автоматически и на поддерживаемых версиях движка может автоматически приостанавливаться до 0 ACU, когда нет открытых соединений. Глава 24. Домен 3.

**Alarm (CloudWatch)** — правило, срабатывающее при пересечении метрикой порога, запускающее уведомление или действие автомасштабирования. Глава 7. Домен 2.

**ALB (Application Load Balancer)** — балансировщик нагрузки уровня 7, маршрутизирующий трафик HTTP/HTTPS на основе правил пути и хоста. Глава 7. Домен 2.

**AMI (Amazon Machine Image)** — шаблон, содержащий ОС, ПО и конфигурацию для инстанса EC2. Глава 4. Домен 3.

**Мышление архитектора (Architect mindset)** — задавать вопрос «что ломается первым, как мы об этом узнаём и что делает человек в 3 часа ночи?», а не только «как это работает?». Глава 32, Глава 34. Межтематическая.

**Architecture Decision Record (ADR)** — короткий документ, фиксирующий решение, его альтернативы, обоснование и то, что заставит пересмотреть его. Глава 32. Межтематическая.

**Обзор архитектуры (Architecture review)** — структурированный процесс: ограничения → неизвестные → варианты → режимы отказа → мониторинг → runbook'и. Глава 32. Межтематическая.

**Athena** — бессерверный сервис SQL-запросов к данным в S3. Оплата за просканированный ТБ. Лучше всего с колоночными форматами Parquet/ORC. Глава 26. Домен 3.

**Auto Scaling Group (ASG)** — группа инстансов EC2, управляемых вместе, автоматически заменяющая неисправные инстансы и масштабирующаяся по нагрузке. Глава 7. Домены 2, 3.

**Availability Zone (AZ)** — один или несколько физически отдельных дата-центров внутри региона, соединённых каналами с низкой задержкой. Глава 2. Домен 2.

## B

**AWS Backup** — централизованное, основанное на политиках резервное копирование для EBS, RDS, DynamoDB, EFS и Storage Gateway. Поддерживает межрегиональные и межаккаунтные копии. Главы 18, 23. Домен 2.

**AWS Batch** — управляемые пакетные вычисления для контейнеров Docker. Состоит из определения задания (что запускать), очереди заданий (где задания ожидают) и вычислительной среды (EC2 или Fargate, On-Demand или Spot). Для нагрузок, превышающих 15-минутный лимит Lambda. Глава 21. Домен 3.

**Bucket (S3)** — контейнер для объектов S3. Бакеты имеют уникальные глобальные имена и находятся в конкретном регионе. Глава 5. Домен 3.

**Политика бакета (Bucket policy)** — ресурсная политика, прикреплённая к бакету S3, контролирующая доступ для принципалов IAM и внешних аккаунтов. Глава 5. Домен 1.

## C

**Паттерн cache-aside** — приложение сначала проверяет кэш; при промахе запрашивает базу данных, затем сохраняет результат в кэш. Глава 10. Домен 3.

**Коэффициент попаданий в кэш (Cache hit rate)** — процент запросов, обслуженных из кэша, а не из источника. Чем выше, тем лучше. Глава 13. Домен 3.

**AWS Client VPN** — управляемая конечная точка OpenVPN. Подключает отдельные устройства (ноутбуки, рабочие станции) к VPC через интернет. Аутентификация через Active Directory, федерацию SAML 2.0 с поставщиком идентификации или взаимный TLS. Поддерживает режимы split-tunnel и full-tunnel. Контраст с Site-to-Site VPN (сеть-к-сети). Глава 11. Домен 1.

**CloudFront** — CDN от AWS. Кэширует контент в 750+ граничных локациях по всему миру. Снижает задержку и затраты на передачу данных из источника. Глава 13. Домены 3, 4.

**CloudTrail** — журналирует каждый вызов API AWS: кто, что, когда, откуда. Хранится в S3. Используется для аудита и расследования инцидентов. Домен 1.

**CloudWatch** — метрики, журналы, алармы и дашборды для ресурсов AWS и пользовательских приложений. Упоминается на протяжении всей книги. Все домены.

**Amazon Cognito** — аутентификация для конечных пользователей вашего приложения: User Pools — это управляемый каталог пользователей (регистрация, вход, MFA, вход через соцсети, JWT); Identity Pools выдают временные учётные данные AWS. IAM — для ваших инженеров; Cognito — для ваших клиентов. Глава 14. Домен 1.

**Холодный старт (Cold start, Lambda)** — задержка при первом вызове (или после простоя), пока Lambda инициализирует среду выполнения. Используйте предоставленный параллелизм для устранения. Глава 20. Домен 3.

**Compute Savings Plan** — обязательство по сумме почасовых расходов на EC2 в долларах, применяемое к любому типу или размеру инстанса. Глава 27. Домен 4.

**Config (AWS)** — отслеживает изменения конфигурации ресурсов AWS во времени и оценивает соответствие правилам. Глава 31. Домен 1.

**AWS Control Tower** — автоматизирует управление многоаккаунтной средой: строит landing zone (аккаунты управления, архива журналов и аудита) с ограничителями за минуты — готовый вариант ручной настройки Organizations, CloudTrail и Config. Глава 14. Домен 1.

**Передача данных между AZ (Cross-AZ data transfer)** — трафик между зонами доступности внутри региона. Тарифицируется по $0,01/ГБ в каждом направлении. Глава 30. Домен 4.

**Межрегиональная репликация (Cross-region replication)** — копирование данных (S3 CRR, Aurora Global, DynamoDB Global Tables) в другой регион. Влечёт плату за передачу данных. Главы 18, 23, 30. Домен 2.

## D

**AWS DataSync** — миграция и синхронизация общих файловых ресурсов (NFS/SMB) в S3, EFS или FSx на основе агента. «rsync на стероидах, с консолью AWS». Глава 25. Домен 3.

**DAX (DynamoDB Accelerator)** — кэш в памяти специально для DynamoDB. Микросекундная задержка чтения. Глава 9. Домен 3.

**Dead Letter Queue (DLQ)** — очередь, куда отправляются повторно сбоящие при обработке сообщения, предотвращая блокировку очереди. Глава 19. Домен 2.

**AWS DMS (Database Migration Service)** — переносит базы данных в AWS с минимальным простоем. Полная загрузка (первоначальная копия) плюс CDC (Change Data Capture) синхронизирует источник и приёмник во время миграции. Гомогенные миграции (тот же тип движка): используйте DMS напрямую. Гетерогенные миграции (разные типы движков, например Oracle → Aurora PostgreSQL): сначала используйте SCT (Schema Conversion Tool), затем DMS. Глава 8. Домен 3.

**Dedicated Host** — физический сервер EC2, зарезервированный исключительно для вашего использования. Требуется для некоторых лицензий ПО. Глава 27. Домен 4.

**Эшелонированная защита (Defense in depth)** — наслоение нескольких средств контроля безопасности (IAM + группы безопасности + NACL + WAF + GuardDuty), чтобы компрометация одного слоя не раскрывала систему. Глава 33. Домен 1.

**Direct Connect** — выделенное приватное сетевое соединение от локальной площадки до AWS. Более стабильное, чем VPN. Глава 25. Домен 3.

**DLQ** — см. Dead Letter Queue.

**DynamoDB** — полностью управляемая база данных NoSQL с задержкой в единицы миллисекунд при любом масштабе. Модель «ключ-значение» и документная. Глава 9. Домен 3.

**DynamoDB Auto Scaling** — автоматически регулирует выделенную ёмкость чтения/записи на основе метрик CloudWatch. Глава 29. Домен 4.

**DynamoDB Streams** — упорядоченный по времени журнал изменений всех элементов таблицы DynamoDB. Используется с Lambda для событийно-ориентированной обработки. Глава 9. Домен 2.

## E

**EBS (Elastic Block Store)** — блочное хранилище, подключённое к одному инстансу EC2. Сохраняется независимо. Типы: gp3, io2, st1. Глава 6. Домен 3.

**EC2 (Elastic Compute Cloud)** — виртуальные машины в облаке. Глава 4. Домен 3.

**ECS (Elastic Container Service)** — управляемая оркестрация контейнеров. Тип запуска Fargate устраняет управление серверами. Глава 21. Домены 2, 3.

**EFS (Elastic File System)** — общая файловая система NFS, доступная с нескольких инстансов EC2. Масштабируется автоматически. Классы хранения включают Standard, Infrequent Access и Archive, с Intelligent-Tiering для автоматического перемещения между уровнями. Глава 6. Домен 3.

**EKS (Elastic Kubernetes Service)** — управляемая плоскость управления Kubernetes в AWS. Глава 21. Домен 3.

**Elastic Disaster Recovery (DRS)** — непрерывная репликация серверов (локальных или EC2) на уровне блоков в недорогую промежуточную область, с запуском инстансов восстановления за минуты — управляемый pilot light. Глава 18. Домен 2.

**ElastiCache** — управляемое кэширование в памяти. Redis (богаче возможностями) или Memcached (проще). Глава 10. Домен 3.

**Elastic IP** — статический публичный IP-адрес, который можно выделить и переассоциировать с инстансами EC2. Глава 11. Домен 3.

**Конвертное шифрование (Envelope encryption)** — паттерн, при котором данные шифруются ключом данных (DEK), а DEK шифруется мастер-ключом (CMK в KMS). Глава 16. Домен 1.

**EventBridge** — шина событий для маршрутизации событий от сервисов AWS, SaaS-партнёров и пользовательских источников к целям. Поддерживает запланированные правила. Глава 22. Домен 2.

**Явный deny (Explicit deny)** — оператор deny в IAM, который не может быть переопределён никаким allow. Имеет приоритет над всеми allow. Глава 3. Домен 1.

## F

**Маршрутизация failover (Route 53)** — направляет трафик на вторичную конечную точку, когда первичная не проходит проверки работоспособности. Глава 12. Домен 2.

**Fargate** — бессерверный вычислительный движок для ECS и EKS. Инстансами EC2 управлять не нужно. Глава 21. Домен 3.

**Паттерн fan-out** — один топик SNS доставляет одно и то же сообщение в несколько очередей SQS одновременно. Глава 19. Домен 2.

**Очередь FIFO (SQS)** — обработка ровно один раз, строгий порядок. Более низкая пропускная способность, чем у стандартных очередей. Глава 19. Домен 2.

**Режим отказа (Failure mode)** — конкретный способ, которым система может отказать. Выявление режимов отказа до продакшена — ядро обзора архитектуры. Глава 32. Межтематическая.

## G

**Gateway Endpoint** — бесплатный тип VPC endpoint для S3 и DynamoDB. Маршрутизирует трафик через приватную сеть AWS, устраняя плату за NAT Gateway. Глава 30. Домен 4.

**Gateway Load Balancer (GWLB)** — балансировщик нагрузки уровня 3 для встраивания сторонних виртуальных сетевых устройств (файрволы, IDS/IPS) в потоки трафика. Глава 7. Домен 1.

**Маршрутизация geolocation (Route 53)** — маршрутизирует на основе географического местоположения источника DNS-запроса. Глава 12. Домен 3.

**Global Accelerator** — маршрутизирует трафик к ближайшей границе AWS через Anycast, улучшая задержку для динамических приложений. Глава 25. Домен 3.

**Glue (AWS)** — бессерверный ETL. Glue Crawlers обнаруживают схему; Glue Jobs преобразуют данные; Data Catalog хранит метаданные. Глава 26. Домен 3.

**GSI (Global Secondary Index)** — альтернативный индекс таблицы DynamoDB с другим ключом раздела и опциональным ключом сортировки. Обеспечивает гибкие паттерны запросов. Глава 9. Домен 3.

**GuardDuty** — сервис обнаружения угроз, использующий ML для журналов CloudTrail, VPC Flow Logs и DNS для обнаружения необычной активности. Глава 17. Домен 1.

## H

**Проверка работоспособности (Health check, Route 53)** — отслеживает доступность конечной точки. Неудачные проверки запускают маршрутизацию failover. Глава 12. Домен 2.

**Горячий раздел (Hot partition, DynamoDB)** — раздел, получающий непропорциональный трафик из-за того, что многие запросы используют один и тот же ключ раздела. Глава 9. Домен 3.

## I

**IAM (Identity and Access Management)** — контролирует аутентификацию и авторизацию для аккаунтов AWS. Пользователи, группы, роли, политики. Главы 3, 14. Домен 1.

**IAM-роль (IAM role)** — идентичность IAM с временными учётными данными, принимаемая сервисами, пользователями или другими аккаунтами. Главы 3, 14. Домен 1.

**Идемпотентность (Idempotency)** — свойство операции давать одинаковый результат при вызове один или много раз. Критично для распределённых систем (возвраты, платежи, обработка заказов). Глава 32. Межтематическая.

**Ключ идемпотентности (Idempotency key)** — уникальный идентификатор операции, проверяемый перед выполнением для предотвращения дублирующей обработки. Глава 32. Межтематическая.

**Interface Endpoint (PrivateLink)** — VPC endpoint для большинства сервисов AWS. Тарифицируется за час + за ГБ. Обеспечивает приватное соединение без интернета или NAT. Глава 30. Домен 4.

**Internet Gateway (IGW)** — позволяет инстансам в публичных подсетях связываться с интернетом. Требует, чтобы таблица маршрутизации подсети имела маршрут к IGW. Глава 11. Домен 3.

**«Это зависит» («It depends»)** — честный ответ на большинство архитектурных вопросов, который всегда нужно завершить: «Это зависит от паттерна доступа / масштаба / последствий отказа / ограничения по стоимости». Глава 33. Межтематическая.

## K

**Kinesis Data Firehose** — прежнее название Amazon Data Firehose: управляемая доставка потоковых данных в S3, Redshift, OpenSearch. Без управления потребителями. Более старые экзаменационные вопросы могут всё ещё использовать старое название. Глава 26. Домен 3.

**Kinesis Data Streams** — упорядоченный поток событий в реальном времени. Долговечный, воспроизводимый в пределах окна хранения (24 часа по умолчанию, до 365 дней). Измеряется в шардах. Глава 26. Домен 3.

**KMS (Key Management Service)** — создаёт, хранит и контролирует криптографические ключи для шифрования в покое. Глава 16. Домен 1.

## L

**Lambda** — бессерверные функции, запускаемые событиями. Оплата за вызов и за мс. Максимальная длительность 15 минут. Глава 20. Домены 2, 3, 4.

**Lambda@Edge** — функции Lambda, выполняющиеся в граничных локациях CloudFront, изменяющие запросы и ответы. Глава 13. Домен 3.

**AWS Lake Formation** — централизованный уровень контроля доступа к озеру данных поверх S3 и Glue Data Catalog. Предоставляет точечные разрешения на уровне таблиц, столбцов и строк. Упрощает настройку безопасного озера данных. Глава 26. Домен 3.

**Маршрутизация по задержке (Latency-based routing, Route 53)** — маршрутизирует DNS-запросы в регион AWS с наименьшей измеренной задержкой. Глава 12. Домен 3.

**Шаблон запуска (Launch template)** — версионированный шаблон, задающий конфигурацию инстанса EC2 для Auto Scaling Groups. Глава 7. Домен 3.

**Минимальные привилегии (Least privilege)** — лучшая практика IAM: предоставлять только необходимые разрешения, не более. Глава 3. Домен 1.

**Политика жизненного цикла (Lifecycle policy, S3)** — правила, автоматически переводящие объекты в более дешёвые классы хранения или удаляющие их по возрасту. Глава 23. Домен 4.

**LSI (Local Secondary Index)** — альтернативный индекс таблицы DynamoDB, использующий тот же ключ раздела, но другой ключ сортировки. Должен быть создан при создании таблицы. Глава 9. Домен 3.

## M

**Amazon Macie** — обнаружение чувствительных данных (ПД) в S3 на основе ML и пометка рисков раскрытия. GuardDuty следит за поведением; Macie проверяет, что хранится. Глава 17. Домен 1.

**Memcached** — простой, многопоточный движок кэширования в памяти. Без сохранения, без структур данных. Используйте Redis, если только вам специально не нужна многопоточность ценой возможностей. Глава 10. Домен 3.

**Amazon MemoryDB for Redis** — долговечная, Redis-совместимая первичная база данных в памяти. В отличие от ElastiCache, MemoryDB пишет в журнал транзакций Multi-AZ, гарантируя долговечность данных. Используйте, когда требуется совместимость с Redis API И потеря данных недопустима. Глава 10. Домен 3.

**MGN (AWS Application Migration Service)** — rehost/lift-and-shift: репликация целых серверов на уровне блоков в AWS, тестовые запуски, затем переключение на нативные инстансы EC2. DataSync перемещает файлы; DMS перемещает базы данных; MGN перемещает серверы. Глава 25. Домен 3.

**Amazon MQ** — управляемый брокер ActiveMQ/RabbitMQ, говорящий на стандартных протоколах (AMQP, MQTT, STOMP). Для lift-and-shift существующих нагрузок брокера без изменения кода; новый обмен сообщениями → SQS/SNS. Глава 19. Домен 2.

**Multi-AZ (RDS)** — синхронная резервная реплика в другой AZ с автоматическим переключением при сбое. RPO ~0, RTO ~60 секунд. Для высокой доступности, не для масштабирования чтения. Главы 8, 18. Домен 2.

**Multi-Region** — развёртывание компонентов приложения в нескольких регионах AWS для географической избыточности и глобальной производительности. Выше сложность и стоимость. Глава 18. Домен 2.

---

## N

**Network Load Balancer (NLB)** — балансировщик нагрузки уровня 4 (TCP/UDP/TLS): миллионы запросов в секунду, статический IP на AZ, сохраняет исходный IP. Без понимания HTTP — это работа ALB. Глава 7. Домен 3.

**NACL (Network Access Control List)** — файрвол без состояния на уровне подсети. Требует как входящих, так и исходящих правил. Правила оцениваются в числовом порядке. Глава 15. Домен 1.

**NAT Gateway** — позволяет инстансам в приватных подсетях устанавливать исходящие соединения с интернетом. Тарифицируется по $0,045/ГБ обработанного трафика. Главы 11, 30. Домен 4.

---

## O

**Object (S3)** — файл, хранящийся в S3. Состоит из ключа (имя), значения (данные) и метаданных. Максимальный размер 5 ТБ. Глава 5. Домен 3.

**On-Demand ёмкость (DynamoDB)** — режим оплаты за запрос. Дороже за запрос, чем provisioned, но не требует планирования ёмкости. Глава 29. Домен 4.

**On-Demand инстансы (EC2)** — оплата за час без обязательств. Максимальная гибкость, максимальная цена. Глава 27. Домен 4.

**AWS Outposts** — полностью управляемая стойка оборудования AWS, установленная в собственном дата-центре клиента или в колокейшн-помещении. Запускает те же сервисы, API и инструменты AWS, что и публичное облако, на ваших площадках. AWS управляет установкой и обновлениями; клиент предоставляет место в стойке и питание. Для резидентности данных, локальных нагрузок с низкой задержкой или отключённых сценариев. Глава 2. Домен 4.

---

## P

**Ключ раздела (Partition key, DynamoDB)** — компонент первичного ключа, определяющий, какой раздел хранит элемент. Выбирайте ключ высокой кардинальности для равномерного распределения. Глава 9. Домен 3.

**Граница разрешений (Permission boundary)** — политика IAM, задающая максимальные разрешения, которые может иметь идентичность IAM, даже если другие политики предоставляют больше. Глава 14. Домен 1.

**Группа размещения (Placement group)** — контролирует физическое размещение инстансов EC2 для минимизации задержки (cluster) или максимизации доступности (spread). Глава 4. Домен 3.

**PrivateLink** — сервис AWS для создания приватных конечных точек к сервисам, размещённым в AWS, доступным через Interface Endpoints. Глава 30. Домен 1.

**Предоставленный параллелизм (Provisioned concurrency, Lambda)** — предварительно инициализированные среды выполнения, устраняющие задержки холодного старта. Глава 20. Домен 3.

**Provisioned ёмкость (DynamoDB)** — предварительно выделенная пропускная способность чтения и записи, измеряемая в единицах ёмкости в секунду. Дешевле on-demand для предсказуемого трафика. Главы 9, 29. Домен 4.

---

## Q

**Amazon QuickSight** — управляемый сервис бизнес-аналитики и визуализации данных. Использует SPICE (Super-fast, Parallel, In-memory Calculation Engine) для кэширования данных ради быстрой отрисовки дашбордов. Подключается к Athena, S3, Redshift, RDS и другим источникам данных AWS. Сервером BI управлять не нужно. Глава 26. Домен 3.

---

## R

**RDS (Relational Database Service)** — управляемая реляционная база данных. Берёт на себя резервное копирование, обновления, переключение при сбое. Глава 8. Домен 3.

**RDS Proxy** — управляет пулом соединений между Lambda/приложением и RDS, предотвращая исчерпание соединений. Глава 8. Домен 3.

**Read Replica (RDS)** — асинхронная копия базы данных для масштабирования чтения. НЕ обеспечивает автоматическое переключение при сбое. Главы 8, 24. Домен 3.

**Redis** — хранилище структур данных в памяти, используемое для кэширования, управления сессиями, таблиц лидеров в реальном времени, pub/sub. Глава 10. Домен 3.

**Reserved Instance (EC2)** — обязательство использовать конкретный тип инстанса в конкретном регионе в течение 1 или 3 лет в обмен на скидку. Глава 27. Домен 4.

**Route 53** — сервис DNS и регистратор доменов AWS. Поддерживает несколько политик маршрутизации. Глава 12. Домены 2, 3.

**RPO (Recovery Point Objective)** — максимально допустимая потеря данных, измеряемая во времени. «Сколько данных мы можем позволить себе потерять?» Глава 18. Домен 2.

**RTO (Recovery Time Objective)** — максимально допустимое время восстановления сервиса после сбоя. «Как долго мы можем быть недоступны?» Глава 18. Домен 2.

**Runbook** — пошаговые инструкции по эксплуатации системы, в частности для реагирования на инциденты. «Что делает человек в 3 часа ночи?» Глава 32. Межтематическая.

---

## S

**S3 Intelligent-Tiering** — автоматически перемещает объекты S3 между уровнями доступа на основе паттернов доступа. Без платы за извлечение. Глава 23. Домен 4.

**S3 Select** — извлекает подмножество содержимого объекта S3 с помощью SQL-выражений, снижая передачу данных. Legacy: недоступен для новых клиентов с середины 2024 года — Athena теперь основной путь для фильтрации и запросов данных в S3. S3 Object Lambda, когда-то предлагавшийся как альтернатива, сам стал legacy (закрыт для новых клиентов в ноябре 2025; существующие нагрузки продолжают работать). Глава 30. Домен 4.

**Savings Plan** — гибкая модель ценообразования с обязательством по сумме почасовых расходов в долларах в обмен на скидку. Более гибкая, чем Reserved Instances. Глава 27. Домен 4.

**SCP (Service Control Policy)** — политика AWS Organizations, ограничивающая максимальные разрешения, доступные аккаунтам в OU. Глава 14. Домен 1.

**Secrets Manager** — хранит и автоматически ротирует секреты (пароли баз данных, ключи API). Глава 16. Домен 1.

**Группа безопасности (Security group)** — виртуальный файрвол с состоянием на уровне инстанса. Только правила allow; обратный трафик автоматический. Глава 15. Домен 1.

**Shard (Kinesis)** — базовая единица пропускной способности в Kinesis Data Streams: 1 МБ/с на запись, 2 МБ/с на чтение. Глава 26. Домен 3.

**Модель разделённой ответственности (Shared Responsibility Model)** — AWS отвечает за безопасность *самого* облака (инфраструктура); вы отвечаете за безопасность *внутри* облака (данные, конфигурация, доступ). Глава 1. Домен 1.

**Shield** — защита от DDoS. Standard: бесплатно, автоматично. Advanced: платно, с поддержкой DRT и финансовой защитой. Глава 17. Домен 1.

**Snow Family** — физические устройства для офлайн массовой передачи данных (Snowball Edge: 80 ТБ) — фрахт грузового рейса вместо поездки по шоссе. Legacy (2026): Snowmobile и Snowcone прекращены; устройства Snow закрыты для новых клиентов в ноябре 2025 (AWS рекомендует DataSync и Data Transfer Terminals), но экзамен SAA-C03 всё ещё ожидает Snowball для «недель передачи, ограниченной пропускной способности». Глава 25. Домен 3.

**SNS (Simple Notification Service)** — обмен сообщениями pub/sub. Отправляет сообщения всем подписчикам одновременно. Паттерн fan-out. Глава 19. Домен 2.

**Ключ сортировки (Sort key, DynamoDB)** — опциональный второй компонент первичного ключа. Обеспечивает запросы по диапазону внутри раздела. Глава 9. Домен 3.

**Spot Instances** — инстансы EC2, использующие свободные мощности со скидкой 60–90 %. Могут быть прерваны с уведомлением за 2 минуты. Только для отказоустойчивых нагрузок. Глава 27. Домен 4.

**SQS (Simple Queue Service)** — управляемая очередь сообщений. Развязывает производителей от потребителей. Очереди Standard (не менее одного раза) и FIFO (ровно один раз). Глава 19. Домен 2.

**Step Functions** — бессерверный сервис оркестрации рабочих процессов. Конечные автоматы для координации сервисов AWS. Глава 22. Домен 2.

**AWS Storage Gateway** — мост между локальным и облачным хранилищем: предоставляет интерфейсы NFS/SMB (File), iSCSI (Volume) или виртуальную ленту (Tape) локально, сохраняя данные в S3, Glacier или снимках EBS. Глава 6. Домен 3.

---

## T

**Масштабирование с целевым отслеживанием (Target tracking scaling)** — политика Auto Scaling, регулирующая ёмкость для поддержания целевого значения метрики (например, 60 % загрузки CPU). Глава 7. Домен 2.

**AWS Transfer Family** — управляемая конечная точка SFTP/FTPS/FTP на базе S3 или EFS. Партнёры сохраняют свои существующие клиенты SFTP; файлы попадают прямо в ваш бакет. Глава 25. Домен 3.

**Transit Gateway** — топология сети «звезда», соединяющая несколько VPC и локальных сетей через центральный шлюз. Глава 25. Домен 3.

**TTL (Time to Live)** — отметка времени, после которой DynamoDB автоматически удаляет элемент. Также используется в DNS (как долго резолверы кэшируют запись) и кэшировании (как долго кэшированное значение действительно). Главы 9, 12. Домен 3.

---

## V

**VIF (Virtual Interface)** — логическое соединение, используемое с AWS Direct Connect. Public VIF обращается к публичным конечным точкам AWS; Private VIF обращается к ресурсам VPC. Глава 25. Домен 3.

**Тайм-аут видимости (Visibility timeout, SQS)** — период, в течение которого полученное сообщение скрыто от других потребителей. Позволяет обрабатывать, не давая другим потребителям видеть то же сообщение. Глава 19. Домен 2.

**VPC (Virtual Private Cloud)** — изолированная виртуальная сеть в AWS. Содержит подсети, таблицы маршрутизации и шлюзы. Глава 11. Домен 1.

**VPC Endpoint** — соединяет ресурсы VPC с сервисами AWS через приватную сеть AWS. Gateway (бесплатно, S3/DynamoDB) и Interface (тарифицируется, большинство других сервисов). Глава 30. Домены 1, 4.

**VPC Flow Logs** — захватывает информацию об IP-трафике, идущем к сетевым интерфейсам VPC и от них. Используется GuardDuty и для устранения сетевых неполадок. Глава 17. Домен 1.

**VPC Peering** — сетевое соединение между двумя VPC, позволяющее трафику маршрутизироваться между ними по приватным IP-адресам. Глава 11. Домен 3.

---

## W

**WAF (Web Application Firewall)** — фильтрует трафик HTTP/HTTPS по правилам (блокировки IP, SQL-инъекции, ограничения частоты). Подключается к CloudFront, ALB или API Gateway. Глава 17. Домен 1.

**AWS Wavelength** — инфраструктура AWS, развёрнутая внутри сетей операторов 5G на радиогранице. Обеспечивает задержку в единицы миллисекунд до мобильных устройств. Для мобильных AR/VR, игр в реальном времени, телеметрии беспилотных автомобилей и живого видео на границе 5G. Wavelength Zones — расширения регионов AWS внутри сетей операторов. Глава 2. Домен 3.

**Well-Architected Framework** — фреймворк оценки AWS из шести столпов: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability. Глава 31. Межтематическая.

**Взвешенная маршрутизация (Weighted routing, Route 53)** — распределяет DNS-запросы между конечными точками по весу. Используется для blue-green развёртываний и A/B-тестирования. Глава 12. Домен 3.

**Кэширование write-through** — обновляет кэш при каждом обновлении базы данных. Данные всегда согласованы, но кэш может содержать много элементов, которые никогда не перечитываются. Глава 10. Домен 3.
