# פרק 6: הדיסק שעוקב אחריך

ל-Tom היה עט אדום והרגל שהעצביר את Leo.

כל שבת בבוקר, Tom הדפיס את סיכום מסוף AWS — מכונות פועלות, כרכי אחסון, דיסקים מחוברים — ועבר עליהם שורה אחר שורה. הוא עשה זאת מאז שבוע שני. הוא קרא לזה "הפנקס". Leo קרא לזה "הדבר שTom עושה שגורם ל-Leo להרגיש שעשה משהו לא בסדר."

אותה שבת, Tom הקיף משהו ועזב את הפריסה על שולחנה של Maya ללא מילה.

היא מצאה אותה ביום שני בבוקר. עיגול אחד. הערה בשוליים, שלוש מילים:

*הכל. מכונה אחת.*

שרת האינטרנט. מסד הנתונים. כל רשומות הלקוחות. שני חודשים של היסטוריית הזמנות. כולם רצים על מכונת EC2 בודדת.

"מה קורה למסד הנתונים אם המכונה מתרסקת?" שאלה Maya, הפריסה בידה.

"הוא מתרסק גם," אמר Leo.

"והנתונים?"

"תלוי באופן שבו מסד הנתונים מאחסן אותם."

ה"תלוי" הזה היה הבעיה.

**כיצד מכונות EC2 מאחסנות נתונים**

כשמכונת EC2 פועלת, מערכת ההפעלה שלה גרה איפשהו על דיסק. הדיסק הזה נקרא **כרך השורש**. כברירת מחדל, זהו **כרך EBS** — גם כשלא חושבים על כך.

אבל יש עוד משהו: למכונות EC2 יש גם אחסון **instance store**.

instance store הוא אחסון זמני המחובר פיזית לחומרה הבסיסית שמריצה את המכונה הוירטואלית שלכם. הוא מהיר מאוד — מהיר יותר מכמעט כל אפשרות אחסון אחרת ב-AWS. אבל יש לו מלכוד.

instance store הוא **ארעי**.

כשהמכונה נעצרת או מסיימת, נתוני instance store נעלמים. לצמיתות. לא ניתן לשחזרם. AWS אינה מאזהירה אתכם בקול רם על כך, וכך צוותים מגלים זאת: על ידי איבוד נתונים.

instance store מתאים למטמונים, קבצי עיבוד זמניים ושטח מחיקה. לעולם לא לנתונים שאתם אכפת לכם מהם.

**EBS: הדיסק העמיד**

**Amazon EBS** — Elastic Block Store — הוא אחסון בלוקים עמיד למכונות EC2.

אחסון בלוקים אומר שהוא מתנהג כמו כונן קשיח אמיתי: מערכת ההפעלה שלכם יכולה ליצור עליו מערכות קבצים, לקרוא ולכתוב בתים שרירותיים במיקומים שרירותיים, להריץ מסדי נתונים עליו, ולהתייחס אליו בדיוק כמו דיסק מחובר.

המאפיינים המרכזיים:

**עמיד.** בשונה מ-instance store, כרכי EBS שורדים עצירות, הפעלות מחדש ואפילו סיומי מכונה (בהתאם להגדרות). הנתונים נשארים על הכרך גם כשאף מכונה אינה משתמשת בו.

**ניתן לחיבור ולנתוק.** כרך EBS יכול להינתק ממכונה אחת ולהתחבר לאחרת. אם אתם צריכים להעביר נתונים או להתאושש ממכונה כושלת, אתם יכולים לנתק את הכרך ולחבר אותו מחדש במקום אחר.

**חיבור בודד (בדרך כלל).** כברירת מחדל, כרך EBS מחובר למכונת EC2 אחת בכל פעם. מכונה בודדת יכולה להיות עם כרכי EBS מרובים, אבל כרך EBS בודד לא יכול להיות מורכב בו זמנית על ידי מכונות מרובות (עם יוצא מן הכלל אחד: EBS Multi-Attach, שיש לו שימושים מוגבלים והגבלות חשובות).

האנלוגיה: EBS הוא כונן קשיח חיצוני שמחברים למחשב נייד. המחשב הנייד (מכונת EC2) יכול לקרוא ולכתוב אליו. כשסיימתם, תוכלו לנתק אותו ולחבר אותו למחשב נייד אחר.

**סוגי כרכי EBS**

לא כל כרכי EBS זהים. AWS מציעה מספר סוגים עם פרופילי ביצועים ועלויות שונים.

**gp3 (SSD כללי)**: ברירת המחדל לרוב עומסי העבודה. איזון טוב של ביצועים ומחיר.

**io2 (IOPS SSD מופרש)**: אפשרות ביצועים גבוהים לעומסי עבודה עתירי I/O. אתם מציינים כמה פעולות I/O לשנייה (IOPS) אתם צריכים, ו-AWS מבטיח ביצועים אלו.

**st1 (HDD ממוטב לתפוקה)**: אחסון מגנטי ממוטב לקריאות וכתיבות רצופות גדולות.

**sc1 (HDD קר)**: האפשרות הזולה ביותר של EBS. לנתונים בגישה לא תכופה.

**תמונות EBS: הגיבוי**

**תמונת EBS** היא גיבוי בזמן נקודה של כרך EBS, המאוחסנת ב-S3. תמונות הן תוספתיות: התמונה הראשונה לוכדת את הכרך המלא; תמונות עוקבות מאחסנות רק מה שהשתנה מאז האחרונה.

אתם יכולים ליצור כרך EBS חדש מתמונה — לשחזר לנקודה בזמן לפני שחיתות מסד נתונים, פריסה גרועה, או מחיקה מקרית.

אתם צריכים לבצע תמונות אוטומטיות. AWS מספק **Amazon Data Lifecycle Manager** למטרה זו: הגדירו מדיניות (צרו תמונה כל 6 שעות, שמרו 7 ימים אחרונים), וזה רץ אוטומטית.

Priya הגדירה זאת לפני שמסד הנתונים בכלל עלה לייצור.

Leo לא חשב על כך.

**EFS: ארון התיוק המשותף**

EBS הוא דיסק המחובר למכונה אחת. מה קורה אם מכונות מרובות צריכות לגשת לאותם קבצים בו זמנית?

הכנסו ל**Amazon EFS** — Elastic File System.

EFS הוא מערכת קבצים רשתית מנוהלת. מכונות EC2 מרובות יכולות לעלות את אותה מערכת קבצים EFS בו זמנית ולקרוא/לכתוב לקבצים משותפים. זוהי היכולת המרכזית ש-EBS אינה מספקת.

חשבו על זה כך:

EBS הוא כונן קשיח חיצוני המחובר למחשב נייד אחד. רק המחשב הנייד הזה יכול להשתמש בו בכל פעם.

EFS הוא ארון תיוק במרכז משרד. כל עובד יכול ללכת אליו, לפתוח מגירה, לקרוא קובץ, לשים משהו בחזרה. אנשים מרובים, בו זמנית, ניגשים לאותו אחסון.

**מתי אתם צריכים EFS?**

- כשמכונות EC2 מרובות צריכות לשתף קבצים
- כשיש לכם יישום בסקאלינג אופקי שבו כל המכונות צריכות גישה לאותם נתונים
- כשאתם צריכים מערכת קבצים עמידה השורדת כשלי מכונה

**EFS לעומת S3:** EFS היא מערכת קבצים (תיקיות, קבצים, הרשאות, נעילה). S3 הוא אחסון אובייקטים (העלאה, הורדה, ללא סמנטיקת מערכת קבצים). EFS יקרה הרבה יותר מ-S3. השתמשו ב-S3 לקבצים המאוחסנים ומאוחזרים שלמים. השתמשו ב-EFS לקבצים שיישומים קוראים ולכותבים באופן פעיל.

**בחירת האחסון הנכון**

| צורך                                      | סוג אחסון          |
|-------------------------------------------|--------------------|
| מסד נתונים זקוק לדיסק מהיר עמיד          | EBS (gp3 or io2)   |
| שרתים מרובים זקוקים לקבצים משותפים        | EFS                |
| קבצים, גיבויים, תמונות, אובייקטים גדולים | S3                 |
| שטח מחיקה זמני לחישוב                    | Instance Store     |
| ארכיונים ארוכי טווח במינימום עלות         | S3 Glacier         |

Priya הדפיסה את הטבלה הזו ותלתה אותה על הקיר.

## סיכום

- **Instance store** הוא אחסון מהיר, זמני המחובר פיזית למארח. נתונים אובדים כשהמכונה נעצרת. לשטח מחיקה בלבד.
- **EBS** (Elastic Block Store) הוא אחסון בלוקים עמיד למכונת EC2 בודדת. הוא שורד עצירות. ניתן לצלם אותו לגיבוי.
- **EFS** (Elastic File System) הוא מערכת קבצים רשתית משותפת שמכונות מרובות יכולות לעלות בו זמנית.
- התאימו את סוג האחסון לדרישה: מסד נתונים → EBS; קבצים משותפים → EFS; אובייקטים/גיבויים → S3; ארכיונים → S3 Glacier.

## עצות לבחינה

*SAA-C03 דומיין 3 — משימה 3.1 (פתרונות אחסון)*

- **כרכי EBS גרים באזור זמינות אחד.** ניתן לצרף אותם רק למכונה באותו AZ.
- **תמונות EBS הן תוספתיות ומאוחסנות ב-S3.** תמונה ראשונה מלאה; עוקבות מאחסנות רק שינויים.
- **EFS הוא חוצה-AZ.** מכונות מרובות באזורי זמינות שונים בתוך אותו אזור יכולות לעלות אותה מערכת קבצים EFS.
- **כשתרחיש אומר "יישום אינטרנט עם תוכן משותף" או "מכונות מרובות ניגשות לאותם קבצים," חשבו EFS.** כשאומר "אחסון מסד נתונים" או "דיסק עמיד לשרת אחד," חשבו EBS.
