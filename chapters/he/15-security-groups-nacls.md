# פרק 15: השומרים בשער

מפתח הפריסה הישן של הגרסה הראשונה של Nimbus עדיין היה פעיל. הוא ביצע שלוש קריאות API בשבוע שעבר. Leo לא ידע מה ביצע אותן.

Priya הורידה את יומני VPC flow — רשומות תנועת רשת שמראות כל חיבור לתוך ה-VPC ומחוצה לו.

"ביום שלישי בשעה 2:17 לפנות בוקר," אמרה, "הייתה חיבור יוצא ממכונת EC2 המריצה את ה-API הישן לכתובת IP ברומניה."

"זה לא התשתית שלנו," אמר Leo.

"לא."

"אז מישהו היה על מכונת EC2 שלנו."

"או משהו."

הם עקבו אחוריה: מפתח הפריסה הישן שימש להעלאת סקריפט קטן למכונת EC2. הסקריפט ניסה לסרוק פורטים בשרתים סמוכים. רוב הסריקות נכשלו.

"Security groups חסמו אותם," אמרה Priya. "התוקף נכנס למכונת EC2 אחת. הם לא יכלו להגיע לאחרות כי ה-security groups אפשרו תנועה רק מ-load balancer."

**שתי שכבות של אבטחת רשת**

ב-VPC, יש שני כלים ייחודיים לשליטה בתנועת רשת:

**Security Groups**: חומות אש וירטואליות המצורפות למשאבים בודדים. הם פועלים ברמת המשאב.

**NACLs (Network Access Control Lists)**: כללי חומת אש המצורפים ל-subnets. הם פועלים בגבול ה-subnet — לפני שתנועה מגיעה לכל משאב ב-subnet.

ההבנה של שניהם דורשת הבנת הבחנה קריטית אחת: **stateful לעומת stateless**.

**Stateful: Security Groups**

Security group הוא **stateful**.

כשאתם מאפשרים תנועה נכנסת על פורט ספציפי, תנועת התגובה מאופשרת אוטומטית החוצה.

כללי security group לדוגמה:

- **נכנס — TCP 8080 — מ-Load Balancer SG** → קבל תנועת API מ-ALB
- **נכנס — TCP 22 — מ-Bastion Host SG** → SSH מ-bastion בלבד
- **יוצא — TCP 5432 — ל-RDS SG** → חיבור ל-PostgreSQL

כברירת מחדל, כל תנועה נכנסת נדחית. Security groups יכולים רק **לאפשר** תנועה — לא ניתן ליצור כללי deny מפורשים.

**Stateless: NACLs**

NACL הוא **stateless**.

כשאתם מאפשרים תנועה נכנסת על פורט 8080, זה מכסה רק נכנסת. תגובה (תנועה יוצאת על פורטים אפמריים) חייבת להיות מאופשרת במפורש עם כלל יוצא.

כללי NACL ממוספרים ומוערכים בסדר. הכלל הראשון שתואם מנצח.

NACLs יכולים **לדחות** תנועה במפורש — בשונה מ-security groups שיכולים רק לאפשר.

**מתי להשתמש בכל אחד**

השתמשו ב**security groups** לשכבת בקרת גישה הראשית. השתמשו ב**NACLs** לבקרות ברמת subnet, במיוחד:

- **כללי deny מפורשים**: חסמו טווח IP ספציפי מלהגיע ל-subnet שלם.
- **חסימת חירום**: IP פעיל תוקף.

## סיכום

- **Security Groups** הם חומות אש stateful לשימוש וירטואלי למשאבים בודדים. רק כללי Allow.
- **NACLs** הם חומות אש stateless לכל ה-subnets. כללי Allow ו-Deny. כללים מוערכים בסדר מספרי.
- **Stateful** אומר שתנועת תגובה מאופשרת אוטומטית. **Stateless** אומר שצריך לאפשר תנועה בשני הכיוונים במפורש.
- כש-NACL מאפשר תנועה נכנסת, צריך גם לאפשר פורטים אפמריים יוצאים (1024-65535).

## עצות לבחינה

- **Stateful לעומת stateless**: זוהי ההבחנה הנבחנת ביותר. Security groups = stateful. NACLs = stateless.
- **כללי security group**: אין deny מפורש. כשמספר security groups מצורפים למכונה, אגודת כל הכללים חלה.
- **סדר כללי NACL**: כללים מוערכים ממספר הנמוך לגבוה. הכלל `*` בתחתית הוא ה-deny המשתמע.
- **פורטים אפמריים**: הטעות הקלאסית של NACL היא שכחת האפשרת יוצא על פורטים 1024-65535.

## סצנה לאחר הקרדיטים

האירוע היה מוכל. מפתח הפריסה שנפגע הושבת. טווח ה-IP הרומני נחסם ב-NACL.
