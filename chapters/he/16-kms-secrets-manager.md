**שתי בעיות: אחסון סודות והצפנת נתונים**

לאבטחה סביב מידע רגיש יש שתי בעיות ייחודיות:

**אחסון אישורים** (סיסמות מסד נתונים, מפתחות API, מחרוזות חיבור): איפה אלה גרים? מי יכול לגשת אליהם? כיצד מאחזרים אותם מבלי לפרוס מחדש את היישום?

**הצפנת נתונים** (מידע לקוח, רשומות תשלום, PII): כיצד מבטיחים שגם אם מישהו מקבל גישה לא מורשית למסד הנתונים או לסל S3, הוא לא יכול לקרוא את הנתונים?

ל-AWS יש שירות ייעודי לכל בעיה:

- **AWS Secrets Manager**: מאחסן ומנהל אישורים בצורה מאובטחת
- **AWS KMS (Key Management Service)**: מנהל מפתחות הצפנה

**AWS Secrets Manager**

Secrets Manager הוא חנות מאובטחת לסודות: אישורי מסד נתונים, מפתחות API, טוקני OAuth, מפתחות SSH, או כל דבר רגיש.

הנה מה שהזרימה נראית כמו:

**הדרך הישנה**:
```
DB_PASSWORD=supersecretpassword123  # בקובץ .env
```

**דרך Secrets Manager**:
```python
import boto3
client = boto3.client('secretsmanager')
secret = client.get_secret_value(SecretId='nimbus/production/db-password')
password = json.loads(secret['SecretString'])['password']
```

**סיבוב אוטומטי: הכוח האמיתי**

כל 30 יום, Secrets Manager מייצר סיסמת מסד נתונים חדשה, מעדכן אותה ב-RDS, מעדכן את הסוד המאוחסן, והיישום שלכם מאחזר את הסיסמה החדשה בפעם הבאה שהוא זקוק לה. אין התערבות ידנית.

**AWS KMS: מפעל המנעולים**

AWS KMS (Key Management Service) מנהל **מפתחות קריפטוגרפיים** — הערכים הסודיים המשמשים להצפנה ולפענוח נתונים.

**מפתחות AWS מנוהלים**: AWS יוצר ומנהל את המפתח אוטומטית עבור שירותים כמו S3, EBS, RDS. חינם.

**מפתחות לקוח מנוהלים**: אתם יוצרים את המפתח ב-KMS ושולטים בכל היבט שלו: מי יכול להשתמש בו, מתי הוא מסתובב, מי יכול לנהל אותו.

**הצפנת מעטפה: כיצד KMS עובד בפועל**

KMS לא מצפין את הנתונים שלכם ישירות ברוב המקרים. הוא משתמש ב**הצפנת מעטפה**:

1. KMS מייצר **מפתח נתונים** (מפתח סימטרי ייחודי)
2. השירות משתמש במפתח הנתונים להצפנת הנתונים שלכם מקומית
3. השירות מבקש מ-KMS להצפין את מפתח הנתונים עצמו
4. גם הנתונים המוצפנים וגם מפתח הנתונים המוצפן נשמרים

## סיכום

- לעולם אל תאחסנו אישורים בקוד, משתני סביבה, או קבצי תצורה שבוצע להם commit.
- **Secrets Manager** מאחסן אישורים בצורה מאובטחת ומסובב אותם אוטומטית.
- **KMS** מנהל מפתחות הצפנה. רוב שירותי AWS משתמשים ב-KMS להצפנה בנח.
- **הצפנת מעטפה**: KMS מצפין את המפתח, לא את הנתונים ישירות.
- **Parameter Store** היא אלטרנטיבה קלה יותר ל-Secrets Manager עבור ערכי תצורה שאינם סודות.

## עצות לבחינה

- **Secrets Manager לעומת SSM Parameter Store**: Secrets Manager לאישורים שצריכים סיבוב אוטומטי; Parameter Store לתצורה כללית.
- **מדיניות מפתח KMS**: למפתח KMS יש מדיניות מפתח משלו. מדיניות IAM לבדה לא מעניקה גישה למפתח KMS.
- **הצפנת RDS**: לא ניתן להפעיל הצפנה על מכונת RDS קיימת לא מוצפנת.
