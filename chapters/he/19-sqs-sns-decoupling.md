# פרק 19: מכונת הכרטיסים

ל-Nimbus הייתה בעיה שלא הרגישה כמו בעיה עד שהזמנות נעשו פופולריות.

בכל פעם שהוזמנה הזמנה, שרת ה-API היה צריך:

1. לשמור את ההזמנה במסד הנתונים
2. לשלוח הודעה לטאבלט של המסעדה
3. לשלוח אימייל אישור ללקוח
4. לעדכן לוח המחוונים של ניתוח המסעדה
5. לרשום את האירוע לחיוב

כל אלה היו צריכים לקרות בצורה סינכרונית לפני ש-API יכול להגיב ללקוח. אם שירות האימייל היה איטי, הלקוח חיכה. אם לוח המחוונים היה מושבת, ההזמנה נכשלה.

"אנחנו מחוברים הדוק," אמרה Priya. "אם שלב כלשהו למטה נכשל, כל ההזמנה נכשלת."

**Amazon SQS: התור**

**Amazon SQS (Simple Queue Service)** הוא שירות תור מסרים מנוהל. הוא מאחסן מסרים בצורה עמידה עד שהם מעובדים על ידי צרכן.

הזרימה הבסיסית:

1. **מפיק** (שרת ה-API) מניח מסר בתור
2. ה-API מגיב מיידית ללקוח: "הזמנה אושרה!"
3. **צרכנים** (שירותי עובד נפרדים) קוראים מסרים מהתור ומעבדים אותם

**מושגי מפתח של SQS**

**Visibility timeout**: כשצרכן קורא מסר, המסר הופך *בלתי נראה* לצרכנים אחרים. זה מבטיח מסירה פחות-פעם-אחת: כל מסר יעובד לפחות פעם אחת.

**Dead-letter queues (DLQ)**: אם מסר נכשל בעיבוד יותר מדי פעמים, SQS מעביר אותו ל-DLQ.

**סוגי תורים**:

**תורים סטנדרטיים**: תפוקה מרבית. סדר המסירה הוא ה-best-effort.

**תורי FIFO**: ראשון נכנס, ראשון יוצא קפדני. מסירה פעם אחת בדיוק. מוגבל ל-3,000 מסרים לשנייה עם batching.

**Amazon SNS: המשדר**

**Amazon SNS (Simple Notification Service)** הוא שירות מסרים פרסום/מינוי. במקום מפיק אחד, צרכן אחד, SNS תומך בהגשת מסר אחד ל*מנויים רבים* בו זמנית.

**דפוס Fan-Out SNS/SQS**

```
שרת API
    |
    | מפרסם ל
    ↓
SNS Topic: "order-placed"
    |
    |—————————————————|—————————————————|
    ↓                 ↓                 ↓
SQS Queue         SQS Queue         SQS Queue
(notifications)  (email service)   (analytics)
```

**כל תור עצמאי.** אם שירות הניתוח איטי — התור שלו מתמלא, אבל שירותי ה-notification ואימייל ממשיכים ללא הפרעה.

## סיכום

- **Decoupling** מפרידה בין רכיבים המייצרים עבודה לבין רכיבים המעבדים אותה.
- **SQS** הוא תור מנוהל. מפיקים שולחים מסרים; צרכנים קוראים ומעבדים אותם אסינכרונית.
- **SQS Standard**: תפוקה גבוהה, סדר מיטבי, מסירה פחות-פעם-אחת.
- **SQS FIFO**: סדר קפדני, מסירה פעם אחת בדיוק, תפוקה נמוכה יותר.
- **SNS** הוא שירות פרסום/מינוי. מסר אחד, מנויים רבים בו זמנית.
- **SNS + SQS fan-out**: הדפוס הסטנדרטי לאירוע אחד המפעיל צינורות עיבוד עצמאיים מרובים.
