# פרק 21: מכולות משלוח לקוד

"זה עובד על המחשב שלי."

Leo למד שלא לאמור זאת בקול. זה לא היה הגנה — זה היה אבחון. ואבחון הפעם היה מכונת EC2 ייצור מספר שלוש, שקיבלה עדכון ספרייה שישה שבועות קודם שאף אחד לא תיעד.

הוא בילה שלוש שעות אתמול בלילה עוקב אחריו.

**מה הוא Container?**

**Container** הוא יחידה קלה וניידת שאורזת את היישום שלכם יחד עם כל מה שהוא צריך להריץ: ה-runtime, הספריות, קבצי התצורה, וקוד היישום.

בשונה ממכונה וירטואלית (שמדמה מחשב שלם כולל גרעין מערכת ההפעלה), container חולק את גרעין ה-OS של המארח תוך שמירת כל שאר מבודד.

המאפיין המרכזי: **אי-שינוי**. תמונה שנבנית היום תרוץ זהה על כל מארח התומך ב-Docker. הסביבה אפויה פנימה. סחרחרת תצורה בלתי אפשרית.

**Amazon ECS: המתזמן**

**Amazon ECS (Elastic Container Service)** הוא שירות תזמור מכולות מנוהל של AWS. אתם מגדירים:

- **Task definition**: איזה תמונת container להריץ, כמה CPU וזיכרון, משתני סביבה
- **Service**: כמה עותקים של המשימה להריץ
- **Cluster**: תשתית המחשוב הבסיסית

**Fargate לעומת EC2 Launch Type**

**EC2 launch type**: אתם מנהלים את מכונות EC2 הבסיסיות.

**Fargate (serverless compute for containers)**: AWS מנהל את התשתית הבסיסית לחלוטין. אתם מציינים CPU וזיכרון לכל משימה; Fargate מספק את הקיבולת הנכונה אוטומטית.

**Amazon EKS: כשאתם צריכים Kubernetes**

**Kubernetes** הוא מערכת תזמור מכולות קוד פתוח — בעצם תקן התעשייה לניהול מכולות בקנה מידה.

**Amazon EKS (Elastic Kubernetes Service)** הוא שירות Kubernetes המנוהל של AWS.

**מתי להשתמש ב-ECS לעומת EKS?**

**השתמשו ב-ECS** אם:
- אתם בעיקר ב-AWS ורוצים חוויה פשוטה יותר
- לצוות שלכם אין מומחיות Kubernetes קיימת

**השתמשו ב-EKS** אם:
- אתם צריכים תכונות ספציפיות ל-Kubernetes
- הצוות שלכם כבר מכיר Kubernetes
- אתם מריצים סביבה היברידית

"ECS," אמרה Priya מיד. "אין לנו מומחיות Kubernetes. ECS עושה כל מה שאנחנו צריכים."

## סיכום

- **Containers** אורזים קוד יישום, runtime ותלויות — רצים זהה בכל מקום.
- **Docker** היא טכנולוגיית container סטנדרטית. תמונות הן תבניות; containers הם מופעים פועלים.
- **ECR (Elastic Container Registry)** הוא ה-registry של Docker המנוהל של AWS.
- **ECS** מתזמר containers. אתם מגדירים משימות ושירותים; ECS מנהל מיקום ומחזור חיים.
- **Fargate** הוא compute serverless ל-containers — ללא מכונות EC2 לנהל.
- **EKS** הוא Kubernetes מנוהל — לצוותים הזקוקים לאקוסיסטם Kubernetes.
- בחרו ECS לפשטות ב-AWS; בחרו EKS לתאימות אקוסיסטם Kubernetes.

## סצנה לאחר הקרדיטים

פריסת ה-container הראשונה הייתה ללא דופי.

גרסה חדשה של ה-API: אפס השבתה. ECS פרס אותה, בדיקות הבריאות עברו, משימות ישנות התנקזו, משימות חדשות השתלטו.

"זה פשוט עבד," אמר Leo.

"זה הנקודה," אמרה Priya.

"ללא SSH. ללא השבתה."

"התמונה היא ה-artifact הפריסה. הסביבה בלתי ניתנת לשינוי."

Leo בהה במסוף עוד רגע.

"בזבזתי שלוש שנים בתיאום פריסות EC2," אמר.

"היית פותר בעיה," אמרה Priya, "שמכולות פותרות בעיצוב."

בפרק הבא: תרשים זרימה שמריץ את עצמו — וזוכר היכן עצר.
