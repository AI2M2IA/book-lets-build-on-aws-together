# פרק 11: הפינה הפרטית שלך בענן

ל-Priya היה נייר עם ציור עליו.

זה לא היה ציור מסובך. מלבן, מסומן "AWS". בתוך המלבן, אשכול קופסאות: מכונות EC2, מסד נתונים RDS, אשכול ElastiCache. קווים שמחברים הכל להכל. ומחוץ למלבן, תווית בודדת: "אינטרנט".

היא שמה אותו במרכז השולחן.

"זה מה שיש לנו," אמרה. "למסד הנתונים שלנו יש כתובת IP ציבורית. שכבת המטמון שלנו ניתנת להגעה מהאינטרנט. מכונות EC2 שלנו הן כולן באותה רשת שטוחה."

"זה נשמע בסדר," אמר Leo. "יש לנו security groups."

"Security groups שאתה הגדרת," אמרה Priya. "בלילה. במהלך ההתקנה הראשונית."

Leo אמר כלום.

"כשהכל גר ברשת ציבורית שטוחה, תצורה שגויה בודדת היא ההבדל בין מערכת עובדת לאחת שנגישה לכולם באינטרנט."

**מה הוא VPC?**

**Virtual Private Cloud (VPC)** הוא חלק לוגי מבודד של ענן AWS — רשת פרטית שאתם מגדירים, שרק המשאבים שלכם יכולים לגשת אליה כברירת מחדל.

חשבו עליו כחלקה פרטית מגודרת בתוך מגרש החנייה הציבורי הגדול. לחלקה שלכם יש כללים משלה: מי יכול להיכנס, מי יכול לצאת, אילו מסלולים קיימים בין מקטעים.

כשאתם יוצרים VPC, אתם מגדירים:

**בלוק CIDR**: טווח כתובות IP הזמינות בתוך הרשת שלכם.

**Subnets**: חלוקות של ה-VPC שלכם, כל אחת עם חלק מטווח כתובות ה-IP שלכם.

**Route tables**: כללים הקובעים לאן תנועת הרשת הולכת.

**Internet Gateway**: החיבור בין ה-VPC שלכם לאינטרנט הציבורי.

**Subnets: ציבורי לעומת פרטי**

**subnet ציבורי** מחובר ל-Internet Gateway ויכול להיות עם משאבים בעלי כתובות IP ציבוריות.

**subnet פרטי** אין לו חיבור ישיר לאינטרנט. משאבים ב-subnet פרטי יכולים לתקשר רק עם משאבים אחרים ב-VPC שלכם.

עבור Nimbus, העיצוב הפך לברור:

ה-load balancer ציבורי — הוא צריך לקבל תנועה מהאינטרנט. מכונות EC2 פרטיות — הן מקבלות תנועה רק מה-load balancer. מסדי הנתונים פרטיים — הם מקבלים תנועה רק ממכונות EC2.

"אז כדי להגיע למסד הנתונים," אמר Tom, "מישהו יצטרך לעבור דרך ה-load balancer, אחר כך דרך מכונת EC2, אחר כך דרך security group של מסד הנתונים?"

"שלוש שכבות," אישרה Priya. "הגנה בעומק."

**NAT Gateway: Subnets פרטיים שעדיין יכולים להוריד דברים**

Subnets פרטיים לא יכולים להגיע לאינטרנט. אבל לפעמים הם צריכים. מכונת EC2 שלכם צריכה להוריד עדכון תוכנה.

כאן נכנס **NAT Gateway** (תרגום כתובת רשת).

NAT Gateway יושב ב-subnet ציבורי. משאבים ב-subnets פרטיים יכולים לשלוח תנועה יוצאת ל-NAT Gateway, שמעביר אותה לאינטרנט — אבל האינטרנט לא יכול ליזום חיבורים בחזרה.

## סיכום

- **VPC** הוא רשת פרטית לוגית מבודדת ב-AWS.
- **Subnets** מחלקים את ה-VPC שלכם לפי אזור זמינות. Subnets ציבוריים מתחברים ל-Internet Gateway; פרטיים לא.
- שמו משאבים הפונים לאינטרנט (load balancers) ב-subnets ציבוריים. שמו כל שאר (EC2, מסדי נתונים, מטמונים) ב-subnets פרטיים.
- **Route tables** שולטות לאן תנועה זורמת.
- **NAT Gateway** (ב-subnet ציבורי) מאפשר למשאבים פרטיים ליזום חיבורי אינטרנט יוצאים.
- **VPC Peering** מחבר שני VPCs באופן פרטי. לא טרנזיטיבי.

## עצות לבחינה

- **Subnet ציבורי לעומת פרטי**: ההבדל הוא ב-route table. Subnet ציבורי יש לו מסלול ל-Internet Gateway. פרטי לא.
- **מיקום NAT Gateway**: תמיד ב-subnet *ציבורי*.
- **VPC Peering אינו טרנזיטיבי**: הבחינה תתאר שלושה VPCs ותשאל אם יכולים לתקשר דרך האמצעי — התשובה היא לא.
- **VPC Endpoints**: מאפשרים למשאבים פרטיים להגיע לשירותי AWS (S3, DynamoDB) מבלי לעבור דרך NAT Gateway.

## סצנה לאחר הקרדיטים

שלושה ימים לאחר מכן, כל משאב היה במקום הנכון. מכונות EC2 ב-subnets פרטיים. Load balancers ב-subnets ציבוריים. RDS ו-ElastiCache נגישים רק משכבת היישום.
