# נספח ג: רשימת מושגים

כל מושג מפתח שהוצג בספר, ממופה לפרקו, לאנלוגיה שנעשה בה שימוש ולתחום SAA-C03 שבו הוא מופיע.

השתמש בנספח זה כאינדקס לימוד: אם אתה מעורפל לגבי מושג לפני הבחינה, מצא אותו כאן וחזור לפרקו להקשר.

---

## א

**ACM (AWS Certificate Manager)** — תעודות TLS ציבוריות חינמיות ל-ALB, CloudFront ו-API Gateway, עם חידוש אוטומטי באמצעות אימות DNS. תעודות CloudFront חייבות לשבת ב-us-east-1. פרק 16. תחום 1.

**ACU (Aurora Capacity Unit)** — יחידת המדידה לקיבולת Aurora Serverless v2. מתרחב אוטומטית. פרק 24. תחום 3.

**Alarm (CloudWatch)** — כלל שמופעל כשמדד חוצה סף, מפעיל התראה או auto scaling. פרק 7. תחום 2.

**ALB (Application Load Balancer)** — load balancer שכבה 7 שמנתב תעבורת HTTP/HTTPS לפי נתיב ו-host. פרק 7. תחום 2.

**AMI (Amazon Machine Image)** — תבנית המכילה את מערכת ההפעלה, התוכנה והתצורה למכונת EC2. פרק 4. תחום 3.

**Architect mindset** — לשאול "מה נשבר ראשון, איך נדע, ומה מישהו עושה ב-3 לפנות בוקר?" במקום רק "איך זה עובד?" פרקים 32, 34. רוחב-תחום.

**Architecture Decision Record (ADR)** — מסמך קצר הלוכד החלטה, חלופותיה, הנימוק לה, ומה יגרום לחדייה. פרק 32. רוחב-תחום.

**Architecture review** — תהליך מובנה המכסה: אילוצים ← נעלמים ← אפשרויות ← מצבי כשל ← ניטור ← runbooks. פרק 32. רוחב-תחום.

**Athena** — שירות שאילתות SQL serverless לנתונים ב-S3. תשלום לפי TB שנסרק. פרק 26. תחום 3.

**Auto Scaling Group (ASG)** — קבוצת מכונות EC2 המנוהלות יחד, מחליפות אוטומטית מכונות לא בריאות ומגדילות לפי עומס. פרק 7. תחומים 2, 3.

**Availability Zone (AZ)** — מרכז נתונים אחד או יותר פיזית נפרדים בתוך אזור, מחוברים בחיבורי זמן השהיה נמוך. פרק 2. תחום 2.

**Object (S3)** — קובץ המאוחסן ב-S3. מורכב ממפתח (שם), ערך (נתונים) ומטה-נתונים. גודל מקסימלי 5TB. פרק 5. תחום 3.

**On-Demand capacity (DynamoDB)** — מצב תשלום לפי בקשה. יקר יותר לכל בקשה מ-provisioned, אך ללא צורך בתכנון קיבולת. פרק 29. תחום 4.

**On-Demand instances (EC2)** — תשלום לפי שעה ללא התחייבות. גמישות מקסימלית, מחיר מקסימלי. פרק 27. תחום 4.

**AWS Outposts** — ארון (rack) מנוהל לחלוטין של חומרת AWS המותקן במרכז הנתונים של הלקוח עצמו או במתקן co-location. מריץ on-premises את אותם שירותי AWS, APIs וכלים כמו בענן הציבורי. AWS מנהל את ההתקנה והעדכונים; הלקוח מספק מקום בארון וחשמל. לדרישות data residency, לעומסי עבודה on-premises עם זמן השהיה נמוך, או לתרחישים מנותקים. פרק 2. תחום 4.

## ב

**AWS Backup** — גיבוי מרכזי מבוסס-מדיניות על פני EBS, RDS, DynamoDB, EFS ו-Storage Gateway. תומך בהעתקות בין-אזוריות ובין-חשבוניות. פרקים 18, 23. תחום 2.

**AWS Batch** — שירות compute מנוהל לעבודות אצווה בקונטיינרים של Docker. מורכב מ-job definition (מה להריץ), job queue (היכן עבודות ממתינות) ו-compute environment (EC2 או Fargate, On-Demand או Spot). לעומסי עבודה שחורגים ממגבלת 15 הדקות של Lambda. פרק 21. תחום 3.

**Bucket (S3)** — קונטיינר לעצמי S3. לדליים יש שמות ייחודיים גלובלית וחיים באזור ספציפי. פרק 5. תחום 3.

**Bucket policy** — מדיניות מבוססת-משאב המוצמדת לדלי S3 ושולטת בגישה עבור IAM principals וחשבונות חיצוניים. פרק 5. תחום 1.

## ג

**Gateway Endpoint** — סוג VPC endpoint חינמי ל-S3 ול-DynamoDB. מנתב תעבורה דרך הרשת הפרטית של AWS, ומבטל חיובי NAT Gateway. פרק 30. תחום 4.

**Gateway Load Balancer (GWLB)** — load balancer שכבה 3 להכנסת מכשירי רשת וירטואליים של צד שלישי (חומות אש, IDS/IPS) באופן מוטבע בזרימות תעבורה. פרק 7. תחום 1.

**Geolocation routing (Route 53)** — מנתב לפי המיקום הגיאוגרפי של מקור שאילתת ה-DNS. פרק 12. תחום 3.

**Global Accelerator** — מנתב תעבורה ל-edge הקרוב ביותר של AWS באמצעות Anycast, ומשפר זמן השהיה לאפליקציות דינמיות. פרק 25. תחום 3.

**GuardDuty** — שירות זיהוי איומים. מנתח CloudTrail, VPC Flow Logs ולוגי DNS. מזהה אנומליות ואיומים בהתנהגות. פרק 17. תחום 1.

**Glue (AWS)** — שירות ETL serverless. Glue Crawlers מגלים סכמות; Glue Jobs מטמירים נתונים; Data Catalog מאחסן מטה-נתונים. פרק 26. תחום 3.

**GSI (Global Secondary Index)** — אינדקס חלופי על טבלת DynamoDB עם partition key ו-sort key שונים. מאפשר דפוסי שאילתה גמישים. פרק 9. תחום 3.

---

## ד

**AWS DataSync** — הגירה וסנכרון מבוססי-agent של שיתופי קבצים (NFS/SMB) ל-S3, EFS או FSx. "rsync על סטרואידים, עם קונסולת AWS." פרק 25. תחום 3.

**DAX (DynamoDB Accelerator)** — מטמון בזיכרון ספציפית ל-DynamoDB. זמן השהיה קריאה במיקרושניות. פרק 9. תחום 3.

**Dead Letter Queue (DLQ)** — תור שאליו מועברות הודעות שנכשלות בעיבוד שוב ושוב. פרק 19. תחום 2.

**AWS DMS (Database Migration Service)** — מהגר מסדי נתונים ל-AWS עם זמן השבתה מינימלי. Full load (העתקה ראשונית) בתוספת CDC (Change Data Capture) שומר על סנכרון בין המקור ליעד במהלך ההגירה. הגירות הומוגניות (אותו סוג מנוע): השתמש ב-DMS ישירות. הגירות הטרוגניות (סוגי מנועים שונים, למשל מ-Oracle ל-Aurora PostgreSQL): השתמש תחילה ב-SCT (Schema Conversion Tool), ואז ב-DMS. פרק 8. תחום 3.

**Dedicated Host** — שרת EC2 פיזי השמור באופן בלעדי לשימושך. נדרש לרישיונות תוכנה מסוימים. פרק 27. תחום 4.

**Defense in depth** — ריבוד שכבות אבטחה מרובות (IAM + קבוצות אבטחה + NACLs + WAF + GuardDuty) כדי שפגיעה בשכבה אחת לא תחשוף את המערכת. פרק 33. תחום 1.

**Direct Connect** — חיבור רשת פרטי ייעודי ממיקום on-premises ל-AWS. עקבי יותר מ-VPN. פרק 25. תחום 3.

**DLQ** — ראו Dead Letter Queue.

**DynamoDB** — מסד נתונים NoSQL מנוהל לחלוטין עם זמן השהיה בספרות בודדות של מילישניות בכל קנה מידה. פרק 9. תחום 3.

**DynamoDB Auto Scaling** — מכוון אוטומטית קיבולת read/write provisioned על בסיס מדדי CloudWatch. פרק 29. תחום 4.

**DynamoDB Streams** — יומן שינויים מסודר בזמן של כל שינויי פריטים בטבלת DynamoDB. מועיל לעיבוד event-driven עם Lambda. פרק 9. תחום 2.

## ה

**Envelope encryption** — דפוס שבו נתונים מוצפנים עם data key (DEK), ו-DEK מוצפן עם master key (CMK ב-KMS). פרק 16. תחום 1.

**EventBridge** — אוטובוס אירועים לניתוב אירועים משירותי AWS, שותפי SaaS ומקורות מותאמים אישית ליעדים. פרק 22. תחום 2.

**Health check (Route 53)** — מנטר זמינות של נקודת קצה. health checks שנכשלים מפעילים failover routing. פרק 12. תחום 2.

**Hot partition (DynamoDB)** — partition המקבל תעבורה לא פרופורציונלית מכיוון שבקשות רבות חולקות את אותו partition key. פרק 9. תחום 3.

## ו

**VIF (Virtual Interface)** — החיבור הלוגי שבו משתמשים עם AWS Direct Connect. Public VIF ניגש לנקודות קצה ציבוריות של AWS; Private VIF ניגש למשאבי VPC. פרק 25. תחום 3.

**Visibility timeout (SQS)** — פרק הזמן שבמהלכו הודעה שהתקבלה מוסתרת מצרכנים אחרים. מאפשר עיבוד מבלי שצרכנים אחרים יראו את אותה הודעה. פרק 19. תחום 2.

**VPC (Virtual Private Cloud)** — רשת וירטואלית מבודדת ב-AWS המכילה תת-רשתות, טבלאות מסלול ושערים. פרק 11. תחום 1.

**VPC Flow Logs** — לוכד מידע על תעבורת IP אל/מ-ממשקי רשת ב-VPC. פרק 17. תחום 1.

**VPC Peering** — חיבור רשת בין שני VPCs המאפשר תעבורה ביניהם באמצעות כתובות IP פרטיות. פרק 11. תחום 3.

**VPC Endpoint** — מחבר משאבי VPC לשירותי AWS דרך הרשת הפרטית של AWS. Gateway (חינם, S3/DynamoDB) ו-Interface (בתשלום, רוב השירותים האחרים). פרק 30. תחומים 1, 4.

**WAF (Web Application Firewall)** — מסנן תעבורת HTTP/HTTPS באמצעות כללים (חסימות IP, SQL injection, מגבלות קצב). מתחבר ל-CloudFront, ALB או API Gateway. פרק 17. תחום 1.

**AWS Wavelength** — תשתית AWS הפרוסה בתוך רשתות של ספקי תקשורת 5G, בקצה הרדיו. מאפשרת זמן השהיה של מילישניות בודדות למכשירים ניידים. ל-AR/VR נייד, גיימינג בזמן אמת, טלמטריית רכב אוטונומי ווידאו חי בקצה ה-5G. Wavelength Zones הם הרחבות של AWS Regions בתוך רשתות הטלקום. פרק 2. תחום 3.

**Well-Architected Framework** — מסגרת ההערכה של AWS בעלת שישה עמודי תווך: מצוינות תפעולית, אבטחה, אמינות, יעילות ביצועים, אופטימיזציית עלויות, קיימות. פרק 31. רוחב-תחום.

**Weighted routing (Route 53)** — מפזר שאילתות DNS בין נקודות קצה לפי משקל. משמש לפריסות blue-green ולבדיקות A/B. פרק 12. תחום 3.

**Write-through caching** — מעדכן את המטמון בכל פעם שמסד הנתונים מתעדכן. הנתונים תמיד עקביים, אך המטמון עלול להחזיק פריטים רבים שלעולם לא נקראים שוב. פרק 10. תחום 3.

## י

**IAM (Identity and Access Management)** — שולט באימות ובהרשאה לחשבונות AWS. משתמשים, קבוצות, roles, מדיניויות. פרקים 3, 14. תחום 1.

**IAM role** — זהות IAM עם אישורים זמניים, הנלקחת (assumed) על ידי שירותים, משתמשים או חשבונות אחרים. פרקים 3, 14. תחום 1.

**Idempotency** — המאפיין של פעולה המייצרת את אותה תוצאה בין אם נקראת פעם אחת ובין אם פעמים רבות. קריטי למערכות מבוזרות (החזרים, תשלומים, עיבוד הזמנות). פרק 32. רוחב-תחום.

**Idempotency key** — מזהה ייחודי לפעולה, הנבדק לפני הביצוע כדי למנוע עיבוד כפול. פרק 32. רוחב-תחום.

**Interface Endpoint (PrivateLink)** — VPC endpoint לרוב שירותי AWS. מתומחר לפי שעה + לפי GB. מספק קישוריות פרטית ללא אינטרנט או NAT. פרק 30. תחום 4.

**Internet Gateway (IGW)** — מאפשר למכונות בתת-רשתות ציבוריות לתקשר עם האינטרנט. דורש שלטבלת המסלול של תת-הרשת יהיה מסלול ל-IGW. פרק 11. תחום 3.

**"It depends"** — התשובה הכנה לרוב שאלות הארכיטקטורה, שחייבת תמיד להיות מושלמת: "תלוי בדפוס הגישה / קנה המידה / תוצאת הכשל / אילוץ העלות." פרק 33. רוחב-תחום.

## כ

**Kinesis Data Firehose** — מסירה מנוהלת של נתוני זרימה ל-S3, Redshift, OpenSearch. ללא ניהול צרכן. פרק 26. תחום 3.

**Kinesis Data Streams** — זרם אירועים מסודר בזמן אמיתי. עמיד, ניתן ל-replay. נמדד ב-shards. פרק 26. תחום 3.

**KMS (Key Management Service)** — יוצר, מאחסן ושולט במפתחות קריפטוגרפיים להצפנה בשאר. פרק 16. תחום 1.

## ל

**Lambda** — פונקציות serverless שמופעלות על ידי אירועים. תשלום לפי הפעלה ולפי ms. מקסימום 15 דקות. פרק 20. תחומים 2, 3, 4.

**Lambda@Edge** — פונקציות Lambda הרצות ב-edge locations של CloudFront, ומשנות בקשות ותגובות. פרק 13. תחום 3.

**AWS Lake Formation** — שכבת בקרת גישה מרכזית ל-data lake מעל S3 ו-Glue Data Catalog. מספק הרשאות עדינות ברמת הטבלה, העמודה והשורה. מפשט הקמת data lake מאובטח. פרק 26. תחום 3.

**Latency-based routing (Route 53)** — מנתב שאילתות DNS לאזור AWS עם זמן ההשהיה הנמוך ביותר הנמדד. פרק 12. תחום 3.

**Launch template** — תבנית עם גרסאות המציינת תצורת מכונת EC2 ל-Auto Scaling Groups. פרק 7. תחום 3.

**Least privilege** — שיטת עבודה מומלצת של IAM: הענק רק את ההרשאות הנחוצות, לא יותר. פרק 3. תחום 1.

**Lifecycle policy (S3)** — כללים שמעבירים אוטומטית עצמים למחלקות אחסון זולות יותר או מוחקים אותם לפי גיל. פרק 23. תחום 4.

**LSI (Local Secondary Index)** — אינדקס חלופי על טבלת DynamoDB המשתמש באותו partition key אך ב-sort key שונה. חייב להיווצר בעת יצירת הטבלה. פרק 9. תחום 3.

## מ

**Amazon Macie** — גילוי מבוסס-ML של נתונים רגישים (PII) ב-S3 וסימון סיכוני חשיפה. GuardDuty צופה בהתנהגות; Macie מבקר את מה שמאוחסן. פרק 17. תחום 1.

**Memcached** — מנוע מטמון בזיכרון פשוט ורב-תהליכונים. ללא persistence, ללא מבני נתונים. השתמש ב-Redis אלא אם אתה זקוק ספציפית לריבוי תהליכונים במחיר ויתור על תכונות. פרק 10. תחום 3.

**Amazon MemoryDB for Redis** — מסד נתונים ראשי בזיכרון, עמיד ותואם-Redis. בניגוד ל-ElastiCache, MemoryDB כותב ליומן טרנזקציות Multi-AZ, ומבטיח עמידות נתונים. השתמש כאשר נדרשת תאימות ל-API של Redis וגם אובדן נתונים אינו מקובל. פרק 10. תחום 3.

**MGN (AWS Application Migration Service)** — Rehost/lift-and-shift: שכפול ברמת הבלוק של שרתים שלמים אל AWS, השקות בדיקה, ואז cutover למכונות EC2 מקוריות. DataSync מעביר קבצים; DMS מעביר מסדי נתונים; MGN מעביר שרתים. פרק 25. תחום 3.

**Amazon MQ** — broker מנוהל של ActiveMQ/RabbitMQ הדובר פרוטוקולים סטנדרטיים (AMQP, MQTT, STOMP). ל-lift-and-shift של עומסי עבודה קיימים של broker ללא שינויי קוד; למערכות הודעות חדשות (greenfield) השתמש ב-SQS/SNS. פרק 19. תחום 2.

**Multi-AZ (RDS)** — replica standby סינכרוני ב-AZ שונה עם כשל-אוטומטי. RPO ~0, RTO ~60 שניות. לזמינות גבוהה, לא להגדלת קריאות. פרקים 8, 18. תחום 2.

**Multi-Region** — פריסת רכיבי אפליקציה על פני אזורי AWS מרובים לצורך יתירות גיאוגרפית וביצועים גלובליים. פרק 18. תחום 2.

## נ

**NACL (Network Access Control List)** — חומת אש stateless ברמת תת-הרשת. דורש כללי כניסה ויציאה כאחד. כללים מוערכים בסדר מספרי. פרק 15. תחום 1.

**NAT Gateway** — מאפשר למכונות בתת-רשתות פרטיות לבצע חיבורים יוצאים לאינטרנט. גובה $0.045/GB מעובד. פרקים 11, 30. תחום 4.

**Network Load Balancer (NLB)** — load balancer שכבה 4 (TCP/UDP/TLS): מיליוני בקשות בשנייה, IP סטטי לכל AZ, משמר את כתובת ה-IP של המקור. ללא מודעות ל-HTTP — זו עבודתו של ה-ALB. פרק 7. תחום 3.

## ע

**EC2 (Elastic Compute Cloud)** — מכונות וירטואליות בענן. פרק 4. תחום 3.

**ECS (Elastic Container Service)** — תזמור containers מנוהל. Fargate launch type מסיר ניהול EC2 לחלוטין. פרק 21. תחומים 2, 3.

**EFS (Elastic File System)** — מערכת קבצים NFS משותפת נגישה ממכונות EC2 מרובות. מתרחב אוטומטית. פרק 6. תחום 3.

**EKS (Elastic Kubernetes Service)** — control plane Kubernetes מנוהל על AWS. פרק 21. תחום 3.

**Elastic Disaster Recovery (DRS)** — שכפול רציף ברמת הבלוק של שרתים (on-premises או EC2) לאזור staging זול, עם השקת מכונות שחזור תוך דקות — pilot light מנוהל. פרק 18. תחום 2.

**ElastiCache** — שירות מטמון בזיכרון מנוהל. Redis (עשיר יותר בתכונות) או Memcached (פשוט יותר). פרק 10. תחום 3.

**Elastic IP** — כתובת IP ציבורית סטטית שניתן להקצות ולשייך מחדש למכונות EC2. פרק 11. תחום 3.

**EBS (Elastic Block Store)** — אחסון בלוקים מתמשך למכונת EC2 בודדת. Snapshots לגיבוי. פרק 6. תחום 3.

**Explicit deny** — הצהרת deny ב-IAM שלא ניתנת לעקיפה על ידי שום allow. גוברת על כל ה-allows. פרק 3. תחום 1.

## פ

**Failover routing (Route 53)** — מנתב תעבורה לנקודת קצה משנית כשהראשית נכשלת ב-health checks. פרק 12. תחום 2.

**Fargate** — מנוע חישוב serverless ל-ECS ו-EKS. ללא מכונות EC2 לניהול. פרק 21. תחום 3.

**Fan-out pattern** — SNS topic אחד מוסר את אותה הודעה לתורי SQS מרובים בו-זמנית. פרק 19. תחום 2.

**FIFO queue (SQS)** — exactly-once processing, strict ordering. תפוקה נמוכה מתורות standard. פרק 19. תחום 2.

**Failure mode** — דרך ספציפית שבה מערכת יכולה להיכשל. זיהוי מצבי כשל לפני הייצור הוא ליבת סקירת הארכיטקטורה. פרק 32. רוחב-תחום.

**Partition key (DynamoDB)** — רכיב המפתח הראשי הקובע איזה partition מאחסן פריט. בחר מפתח עם קרדינליות גבוהה לפיזור אחיד. פרק 9. תחום 3.

**Permission boundary** — מדיניות IAM הקובעת את ההרשאות המקסימליות שזהות IAM יכולה לקבל, גם אם מדיניויות אחרות מעניקות יותר. פרק 14. תחום 1.

**Placement group** — שולט במיקום הפיזי של מכונות EC2 כדי למזער זמן השהיה (cluster) או למקסם זמינות (spread). פרק 4. תחום 3.

**PrivateLink** — שירות AWS ליצירת נקודות קצה פרטיות לשירותים המתארחים ב-AWS, נגישות דרך Interface Endpoints. פרק 30. תחום 1.

**Provisioned concurrency (Lambda)** — סביבות ריצה מאותחלות מראש המבטלות עיכובי cold start. פרק 20. תחום 3.

**Provisioned capacity (DynamoDB)** — תפוקת קריאה וכתיבה מוקצית מראש, נמדדת ביחידות קיבולת לשנייה. זול יותר מ-on-demand לתעבורה צפויה. פרקים 9, 29. תחום 4.

## ק

**Cache-aside pattern** — האפליקציה בודקת תחילה את המטמון; ב-miss, היא שואלת את מסד הנתונים ואז מאחסנת את התוצאה במטמון. פרק 10. תחום 3.

**Cache hit rate** — אחוז הבקשות המוגשות מהמטמון במקום מהמקור. גבוה יותר עדיף. פרק 13. תחום 3.

**AWS Client VPN** — נקודת קצה OpenVPN מנוהלת. מחברת מכשירים בודדים (מחשבים ניידים, תחנות עבודה) ל-VPC דרך האינטרנט. אימות באמצעות Active Directory, פדרציית SAML 2.0 עם ספק זהויות, או mutual TLS. תומך במצבי split-tunnel ו-full-tunnel. בניגוד ל-Site-to-Site VPN (רשת-לרשת). פרק 11. תחום 1.

**CloudFront** — ה-CDN של AWS. שומר תוכן במטמון ב-750+ edge locations ברחבי העולם. מפחית זמן השהיה ועלויות העברת נתונים מהמקור. פרק 13. תחומים 3, 4.

**CloudTrail** — מתעד כל קריאת API ב-AWS: מי, מה, מתי, מאיפה. מאוחסן ב-S3. משמש לביקורת ולחקירת אירועים. תחום 1.

**CloudWatch** — מדדים, לוגים, התראות ולוחות מחוונים למשאבי AWS ולאפליקציות מותאמות אישית. מוזכר לכל אורך הספר. כל התחומים.

**Amazon Cognito** — אימות למשתמשי הקצה של האפליקציה שלך: User Pools הם ספריית משתמשים מנוהלת (הרשמה, התחברות, MFA, התחברות חברתית, JWTs); Identity Pools מנפיקים אישורי AWS זמניים. IAM הוא למהנדסים שלך; Cognito הוא ללקוחות שלך. פרק 14. תחום 1.

**Cold start (Lambda)** — עיכוב בהפעלה הראשונה (או אחרי חוסר פעילות) בזמן ש-Lambda מאתחל את סביבת הריצה. השתמש ב-provisioned concurrency כדי לבטל. פרק 20. תחום 3.

**Compute Savings Plan** — התחייבות לסכום דולרי של הוצאת EC2 שעתית, החלה על כל סוג או גודל מכונה. פרק 27. תחום 4.

**Config (AWS)** — עוקב אחר שינויי תצורה במשאבי AWS לאורך זמן ומעריך תאימות מול כללים. פרק 31. תחום 1.

**AWS Control Tower** — ממכן ממשל רב-חשבוני: בונה landing zone (חשבונות management, log archive ו-audit) עם guardrails תוך דקות — הגרסה הטרומית של חיווט Organizations, CloudTrail ו-Config ביד. פרק 14. תחום 1.

**Cross-AZ data transfer** — תעבורה בין Availability Zones בתוך אזור. מחויבת ב-$0.01/GB לכל כיוון. פרק 30. תחום 4.

**Cross-region replication** — העתקת נתונים (S3 CRR, Aurora Global, DynamoDB Global Tables) לאזור אחר. כרוכה בחיובי העברת נתונים. פרקים 18, 23, 30. תחום 2.

**Amazon QuickSight** — שירות מנוהל לבינה עסקית ולהדמיית נתונים. משתמש ב-SPICE (Super-fast, Parallel, In-memory Calculation Engine) לשמירת נתונים במטמון לרינדור מהיר של לוחות מחוונים. מתחבר ל-Athena, S3, Redshift, RDS ומקורות נתונים נוספים של AWS. ללא שרת BI לניהול. פרק 26. תחום 3.

## ר

**RDS (Relational Database Service)** — מסד נתונים רלציוני מנוהל. מטפל בגיבויים, תיקון, כשל-אוטומטי. פרק 8. תחום 3.

**RDS Proxy** — מנהל מאגר חיבורים בין Lambda/אפליקציה ו-RDS, מונע מיצוי חיבורים. פרק 8. תחום 3.

**Read Replica (RDS)** — עותק אסינכרוני של מסד הנתונים להגדלת קריאות. לא מספק כשל-אוטומטי. פרקים 8, 24. תחום 3.

**Redis** — מאגר מבני נתונים בזיכרון לmטמון, ניהול סשנים, לוחות תוצאות בזמן אמיתי, pub/sub. פרק 10. תחום 3.

**Reserved Instance (EC2)** — התחייבות לשימוש בסוג מכונה ספציפי באזור ספציפי ל-1 או 3 שנים בתמורה להנחה. פרק 27. תחום 4.

**Route 53** — שירות DNS ורשם תחומים של AWS. תומך במדיניות ניתוב מרובות. פרק 12. תחומים 2, 3.

**RPO (Recovery Point Objective)** — אובדן נתונים מקסימלי מקובל הנמדד בזמן. "כמה נתונים אנחנו יכולים להרשות לאבד?" פרק 18. תחום 2.

**RTO (Recovery Time Objective)** — זמן שחזור שירות מקסימלי מקובל לאחר כשל. "כמה זמן אנחנו יכולים להיות מושבתים?" פרק 18. תחום 2.

**Runbook** — הוראות שלב-אחר-שלב לתפעול מערכת, ספציפית לתגובה לאירועים. פרק 32. רוחב-תחום.

## ש

**Shard (Kinesis)** — יחידת התפוקה הבסיסית ב-Kinesis Data Streams: כתיבה 1 MB/s, קריאה 2 MB/s. פרק 26. תחום 3.

**Shared Responsibility Model** — AWS אחראי על אבטחה *של* הענן (תשתית); אתה אחראי על אבטחה *בתוך* הענן (נתונים, תצורה, גישה). פרק 1. תחום 1.

**Shield** — הגנת DDoS. Standard: חינם, אוטומטי. Advanced: בתשלום, עם תמיכת DRT והגנה פיננסית. פרק 17. תחום 1.

**Snow Family** — מכשירים פיזיים להעברת נתונים בכמויות גדולות באופן לא מקוון (Snowball Edge: 80 TB) — שכירת מטוס מטען במקום נסיעה בכביש המהיר. Legacy (2026): Snowmobile ו-Snowcone הופסקו; מכשירי Snow נסגרו ללקוחות חדשים בנובמבר 2025 (AWS מפנה ל-DataSync ול-Data Transfer Terminals), אך בחינת ה-SAA-C03 עדיין מצפה ל-Snowball עבור "שבועות של העברה, רוחב פס מוגבל." פרק 25. תחום 3.

**SNS (Simple Notification Service)** — הודעות pub/sub. דוחף הודעות לכל המנויים בו-זמנית. דפוס fan-out. פרק 19. תחום 2.

**Sort key (DynamoDB)** — רכיב שני אופציונלי של המפתח הראשי. מאפשר שאילתות טווח בתוך partition. פרק 9. תחום 3.

**Spot Instances** — מכונות EC2 המשתמשות בקיבולת פנויה בהנחה של 60-90%. עלולות להיקטע בהתראה של 2 דקות. רק לעומסי עבודה סובלי-תקלות. פרק 27. תחום 4.

**SQS (Simple Queue Service)** — תור הודעות מנוהל. מנתק מפיקים מצרכנים. תורות Standard (at-least-once) ו-FIFO (exactly-once). פרק 19. תחום 2.

**Step Functions** — שירות תזמור תהליכי עבודה serverless. State machines לתיאום שירותי AWS. פרק 22. תחום 2.

**AWS Storage Gateway** — הגשר בין אחסון on-premises לענן: מציג מקומית ממשקי NFS/SMB (File), iSCSI (Volume) או virtual tape (Tape), תוך שמירת הנתונים ב-S3, Glacier או EBS snapshots. פרק 6. תחום 3.

**S3 Intelligent-Tiering** — מעביר אוטומטית עצמי S3 בין שכבות גישה על בסיס דפוסי גישה. ללא דמי שחזור. פרק 23. תחום 4.

**S3 Select** — שולף תת-קבוצה של תוכן עצם S3 באמצעות ביטויי SQL, מפחית העברת נתונים. פרק 30. תחום 4.

**Savings Plan** — מודל תמחור גמיש המתחייב לסכום של הוצאה שעתית בתמורה להנחה. גמיש יותר מ-Reserved Instances. פרק 27. תחום 4.

**SCP (Service Control Policy)** — מדיניות AWS Organizations שמגבילה את ההרשאות המקסימליות הזמינות לחשבונות ב-OU. פרק 14. תחום 1.

**Secrets Manager** — מאחסן ומסובב אוטומטית secrets (סיסמאות מסד נתונים, API keys). פרק 16. תחום 1.

**Security group** — חומת אש וירטואלית stateful ברמת המכונה. כללי allow בלבד; תעבורת חזרה היא אוטומטית. פרק 15. תחום 1.

## ת

**Target tracking scaling** — מדיניות Auto Scaling המכוונת קיבולת לשמירה על ערך מדד יעד (למשל 60% ניצול CPU). פרק 7. תחום 2.

**AWS Transfer Family** — נקודת קצה SFTP/FTPS/FTP מנוהלת המגובה ב-S3 או EFS. שותפים שומרים על לקוחות ה-SFTP הקיימים שלהם; קבצים נוחתים ישירות בדלי שלך. פרק 25. תחום 3.

**Transit Gateway** — רכזת לקישוריות VPC ו-on-premises. מאפשר ניתוב עקיף (בשונה מ-VPC peering). פרק 25. תחום 3.

**TTL (Time to Live)** — חותמת זמן שלאחריה DynamoDB מוחק אוטומטית פריט. מועיל גם ב-DNS (כמה זמן resolvers שומרים רשומה במטמון) ובmטמון (כמה זמן ערך במטמון תקף). פרקים 9, 12. תחום 3.
