# 前言

您可能以前尝试过学习 AWS。

也许您打开了文档，十分钟后，在还没搞清楚 IAM 是用来做什么的时候，就已经盯着 IAM 策略语法发呆了。

也许您看完了一门视频课程，却发现自己仍然无法解释一个网站究竟存放在哪里。

也许您在考试指南上画满了重点，记住了服务名称，但当某道情景题问到晚餐高峰期间数据库故障该怎么办时，您却第一次陷入了茫然。

这不是您的错。

这是云计算通常的教学方式：先讲目录，后讲系统。

本书的做法不同。

**您不会去"学习" AWS，您会去"使用"它。**

我们从一家餐厅开始——它因为电话线占线、没有网站而不断丢失订单。

从那里出发，您将跟随 Maya、Tom、Priya 和 Leo，一步一个决策地构建 Nimbus 的基础架构。不是按照认证考试大纲偏爱的整洁顺序，而是按照真实系统所要求的那种杂乱无章的顺序。

到最后，Nimbus 将每天处理 18,000 个订单：跨多个可用区运行、自动从故障中恢复、通过内容分发网络在毫秒内响应西海岸用户、通过实时分析管道处理每一笔订单，并在架构随业务成长的同时控制成本。

本书中的每项 AWS 服务都在它变得必要的那一刻出现。不是因为考试大纲要求，而是因为系统需要。

**本书适合谁阅读** 如果您通过解决问题比通过阅读文档学得更好，本书就是为您而写的。如果您正在备考 AWS 解决方案架构师助理认证（SAA-C03），本书同样适合您：每个考试领域都有覆盖，每章末尾都附有考试技巧和 SAA-C03 风格的练习题。如果您已经在从事工程工作，希望理解架构决策为何有效，而不仅仅是服务叫什么名字，您将在每一页都能找到这种推理过程。

**您在这里找不到什么** 捷径。这不是一本应试速成指南。它比速成指南更长，因为理解比记忆需要更多时间，而真正能迁移到您下一个岗位、下一个系统以及那些从未被妥善记录的生产事故中的，正是这种理解。

**如何阅读本书** 第一遍像读小说一样读。让架构随着团队遇到真实问题、做出真实权衡而自然呈现。每章结束时，主动运用考试技巧和练习：先盖住答案，自己推理场景，然后再核对结果。

当您读完本书，Nimbus 将已投入生产。您对 AWS 的理解也将如此。

让我们开始吧。
