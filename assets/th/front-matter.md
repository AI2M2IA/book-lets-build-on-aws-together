# คำนำ

คุณอาจเคยพยายามเรียนรู้ AWS มาก่อนแล้ว

บางทีคุณเปิดเอกสารและสิบนาทีต่อมา พบว่าตัวเองกำลังจ้องมองที่ไวยากรณ์นโยบาย IAM ก่อนที่จะเข้าใจว่า IAM มีไว้ทำอะไร

บางทีคุณเรียนจบคอร์สวิดีโอแล้วตระหนักว่าคุณยังไม่สามารถอธิบายได้ว่าเว็บไซต์อยู่ที่ไหนจริงๆ

บางทีคุณไฮไลท์คู่มือสอบ จำชื่อบริการ แล้วก็แข็งทื่อเมื่อครั้งแรกที่สถานการณ์ถามว่าคุณจะทำอะไรถ้าฐานข้อมูลล้มเหลวในช่วงชั่วโมงเร่งรีบมื้อเย็น

นั่นไม่ใช่ความผิดของคุณ

นั่นคือวิธีที่การประมวลผลแบบคลาวด์มักถูกสอน: แคตตาล็อกก่อน แล้วค่อยเป็นระบบ

หนังสือเล่มนี้ทำงานแตกต่างออกไป

**คุณจะไม่ศึกษา AWS คุณจะใช้มัน**

เราเริ่มต้นด้วยร้านอาหารที่กำลังสูญเสียออร์เดอร์เพราะสายโทรศัพท์ยุ่งและไม่มีเว็บไซต์

จากนั้นคุณจะติดตาม Maya, Tom, Priya และ Leo ขณะที่พวกเขาสร้างโครงสร้างพื้นฐานของ Nimbus ทีละการตัดสินใจ ไม่ใช่ตามลำดับที่เรียบร้อยที่หลักสูตรรับรองต้องการ แต่ตามลำดับที่วุ่นวายที่ระบบจริงต้องการ

ถึงตอนจบ Nimbus จะจัดการ 18,000 ออร์เดอร์ต่อวัน: ทำงานข้ามหลาย Availability Zone ฟื้นตัวจากความล้มเหลวโดยอัตโนมัติ ให้บริการผู้ใช้บนชายฝั่งตะวันตกในมิลลิวินาทีผ่านเครือข่ายการส่งเนื้อหา ประมวลผลทุกออร์เดอร์ผ่านไปป์ไลน์การวิเคราะห์แบบเรียลไทม์ และควบคุมต้นทุนขณะที่สถาปัตยกรรมเติบโตพร้อมธุรกิจ

ทุก AWS service ในหนังสือเล่มนี้ปรากฏในขณะที่มันจำเป็น ไม่ใช่เพราะหลักสูตรต้องการ แต่เพราะระบบต้องการ

**หนังสือเล่มนี้สำหรับใคร** หากคุณเรียนรู้ได้ดีกว่าผ่านปัญหามากกว่าเอกสาร หนังสือเล่มนี้เขียนขึ้นสำหรับคุณ หากคุณกำลังเตรียมตัวสำหรับการรับรอง AWS Solutions Architect Associate (SAA-C03) หนังสือเล่มนี้ก็เหมาะสำหรับคุณเช่นกัน: ทุกโดเมนการสอบได้รับการครอบคลุม และทุกบทจบด้วยเคล็ดลับการสอบและคำถามฝึกหัดสไตล์ SAA-C03 หากคุณทำงานด้านวิศวกรรมอยู่แล้วและต้องการเข้าใจว่า *ทำไม* การตัดสินใจสถาปัตยกรรมถึงได้ผล ไม่ใช่แค่บริการเรียกว่าอะไร คุณจะพบเหตุผลนั้นในทุกหน้า

**สิ่งที่คุณจะไม่พบที่นี่** ทางลัด นี่ไม่ใช่คู่มือท่อง มันยาวกว่าคู่มือท่องเพราะการเข้าใจใช้เวลานานกว่าการจำ และนั่นคือความเข้าใจที่ถ่ายโอนไปยังบทบาทถัดไปของคุณ ระบบถัดไป และเหตุการณ์การผลิตที่ไม่มีใครบันทึกอย่างถูกต้อง

**วิธีอ่านหนังสือเล่มนี้** อ่านเหมือนนิยายในครั้งแรก ปล่อยให้สถาปัตยกรรมเปิดเผยตัวเองขณะที่ทีมเผชิญกับปัญหาจริงและทำการแลกเปลี่ยนจริง ตอนท้ายแต่ละบท หยุดแล้วใช้เคล็ดลับการสอบและแบบฝึกหัดอย่างแข็งขัน: ปิดคำตอบ ใช้เหตุผลผ่านสถานการณ์ด้วยตัวเอง แล้วตรวจสอบสิ่งที่เกิดขึ้น

เมื่อคุณเสร็จสิ้น Nimbus จะอยู่ในการผลิต ความเข้าใจ AWS ของคุณก็เช่นกัน
